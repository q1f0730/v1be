乐观更新 (Optimistic UI)

Optimistic UI

📐 01 · 定义

乐观更新（Optimistic UI）是一种前端交互模式：在服务器确认前就按预期成功的结果更新界面，请求失败时再回滚并提示。它属于前端状态管理与交互设计层，用于掩盖网络延迟，让高成功率操作（点赞、收藏、发消息、拖拽排序）感觉即时。React 19 提供 useOptimistic，TanStack Query 等库支持基于缓存的乐观更新。

⚙️ 02 · 原理
  1. 1

    用户触发操作，前端先保存当前状态（或缓存数据）的快照，用于请求失败时回滚。

  2. 2

    立即把预期结果写入本地状态或请求缓存，界面马上反映变化，可附加「发送中」等待定标记。

  3. 3

    同时向服务器发送变更请求，并取消可能覆盖乐观值的进行中查询。

  4. 4

    成功：用服务器返回的权威数据替换乐观值，或使相关缓存失效后重新获取。

  5. 5

    失败：恢复快照、用 toast 等方式提示用户，并视情况提供重试或撤销入口。

🔤 03 · 术语
乐观更新 (Optimistic Update)
假设请求成功，先更新界面再等待确认。
回滚 (Rollback)
请求失败时把界面恢复到操作前的状态。
useOptimistic
React 19 Hook，在异步操作进行期间显示临时状态。
onMutate
TanStack Query 变更前回调，常用于写入乐观值并返回快照。
权威状态 (Source of Truth)
服务器上的真实数据，最终以它为准。
💻 04 · 代码
TanStack Query 乐观点赞typescript
import { useMutation, useQueryClient } from "@tanstack/react-query";

export function useLike(postId: string) {
  const qc = useQueryClient();
  const key = ["post", postId];
  return useMutation({
    mutationFn: () => fetch(`/api/posts/${postId}/like`, { method: "POST" }),
    onMutate: async () => {
      await qc.cancelQueries({ queryKey: key });   // 防止旧请求覆盖乐观值
      const prev = qc.getQueryData<{ likes: number; liked: boolean }>(key);
      qc.setQueryData(key, (old: any) => ({ ...old, likes: old.likes + 1, liked: true }));
      return { prev };                              // 快照，用于回滚
    },
    onError: (_err, _vars, ctx) => {
      qc.setQueryData(key, ctx?.prev);              // 失败回滚
    },
    onSettled: () => qc.invalidateQueries({ queryKey: key }), // 以服务器为准
  });
}

onMutate 写入乐观值并返回快照，onError 回滚，onSettled 重新获取权威数据。

📊 05 · 参数对比

乐观更新适用性判断

维度适合不适合
失败概率极低（点赞、收藏）较高（库存、竞价）
失败代价可轻松撤销涉及资金、法律、不可逆
结果可预测性前端能算出结果依赖服务端计算（如价格）
并发冲突个人数据多人同时编辑同一记录
⚖️ 06 · 方案取舍

乐观更新

优点零感知延迟，体验流畅

代价需写回滚逻辑，失败时界面跳变

适用高成功率、可撤销操作

悲观更新（等待确认）

优点界面始终真实

代价延迟明显，需加载状态

适用支付、下单、权限变更

乐观 + 待定标记

优点即时又诚实，如消息「发送中」

代价需要额外 UI 状态

适用聊天、评论、上传

🕳️ 07 · 常见坑

  • ✗没有保存快照，失败后无法正确回滚

    ✓在变更前保存先前状态，失败时整体恢复

  • ✗乐观更新后不与服务器对齐

    ✓成功后用响应数据或重新获取覆盖乐观值

  • ✗进行中的旧查询返回后覆盖了乐观值

    ✓变更前取消相关查询，再写入乐观值

  • ✗对涉及金额或库存的操作使用乐观更新

    ✓关键业务等待服务器确认，可用加载态与禁用重复提交

🎤 09 · 面试追问
乐观更新失败时如何避免糟糕体验？

回滚要平滑并给出明确提示与重试入口；对可能失败的操作显示待定状态而非完全成功；失败率高的操作不应使用乐观更新。

用户快速连点点赞/取消，如何保证最终一致？

可对请求排队或只发送最终状态（防抖）；每次变更前取消进行中查询；成功或失败后统一重新获取服务器状态。后端接口最好设计成设置状态（PUT liked=true）而非切换。

useOptimistic 与 TanStack Query 乐观更新有何不同？

useOptimistic 管组件内的临时状态，在 Action 进行期间显示，结束后自动回到真实状态；TanStack Query 直接修改共享的查询缓存，所有用该数据的组件同步更新，需要手动回滚与失效。
