退避随机抖动

Jitter

📐 01 · 定义

抖动（Jitter）是在重试退避或定时任务的等待时间中加入随机量的技术。纯指数退避会让同时失败的大量客户端在相同时间点再次重试，形成同步尖峰；加入随机性可以把重试分散到时间窗口内，降低对恢复中服务的冲击。它是客户端重试策略中与超时、退避、重试上限配套的一环。

⚙️ 02 · 原理
  1. 1

    客户端请求失败后，先计算指数退避上界：base × 2^attempt，并用 cap 封顶。

  2. 2

    在 0 到上界之间随机取值（Full Jitter），或在一半到上界之间取值（Equal Jitter）。

  3. 3

    大量客户端的重试时刻由此均匀散开，服务端看到的是平滑负载而非周期性尖峰。

  4. 4

    同理，定时任务、缓存过期时间、连接重建也加随机偏移，避免同时触发。

  5. 5

    同时配合最大重试次数和重试预算，防止随机化之后重试总量仍然过大。

🔤 03 · 术语
全抖动 (Full Jitter)
等待时间在 0 到退避上界间均匀随机。
等值抖动 (Equal Jitter)
保留一半退避时间，另一半随机，保证最小等待。
去相关抖动 (Decorrelated Jitter)
基于上次等待时间随机增长下一次等待的变体。
退避上限 (Cap)
单次等待时间的最大值，防止指数增长过长。
同步化 (Synchronization)
多个客户端行为在时间上对齐，导致负载尖峰。
💻 04 · 代码
指数退避加全抖动python
import random, time
import requests

def get_with_retry(url, max_attempts=5, base=0.1, cap=10.0):
    for attempt in range(max_attempts):
        try:
            r = requests.get(url, timeout=3)
            if r.status_code < 500:
                return r              # 成功或 4xx 都不再重试
        except requests.RequestException:
            pass                       # 网络错误，进入重试
        if attempt == max_attempts - 1:
            break
        # Full Jitter：在 [0, min(cap, base*2^n)] 内随机等待
        sleep = random.uniform(0, min(cap, base * 2 ** attempt))
        time.sleep(sleep)
    raise RuntimeError("retries exhausted")

按 AWS 架构博客的 Full Jitter 公式实现，有重试上限并跳过 4xx。

📊 05 · 参数对比

退避策略对比

策略等待公式（概念）特点
固定间隔sleep = c最易同步，易打爆服务
指数退避min(cap, base·2^n)总量下降，但仍同步
Full Jitterrandom(0, 指数上界)分散最好，平均等待短
Equal Jitter上界/2 + random(0, 上界/2)保证最小间隔
⚖️ 06 · 方案取舍

Full Jitter

优点分散效果好，总调用少

代价个别请求可能几乎不等待

适用大量客户端的默认选择

Equal Jitter

优点保证最小退避

代价平均等待更长

适用需要强制冷却时间

不加抖动

优点行为可预测

代价多客户端时形成同步尖峰

适用只有单个客户端的脚本

🕳️ 07 · 常见坑

  • ✗所有实例用同一随机种子或启动即同时开始，抖动失效。

    ✓使用系统随机源，不手动固定种子。

  • ✗只给重试加抖动，定时任务全部整点触发。

    ✓cron 和缓存 TTL 同样加入随机偏移。

  • ✗抖动后没有上限，退避时间无限增长。

    ✓设置 cap 与最大重试次数。

🎤 09 · 面试追问
为什么有了指数退避还需要抖动？

指数退避减少了重试次数，但同一时刻失败的客户端仍按相同序列重试，请求在 1、2、4 秒处成簇到达。抖动把每个客户端的等待随机化，打散这些簇，让服务恢复期的负载平滑。

Full Jitter 和 Equal Jitter 如何选？

AWS 的模拟显示 Full Jitter 在总调用次数和完成时间上表现好，适合作为默认；若业务需要保证两次重试间至少间隔一段时间，选 Equal Jitter。

抖动还能用在哪些地方？

缓存 TTL 加随机偏移避免同时过期；定时任务错峰执行；客户端重连、心跳和轮询间隔；滚动发布中批次间隔。本质都是打破多实例的时间同步。
