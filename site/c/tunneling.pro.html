内网穿透 (Cloudflare Tunnel / ngrok)

Tunneling

📐 01 · 定义

内网穿透（Tunneling）指让处于 NAT、防火墙后、没有公网 IP 的本地服务被公网访问的技术。主流方案由本地代理程序主动向公网中继或边缘节点建立出站长连接，外部请求先到达中继，再经该连接回传到本地端口。典型工具有 Cloudflare Tunnel（cloudflared）、ngrok、frp，以及 SSH 远程端口转发。

⚙️ 02 · 原理
  1. 1

    本地运行代理客户端（如 cloudflared、ngrok agent），它向服务商边缘或自建中继发起出站 TLS 连接，无需在路由器上开放入站端口。

  2. 2

    服务商为该隧道分配公网主机名（随机子域或绑定的自有域名），并在边缘终止 TLS。

  3. 3

    外部用户访问该主机名，边缘根据主机名找到对应隧道，把 HTTP 请求经已建立的长连接转发给本地代理。

  4. 4

    本地代理把请求转给配置的源地址（如 http://localhost:3000），再把响应原路返回。

  5. 5

    可在边缘叠加访问控制（如 Cloudflare Access 身份验证、IP 限制），避免隧道成为未授权入口。

🔤 03 · 术语
NAT 穿越 (NAT Traversal)
让位于地址转换设备后的主机可被外部访问的技术总称。
出站连接 (Outbound-only)
隧道由内向外建立，因此不需要开放入站防火墙端口。
Quick Tunnel
cloudflared 无需账号即可生成 trycloudflare.com 临时地址的模式。
反向隧道 (Reverse Tunnel)
由内网主动连到外部，再由外部把流量反向送回内网。
frp
开源的自建内网穿透工具，需要一台有公网 IP 的服务器。
零信任访问 (Zero Trust Access)
在隧道入口按用户身份而非网络位置授权访问。
💻 04 · 代码
三种方式暴露本地 3000 端口bash
# 方式一：Cloudflare 临时隧道（无需账号，地址随机且不保证可用性）
cloudflared tunnel --url http://localhost:3000
# 输出类似 https://<random>.trycloudflare.com

# 方式二：ngrok（需注册并配置 authtoken）
ngrok config add-authtoken <YOUR_TOKEN>
ngrok http 3000

# 方式三：SSH 远程端口转发（需要一台公网 VPS）
# 把 VPS 的 8080 转到本机 3000；VPS 的 sshd 需允许 GatewayPorts
ssh -N -R 0.0.0.0:8080:localhost:3000 user@203.0.113.10

# 长期使用：cloudflared 命名隧道 + 自有域名
cloudflared tunnel login
cloudflared tunnel create myapp
cloudflared tunnel route dns myapp dev.example.com
cloudflared tunnel run --url http://localhost:3000 myapp

临时演示用 Quick Tunnel 或 ngrok；长期用命名隧道绑定自有域名并加访问控制。

📊 05 · 参数对比

穿透方案对比

方案是否需公网服务器优点注意事项
Cloudflare Tunnel否免费额度、可接入 Access 鉴权需域名托管在 Cloudflare（命名隧道）
ngrok否上手快，带请求检查面板免费版有限制，以官方为准
frp 自建是完全可控、协议灵活需自行维护与加固服务器
SSH -R是无需额外软件稳定性需配合 autossh 等
⚖️ 06 · 方案取舍

托管隧道（Cloudflare/ngrok）

优点零运维，自动 HTTPS

代价流量经第三方，受其策略约束

适用演示、Webhook 调试、小项目

自建 frp / SSH 中继

优点数据路径可控，可支持 TCP/UDP

代价需要 VPS 与安全维护

适用有服务器、需非 HTTP 协议

直接公网 IP + 端口映射

优点无中间层

代价暴露家庭网络，安全风险高

适用一般不推荐

🕳️ 07 · 常见坑

  • ✗把开发服务器（含调试模式）直接暴露公网

    ✓只暴露需要的服务，关闭调试模式，加身份验证

  • ✗临时隧道长期挂着当生产入口

    ✓生产使用正式部署；长期隧道用命名隧道加访问策略

  • ✗本地服务只信任 localhost 来源，经隧道后被绕过

    ✓经代理后所有请求都像来自本机，不要以来源地址作为鉴权依据

  • ✗调试 Webhook 时把签名校验关掉

    ✓保留签名校验，用服务商提供的测试密钥

🎤 09 · 面试追问
隧道为什么不需要开放入站端口？

因为连接方向是由内向外：本地代理主动连接服务商边缘并保持长连接，防火墙和 NAT 只看到普通的出站流量。外部请求到达边缘后，复用这条已建立的连接下发到本地，因此路由器无需端口映射。

暴露本地服务到公网有哪些安全风险？

开发服务器常开启调试接口、热更新端点和详细报错，可能泄露源码与密钥；本地应用若把来自 127.0.0.1 的请求视为可信，经隧道后外部请求同样显示为本机来源。应加认证、关调试、限时使用。

Webhook 开发为什么常用隧道？

支付、GitHub 等平台需要把事件推送到公网 HTTPS 地址，本地开发机无法直接接收。隧道提供临时公网地址，开发者可在本地断点调试回调逻辑；部分工具还能查看和重放请求。
