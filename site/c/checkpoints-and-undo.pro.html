检查点与撤回

Checkpoints & Undo

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

检查点与撤回（Checkpoints & Undo）指 AI 编码工具在 Agent 修改代码前后自动保存文件状态，允许用户把代码和对话回退到之前某一时刻的机制。它是 Agent 时代的“安全网”层，与 Git 互补：检查点粒度细、随会话自动生成，Git 则负责持久、可共享的版本历史。

⚙️ 02 · 原理
  1. 1

    Agent 每次通过编辑工具修改文件前，工具记录受影响文件的原始内容，形成与对话轮次关联的检查点。

  2. 2

    用户可选择回到某个检查点，仅恢复代码、仅恢复对话，或两者同时恢复。

  3. 3

    Claude Code 通过 /rewind 或连按两次 Esc 打开回退菜单；Cursor 在对话中提供恢复检查点按钮。

  4. 4

    通过 shell 命令产生的改动（如 rm、数据库迁移）通常不在检查点跟踪范围内，无法自动撤回。

  5. 5

    检查点是本地、会话级的，不替代 Git 提交；长期保存和协作仍依赖版本控制。

🔤 03 · 术语
检查点 (Checkpoint)
某一时刻文件状态的快照，可用于恢复。
/rewind
Claude Code 中回退代码和/或对话到先前状态的命令。
git stash
临时保存未提交改动并恢复干净工作区的 Git 命令。
git worktree
同一仓库检出多个工作目录，便于隔离并行任务。
副作用 (Side Effect)
文件之外的改动，如数据库写入、外部请求，检查点无法撤回。
💻 04 · 代码
用 Git 为 Agent 兜底bash
# 让 Agent 动手前先打一个可回退的点
git add -A && git commit -m "wip: before agent"

# 或在独立 worktree 中让 Agent 工作，主目录不受影响
git worktree add ../feat-paging -b feat/paging
cd ../feat-paging && claude

# 查看 Agent 改了什么
git diff --stat

# 不满意：丢弃全部未提交改动（不可恢复，谨慎）
git restore --staged --worktree .
git clean -fd          # 同时删除新建的未跟踪文件

# 满意：合并回主分支后清理 worktree
git worktree remove ../feat-paging

检查点之外的持久保护：先提交、隔离目录、看 diff、再决定保留或丢弃。

🕳️ 07 · 常见坑

  • ✗以为检查点能撤回 Agent 执行的删除命令

    ✓危险命令要求确认，并在沙箱或有备份的环境执行

  • ✗长时间不提交，只靠检查点

    ✓每完成一个可验证的小步就 Git 提交

  • ✗回退代码却忘了回退对话

    ✓同时回退对话，避免模型基于已撤销的改动继续

  • ✗Agent 直接连接生产数据库

    ✓只给开发库权限，迁移脚本人工审阅后执行

🎤 09 · 面试追问
检查点和 Git 有什么区别？

检查点由工具自动生成，粒度到每次编辑，绑定会话，便于快速试错回退；Git 由人主动提交，持久、可共享、可审查，是团队协作和发布的基础。检查点解决“刚才那步改坏了”，Git 解决“版本历史”。

为什么检查点无法撤回所有改动？

检查点通常只追踪工具自身编辑接口修改的文件。Agent 通过 shell 执行的命令可能删除文件、安装依赖、写数据库或调用外部服务，这些副作用不经过编辑接口，也可能根本不在文件系统内，因此无法自动恢复。

如何让 Agent 自主运行同时控制风险？

在容器或虚拟机等隔离环境中运行，限制网络和凭证；使用独立分支或 worktree；只开放开发环境资源；对不可逆命令设置确认或拦截；结束后由人审阅 diff 和执行记录再合并。
