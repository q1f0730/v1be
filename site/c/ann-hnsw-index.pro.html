近似最近邻索引 (ANN / HNSW)

ANN Index (HNSW)

📐 01 · 定义

近似最近邻（ANN）索引用少量精度换取数量级的检索加速，是向量数据库的核心。HNSW（Hierarchical Navigable Small World）是最常用的 ANN 图索引：把向量组织成多层近邻图，高层稀疏用于长距离跳转，底层稠密用于精细搜索，查询复杂度近似对数级，在召回率与延迟之间可通过参数调节。

⚙️ 02 · 原理
  1. 1

    插入时为每个向量随机抽取最高层级，层级服从指数衰减分布，因此越高层节点越少。

  2. 2

    从顶层入口点开始贪心搜索，逐层下降到新节点所在层，在每层找到候选近邻并建立双向边，每个节点边数受 M 限制。

  3. 3

    建图时的候选队列大小由 efConstruction 控制，越大图质量越高、建索引越慢。

  4. 4

    查询时同样从顶层贪心下降，在底层用大小为 efSearch 的优先队列做束搜索，返回 top-k。

  5. 5

    efSearch 越大召回率越高、延迟越高；必须不小于 k，通常按目标召回率实测调优。

  6. 6

    删除通常是标记删除，频繁删改会让图质量下降，需要定期重建或依赖引擎的修复机制。

🔤 03 · 术语
召回率 (Recall@k)
ANN 返回的 top-k 中与精确搜索 top-k 重合的比例，衡量近似质量。
M
HNSW 每个节点在各层保留的最大邻居数，影响内存、召回与建图速度。
efConstruction
建图时动态候选列表大小，越大图越好、构建越慢。
efSearch
查询时候选列表大小，是在线调节召回与延迟的主要旋钮。
IVF (Inverted File)
另一类 ANN：先聚类分桶，查询只扫描最近的若干桶。
乘积量化 (PQ)
把向量切段分别量化压缩，大幅降低内存，代价是精度损失。
💻 04 · 代码
pgvector 建 HNSW 索引sql
-- 需要已安装 pgvector 扩展
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE docs (
  id bigserial PRIMARY KEY,
  content text,
  embedding vector(1536)      -- 维度与所用嵌入模型一致
);

-- 余弦距离的 HNSW 索引；m / ef_construction 为 pgvector 默认值
CREATE INDEX ON docs
  USING hnsw (embedding vector_cosine_ops)
  WITH (m = 16, ef_construction = 64);

-- 会话级调大查询候选数以提高召回（默认 40）
SET hnsw.ef_search = 100;

SELECT id, content
FROM docs
ORDER BY embedding <=> '[0.01, 0.02, ...]'::vector  -- 替换为查询向量
LIMIT 5;

操作符类必须与查询用的距离运算符匹配（<=> 对应 cosine），否则索引不会被使用。

📊 05 · 参数对比

常见 ANN 索引对比

索引原理优势代价
Flat（暴力）逐个计算距离100% 精确数据量大时线性变慢
HNSW多层近邻图高召回、低延迟内存占用高，建图较慢
IVF聚类分桶后只查近桶建索引快、省内存召回依赖 nprobe，需训练
IVF-PQ分桶 + 乘积量化内存极省，适合超大规模精度损失明显，常需重排
⚖️ 06 · 方案取舍

调大 efSearch

优点召回率提升，无需重建索引

代价单次查询延迟和 CPU 增加

适用召回不达标且延迟有余量

调大 M

优点图连通性更好，高维数据召回更稳

代价内存与建图时间显著增加

适用高维、对召回要求严的场景

改用 IVF/PQ

优点内存成本大幅下降

代价精度下降，参数需训练调优

适用向量规模大到 HNSW 放不进内存

🕳️ 07 · 常见坑

  • ✗带 WHERE 过滤的向量查询结果数不足或召回骤降

    ✓了解引擎的过滤策略（先过滤/后过滤/迭代扫描），必要时分区或用支持过滤感知的索引

  • ✗只看延迟不测召回率

    ✓用暴力搜索结果做基准，离线计算 Recall@k 后再定参数

  • ✗索引距离类型与嵌入模型推荐的不一致

    ✓按模型文档选 cosine / 内积 / L2，并保证查询运算符一致

  • ✗大批量导入前先建 HNSW，导入极慢

    ✓先导入数据再建索引，并为建索引分配足够内存

🎤 09 · 面试追问
HNSW 为什么能做到近似对数级查询？

高层节点稀疏，边跨度大，贪心搜索几步就能接近目标区域；逐层下降后底层只需在局部做束搜索。层级按指数分布随机分配，期望层数与 log N 成正比，类似跳表思想在图上的推广。

RAG 召回差，你如何定位是 ANN 的问题？

先对同一批查询跑精确搜索，若精确结果也不对，问题在嵌入模型或切块；若精确正确而 ANN 漏掉，说明索引近似损失，调大 efSearch 或 M。还要检查过滤条件是否导致候选不足。

HNSW 和 IVF-PQ 如何选？

内存充足、追求高召回低延迟选 HNSW；向量规模极大、内存是瓶颈选 IVF-PQ，并常配合原始向量重排补精度。数据频繁删改时还要考虑 HNSW 图退化与重建成本。
