缓存命中率

Cache Hit Ratio

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

缓存命中率是命中次数占总访问次数的比例：命中数 ÷（命中数 + 未命中数）。它是衡量缓存有效性的核心指标，直接决定后端负载与平均延迟。适用于应用缓存（Redis、Memcached）、CDN 和数据库缓冲池。要结合未命中原因、按键空间拆分和字节命中率一起看。

⚙️ 02 · 原理
  1. 1

    每次访问缓存记一次命中或未命中，按时间窗口（如每分钟）计算比例并上报。

  2. 2

    平均延迟 ≈ 命中率 × 缓存延迟 +（1 − 命中率）× 回源延迟，未命中代价通常高出几个数量级。

  3. 3

    回源量 = 总请求 ×（1 − 命中率），命中率从 99% 降到 98%，回源量翻倍。

  4. 4

    未命中原因可分为冷启动、容量不足被淘汰、主动失效、键本身不可缓存。

  5. 5

    访问分布多呈长尾，少量热点键贡献大部分命中，容量增加的边际收益递减。

🔤 03 · 术语
命中 / 未命中 (Hit / Miss)
请求的数据在缓存中找到或找不到。
字节命中率 (Byte Hit Ratio)
按传输字节计算的命中率，CDN 常用。
冷未命中 (Cold Miss)
数据首次被访问、缓存中尚未存在。
容量未命中 (Capacity Miss)
缓存空间不足、数据被淘汰后造成的未命中。
keyspace_hits / misses
Redis INFO 中的命中与未命中计数。
工作集 (Working Set)
一段时间内被频繁访问的数据集合。
💻 04 · 代码
Redis 命中率与淘汰情况bash
#!/usr/bin/env bash
# 1. 计算自上次重置以来的整体命中率
redis-cli INFO stats | tr -d '\r' | awk -F: '
  /^keyspace_hits/   {h=$2}
  /^keyspace_misses/ {m=$2}
  /^evicted_keys/    {e=$2}
  END { printf "hits=%d misses=%d hit_ratio=%.2f%% evicted=%d\n", h, m, h*100/(h+m), e }'

# 2. 内存使用与上限，判断是否因容量不足而淘汰
redis-cli INFO memory | grep -E '^(used_memory_human|maxmemory_human):'

# 3. 重置统计计数，便于观察某次调整后的效果
# redis-cli CONFIG RESETSTAT

# 4. 抽样找出访问频率最高的键（需 LFU 淘汰策略）
redis-cli --hotkeys

# 注意：INFO 只给全局命中率；按业务前缀统计需在应用侧埋点
# 如 cache_requests_total{prefix="user", result="hit"}

evicted_keys 增长说明有容量未命中；按业务前缀拆分命中率需应用侧埋点。

⚖️ 06 · 方案取舍

加大缓存容量

优点直接减少容量未命中

代价长尾下边际收益递减，成本上升

适用evicted_keys 持续增长

延长 TTL

优点命中率提升明显

代价数据更旧，需配合主动失效

适用数据变化慢

改进缓存键设计

优点合并重复，提高复用

代价需要改代码

适用键含时间戳、随机参数等

🕳️ 07 · 常见坑

  • ✗只看全局命中率，掩盖某类关键数据命中极低

    ✓按键前缀或业务类型拆分统计

  • ✗缓存不存在的数据，空查询永远未命中

    ✓缓存空值（短 TTL）或使用布隆过滤器

  • ✗缓存键包含时间戳、追踪 ID 等易变参数

    ✓规范化键，只保留影响结果的参数

  • ✗只追求命中率，忽略数据新鲜度

    ✓命中率与过期数据比例一起设定目标

☑️ 08 · 检查清单
🎤 09 · 面试追问
命中率 95% 和 99% 差别大吗？

非常大。看未命中率：5% 对 1%，回源量相差 5 倍。若后端只能承受 1% 的回源，命中率跌到 95% 就可能压垮数据库。所以要盯住未命中率与回源 QPS，而不仅是看起来都很高的命中率。

命中率突然下降，如何排查？

看是否有发布改了缓存键或序列化格式；evicted_keys 是否上升（容量不足）；是否有批量失效或缓存节点重启（冷启动）；流量构成是否变化（爬虫访问长尾数据）；TTL 是否被改短。

CDN 的请求命中率和字节命中率有何不同？

请求命中率按请求数计算，小文件多时容易很高；字节命中率按流量计算，更直接对应回源带宽与费用。大文件未命中会显著拉低字节命中率，因此优化成本时更应关注后者。
