合并冲突

Merge Conflict

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

合并冲突（Merge Conflict）发生在 Git 无法自动整合两条分支对同一文件同一区域的不同修改时，或一方修改、另一方删除同一文件时。Git 会暂停操作，在文件中插入冲突标记，由人判断保留哪一方或如何组合。冲突本身不是错误，而是需要人类判断语义的信号。

⚙️ 02 · 原理
  1. 1

    找共同祖先：合并时 Git 找到两条分支的共同祖先提交（merge base）。

  2. 2

    三方比较：分别比较祖先与双方版本，只有一方改动的区域自动采纳。

  3. 3

    检测冲突：双方都改了同一区域且内容不同，Git 标记为冲突并暂停合并。

  4. 4

    插入标记：在文件中用 <<<<<<<、=======、>>>>>>> 包围双方版本，等待解决。

  5. 5

    完成合并：手动编辑为正确内容，git add 标记已解决，再提交或继续 rebase。

🔤 03 · 术语
三方合并 (Three-way Merge)
基于共同祖先与两方版本进行比较合并。
合并基点 (Merge Base)
两条分支最近的共同祖先提交。
ours / theirs
冲突中的当前分支版本与被合入的版本。
diff3 / zdiff3
冲突标记中额外显示祖先版本的样式，便于理解原意。
rerere
记录冲突解决方式，再遇相同冲突时自动复用。
💻 04 · 代码
解决冲突流程bash
git merge origin/main
# CONFLICT (content): Merge conflict in src/config.ts

git status                 # 列出所有冲突文件

# 文件中的冲突标记（启用 diff3 后会多出祖先版本）：
# <<<<<<< HEAD
# const TIMEOUT = 5000;
# ||||||| base
# const TIMEOUT = 3000;
# =======
# const TIMEOUT = 3000; const RETRIES = 3;
# >>>>>>> origin/main

# 编辑为正确的组合结果，删除所有标记后：
git add src/config.ts
npm test                   # 解决后务必跑测试
git commit                 # rebase 中则用 git rebase --continue

# 放弃本次合并，回到合并前
git merge --abort

# 推荐配置：显示祖先版本、记住解决方式
git config --global merge.conflictStyle zdiff3
git config --global rerere.enabled true

看懂祖先版本才能判断双方意图；解决后跑测试，因为无文本冲突不代表语义正确。

📊 05 · 参数对比

冲突类型与处理

类型原因处理方式
内容冲突双方改了同一行区域理解双方意图后手动组合
修改/删除冲突一方修改、一方删除文件决定保留修改或确认删除
锁文件冲突双方都改了依赖以一方为准后重新安装生成锁文件
语义冲突无文本冲突但逻辑互相破坏依靠测试与评审发现
⚖️ 06 · 方案取舍

手动逐块解决

优点精确，理解每处改动

代价冲突多时耗时

适用业务逻辑冲突

整体采用一方（--ours/--theirs）

优点快

代价可能丢失另一方的重要修改

适用生成文件或确定以一方为准

让 AI 协助解决

优点能快速理解双方并给出组合

代价可能误合并逻辑

适用冲突多但有测试兜底

🕳️ 07 · 常见坑

  • ✗冲突标记残留在代码里被提交

    ✓提交前搜索 <<<<<<< 标记，并让构建和测试兜底

  • ✗手动合并 package-lock.json 等锁文件

    ✓选定一方的清单后重新运行安装生成锁文件

  • ✗解决冲突后不跑测试直接提交

    ✓合并后运行完整测试，防止语义冲突

  • ✗长期分支积累大量冲突

    ✓缩短分支寿命，频繁同步主干

🎤 09 · 面试追问
没有文本冲突就说明合并正确吗？

不是。语义冲突时两边改动在不同行，Git 能自动合并，但组合后逻辑错误，例如一方重命名函数、另一方新增了对旧函数名的调用。只能靠编译、类型检查和测试发现，所以合并后必须跑完整测试。

rebase 时的 ours/theirs 为什么容易混淆？

rebase 是把你的提交逐个重放到目标分支上，此时「当前」是目标分支，所以 ours 指上游，theirs 才是你正在重放的提交，与 merge 时正好相反。解决时最好看内容而非依赖这两个名字。

如何从流程上减少冲突？

小而频繁的 PR、短生命周期分支、经常同步主干、明确模块归属、格式化工具统一风格避免格式噪声冲突、把容易冲突的生成文件排除在手工编辑之外，并行 Agent 尽量分配到不同文件或模块。
