无服务器 (Serverless)

📐 01 · 定义

Serverless（无服务器）是一种云计算模型：开发者只提交函数或容器，平台负责服务器供给、扩缩容和运维，按实际调用次数与执行时长计费，空闲时可缩容到零。函数即服务（FaaS）如 AWS Lambda、Vercel Functions、Cloudflare Workers 是其代表；数据库、队列等托管服务的按量模式也常被归入其中。

⚙️ 02 · 原理
  1. 1

    开发者编写处理函数并部署，平台把代码与依赖打包为可快速启动的运行单元。

  2. 2

    请求或事件（HTTP、队列消息、定时任务、文件上传）到达时，平台路由到空闲实例；没有空闲实例就新建，即冷启动。

  3. 3

    实例执行函数后可被保留一段时间复用（热启动），持续空闲则被回收；并发请求增多时平台横向扩出更多实例。

  4. 4

    函数应无状态：实例随时可能被回收，持久数据需存入数据库、对象存储或缓存。

  5. 5

    平台按调用次数和“内存 × 时长”等维度计费，并设有超时、内存、包大小与并发上限（如 Lambda 单次最长 15 分钟）。

🔤 03 · 术语
FaaS (Function as a Service)
以函数为单位部署和计费的无服务器形态。
冷启动 (Cold Start)
无可用实例时新建运行环境带来的额外延迟。
缩容到零 (Scale to Zero)
无流量时不保留实例，也不产生计算费用。
并发上限 (Concurrency Limit)
同时运行实例数的限制，超出会被限流。
边缘函数 (Edge Function)
在 CDN 边缘节点运行的轻量函数，常基于 V8 隔离。
事件源 (Event Source)
触发函数的来源，如 API 网关、队列、定时器。
💻 04 · 代码
AWS Lambda 处理 HTTP 请求python
import json
import os
import boto3

# 放在函数外：热启动时复用连接，减少冷启动后的开销
table = boto3.resource("dynamodb").Table(os.environ["TABLE_NAME"])

def lambda_handler(event, context):
    # 经 API Gateway / 函数 URL 触发时，body 为字符串
    body = json.loads(event.get("body") or "{}")
    if "id" not in body:
        return {"statusCode": 400, "body": json.dumps({"error": "id required"})}

    table.put_item(Item={"id": body["id"], "note": body.get("note", "")})
    # 无状态：不要把数据存在全局变量里指望下次还在
    return {
        "statusCode": 201,
        "headers": {"Content-Type": "application/json"},
        "body": json.dumps({"ok": True}),
    }

处理函数无状态，客户端在全局初始化以复用；持久数据写入托管数据库。

⚖️ 06 · 方案取舍

Serverless 函数

优点免运维、空闲零成本、自动扩容

代价冷启动、时长限制、厂商锁定

适用流量波动大、事件驱动、API 后端

长期运行的容器或 VM

优点无冷启动，可跑长任务和长连接

代价空闲也付费，需运维

适用稳定高负载、WebSocket、长任务

混合架构

优点各取所长

代价系统复杂度上升

适用核心服务常驻，突发任务用函数

🕳️ 07 · 常见坑

  • ✗每次调用都新建数据库连接，压垮数据库

    ✓使用连接池代理或 HTTP 型数据库驱动，并在全局复用客户端

  • ✗函数递归触发自身（如写入同一个触发桶）

    ✓分离输入输出资源，设置并发上限与预算告警

  • ✗把长时间任务塞进函数导致超时

    ✓拆分为队列任务或使用工作流编排、容器任务

  • ✗依赖包过大，冷启动很慢

    ✓精简依赖、按需导入，必要时用预置并发

🎤 09 · 面试追问
冷启动由哪些因素决定？

包括运行时类型（解释型语言通常较快，JVM 较慢）、部署包大小、初始化代码耗时、是否处于 VPC、内存配置（与 CPU 配额相关）。缓解方式有精简依赖、延迟初始化、预置并发或保持定时预热。

Serverless 一定更便宜吗？

不一定。低流量和波动流量时按需计费很省；但持续高负载下，按调用与时长计费可能高于同等容量的常驻实例。还要计入 API 网关、数据传输等附加费用，应按实际流量模型测算。

为什么说函数要无状态？

平台可随时回收或新建实例，同一用户的连续请求可能落到不同实例上，内存和本地磁盘里的数据不保证存在。会话、文件和计数器必须存入外部存储，函数只做计算，才能安全地水平扩展。
