模型路由

Model Routing

🧸 回到小白版

📐 01 · 定义

模型路由（Model Routing）是在 LLM 应用中根据请求的难度、类型、成本预算或延迟要求，把每次调用分派给最合适模型的策略层。简单请求走便宜快速的小模型，复杂推理走能力更强的大模型，失败时可升级或切换供应商。它位于应用与模型 API 之间，目标是在质量不明显下降的前提下降低成本与延迟。

⚙️ 02 · 原理
  1. 1

    定义候选模型池，记录各自的能力、价格、上下文长度、延迟与可用性。

  2. 2

    对请求提取特征：任务类型、输入长度、是否需要工具或视觉、用户套餐等。

  3. 3

    路由器根据这些特征，用规则、轻量分类器或小模型打分，决定首选模型。

  4. 4

    调用后可做质量检查（格式校验、置信度），不达标则升级到更强模型重试（级联）。

  5. 5

    持续记录每条路由的成本、延迟与评测分数，据此调整规则或重新训练路由器。

🔤 03 · 术语
级联 (Cascade)
先用便宜模型，不满足条件再逐级升级。
回退 (Fallback)
首选模型报错或限流时切换到备用模型或供应商。
路由分类器 (Router Classifier)
预测请求难度或类别以选择模型的轻量模型。
质量-成本前沿 (Pareto Frontier)
在给定成本下能达到的最佳质量曲线。
LLM 网关 (LLM Gateway)
统一代理多家模型 API，集中做路由、限流与计费。
💻 04 · 代码
规则路由 + 级联升级python
import json

SMALL, LARGE = "small-model", "large-model"   # 替换为实际模型名

def pick_model(task: str, prompt: str) -> str:
    if task in {"classify", "extract", "translate"} and len(prompt) < 4000:
        return SMALL
    if task in {"code", "plan", "math"}:
        return LARGE
    return SMALL

def valid(output: str) -> bool:
    try:
        json.loads(output)          # 要求结构化输出
        return True
    except ValueError:
        return False

def run(task: str, prompt: str, call_llm) -> str:
    model = pick_model(task, prompt)
    out = call_llm(model, prompt)
    if model == SMALL and not valid(out):
        out = call_llm(LARGE, prompt)   # 级联：小模型不达标就升级
    return out
# call_llm(model, prompt) 由你接入具体 SDK；记录每次的模型、token 与是否升级

先用规则把明显简单的任务交给小模型，用可校验的输出决定是否升级。

📊 05 · 参数对比

路由策略对比

策略实现成本效果风险
静态规则低取决于任务划分是否清晰边界请求分错
分类器路由中可学习难度分布需要标注数据
级联升级低到中质量有兜底失败请求延迟翻倍
供应商回退低提升可用性不同模型行为不一致
⚖️ 06 · 方案取舍

全部用最强模型

优点质量最稳，实现简单

代价成本和延迟最高

适用流量小或质量要求极高

按任务静态路由

优点可预期，易调试

代价无法适应同类任务的难度差异

适用任务类型清晰的产品

动态路由/级联

优点成本与质量兼顾

代价需评测体系与监控

适用流量大、成本敏感

🕳️ 07 · 常见坑

  • ✗没有评测就上路由，质量下降无人察觉

    ✓按路由分支分别评测，并对比全用大模型的基线

  • ✗同一提示词直接套用不同模型

    ✓为各模型调整提示词与输出格式要求

  • ✗回退模型能力差太多，静默降低质量

    ✓记录回退事件并告警，关键任务宁可报错重试

  • ✗路由本身用大模型判断，成本反而更高

    ✓路由器用规则或轻量模型，开销远小于节省

🎤 09 · 面试追问
如何判断一个请求该用小模型？

离线用评测集同时跑大小模型，标出小模型也能做对的样本，提取其特征（任务类型、长度、关键词）形成规则或训练分类器；线上再用可验证的输出（格式、测试通过）兜底升级。

级联路由的主要代价是什么？

被升级的请求要先等小模型失败，延迟叠加，且付了两次费用；若小模型失败率高，总成本可能高于直接用大模型。需监控升级率并调整入口规则。

多供应商回退要注意什么？

统一抽象接口与错误分类，区分可重试错误（限流、超时）与不可重试错误；各模型的工具调用格式、上下文长度、安全策略不同，要分别测试；数据合规上确认每家供应商都允许处理该数据。
