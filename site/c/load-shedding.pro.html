负载卸载 / 主动弃载

Load Shedding

📐 01 · 定义

负载卸载（Load Shedding）是服务在接近容量极限时主动拒绝一部分请求，以保证其余请求仍能在延迟目标内完成的过载保护手段。它位于服务入口或中间件层，核心思想是快速失败优于全部变慢：拒绝的成本远低于处理一个最终会超时的请求，从而避免吞吐崩塌（goodput 下降）。

⚙️ 02 · 原理
  1. 1

    服务持续度量负载信号，如在途请求数、队列长度、排队时间或 CPU 使用率。

  2. 2

    信号超过阈值时，新请求在最早阶段被拒绝，通常返回 503 或 429 并可带 Retry-After。

  3. 3

    可按优先级卸载：健康检查、付费用户、关键写操作保留，批处理和低优先级先丢。

  4. 4

    对已在队列中等待过久、客户端大概率已超时的请求直接丢弃，不再浪费算力。

  5. 5

    客户端收到拒绝后配合退避重试，或降级显示，形成端到端的过载控制。

🔤 03 · 术语
有效吞吐 (Goodput)
在时限内成功完成、对用户有价值的请求吞吐量。
并发限制 (Concurrency Limit)
同时处理的请求数上限，超出即排队或拒绝。
请求优先级 (Criticality)
给请求打的重要程度标签，过载时决定先丢谁。
截止时间传播 (Deadline Propagation)
把客户端剩余超时随请求传下去，过期即放弃处理。
Retry-After
HTTP 响应头，告诉客户端多久后再重试。
💻 04 · 代码
ASGI 并发限制卸载python
import asyncio

class ShedMiddleware:
    """在途请求超过上限时直接返回 503"""
    def __init__(self, app, max_inflight: int = 200):
        self.app = app
        self.sem = asyncio.Semaphore(max_inflight)

    async def __call__(self, scope, receive, send):
        if scope["type"] != "http" or scope["path"] == "/healthz":
            return await self.app(scope, receive, send)  # 探针不卸载
        if self.sem.locked():                           # 已满，快速失败
            await send({"type": "http.response.start", "status": 503,
                        "headers": [(b"retry-after", b"1")]})
            await send({"type": "http.response.body", "body": b"overloaded"})
            return
        async with self.sem:
            await self.app(scope, receive, send)

一个可套在 FastAPI/Starlette 外层的纯 ASGI 中间件，超并发时立刻返回 503。

⚖️ 06 · 方案取舍

固定并发上限

优点实现简单，行为可预测

适用负载形态稳定的服务

自适应并发限制

优点随延迟变化自动调整

优点保护核心业务

🕳️ 07 · 常见坑

  • ✗卸载逻辑放在请求处理很深的位置，拒绝前已花掉大量资源。

    ✓在入口最早阶段判断并拒绝。

  • ✗连健康检查一起拒绝，编排系统误判实例死亡并重启，雪上加霜。

    ✓探针请求绕过卸载，或单独端口处理。

  • ✗返回 503 但客户端立即无退避重试，负载反而翻倍。

    ✓带 Retry-After，客户端使用退避和重试预算。

🎤 09 · 面试追问
为什么过载时拒绝请求反而提高可用性？

超过容量后所有请求共享资源，排队延迟飙升，大部分请求都超时，有效吞吐趋近于零。卸载把一部分请求快速拒掉，剩余请求在时限内完成，goodput 保持在接近容量的水平。

负载卸载和限流有何不同？

限流通常按调用方配额控制，即使服务空闲也会拒绝超额者，偏公平与防滥用；负载卸载依据服务自身健康信号，只在过载时触发，偏自我保护。两者常一起使用。

如何为卸载设置阈值？

通过压测找出延迟开始急剧上升的并发拐点，留出余量设上限；结合排队时间信号；上线后用指标观察拒绝率与延迟，逐步调整，或采用自适应并发算法。
