DNS缓存传播延迟

DNS Propagation

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

所谓 DNS 传播（DNS Propagation）并不是变更被主动推送到全网，而是各级缓存（递归解析器、操作系统、浏览器）在旧记录的 TTL 到期前继续返回旧值。修改记录后，不同用户在不同时间看到新值。理解 TTL 与缓存层级，才能把切换窗口控制到可预期。

⚙️ 02 · 原理
  1. 1

    权威 DNS 服务器保存记录及其 TTL，修改后权威端立即返回新值。

  2. 2

    递归解析器（运营商、8.8.8.8、1.1.1.1）按 TTL 缓存答案，到期前不会重新查询。

  3. 3

    操作系统、浏览器和应用运行时也有各自的缓存，部分客户端不严格遵守 TTL。

  4. 4

    更换 NS（换 DNS 服务商）还受上级注册局委派记录的 TTL 影响，通常更久。

  5. 5

    查询不存在的记录也会被缓存（负缓存），时长由 SOA 记录决定。

🔤 03 · 术语
TTL (Time To Live)
记录可被缓存的秒数。
权威服务器 (Authoritative Server)
持有域名区域数据的最终来源。
递归解析器 (Recursive Resolver)
替客户端逐级查询并缓存结果的服务器。
负缓存 (Negative Caching)
缓存“记录不存在”的结果，见 RFC 2308。
NS 委派 (Delegation)
上级区域用 NS 记录指明子域由谁负责。
SOA 记录
区域起始授权记录，含序列号与负缓存时长等。
💻 04 · 代码
切换前后的 DNS 排查bash
# 1. 查当前记录与剩余 TTL（第二列为秒）
dig +noall +answer api.example.com A

# 2. 直接问权威服务器，确认改动已生效
dig +short NS example.com
dig @ns1.example-dns.com api.example.com A +norecurse

# 3. 对比几家公共解析器的缓存状态
for r in 8.8.8.8 1.1.1.1 223.5.5.5; do
  echo "$r -> $(dig @$r +short api.example.com A)"
done

# 4. 从根开始逐级追踪委派路径（换 NS 时尤其有用）
dig +trace api.example.com

# 5. 本机缓存：macOS 清缓存
sudo dscacheutil -flushcache; sudo killall -HUP mDNSResponder
# Linux（systemd-resolved）
resolvectl flush-caches

先问权威确认改动，再看各解析器缓存；dig +trace 排查委派问题。

📊 05 · 参数对比

影响生效时间的因素

因素影响可控性
记录 TTL解析器最长缓存时长可控：变更前提前调低
NS 委派 TTL换服务商时的延迟由注册局决定，常为数小时到两天
负缓存 TTL新增记录前被查过则延迟可控：SOA 中设置
客户端缓存浏览器/OS/JVM 自有缓存部分可控，需应用配置
⚖️ 06 · 方案取舍

长 TTL（数小时）

优点查询少、解析快，抗权威故障

代价切换慢，出错回滚也慢

适用长期稳定的记录

短 TTL（数十秒到几分钟）

优点切换和回滚快

代价查询量与延迟增加

适用迁移窗口或故障切换记录

不改 DNS，改后端指向

优点切换即时生效

代价需要负载均衡或 Anycast 层

适用频繁切换的生产流量

🕳️ 07 · 常见坑

  • ✗切换当天才把 TTL 调低

    ✓至少提前一个旧 TTL 周期调低，等旧缓存过期

  • ✗切换后立刻下线旧服务器

    ✓保留旧服务直到旧 TTL 过期且流量归零

  • ✗上线前反复查询尚未创建的记录

    ✓注意负缓存，必要时降低 SOA 负缓存时长

  • ✗Java 等运行时永久缓存 DNS，切换后连旧 IP

    ✓配置运行时 DNS 缓存时长，如 networkaddress.cache.ttl

🎤 09 · 面试追问
为什么说“DNS 传播”这个说法不准确？

DNS 没有把变更推送出去的机制。权威端修改即生效，各处看到旧值是因为解析器和客户端缓存未过期。生效时间由旧记录的 TTL 和缓存行为决定，所以要提前降 TTL，而不是等它“传播”。

迁移服务器时如何安排 DNS 切换？

提前一个以上旧 TTL 周期把记录 TTL 降到较短值；新服务准备好后修改记录；用权威查询与多家解析器验证；新旧服务并行运行直到旧流量消失；确认稳定后恢复正常 TTL。

换 DNS 服务商为什么比改 A 记录慢？

换服务商要修改注册局中的 NS 委派，解析器缓存的是上级区域返回的 NS 记录，其 TTL 由注册局设定，常比普通记录长。期间新旧服务商都应保持相同的完整记录，避免解析失败。
