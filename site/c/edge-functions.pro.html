边缘函数 (Edge Functions)

Edge Functions

📐 01 · 定义

边缘函数（Edge Functions）是部署在 CDN 或边缘网络众多节点上的轻量无服务器函数，请求在离用户最近的节点执行。它属于部署与网络层，多基于 V8 isolate 等轻量运行时，启动快、冷启动低，但 API 与资源受限。代表有 Cloudflare Workers、Vercel Edge Functions/Middleware、Deno Deploy、Supabase Edge Functions，常用于鉴权、重定向、个性化与 A/B。

⚙️ 02 · 原理
  1. 1

    开发者编写处理 Request、返回 Response 的函数，平台把代码分发到全球边缘节点。

  2. 2

    用户请求经 Anycast/DNS 路由到最近节点，在该节点的隔离环境中执行函数。

  3. 3

    函数可读取请求头、Cookie 与平台提供的地理信息，决定重写、重定向、直接响应或回源。

  4. 4

    运行时多为 Web 标准 API（fetch、Request、Response、Web Crypto），通常不支持完整 Node.js 内置模块与原生扩展。

  5. 5

    需要数据时访问边缘 KV、全球分布式数据库或回源；访问单区域数据库会引入跨地域往返延迟。

🔤 03 · 术语
V8 Isolate
同一进程内相互隔离的轻量 JS 执行环境，启动远快于容器。
Anycast
多个节点共享同一 IP，网络把用户路由到最近节点。
边缘中间件 (Edge Middleware)
在请求到达页面或 API 前运行的边缘逻辑。
边缘 KV (Edge KV)
在边缘节点间复制的键值存储，读快、写入最终一致。
回源 (Origin Fetch)
边缘节点向源站请求内容或数据。
💻 04 · 代码
Cloudflare Worker 按国家跳转javascript
// 使用 Workers 的 ES Module 语法，部署：npx wrangler deploy
const LANG_BY_COUNTRY = { CN: "zh", TW: "zh", JP: "ja", DE: "de" };

export default {
  async fetch(request) {
    const url = new URL(request.url);
    // 已在语言路径下则直接回源，避免循环跳转
    if (/^\/(zh|ja|de|en)(\/|$)/.test(url.pathname)) {
      return fetch(request);
    }
    // request.cf 由 Cloudflare 注入，包含访问者国家代码
    const country = request.cf?.country ?? "US";
    const lang = LANG_BY_COUNTRY[country] ?? "en";
    url.pathname = `/${lang}${url.pathname}`;
    return Response.redirect(url.toString(), 302);
  },
};

地理判断在最近节点完成，无需回源；国家代码来自平台注入的 request.cf。

📊 05 · 参数对比

边缘函数 vs 区域无服务器函数

维度边缘函数区域无服务器函数
执行位置全球众多节点选定的一个或几个区域
冷启动通常很低可能较明显
运行时能力Web 标准 API，限制较多完整语言运行时
数据访问离单区域数据库远可与数据库同区域
⚖️ 06 · 方案取舍

边缘函数

优点全球低延迟、冷启动低

代价运行时受限，访问中心数据库慢

适用鉴权、重定向、个性化、A/B

区域无服务器函数

优点完整运行时，靠近数据库

代价远端用户延迟较高

适用业务 API、数据库密集逻辑

边缘 + 区域混合

优点边缘做轻逻辑，重活回源

代价架构更复杂

适用全球用户的 Web 应用

🕳️ 07 · 常见坑

  • ✗在边缘函数中多次查询单区域数据库

    ✓把数据库逻辑放在靠近数据库的区域函数，或使用边缘缓存/复制数据

  • ✗引入依赖 Node 内置模块的库导致运行失败

    ✓选择支持 Web 标准运行时的库，部署前在对应运行时测试

  • ✗在边缘做 CPU 密集计算

    ✓边缘通常有 CPU 时间限制，重计算移到区域函数或队列

  • ✗把密钥硬编码在边缘代码中

    ✓使用平台的 Secret/环境变量绑定

🎤 09 · 面试追问
什么时候不适合用边缘函数？

逻辑需要多次访问单一区域的数据库、依赖完整 Node API 或原生模块、CPU 密集或长时间运行时。此时用区域函数或容器，边缘只做前置的轻逻辑。

V8 isolate 为什么冷启动快？

多个 isolate 运行在同一进程中，无需为每个函数启动容器或虚拟机与完整运行时，只需创建隔离的堆和上下文，开销远小于容器冷启动。

边缘 KV 的一致性如何？

通常读多写少、写入在全球传播需要时间，属于最终一致；不适合需要强一致的计数或库存。强一致需求可用 Durable Objects 一类单点协调对象或中心数据库。
