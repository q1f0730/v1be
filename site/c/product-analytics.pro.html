产品埋点与事件分析

Product Analytics

📐 01 · 定义

产品分析（Product Analytics）通过埋点采集用户在产品中的行为事件，结合用户属性做漏斗、留存、路径与分群分析，回答「用户怎么用、在哪流失、哪个改动有效」。它属于数据层与增长体系，核心工件是追踪计划（Tracking Plan）；PostHog、Mixpanel、Amplitude、GA4 是常见工具。

⚙️ 02 · 原理
  1. 1

    定义问题与指标（如激活率、付费转化），据此编写追踪计划：事件名、属性、触发时机、负责人。

  2. 2

    在客户端或服务端调用 SDK 上报事件，携带匿名 ID；用户登录后通过 identify 关联到真实用户 ID。

  3. 3

    事件进入分析平台或数据仓库，按时间、用户与属性建模。

  4. 4

    分析：漏斗看逐步转化，留存看同期群回访，路径看行为序列，分群对比不同用户。

  5. 5

    结论驱动产品决策，并通过 A/B 测试验证因果，而非只看相关性。

🔤 03 · 术语
追踪计划 (Tracking Plan)
列明所有事件、属性与含义的规范文档，是埋点的单一事实来源。
漏斗 (Funnel)
按顺序统计用户在各步骤的转化与流失。
同期群留存 (Cohort Retention)
按首次使用时间分组，观察各组后续回访比例。
身份关联 (Identify)
把匿名访客 ID 与登录用户 ID 合并为同一用户。
北极星指标 (North Star Metric)
最能反映产品为用户创造价值的核心指标。
💻 04 · 代码
用 PostHog 上报关键事件javascript
// npm install posthog-js
import posthog from "posthog-js";

posthog.init("<项目 API Key>", {
  api_host: "https://us.i.posthog.com", // 按你所在区域填写
});

// 登录后关联身份：匿名期间的事件会归到该用户
function onLogin(user) {
  posthog.identify(user.id, { plan: user.plan }); // 不传邮箱、手机号等敏感信息
}

// 事件命名统一为「对象_动作」，属性只放分析需要的字段
function onCheckoutStart(cart) {
  posthog.capture("checkout_started", {
    item_count: cart.items.length,
    cart_value: cart.total,
    source_page: location.pathname,
  });
}

// 付费成功等关键事件最好在服务端再上报一次，避免广告拦截导致丢失

事件名与属性需与追踪计划一致；关键转化事件建议服务端上报，客户端可能被拦截。

📊 05 · 参数对比

客户端与服务端埋点

方式优点缺点适合事件
客户端 SDK能采集交互细节可被拦截、可伪造页面浏览、点击
服务端上报可靠、可信看不到前端交互注册、支付、订阅
自动采集零配置覆盖广噪声大、语义弱探索性分析
⚖️ 06 · 方案取舍

SaaS 分析平台

优点开箱即用的漏斗与留存

代价费用随事件量增长，数据在第三方

适用早中期团队

自托管或数仓建模

优点数据自有、可深度定制

代价需数据工程投入

适用合规要求高或规模大

少而精的埋点

优点数据干净，易维护

代价临时问题可能缺数据

适用以明确问题驱动

🕳️ 07 · 常见坑

  • ✗没有追踪计划，事件命名五花八门

    ✓统一命名规范，变更走评审并同步文档

  • ✗在事件属性里上报邮箱、手机号等 PII

    ✓只传内部 ID，按隐私法规获取同意

  • ✗登录前后用户被算成两个人

    ✓登录时调用 identify，退出时 reset

  • ✗把相关性当因果做决策

    ✓关键改动用 A/B 测试验证

🎤 09 · 面试追问
如何设计一个新功能的埋点？

先明确要回答的问题和成功指标；梳理用户路径，选出关键步骤事件；为每个事件定义必要属性与触发条件；写入追踪计划并评审；上线后用实时调试工具与数据校验确认上报正确。

漏斗转化突然下降，你怎么排查？

先排除数据问题：埋点是否被改、SDK 版本、广告拦截、身份合并；再按渠道、设备、版本、地区分群定位；对照发布记录与实验；最后结合会话回放或用户反馈找到体验原因。

产品分析如何兼顾隐私合规？

数据最小化，只采集必要字段；不上报 PII 或做脱敏；按地区法规获取同意并支持撤回与删除；设置数据保留期限；选择支持数据驻留或自托管的方案。
