版本库分支保护规则

Branch Protection

📐 01 · 定义

分支保护（Branch Protection）是代码托管平台对指定分支（通常是 main 或 release/*）施加的写入规则，如必须通过 Pull Request、必须有审批、必须通过 CI 状态检查、禁止强制推送和删除。它属于代码治理与软件供应链层，保证进入主干的每次变更都经过审查与验证。

⚙️ 02 · 原理
  1. 1

    管理员为匹配模式的分支配置规则，GitHub 中可用经典分支保护或更新的规则集（Rulesets）。

  2. 2

    直接 push 到受保护分支被拒绝，变更必须通过 Pull Request 合并。

  3. 3

    合并前需满足条件：指定数量的批准、CODEOWNERS 审查、所需 CI 检查全部通过。

  4. 4

    可要求分支与目标保持最新、线性历史、签名提交，并在新提交后撤销旧批准。

  5. 5

    规则可选择是否对管理员生效，并可为自动化账号或应急场景设置受控的绕过名单。

🔤 03 · 术语
必需状态检查 (Required Status Checks)
合并前必须通过的 CI 检查项。
CODEOWNERS
按路径指定负责人，相关改动需其审批。
规则集 (Rulesets)
GitHub 新一代分支/标签保护机制，可多层叠加。
合并队列 (Merge Queue)
按序在最新主干上验证并合并 PR，避免语义冲突。
强制推送 (Force Push)
改写远端历史的推送，受保护分支通常禁止。
💻 04 · 代码
用 GitHub API 设置保护bash
# 需要仓库管理员权限；OWNER/REPO 替换为实际值
gh api -X PUT repos/OWNER/REPO/branches/main/protection \
  -H "Accept: application/vnd.github+json" \
  --input - <<'JSON'
{
  "required_status_checks": {
    "strict": true,
    "contexts": ["ci/test", "ci/lint"]
  },
  "enforce_admins": true,
  "required_pull_request_reviews": {
    "required_approving_review_count": 1,
    "dismiss_stale_reviews": true,
    "require_code_owner_reviews": true
  },
  "restrictions": null,
  "allow_force_pushes": false,
  "allow_deletions": false
}
JSON

要求 CI 通过、至少一人批准与代码所有者审查，管理员同样受约束，禁止强推与删除。

📊 05 · 参数对比

常用保护规则

规则防止什么注意点
必须经 PR 合并未审查的直接推送自动化账号需单独授权
必需审批 + 撤销过期批准批准后偷偷追加改动小团队审批人数要现实
必需状态检查测试失败的代码进主干检查名变更需同步更新
禁止强推与删除历史被改写或分支丢失应急恢复需管理员流程
⚖️ 06 · 方案取舍

规则对管理员生效

优点没有人能绕过审查

代价紧急修复流程变慢

适用生产代码、合规要求高

允许指定账号绕过

优点发布机器人可自动推送

代价绕过账号成为攻击目标

适用自动化发布，需最小权限

启用合并队列

优点保证主干始终可构建

代价合并有排队延迟

适用PR 多、主干频繁变动

🕳️ 07 · 常见坑

  • ✗设置了必需检查但检查名写错，规则形同虚设或永远卡住

    ✓从最近一次 CI 运行中复制确切检查名，并验证生效

  • ✗批准后作者继续推送未审代码

    ✓开启新提交时撤销过期批准

  • ✗只保护 main，release 分支可随意推送

    ✓用通配模式覆盖所有发布分支

  • ✗让 AI Agent 拥有绕过保护的 token

    ✓Agent 只能开 PR，合并由人或受控流程完成

🎤 09 · 面试追问
strict 状态检查（要求分支最新）有什么作用？

保证 CI 是在合并了最新主干后的代码上通过的，避免两个各自通过的 PR 合在一起后出错。代价是需要频繁更新分支，PR 多时可用合并队列代替。

分支保护和 CODEOWNERS 如何配合？

CODEOWNERS 按路径声明负责人；开启「要求代码所有者审查」后，改动这些路径的 PR 必须有对应负责人批准，适合保护基础设施、支付、权限等敏感目录。

AI 编码 Agent 接入仓库时如何设计权限？

给 Agent 使用最小权限的令牌，只允许推送到自己的分支并创建 PR；主干保护规则强制人工审查与 CI 通过；禁止其修改 CI 配置与保护规则，敏感路径加 CODEOWNERS。
