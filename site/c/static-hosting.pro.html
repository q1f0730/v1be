静态网站托管

Static Hosting

🧸 回到小白版

📐 01 · 定义

静态网站托管（Static Hosting）是把预先生成好的 HTML、CSS、JS、图片等文件放到存储和 CDN 上直接分发的部署方式，服务器不在请求时执行业务代码。它属于交付层，适合文档站、博客、单页应用（SPA）和静态生成站点，具有成本低、易扩展、攻击面小的特点。

⚙️ 02 · 原理
  1. 1

    构建工具（Vite、Next.js 静态导出、Astro 等）把源码编译为纯静态文件，输出到 dist 等目录。

  2. 2

    托管平台把文件上传到对象存储，并分发到全球 CDN 边缘节点缓存。

  3. 3

    用户请求时由最近的边缘节点直接返回文件，无需访问源站应用服务器。

  4. 4

    带内容哈希的资源文件可设置长期缓存；HTML 设置短缓存或协商缓存，保证发布后及时更新。

  5. 5

    SPA 需配置回退规则，把未知路径重写到 index.html，由前端路由接管。

🔤 03 · 术语
CDN (内容分发网络)
在全球边缘节点缓存内容，就近响应用户请求。
SSG (静态站点生成)
构建时预渲染出全部页面的 HTML。
SPA 回退 (SPA Fallback)
未匹配文件的路径返回 index.html，交给前端路由。
缓存失效 (Cache Invalidation)
发布后让 CDN 丢弃旧缓存的操作或策略。
内容哈希 (Content Hash)
文件名中包含内容指纹，内容变则文件名变，可长期缓存。
💻 04 · 代码
发布到 Cloudflare Pagesbash
# 1. 构建静态产物到 dist/
npm run build

# 2. SPA 回退：Cloudflare Pages 在无 404.html 时默认回退到 index.html
#    Netlify 则需在 dist/_redirects 写入：/*  /index.html  200

# 3. 为带哈希的静态资源设置长缓存（Cloudflare Pages / Netlify 的 _headers）
cat > dist/_headers <<'EOF'
/assets/*
  Cache-Control: public, max-age=31536000, immutable
EOF

# 4. 用 Wrangler 直接上传（项目名自定）
npx wrangler pages deploy dist --project-name=my-site

_headers 为 Cloudflare Pages/Netlify 配置文件；首次需 wrangler login。

📊 05 · 参数对比

静态 vs 服务端渲染

维度静态托管服务端渲染
请求时计算无每次请求执行代码
成本与扩展低，CDN 天然扩展随流量增加计算资源
动态数据前端调用 API 获取服务端直接渲染
SEOSSG 良好，纯 SPA 较弱良好
⚖️ 06 · 方案取舍

纯静态 SSG

优点最快、最便宜、最安全

代价内容更新需重新构建

适用文档、博客、营销页

SPA + 后端 API

优点交互丰富，前后端分离

代价首屏与 SEO 较弱

适用登录后的应用后台

静态 + 边缘函数

优点保留静态优势，补少量动态

代价平台相关性增强

适用需要表单、鉴权等少量逻辑

🕳️ 07 · 常见坑

  • ✗把 API 密钥写进前端代码再托管

    ✓静态文件对所有人可见，密钥放在后端或边缘函数

  • ✗SPA 刷新子路径出现 404

    ✓配置回退规则把路径重写到 index.html

  • ✗index.html 也设置一年缓存

    ✓HTML 用短缓存或 no-cache，只对哈希资源长缓存

  • ✗构建时环境变量当成运行时配置

    ✓静态构建会把变量写死，换环境需重新构建

🎤 09 · 面试追问
为什么静态站点比动态站点更安全？

请求时没有服务端代码执行，也没有数据库直连，SQL 注入、远程代码执行等服务端攻击面大幅减少。剩余风险主要在前端（XSS、依赖供应链）和调用的第三方 API 上，以及误把密钥打包进前端产物。

静态托管如何处理缓存与更新？

资源文件名带内容哈希，设置长期 immutable 缓存；HTML 不带哈希，使用 no-cache 或短 max-age，每次发布后浏览器重新获取 HTML，进而引用新文件名的资源。这样既快又不会出现新旧版本混用。

“静态”网站能有登录和表单吗？

可以。页面是静态的，动态能力通过前端调用外部 API、BaaS 服务或平台的边缘函数实现。静态指的是托管方式不在请求时渲染页面，不代表应用没有交互和数据。
