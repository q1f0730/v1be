📐 01 · 定义

后端（Backend）是运行在服务器上、用户不可见的那部分系统，负责业务逻辑、数据存取、身份认证与权限、与第三方服务集成，并通过 API 向前端提供数据。它关注正确性、安全、性能、可扩展性与可观测性，常用语言包括 Node.js、Python、Go、Java 等。

⚙️ 02 · 原理
  1. 1

    接收请求：Web 服务器或框架监听端口，接收 HTTP 请求并按路由分发到处理函数。

  2. 2

    中间件处理：依次执行日志、鉴权、限流、请求体解析、参数校验等通用逻辑。

  3. 3

    业务逻辑：执行核心规则，如下单扣库存、计算价格、调用模型 API。

  4. 4

    数据访问：读写数据库、缓存或对象存储，必要时使用事务保证一致性。

  5. 5

    返回响应：序列化为 JSON 并附状态码返回；记录日志与指标供监控。

🔤 03 · 术语
路由 (Routing)
把 URL 和 HTTP 方法映射到具体处理函数的规则。
中间件 (Middleware)
请求处理链中的可插拔环节，如鉴权、日志。
ORM
对象关系映射，用代码对象操作数据库表，如 Prisma、SQLAlchemy。
无状态服务 (Stateless)
不在进程内保存会话状态，便于水平扩展。
可观测性 (Observability)
通过日志、指标、链路追踪了解系统运行状况。
💻 04 · 代码
最小 FastAPI 后端python
# pip install fastapi uvicorn ；运行：uvicorn main:app --reload
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()
TODOS: dict[int, str] = {}          # 演示用内存存储，生产应换数据库

class TodoIn(BaseModel):
    title: str = Field(min_length=1, max_length=100)   # 自动参数校验

@app.post("/api/todos", status_code=201)
def create_todo(todo: TodoIn):
    new_id = len(TODOS) + 1
    TODOS[new_id] = todo.title
    return {"id": new_id, "title": todo.title}

@app.get("/api/todos/{todo_id}")
def get_todo(todo_id: int):
    if todo_id not in TODOS:
        raise HTTPException(status_code=404, detail="not found")
    return {"id": todo_id, "title": TODOS[todo_id]}

路由、参数校验、状态码、错误处理是后端接口的四个基本要素，FastAPI 会自动生成 /docs 文档。

📊 05 · 参数对比

后端架构选项

架构特点适合
单体 (Monolith)一个应用包含全部功能早期产品、小团队
微服务按业务拆分独立部署大团队、复杂业务
Serverless 函数按请求运行，免管服务器流量波动大、轻量接口
BaaS（如 Supabase、Firebase）托管数据库、鉴权与存储快速原型、前端主导项目
⚖️ 06 · 方案取舍

自建后端服务

优点完全可控，逻辑灵活

代价需运维、安全责任自负

适用复杂业务或特殊需求

BaaS 托管后端

优点上手极快，省去基础设施

代价供应商锁定，复杂逻辑受限

适用MVP、个人项目

Serverless

优点按量付费、自动扩缩

代价冷启动、执行时长受限

适用事件驱动、低频接口

🕳️ 07 · 常见坑

  • ✗信任前端传来的价格、用户 ID 等关键字段

    ✓服务端根据会话身份和数据库重新计算与校验

  • ✗把报错堆栈和 SQL 原样返回给客户端

    ✓对外返回通用错误信息，细节只写入服务端日志

  • ✗BaaS 数据库未配置行级权限就上线

    ✓启用并测试行级安全策略，确保用户只能访问自己的数据

  • ✗没有日志和监控，出问题只能猜

    ✓结构化日志、错误告警、关键接口指标从第一天就配置

🎤 09 · 面试追问
认证和授权有什么区别？

认证（Authentication）确认「你是谁」，如密码、MFA、OAuth 登录；授权（Authorization）决定「你能做什么」，如只能访问自己的订单。常见漏洞是只做了认证却没检查资源归属，导致越权访问（IDOR）。

为什么后端要设计成无状态？

无状态服务不在内存中保存会话，状态放在数据库、缓存或客户端令牌中，任何实例都能处理任何请求，从而可以随意增减实例、负载均衡和故障转移。

AI 生成的后端代码评审重点？

鉴权与资源归属检查、SQL 注入与参数校验、密钥是否硬编码、错误处理是否泄露信息、并发与事务正确性、依赖是否真实可信、是否有分页和限流，以及数据库权限策略。
