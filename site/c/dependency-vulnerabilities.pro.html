依赖项已知漏洞

Dependency Vulnerabilities

📐 01 · 定义

依赖项已知漏洞指项目直接或间接引入的第三方包中已被公开披露的安全缺陷（通常有 CVE 或 GHSA 编号）。现代项目的传递依赖往往成百上千，治理目标是持续发现、评估可利用性、按优先级升级或缓解，而非追求扫描结果清零。

⚙️ 02 · 原理
  1. 1

    包管理器根据清单与锁文件解析出完整依赖树，其中多数是传递依赖。

  2. 2

    扫描器把依赖树中的包名与版本，与 OSV、GitHub Advisory、NVD 等漏洞库比对。

  3. 3

    命中后按 CVSS 严重度、是否在野利用（如 CISA KEV）、EPSS 概率和代码可达性排序。

  4. 4

    修复方式：升级到修复版本、覆盖传递依赖版本、替换库，或加缓解措施并记录豁免。

  5. 5

    Dependabot、Renovate 等机器人持续发起升级 PR，CI 跑测试与扫描作为合并门禁。

🔤 03 · 术语
CVE
公共漏洞编号体系，每个公开漏洞一个唯一 ID。
传递依赖 (Transitive Dependency)
依赖的依赖，未在清单中声明却会被安装。
CVSS
通用漏洞评分系统，0–10 分描述技术严重度，不等于实际风险。
EPSS
预测漏洞在未来 30 天被利用概率的评分模型。
可达性分析 (Reachability)
判断项目代码是否真的调用到漏洞函数。
SBOM
软件物料清单，列出制品包含的全部组件与版本。
💻 04 · 代码
多语言依赖漏洞扫描bash
#!/usr/bin/env bash
set -euo pipefail

# Node：按锁文件安装，只审计生产依赖，高危及以上让 CI 失败
npm ci
npm audit --omit=dev --audit-level=high

# 定位某个有漏洞的传递依赖是被谁引入的
npm explain minimist

# Python：pip install pip-audit
pip-audit -r requirements.txt

# Go：只报告代码实际调用到的漏洞
govulncheck ./...

# 多语言：OSV-Scanner（v2 命令格式）递归扫描仓库中的锁文件
osv-scanner scan source -r .

按生态选工具；npm explain 找出传递依赖来源，govulncheck 自带可达性分析。

📊 05 · 参数对比

漏洞优先级信号

信号含义用法
CVSS 分数技术严重度初筛，不能单独决定优先级
CISA KEV 收录已确认在野利用最高优先级，限期修复
EPSS 概率近期被利用可能性在大量中危中排序
可达性代码是否调用漏洞路径不可达可降级并记录
⚖️ 06 · 方案取舍

自动升级机器人

优点持续小步升级，修复快

代价PR 噪音多，依赖测试覆盖

适用测试较完善的活跃项目

覆盖传递依赖版本

优点不等上游发版即可修复

代价可能破坏兼容，需回归测试

适用上游维护慢、漏洞紧急

风险接受并豁免

优点避免为不可达漏洞冒升级风险

代价需定期复审，易被遗忘

适用确认不可达且有到期日

🕳️ 07 · 常见坑

  • ✗只看直接依赖，忽略传递依赖

    ✓扫描锁文件中的完整依赖树

  • ✗按 CVSS 一刀切，全员疲于处理低风险告警

    ✓结合 KEV、EPSS、可达性做优先级

  • ✗CI 用 npm install，实际版本与锁文件漂移

    ✓CI 与生产构建用 npm ci 或等价的锁定安装

  • ✗让 AI 助手“修漏洞”，它跨大版本升级引入破坏性变更

    ✓限定升级范围到修复版本，跑完整测试再合并

🎤 09 · 面试追问
扫描出几百个漏洞，怎么排期？

先过滤只在开发依赖中的；再看是否在 KEV 或 EPSS 高、是否暴露在公网入口；用可达性分析剔除未调用的。剩下的按“一次升级能消掉多少条”批量处理，并设定 SLA，例如严重级限期修复。

上游不修，传递依赖有漏洞怎么办？

用 npm overrides、yarn resolutions、pip 约束文件等强制提升版本并回归测试；或换库、fork 打补丁；无法修时加 WAF 规则或输入校验等缓解，并记录豁免和复审日期。

锁文件为什么对安全很重要？

锁文件固定了每个包的精确版本和完整性哈希，保证扫描的就是实际部署的依赖，也防止构建时悄悄拉到被投毒的新版本。没有锁文件，扫描结果和生产环境可能不一致。
