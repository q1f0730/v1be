并发与并行

Concurrency vs Parallelism

📐 01 · 定义

并发（Concurrency）是指程序结构上能同时处理多个任务，任务在时间上交错推进，单核也能实现；并行（Parallelism）是指多个任务在同一时刻真正同时执行，需要多核或多机。Rob Pike 的概括是：并发关乎“处理”多件事，并行关乎“执行”多件事。区分二者是选择异步、多线程还是多进程等优化手段的前提。

⚙️ 02 · 原理
  1. 1

    先判断瓶颈：任务大部分时间在等待 I/O（网络、磁盘、数据库）还是在占用 CPU 计算。

  2. 2

    I/O 密集任务适合并发：在等待期间切换到其他任务，常用事件循环（async/await）或线程实现。

  3. 3

    CPU 密集任务需要并行：把计算拆分到多个核心或机器上同时执行，如多进程、线程池（无 GIL 语言）或分布式计算。

  4. 4

    并行加速受阿姆达尔定律限制：程序中不可并行的串行部分决定了加速比的上限。

  5. 5

    两者可以组合：例如多个工作进程（并行），每个进程内运行异步事件循环处理大量连接（并发）。

🔤 03 · 术语
I/O 密集 (I/O-bound)
耗时主要在等待外部输入输出的任务。
CPU 密集 (CPU-bound)
耗时主要在计算、受 CPU 速度限制的任务。
事件循环 (Event Loop)
单线程调度大量异步任务、在 I/O 就绪时恢复执行的机制。
阿姆达尔定律 (Amdahl's Law)
加速比上限由程序中串行部分所占比例决定。
协程 (Coroutine)
可在等待点暂停并恢复的函数，是异步并发的基础单元。
💻 04 · 代码
asyncio 并发 vs 多进程并行python
import asyncio, time
from concurrent.futures import ProcessPoolExecutor

async def fake_io(i):          # 模拟网络请求：大部分时间在等待
    await asyncio.sleep(1)
    return i

async def concurrent_io():
    t = time.perf_counter()
    await asyncio.gather(*(fake_io(i) for i in range(100)))
    print(f"100 个 I/O 任务并发：{time.perf_counter() - t:.1f}s")  # 约 1 秒

def crunch(n):                 # CPU 密集：只有多核并行能加速
    return sum(i * i for i in range(n))

if __name__ == "__main__":
    asyncio.run(concurrent_io())
    t = time.perf_counter()
    with ProcessPoolExecutor() as ex:
        list(ex.map(crunch, [3_000_000] * 8))
    print(f"8 个计算任务并行：{time.perf_counter() - t:.1f}s")

100 个各等 1 秒的任务并发只需约 1 秒，单线程即可；计算任务则要靠多进程使用多核。

📊 05 · 参数对比

并发与并行对比

维度并发并行
核心含义交错推进多个任务同一时刻同时执行
硬件要求单核即可多核或多机
适合瓶颈I/O 等待CPU 计算
典型手段async/await、线程多进程、GPU、分布式
主要风险共享状态竞态、阻塞事件循环通信与同步开销、负载不均
⚖️ 06 · 方案取舍

异步并发（asyncio、Node.js）

优点单线程即可处理大量连接，开销低

代价CPU 密集代码会阻塞全部任务

适用网络服务、爬虫、调用 LLM API

多线程

优点编程模型直观，可共享内存

代价竞态、死锁；CPython 受 GIL 限制

适用阻塞式 I/O 库、GUI

多进程 / 分布式并行

优点真正利用多核或多机

代价通信与序列化开销

适用数据处理、模型推理、编码转码

🕳️ 07 · 常见坑

  • ✗在 async 函数里调用阻塞的同步库

    ✓使用异步客户端，或用 asyncio.to_thread 放到线程中

  • ✗CPU 密集任务用 asyncio 期望变快

    ✓用多进程或把计算交给原生扩展

  • ✗无限制并发请求，触发限流或耗尽连接

    ✓用信号量或连接池控制并发上限

  • ✗并行任务粒度过细，调度开销超过收益

    ✓合并为较大块，减少进程间通信次数

🎤 09 · 面试追问
并发和并行能否同时存在？

可以，而且很常见。例如 Web 服务器启动与 CPU 核数相同的工作进程实现并行，每个进程内用事件循环并发处理数千个连接。并发是程序结构，并行是执行方式，二者正交。

批量调用 LLM API 应该用并发还是并行？

调用 API 时程序主要在等待网络响应，是典型的 I/O 密集任务，使用 asyncio 等异步并发即可显著提速，无需多进程。同时要用信号量限制并发数，遵守速率限制并处理 429 重试。

阿姆达尔定律说明了什么？

若程序中比例为 p 的部分可并行，使用 N 个处理器的加速比为 1/((1-p)+p/N)。即使无限增加处理器，加速比也不超过 1/(1-p)。例如 90% 可并行，最多加速 10 倍。优化应先减少串行部分。
