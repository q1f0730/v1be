浏览器本地存储 (localStorage / IndexedDB)

Browser Storage

📐 01 · 定义

浏览器本地存储指 Web 平台提供的客户端持久化机制，主要有 localStorage、sessionStorage、IndexedDB、Cache API 与 Cookie。它们按源（origin）隔离，属于前端数据层，用于保存偏好、离线数据与缓存。各机制在容量、同步/异步、生命周期与安全性上差异明显，选错会带来性能或安全问题。

⚙️ 02 · 原理
  1. 1

    所有存储按协议 + 域名 + 端口组成的源隔离，一个源无法读取另一个源的数据。

  2. 2

    Web Storage 是同步的键值对接口，只能存字符串，容量通常为每源数 MB，大量读写会阻塞主线程。

  3. 3

    IndexedDB 是异步的事务型对象数据库，支持索引与结构化克隆，可存 Blob 等大量数据。

  4. 4

    浏览器按配额管理存储，空间紧张时可能清除尽力而为（best-effort）的数据；可申请持久化存储。

  5. 5

    同源页面脚本都能读取这些存储，因此遭遇 XSS 时其中内容会被窃取。

🔤 03 · 术语
同源策略 (Same-Origin Policy)
以协议、主机、端口划分边界，隔离存储与脚本访问。
localStorage
同步键值存储，除非清除否则长期保留，同源各标签页共享。
sessionStorage
按标签页隔离，标签页关闭后清空。
IndexedDB
异步事务型数据库，适合大量结构化数据与离线应用。
存储配额 (Storage Quota)
浏览器为每个源分配的可用空间，可用 StorageManager 查询。
💻 04 · 代码
安全地读写本地偏好javascript
// localStorage 只存字符串，对象需序列化；读写都可能抛错
function savePrefs(prefs) {
  try {
    localStorage.setItem("prefs:v1", JSON.stringify(prefs));
  } catch (e) {
    console.warn("存储失败（配额满或被禁用）", e);
  }
}

function loadPrefs() {
  try {
    return JSON.parse(localStorage.getItem("prefs:v1")) ?? { theme: "light" };
  } catch {
    return { theme: "light" }; // 数据损坏时回退默认值
  }
}

// 其他标签页修改时同步界面
window.addEventListener("storage", (e) => {
  if (e.key === "prefs:v1") applyTheme(loadPrefs().theme);
});

// 查询配额，并申请持久化（浏览器可能拒绝）
const { usage, quota } = await navigator.storage.estimate();
const persisted = await navigator.storage.persist();

键名带版本便于迁移；读写包 try/catch；顶层 await 需在 ES 模块中运行。

📊 05 · 参数对比

客户端存储机制对比

机制接口生命周期典型用途
localStorage同步键值长期，直到清除主题、语言偏好
sessionStorage同步键值标签页关闭即清单次流程临时数据
IndexedDB异步事务长期，受配额管理离线数据、大文件
Cookie随请求发送可设过期时间会话标识（配 HttpOnly）
⚖️ 06 · 方案取舍

localStorage

优点API 简单，同步易用

代价阻塞主线程、仅字符串、容量小

适用少量非敏感偏好

IndexedDB

优点容量大、异步、支持索引

代价原生 API 繁琐，常需封装库

适用离线优先、本地缓存数据集

HttpOnly Cookie

优点JS 读不到，降低 XSS 窃取风险

代价每次请求携带，需防 CSRF

适用登录会话标识

🕳️ 07 · 常见坑

  • ✗把访问令牌或 API 密钥存进 localStorage

    ✓会话用 HttpOnly + Secure + SameSite Cookie，密钥只放服务端

  • ✗在 localStorage 中存放大量数据并频繁读写

    ✓大数据改用 IndexedDB，并在必要时放入 Web Worker 处理

  • ✗假设本地数据永远存在

    ✓数据可能被用户或浏览器清除，需有回退默认值与服务端来源

  • ✗数据结构升级后旧数据解析崩溃

    ✓键名带版本号，读取时校验并迁移

🎤 09 · 面试追问
JWT 放 localStorage 还是 Cookie？

localStorage 可被任何同源脚本读取，XSS 时直接泄露；HttpOnly Cookie 脚本读不到，但会自动随请求发送，需配合 SameSite 与 CSRF 防护。多数安全建议倾向 HttpOnly Cookie 承载会话，同时仍要根治 XSS。

IndexedDB 和 localStorage 在性能上有何本质区别？

localStorage 是同步 API，读写会阻塞主线程，数据量大时造成卡顿；IndexedDB 是异步事务模型，不阻塞渲染，支持索引查询与二进制数据，适合大量数据，代价是 API 更复杂。

浏览器什么时候会清除本地存储？

用户手动清除；存储空间紧张时按策略淘汰非持久化的源；部分浏览器的隐私策略会清理长期无交互站点的脚本可写存储。可调用 navigator.storage.persist() 申请持久化，但关键数据仍应以服务端为准。
