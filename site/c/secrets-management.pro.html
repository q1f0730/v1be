机密管理

Secrets Management

📐 01 · 定义

机密管理（Secrets Management）是对 API Key、数据库密码、令牌、证书私钥等敏感凭证进行集中存储、访问控制、分发、轮换和审计的实践与工具体系。目标是让机密永不出现在代码和日志中，只在运行时按最小权限提供给需要的服务，并在泄露时能快速吊销与替换。

⚙️ 02 · 原理
  1. 1

    集中存储：机密存放在加密的管理系统中，如云密钥服务、Vault 或平台 Secrets。

  2. 2

    访问控制：按服务、环境与角色授权，谁能读取哪个机密都有明确策略。

  3. 3

    运行时注入：部署时通过环境变量、挂载文件或 SDK 拉取，把机密提供给应用。

  4. 4

    轮换与吊销：定期或泄露后生成新凭证、更新使用方，并作废旧凭证。

  5. 5

    审计与检测：记录机密访问日志，并用扫描工具在提交和 CI 中拦截泄露。

🔤 03 · 术语
密钥轮换 (Rotation)
定期更换凭证，缩短泄露凭证的有效窗口。
短期凭证 (Short-lived Credentials)
几分钟到几小时自动过期的令牌，泄露危害小。
OIDC 联合身份
CI 用身份令牌换取云端临时凭证，无需存长期密钥。
密钥扫描 (Secret Scanning)
检测代码与历史中疑似密钥的工具，如 gitleaks。
最小权限 (Least Privilege)
凭证只授予完成任务所需的最少权限。
💻 04 · 代码
提交前自动拦截密钥yaml
# .pre-commit-config.yaml
# 安装：pip install pre-commit && pre-commit install
# 之后每次 git commit 都会先扫描暂存内容，发现疑似密钥即阻止提交
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.0          # 固定版本，按需升级到最新发布
    hooks:
      - id: gitleaks

# 手动对整个历史做一次扫描（gitleaks 需单独安装）：
#   gitleaks detect --source . -v
#
# GitHub 仓库还可开启：
#   Settings → Code security → Secret scanning 与 Push protection

本地提交钩子加平台推送保护，在密钥离开开发机之前就把它拦下。

⚖️ 06 · 方案取舍

长期静态密钥

优点简单，兼容性好

代价泄露后长期有效

适用第三方仅支持静态 Key 时

短期动态凭证

优点自动过期，泄露危害小

代价需要支持的平台与集成

适用云资源访问、CI 部署

密码管理器 CLI 注入

优点团队共享方便，不落盘

代价依赖工具与网络

适用小团队本地开发

🕳️ 07 · 常见坑

  • ✗在聊天、工单或 AI 对话里粘贴真实密钥

    ✓通过密钥管理系统共享，误粘贴后立即轮换

  • ✗所有服务共用一个高权限 Key

    ✓按服务与环境拆分，限定最小权限

  • ✗日志中打印了请求头或完整配置

    ✓日志框架中屏蔽 Authorization 等敏感字段

  • ✗从不轮换，离职员工仍持有可用凭证

    ✓建立轮换周期，人员变动时同步轮换

🎤 09 · 面试追问
密钥泄露的应急流程？

第一时间吊销或轮换泄露的凭证，而不是先删代码；评估影响范围，检查访问日志与账单；更新所有使用方；清理代码与 Git 历史；复盘泄露路径并补上扫描、权限或流程漏洞；必要时通知受影响方。

为什么推荐 CI 使用 OIDC？

传统做法要在 CI 中存放长期云密钥，一旦泄露危害大。OIDC 让 CI 在每次运行时用平台签发的身份令牌向云厂商换取短期凭证，可按仓库、分支限定权限，凭证自动过期，无需存储和轮换长期密钥。

使用 AI 编程工具时如何保护机密？

密钥只放在被忽略的 .env 或密钥管理中；配置工具禁止读取敏感文件；不在提示中粘贴真实值；对 Agent 可执行的命令设权限，防止它打印环境变量；使用企业版的数据保留策略；定期扫描仓库。
