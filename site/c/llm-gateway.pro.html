模型网关 (LiteLLM / OpenRouter)

LLM Gateway

📐 01 · 定义

模型网关（LLM Gateway）是位于应用与多个模型提供方之间的代理层，对外提供统一（通常为 OpenAI 兼容）的接口，集中处理鉴权、密钥托管、路由、降级、限流、缓存、日志与成本核算。它属于 AI 应用的基础设施层，开源自托管代表是 LiteLLM Proxy，托管聚合服务代表是 OpenRouter。

⚙️ 02 · 原理
  1. 1

    应用使用网关签发的虚拟密钥，以统一格式发送请求，不直接持有各厂商的真实密钥。

  2. 2

    网关校验虚拟密钥对应的团队、预算与速率限制，超额则拒绝或排队。

  3. 3

    根据模型别名与路由策略（成本、延迟、负载、权重）选择具体提供方与部署，并转换为该厂商的 API 格式。

  4. 4

    调用失败、超时或触发限流时，按配置重试或降级到备用模型。

  5. 5

    记录请求的 Token 用量、费用、延迟与错误，发送到日志、可观测与计费系统。

🔤 03 · 术语
虚拟密钥 (Virtual Key)
网关签发给应用的密钥，可绑定预算、模型白名单与限额。
模型别名 (Model Alias)
应用使用的逻辑模型名，网关映射到具体厂商模型。
降级 (Fallback)
主模型失败时自动改用备用模型或提供方。
语义缓存 (Semantic Cache)
对语义相近的请求复用历史响应，降低成本。
OpenAI 兼容接口
沿用 OpenAI API 格式，现有 SDK 只需改 base_url。
💻 04 · 代码
LiteLLM Proxy 配置yaml
# config.yaml   启动：litellm --config config.yaml
model_list:
  - model_name: main            # 应用里使用的别名
    litellm_params:
      model: openai/gpt-4o-mini
      api_key: os.environ/OPENAI_API_KEY
  - model_name: backup
    litellm_params:
      model: anthropic/claude-3-5-haiku-20241022   # 模型 ID 以厂商当前列表为准
      api_key: os.environ/ANTHROPIC_API_KEY

litellm_settings:
  num_retries: 2
  fallbacks: [{"main": ["backup"]}]   # main 失败后改用 backup

general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY   # 管理与签发虚拟密钥
# 应用侧：OpenAI SDK 设 base_url=http://网关地址:4000，model="main"

真实密钥只在网关环境变量中；应用用别名调用，主模型失败自动切到备用。

📊 05 · 参数对比

网关方案对比

方案部署特点
LiteLLM Proxy自托管（开源）支持大量提供方，虚拟密钥与预算
OpenRouter托管 SaaS一个账号访问多家模型，统一计费
云厂商 AI 网关托管与自家云的日志、缓存、限流集成
自研代理自托管完全可控，维护成本高
⚖️ 06 · 方案取舍

自托管网关

优点数据与密钥自控，可深度定制

代价需运维，网关本身成为关键依赖

适用合规要求高、多团队共用

托管聚合服务

优点零运维，快速接入多模型

代价多一层数据经手方与加价/费用

适用原型与中小团队

应用内 SDK 直连

优点最少组件、延迟最低

代价密钥分散，难统一计费与降级

适用单应用、单模型

🕳️ 07 · 常见坑

  • ✗网关单实例部署，挂了所有 AI 功能一起挂

    ✓多副本部署、健康检查，必要时客户端保留直连兜底

  • ✗降级到能力差异大的模型却不评估

    ✓备用模型经过同一评测集验证，或对关键任务限制降级

  • ✗日志记录完整提示与输出，含用户隐私

    ✓按需脱敏或只记录元数据，设置日志保留期

  • ✗只设全局预算，不区分团队与用户

    ✓按虚拟密钥/团队设预算与速率限制，避免单个应用耗尽额度

🎤 09 · 面试追问
模型网关和普通 API 网关有何不同？

除鉴权、限流等通用能力外，模型网关理解 LLM 语义：按 Token 计量计费、跨厂商格式转换、模型级降级与路由、流式响应处理、提示缓存与语义缓存、内容安全检查等。

降级策略要注意什么？

区分可重试错误（超时、429、5xx）与不可重试错误（参数错误、内容拒绝）；备用模型需支持相同功能（工具调用、结构化输出、上下文长度）；记录降级次数并告警。

如何用网关控制 Agent 成本失控？

为 Agent 使用的虚拟密钥设置预算与速率上限；按任务路由到合适大小的模型；开启缓存；监控每个任务的 Token 消耗，异常时熔断。
