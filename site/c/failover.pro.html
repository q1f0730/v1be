故障自动转移

Failover

📐 01 · 定义

故障转移（Failover）是主组件失效时，由备用组件接管其工作负载的过程，可以自动或手动触发。它是高可用架构的核心机制，常见于数据库主从、负载均衡后端、DNS 和多区域部署。关键问题包括如何可靠地检测故障、如何避免两个节点同时认为自己是主（脑裂），以及切换期间数据是否会丢失。

⚙️ 02 · 原理
  1. 1

    主节点与备节点之间进行数据复制，同步复制保证不丢数据，异步复制有延迟但性能好。

  2. 2

    监控组件通过心跳或健康检查探测主节点，连续失败超过阈值即判定故障。

  3. 3

    多个观察者投票或借助共识系统决定是否切换，减少因网络分区导致的误判。

  4. 4

    选出新主并提升，隔离旧主（Fencing），防止它恢复后继续接受写入。

  5. 5

    更新路由：修改 DNS、虚拟 IP、服务发现或客户端配置，让流量指向新主。

🔤 03 · 术语
脑裂 (Split-Brain)
网络分区下两个节点都认为自己是主，各自接受写入导致数据冲突。
隔离 (Fencing)
确保旧主无法继续写入，如断电、撤销存储访问或递增任期号。
法定人数 (Quorum)
做出决策所需的最少投票节点数，通常为多数。
复制延迟 (Replication Lag)
备节点落后主节点的数据量或时间，决定切换时可能丢失的数据。
故障回切 (Failback)
原主节点修复后把服务切回的过程。
💻 04 · 代码
通过 Sentinel 自动找主python
from redis.sentinel import Sentinel

# 连接 3 个哨兵（奇数个，便于形成多数派）
sentinel = Sentinel(
    [("sentinel-1", 26379), ("sentinel-2", 26379), ("sentinel-3", 26379)],
    socket_timeout=0.5,
)

# 客户端不写死主节点地址，而是向哨兵询问当前主
print(sentinel.discover_master("mymaster"))

master = sentinel.master_for("mymaster", socket_timeout=0.5)
replica = sentinel.slave_for("mymaster", socket_timeout=0.5)

master.set("greeting", "hello")   # 写走主
print(replica.get("greeting"))      # 读可走从，可能有复制延迟
# 主宕机后，哨兵选出新主，master_for 返回的连接会自动指向新主

redis-py 通过 Sentinel 发现主节点，故障转移后客户端自动跟随新主。

🕳️ 07 · 常见坑

  • ✗只有两个节点互相探测，网络分区时双方都升为主。

    ✓使用奇数个观察者或共识系统，并实施 fencing。

  • ✗应用缓存了数据库 IP，切换后仍连旧主。

    ✓通过服务发现或哨兵获取地址，连接失败时重新解析。

  • ✗从未演练过故障转移，真出事时才发现脚本失效。

    ✓定期演练，记录切换耗时与数据损失。

  • ✗故障检测阈值过于敏感，网络抖动就切换。

    ✓多次连续失败才判定，并结合多个观察点。

🎤 09 · 面试追问
如何防止故障转移中的脑裂？

用奇数个节点做多数派决策，少数派一侧不能选主；实施 fencing，例如递增任期号让旧主写入被拒、或撤销其存储访问；客户端只认可最新任期的主。

异步复制下故障转移会丢数据吗？

会。主节点已确认但尚未复制到备节点的写入，在切换后会丢失或产生冲突，丢失量取决于复制延迟。可用半同步或同步复制降低风险，代价是写延迟增加。

为什么 DNS 故障转移常常比预期慢？

切换时间受记录 TTL、递归解析器缓存以及客户端自身缓存影响，有的运行时会长时间缓存解析结果。因此要设较短 TTL，并确保客户端遵守 TTL 或在连接失败时重新解析。
