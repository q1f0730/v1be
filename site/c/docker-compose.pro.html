Docker Compose 多容器编排

Docker Compose

📐 01 · 定义

Docker Compose 是用一个 YAML 文件（推荐命名 compose.yaml）声明多容器应用的服务、网络、数据卷与配置，并用 docker compose 命令统一创建、启动、停止的工具，遵循开放的 Compose Specification。它定位于本地开发、测试与单机部署，是「一条命令拉起整套环境」的标准做法。

⚙️ 02 · 原理
  1. 1

    compose.yaml 的 services 下定义每个服务的镜像或构建上下文、端口、环境变量、挂载与依赖。

  2. 2

    Compose 为项目创建默认网络，服务之间可直接用服务名作为主机名互相访问。

  3. 3

    命名数据卷在容器重建后保留数据；绑定挂载把本地目录映射进容器，便于开发热更新。

  4. 4

    depends_on 结合 healthcheck 与 condition: service_healthy，可让依赖服务就绪后再启动应用。

  5. 5

    支持 .env 变量替换、多文件覆盖（compose.override.yaml）与 profiles 按需启用服务。

🔤 03 · 术语
Compose Specification
定义多容器应用的开放规范，docker compose 实现它。
服务 (Service)
一类容器的定义，可扩展为多个副本。
命名卷 (Named Volume)
由 Docker 管理的持久化存储，独立于容器生命周期。
健康检查 (Healthcheck)
定期执行的探测命令，决定容器是否健康。
Profiles
为服务打标签，只在指定 profile 启用时启动。
💻 04 · 代码
Web + PostgreSQL + Redisyaml
# compose.yaml（顶层 version 字段已过时，不需要写）
services:
  web:
    build: .
    ports:
      - "3000:3000"
    environment:
      DATABASE_URL: postgres://app:${DB_PASSWORD}@db:5432/app   # 用服务名 db 访问
      REDIS_URL: redis://cache:6379
    depends_on:
      db:
        condition: service_healthy   # 等数据库就绪再启动
  db:
    image: postgres:16
    environment:
      POSTGRES_USER: app
      POSTGRES_PASSWORD: ${DB_PASSWORD}   # 从同目录 .env 读取
      POSTGRES_DB: app
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U app"]
      interval: 5s
      retries: 10
  cache:
    image: redis:7
volumes:
  pgdata:

数据库不映射宿主端口即可只供内部访问；docker compose down -v 会删除 pgdata 卷。

📊 05 · 参数对比

常用命令

命令作用注意
docker compose up -d构建并后台启动配置变化会重建容器
docker compose logs -f web跟踪某服务日志排错首选
docker compose exec db psql -U app进入容器执行命令服务需在运行
docker compose down停止并删除容器与网络加 -v 会删除数据卷
⚖️ 06 · 方案取舍

Compose

优点简单、声明式、上手快

代价单机为主，无自动扩缩容与自愈调度

适用本地开发、测试、小型单机部署

Kubernetes

优点多节点调度、自愈、滚动更新

代价复杂度与运维成本高

适用生产多服务、需要高可用

直接 docker run

优点无额外文件

代价多服务时命令难维护

适用临时跑单个容器

🕳️ 07 · 常见坑

  • ✗以为 depends_on 会等数据库可用

    ✓配合 healthcheck 与 condition: service_healthy，应用也应重试连接

  • ✗数据库端口映射到 0.0.0.0 暴露公网

    ✓不映射端口，或绑定 127.0.0.1:5432:5432

  • ✗密码明文写在 compose.yaml 并提交

    ✓用 .env（不入库）或 secrets 注入

  • ✗习惯性 down -v 清掉了数据

    ✓清楚 -v 会删命名卷，重要数据先备份

🎤 09 · 面试追问
Compose 中服务间如何通信？

Compose 为项目创建默认 bridge 网络，并提供内置 DNS，服务名即主机名，容器间直接用 db:5432 访问容器端口，无需映射到宿主机。ports 只用于宿主机或外部访问。

depends_on 能保证启动顺序和可用性吗？

短语法只保证容器启动顺序，不保证进程就绪。长语法配合 condition: service_healthy 可等待健康检查通过。但运行中依赖也可能重启，应用仍需具备连接重试能力。

Compose 能用于生产吗？

单机、小规模、可接受停机维护的场景可以，配合 restart 策略、日志轮转与备份即可。需要多节点、高可用、滚动更新与自动扩缩时，应迁移到 Kubernetes 或托管容器平台。
