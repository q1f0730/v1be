唯一性约束

Unique Constraints

🧸 回到小白版

📐 01 · 定义

唯一性约束（Unique Constraint）要求表中某列或列组合的值不重复，数据库通常通过建立唯一索引来实现并在写入时检查。它是数据完整性层的最后防线：应用层「先查后插」在并发下必然有竞态，只有数据库约束能原子地保证唯一，同时为幂等写入和 upsert 提供基础。

⚙️ 02 · 原理
  1. 1

    声明 UNIQUE 或 CREATE UNIQUE INDEX 后，数据库为对应列建立唯一 B-tree 索引。

  2. 2

    插入或更新时，在索引中查找相同键；若已存在已提交或进行中的冲突行，则等待或报错。

  3. 3

    并发事务插入同一键时，后者会等待前者结束，前者提交则后者报唯一冲突错误。

  4. 4

    SQL 标准中 NULL 互不相等，因此多数数据库允许唯一列存在多行 NULL。

  5. 5

    冲突可由 INSERT … ON CONFLICT（PostgreSQL）或 ON DUPLICATE KEY UPDATE（MySQL）转为更新。

🔤 03 · 术语
唯一索引 (Unique Index)
实现唯一约束的索引结构，也可加速等值查询。
复合唯一 (Composite Unique)
多列组合唯一，如 (tenant_id, email)。
部分唯一索引 (Partial Unique Index)
只对满足条件的行生效，如未删除行。
Upsert
插入若冲突则更新，依赖唯一约束判定冲突。
NULLS NOT DISTINCT
PostgreSQL 15+ 选项，让多个 NULL 也视为重复。
💻 04 · 代码
多租户唯一与 upsertsql
-- 同一租户内邮箱唯一（不同租户可重复）
ALTER TABLE users
  ADD CONSTRAINT users_tenant_email_uniq UNIQUE (tenant_id, email);

-- 软删除场景：只约束未删除的行
CREATE UNIQUE INDEX users_active_email_uniq
  ON users (tenant_id, lower(email))
  WHERE deleted_at IS NULL;

-- 幂等写入：同一请求键重复提交只生效一次
INSERT INTO payments (idempotency_key, amount)
VALUES ('req-123', 100)
ON CONFLICT (idempotency_key) DO NOTHING;

-- upsert：存在则更新计数
INSERT INTO daily_stats (day, page, views)
VALUES (CURRENT_DATE, '/home', 1)
ON CONFLICT (day, page)
DO UPDATE SET views = daily_stats.views + EXCLUDED.views;

复合唯一、部分唯一索引和 ON CONFLICT 组合，覆盖多租户、软删除和幂等场景。

保证唯一的几种做法

做法并发安全备注
应用先查再插否两个请求可同时查到不存在
数据库唯一约束是冲突时报错，需捕获处理
唯一约束 + upsert是冲突转为更新或忽略
分布式锁 + 查询依赖锁实现复杂且仍建议加约束兜底
⚖️ 06 · 方案取舍

UNIQUE 约束

优点语义清晰，可被外键引用

代价无法带条件或表达式

适用普通单列或多列唯一

部分/表达式唯一索引

优点支持条件、大小写不敏感等

代价不能被外键引用，ORM 支持不一

适用软删除、忽略大小写邮箱

仅应用层校验

优点能给友好提示

代价并发下必然漏

适用只作体验优化，必须配数据库约束

🕳️ 07 · 常见坑

  • ✗只在接口里查重，没有数据库约束

    ✓加唯一约束兜底，捕获冲突错误转为业务提示

  • ✗软删除后同邮箱无法重新注册

    ✓改用 WHERE deleted_at IS NULL 的部分唯一索引

  • ✗邮箱大小写不同被当成两个用户

    ✓统一规范化存储，或对 lower(email) 建唯一索引

  • ✗在已有重复数据的大表上直接加约束失败

    ✓先查出并清理重复，再用 CREATE UNIQUE INDEX CONCURRENTLY

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么「先查后插」不能保证唯一？

两个并发请求可能在对方插入前同时查询到「不存在」，随后都执行插入，形成竞态（TOCTOU）。只有数据库在索引层原子检查才能保证；应用层查询仅用于提前给出友好提示。

唯一列允许多个 NULL 吗？

按 SQL 标准 NULL 不等于 NULL，PostgreSQL、MySQL 默认允许多个 NULL。PostgreSQL 15 起可用 NULLS NOT DISTINCT 改变此行为；SQL Server 的唯一约束默认只允许一个 NULL，跨库时要注意。

ON CONFLICT DO NOTHING 有什么坑？

冲突时不返回行，RETURNING 拿不到已有记录，需要再查一次；且它要求冲突目标与某个唯一索引精确匹配，部分索引需写出相同 WHERE 条件。
