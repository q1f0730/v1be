构建 (Build)

Build

📐 01 · 定义

构建（Build）是把源代码及依赖转换为可部署产物的自动化过程，属于交付流水线的前段。对前端通常包括依赖解析、转译（TypeScript/JSX）、打包、压缩、代码分割与资源指纹；对后端则可能是编译二进制或生成容器镜像。构建应可重复：同样的输入得到同样的输出。

⚙️ 02 · 原理
  1. 1

    按锁文件安装确定版本的依赖，保证不同机器、不同时间安装的依赖完全一致。

  2. 2

    转译源代码：TypeScript、JSX、新语法被转换为目标运行环境支持的 JavaScript。

  3. 3

    打包器从入口出发构建依赖图，合并模块、做 Tree Shaking 去除未使用代码，并按路由拆分代码块。

  4. 4

    压缩代码和资源，给文件名加内容哈希，生成 Source Map 便于调试线上错误。

  5. 5

    输出到 dist 等目录，或打包成镜像，作为后续部署的不可变制品。

🔤 03 · 术语
打包器 (Bundler)
合并模块并处理依赖关系的工具，如 Vite（Rollup）、webpack。
Tree Shaking
基于 ES 模块静态分析删除未被使用的导出代码。
代码分割 (Code Splitting)
把产物拆成按需加载的多个块，减小首屏体积。
Source Map
将压缩后代码映射回源码位置的文件，用于调试。
可重复构建 (Reproducible Build)
相同输入始终产出相同制品，便于审计和回溯。
💻 04 · 代码
前端构建常用命令bash
# 严格按锁文件安装，CI 中优先使用
npm ci

# 类型检查（Vite 只转译，不做类型检查）
npx tsc --noEmit

# 生产构建，输出到 dist/
npx vite build

# 本地预览构建产物，确认与开发环境表现一致
npx vite preview

# 查看产物体积，排查过大的依赖
du -sh dist/assets/* | sort -h

构建与类型检查分开执行；用 preview 验证产物而不是只看开发服务器。

⚖️ 06 · 方案取舍

零配置构建工具（Vite 等）

优点上手快，默认合理

代价深度定制需插件

适用多数新前端项目

高度定制的 webpack 配置

优点可控性强

代价配置复杂、构建慢

适用历史大型项目、特殊需求

无构建（原生 ES 模块）

优点无工具链

代价无法优化体积和兼容性

适用小工具页、原型

🕳️ 07 · 常见坑

  • ✗以为开发服务器能跑，构建就一定成功

    ✓CI 中执行生产构建并用 preview 验证

  • ✗CI 用 npm install 导致依赖漂移

    ✓CI 使用 npm ci 严格按锁文件安装

  • ✗生产环境公开 Source Map 暴露源码

    ✓Source Map 只上传到错误监控平台，不随站点公开

  • ✗构建产物提交进 Git 仓库

    ✓产物由流水线生成，dist 加入 .gitignore

🎤 09 · 面试追问
Vite 为什么开发时快、生产还要打包？

开发时 Vite 利用浏览器原生 ES 模块按需提供文件，并用 esbuild 预构建依赖，无需整体打包，所以启动快。生产环境大量小模块请求会影响性能，因此仍用 Rollup 系打包，做 Tree Shaking、代码分割和压缩。

Tree Shaking 失效的常见原因？

依赖使用 CommonJS 而非 ES 模块，无法静态分析；模块有副作用且未在 package.json 中声明 sideEffects；整体导入大库而不是按需导入；动态访问导出。可用产物分析工具确认哪些代码被打进来。

为什么要追求可重复构建？

可重复构建保证同一提交在任何时间、任何机器上产出一致制品，排查线上问题时能精确复现，也能防范构建环境被篡改的供应链风险。实现上依赖锁文件、固定工具版本和隔离的构建环境。
