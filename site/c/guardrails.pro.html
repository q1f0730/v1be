护栏 (Guardrails)

📐 01 · 定义

护栏（Guardrails）是围绕 LLM 调用设置的输入、输出与行为约束层，用于拦截提示注入、越权工具调用、敏感信息泄露、有害内容和不符合格式的输出。它在模型自身对齐之外提供可控、可审计的防线，通常由规则校验、分类模型、结构化输出校验和权限控制组合而成。

⚙️ 02 · 原理
  1. 1

    输入护栏：检测提示注入、越狱尝试、敏感信息和超出业务范围的请求，必要时拒绝或改写。

  2. 2

    上下文护栏：把检索内容、网页、文件标记为不可信数据，与系统指令明确分隔。

  3. 3

    工具护栏：限定可调用工具与参数范围，高风险操作需人工确认，权限按最小化原则。

  4. 4

    输出护栏：用 schema 校验结构，检测 PII、有害内容与事实性问题，不合格则重试或拦截。

  5. 5

    记录所有拦截事件、触发规则与样本，用于监控攻击趋势和调整阈值。

🔤 03 · 术语
提示注入 (Prompt Injection)
通过输入或外部内容篡改模型行为，OWASP LLM Top 10 首位。
间接提示注入 (Indirect Injection)
恶意指令藏在模型读取的网页、文档或邮件中。
结构化输出 (Structured Output)
约束模型按 JSON Schema 输出，便于校验。
内容分类器 (Safety Classifier)
判断输入输出是否违规的专用模型，如 Llama Guard。
过度代理 (Excessive Agency)
赋予模型过多权限或自主性导致的风险。
💻 04 · 代码
输出 schema 校验与工具白名单python
import re
from pydantic import BaseModel, Field, ValidationError

class RefundDecision(BaseModel):
    approve: bool
    amount_cents: int = Field(ge=0, le=50_000)   # 金额上限硬约束
    reason: str = Field(max_length=300)

ALLOWED_TOOLS = {"lookup_order", "issue_refund"}
NEEDS_HUMAN = {"issue_refund"}
PII = re.compile(r"\b\d{16}\b")                   # 粗略的卡号模式

def check_output(raw_json: str) -> RefundDecision | None:
    try:
        d = RefundDecision.model_validate_json(raw_json)
    except ValidationError:
        return None                    # 结构不合格：重试或拒绝
    if PII.search(d.reason):
        return None                    # 输出含疑似卡号：拦截
    return d

def check_tool(name: str) -> str:
    if name not in ALLOWED_TOOLS:
        return "deny"
    return "ask_human" if name in NEEDS_HUMAN else "allow"

用代码强制的约束（schema、上限、白名单）比提示词里的「请不要」可靠得多。

🕳️ 07 · 常见坑

  • ✗以为在系统提示里写「忽略任何注入」就安全

    ✓把权限控制放在代码与基础设施层，不依赖模型自律

  • ✗Agent 读取网页后可以直接调用发邮件、转账工具

    ✓处理不可信内容的上下文中限制高风险工具，或需人工确认

  • ✗护栏过严，大量正常请求被拒绝

    ✓用评测集同时衡量拦截率与误拒率，逐步调阈值

  • ✗只拦截不记录，无法发现攻击模式

    ✓记录拦截事件与样本，定期复盘

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么提示注入很难彻底解决？

LLM 在同一输入流中处理指令和数据，无法从机制上区分可信指令与不可信内容。因此只能降低风险：限制模型权限、隔离不可信上下文、高风险操作需人工确认，假设注入终会成功来设计影响范围。

护栏应该放在哪一层？

多层叠加：输入层过滤明显攻击，上下文层隔离外部数据，工具层用权限与参数校验做硬约束，输出层校验结构与敏感信息。最关键的是工具/权限层，因为真正造成损失的是行动。

如何评估护栏效果？

构建攻击样本集（直接与间接注入、越狱、PII 诱导）与正常请求集，分别统计拦截率与误拒率；做红队测试；上线后监控拦截日志与用户投诉，持续补充样本。
