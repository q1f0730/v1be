点击劫持

Clickjacking

📐 01 · 定义

点击劫持（Clickjacking / UI Redressing）是攻击者把目标网站嵌入透明或伪装的 iframe，覆盖在诱饵页面上，诱导用户在不知情时点击目标站的按钮，完成授权、转账、修改设置等操作。由于请求带着用户的真实登录态，服务端难以区分。防御核心是由目标站声明自己不允许被他站嵌入。

⚙️ 02 · 原理
  1. 1

    攻击者在自己的页面中用 iframe 加载目标站的敏感操作页，用户此时已登录目标站。

  2. 2

    通过 CSS 把 iframe 设为透明并精确定位，使目标按钮正好位于诱饵按钮下方。

  3. 3

    用户以为点击的是诱饵内容，实际点击落在 iframe 中的目标站按钮上。

  4. 4

    浏览器自动携带目标站 Cookie（取决于 SameSite 设置），操作以用户身份执行。

  5. 5

    防御：响应头 CSP frame-ancestors 或 X-Frame-Options 让浏览器拒绝跨站嵌入。

🔤 03 · 术语
UI 伪装 (UI Redressing)
通过叠层与透明度伪装界面诱导交互。
frame-ancestors
CSP 指令，规定哪些来源可以嵌入本页面。
X-Frame-Options
RFC 7034 描述的旧式响应头，取值 DENY 或 SAMEORIGIN。
SameSite Cookie
限制跨站请求携带 Cookie，可降低嵌入页的登录态。
防框架脚本 (Frame Busting)
用 JS 检测并跳出框架的旧方法，易被绕过。
💻 04 · 代码
禁止被跨站嵌入的响应头http
# 方案一：完全禁止任何站点（包括自己）嵌入
HTTP/1.1 200 OK
Content-Security-Policy: frame-ancestors 'none'
X-Frame-Options: DENY

# 方案二：只允许同源页面嵌入
HTTP/1.1 200 OK
Content-Security-Policy: frame-ancestors 'self'
X-Frame-Options: SAMEORIGIN

# 方案三：允许指定合作方嵌入（X-Frame-Options 无法表达，只用 CSP）
HTTP/1.1 200 OK
Content-Security-Policy: frame-ancestors 'self' https://partner.example.com

# 同时设置会话 Cookie 的 SameSite，减少被嵌入时携带登录态
Set-Cookie: session=abc123; Secure; HttpOnly; SameSite=Lax

frame-ancestors 是现代标准，X-Frame-Options 兼容旧浏览器；两者并存时以 CSP 为准。

📊 05 · 参数对比

防御手段对比

手段粒度说明
CSP frame-ancestors可列多个来源推荐，现代浏览器支持
X-Frame-OptionsDENY / SAMEORIGIN兼容旧浏览器，不能列多个来源
SameSite CookieCookie 级降低风险，不能替代上两者
敏感操作二次确认业务级密码、验证码等打断一键点击
⚖️ 06 · 方案取舍

frame-ancestors 'none'

优点最安全，配置简单

代价自身也无法嵌入

适用不需要被嵌入的应用

frame-ancestors 'self'

优点允许同源内嵌

代价同源页面若有漏洞仍可被利用

适用站内有 iframe 布局

允许指定外部来源

优点支持合作方嵌入

代价信任范围扩大

适用嵌入式组件、支付插件

🕳️ 07 · 常见坑

  • ✗只在首页加防护头，敏感操作页漏掉

    ✓在网关或中间件全局设置，例外页面单独放开

  • ✗依赖 JS frame busting 脚本

    ✓使用响应头，脚本可被 sandbox 属性等手段禁用

  • ✗用 X-Frame-Options ALLOW-FROM 指定来源

    ✓ALLOW-FROM 已不被现代浏览器支持，改用 frame-ancestors

  • ✗在 meta 标签里写 frame-ancestors

    ✓该指令在 meta 中无效，必须通过 HTTP 响应头下发

☑️ 08 · 检查清单
🎤 09 · 面试追问
X-Frame-Options 和 frame-ancestors 怎么选？

优先 CSP frame-ancestors，它可列多个来源并支持通配，是标准方案；X-Frame-Options 只有 DENY 与 SAMEORIGIN，作为旧浏览器兼容一起下发。两者同时存在时，支持 CSP 的浏览器以 frame-ancestors 为准。

API 接口需要防点击劫持吗？

点击劫持针对被渲染并可交互的页面，纯 JSON API 不会被用户直接点击，风险很低；但统一下发防护头成本几乎为零，很多团队在网关全局设置。

SameSite 能完全防御点击劫持吗？

不能。SameSite=Lax/Strict 使跨站 iframe 中通常不携带 Cookie，能大幅降低风险，但依赖浏览器行为与 Cookie 配置，且对同站子域无效。应与 frame-ancestors 一起使用。
