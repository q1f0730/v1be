单实例表分区

Partitioning

📐 01 · 定义

表分区（Partitioning）在单个数据库实例内，把一张大表按分区键拆成多个物理子表，对应用仍呈现为一张逻辑表。它让查询只扫描相关分区（分区裁剪），并能整块删除或归档旧数据，常用于按时间增长的日志、订单、事件表，但不增加机器，也不解决单机容量上限。

⚙️ 02 · 原理
  1. 1

    定义分区方式：范围（RANGE，常按时间）、列表（LIST，按枚举值）或哈希（HASH）。

  2. 2

    创建子分区：为每个区间建子表，数据写入时数据库按分区键自动路由。

  3. 3

    分区裁剪：查询条件包含分区键时，优化器跳过不相关分区，减少扫描量。

  4. 4

    生命周期管理：提前创建未来分区，过期分区直接 DETACH/DROP，代替大批量 DELETE。

  5. 5

    索引与约束：索引在各分区上分别维护，主键/唯一约束通常必须包含分区键。

🔤 03 · 术语
分区键 (Partition Key)
决定行归属哪个分区的列或表达式。
分区裁剪 (Partition Pruning)
根据查询条件排除不需要扫描的分区。
声明式分区 (Declarative Partitioning)
PostgreSQL 10 起支持的 PARTITION BY 语法。
默认分区 (Default Partition)
接收不匹配任何分区范围数据的兜底分区。
分离分区 (Detach Partition)
把子分区从父表拆出为独立表，便于归档或删除。
💻 04 · 代码
PostgreSQL 按月分区sql
-- 父表：按 created_at 做范围分区
CREATE TABLE events (
  id         bigint GENERATED ALWAYS AS IDENTITY,
  created_at timestamptz NOT NULL,
  payload    jsonb,
  PRIMARY KEY (id, created_at)          -- 主键必须包含分区键
) PARTITION BY RANGE (created_at);

-- 子分区：区间左闭右开
CREATE TABLE events_2026_10 PARTITION OF events
  FOR VALUES FROM ('2026-10-01') TO ('2026-11-01');
CREATE TABLE events_2026_11 PARTITION OF events
  FOR VALUES FROM ('2026-11-01') TO ('2026-12-01');

-- 查询带分区键，EXPLAIN 可看到只扫描一个分区
EXPLAIN SELECT count(*) FROM events
WHERE created_at >= '2026-10-15' AND created_at < '2026-10-16';

-- 归档旧数据：分离后删除，代替大规模 DELETE
ALTER TABLE events DETACH PARTITION events_2026_10;
DROP TABLE events_2026_10;

按时间分区让查询只扫相关月份，删除旧数据从慢 DELETE 变成瞬间 DROP。

📊 05 · 参数对比

三种分区方式

方式适用数据注意
RANGE时间序列、递增 ID要提前建好未来分区
LIST地区、租户类型等枚举新取值需新增分区或默认分区
HASH无自然区间、需均匀分散无法按区间裁剪和整块归档
⚖️ 06 · 方案取舍

表分区

优点对应用透明，归档与裁剪高效

代价不增加机器，唯一约束受限

适用单表很大、按时间增长

分库分片

优点突破单机容量与写入上限

代价分布式复杂度高

适用单机资源确实不够

只靠索引

优点最简单，无结构变更

代价超大表维护、删除和 VACUUM 成本高

适用表规模适中

🕳️ 07 · 常见坑

  • ✗查询条件不带分区键，反而扫描所有分区更慢

    ✓按主要查询模式选分区键，确保高频查询能裁剪

  • ✗忘了提前创建新分区，写入报错或落入默认分区

    ✓用定时任务或 pg_partman 自动预建未来分区并监控

  • ✗分区过多（数千个），规划与锁开销上升

    ✓控制分区粒度，如按月而非按小时，按数据量权衡

☑️ 08 · 检查清单
🎤 09 · 面试追问
分区表为什么主键要包含分区键？

数据库的唯一约束在各分区上分别用本地索引实现，没有跨分区的全局唯一索引；只有约束包含分区键，才能保证同一键值只可能落在一个分区里，从而用本地索引保证全局唯一。

分区能提升所有查询性能吗？

不能。只有条件包含分区键、能触发裁剪的查询受益；不带分区键的查询要扫描每个分区，计划和执行开销可能更大。分区的主要收益常在数据生命周期管理和维护操作上。

按时间分区怎么删除一年前的数据？

直接分离并删除对应时间段的分区，是元数据操作，几乎瞬时完成，不产生大量死元组和 WAL；相比 DELETE 数亿行后再等待 VACUUM，代价小得多。
