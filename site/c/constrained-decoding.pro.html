约束解码 (Grammar / JSON Schema)

Constrained Decoding

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

约束解码（Constrained Decoding）是在生成的每一步，根据语法或 JSON Schema 计算当前允许的 Token 集合，并把不允许 Token 的概率置零后再采样，从而保证输出在结构上必然合法。它是 OpenAI、Gemini 等结构化输出功能以及 Outlines、XGrammar、llama.cpp GBNF 等开源实现的基础。

⚙️ 02 · 原理
  1. 1

    把 JSON Schema、正则表达式或上下文无关文法编译为有限状态机或下推自动机。

  2. 2

    预先计算自动机状态与词表 Token 的对应关系，处理一个 Token 跨越多个语法符号的情况。

  3. 3

    每生成一步，根据当前自动机状态得到合法 Token 掩码，把非法 Token 的 logit 设为负无穷。

  4. 4

    在剩余 Token 上按原采样策略采样，并用所选 Token 推进自动机状态。

  5. 5

    直到自动机进入接受状态才允许结束符，确保输出完整闭合；工程实现会缓存掩码以降低每步开销。

🔤 03 · 术语
Logit 掩码 (Logit Mask)
把不允许 Token 的分数置为负无穷，使其采样概率为零。
有限状态机 (FSM)
可表达正则语言的自动机，适合正则与扁平 JSON 约束。
下推自动机 (PDA)
带栈的自动机，可表达任意嵌套的上下文无关文法。
GBNF
llama.cpp 使用的文法描述格式，用于约束本地模型输出。
严格模式 (strict)
OpenAI 结构化输出中保证输出符合所给 JSON Schema 的开关。
💻 04 · 代码
JSON Schema 结构化输出python
# pip install openai ；模型名以官方文档为准
import json
from openai import OpenAI

client = OpenAI()
schema = {
    "type": "object",
    "properties": {
        "title":    {"type": "string"},
        "priority": {"type": "string", "enum": ["low", "medium", "high"]},
        "due_days": {"type": "integer"},
    },
    "required": ["title", "priority", "due_days"],
    "additionalProperties": False,          # 严格模式要求
}

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "从这句话提取任务：下周五前务必修好登录 Bug"}],
    response_format={"type": "json_schema",
                     "json_schema": {"name": "task", "strict": True, "schema": schema}},
)
task = json.loads(resp.choices[0].message.content)   # 结构合法
assert 0 <= task["due_days"] <= 30, "内容是否合理仍需业务校验"
print(task)

约束只保证结构；字段值是否正确仍需校验。需处理模型拒答与输出被截断的情况。

📊 05 · 参数对比

获得结构化输出的方式

方式格式保证实现位置限制
提示词要求 JSON无保证提示偶发多余文字或缺字段
JSON 模式合法 JSON服务端不保证符合具体 Schema
Schema 约束解码符合 Schema服务端解码器支持的 Schema 关键字有限
工具/函数调用参数符合定义服务端需按工具调用协议使用
事后校验 + 重试最终可保证客户端增加延迟与成本

优点零运维，格式基本可靠

优点支持正则与自定义文法，可控性强

优点通用，对任何模型可用

🕳️ 07 · 常见坑

  • ✗以为格式合法就等于内容正确

    ✓对字段值做业务校验，如范围、枚举含义与引用是否存在

  • ✗Schema 过深或过于复杂，导致质量下降或不被支持

    ✓精简结构，字段命名语义清楚，必要时拆成多步

  • ✗要求先输出答案字段再输出推理字段

    ✓需要推理时把推理字段放在答案字段之前

  • ✗未处理 max_tokens 截断导致 JSON 不完整

    ✓设置足够的输出上限，并检查结束原因

🎤 09 · 面试追问
约束解码如何保证 100% 符合 Schema？

把 Schema 编译成自动机，每一步只允许能让当前前缀继续成为合法输出的 Token，非法 Token 概率被置零，结束符只有在结构完整时才允许。因此任何采样路径都必然产生合法结构，前提是输出没有被长度上限截断。

约束解码会影响模型输出质量吗？

可能。掩码改变了模型原本的分布，若 Schema 与模型自然表达方式差异大，或强制在推理前输出结论，质量可能下降。缓解方式：字段语义清晰、先推理后答案、Schema 尽量简单，并用评测集对比。

为什么 Token 边界是约束解码实现的难点？

文法定义在字符层面，而模型以子词 Token 生成，一个 Token 可能跨越多个语法符号或只覆盖半个关键字。实现需要把词表中的每个 Token 映射到自动机的状态转移，并缓存这些映射，否则每步检查整个词表会非常慢。
