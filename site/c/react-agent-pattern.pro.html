ReAct 推理-行动循环

ReAct Pattern

🧸 回到小白版

📐 01 · 定义

ReAct（Reasoning + Acting）是 2022 年论文提出的 Agent 范式：让大模型交替产生推理（Thought）与行动（Action，即调用工具），并把工具返回的观察（Observation）加入上下文，循环直到得出最终答案。它把思维链推理与外部工具结合，减少凭空编造，是当今多数 Agent 框架和编程 Agent 循环的基础思想。

⚙️ 02 · 原理
  1. 1

    系统提示定义任务、可用工具及其参数，并要求模型在每一步先给出推理，再选择行动或给出最终答案。

  2. 2

    模型输出一个工具调用（现代实现多用原生 tool calling 的结构化格式，而非解析文本）。

  3. 3

    运行时（harness）执行工具，把结果作为观察追加到消息历史中。

  4. 4

    模型基于新的观察继续推理，决定下一次行动、修正计划，或判断信息足够后输出最终答案。

  5. 5

    运行时施加终止条件：最大步数、token 预算、超时，以及对危险工具的人工确认。

🔤 03 · 术语
思考 (Thought)
模型对当前状态和下一步的推理文本。
行动 (Action)
模型选择调用的工具及参数。
观察 (Observation)
工具执行结果，作为下一轮输入。
Agent 循环 (Agent Loop)
模型调用、工具执行、结果回填的反复迭代。
终止条件 (Stop Condition)
最大步数、预算或模型声明完成等结束循环的规则。
Harness
包裹模型的运行时，负责工具执行、权限、上下文管理。
💻 04 · 代码
最小 ReAct 循环（原生工具调用）python
import json
from openai import OpenAI

client = OpenAI()
def get_weather(city: str) -> str:          # 示例工具
    return json.dumps({"city": city, "forecast": "rain"})
TOOLS = {"get_weather": get_weather}
schema = [{"type": "function", "function": {
    "name": "get_weather", "description": "查询城市天气",
    "parameters": {"type": "object", "properties": {"city": {"type": "string"}},
                   "required": ["city"]}}}]

msgs = [{"role": "system", "content": "先简述思考，再按需调用工具。"},
        {"role": "user", "content": "明天去杭州要带伞吗？"}]
for step in range(8):                        # 终止条件：最多 8 步
    m = client.chat.completions.create(model="gpt-4o-mini",  # 以官方文档为准
        messages=msgs, tools=schema).choices[0].message
    msgs.append(m)
    if not m.tool_calls:                     # 无工具调用 = 最终答案
        print(m.content); break
    for call in m.tool_calls:                # 行动 -> 观察
        result = TOOLS[call.function.name](**json.loads(call.function.arguments))
        msgs.append({"role": "tool", "tool_call_id": call.id, "content": result})

模型决定行动，运行时执行并回填观察，直到不再调用工具；步数上限防止无限循环。

📊 05 · 参数对比

Agent 范式对比

范式流程优点缺点
ReAct想—做—看 逐步循环灵活，能根据观察纠错步数多、成本与延迟高
Plan-and-Execute先完整规划再逐步执行结构清晰、可审阅计划计划失效时调整慢
单次工具调用一次调用后直接回答快、便宜无法处理多步任务
固定工作流开发者编排步骤可预测、易测试缺乏灵活性
⚖️ 06 · 方案取舍

自由 ReAct 循环

优点适应开放任务

代价行为难预测，可能绕圈

适用探索性任务、编程 Agent

固定工作流 + 局部 ReAct

优点可控性高

代价设计成本高

适用业务流程明确的生产系统

先规划后执行

优点计划可被人审阅

代价对动态环境适应较差

适用长任务、需审批的场景

🕳️ 07 · 常见坑

  • ✗不设最大步数和预算，Agent 无限循环

    ✓设置步数、token、时间上限，并检测重复调用

  • ✗工具报错只返回空字符串

    ✓返回结构化、可读的错误信息，帮助模型自我纠正

  • ✗一次暴露几十个工具，模型选错

    ✓精简工具集，写清描述与参数约束，按任务动态加载

  • ✗把工具结果中的指令当作可信输入

    ✓把观察视为不可信数据，敏感操作需人工确认

☑️ 08 · 检查清单
🎤 09 · 面试追问
ReAct 和思维链（CoT）有什么区别？

思维链只在模型内部推理，所有信息来自参数记忆，容易编造事实；ReAct 在推理中穿插工具调用，用外部观察校正推理。代价是更多轮调用，带来更高延迟和成本。

现代 Agent 还需要显式写出 Thought 吗？

原论文用文本格式让模型写 Thought/Action。如今主流模型有原生工具调用，推理模型也有内部思考，因此不一定需要显式 Thought 文本，但“推理—行动—观察”的循环结构不变；保留简短的推理说明有助于调试与审计。

如何防止 Agent 陷入循环？

设置最大步数与预算；检测相同工具和参数的重复调用；在观察中提供明确的成功或失败信号；上下文过长时压缩历史；必要时引入反思步骤或交给人工处理。
