温度 (Temperature)

Temperature

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

温度（Temperature）是 LLM 解码阶段的采样参数，用于缩放输出概率分布的「尖锐程度」：低温让高概率 Token 更占优，输出更确定；高温拉平分布，输出更多样。它不改变模型知识，只改变选词的随机性，常与 top_p、top_k 一起控制生成风格。

⚙️ 02 · 原理
  1. 1

    模型为词表中每个 Token 输出一个原始分数（logit）。

  2. 2

    把每个 logit 除以温度 T，再做 softmax 得到概率分布。

  3. 3

    T < 1 放大分数差距，分布变尖；T > 1 缩小差距，分布变平。

  4. 4

    T 趋近 0 时近似贪心解码，总选最高概率 Token，但多数服务不保证完全确定。

  5. 5

    可再叠加 top_p（核采样）或 top_k 截掉长尾，然后按概率随机抽取下一个 Token。

🔤 03 · 术语
Logit
softmax 之前的原始分数，温度作用在这一层。
Softmax
把一组分数转换成总和为 1 的概率分布的函数。
Top-p (Nucleus Sampling)
只在累计概率达到 p 的最小 Token 集合里采样。
Top-k
只在概率最高的 k 个 Token 中采样。
贪心解码 (Greedy Decoding)
每步直接取概率最高的 Token，不做随机采样。
💻 04 · 代码
温度如何改变分布python
# pip install numpy ；演示温度对 softmax 分布的影响
import numpy as np

logits = np.array([4.0, 3.0, 1.0, 0.5])   # 4 个候选 Token 的原始分数
tokens = ["的", "了", "吧", "呢"]

def softmax_t(x, t):
    z = x / t
    z = z - z.max()                # 数值稳定
    p = np.exp(z)
    return p / p.sum()

for t in [0.2, 0.7, 1.0, 1.5]:
    p = softmax_t(logits, t)
    print(f"T={t}: ", {k: round(float(v), 3) for k, v in zip(tokens, p)})

# 输出可见：T 越低，第一名概率越接近 1；T 越高，分布越平均

温度只是对 logit 的缩放，跑一下就能直观看到分布尖锐度的变化。

⚖️ 06 · 方案取舍

低温（约 0–0.3）

优点稳定、可复现性更好

代价措辞单调，可能陷入重复

适用抽取、分类、代码、结构化输出

中温（约 0.5–0.8）

优点兼顾准确与自然

代价偶有发散

适用对话、解释、一般写作

高温（≥1）

优点多样、有创意

代价更易出错和跑题

适用头脑风暴、多候选生成

🕳️ 07 · 常见坑

  • ✗以为 temperature=0 就完全可复现

    ✓服务端并行计算等因素仍可能有差异，需要缓存或记录输出

  • ✗同时大幅调 temperature 和 top_p

    ✓官方通常建议只调其中一个，便于定位效果

  • ✗用高温度「治」回答单调

    ✓先改提示词和示例，温度只做微调

☑️ 08 · 检查清单
🎤 09 · 面试追问
温度为 0 时为什么输出仍可能变化？

服务端推理涉及浮点运算顺序、批处理和硬件并行，相同输入的 logit 可能有微小差异，平局或近似平局时会选到不同 Token，后续自回归放大差异。此外部分接口在 0 时并非严格贪心。

temperature 和 top_p 有何区别？

温度改变整个分布的形状（缩放 logit）；top_p 不改形状，只截掉累计概率之外的长尾再归一化采样。前者控制「多随机」，后者控制「候选池多大」，通常二选一调整。

代码生成该用什么温度？

一般偏低以减少语法和逻辑错误；但若用「生成多个候选再用测试筛选」的策略，适度提高温度可增加候选多样性、提高至少一个通过的概率。具体以评测结果为准。
