抗暴力破解慢哈希

bcrypt & Argon2

📐 01 · 定义

bcrypt 与 Argon2 是专为口令存储设计的慢哈希（密钥派生函数，KDF），位于应用的认证层。它们通过可调的计算成本和内存成本，让每次口令验证都付出固定代价，使离线暴力破解与 GPU/ASIC 并行攻击在经济上不可行。

⚙️ 02 · 原理
  1. 1

    注册时生成随机盐（salt），与口令一起输入 KDF，同一口令每次得到不同哈希。

  2. 2

    bcrypt 基于 Blowfish 的昂贵密钥扩展，成本因子 cost 是对数，每加 1 耗时约翻倍。

  3. 3

    Argon2 用内存成本 m、迭代次数 t、并行度 p 三个参数控制代价，大内存让 GPU 难以并行。

  4. 4

    输出是自描述字符串（如 $2b$12$… 或 $argon2id$v=19$m=…），算法、参数和盐都编码在内。

  5. 5

    登录时从存储串解析参数，重新计算并做常量时间比较，验证通过即可判断是否需要按新参数重哈希。

🔤 03 · 术语
密钥派生函数 (KDF)
从口令派生密钥或校验值的函数，口令存储用的是刻意变慢的 KDF。
成本因子 (Cost Factor)
bcrypt 的对数轮数参数，cost=12 表示 2^12 轮密钥扩展。
内存困难 (Memory-hard)
计算必须占用大量内存，削弱 GPU/ASIC 的并行优势。
Argon2id
Argon2 的混合变体，兼顾抗侧信道与抗 GPU，是 RFC 9106 推荐的默认选择。
胡椒 (Pepper)
存放在数据库之外（如 KMS/环境变量）的额外秘密，可选的纵深防御。
重哈希 (Rehash)
用户登录成功后按新参数或新算法重新计算并覆盖旧哈希。
💻 04 · 代码
argon2-cffi 存储与校验python
# pip install argon2-cffi
from argon2 import PasswordHasher
from argon2.exceptions import VerifyMismatchError

# OWASP 给出的 Argon2id 最低配置之一：19 MiB 内存、2 次迭代、并行度 1
ph = PasswordHasher(time_cost=2, memory_cost=19456, parallelism=1)

stored = ph.hash("correct horse battery staple")
print(stored)  # $argon2id$v=19$m=19456,t=2,p=1$<salt>$<hash>

def login(stored_hash: str, password: str) -> bool:
    try:
        ph.verify(stored_hash, password)
    except VerifyMismatchError:
        return False
    # 参数升级后，旧哈希在登录成功时顺手重算
    if ph.check_needs_rehash(stored_hash):
        new_hash = ph.hash(password)  # 写回数据库
    return True

参数显式写出，哈希串自带算法与参数；check_needs_rehash 支持平滑升级。

⚖️ 06 · 方案取舍

Argon2id

优点内存困难，抗 GPU 最好，标准化（RFC 9106）

代价每次登录占内存，高并发需容量规划

适用新项目默认选择

bcrypt

优点生态成熟，各语言都有稳定实现

代价非内存困难，72 字节截断

适用老系统或框架默认即 bcrypt

PBKDF2

优点FIPS-140 认可，标准库常自带

代价易被 GPU 并行加速

适用必须满足 FIPS 合规时

🕳️ 07 · 常见坑

  • ✗用 SHA-256 加盐就当作口令存储

    ✓通用哈希太快，改用 Argon2id/bcrypt 等专用 KDF

  • ✗bcrypt 前先拼接超长内容，导致超过 72 字节部分被忽略

    ✓限制口令长度或改用 Argon2id，避免静默截断

  • ✗参数调得过高，登录高峰把 CPU/内存打满

    ✓压测单次耗时与并发上限，配合登录限流

  • ✗升级算法时强制全员重置密码

    ✓登录成功时按新参数重哈希，逐步迁移

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么不能用 SHA-256 存口令？

SHA-256 为速度设计，单卡每秒可算数十亿次，泄库后可快速离线爆破。口令 KDF 引入可调成本和内存占用，把每次猜测的代价拉高几个数量级，同时盐防彩虹表、防同口令同哈希。

Argon2 的 m、t、p 如何取舍？

先定可接受的单次耗时与内存预算，再优先把内存 m 调大（抗 GPU 主要靠它），t 补足耗时，p 按可用核数。OWASP 给出多组等价配置，如 m=19MiB,t=2,p=1。必须结合并发登录量压测。

如何从 bcrypt 平滑迁到 Argon2id？

哈希串自带前缀可识别算法。登录时按前缀选算法校验，成功后用 Argon2id 重算并覆盖。长期不登录的账户可用“外层包裹”方案：对旧 bcrypt 值再做 Argon2id，或到期强制重置。
