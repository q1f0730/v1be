📐 01 · 定义

OpenAI 兼容接口指第三方模型服务或本地推理引擎，按 OpenAI REST API 的路径、请求体与响应结构（最常见是 /v1/chat/completions）提供服务。客户端只需替换 base_url、API Key 和模型名，即可复用 OpenAI SDK 和现有代码，是多模型切换与本地部署的事实标准；兼容通常只覆盖核心字段。

⚙️ 02 · 原理
  1. 1

    服务端实现与 OpenAI 相同的路径，如 POST /v1/chat/completions、/v1/embeddings、GET /v1/models。

  2. 2

    鉴权沿用 Authorization: Bearer <key> 请求头；本地服务往往不校验，但 SDK 仍要求传入一个非空字符串。

  3. 3

    请求体使用 messages 数组、model、temperature、max_tokens、stream 等字段；服务端忽略或报错其不支持的字段。

  4. 4

    流式响应采用 SSE（Server-Sent Events），逐行返回 data: {...} 的 chunk，最后以 data: [DONE] 结束。

  5. 5

    LLM 网关可在兼容层之上做路由、重试、限流与计费，把多家模型统一成一个入口。

🔤 03 · 术语
base_url
SDK 请求的根地址，替换它即可指向其他兼容服务。
Chat Completions
OpenAI 的对话补全接口，兼容生态最广泛的格式。
SSE (Server-Sent Events)
基于 HTTP 的单向流协议，用于流式返回 token。
工具调用 (Tool Calling)
tools / tool_calls 字段，各兼容实现支持程度不一。
LLM 网关 (LLM Gateway)
统一多家模型接口、做路由与观测的代理层。
Responses API
OpenAI 较新的接口，第三方兼容程度通常低于 Chat Completions。
💻 04 · 代码
同一份代码切换多家服务python
import os
from openai import OpenAI

# 示例：.env 中按需切换（地址与模型名以各家官方文档为准）
# OpenAI:  LLM_BASE_URL=https://api.openai.com/v1
# Ollama:  LLM_BASE_URL=http://localhost:11434/v1
# vLLM:    LLM_BASE_URL=http://localhost:8000/v1
client = OpenAI(
    base_url=os.environ["LLM_BASE_URL"],
    api_key=os.environ.get("LLM_API_KEY", "not-needed"),  # 本地服务也需非空
)

resp = client.chat.completions.create(
    model=os.environ["LLM_MODEL"],
    messages=[
        {"role": "system", "content": "你是简洁的助手"},
        {"role": "user", "content": "一句话解释 DNS"},
    ],
    temperature=0.2,
)
print(resp.choices[0].message.content)
print(resp.usage)  # 部分实现可能不返回 usage

配置外置到环境变量，代码零修改即可在云端与本地兼容服务间切换。

📊 05 · 参数对比

兼容性需逐项核对的点

能力常见差异验证方法
工具调用不支持、并行调用不支持或格式略有出入用固定用例测 tool_calls
结构化输出json_schema 严格模式支持不一检查是否返回合法 JSON
流式 usage可能不返回 token 统计检查最后一个 chunk
多模态输入图片字段支持不一发送图片测试
错误码与限流429 / Retry-After 行为不同模拟超限请求
⚖️ 06 · 方案取舍

直接用兼容接口 + 官方 SDK

优点代码简单，切换成本低

代价只能用到各家公共子集

适用原型、单一主力模型

经过 LLM 网关

优点统一路由、重试、观测与成本

代价多一跳延迟与一个组件

适用多模型生产环境

使用各家原生 SDK

优点可用全部专有特性

代价切换成本高

适用深度依赖某家特性时

🕳️ 07 · 常见坑

  • ✗假设兼容就等于行为一致

    ✓对工具调用、JSON 输出、流式结束信号做契约测试

  • ✗把各家 API Key 写死在代码里

    ✓放环境变量或密钥管理服务，按环境注入

  • ✗切换模型后不重跑评测

    ✓不同模型对同一提示表现不同，切换前跑回归评测集

  • ✗本地服务直接暴露到公网且不鉴权

    ✓加反向代理鉴权或仅监听内网地址

🎤 09 · 面试追问
为什么 OpenAI 格式成了事实标准？

Chat Completions 较早普及，SDK 与周边工具（LangChain、各类 IDE 插件）大量基于它构建。新厂商和开源推理引擎提供兼容层，就能让用户零改造接入，降低迁移阻力。这是生态网络效应，而非正式标准。

兼容接口如何处理工具调用差异？

先查目标服务文档确认是否支持 tools 以及 tool_choice、并行调用等细节。然后用固定用例做契约测试，比较返回的 tool_calls 结构。差异大时在网关或适配层做转换，或针对该模型调整提示与解析逻辑。

如何设计可平滑切换模型的应用？

把模型访问封装成内部接口，配置外置；记录每次请求的模型、token 与延迟；建立黄金评测集，切换前对比质量；在网关层实现回退策略，主模型失败时降级到备用模型。
