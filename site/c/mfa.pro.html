多因素认证

MFA

📐 01 · 定义

多因素认证（Multi-Factor Authentication, MFA）要求用户提供两类及以上不同性质的凭证才能登录：你知道的（密码）、你拥有的（手机、安全密钥）、你本身的（指纹、面部）。即使密码泄露，攻击者仍缺少其他因素。抗钓鱼的 FIDO2/WebAuthn（含通行密钥）是目前安全性最高的主流方案。

⚙️ 02 · 原理
  1. 1

    第一因素：用户输入账号密码，服务端验证通过后并不直接放行，而是进入第二步。

  2. 2

    第二因素挑战：服务端要求出示另一类凭证，如动态验证码或安全密钥签名。

  3. 3

    TOTP 验证：认证 App 用共享密钥和当前时间计算 6 位码，服务端用同样算法比对。

  4. 4

    WebAuthn 验证：设备用绑定该网站域名的私钥签名挑战，服务端用公钥验证，钓鱼站无法复用。

  5. 5

    恢复机制：提供一次性恢复码或备用因素，防止设备丢失后无法登录。

🔤 03 · 术语
TOTP
基于时间的一次性密码，RFC 6238，常见于认证器 App。
WebAuthn / FIDO2
基于公钥加密的 Web 认证标准，绑定域名，抗钓鱼。
通行密钥 (Passkey)
可跨设备同步的 FIDO 凭证，可替代密码登录。
SIM 卡劫持 (SIM Swap)
攻击者冒领手机号以截获短信验证码。
MFA 疲劳攻击 (MFA Fatigue)
反复推送登录确认，诱使用户误点批准。
💻 04 · 代码
TOTP 原理演示python
# pip install pyotp
import pyotp

# 1. 用户开启 MFA 时，服务端为其生成共享密钥并安全保存
secret = pyotp.random_base32()

# 2. 生成二维码内容，用户用认证 App 扫描绑定
uri = pyotp.TOTP(secret).provisioning_uri(
    name="alice@example.com", issuer_name="MyApp")
print(uri)   # otpauth://totp/MyApp:alice%40example.com?secret=...&issuer=MyApp

# 3. 登录时：App 与服务端用同一密钥 + 当前时间各自算出 6 位码
totp = pyotp.TOTP(secret)          # 默认 30 秒一个时间窗口
code_from_user = totp.now()        # 演示：假装这是用户输入的码

# 4. 服务端验证；valid_window=1 容忍前后一个窗口的时钟偏差
print(totp.verify(code_from_user, valid_window=1))   # True

# 生产中还需：限制尝试次数、防止同一验证码重复使用

TOTP 不需要网络通信，安全性依赖共享密钥保密；它能防密码泄露，但不能防实时钓鱼。

📊 05 · 参数对比

第二因素安全性对比

方式抗钓鱼主要风险建议
短信验证码否SIM 劫持、短信拦截仅作最低保障
TOTP 认证器 App否实时钓鱼页面转发验证码常规账户推荐
推送确认部分MFA 疲劳攻击启用号码匹配
FIDO2 安全密钥 / 通行密钥是设备丢失需备用方案高价值账户首选
⚖️ 06 · 方案取舍

短信验证码

优点无需安装 App，普及度高

代价易受 SIM 劫持

适用面向大众且无更好选项时

认证器 App

优点离线可用、成本低

代价可被钓鱼页实时转发

适用开发者账号、常规业务系统

通行密钥 / 硬件密钥

优点抗钓鱼、体验好

代价跨平台恢复与兼容需规划

适用管理员、云平台、代码托管账号

🕳️ 07 · 常见坑

  • ✗只给普通账号开 MFA，管理员和云控制台没开

    ✓优先覆盖高权限账号：云平台、域名注册商、GitHub、邮箱

  • ✗恢复码截图存在相册或桌面

    ✓恢复码存进密码管理器或离线安全位置

  • ✗自研 MFA 不限制验证码尝试次数

    ✓加入速率限制与锁定，防止暴力枚举 6 位码

  • ✗用户对陌生推送随手点「批准」

    ✓启用号码匹配和上下文提示，并培训用户

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么 WebAuthn 能抗钓鱼而 TOTP 不能？

TOTP 验证码与网站无关，用户在钓鱼页输入后可被攻击者实时转发到真站。WebAuthn 的签名绑定了浏览器所见的真实域名（origin），钓鱼域名拿到的签名在真站无效，私钥也从不离开设备。

MFA 开启后账户就绝对安全吗？

不是。仍存在会话令牌窃取（登录后 Cookie 被盗）、实时钓鱼代理、MFA 疲劳、社会工程重置 MFA、恢复流程薄弱等风险。需要配合抗钓鱼因素、会话保护、异常登录检测和严格的重置流程。

开发者最应该优先保护哪些账号？

邮箱（可重置其他账号）、域名注册商与 DNS（可劫持流量）、云平台与模型 API 控制台（直接产生费用和数据访问）、代码托管平台（可篡改代码与 CI）、包注册表发布账号（供应链风险）。
