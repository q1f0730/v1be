乐观并发控制

Optimistic Locking

🧸 回到小白版

📐 01 · 定义

乐观锁（Optimistic Locking）是一种并发控制策略：读取时不加锁，写入时检查数据自读取后是否被他人修改（通常比较版本号），若已变化则拒绝写入并让调用方重试或提示冲突。它适合冲突概率低、读多写少，以及跨请求的长时间编辑场景。

⚙️ 02 · 原理
  1. 1

    表中增加 version 整数列（或更新时间戳），读取数据时一并取回版本号。

  2. 2

    用户在客户端编辑，可能持续数分钟，期间数据库不持有任何锁。

  3. 3

    保存时执行 UPDATE … SET version = version + 1 WHERE id = ? AND version = 读到的版本。

  4. 4

    受影响行数为 1 表示成功；为 0 说明版本已变化，发生冲突。

  5. 5

    冲突时由应用决定：自动重试、合并修改，或返回 409/412 让用户处理。

🔤 03 · 术语
版本列 (Version Column)
每次更新自增的整数，用于检测并发修改。
丢失更新 (Lost Update)
后写者覆盖先写者的修改而无人察觉。
比较并交换 (CAS)
仅当当前值等于预期值时才写入的原子操作。
If-Match / ETag
HTTP 层的乐观锁：带上版本标识，不匹配返回 412。
冲突率 (Conflict Rate)
写入因版本不符被拒的比例，决定是否适合乐观锁。
💻 04 · 代码
版本号检测并发修改python
import sqlite3

conn = sqlite3.connect(":memory:")
conn.execute("CREATE TABLE doc(id INTEGER PRIMARY KEY, body TEXT, version INTEGER NOT NULL)")
conn.execute("INSERT INTO doc VALUES (1, '初稿', 1)")

def save(doc_id: int, new_body: str, read_version: int) -> bool:
    cur = conn.execute(
        "UPDATE doc SET body = ?, version = version + 1 "
        "WHERE id = ? AND version = ?",
        (new_body, doc_id, read_version),
    )
    conn.commit()
    return cur.rowcount == 1   # 0 行表示被别人抢先修改了

# A、B 同时打开文档，都读到 version = 1
print(save(1, "A 的修改", 1))  # True，version 变为 2
print(save(1, "B 的修改", 1))  # False，冲突，需要重新读取后再改
print(conn.execute("SELECT body, version FROM doc").fetchone())  # ('A 的修改', 2)

版本检查与更新在一条 UPDATE 中原子完成；rowcount 为 0 即冲突。

⚖️ 06 · 方案取舍

乐观锁

优点无锁等待，可跨请求、跨长时间编辑

代价冲突多时大量重试浪费

适用冲突概率低、读多写少

悲观锁

优点冲突时排队而非失败

代价持锁阻塞他人，有死锁风险

适用热点数据高频写入

原子更新语句

优点最简单，无需版本

代价只适用于可表达为单条 SQL 的修改

适用计数器、余额增减

🕳️ 07 · 常见坑

  • ✗先 SELECT 版本比对，再单独 UPDATE

    ✓把版本条件写进同一条 UPDATE 的 WHERE

  • ✗冲突后自动重试，但用的仍是旧数据

    ✓重试前重新读取最新数据和版本

  • ✗用毫秒时间戳当版本，同毫秒更新漏检

    ✓使用自增整数版本列

  • ✗秒杀等高冲突场景用乐观锁

    ✓改用原子扣减、队列或悲观锁

🎤 09 · 面试追问
乐观锁和悲观锁怎么选？

看冲突概率与持锁时长。冲突少、编辑跨越多个请求（表单、文档）适合乐观锁，避免长时间持锁；冲突频繁、操作短小的热点写入适合悲观锁或原子更新，避免反复重试。

HTTP API 如何实现乐观锁？

GET 响应返回 ETag（版本或内容哈希），客户端 PUT/PATCH 时带 If-Match: 该 ETag。服务端比对当前版本，不一致返回 412 Precondition Failed；缺少 If-Match 可返回 428 要求带上。

乐观锁能防止写偏斜吗？

单行版本号只能检测同一行的并发修改。写偏斜涉及读取多行、写入不同的行，各行版本都不冲突，因此防不住。需要锁住相关行集合、引入汇总行版本或使用可串行化隔离。
