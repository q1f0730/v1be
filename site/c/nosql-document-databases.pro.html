文档型数据库 (NoSQL / MongoDB)

NoSQL Document Databases

📐 01 · 定义

文档型数据库以 JSON 类文档（MongoDB 使用二进制的 BSON）为存储单元，文档可嵌套数组与子文档、同一集合中字段结构可以不同。它属于 NoSQL 家族，强调按访问模式建模、读取一个聚合只需一次查询；代价是跨文档关联与约束弱于关系数据库。MongoDB、Firestore、Couchbase 是代表。

⚙️ 02 · 原理
  1. 1

    数据按集合（Collection）组织，每个文档有唯一 _id，可直接嵌入相关子数据。

  2. 2

    建模围绕查询模式：经常一起读取的数据嵌入同一文档，独立增长或多处共享的数据用引用。

  3. 3

    二级索引、复合索引与聚合管道支持过滤、排序、分组与有限的关联（$lookup）。

  4. 4

    单文档写入是原子的；MongoDB 自 4.0 起支持副本集上的多文档事务，但开销更高。

  5. 5

    模式灵活不代表无模式：可用 $jsonSchema 校验器在数据库层约束字段与类型。

🔤 03 · 术语
BSON
MongoDB 使用的二进制 JSON 格式，支持日期、Decimal128 等类型。
嵌入 vs 引用 (Embedding vs Referencing)
把关联数据放进同一文档，或只存另一文档的 ID。
聚合管道 (Aggregation Pipeline)
由 $match、$group 等阶段组成的数据处理流水线。
模式校验 (Schema Validation)
用 $jsonSchema 等规则在写入时校验文档结构。
JSONB
PostgreSQL 的二进制 JSON 类型，可在关系库中存文档。
💻 04 · 代码
mongosh：校验、嵌入与索引javascript
// 集合级模式校验：灵活但不失控
db.createCollection("orders", {
  validator: { $jsonSchema: {
    bsonType: "object",
    required: ["userId", "items", "total", "createdAt"],
    properties: {
      userId: { bsonType: "int" },
      total: { bsonType: "decimal" },   // 金额用 Decimal128，避免浮点误差
      items: { bsonType: "array", minItems: 1 },
    },
  }},
});

// 订单明细随订单一起读写：嵌入
db.orders.insertOne({
  userId: 42, createdAt: new Date(), total: NumberDecimal("59.80"),
  items: [{ sku: "TEA-01", qty: 2, price: NumberDecimal("29.90") }],
});

// 按查询模式建复合索引
db.orders.createIndex({ userId: 1, createdAt: -1 });
db.orders.find({ userId: 42 }).sort({ createdAt: -1 }).limit(10);

// 聚合：每个用户的消费总额
db.orders.aggregate([{ $group: { _id: "$userId", spent: { $sum: "$total" } } }]);

明细嵌入订单、用户信息引用；校验器与索引都按真实查询与约束设计。

📊 05 · 参数对比

文档库与关系库对比

维度文档数据库关系数据库
数据模型嵌套文档，模式灵活表与行，模式严格
关联查询嵌入或 $lookup，能力有限JOIN 成熟高效
事务单文档原子，多文档事务开销较大多行事务是核心能力
水平扩展原生分片较常见需分片方案或分布式 SQL
⚖️ 06 · 方案取舍

文档数据库

优点贴合对象结构、迭代快、读聚合一次到位

代价复杂关联与跨文档约束弱

适用内容、目录、事件、用户配置

关系数据库

优点强约束、JOIN 与事务成熟

代价模式变更需迁移

适用订单、账务等强一致关系数据

关系库 + JSONB 列

优点兼顾约束与灵活字段

代价JSON 内字段约束与索引需额外设计

适用大部分结构固定、少量扩展字段

🕳️ 07 · 常见坑

  • ✗把关系模型照搬成多个集合再频繁 $lookup

    ✓按访问模式重新建模，经常一起读的数据嵌入

  • ✗无限增长的数组嵌入文档（如全部评论）

    ✓无界数据拆到独立集合，文档有大小上限

  • ✗没有模式校验，同一字段类型混乱

    ✓启用 $jsonSchema 校验，应用层也做校验

  • ✗金额用 double 存储

    ✓使用 Decimal128 或以分为单位的整数

☑️ 08 · 检查清单
🎤 09 · 面试追问
什么时候嵌入，什么时候引用？

一对少、总是一起读取、生命周期一致的数据适合嵌入；一对多且无界增长、被多个父文档共享、需独立查询或频繁单独更新的数据适合引用。核心原则是按读写访问模式设计，并注意单文档大小上限。

MongoDB 支持事务吗？为何仍建议少用？

支持：4.0 起副本集多文档事务，4.2 起扩展到分片集群。但多文档事务有额外开销与时间限制，良好的文档建模通常能让大多数写入落在单文档内，利用单文档原子性即可。

博客系统选 MongoDB 还是 PostgreSQL？

关系清晰（用户、文章、评论、标签）且需要一致性与灵活查询时，PostgreSQL 更稳，必要字段可用 JSONB 扩展；若内容结构多变、读多写少且按文章聚合读取为主，文档库也合适。团队熟悉度也是关键因素。
