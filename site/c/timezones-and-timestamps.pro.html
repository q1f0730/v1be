时区与时间戳 (UTC)

Timezones & Timestamps

📐 01 · 定义

时间戳表示时间线上的一个绝对瞬间（如 Unix 时间：自 1970-01-01T00:00:00Z 起的秒数），时区则是把瞬间映射为当地钟面时间的规则，包含 UTC 偏移与夏令时变化，由 IANA 时区数据库维护。正确区分「瞬间」与「本地时间」，是避免跨时区显示错误、定时任务漂移和数据错位的基础。

⚙️ 02 · 原理
  1. 1

    系统内部用 UTC 瞬间存储与计算（Unix 时间戳或带时区的类型），与服务器所在地无关。

  2. 2

    传输使用 ISO 8601/RFC 3339 格式并带偏移，如 2026-10-20T08:00:00Z 或 +08:00。

  3. 3

    展示时按用户的 IANA 时区（如 Asia/Shanghai）转换；偏移会随夏令时变化，不能写死。

  4. 4

    对「每天早上 9 点」这类本地规则，需保存时区名称，在每次计算时按当日规则换算成 UTC。

  5. 5

    PostgreSQL 的 timestamptz 存储 UTC 瞬间，输出时按会话 TimeZone 转换；timestamp 不带时区信息。

🔤 03 · 术语
UTC
协调世界时，全球时间基准，没有夏令时。
Unix 时间戳 (Epoch Time)
自 1970-01-01 UTC 起经过的秒数（或毫秒数）。
IANA 时区数据库 (tz database)
记录各地区历史与当前时区规则，以 Area/City 命名。
朴素时间 (Naive Datetime)
不含时区信息的日期时间，无法确定对应哪个瞬间。
RFC 3339
ISO 8601 的互联网时间格式子集，要求带时区偏移。
💻 04 · 代码
Python 中正确处理时区python
from datetime import datetime, timedelta, timezone
from zoneinfo import ZoneInfo   # Python 3.9+

# 1) 取当前时间：用带时区的 UTC（utcnow() 返回朴素时间，3.12 起已弃用）
now = datetime.now(timezone.utc)
print(now.isoformat())                      # 如 2026-10-20T08:00:00+00:00

# 2) 展示时转换为用户时区
print(now.astimezone(ZoneInfo("Asia/Shanghai")))

# 3) 解析带偏移的字符串
t = datetime.fromisoformat("2026-10-20T16:00:00+08:00")
print(t.astimezone(timezone.utc))           # 2026-10-20 08:00:00+00:00

# 4) 夏令时陷阱：本地时间加 1 天，不一定等于加 24 小时
ny = ZoneInfo("America/New_York")
before = datetime(2026, 3, 7, 12, 0, tzinfo=ny)   # 美东 2026-03-08 开始夏令时
after = before + timedelta(days=1)                # 墙上时间仍是 12:00
print((after - before), after.utcoffset())       # 1 day，偏移已从 -05:00 变为 -04:00
print(after.astimezone(timezone.utc) - before.astimezone(timezone.utc))  # 23:00:00

同一时区内相减按墙上时间计；换算成 UTC 后才是真实间隔。周期规则要保存时区名。

时间数据该存什么

场景存储方式原因
事件发生时刻UTC 瞬间（timestamptz）全球唯一、可比较
未来的本地预约本地时间 + IANA 时区名时区规则可能变化
生日等纯日期date 类型与时区无关

⚖️ 06 · 方案取舍

存 Unix 整数时间戳

优点紧凑、比较快、跨语言

代价不可读，秒/毫秒易混

适用日志、高性能计算

存 timestamptz

优点数据库原生时区转换与函数

代价依赖会话时区设置展示

适用关系数据库业务表

存本地时间 + 时区名

优点正确表达未来本地规则

代价计算时需转换，查询复杂

适用日程、闹钟、周期任务

🕳️ 07 · 常见坑

  • ✗存储朴素本地时间，不知道是哪个时区

    ✓存 UTC 瞬间或明确带时区的类型

  • ✗把偏移量（+08:00）当时区存储

    ✓存 IANA 名称，偏移会随夏令时与政策变化

  • ✗前端 new Date('2026-10-20') 与 new Date('2026-10-20T00:00') 解析时区不同

    ✓前者按 UTC、后者按本地解析；统一传完整 RFC 3339 字符串

  • ✗秒级与毫秒级时间戳混用

    ✓约定单位并在字段名中注明，如 created_at_ms

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么不能把 +08:00 当作用户时区存储？

偏移只描述某一时刻与 UTC 的差。很多地区有夏令时，偏移随季节变化，政府也可能调整时区规则。保存 IANA 名称（如 America/New_York），由时区数据库在具体日期计算正确偏移。

PostgreSQL 中 timestamp 与 timestamptz 的区别？

timestamptz 输入时按会话时区或显式偏移换算为 UTC 存储，输出时再转为会话时区，代表绝对瞬间；timestamp 只存钟面值、不含时区，无法确定对应哪个瞬间。业务时刻通常应使用 timestamptz。

「每天北京时间 9 点提醒」应该怎么存和算？

存本地时间 09:00 与时区 Asia/Shanghai，每次调度时用时区库算出下一次对应的 UTC 瞬间。若直接存一个 UTC 时刻，在有夏令时的地区会出现整小时漂移。
