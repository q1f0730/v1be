分支 (Branch)

Branch

🧸 回到小白版

📐 01 · 定义

分支（Branch）在 Git 中只是一个指向某个提交的可移动指针，创建和切换几乎零成本。它让开发者在隔离的历史线上并行开发功能、修复缺陷或做实验，完成后再合并回主分支。分支策略（如 GitHub Flow、主干开发）决定团队如何组织并行工作与发布。

⚙️ 02 · 原理
  1. 1

    创建：git switch -c 新建一个指向当前提交的指针，不复制任何文件，几乎瞬间完成。

  2. 2

    切换：HEAD 指向新分支，Git 把工作区更新为该分支最新提交的状态。

  3. 3

    前进：在分支上提交时，只有当前分支的指针随新提交向前移动，其他分支保持不动。

  4. 4

    分叉：多个分支从同一祖先提交出发各自提交，形成互不影响的并行历史线。

  5. 5

    合并或删除：通过 merge 或 PR 合回主分支，完成后删除分支指针，提交仍保留。

🔤 03 · 术语
主分支 (main)
代表可发布状态的默认分支，旧称 master。
功能分支 (Feature Branch)
为单个功能或修复创建的短期分支。
主干开发 (Trunk-based Development)
所有人频繁向主干合入小改动，分支存活很短。
跟踪分支 (Tracking Branch)
与远程分支关联的本地分支，便于 push/pull。
快进合并 (Fast-forward)
目标分支无新提交时，直接移动指针完成合并。
💻 04 · 代码
分支日常与并行 Agentbash
git switch -c feat/search          # 新建并切换到功能分支
git branch -vv                     # 查看本地分支及跟踪关系

# 推送并建立跟踪关系
git push -u origin feat/search

# 保持与主干同步（在功能分支上）
git fetch origin
git rebase origin/main             # 或 git merge origin/main

# 用 worktree 同时检出多个分支到不同目录
# 适合让两个 AI Agent 并行开发而互不干扰
git worktree add ../app-fix-login -b fix/login
git worktree list

# 合并后清理
git switch main && git pull
git branch -d feat/search          # 已合并才允许删除
git worktree remove ../app-fix-login

分支只是指针，代价极低；worktree 让多个分支同时拥有独立工作目录。

📊 05 · 参数对比

常见分支策略

策略做法适合
GitHub Flowmain + 短期功能分支 + PR持续部署的 Web 项目
主干开发极短分支或直接小步合入，配合特性开关CI 成熟的高频发布团队
Git Flowdevelop、release、hotfix 等多条长期分支有固定版本发布周期的软件
⚖️ 06 · 方案取舍

短期分支（数小时到几天）

优点冲突少，合并简单

代价需拆小任务

适用大多数团队的默认选择

长期功能分支

优点大功能可完整开发后再合

代价与主干偏离大，合并冲突多

适用尽量避免，必要时定期同步主干

特性开关代替长分支

优点代码早合入，按开关发布

代价需管理开关与清理

适用高频发布、灰度上线

🕳️ 07 · 常见坑

  • ✗直接在 main 上开发并推送

    ✓所有改动走功能分支与 PR，并开启分支保护

  • ✗功能分支几周不同步主干

    ✓定期 rebase 或 merge 主干，及早暴露冲突

  • ✗多个 Agent 在同一工作目录切换不同分支

    ✓每个 Agent 用独立 worktree 或克隆

  • ✗分支命名随意，难以识别

    ✓约定前缀，如 feat/、fix/、chore/

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么 Git 分支比 SVN 分支轻量？

Git 分支只是一个记录提交哈希的小文件（引用），创建和切换不复制文件；SVN 分支是服务器上的目录拷贝，概念和操作都更重。正因为轻量，Git 鼓励为每个小任务开分支。

主干开发如何保证主干稳定？

依靠小批量改动、完整的自动化测试与 CI 必需检查、代码评审、特性开关隐藏未完成功能，以及快速回滚能力。主干随时可发布，问题通过小步修复或回滚解决，而不是靠长时间隔离分支。

如何让多个 AI Agent 并行开发？

给每个 Agent 分配独立任务与分支，用 git worktree 为每个分支提供独立目录，避免互相覆盖文件；各自运行测试后提交 PR；由人或合并流程统一处理冲突与集成测试。
