Kubernetes (K8s)

📐 01 · 定义

Kubernetes（K8s）是开源的容器编排平台，用声明式 API 管理容器化应用的部署、扩缩、服务发现、配置和自愈。用户提交期望状态，控制平面中的各类控制器持续把实际状态调谐到期望状态。它位于基础设施与应用之间的平台层，已成为云原生事实标准，但学习和运维成本较高。

⚙️ 02 · 原理
  1. 1

    用户用 YAML 描述期望状态，如 Deployment 的副本数和镜像，通过 kubectl 提交给 API Server。

  2. 2

    API Server 校验后把对象存入 etcd，etcd 是集群状态的唯一来源。

  3. 3

    控制器监听对象变化，例如 Deployment 控制器创建 ReplicaSet，进而创建 Pod。

  4. 4

    调度器根据资源请求、亲和性等约束把 Pod 分配到节点，节点上的 kubelet 拉起容器。

  5. 5

    Service 为一组 Pod 提供稳定访问入口；Pod 故障时控制器自动重建，实现自愈。

🔤 03 · 术语
Pod
最小调度单元，包含一个或多个共享网络与存储的容器。
控制循环 (Reconciliation Loop)
控制器不断比较期望与实际状态并做调整。
etcd
保存集群全部状态的分布式键值存储。
Service
为一组 Pod 提供稳定虚拟 IP 和 DNS 名称的抽象。
Operator
用自定义资源和控制器封装特定应用运维知识的模式。
💻 04 · 代码
Deployment 加 Serviceyaml
apiVersion: apps/v1
kind: Deployment
metadata: { name: web }
spec:
  replicas: 3                       # 期望状态：始终 3 个副本
  selector: { matchLabels: { app: web } }
  template:
    metadata: { labels: { app: web } }
    spec:
      containers:
        - name: web
          image: nginx:1.27
          ports: [{ containerPort: 80 }]
          resources:
            requests: { cpu: 100m, memory: 128Mi }
            limits: { memory: 256Mi }
---
apiVersion: v1
kind: Service
metadata: { name: web }
spec:
  selector: { app: web }            # 按标签找到后端 Pod
  ports: [{ port: 80, targetPort: 80 }]

kubectl apply -f 提交后，删掉任意一个 Pod 都会被自动补回，体现声明式与自愈。

📊 05 · 参数对比

核心组件分工

组件所在位置职责
kube-apiserver控制平面所有操作的统一入口与校验
etcd控制平面持久化集群状态
kube-scheduler控制平面为 Pod 选择节点
kube-controller-manager控制平面运行各类控制器
kubelet每个节点按 Pod 规格运行并上报容器状态
⚖️ 06 · 方案取舍

托管 Kubernetes（EKS/GKE/AKS 等）

优点控制平面由厂商运维

代价仍需管理节点、网络与升级

适用需要 K8s 能力的多数团队

自建集群

优点完全可控

代价运维 etcd、升级、证书成本高

适用本地机房或有强定制需求

更简单的平台（PaaS/Serverless 容器）

优点上手快、运维少

代价灵活性和可移植性较低

适用小团队、少量服务

🕳️ 07 · 常见坑

  • ✗不设资源 requests，调度器无法合理分配，节点过载。

    ✓为所有容器设置 requests 与内存 limit。

  • ✗使用 latest 镜像标签，回滚和排查时不知道跑的是哪个版本。

    ✓使用不可变版本号或镜像摘要。

  • ✗直接用 kubectl edit 改生产，配置与仓库不一致。

    ✓配置纳入 Git，通过 CI 或 GitOps 工具发布。

  • ✗把 Secret 当成加密存储。

    ✓Secret 默认仅 base64 编码，需开启静态加密并控制 RBAC。

🎤 09 · 面试追问
Deployment 创建后发生了什么？

API Server 校验并写入 etcd；Deployment 控制器创建 ReplicaSet；ReplicaSet 控制器按副本数创建 Pod；调度器为 Pod 选节点；kubelet 通过容器运行时拉镜像启动容器并上报状态；Service 端点随 Pod 就绪更新。

什么是声明式 API，好处是什么？

用户描述想要的最终状态而不是操作步骤，控制器负责持续让现实接近它。好处是幂等，可重复 apply；自愈，故障后自动恢复；便于把配置纳入 Git 做审计和回滚。

小团队一定要上 Kubernetes 吗？

不一定。它解决多服务调度、扩缩和自愈问题，但带来网络、存储、升级、安全等运维负担。服务少、团队小时，托管 PaaS 或 Serverless 容器往往更划算，等规模需要时再迁移。
