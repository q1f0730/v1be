个人敏感信息脱敏 (PII)

PII Redaction

📐 01 · 定义

PII 脱敏（PII Redaction）指在日志、分析数据、第三方调用（包括发给大模型的提示）中识别并遮蔽、替换或删除个人身份信息，如姓名、手机号、证件号、邮箱、地址、银行卡号。它属于数据安全与隐私工程层，是数据最小化原则的落地手段，可降低泄露影响与合规风险。

⚙️ 02 · 原理
  1. 1

    梳理数据流，确定 PII 可能出现的位置：请求日志、错误追踪、分析埋点、LLM 提示与输出。

  2. 2

    识别：用正则与校验规则（如证件号校验位）、字典、NER 模型或组合检测器找出 PII 实体。

  3. 3

    处理：按场景选择遮蔽（138****5678）、替换为类型占位符、哈希、加密或可逆的令牌化。

  4. 4

    在数据离开受信边界前执行，如日志写入前、调用外部模型前，而非事后清洗。

  5. 5

    需要还原时（如 LLM 回答中引用用户姓名），由服务端用令牌映射表替换回原值，映射表严格限权。

🔤 03 · 术语
PII (Personally Identifiable Information)
能直接或结合其他信息识别个人的数据。
遮蔽 (Masking)
用星号等字符替换部分内容，保留格式。
令牌化 (Tokenization)
用无意义令牌替换原值，映射表单独保存，可逆。
假名化 (Pseudonymisation)
处理后需借助额外信息才能识别个人，GDPR 中仍属个人数据。
匿名化 (Anonymisation)
无法再识别个人，通常不再受个人数据法规约束。
💻 04 · 代码
日志与 LLM 调用前的脱敏python
import re, uuid

PATTERNS = {
    "PHONE": re.compile(r"(?<!\d)1[3-9]\d{9}(?!\d)"),             # 中国大陆手机号
    "ID":    re.compile(r"(?<!\d)\d{17}[\dXx](?!\d)"),             # 18 位身份证号
    "EMAIL": re.compile(r"[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(?:\.[A-Za-z0-9-]+)+"),
}

def redact(text: str, vault: dict | None = None) -> str:
    """把 PII 替换为占位符；传入 vault 时记录映射以便服务端还原"""
    for kind, pat in PATTERNS.items():
        def sub(m):
            token = f"<{kind}_{uuid.uuid4().hex[:6]}>"
            if vault is not None:
                vault[token] = m.group()
            return token
        text = pat.sub(sub, text)
    return text

vault = {}
prompt = redact("我叫小王，电话13812345678，邮箱wang@example.com", vault)
print(prompt)   # 发给模型的内容不含原始手机号与邮箱
# 模型回复中的占位符可用 vault 在服务端替换回原值

正则只覆盖格式固定的 PII；姓名、地址需 NER（如 Microsoft Presidio）辅助检测。

📊 05 · 参数对比

脱敏方式对比

方式可逆保留可用性典型场景
遮蔽否保留格式，便于人工核对客服界面、日志
占位符替换否（或配映射表）保留语义类型LLM 提示、分析
哈希（加盐/HMAC）否可做关联与去重埋点用户 ID
令牌化/加密是（需密钥/映射）可还原原值支付卡、需回填的流程
⚖️ 06 · 方案取舍

规则/正则检测

优点快、可解释、零成本

代价对姓名、地址等非结构化 PII 漏检

适用格式固定的字段

NER 模型检测

优点覆盖非结构化文本

代价有误报漏报，需算力，中文支持需验证

适用聊天记录、文档

源头不记录（字段白名单）

优点最彻底

代价排障信息可能不足

适用日志与埋点设计

🕳️ 07 · 常见坑

  • ✗先全量写日志，再定期批量清洗

    ✓在写入前脱敏，并对日志字段使用白名单

  • ✗只脱敏请求体，忽略 URL 参数和错误堆栈

    ✓覆盖 URL、Header、异常信息与第三方 SDK 上报

  • ✗用无盐哈希处理手机号，被字典轻易还原

    ✓使用带密钥的 HMAC，或改用令牌化

  • ✗把可逆映射表和脱敏数据放在一起

    ✓映射表单独存储、加密并严格限制访问

🎤 09 · 面试追问
假名化和匿名化有什么区别？

假名化后借助额外信息（如映射表、密钥）仍可识别个人，GDPR 下仍是个人数据；匿名化后无法以合理手段重新识别，才可能脱离个人数据范畴。仅哈希手机号通常只算假名化。

向 LLM 发送数据时如何处理 PII？

先评估是否真的需要；需要时在服务端用占位符替换，模型只处理语义，返回后再还原；同时确认供应商的数据保留与训练使用政策，签订数据处理协议。

为什么正则脱敏不够？

正则只能匹配格式固定的模式；姓名、地址、自由文本中的健康信息等无固定格式，还存在组合识别风险。需要 NER 模型、字段级白名单与数据最小化共同作用。
