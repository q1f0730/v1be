K8s入口控制器

Ingress Controllers

📐 01 · 定义

Ingress 控制器是 Kubernetes 集群的 L7 入口组件：它监听 Ingress 资源中声明的域名、路径和 TLS 规则，配置底层反向代理（如 NGINX、Envoy、Traefik），把外部 HTTP/HTTPS 请求路由到集群内的 Service。Ingress 资源只是规则，需控制器才生效。

⚙️ 02 · 原理
  1. 1

    部署控制器：以 Deployment 运行代理，并通过 LoadBalancer 或 NodePort 暴露。

  2. 2

    声明规则：用户创建 Ingress 资源，指定 ingressClassName、主机名、路径与后端 Service。

  3. 3

    监听变化：控制器监听 Ingress、Service、Endpoint 与 Secret，生成代理配置并热加载。

  4. 4

    处理请求：按 Host 与路径匹配规则，终止 TLS 后转发到后端 Pod。

  5. 5

    扩展能力：通过注解或自定义资源配置重写、限流、认证等，各控制器语法不同。

🔤 03 · 术语
Ingress 资源
声明 HTTP 路由规则的 K8s API 对象，本身不处理流量。
IngressClass
指定由哪个控制器处理某个 Ingress，支持多控制器并存。
TLS 终止 (TLS Termination)
在入口处解密 HTTPS，后端可以使用明文或重新加密。
Gateway API
Ingress 的后继 API，角色分离、表达力更强、可移植性更好。
pathType
路径匹配方式：Exact、Prefix 或 ImplementationSpecific。
💻 04 · 代码
带 TLS 的 Ingressyaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web
spec:
  ingressClassName: nginx            # 由哪个控制器处理
  tls:
  - hosts: ["app.example.com"]
    secretName: app-tls              # 证书存放在该 Secret
  rules:
  - host: app.example.com
    http:
      paths:
      - path: /api
        pathType: Prefix
        backend:
          service: {name: api, port: {number: 8080}}
      - path: /
        pathType: Prefix
        backend:
          service: {name: frontend, port: {number: 80}}

同一域名按路径分流到两个 Service；证书可由 cert-manager 自动签发到该 Secret。

⚖️ 06 · 方案取舍

Ingress

优点生态成熟，资料多

代价高级功能依赖各家注解，不可移植

适用简单的 HTTP 路由需求

Gateway API

优点标准化流量切分、跨命名空间授权

代价需选择支持它的实现，迁移有成本

适用新集群或需要高级路由

云厂商 L7 负载均衡器

优点托管、与云 WAF 等集成

代价绑定厂商，功能受产品限制

适用深度使用单一云

🕳️ 07 · 常见坑

  • ✗大量依赖某控制器的注解，换实现时全部重写

    ✓尽量用标准字段，复杂路由考虑 Gateway API

  • ✗继续在新项目使用已退役的社区 ingress-nginx

    ✓该项目 2026 年 3 月起停止维护，应迁移到 Gateway API 或其他控制器

  • ✗控制器只跑单副本，升级或节点故障时全站中断

    ✓多副本加 PodDisruptionBudget 与反亲和

  • ✗未设置 ingressClassName，被意外的控制器接管

    ✓显式指定 ingressClassName 并配置默认类

🎤 09 · 面试追问
Ingress 和 Ingress Controller 的关系？

Ingress 是声明式路由规则对象，只是数据；Ingress Controller 是实际运行的程序，监听这些对象并据此配置反向代理处理流量。集群没有控制器时，创建 Ingress 不会有任何效果。

为什么社区在推 Gateway API？

Ingress 只覆盖基础 HTTP 路由，高级功能靠各家注解，不可移植；也没有角色划分。Gateway API 把基础设施（GatewayClass/Gateway）与应用路由（HTTPRoute）分离，原生支持流量切分、头部匹配和多协议。

ingress-nginx 退役对团队意味着什么？

Kubernetes 社区宣布该项目 2026 年 3 月后不再发布版本和安全修复，现有部署仍可运行但风险逐步上升。应盘点使用的注解，选择替代实现并规划向 Gateway API 迁移。
