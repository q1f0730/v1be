分词器 (Tokenizer / BPE)

Tokenizer / BPE

📐 01 · 定义

分词器（Tokenizer）把文本映射为模型词表中的整数 ID 序列，并能反向解码。主流 LLM 使用子词算法：BPE（字节对编码）及其字节级变体、SentencePiece 的 Unigram/BPE 等。它决定了 Token 计数、计费、上下文占用与多语言效率，每个模型族的分词器各不相同，不能混用。

⚙️ 02 · 原理
  1. 1

    训练阶段：从字节或字符起步，BPE 反复合并语料中最高频的相邻符号对，直到达到目标词表大小。

  2. 2

    字节级 BPE 以 UTF-8 字节为基本单元，任何文本都能编码，不存在未登录词。

  3. 3

    编码时先做预切分（按空格、标点、数字等规则），再按合并规则把片段转为 Token ID。

  4. 4

    高频片段（常见英文单词、代码关键字）成为单个 Token；低频文字被拆成多个子词或字节。

  5. 5

    特殊 Token（如对话角色分隔符、结束符）由对话模板插入，标记消息边界。

🔤 03 · 术语
BPE (Byte Pair Encoding)
迭代合并高频符号对构建子词词表的算法。
词表 (Vocabulary)
分词器可输出的全部 Token 集合，大小影响压缩率与嵌入层参数。
SentencePiece
Google 的分词库，直接处理原始文本，支持 Unigram 与 BPE。
特殊 Token (Special Tokens)
表示开始、结束、角色等控制信息的保留 Token。
Token 生育率 (Fertility)
平均每个词或字被切成的 Token 数，衡量语言效率。
💻 04 · 代码
用 tiktoken 观察切分python
# pip install tiktoken
import tiktoken

# o200k_base 是 OpenAI 较新模型使用的编码之一
enc = tiktoken.get_encoding("o200k_base")

samples = {
    "英文": "Hello, how are you today?",
    "中文": "你好，今天过得怎么样？",
    "代码": "def add(a, b): return a + b",
    "长数字": "3.14159265358979323846",
}
for name, text in samples.items():
    ids = enc.encode(text)
    # 单个 Token 可能是不完整的 UTF-8 字节，用 bytes 形式查看
    pieces = [enc.decode_single_token_bytes(i) for i in ids]
    print(f"{name}: {len(text)} 字符 -> {len(ids)} tokens")
    print("   ", pieces[:8])

assert enc.decode(enc.encode("往返测试")) == "往返测试"

tiktoken 只对应 OpenAI 模型；Claude、Gemini 等需用各自的计数接口或分词器。

⚖️ 06 · 方案取舍

大词表

优点序列更短，多语言更高效

代价嵌入与输出层参数增大

适用多语言、长上下文模型

小词表

优点参数少，训练更易收敛

代价序列更长，推理与计费更贵

适用小模型或单语言场景

字节级回退

优点无未登录词，任何输入可编码

代价罕见文字被拆得很碎

适用通用开放域模型

🕳️ 07 · 常见坑

  • ✗用 tiktoken 估算非 OpenAI 模型的 Token 与费用

    ✓使用目标模型官方的计数 API 或其分词器

  • ✗按「字数 ≈ Token 数」做预算

    ✓用真实分词器在样本数据上统计比例

  • ✗截断文本时按字符切，破坏 Token 或 UTF-8 边界

    ✓在 Token 层截断后再解码，或按句子边界切

  • ✗把 Base64、长日志、压缩 JSON 直接塞进提示

    ✓先摘要或抽取关键字段，图片走多模态接口

🎤 09 · 面试追问
为什么同样内容中文可能比英文更费 Token？

分词器词表由训练语料统计得出。若英文占比高，英文常见词被合并为单个 Token，而中文字符 UTF-8 为 3 字节，合并不足时一个字占一个或多个 Token。较新的大词表分词器（如 o200k_base）中文效率明显改善，差距因模型而异，应实测。

BPE 是怎么构建词表的？

从基础符号（字符或字节）开始，统计语料中相邻符号对的频率，把最高频的一对合并为新符号并记录规则，重复直到词表达到预设大小。编码时按学到的合并顺序应用规则。

分词器对模型能力有什么影响？

影响算术与字符级任务（数字被不规则切分、模型难以数字母），影响多语言效率与有效上下文长度，也影响代码缩进、空格的表达。换分词器通常意味着需要重新训练嵌入层乃至整个模型。
