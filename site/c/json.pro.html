📐 01 · 定义

JSON（JavaScript Object Notation）是一种轻量的文本数据交换格式，由对象、数组、字符串、数字、布尔、null 六类值构成，规范见 RFC 8259 与 ECMA-404。它语言无关、可读，是 Web API 和 LLM 结构化输出的事实标准，配合 JSON Schema 可描述和校验结构。

⚙️ 02 · 原理
  1. 1

    数据建模：用对象表示键值结构、数组表示有序列表，可任意嵌套组合。

  2. 2

    序列化：程序把内存中的数据结构转换成 JSON 文本，如 JSON.stringify、json.dumps。

  3. 3

    传输：通过 HTTP 以 Content-Type: application/json 发送，文本编码规定为 UTF-8。

  4. 4

    反序列化：接收方解析文本还原为本语言的数据结构，语法错误时直接抛出异常。

  5. 5

    校验：用 JSON Schema 检查字段、类型、必填项和取值范围，拒绝不合规数据。

🔤 03 · 术语
序列化 (Serialization)
把内存数据转换为可存储或传输的文本或字节。
JSON Schema
用 JSON 描述 JSON 结构的规范，用于校验与文档。
JSON Lines (JSONL)
每行一个 JSON 对象的格式，常用于日志和批处理数据。
结构化输出 (Structured Outputs)
让 LLM 严格按给定 Schema 输出 JSON 的能力。
JSON5 / JSONC
允许注释、尾逗号的扩展格式，不是标准 JSON。
💻 04 · 代码
解析并校验 LLM 输出python
# pip install jsonschema
import json
from jsonschema import validate, ValidationError

schema = {
    "type": "object",
    "properties": {
        "sentiment": {"enum": ["positive", "negative", "neutral"]},
        "score": {"type": "number", "minimum": 0, "maximum": 1},
    },
    "required": ["sentiment", "score"],
    "additionalProperties": False,
}

raw = '{"sentiment": "positive", "score": 0.92}'   # 假设这是模型返回的文本

try:
    data = json.loads(raw)            # 1. 语法是否合法
    validate(instance=data, schema=schema)  # 2. 结构是否符合约定
    print("ok:", data)
except json.JSONDecodeError as e:
    print("不是合法 JSON：", e)
except ValidationError as e:
    print("结构不符：", e.message)    # 可把错误回传给模型让其修正

先解析语法，再用 Schema 校验结构；两步都通过的数据才能交给后续代码。

JSON 规范易错点

写法是否合法说明
{'a': 1}不合法字符串和键必须用双引号
[1, 2, ]不合法不允许尾逗号
// 注释不合法标准 JSON 不支持注释

⚖️ 06 · 方案取舍

JSON

优点通用、可读、生态最广

代价无注释、体积较大、无日期类型

适用Web API、数据交换

YAML

优点可读性好、支持注释

代价缩进敏感，隐式类型易踩坑

适用配置文件、CI 流水线

Protobuf 等二进制格式

优点体积小、解析快、强类型

代价不可读，需要 Schema 编译

适用高性能内部通信

🕳️ 07 · 常见坑

  • ✗用正则从模型回复里「抠」JSON

    ✓用结构化输出或工具调用，再 json.loads 加 Schema 校验

  • ✗ID 用数字类型，前端 JS 解析后精度丢失

    ✓超大整数 ID 用字符串传输

  • ✗日期格式各写各的

    ✓统一使用 ISO 8601 字符串并带时区

  • ✗对不可信 JSON 不做大小和深度限制

    ✓限制请求体大小与嵌套深度，防止资源耗尽

🎤 09 · 面试追问
如何让 LLM 稳定输出可用的 JSON？

优先使用供应商的结构化输出或工具调用，按 JSON Schema 约束生成；提示中给出 Schema 和示例；代码端解析并校验，失败时把错误信息回传模型重试；对关键字段再做业务规则校验。

JSON 为什么没有日期类型？带来什么问题？

JSON 刻意保持极简，只定义六种值类型。日期只能用字符串或时间戳表示，若各方格式和时区不统一，会出现解析错误和时区偏移。通常约定使用 ISO 8601 字符串（如 2026-10-20T08:00:00Z）。

JSON 与 JSONL 分别适合什么？

JSON 适合一次性传输一个完整文档；JSONL 每行一条记录，可流式逐行读写、追加写入、并行处理，适合日志、批量 API 请求和训练数据。很多 Batch API 和微调数据集采用 JSONL 格式。
