火焰图

Flame Graphs

📐 01 · 定义

火焰图（Flame Graph）是 Brendan Gregg 提出的剖析数据可视化方法，把大量采样到的调用栈合并后绘制成层叠矩形：纵轴是调用栈深度，横轴宽度表示该函数在样本中出现的比例，即消耗资源的多少。横轴按字母排序而非时间顺序。它让人一眼看出最宽的热点路径，是 CPU、内存和阻塞剖析的通用展示形式。

⚙️ 02 · 原理
  1. 1

    剖析器采集大量调用栈样本，每个样本是从入口函数到当前执行函数的一条路径。

  2. 2

    把相同调用栈合并计数，形成折叠格式：一行一个栈，函数用分号连接，末尾是计数。

  3. 3

    绘图时每个函数画成矩形，宽度与包含它的样本数成正比，子调用叠在上方。

  4. 4

    顶层边缘代表正在 CPU 上执行的函数，又宽又平的顶部就是自身耗时热点。

  5. 5

    通过点击放大、搜索函数名，或对比两次剖析的差分火焰图找回归。

🔤 03 · 术语
折叠栈 (Folded Stacks)
每行一个以分号分隔的调用栈及其样本计数的中间格式。
冰柱图 (Icicle Graph)
上下倒置的火焰图，根在顶部。
差分火焰图 (Differential Flame Graph)
对比两次剖析，用颜色标出变多或变少的部分。
Off-CPU 火焰图
展示线程阻塞等待而非执行时的调用栈。
平顶 (Plateau)
顶部又宽又平的矩形，表示函数自身消耗大量资源。
💻 04 · 代码
perf 生成 CPU 火焰图bash
# 依赖 Brendan Gregg 的 FlameGraph 脚本
git clone https://github.com/brendangregg/FlameGraph.git

# 1. 以 99Hz 对全系统采样 30 秒，记录调用栈
sudo perf record -F 99 -a -g -- sleep 30

# 2. 导出样本并折叠成一行一个栈
sudo perf script > out.perf
./FlameGraph/stackcollapse-perf.pl out.perf > out.folded

# 3. 生成可交互的 SVG，用浏览器打开可点击放大与搜索
./FlameGraph/flamegraph.pl out.folded > cpu-flame.svg

# 折叠格式示例：main;handle_request;json_encode 1234

perf 采样、折叠、绘图三步生成火焰图；py-spy、pprof 等工具也能直接输出。

📊 05 · 参数对比

火焰图读法

视觉特征含义通常的动作
矩形很宽该函数及子调用占用多优先关注
顶部平而宽自身代码耗时高优化该函数逻辑
栈很深很窄调用层次多但耗时少通常可忽略
颜色多为随机或按类型区分一般不代表耗时
⚖️ 06 · 方案取舍

On-CPU 火焰图

优点直接显示计算热点

代价看不到等待时间

适用CPU 使用率高

Off-CPU 火焰图

优点揭示阻塞与等待来源

代价采集更复杂，开销更高

适用CPU 低但延迟高

差分火焰图

优点快速发现版本回归

代价需要两次可比的剖析

适用版本对比、优化验证

🕳️ 07 · 常见坑

  • ✗把横轴当时间轴，以为左边先执行。

    ✓横轴按函数名排序合并，只有宽度有意义。

  • ✗缺少符号或帧指针，火焰图满是 unknown 或栈被截断。

    ✓安装调试符号，开启帧指针或使用 DWARF 栈展开。

  • ✗采样时间太短，热点结论不稳定。

    ✓在代表性负载下采足样本。

🎤 09 · 面试追问
火焰图的横轴和纵轴分别代表什么？

纵轴是调用栈深度，下层调用上层；横轴宽度代表该函数出现在样本中的比例，即资源消耗占比。横轴按字母顺序排列以便合并相同栈，不代表时间先后，这一点最容易误读。

火焰图中怎么找优化点？

先找顶部又宽又平的矩形，它们是自身耗时最多的函数；再沿着宽的塔往下看是哪个业务调用路径引起的；可以搜索特定函数名查看其总占比，并用差分火焰图对比优化前后。

为什么有时火焰图满是 unknown？

剖析器无法解析函数名或展开调用栈，常见原因是缺少调试符号、编译时省略了帧指针、JIT 语言未输出符号映射，或容器中找不到对应二进制。需要补充符号、开启帧指针或使用语言专用剖析器。
