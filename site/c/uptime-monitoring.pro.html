可用性监控 (拨测)

Uptime Monitoring

📐 01 · 定义

可用性监控（Uptime Monitoring），又称拨测或合成监控（Synthetic Monitoring），是从外部站点按固定频率主动请求服务，检查其是否可达、响应正确且足够快，并在失败时告警。它从用户视角补充内部指标，能发现 DNS、证书、CDN、网络等内部监控看不到的故障，也用于统计可用率、验证 SLA。

⚙️ 02 · 原理
  1. 1

    在多个地理位置部署探针，按设定间隔（常见 30 秒到 5 分钟）向目标 URL、端口或接口发请求。

  2. 2

    对响应做断言：状态码、关键字、响应时间阈值、JSON 字段，以及 TLS 证书剩余有效期。

  3. 3

    为避免误报，通常要求连续多次失败或多个地点同时失败才判定宕机。

  4. 4

    判定宕机后通过邮件、短信、IM 或值班系统通知，并在恢复时发送恢复通知、记录故障时长。

  5. 5

    心跳监控反向工作：定时任务完成后主动 ping 监控地址，超时未收到即告警，用于发现静默失败的 cron。

🔤 03 · 术语
合成监控 (Synthetic Monitoring)
用脚本模拟用户请求主动探测服务。
心跳监控 (Heartbeat / Dead Man's Switch)
任务定期上报，超时未上报即告警。
多地点确认 (Multi-location Confirmation)
多个探针同时失败才判定故障，降低误报。
可用率 (Availability)
正常时间占总时间的比例，如 99.9%。
状态页 (Status Page)
向用户公开展示服务状态与故障历史的页面。
💻 04 · 代码
简易拨测与心跳脚本python
import time, ssl, socket, datetime
import requests

def check_http(url: str, keyword: str, max_ms: int = 2000) -> str | None:
    t = time.perf_counter()
    try:
        r = requests.get(url, timeout=10)
    except requests.RequestException as e:
        return f"请求失败: {e}"
    ms = (time.perf_counter() - t) * 1000
    if r.status_code != 200: return f"状态码 {r.status_code}"
    if keyword not in r.text: return "关键字缺失"
    if ms > max_ms: return f"过慢 {ms:.0f}ms"
    return None

def cert_days_left(host: str) -> int:
    ctx = ssl.create_default_context()
    with socket.create_connection((host, 443), timeout=10) as s:
        with ctx.wrap_socket(s, server_hostname=host) as ss:
            exp = ssl.cert_time_to_seconds(ss.getpeercert()["notAfter"])
    return int((exp - time.time()) // 86400)

print(check_http("https://example.com", "Example Domain"))
print("证书剩余天数:", cert_days_left("example.com"))
# cron 任务结束时上报心跳：requests.get(HEARTBEAT_URL, timeout=10)

演示状态码、关键字、延迟、证书四类断言；生产中应使用多地点的托管或自建监控服务。

⚖️ 06 · 方案取舍

托管拨测服务

优点多地点、开箱即用、带状态页

代价按监控数与频率收费

适用大多数线上产品

自建（如 Uptime Kuma）

优点免费、可控

代价单点部署，监控自身也会挂

适用个人项目、内网服务

只用内部指标

优点无额外成本

代价看不到 DNS、证书、网络问题

适用不推荐单独使用

🕳️ 07 · 常见坑

  • ✗只检查首页返回 200，接口挂了没发现

    ✓同时监控健康检查接口和关键 API，并做内容断言

  • ✗单地点探测，网络抖动频繁误报

    ✓多地点确认、连续失败 N 次再告警

  • ✗监控服务与被监控服务部署在同一台机器

    ✓监控部署在独立的基础设施或使用外部服务

  • ✗后台定时任务静默失败无人知晓

    ✓为 cron 任务配置心跳监控

🎤 09 · 面试追问
拨测和内部监控如何互补？

内部指标能看到服务内部的延迟、错误和资源，但服务完全宕机时可能连指标都发不出来，也看不到 DNS、证书、CDN 和跨地域网络问题。拨测从外部模拟用户，能发现这些盲区，两者结合才能完整覆盖。

如何减少拨测误报？

使用多个地理位置的探针，要求多数地点同时失败；设置连续失败次数阈值；合理的超时；把维护窗口设为静默期。同时区分告警级别，非关键检查只发通知不呼叫值班。

99.9% 可用率意味着什么？

以 30 天计约允许 43 分钟停机，一年约 8.8 小时。这决定了故障响应和发布策略：要达到更高可用率，需要自动故障转移、多可用区部署和更快的告警响应，成本会显著上升。
