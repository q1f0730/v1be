暴力破解防护

Brute Force Protection

📐 01 · 定义

暴力破解防护（Brute Force Protection）是一组防止攻击者通过大量尝试猜中密码、验证码或令牌的机制，包括限流、渐进延迟、账号锁定、验证码挑战和多因素认证。它属于认证安全层，需同时应对针对单账号的猜测、跨账号的密码喷洒和使用泄露凭证的撞库攻击。

⚙️ 02 · 原理
  1. 1

    按多个维度计数失败尝试：用户名、IP、设备指纹、IP+用户名组合。

  2. 2

    超过阈值时逐步升级响应：增加延迟、要求验证码、临时锁定或要求额外验证。

  3. 3

    对短数字验证码、重置令牌等低熵凭证设置严格的尝试上限和有效期。

  4. 4

    检测密码喷洒与撞库：同一 IP 尝试大量账号、或大量来源使用已泄露凭证。

  5. 5

    提供 MFA，并对异常登录通知用户，使猜中密码也不足以接管账号。

🔤 03 · 术语
撞库 (Credential Stuffing)
用其他网站泄露的用户名密码对批量尝试登录。
密码喷洒 (Password Spraying)
用少数常见密码尝试大量账号，避开单账号锁定。
限流 (Rate Limiting)
限制单位时间内的请求次数，超出返回 429。
账号锁定 (Account Lockout)
失败次数过多后暂时禁止登录，可能被滥用为 DoS。
令牌桶 (Token Bucket)
常用限流算法，允许一定突发并按固定速率恢复。
💻 04 · 代码
Express 登录接口限流javascript
import express from "express";
import { rateLimit } from "express-rate-limit";

const app = express();
app.use(express.json());

// 按 IP + 用户名组合限流，兼顾单账号猜测与共享出口 IP
const loginLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,      // 15 分钟窗口
  limit: 5,                      // 每个键最多 5 次
  standardHeaders: "draft-7",    // 返回 RateLimit 相关响应头
  legacyHeaders: false,
  keyGenerator: (req) => `${req.ip}:${String(req.body?.email).toLowerCase()}`,
  skipSuccessfulRequests: true,  // 成功登录不计数
  message: { error: "尝试过于频繁，请稍后再试" },
});

app.post("/login", loginLimiter, async (req, res) => {
  // ...校验密码；失败时返回统一提示，不区分用户名或密码错误
  res.status(401).json({ error: "邮箱或密码错误" });
});

多实例部署需配置共享存储（如 Redis store）；IPv6 等场景需按文档处理键生成。

📊 05 · 参数对比

防护手段对比

手段防什么副作用
IP 限流单源大量尝试共享 IP 用户受影响，分布式攻击可绕过
账号锁定单账号猜测攻击者可故意锁定他人账号
验证码挑战自动化脚本影响体验，可被打码服务绕过
MFA密码泄露后的接管增加登录步骤
⚖️ 06 · 方案取舍

硬锁定账号

优点彻底阻断单账号猜测

代价可被用作拒绝服务

适用高价值账号，配合解锁流程

渐进延迟 + 验证码

优点不影响正常用户登录

代价实现更复杂

适用大多数面向公众的登录

无密码/通行密钥

优点从根本上消除密码猜测

代价迁移成本与兼容性

适用新产品或安全升级

🕳️ 07 · 常见坑

  • ✗登录提示区分“用户不存在”和“密码错误”

    ✓统一失败提示，注册和找回流程同样避免泄露

  • ✗只限流登录，忘了短信验证码和重置接口

    ✓所有验证凭证的接口都限次数和有效期

  • ✗限流计数存在单实例内存中

    ✓多实例部署使用 Redis 等共享存储

  • ✗信任 X-Forwarded-For 任意值作为 IP

    ✓正确配置可信代理，只取可信跳数

🎤 09 · 面试追问
为什么只按 IP 限流不够？

攻击者可使用代理池和僵尸网络，从大量 IP 分散尝试，每个 IP 都在阈值以下；同时大量正常用户可能共享一个出口 IP 而被误伤。需要组合用户名维度、IP+用户名维度、全局异常检测和验证码挑战。

账号锁定有什么风险？

攻击者知道用户名就能故意输错密码，把目标用户锁在外面，形成拒绝服务。缓解方式是使用临时锁定和渐进延迟而非永久锁定，锁定后提供验证码或邮件解锁，并结合设备识别让已知设备不受影响。

如何防御撞库攻击？

撞库使用的是真实有效的密码，单账号可能只尝试一次，限流难以奏效。对策包括 MFA、检测已泄露密码并拒绝使用、识别自动化流量（设备指纹、行为分析）、异常登录二次验证，以及新设备登录通知。
