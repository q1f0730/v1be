提示词缓存

Prompt Caching

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

提示词缓存（Prompt Caching）是模型服务端对请求中重复出现的前缀（系统提示、工具定义、长文档、历史对话）缓存其中间计算结果（KV Cache），后续请求命中相同前缀时跳过重复计算的机制。它属于推理优化层，可显著降低长上下文请求的成本与首 token 延迟，对多轮 Agent 尤为关键。

⚙️ 02 · 原理
  1. 1

    模型处理输入时为每个 token 计算注意力的键值（KV），这部分计算与前缀内容一一对应。

  2. 2

    服务端以前缀内容为键保存 KV 结果；只有从开头起完全一致的部分才能命中。

  3. 3

    Anthropic API 需用 cache_control 显式标记缓存断点；OpenAI 对足够长的提示自动缓存。

  4. 4

    命中时缓存部分按较低单价计费，并减少首 token 延迟；未命中则正常计算并写入缓存。

  5. 5

    缓存有存活时间，一段时间无访问即失效，命中后通常会刷新存活时间。

🔤 03 · 术语
KV 缓存 (KV Cache)
注意力层中已计算 token 的键值张量。
前缀匹配 (Prefix Match)
只有与已缓存内容从头完全一致的部分可复用。
缓存断点 (Cache Breakpoint)
Anthropic 中用 cache_control 标记的缓存边界。
缓存写入/读取 token
响应 usage 中分别统计的写入与命中 token 数。
首 token 延迟 (TTFT)
从发出请求到收到第一个输出 token 的时间。
💻 04 · 代码
Anthropic 显式缓存长前缀python
import anthropic

client = anthropic.Anthropic()
LONG_DOC = open("handbook.md").read()      # 长且不变的内容放前面

def ask(question: str):
    resp = client.messages.create(
        model="claude-sonnet-4-5",          # 以实际可用模型为准
        max_tokens=1024,
        system=[
            {"type": "text", "text": "你是员工手册问答助手。"},
            {"type": "text", "text": LONG_DOC,
             "cache_control": {"type": "ephemeral"}},   # 断点：此前内容被缓存
        ],
        messages=[{"role": "user", "content": question}],  # 变化部分放最后
    )
    u = resp.usage
    print("写入缓存:", u.cache_creation_input_tokens,
          "命中缓存:", u.cache_read_input_tokens,
          "未缓存输入:", u.input_tokens)
    return resp.content[0].text

ask("年假有几天？")     # 首次：写入缓存
ask("报销流程是？")     # 存活期内再次调用：命中缓存

稳定内容在前、变化内容在后；通过 usage 字段确认是否真的命中。

⚖️ 06 · 方案取舍

显式标记缓存

优点可精确控制缓存内容与时机

代价需要设计断点，写入可能有溢价

适用前缀稳定且重复调用频繁

依赖自动缓存

优点零改动

代价命中依赖提示结构，难以保证

适用OpenAI 等自动缓存平台

不使用缓存

优点无需关心结构

代价长上下文重复付费

适用短提示或前缀每次都不同

🕳️ 07 · 常见坑

  • ✗在系统提示开头插入当前时间或请求 ID

    ✓动态内容移到最后，保持前缀逐字节稳定

  • ✗工具定义顺序或 JSON 序列化每次不同

    ✓固定工具列表顺序与序列化方式

  • ✗前缀低于最小可缓存长度，以为已缓存

    ✓查阅官方最小长度要求，并以 usage 字段验证

  • ✗请求间隔超过缓存存活时间，始终未命中

    ✓根据调用频率选择存活时间，或合并请求

🎤 09 · 面试追问
为什么提示词缓存只能匹配前缀？

Transformer 中每个 token 的 KV 依赖它之前的全部 token；前面任何一个 token 变化，其后所有 KV 都会不同，因此只有从开头起完全一致的部分才能复用。

Agent 场景下如何最大化缓存命中？

保持系统提示与工具定义固定，对话历史只追加不修改，在最新消息处设置断点使每轮都复用之前的前缀；避免在中途改写早期消息或频繁切换工具集。

提示词缓存和应用层响应缓存有何不同？

提示词缓存复用的是模型对输入前缀的中间计算，输出仍由模型实时生成，问题不同也能受益；响应缓存直接返回之前的完整答案，只适用于完全相同或语义等价的请求。
