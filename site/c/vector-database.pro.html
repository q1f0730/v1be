向量数据库

Vector Database

📐 01 · 定义

向量数据库（Vector Database）是专门存储高维向量并支持相似度检索的数据系统，属于数据存储层。它在向量之外通常还存储元数据，提供近似最近邻（ANN）索引、过滤、增删改和持久化能力，是语义搜索和 RAG 的检索底座。形态包括专用数据库、传统数据库的向量扩展和嵌入式库。

⚙️ 02 · 原理
  1. 1

    写入时为每条记录存储 ID、向量和元数据，并按选定的距离度量（余弦、内积、欧氏）组织索引。

  2. 2

    构建 ANN 索引，如 HNSW 图或 IVF 倒排聚类，用少量精度损失换取远快于暴力搜索的查询速度。

  3. 3

    查询时对查询向量在索引中搜索最近的 k 个邻居，可通过参数（如 HNSW 的 ef）调节召回与速度。

  4. 4

    元数据过滤可在检索前、检索中或检索后执行，影响结果数量和性能。

  5. 5

    生产系统还需分片、副本、持久化和索引重建，部分产品支持混合检索和多租户隔离。

🔤 03 · 术语
近似最近邻 (ANN)
允许少量误差的最近邻搜索，换取亚线性查询时间。
HNSW
分层可导航小世界图索引，召回高、内存占用较大。
IVF
先聚类再在少数簇内搜索的倒排索引方法。
召回率@k (Recall@k)
ANN 返回的前 k 个结果中真实最近邻所占比例。
乘积量化 (PQ)
把向量分段压缩编码，大幅降低内存，牺牲一定精度。
💻 04 · 代码
pgvector 建表与检索sql
-- 启用扩展（需已安装 pgvector）
CREATE EXTENSION IF NOT EXISTS vector;

CREATE TABLE docs (
  id        bigserial PRIMARY KEY,
  tenant_id int NOT NULL,
  content   text,
  embedding vector(1536)
);

-- HNSW 索引，使用余弦距离算子类
CREATE INDEX ON docs USING hnsw (embedding vector_cosine_ops);

-- 查询：<=> 为余弦距离，越小越相似
SELECT id, content, 1 - (embedding <=> $1) AS similarity
FROM docs
WHERE tenant_id = 42
ORDER BY embedding <=> $1
LIMIT 5;

$1 为查询向量参数；ORDER BY 使用与索引相同的距离算子才能走索引。

优点检索性能与功能丰富

🕳️ 07 · 常见坑

  • ✗索引距离度量与嵌入模型推荐度量不一致

    ✓按模型文档选择度量，并在建索引时对齐

  • ✗强过滤条件下 HNSW 返回结果不足 k 条

    ✓使用支持过滤感知检索的方案或调大候选数

  • ✗不评估 ANN 召回率就上线

    ✓用精确搜索结果作基准测 Recall@k 并调参

  • ✗源数据删除后向量残留

    ✓建立与主库的同步与删除机制

🎤 09 · 面试追问
HNSW 的原理和主要参数？

构建多层图，上层稀疏用于快速定位，下层稠密用于精细搜索，查询时自顶向下贪心逼近。M 控制每个节点的连接数，影响内存和召回；ef_construction 影响建索引质量；查询时 ef 越大召回越高、速度越慢。

什么时候不需要专用向量数据库？

数据量在百万级以内、已经使用 PostgreSQL 且需要与业务数据联合查询或事务一致时，pgvector 通常足够。原型阶段用 FAISS 或内存数组也可以。当规模、并发或高级功能成为瓶颈时再迁移。

向量检索里的过滤为什么难？

ANN 索引按向量邻近组织，不了解元数据。先过滤后搜索可能无法利用索引；先搜索后过滤可能把候选都过滤掉，导致结果不足。不同产品通过过滤感知遍历、分区索引等方式解决，需要按过滤选择性实测。
