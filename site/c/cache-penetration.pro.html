缓存穿透

Cache Penetration

📐 01 · 定义

缓存穿透（Cache Penetration）指请求查询的数据在缓存和数据库中都不存在，因此每次都无法命中缓存而直接打到数据库。在恶意构造随机 ID 或爬虫遍历时，大量此类请求会压垮数据库。常见防护是参数校验、缓存空结果（负缓存）和布隆过滤器。它常与缓存击穿（热点键过期）和缓存雪崩（大量键同时过期或缓存宕机）一起讨论。

⚙️ 02 · 原理
  1. 1

    正常的旁路缓存只在数据库返回结果时写缓存，查询结果为空时不写，导致同一不存在的键每次都回源。

  2. 2

    攻击者或缺陷代码用大量不存在的键（如负数 ID、随机 UUID）发起请求，缓存命中率趋近于零。

  3. 3

    第一道防线是接口层参数校验：格式、范围、权限不合法的请求直接拒绝，不访问缓存或数据库。

  4. 4

    负缓存：把“不存在”也写入缓存（如特殊空值），设置较短 TTL，防止同一键反复回源。

  5. 5

    布隆过滤器：预先把所有合法键加入过滤器，查询前判断，若“肯定不存在”则直接返回；它有误判率但无漏判。

🔤 03 · 术语
负缓存 (Negative Caching)
缓存“查无结果”，用较短 TTL 防止重复回源。
布隆过滤器 (Bloom Filter)
概率型集合结构，能确定“一定不存在”，存在判断有误判率。
缓存击穿 (Cache Breakdown)
热点键过期瞬间大量并发请求同时回源。
缓存雪崩 (Cache Avalanche)
大量键同时过期或缓存整体故障，流量涌向数据库。
误判率 (False Positive Rate)
布隆过滤器把不存在的元素判为存在的概率。
💻 04 · 代码
空值缓存 + 布隆过滤器防穿透python
import json
import redis

r = redis.Redis(decode_responses=True)
NULL = "__NULL__"

def get_user(uid: str, db) -> dict | None:
    if not uid.isdigit() or len(uid) > 12:              # 1. 参数校验
        return None
    # 2. 布隆过滤器（需 Redis 8 或 RedisBloom 模块）：0 表示一定不存在
    if r.execute_command("BF.EXISTS", "bf:users", uid) == 0:
        return None
    key = f"user:{uid}"
    cached = r.get(key)
    if cached == NULL:                                   # 3. 命中空值缓存
        return None
    if cached is not None:
        return json.loads(cached)
    row = db.find_user(uid)
    if row is None:
        r.set(key, NULL, ex=120)                         # 不存在：短 TTL
    else:
        r.set(key, json.dumps(row), ex=3600)
    return row

# 新增用户时同步写入过滤器：r.execute_command("BF.ADD", "bf:users", uid)

三层防护依次拦截非法参数、肯定不存在的键与重复的空查询；db 为示意对象。

📊 05 · 参数对比

穿透、击穿、雪崩对比

问题触发条件主要对策
穿透查询不存在的数据参数校验、负缓存、布隆过滤器
击穿单个热点键过期瞬间高并发互斥锁重建、逻辑过期、提前刷新
雪崩大量键同时过期或缓存宕机TTL 随机抖动、多级缓存、限流降级、缓存高可用
⚖️ 06 · 方案取舍

负缓存

优点实现简单，对重复键有效

代价随机键攻击下仍会占满缓存空间

适用少量不存在键被反复查询

布隆过滤器

优点内存占用小，挡住海量随机键

代价需维护键集合，删除困难，有误判

适用合法键集合可预知、攻击面大

限流与风控

优点直接遏制恶意来源

代价无法区分合法的偶发空查询

适用叠加使用，应对恶意流量

🕳️ 07 · 常见坑

  • ✗空值缓存使用与正常数据相同的长 TTL

    ✓空值使用较短 TTL，数据新增时主动删除空值缓存

  • ✗布隆过滤器建好后不随数据新增更新

    ✓写入数据时同步加入过滤器，并定期重建

  • ✗用普通布隆过滤器处理需要删除的键

    ✓选择支持删除的变体（如计数布隆、Cuckoo 过滤器）或定期重建

  • ✗只做缓存防护，不做参数校验和限流

    ✓在网关和接口层先校验参数并按来源限流

☑️ 08 · 检查清单
🎤 09 · 面试追问
布隆过滤器为什么能防穿透，又有什么局限？

它用多个哈希函数把元素映射到位数组；查询时若任一位为 0，元素一定不存在，可直接拒绝。局限是存在误判（少量不存在的键被判为可能存在，仍会回源），标准实现不支持删除，且需要随数据变化维护。

负缓存会带来什么一致性问题？

如果某键先被缓存为“不存在”，随后数据被创建，在空值 TTL 到期前读请求仍返回不存在。解决办法是空值 TTL 设短，并在创建数据时主动删除对应的空值缓存。

如何区分穿透、击穿和雪崩？

穿透是数据根本不存在，缓存永远命中不了；击穿是某个存在的热点键恰好过期，瞬间并发回源；雪崩是大量键集中过期或缓存服务整体不可用。三者对策不同，监控上可分别观察空结果比例、单键回源并发和整体命中率。
