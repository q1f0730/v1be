静态生成与增量再生 (SSG / ISR)

Static Site Generation & ISR

📐 01 · 定义

静态站点生成（SSG）指在构建阶段预先把页面渲染成 HTML，部署后由 CDN 直接返回；增量静态再生（ISR）在此基础上允许页面在运行时按时间或按需在后台重新生成。二者属于前端渲染策略层，兼顾首屏速度、低服务器成本与 SEO，代表实现有 Next.js、Astro、Hugo 等。

⚙️ 02 · 原理
  1. 1

    构建时框架执行数据获取（读 CMS、数据库或文件），为每个路由渲染出 HTML 与所需资源。

  2. 2

    动态路由需在构建时枚举参数（如 generateStaticParams），生成对应的静态页面。

  3. 3

    产物部署到 CDN 或静态托管，请求直接命中缓存文件，无需运行服务端渲染。

  4. 4

    ISR：页面带重新验证时间，过期后的首个请求仍先拿到旧页面，同时后台触发重新生成。

  5. 5

    按需重新验证：内容更新时由 Webhook 调用 revalidatePath/revalidateTag，立即使对应缓存失效。

🔤 03 · 术语
SSG (Static Site Generation)
构建时预渲染页面为静态 HTML。
ISR (Incremental Static Regeneration)
运行时按周期或按需在后台重建静态页面。
重新验证 (Revalidation)
判定缓存页面过期并触发重新生成的过程。
stale-while-revalidate
先返回旧内容、后台刷新的缓存策略，ISR 采用类似语义。
按需重新验证 (On-demand Revalidation)
由事件主动触发失效，而非等待时间到期。
💻 04 · 代码
Next.js App Router 的 ISRtypescript
// app/products/[id]/page.tsx
// 页面最多每 600 秒在后台重新生成一次
export const revalidate = 600;

// 构建时预生成热门商品，其余在首次访问时生成
export async function generateStaticParams() {
  const top = await fetch("https://api.example.com/products/top").then(r => r.json());
  return top.map((p: { id: string }) => ({ id: p.id }));
}

export default async function Page({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;  // Next.js 15 起 params 为 Promise
  const p = await fetch(`https://api.example.com/products/${id}`).then(r => r.json());
  return <h1>{p.name} - ¥{p.price}</h1>;
}

// 另在 Route Handler 中按需失效：
// import { revalidatePath } from "next/cache";
// revalidatePath(`/products/${id}`);

revalidate 定义时间驱动的 ISR；内容变更时可用 revalidatePath 立即刷新。

📊 05 · 参数对比

渲染策略对比

策略生成时机数据新鲜度服务器成本
SSG构建时到下次构建前不变最低
ISR构建时 + 后台周期/按需分钟级或事件触发低
SSR每次请求实时高
CSR浏览器运行时实时低（但首屏慢、SEO 弱）
⚖️ 06 · 方案取舍

纯 SSG

优点最快最便宜，可部署到任意静态托管

代价内容更新需重新构建，页面多时构建慢

适用文档、博客、营销页

ISR

优点静态速度 + 定期更新，构建时间可控

代价存在过期窗口，依赖平台支持

适用商品页、文章列表

SSR

优点每次实时、可个性化

代价每请求消耗算力，TTFB 较高

适用强个性化或实时数据页面

🕳️ 07 · 常见坑

  • ✗对用户个性化内容（购物车、登录态）用 SSG/ISR

    ✓个性化部分放客户端或 SSR，静态页只放公共内容

  • ✗构建时生成数十万页，构建时间爆炸

    ✓只预生成热门页，其余首次访问时生成并缓存

  • ✗以为 revalidate 到期立刻更新，用户看到的都是新内容

    ✓到期后首个请求仍返回旧页并触发重建，需要即时性用按需失效

  • ✗自托管时多实例各自缓存，页面版本不一致

    ✓配置共享缓存处理器，或使用支持 ISR 的托管平台

🎤 09 · 面试追问
ISR 的 stale-while-revalidate 语义是什么？

页面过期后，下一个请求仍立即拿到旧版本，同时后台重新生成；生成成功后替换缓存，之后的请求拿到新版本。生成失败则继续提供旧页面，保证可用性。

什么时候不该用 SSG？

内容高度个性化、强实时（行情、库存精确数）、或页面数量巨大且更新频繁时。此时用 SSR、客户端获取或 ISR 结合按需失效。

SSG 对 SEO 和性能为何有利？

爬虫和用户直接拿到完整 HTML，无需等待 JS 渲染；文件可被 CDN 边缘缓存，TTFB 低，有利于 LCP；同时服务器无需在每次请求时执行渲染，抗突发流量能力强。
