检索增强生成 (RAG)

RAG

📐 01 · 定义

检索增强生成（Retrieval-Augmented Generation，RAG）是在生成前先从外部知识库检索相关内容并注入提示，让模型基于这些材料作答的架构模式。它位于应用编排层，解决模型知识过时、缺少私有数据和幻觉问题，并使答案可以附带出处，无需重新训练模型即可更新知识。

⚙️ 02 · 原理
  1. 1

    离线索引：解析文档，按语义或长度切分为块（chunk），附加元数据后计算嵌入写入向量库。

  2. 2

    在线检索：把用户问题编码为向量，做近似最近邻搜索，常与 BM25 关键词检索混合召回。

  3. 3

    重排（Rerank）：用交叉编码器等模型对候选块精排，只保留最相关的若干条。

  4. 4

    生成：把检索结果连同出处标识拼入提示，指示模型仅依据材料回答并标注引用。

  5. 5

    评估与迭代：分别衡量检索召回率和答案忠实度，定位问题出在检索还是生成环节。

🔤 03 · 术语
分块 (Chunking)
把文档切成适合检索的片段，块大小和重叠影响召回质量。
混合检索 (Hybrid Search)
结合稠密向量与 BM25 等稀疏检索，兼顾语义和精确词。
重排器 (Reranker)
对查询-文档对逐一打分的模型，精度高于向量检索但更慢。
忠实度 (Faithfulness)
答案中的陈述能否被检索材料支持的评估指标。
Top-k
检索返回的候选数量，影响召回与上下文噪声的平衡。
💻 04 · 代码
最小 RAG 流程python
import numpy as np
from openai import OpenAI
client = OpenAI()

def embed(texts):
    r = client.embeddings.create(model="text-embedding-3-small", input=texts)
    v = np.array([d.embedding for d in r.data])
    return v / np.linalg.norm(v, axis=1, keepdims=True)

chunks = ["退款需在签收后7天内申请", "会员每月可免运费3次", "客服时间9:00-21:00"]
index = embed(chunks)                         # 离线：建索引

q = "买了东西多久内能退？"
scores = index @ embed([q])[0]                # 在线：检索
top = [chunks[i] for i in np.argsort(-scores)[:2]]

ctx = "\n".join(f"[{i+1}] {c}" for i, c in enumerate(top))
ans = client.chat.completions.create(model="gpt-4o-mini", messages=[
    {"role": "system", "content": "仅依据资料回答并标注[编号]，资料没有就说不知道。"},
    {"role": "user", "content": f"资料:\n{ctx}\n\n问题:{q}"}])
print(ans.choices[0].message.content)

用内存数组代替向量库演示索引、检索、拼接引用、生成四步；生产需加重排与评测。

RAG 问题定位

症状可能环节常见对策

⚖️ 06 · 方案取舍

RAG

优点知识可更新、可溯源

代价多一套检索系统

适用私有或常变的知识

长上下文全量塞入

优点实现简单

代价成本高，规模受限

适用文档少、问题集中

微调

优点学习风格和格式

代价注入事实不可靠，更新慢

适用改变行为而非补充知识

🕳️ 07 · 常见坑

  • ✗只看最终答案判断 RAG 好坏

    ✓分别评估检索召回和生成忠实度

  • ✗固定字数硬切，表格和代码被截断

    ✓按标题、段落等结构分块并保留适度重叠

  • ✗不做权限过滤，检索到用户无权看的文档

    ✓在检索时按用户权限过滤元数据

  • ✗把检索到的文档当可信指令

    ✓文档可能含注入内容，作为数据处理并隔离

🎤 09 · 面试追问
RAG 和微调分别适合解决什么问题？

RAG 解决“知道什么”：注入私有、最新、需溯源的事实，更新只需改索引。微调解决“怎么做”：输出风格、格式、领域行为。用微调灌事实容易幻觉且更新成本高，两者也可结合使用。

如何选择分块大小？

块太小上下文不完整，太大则向量被稀释且挤占窗口。通常按文档结构切分，再用评测集比较几种大小和重叠的召回率。也可小块检索、返回其所在的父段落，兼顾精度和完整性。

什么是 Agentic RAG？

由 Agent 自主决定是否检索、检索什么、是否改写查询或多次检索，并根据结果判断信息是否足够，而非固定的“检索一次再生成”管线。灵活度高，适合复杂问题，但延迟和成本更高、行为更难预测。
