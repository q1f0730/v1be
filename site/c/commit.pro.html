提交 (Commit)

Commit

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

提交（Commit）是 Git 中不可变的项目快照对象，包含指向目录树的引用、父提交、作者与提交者信息、时间戳和提交说明，并由内容计算出唯一哈希。提交串联成历史图，是回滚、审查、定位问题和生成变更日志的基本单位。好的提交应原子化（一件事）并配有说明「为什么」的信息。

⚙️ 02 · 原理
  1. 1

    选择改动：用 git add 或 git add -p 把属于同一件事的改动放进暂存区。

  2. 2

    生成树对象：Git 根据暂存区内容生成目录树（tree）对象，未改动的文件复用已有对象。

  3. 3

    创建提交对象：记录 tree、父提交、作者、时间与说明，计算出提交哈希。

  4. 4

    移动分支指针：当前分支改为指向新提交，新提交以上一个提交为父节点，历史向前延伸。

  5. 5

    不可变性：任何内容变化都会产生新哈希，修改旧提交实际是创建新提交替换它。

🔤 03 · 术语
原子提交 (Atomic Commit)
每个提交只包含一个逻辑完整的改动。
Conventional Commits
用 feat:、fix: 等前缀规范提交说明的约定。
amend
修改最近一次提交的内容或说明，会生成新哈希。
签名提交 (Signed Commit)
用 GPG 或 SSH 密钥签名，证明提交确实来自作者。
Co-authored-by
提交说明尾部标注共同作者，AI 工具常用它署名。
💻 04 · 代码
写出好提交bash
# 只暂存相关改动：交互式逐块选择
git add -p src/auth/

# 提交前确认暂存内容
git diff --staged

# Conventional Commits 格式：类型(范围): 摘要，正文说明原因
git commit -m "fix(auth): handle expired refresh token" \
           -m "Previously the app looped on 401. Now it logs out and redirects to /login."

# 刚提交发现漏了文件（未推送时）
git add src/auth/session.ts
git commit --amend --no-edit

# 查看提交详情
git show --stat HEAD

# 常见类型：feat 新功能 / fix 修复 / docs 文档 / refactor 重构
#           test 测试 / chore 杂项 / perf 性能

摘要说做了什么，正文说为什么；amend 只用于尚未推送的提交。

📊 05 · 参数对比

提交粒度对比

粒度示例影响
过粗「完成登录、支付和 UI 调整」难以评审，无法单独回滚
合适「fix(auth): 处理过期令牌」易评审、可精准回滚与 bisect
过细「改一个空格」连续十次历史噪声大，可在合并时 squash
⚖️ 06 · 方案取舍

频繁小提交

优点回退点多，bisect 精确

代价历史较碎

适用开发过程中、Agent 每步改动

合并前整理提交

优点历史清晰可读

代价需要 rebase 技巧

适用提交 PR 前

squash 合并

优点主干一个功能一个提交

代价丢失过程细节

适用团队偏好简洁主干历史

🕳️ 07 · 常见坑

  • ✗提交说明写「update」「fix bug」

    ✓写清改了什么和为什么，便于日后检索

  • ✗一个提交混入格式化与逻辑修改

    ✓格式化单独提交，逻辑改动保持可读 diff

  • ✗对已推送的提交使用 amend 后强推

    ✓已共享的提交用新提交修正

  • ✗提交了密钥再用新提交删除

    ✓密钥仍在历史中，需立即轮换并清理历史

🎤 09 · 面试追问
提交哈希由什么决定？

由提交对象的全部内容计算：目录树哈希、父提交哈希、作者与提交者信息及时间、提交说明。因此任一内容或任一祖先变化都会导致哈希改变，这让历史具备防篡改特性，也解释了 rebase 后哈希全部变化。

为什么推荐 Conventional Commits？

结构化前缀让历史可读、可机器解析：能自动生成变更日志、根据 feat/fix/BREAKING CHANGE 推导语义化版本号、在评审时快速判断改动性质。对 AI 生成提交说明也提供了明确格式约束。

Agent 自动提交，你会设什么规范？

每完成一个可验证的步骤提交一次；说明遵循约定格式并写明原因；提交前必须通过测试或类型检查；标注 AI 参与（如 Co-authored-by）；禁止提交密钥与大文件；不允许改写已推送历史。
