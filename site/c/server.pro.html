📐 01 · 定义

服务器（Server）既指持续运行、通过网络响应请求的程序，也指承载这些程序的计算机（物理机、虚拟机或容器）。它需要稳定的网络、公网可达的地址或入口、持续供电和运维。现代开发中，开发者多通过云主机、容器平台或 Serverless 使用服务器，而不直接管理硬件。

⚙️ 02 · 原理
  1. 1

    监听：服务程序启动后绑定 IP 地址和端口，持续等待客户端发起网络连接。

  2. 2

    接入：请求经 DNS、负载均衡或反向代理到达具体服务器实例。

  3. 3

    处理：服务进程（或线程、协程）处理请求，访问数据库或其他服务。

  4. 4

    响应：把处理结果按协议格式通过网络返回给客户端，连接随后保持复用或关闭。

  5. 5

    守护：进程管理器或编排平台在崩溃时自动重启，并记录日志与指标。

🔤 03 · 术语
VPS / 云主机
云厂商提供的虚拟服务器，可自行安装系统与软件。
反向代理 (Reverse Proxy)
如 Nginx，接收外部请求并转发给内部服务，可做 HTTPS 与负载均衡。
容器 (Container)
用 Docker 等打包应用与依赖，在任意主机一致运行。
Serverless
开发者只写函数，平台按请求分配算力并计费。
SSH
加密的远程登录协议，用于管理服务器。
💻 04 · 代码
在云主机上运行服务bash
# 用 SSH 密钥登录（比密码更安全）
ssh -i ~/.ssh/id_ed25519 ubuntu@203.0.113.10

# 安装并启动 Nginx（Ubuntu/Debian）
sudo apt update && sudo apt install -y nginx
sudo systemctl enable --now nginx      # 开机自启并立即启动
systemctl status nginx --no-pager      # 查看运行状态

# 查看哪些进程在监听哪些端口
sudo ss -tlnp

# 只放行 SSH 和 HTTP/HTTPS（ufw 防火墙）
sudo ufw allow OpenSSH
sudo ufw allow 'Nginx Full'
sudo ufw enable

# 查看服务日志
journalctl -u nginx -n 50 --no-pager

登录、装服务、守护进程、开放端口、看日志，是管理一台 Linux 服务器的基本动作。

📊 05 · 参数对比

服务器托管方式对比

方式你负责什么适合
物理机 / 自建机房硬件、网络、系统、应用全部特殊合规或超大规模
云主机 VPS系统、安全补丁、应用需要完全控制的服务
容器平台 / PaaS镜像或代码与配置多数 Web 应用
Serverless只写函数代码事件驱动、流量波动大
⚖️ 06 · 方案取舍

自管云主机

优点灵活、成本透明

代价补丁、安全、备份都要自己做

适用有运维能力、需定制环境

PaaS 平台部署

优点git push 即部署，免运维

代价单价更高，灵活性受限

适用Web 应用、小团队

Serverless

优点零闲置成本、自动扩缩

代价冷启动、时长与状态限制

适用API、定时任务、Webhook

🕳️ 07 · 常见坑

  • ✗SSH 允许密码登录且用 root 直接操作

    ✓改用密钥登录，禁用密码与 root 远程登录

  • ✗数据库端口直接暴露在公网

    ✓防火墙只开放必要端口，数据库仅内网访问

  • ✗进程手动启动，崩溃或重启后服务就没了

    ✓用 systemd、Docker 重启策略或平台托管保证自愈

  • ✗服务器长期不打补丁

    ✓开启自动安全更新，定期检查系统与依赖漏洞

🎤 09 · 面试追问
为什么需要 Nginx 这类反向代理？

统一入口：终止 HTTPS、按域名或路径转发到不同后端、负载均衡、静态文件服务、限流和缓存，并隐藏内部服务端口。应用本身只需监听本地端口，安全与流量管理交给代理层。

垂直扩展与水平扩展有何区别？

垂直扩展是给单机加 CPU、内存，简单但有上限且有单点；水平扩展是增加实例并通过负载均衡分流，可近乎线性扩容，但要求服务无状态、会话和数据外置。

让 AI Agent 操作生产服务器有何风险？

误执行破坏性命令、错误修改配置导致宕机、泄露凭证。应使用最小权限账号、只读优先、命令需人工确认，在预发环境演练，变更走版本化的基础设施即代码而非手动操作。
