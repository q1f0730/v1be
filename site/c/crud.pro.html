增删改查 (CRUD)

CRUD

📐 01 · 定义

CRUD 是 Create、Read、Update、Delete 四种基本数据操作的缩写，分别对应 SQL 的 INSERT、SELECT、UPDATE、DELETE，以及 REST 的 POST、GET、PUT/PATCH、DELETE，是业务系统的数据骨架。专业实现还要处理校验、授权、并发、分页、软删除和审计。

⚙️ 02 · 原理
  1. 1

    Create：校验输入，生成主键，写入数据库，返回 201 和新资源或其地址。

  2. 2

    Read：按 ID 读取单个资源，或按条件、分页、排序读取列表，并做对象级授权。

  3. 3

    Update：PUT 整体替换、PATCH 部分更新，用字段白名单和版本号防止越权与并发覆盖。

  4. 4

    Delete：硬删除直接移除数据；软删除标记 deleted_at，便于恢复和审计。

  5. 5

    每个操作都经过认证、授权、校验三层，并记录关键变更的审计日志。

🔤 03 · 术语
幂等性 (Idempotency)
PUT、DELETE 多次执行结果相同，POST 通常不是。
乐观锁 (Optimistic Locking)
用版本号或 ETag 检测并发修改，冲突时拒绝更新。
软删除 (Soft Delete)
用标记字段表示删除而不真正移除数据。
游标分页 (Cursor Pagination)
用上一页最后一条的排序键取下一页，适合大数据量。
Upsert
存在则更新、不存在则插入，如 PostgreSQL 的 ON CONFLICT。
💻 04 · 代码
CRUD 的专业写法sql
-- Create：返回生成的记录（PostgreSQL / SQLite 3.35+ 支持 RETURNING）
INSERT INTO notes (owner_id, title, body, version)
VALUES ($1, $2, $3, 1)
RETURNING id, created_at;

-- Read：游标分页 + 归属过滤 + 排除软删除
SELECT id, title, created_at FROM notes
WHERE owner_id = $1 AND deleted_at IS NULL AND id < $2
ORDER BY id DESC
LIMIT 20;

-- Update：乐观锁，版本不匹配则影响 0 行，应返回 409/412
UPDATE notes SET title = $3, version = version + 1, updated_at = now()
WHERE id = $1 AND owner_id = $2 AND version = $4;

-- Delete：软删除
UPDATE notes SET deleted_at = now()
WHERE id = $1 AND owner_id = $2 AND deleted_at IS NULL;

-- Upsert：存在则更新
INSERT INTO settings (user_id, theme) VALUES ($1, $2)
ON CONFLICT (user_id) DO UPDATE SET theme = EXCLUDED.theme;

PostgreSQL 语法；每条语句都带 owner_id 授权条件，更新带版本号防覆盖。

⚖️ 06 · 方案取舍

硬删除

优点数据干净，符合删除权要求

代价无法恢复

适用用户要求删除个人数据

软删除

优点可恢复、可审计

代价每个查询都要过滤，唯一约束更复杂

适用业务数据、误删风险高

偏移分页 OFFSET

优点实现简单，可跳页

代价深分页慢，数据变动时重复或遗漏

适用小数据量后台列表

🕳️ 07 · 常见坑

  • ✗Read/Update/Delete 只按 ID 操作不查归属

    ✓所有语句带 owner_id 或租户条件

  • ✗后写覆盖先写，丢失他人修改

    ✓使用版本号或 ETag 实现乐观锁

  • ✗列表接口不分页，一次返回全表

    ✓强制分页并限制最大页大小

  • ✗软删除后唯一约束导致无法重建同名记录

    ✓使用部分唯一索引，排除已删除行

☑️ 08 · 检查清单
🎤 09 · 面试追问
PUT 和 PATCH 的区别？

PUT 用请求体完整替换资源，缺失字段会被置空或默认值，语义上是幂等的；PATCH 只修改提供的字段，适合部分更新，不保证幂等。实践中 PATCH 更常用，但要配合字段白名单，防止客户端修改不允许的字段。

如何处理并发更新冲突？

乐观锁：读取时拿到版本号或 ETag，更新时带上，WHERE 条件匹配版本才更新，影响行数为 0 说明已被他人修改，返回 409 或 412 让客户端重新获取。高冲突场景可用悲观锁 SELECT ... FOR UPDATE，但会降低并发。

为什么大数据量推荐游标分页？

OFFSET 分页需要扫描并丢弃前面所有行，页码越深越慢；数据插入或删除时还会出现重复或遗漏。游标分页用上一页最后一条的排序键作为起点，配合索引可直接定位，性能稳定，结果也更一致，代价是不能随意跳页。
