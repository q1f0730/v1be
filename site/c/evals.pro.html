AI 评测 (Evals)

📐 01 · 定义

AI 评测（Evals）是用一组带期望结果或评分标准的测试用例，系统地衡量 LLM 应用输出质量的过程，评分方式包括代码断言、人工标注和 LLM 评审（LLM-as-a-Judge）。它是 AI 工程的质量保障层，相当于传统软件的测试套件，用于比较提示词、模型与架构改动，防止回归。

⚙️ 02 · 原理
  1. 1

    明确成功标准：任务正确性、格式、事实性、安全性、延迟与成本等可衡量维度。

  2. 2

    构建数据集：从真实日志、失败案例和边界场景收集输入，并标注期望输出或评分细则。

  3. 3

    运行被测系统得到输出，用确定性检查、相似度、LLM 评审或人工打分逐条评分。

  4. 4

    汇总为通过率、平均分等指标，按类别切片分析，定位具体失败模式。

  5. 5

    接入 CI，每次修改提示词或换模型都自动跑评测，与基线对比后再发布。

🔤 03 · 术语
LLM 评审 (LLM-as-a-Judge)
用模型按评分细则给输出打分，需与人工校准。
黄金数据集 (Golden Dataset)
经人工确认的标准输入与期望输出集合。
回归测试 (Regression Eval)
确保改动不破坏原本能通过的用例。
评分细则 (Rubric)
把主观质量拆成可判定的具体标准。
pass@k
k 次采样中至少一次通过的概率，常用于代码生成。

def grade(output: str, expect: str) -> bool:
    return expect.lower() in output.strip().lower()   # 确定性检查优先

def main():
    results = []
    for c in CASES:
        out = run_system(c["input"])
        results.append({**c, "output": out, "pass": grade(out, c["expect"])})
    rate = sum(r["pass"] for r in results) / len(results)
    print(f"通过率 {rate:.0%}")
    json.dump(results, open("eval_results.json", "w"), ensure_ascii=False, indent=2)

if __name__ == "__main__":
    main()

📊 05 · 参数对比

评分方式对比

方式成本适用风险
代码断言/精确匹配极低格式、抽取、分类覆盖不了开放式回答
LLM 评审中语气、相关性、完整性评审偏差，需人工校准
人工评审高高风险、主观质量慢，标准不一致
线上 A/B 指标中真实用户效果滞后，噪声大

🕳️ 07 · 常见坑

  • ✗凭几次手动试用就判断新提示词更好

    ✓固定数据集批量评测，与基线对比再决定

  • ✗LLM 评审未经校准就当真值

    ✓抽样与人工标注比对一致性，迭代评审提示词

  • ✗只看总分，不看失败案例

    ✓按类别切片并逐条阅读失败输出，归纳错误模式

  • ✗评测集被用来反复调提示词，产生过拟合

    ✓保留不参与调优的留出集定期验证

🎤 09 · 面试追问
如何让 LLM 评审更可靠？

使用具体评分细则而非笼统打分，优先二元或少档位判断；让评审先给理由再给结论；与人工标注比较一致率；注意位置偏差与偏好自身风格等问题，可交换顺序或换模型评审。

评测数据从哪来？

从真实用户日志与客服反馈中挑选典型与失败案例，补充领域专家写的边界场景，再用合成数据扩展覆盖；每次线上发现的新问题都转成一条回归用例。

Agent 类系统怎么评测？

除最终结果外，还要评估过程：是否选对工具、步骤数、是否越权操作、成本与耗时。可在可复现的沙箱环境中运行任务，用状态检查判定结果，并记录完整轨迹供分析。
