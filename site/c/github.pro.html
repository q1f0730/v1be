📐 01 · 定义

GitHub 是基于 Git 的代码托管与协作平台，提供 PR 评审、Issues 跟踪、Actions 自动化、Pages 托管与安全扫描等能力。Git 是本地工具，GitHub 是网络服务，同类平台还有 GitLab、Gitee。它也是 AI 编程 Agent 提交 PR、读取 Issue 的常见场所。

⚙️ 02 · 原理
  1. 1

    托管远程仓库：作为团队共享的远程仓库，通过 HTTPS 或 SSH 进行 push、pull。

  2. 2

    协作评审：开发者从分支发起 Pull Request，团队在线评论、审查并合并。

  3. 3

    自动化：GitHub Actions 根据推送、PR 等事件触发工作流，运行测试、构建与部署。

  4. 4

    项目管理：Issues、Projects 跟踪任务与缺陷，可与提交和 PR 相互关联。

  5. 5

    安全与治理：分支保护、必需检查、Dependabot、密钥扫描保障代码质量与安全。

🔤 03 · 术语
Fork
把他人仓库复制到自己账号下，常用于向开源项目贡献。
GitHub Actions
GitHub 内置的 CI/CD 与自动化工作流平台。
分支保护 (Branch Protection)
限制直接推送，要求评审和检查通过才能合并。
gh CLI
GitHub 官方命令行工具，可在终端操作 PR、Issue 等。
Personal Access Token
代替密码访问 GitHub API 和 HTTPS Git 操作的令牌。
💻 04 · 代码
每次 PR 自动跑测试yaml
# .github/workflows/ci.yml
name: CI
on:
  pull_request:
  push:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4          # 拉取代码
      - uses: actions/setup-node@v4        # 安装 Node
        with:
          node-version: 20
          cache: npm
      - run: npm ci                        # 按锁文件安装依赖
      - run: npm run lint --if-present
      - run: npm test

# 配合分支保护的「必需状态检查」，测试不通过的 PR 无法合并

PR 自动测试加分支保护，是把人和 AI 写的代码挡在质量门槛外的基础设施。

📊 05 · 参数对比

GitHub 核心功能

功能解决什么关键配置
Pull Request代码评审与讨论评审人、模板、必需审批数
Actions自动测试、构建、部署工作流文件、Secrets

⚖️ 06 · 方案取舍

公开仓库

优点免费协作，利于开源与作品展示

代价代码与历史完全公开

适用开源项目、个人作品

私有仓库

优点代码保密

代价部分高级功能按套餐收费

适用商业项目、未公开产品

自托管平台（如 GitLab 自建）

优点数据完全自控

代价需运维

适用强合规、内网环境

🕳️ 07 · 常见坑

  • ✗把密钥推送到公开仓库后删除了事

    ✓立即轮换密钥；历史中仍可见，需清理历史并开启推送保护

  • ✗用 GitHub 账号密码进行 HTTPS 推送

    ✓改用 SSH 密钥、gh auth login 或 Personal Access Token

  • ✗主分支没有保护，任何人可直接推送

    ✓开启分支保护，要求 PR 评审与 CI 通过

  • ✗Actions 中直接写明文密钥

    ✓使用仓库 Secrets，并最小化工作流权限

🎤 09 · 面试追问
Git 和 GitHub 是什么关系？

Git 是开源的分布式版本控制工具，在本地运行；GitHub 是托管 Git 仓库的商业平台，在其上提供协作、评审、CI/CD、项目管理等服务。不用 GitHub 也能用 Git，也可以选择 GitLab、Gitee 等其他托管平台。

如何安全地在 Actions 中使用密钥？

存放在仓库或环境级 Secrets，日志中会自动打码；设置 permissions 最小化 GITHUB_TOKEN 权限；来自 fork 的 PR 默认拿不到 Secrets；部署到云平台优先用 OIDC 换取短期凭证，避免长期密钥；对第三方 Action 固定版本或提交哈希。

AI Agent 如何与 GitHub 协作？

Agent 可在分支上修改代码，用 gh CLI 或 API 创建 PR、回复评审、读取 Issue；也有在 Actions 中运行的编码 Agent 由 Issue 或评论触发。关键是 Agent 产出仍走 PR 评审和 CI 检查，不直接写主分支。
