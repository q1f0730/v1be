📐 01 · 定义

YAML（YAML Ain't Markup Language）是以缩进表达层级、面向人类可读的数据序列化格式，是 JSON 的超集（YAML 1.2）。它是配置层的事实标准：GitHub Actions、Kubernetes、Docker Compose、OpenAPI 等都用它。灵活的隐式类型与缩进语义也带来一类常见配置错误。

⚙️ 02 · 原理
  1. 1

    文档由映射（键值对）、序列（- 开头的列表）和标量（字符串、数字、布尔等）三类节点组成。

  2. 2

    层级完全由空格缩进决定，同级元素缩进必须一致，规范禁止用 Tab 缩进。

  3. 3

    未加引号的标量会被解析器隐式推断类型，YAML 1.1 解析器会把 yes/no/on/off 当布尔值。

  4. 4

    支持锚点（&）与别名（*）复用节点、| 与 > 书写多行文本、--- 分隔同一文件中的多个文档。

  5. 5

    程序用库（如 PyYAML、js-yaml）解析为原生数据结构；不可信输入必须用安全加载函数。

🔤 03 · 术语
映射 (Mapping)
键值对集合，对应 JSON 对象或 Python dict。
序列 (Sequence)
以 - 开头的有序列表，对应 JSON 数组。
锚点与别名 (Anchor & Alias)
&name 标记节点，*name 引用它，用于复用配置块。
块标量 (Block Scalar)
| 保留换行，> 把换行折叠为空格，用于多行文本。
Norway 问题
YAML 1.1 中未加引号的 NO 被解析为 false，国家代码因此出错。
💻 04 · 代码
常见陷阱与正确写法yaml
# 字符串最好加引号，避免隐式类型转换
country: "NO"        # 不加引号时 YAML 1.1 解析器视为 false
version: "3.10"      # 不加引号会变成浮点数 3.1
port: 8080            # 数字

# 锚点复用公共配置
defaults: &defaults
  retries: 3
  timeout: 30

service_a:
  <<: *defaults       # 合并键：部分解析器支持
  timeout: 60         # 覆盖默认值

# 多行文本：| 保留换行
script: |
  npm ci
  npm test

# 列表：短横后需一个空格，缩进只能用空格
branches:
  - main
  - "release/*"

版本号、国家代码、带通配符的字符串一律加引号；<< 合并键并非所有工具都支持。

⚖️ 06 · 方案取舍

YAML

优点可读性好、支持注释与复用

代价缩进与隐式类型易出错

适用人工维护的复杂配置

JSON

优点语法严格、解析一致

代价无注释、括号多

适用机器生成与交换的数据

TOML

优点类型明确、歧义少

代价深层嵌套较啰嗦

适用工具与包的元数据配置

🕳️ 07 · 常见坑

  • ✗用 yaml.load 解析不可信输入

    ✓PyYAML 用 yaml.safe_load，防止构造任意 Python 对象

  • ✗版本号 3.10 不加引号被解析成 3.1

    ✓版本号、邮编、以 0 开头的编码都加引号

    ✓编辑器显示空白字符，提交前用 yamllint 检查

  • ✗以为所有工具都支持锚点合并键

    ✓查目标工具文档，必要时展开写全

🎤 09 · 面试追问
为什么说 YAML 是 JSON 的超集？

YAML 1.2 规范的目标之一是与 JSON 兼容，合法 JSON 基本都能被 YAML 1.2 解析器读取。但很多常用库仍实现 YAML 1.1（如 PyYAML），在布尔值等细节上与 1.2 不同。

yaml.load 为什么危险？

PyYAML 的完整加载器支持特定标签构造任意 Python 对象，恶意文档可借此执行代码。应使用 safe_load，只解析基本类型；PyYAML 5.1 起不带 Loader 调用会警告，6.0 起必须显式指定 Loader。

如何降低 CI 配置写错的概率？

编辑器启用 YAML Language Server 与官方 JSON Schema；提交前跑 yamllint 和 actionlint 等工具；复用部分抽成可复用工作流或模板；改动后在分支上先跑一遍。
