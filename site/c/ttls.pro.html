缓存生存时间 (TTL)

TTLs

📐 01 · 定义

TTL（Time To Live，生存时间）是给缓存项或数据设置的有效期，到期后被视为过期并重新获取或删除。它出现在 HTTP 缓存（Cache-Control max-age）、DNS 记录、Redis 键、CDN 边缘等多个层次，是在数据新鲜度与源站负载之间做权衡的核心参数。

⚙️ 02 · 原理
  1. 1

    写入缓存时附带 TTL，存储层记录过期时间点，如 Redis 的 EXPIRE 或 SET … EX。

  2. 2

    读取时若未过期直接返回；过期则视为未命中，回源获取并重新写入。

  3. 3

    HTTP 中由 Cache-Control: max-age / s-maxage 指定浏览器和共享缓存的 TTL。

  4. 4

    stale-while-revalidate 允许过期后短时间内先返回旧值，同时后台刷新。

  5. 5

    大量键同时过期会导致回源洪峰，通常给 TTL 加随机抖动来分散过期时间。

🔤 03 · 术语
max-age
响应可被视为新鲜的秒数，作用于所有缓存。
s-maxage
仅对共享缓存（CDN、代理）生效的 TTL。
stale-while-revalidate
RFC 5861 扩展，过期后可先用旧值并后台刷新。
缓存雪崩 (Cache Avalanche)
大量缓存同时失效，请求集中打到源站。
缓存击穿 (Cache Stampede)
热点键过期瞬间大量并发同时回源。
💻 04 · 代码
带抖动与互斥的 Redis 缓存python
import json, random
import redis

r = redis.Redis()
BASE_TTL = 300  # 5 分钟

def get_product(pid, load_from_db):
    key = f"product:{pid}"
    cached = r.get(key)
    if cached:
        return json.loads(cached)
    # 互斥锁：只让一个请求回源，防止热点击穿
    if r.set(f"lock:{key}", 1, nx=True, ex=10):
        try:
            data = load_from_db(pid)
            ttl = BASE_TTL + random.randint(0, 60)   # 抖动，避免同时过期
            r.set(key, json.dumps(data), ex=ttl)
            return data
        finally:
            r.delete(f"lock:{key}")
    return load_from_db(pid)  # 简化：未抢到锁直接查库，也可短暂等待重试

# 查看剩余寿命：r.ttl("product:1")  -> 秒数，-1 无过期，-2 不存在

TTL 加随机抖动分散过期，互斥锁让热点键只回源一次。

📊 05 · 参数对比

不同层的 TTL 设置

层级配置方式典型考虑
浏览器Cache-Control: max-age用户无法主动清除，宜保守
CDNs-maxage 或控制台规则可主动清除，可设较长
应用缓存 (Redis)EXPIRE / SET EX按数据变化频率设定
DNS记录 TTL迁移前提前调低
⚖️ 06 · 方案取舍

短 TTL

优点数据更新快，不一致窗口小

代价命中率低，回源压力大

适用价格、库存等易变数据

长 TTL + 主动失效

优点命中率高且能及时更新

代价需在写路径维护失效逻辑

适用读多写少、写入点可控

永不过期 + 后台刷新

优点无击穿，延迟稳定

代价数据可能长期陈旧，占内存

适用配置、榜单等少量热点

🕳️ 07 · 常见坑

  • ✗所有键使用同一固定 TTL

    ✓加随机抖动，分散过期时间

  • ✗HTML 设置很长的 max-age，发布后用户拿不到新版本

    ✓HTML 用短 TTL 或 no-cache，静态资源用带哈希文件名加长 TTL

  • ✗迁移服务器当天才调低 DNS TTL

    ✓提前至少一个旧 TTL 周期调低，切换后再恢复

  • ✗Redis 中忘记设置过期，内存持续增长

    ✓写入缓存统一走带 TTL 的封装，并配置淘汰策略

☑️ 08 · 检查清单
🎤 09 · 面试追问
缓存雪崩、击穿、穿透的区别？

雪崩：大量键同时过期或缓存宕机，请求集中回源，靠 TTL 抖动和高可用缓解。击穿：单个热点键过期瞬间并发回源，用互斥锁或提前刷新。穿透：查询不存在的数据始终未命中，用空值缓存或布隆过滤器。

max-age 和 s-maxage 怎么配合？

s-maxage 只对共享缓存生效并覆盖 max-age。常见做法是浏览器短 TTL、CDN 长 TTL，发布时主动清 CDN，兼顾新鲜度和源站负载。

TTL 是精确到期删除吗？

不一定。Redis 结合访问时惰性删除和周期性抽样删除，过期键不会都在到期瞬间释放内存，但读取时不会返回过期值。CDN 也可能在 TTL 内因容量提前淘汰。
