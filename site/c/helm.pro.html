Helm 包管理

Helm

📐 01 · 定义

Helm 是 Kubernetes 的包管理器，属于应用交付层。它把一组 K8s 资源清单模板化为 Chart，用 values 文件参数化不同环境，安装后形成带版本历史的 Release，支持升级、回滚和卸载。CNCF 毕业项目，是分发第三方组件（数据库、监控、Ingress）最常用的方式。

⚙️ 02 · 原理
  1. 1

    Chart 由 Chart.yaml（元数据）、values.yaml（默认参数）和 templates/（Go 模板写的资源清单）组成。

  2. 2

    执行 helm install/upgrade 时，Helm 合并默认 values、-f 文件与 --set 参数，渲染模板得到最终 YAML。

  3. 3

    渲染结果提交给 Kubernetes API Server 创建或更新资源，Helm 3 不再需要集群内的 Tiller 组件。

  4. 4

    每次安装或升级生成一个 Release 修订版本，默认以 Secret 形式存储在所在命名空间中。

  5. 5

    helm rollback 用历史修订的清单重新应用；helm uninstall 删除该 Release 管理的资源。

🔤 03 · 术语
Chart
Helm 的打包格式，包含模板、默认配置与元数据。
Values
注入模板的参数，可分层覆盖以区分环境。
Release
Chart 在集群中的一次安装实例，带修订历史。
Repository / OCI Registry
存放和分发 Chart 的仓库，Helm 3 支持 OCI 镜像仓库。
Hook
在安装、升级等生命周期节点执行的特殊资源，如迁移 Job。
💻 04 · 代码
安装、升级与回滚bash
# 添加仓库并安装（Bitnami 等仓库也提供 OCI 地址）
helm repo add bitnami https://charts.bitnami.com/bitnami
helm repo update

# 先渲染查看最终 YAML，不真正部署
helm template my-redis bitnami/redis -f values-prod.yaml | less

# 安装或升级（不存在则安装），失败自动回滚
helm upgrade --install my-redis bitnami/redis \
  -n data --create-namespace \
  -f values-prod.yaml --atomic --timeout 5m

# 查看修订历史并回滚到修订 1
helm history my-redis -n data
helm rollback my-redis 1 -n data

upgrade --install 实现幂等部署；--atomic 在失败时自动回滚，适合放进 CI。

📊 05 · 参数对比

K8s 配置管理方案对比

方案机制适用
原生 YAML + kubectl直接应用清单资源少、单环境
Kustomize基础清单 + 补丁叠加自有应用多环境
Helm模板 + values + 版本历史分发与复用第三方组件
Helm + GitOpsArgo CD/Flux 拉取同步需要审计与自动对齐
⚖️ 06 · 方案取舍

使用社区 Chart

优点开箱即用，维护者负责升级

代价模板复杂、默认值未必安全

适用标准组件如 Redis、Prometheus

自写 Chart

优点完全掌控，贴合业务

代价模板维护成本，Go 模板可读性差

适用需分发给多团队/多客户的应用

Kustomize 替代

优点纯 YAML 无模板，直观

代价缺少打包分发与版本历史

适用只有自家应用、环境差异小

🕳️ 07 · 常见坑

  • ✗在集群里 kubectl edit 改 Helm 管理的资源

    ✓所有修改走 values 并 helm upgrade，或交给 GitOps

  • ✗Secret 明文写进 values 并提交 Git

    ✓用外部密钥管理（如 External Secrets、SOPS）注入

  • ✗不固定 Chart 版本，upgrade 时意外升大版本

    ✓安装时用 --version 锁定，升级前读变更说明

  • ✗只看 values 不看渲染结果就上生产

    ✓用 helm template 或 helm diff 插件审查最终清单

🎤 09 · 面试追问
Helm 3 相比 Helm 2 最大的架构变化？

移除了集群内的 Tiller 服务端组件，客户端直接以用户凭据调用 API Server，权限由 K8s RBAC 控制；Release 信息默认存为命名空间内的 Secret；引入三方合并补丁与 OCI 支持。

Helm 和 Kustomize 怎么选？

Helm 适合需要打包、分发、参数化和版本回滚的场景，尤其第三方组件；Kustomize 用纯 YAML 补丁叠加，透明无模板，适合自家应用多环境。二者也可组合使用。

helm rollback 能恢复数据吗？

不能。它只重新应用旧版本的 K8s 清单；数据库 Schema 变更、PVC 中的数据不会回退。有状态升级需另做备份和迁移回滚方案。
