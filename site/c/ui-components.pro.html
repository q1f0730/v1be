组件化 (Component)

📐 01 · 定义

组件（Component）是把 UI 的结构、样式与行为封装成可复用、可组合单元的前端设计方式，React、Vue、Svelte 与 Web Components 都以此为核心。组件通过属性（props）接收输入、通过事件或回调向外通知，内部管理局部状态。它属于前端架构层，决定代码复用度、可测试性与 AI 修改时的上下文边界。

⚙️ 02 · 原理
  1. 1

    把页面按职责拆成组件树：页面组件组合区块组件，区块组件组合基础组件（按钮、输入框）。

  2. 2

    父组件通过 props 向下传数据，子组件通过回调或事件向上通知，形成单向数据流。

  3. 3

    组件内部用局部状态管理交互细节，跨组件共享的状态上提到共同父级或交给状态管理方案。

  4. 4

    框架在状态或 props 变化时重新渲染组件，并把差异同步到 DOM。

  5. 5

    通过组合（children、插槽）而非继承扩展组件，使同一外壳能容纳不同内容。

🔤 03 · 术语
属性 (Props)
父组件传给子组件的只读输入参数。
状态 (State)
组件内部可变数据，变化会触发重新渲染。
状态提升 (Lifting State Up)
把多个组件共享的状态移到它们最近的共同父组件。
组合 (Composition)
通过 children 或插槽嵌入内容，而不是继承扩展。
受控组件 (Controlled Component)
表单值由父级状态决定并通过回调更新的组件。
💻 04 · 代码
可复用的 React 组件typescript
// Button.tsx：基础组件，只关心外观与点击
type ButtonProps = {
  variant?: "primary" | "ghost";
  onClick?: () => void;
  children: React.ReactNode; // 组合：内容由外部决定
};

export function Button({ variant = "primary", onClick, children }: ButtonProps) {
  return (
    <button className={`btn btn-${variant}`} onClick={onClick}>
      {children}
    </button>
  );
}

// Counter.tsx：业务组件，持有状态，组合基础组件
import { useState } from "react";

export function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <span>已点击 {count} 次</span>
      <Button onClick={() => setCount((c) => c + 1)}>+1</Button>
    </div>
  );
}

基础组件无业务状态、靠 props 与 children 定制；业务组件持有状态并组合它们。

📊 05 · 参数对比

组件分层与职责

层级例子是否持有业务状态
基础组件Button、Input否，仅 props
复合组件表单、卡片列表少量 UI 状态
页面/容器组件订单页是，负责取数与编排
⚖️ 06 · 方案取舍

细粒度组件

优点复用高、易测试、AI 改动范围小

代价文件多、props 传递层级深

适用设计系统、长期维护项目

粗粒度组件

优点上手快、跳转少

代价难复用，改动牵一发动全身

适用原型与一次性页面

Web Components

优点框架无关、可跨技术栈

代价与框架状态集成较繁琐

适用多框架共存的组织

🕳️ 07 · 常见坑

  • ✗props 逐层透传五六层（prop drilling）

    ✓用组合传入子组件，或改用 Context/状态库

  • ✗基础组件里写死业务逻辑和接口请求

    ✓基础组件保持纯展示，数据与副作用放到容器层

  • ✗把可由 props 推导的值复制进 state

    ✓渲染时直接计算派生值，避免两份数据不同步

  • ✗让 AI 在超大单文件组件中修改

    ✓先拆分组件，再按文件给 AI 最小上下文

🎤 09 · 面试追问
为什么 React 推荐组合而不是继承？

组合通过 props 与 children 注入内容和行为，依赖关系显式、可替换；继承形成脆弱的层级耦合，父类改动影响所有子类。官方文档也指出用组合即可覆盖绝大多数复用场景。

什么时候该把状态提升，什么时候引入状态库？

两个兄弟组件需共享数据时先提升到共同父级；当共享跨越很多层、多个远距离组件读写同一数据，或需要缓存服务端数据时，再考虑 Context、Zustand 或 TanStack Query 等方案。

组件拆分对 AI 辅助开发有什么影响？

小而清晰的组件让 Agent 只需读少量文件即可改动，降低上下文消耗和误改风险；明确的 props 类型充当契约，类型检查能及时发现 AI 改坏的调用点。
