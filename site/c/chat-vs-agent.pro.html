聊天模式 vs 智能体模式

Chat vs Agent

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

聊天模式（Chat）是「一问一答」：模型只生成文本，由人决定是否采纳和执行。智能体模式（Agent）是让模型在循环中自主调用工具（读写文件、运行命令、查询 API），根据结果继续决策直到完成目标。两者底层可能是同一个模型，差别在于是否有工具、循环和执行权限。

⚙️ 02 · 原理
  1. 1

    定义工具：开发者向模型声明可用工具的名称、描述和参数 Schema。

  2. 2

    模型决策：模型根据任务判断是直接回答，还是输出一个结构化的工具调用请求。

  3. 3

    执行工具：由应用程序（而非模型本身）解析参数并真正执行该调用，拿到执行结果。

  4. 4

    回传结果：把工具结果作为新消息追加到上下文，带着完整历史再次请求模型。

  5. 5

    循环终止：重复以上步骤，直到模型给出最终答复、达到步数上限或需要人确认。

🔤 03 · 术语
工具调用 (Tool Use / Function Calling)
模型输出结构化调用请求，由应用执行并回传结果。
Agent 循环 (Agent Loop)
「思考—调用工具—观察结果」不断重复的控制流程。
ReAct
交替生成推理与行动的 Agent 范式，出自 2022 年论文。
人工确认 (Human Approval)
高风险工具执行前暂停，等待用户批准。
子 Agent (Subagent)
由主 Agent 派出的独立上下文执行子任务的 Agent。
💻 04 · 代码
最小 Agent 循环python
import anthropic, subprocess
client = anthropic.Anthropic()
tools = [{"name": "run_bash", "description": "在当前目录执行一条 shell 命令",
          "input_schema": {"type": "object",
                           "properties": {"cmd": {"type": "string"}},
                           "required": ["cmd"]}}]
messages = [{"role": "user", "content": "统计当前目录下有多少个 .py 文件"}]

for _ in range(5):                       # 步数上限，防止死循环
    resp = client.messages.create(model="claude-sonnet-4-5", max_tokens=1024,
                                  tools=tools, messages=messages)
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":   # 不再调用工具 = 任务结束
        print(resp.content[-1].text); break
    results = []
    for block in resp.content:
        if block.type == "tool_use":     # 真实执行由程序完成（演示用，生产需沙箱与确认）
            out = subprocess.run(block.input["cmd"], shell=True,
                                 capture_output=True, text=True).stdout
            results.append({"type": "tool_result",
                            "tool_use_id": block.id, "content": out})
    messages.append({"role": "user", "content": results})

Agent 的本质就是这个循环：模型提议工具调用，程序执行并回传，直到模型不再调用工具。

📊 05 · 参数对比

聊天与 Agent 工程差异

维度聊天Agent
每次任务调用次数通常 1 次多次，随步骤增长
副作用无，只产出文本会改文件、发请求、执行命令
失败模式答错错误累积、死循环、误操作
必需的工程配套提示词与输出校验权限、沙箱、步数上限、日志审计
⚖️ 06 · 方案取舍

聊天模式

优点便宜、可控、无副作用

代价需要人手动落地

适用提问、方案讨论、学习

受控 Agent（逐步确认）

优点能执行又能把关

代价需频繁人工介入

适用陌生代码库、敏感操作

自主 Agent（自动批准）

优点效率最高

代价误操作风险和成本最高

适用隔离环境、目标明确、可回滚

🕳️ 07 · 常见坑

  • ✗Agent 循环不设步数或预算上限

    ✓设置最大轮数、Token 预算和超时，超限即停

  • ✗工具直接拿模型参数执行 shell，无沙箱

    ✓在容器或受限环境执行，危险命令走白名单或人工确认

  • ✗工具返回内容未截断，迅速撑爆上下文

    ✓截断或摘要大输出，只回传关键部分

  • ✗简单问答也上 Agent 架构

    ✓能一次调用解决的不要引入循环

☑️ 08 · 检查清单
🎤 09 · 面试追问
工具调用时，模型真的执行了代码吗？

没有。模型只输出一个结构化请求（工具名和参数），由应用程序解析并执行，再把结果作为消息回传。因此安全边界在应用侧：参数校验、权限控制、沙箱都由开发者实现。

Agent 为什么容易越做越偏？

每步都有出错概率，错误会写入上下文并影响后续决策；长任务中上下文膨胀、早期目标被稀释。对策：清晰的完成标准、拆分子任务、阶段性校验（测试）、步数上限、必要时让人确认计划后再执行。

workflow 与 agent 怎么选？

路径固定、可枚举的流程用预定义工作流（代码编排多次 LLM 调用），可预测、易调试；步骤无法事先确定、需要根据结果动态决策时才用 Agent。Anthropic 的建议是从最简单方案开始，只在必要时增加自主性。
