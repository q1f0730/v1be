子网划分与公私隔离

Subnets

🧸 回到小白版

📐 01 · 定义

子网（Subnet）是把 VPC 地址段进一步切分出的更小网段，在主流云上每个子网位于单一可用区。子网本身没有“公有”“私有”属性，决定其角色的是关联的路由表：默认路由指向互联网网关即为公有子网，指向 NAT 或无出网路由即为私有/隔离子网。

⚙️ 02 · 原理
  1. 1

    从 VPC 的 CIDR 中划出不重叠的子网段，每个子网落在一个可用区。

  2. 2

    云平台会保留每个子网的部分地址（AWS 为每个子网 5 个），可用地址少于理论值。

  3. 3

    每个子网关联一张路由表；0.0.0.0/0 指向 IGW 为公有，指向 NAT 网关为私有。

  4. 4

    典型三层布局：公有层放负载均衡与 NAT，私有层放应用，隔离层放数据库。

  5. 5

    同一层在多个可用区各建一个子网，单个可用区故障时其他可用区继续服务。

🔤 03 · 术语
公有子网 (Public Subnet)
路由表含指向互联网网关的默认路由。
私有子网 (Private Subnet)
通过 NAT 出网，不能被公网直接访问。
隔离子网 (Isolated Subnet)
完全没有通往公网的路由。
路由表 (Route Table)
按目的网段决定下一跳的规则集合。
前缀长度 (Prefix Length)
/24 表示 256 个地址，前缀越大网段越小。
保留地址 (Reserved IPs)
云平台为网关、DNS 等占用的子网地址。
💻 04 · 代码
规划三层多可用区子网python
import ipaddress

vpc = ipaddress.ip_network("10.20.0.0/16")
azs = ["a", "b", "c"]
blocks = list(vpc.subnets(new_prefix=20))   # 切成 16 个 /20，每个 4096 个地址

plan = {}
for i, az in enumerate(azs):
    plan[f"public-{az}"]  = blocks[i]       # 负载均衡、NAT 网关
    plan[f"private-{az}"] = blocks[i + 3]   # 应用、容器
    plan[f"data-{az}"]    = blocks[i + 6]   # 数据库、缓存（无公网路由）

for name, net in plan.items():
    usable = net.num_addresses - 5           # AWS 每个子网保留 5 个地址
    print(f"{name:10} {str(net):16} 可用 {usable}")

print("预留扩展：", [str(b) for b in blocks[9:]])

# 路由表设计：
#   public-*  : 0.0.0.0/0 -> igw-xxxx
#   private-* : 0.0.0.0/0 -> 同可用区的 nat-xxxx
#   data-*    : 只有 VPC 本地路由

用标准库算 CIDR，避免手算出错；公私属性由路由表决定，并预留空闲网段。

⚖️ 06 · 方案取舍

每个 AZ 一个 NAT 网关

优点单 AZ 故障不影响其他 AZ 出网

代价NAT 固定费用翻倍

适用生产环境

共享单个 NAT 网关

优点成本低

代价单点故障，跨 AZ 流量费

适用开发测试环境

大子网（/20 以上）

优点容器等场景 IP 充足

代价隔离粒度粗

适用Kubernetes 节点与 Pod 子网

🕳️ 07 · 常见坑

  • ✗子网开成 /24，Kubernetes Pod 很快耗尽 IP

    ✓按 Pod 网络模型估算 IP 需求，给足前缀

  • ✗以为给实例分配公网 IP 就能上网

    ✓还需所在子网路由指向 IGW 且安全规则放行

  • ✗应用层只建在一个可用区

    ✓每一层在至少两个可用区各建子网

  • ✗私有子网路由指向其他 AZ 的 NAT

    ✓每个 AZ 路由到本 AZ 的 NAT，避免跨 AZ 依赖

🎤 09 · 面试追问
什么决定一个子网是公有还是私有？

关联的路由表。默认路由 0.0.0.0/0 指向互联网网关就是公有子网；指向 NAT 网关是私有子网；没有出网路由是隔离子网。实例是否有公网 IP、安全组是否放行是另外两个条件。

/24 子网在 AWS 上实际有多少可用地址？

/24 共 256 个地址，AWS 保留网络地址、VPC 路由器、DNS、未来使用和广播地址共 5 个，因此可用 251 个。规划时还要考虑负载均衡、Lambda 网卡、Pod 等也会占用 IP。

为什么数据库要放隔离子网？

数据库不需要主动访问公网，也不应被公网访问。去掉出网路由可以减少数据外泄路径和误配置风险；更新补丁、备份等通过 VPC 端点或托管服务完成，即使安全组配置失误也多一层保护。
