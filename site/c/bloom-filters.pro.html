布隆过滤器

Bloom Filters

📐 01 · 定义

布隆过滤器（Bloom Filter）是一种空间效率极高的概率型数据结构，用一个位数组和 k 个哈希函数判断元素是否在集合中：回答「不在」一定正确，回答「可能在」有一定误判率，且标准版本不支持删除。常用于减少无效磁盘读取、防缓存穿透和大规模去重预筛。

⚙️ 02 · 原理
  1. 1

    初始化：分配 m 位全为 0 的位数组，并选定 k 个相互独立的哈希函数。

  2. 2

    插入：对元素计算 k 个哈希值，把位数组中对应的 k 个位置都置为 1。

  3. 3

    查询：检查 k 个位置，只要有任一位为 0 就说明该元素一定不在集合中。

  4. 4

    误判：k 个位置全为 1 时也可能是被其他元素置位的，结论只能是可能存在。

  5. 5

    参数：误判率约为 (1 − e^(−kn/m))^k，最优 k = (m/n)·ln2，n 为元素数量。

🔤 03 · 术语
误判率 (False Positive Rate)
不在集合中的元素被判为可能存在的概率。
假阴性 (False Negative)
标准布隆过滤器不会出现：已插入的元素一定被判为存在。
计数布隆过滤器 (Counting Bloom)
位换成计数器以支持删除，空间开销更大。
布谷鸟过滤器 (Cuckoo Filter)
支持删除、在低误判率下空间效率更好的替代结构。
缓存穿透 (Cache Penetration)
大量查询不存在的键，绕过缓存直接压垮数据库。
💻 04 · 代码
按目标误判率建过滤器python
import hashlib, math

class Bloom:
    def __init__(self, n: int, p: float):
        self.m = math.ceil(-n * math.log(p) / (math.log(2) ** 2))  # 位数
        self.k = max(1, round(self.m / n * math.log(2)))           # 哈希个数
        self.bits = bytearray((self.m + 7) // 8)

    def _idx(self, item: str):
        d = hashlib.sha256(item.encode()).digest()
        a, b = int.from_bytes(d[:8], "big"), int.from_bytes(d[8:16], "big")
        return [(a + i * b) % self.m for i in range(self.k)]       # 双重哈希

    def add(self, item: str):
        for i in self._idx(item):
            self.bits[i // 8] |= 1 << (i % 8)

    def __contains__(self, item: str) -> bool:
        return all(self.bits[i // 8] >> (i % 8) & 1 for i in self._idx(item))

bf = Bloom(n=1_000_000, p=0.01)     # 百万元素、1% 误判率 → 约 1.2MB、k=7
bf.add("user:42")
print("user:42" in bf, "user:43" in bf, bf.m, bf.k)

按公式由元素数 n 和目标误判率 p 推出 m 与 k；1% 误判率约需每元素 9.6 位。

场景过滤器作用误判的后果

⚖️ 06 · 方案取舍

标准布隆过滤器

优点空间极省、查询 O(k)

代价不能删除，有误判

适用集合只增不删

计数布隆/布谷鸟过滤器

优点支持删除

代价实现更复杂，空间更大或有插入失败

适用集合需删除元素

精确集合（哈希表）

优点无误判

代价内存占用高

适用元素量可承受且不能误判

🕳️ 07 · 常见坑

  • ✗实际元素数远超设计容量，误判率急剧上升

    ✓按预期规模留余量，监控填充率，超限时重建或使用可扩展版本

  • ✗用它判断「一定存在」做业务决策

    ✓只用其「一定不存在」的结论，存在时仍需查真实数据

  • ✗数据删除后过滤器仍判为存在，长期失真

    ✓定期全量重建，或改用支持删除的结构

🎤 09 · 面试追问
布隆过滤器为什么不会假阴性？

插入时元素对应的 k 个位都被置 1，标准版本从不把位清零，因此查询同一元素时这 k 位必然仍为 1，结果总是可能存在。误判只来自其他元素恰好把这 k 位都置成了 1。

如何确定位数组大小和哈希个数？

给定元素数 n 和目标误判率 p，m = −n·ln p / (ln2)²，k = (m/n)·ln2。例如 p=1% 时每元素约 9.6 位、k 约为 7；误判率每降低 10 倍，每元素约增加 4.8 位。

怎么用布隆过滤器防缓存穿透？

把数据库中所有有效键预先加入过滤器，请求先查过滤器：判为一定不存在则直接返回，不查缓存和数据库；判为可能存在才走正常流程。新增数据要同步加入，删除较多时需定期重建。
