网址 (URL)

URL

📐 01 · 定义

URL（统一资源定位符）是标识并定位网络资源的字符串，由协议（scheme）、主机、端口、路径、查询参数和片段等部分组成，语法由 RFC 3986 定义，浏览器实际遵循 WHATWG URL 标准。它是前端路由、API 设计、链接分享、缓存和安全策略（同源判断）的共同基础。

⚙️ 02 · 原理
  1. 1

    协议：scheme 决定如何访问资源，如 https、http、mailto，后接分隔符「://」。

  2. 2

    定位主机：host 部分经 DNS 解析为 IP，port 缺省时使用协议默认端口（443/80）。

  3. 3

    资源路径：path 标识服务器上的资源，在 API 中常对应 REST 资源层级。

  4. 4

    查询参数：「?」后的 key=value 对，以「&」分隔，用于过滤、分页等。

  5. 5

    片段：「#」后的部分只在浏览器端使用，不会发送给服务器，常用于页面锚点和前端路由。

🔤 03 · 术语
URI / URL
URI 是资源标识符总称，URL 是带定位方式的 URI。
百分号编码 (Percent-encoding)
把空格、中文等特殊字符编码成 %XX 形式。
源 (Origin)
协议 + 主机 + 端口三元组，是浏览器同源策略的判断单位。
查询字符串 (Query String)
URL 中「?」之后的参数部分。
相对 URL
省略协议或主机的地址，相对于当前页面解析。
💻 04 · 代码
安全地解析与拼接 URLjavascript
// 浏览器与 Node.js 都内置 URL 和 URLSearchParams
const u = new URL("https://api.example.com:8443/v1/search?q=hello#top");

console.log(u.protocol); // "https:"
console.log(u.hostname); // "api.example.com"
console.log(u.port);     // "8443"
console.log(u.pathname); // "/v1/search"
console.log(u.hash);     // "#top"（不会发给服务器）
console.log(u.origin);   // "https://api.example.com:8443"

// 拼查询参数：自动做百分号编码，避免手拼字符串出错
const api = new URL("/v1/search", "https://api.example.com");
api.searchParams.set("q", "大语言模型 & RAG");
api.searchParams.set("page", "2");
console.log(api.toString());
// https://api.example.com/v1/search?q=%E5%A4%A7...&page=2

用 URL API 解析和构造地址，比字符串拼接更不易出错，也能正确处理编码。

📊 05 · 参数对比

URL 设计规范要点

场景推荐做法原因
REST 资源/users/42/orders名词复数、层级表达关系
过滤与分页?status=paid&page=2参数可选、可组合、可缓存
版本/v1/... 或请求头便于兼容旧客户端
敏感信息不放进 URL会进入日志、历史记录与 Referer
⚖️ 06 · 方案取舍

路径参数 /items/42

优点语义清晰，标识唯一资源

代价层级多时冗长

适用定位单个资源

查询参数 ?id=42

优点可选、灵活组合

代价语义不如路径明确

适用过滤、排序、分页、搜索

请求体传参（POST）

优点可传复杂结构，不进 URL 日志

代价不可直接分享与缓存

适用复杂查询、敏感数据

🕳️ 07 · 常见坑

  • ✗把 Token、密码放进 URL 查询参数

    ✓敏感数据放请求头或请求体，URL 会被记录在日志与浏览器历史

  • ✗手动拼接参数，中文和 & 符号导致参数错乱

    ✓使用 URLSearchParams 或 encodeURIComponent 编码

  • ✗重定向目标直接取自用户传入的 URL

    ✓校验跳转地址白名单，防止开放重定向钓鱼

🎤 09 · 面试追问
URL 中 # 后面的部分会发送到服务器吗？

不会。片段（fragment）只在客户端使用，浏览器发请求时会去掉它。因此早期 SPA 用 hash 路由无需服务端配置；但也意味着服务端无法据此渲染内容，对 SEO 不友好。

什么是同源？为什么重要？

协议、主机、端口三者都相同才是同源。浏览器同源策略限制脚本读取跨源响应，防止恶意网站读取你在其他站点的数据。跨源访问需要服务端通过 CORS 头明确允许。

encodeURI 和 encodeURIComponent 区别？

encodeURI 用于编码整条 URL，保留 :/?#& 等结构字符；encodeURIComponent 用于编码单个参数值，会把这些字符也编码。拼参数值应使用后者，或直接用 URLSearchParams。
