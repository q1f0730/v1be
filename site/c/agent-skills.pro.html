智能体技能 (Skills)

Agent Skills

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

智能体技能（Agent Skills）是 Anthropic 提出的把专业知识打包给智能体的方式：一个技能是包含 SKILL.md（带名称与描述的 YAML 头部和指令正文）及可选脚本、模板、参考资料的文件夹。智能体平时只加载各技能的简短描述，相关时才读取全文和附属文件，即渐进式披露。

⚙️ 02 · 原理
  1. 1

    每个技能是一个目录，核心文件 SKILL.md 以 YAML 头部声明 name 与 description。

  2. 2

    会话启动时只把所有技能的名称和描述放入上下文，常驻开销很小。

  3. 3

    任务与某个技能描述匹配时，智能体读取该 SKILL.md 正文获取详细步骤。

  4. 4

    正文可引用同目录下的其他文件或脚本，智能体按需读取或执行，而非全部加载。

  5. 5

    技能可放在用户级或项目级目录中共享，也可通过 API 上传给托管智能体使用。

🔤 03 · 术语
SKILL.md
技能的入口文件，含 YAML 元数据与指令正文。
渐进式披露 (Progressive Disclosure)
先给摘要，需要时再逐层加载细节。
description 字段
决定智能体何时使用技能的关键描述。
附属脚本 (Bundled Scripts)
技能内可执行的代码，用于确定性操作。
MCP
模型上下文协议，用于连接外部工具与数据，与技能互补。
💻 04 · 代码
一个技能的目录与 SKILL.mdtext
# 目录结构（例如放在 .claude/skills/ 下）
release-notes/
├── SKILL.md
├── template.md          # 发布说明模板
└── scripts/
    └── collect_commits.sh

# SKILL.md
---
name: release-notes
description: 根据 git 提交生成面向用户的发布说明。当用户要求写
  release notes、更新日志或版本说明时使用。
---
# 生成发布说明
1. 运行 scripts/collect_commits.sh <上一个标签> 获取提交列表
2. 按 feat / fix / perf 分组，忽略 chore 与 ci
3. 用 template.md 的结构输出，语言面向终端用户
4. 破坏性变更单独列在最前面，并给出迁移步骤

描述写清何时使用；正文写步骤；确定性的工作交给脚本，模板按需读取。

📊 05 · 参数对比

给智能体扩展能力的方式

方式提供什么加载时机
系统提示/记忆文件常驻规则与约定每次会话全部加载
Agent Skills专业流程、脚本、资料按需加载
MCP 服务器外部工具与数据访问工具定义随会话加载
子代理独立上下文的专项执行者被委派时启动
⚖️ 06 · 方案取舍

写进系统提示

优点始终生效，简单

代价内容多时挤占上下文

适用少量全局规则

做成技能

优点按需加载，可附脚本与资料

代价依赖描述触发，可能漏用

适用可复用的专业流程

做成 MCP 工具

优点可访问外部系统与实时数据

代价需运行服务，工具定义占上下文

适用需要调用外部 API

🕳️ 07 · 常见坑

  • ✗description 太笼统，技能该用时没被触发

    ✓写明具体任务、关键词与使用时机

  • ✗把所有资料塞进 SKILL.md 正文

    ✓正文保持精炼，详细资料拆到附属文件按需读取

  • ✗直接安装来源不明的技能

    ✓像审查代码一样审查技能内的指令与脚本

  • ✗用自然语言描述本可用脚本完成的确定性步骤

    ✓格式转换、校验等交给附属脚本执行

☑️ 08 · 检查清单
🎤 09 · 面试追问
Skills 为什么能节省上下文？

采用渐进式披露：常驻上下文的只有每个技能的名称与描述；正文仅在任务相关时读取，附属文件和脚本更是在需要时才访问。因此可以安装很多技能而几乎不增加基础开销。

Skills 和 MCP 是什么关系？

互补。MCP 提供连接外部系统的工具与数据通道；Skills 提供如何完成某类任务的知识与流程，可以指导智能体如何组合使用这些 MCP 工具。

技能有哪些安全风险？

技能包含指令和可执行脚本，恶意技能可能诱导智能体泄露数据或执行危险命令。应只使用可信来源的技能，审查其内容与脚本，并在沙箱与权限控制下运行。
