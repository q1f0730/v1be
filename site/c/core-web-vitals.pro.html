网页核心指标 (LCP / INP / CLS)

Core Web Vitals

📐 01 · 定义

Core Web Vitals 是 Google 定义的一组衡量真实用户体验的网页指标，当前为 LCP（加载）、INP（交互响应）和 CLS（视觉稳定）。它属于前端性能与可观测层，以真实用户数据（字段数据）的第 75 百分位评估，是 Google 搜索页面体验信号的一部分。INP 于 2024 年 3 月取代 FID。

⚙️ 02 · 原理
  1. 1

    LCP（Largest Contentful Paint）测量视口内最大图片或文本块渲染完成的时间，良好阈值为 2.5 秒以内。

  2. 2

    INP（Interaction to Next Paint）观察页面生命周期内的点击、触摸、按键交互，取接近最差的交互到下一帧绘制的延迟，良好为 200 毫秒以内。

  3. 3

    CLS（Cumulative Layout Shift）累计意外布局偏移得分，取会话窗口中最大的一段，良好为 0.1 以内。

  4. 4

    评估以页面访问的第 75 百分位为准，区分移动端和桌面端分别统计。

  5. 5

    数据来源分字段数据（CrUX、RUM 埋点）与实验室数据（Lighthouse），排名与诊断以字段数据为准。

🔤 03 · 术语
LCP (Largest Contentful Paint)
最大内容元素渲染完成时间，衡量感知加载速度。
INP (Interaction to Next Paint)
交互到下一次绘制的延迟，衡量整体响应性。
CLS (Cumulative Layout Shift)
意外布局偏移的累计得分，衡量视觉稳定性。
CrUX (Chrome UX Report)
Chrome 真实用户体验数据集，PageSpeed Insights 字段数据来源。
长任务 (Long Task)
主线程上超过 50 毫秒的任务，是 INP 变差的常见原因。
💻 04 · 代码
用 web-vitals 采集真实数据javascript
import { onLCP, onINP, onCLS } from "web-vitals";

// 把指标发送到自己的分析端点
function send(metric) {
  const body = JSON.stringify({
    name: metric.name,        // "LCP" | "INP" | "CLS"
    value: metric.value,      // LCP/INP 为毫秒，CLS 无单位
    rating: metric.rating,    // "good" | "needs-improvement" | "poor"
    id: metric.id,
    page: location.pathname,
  });
  // 页面关闭时也能可靠发送
  navigator.sendBeacon("/analytics/vitals", body);
}

onLCP(send);
onINP(send);
onCLS(send);

web-vitals 是 Google 维护的库；字段数据比本地 Lighthouse 分数更能反映真实体验。

⚖️ 06 · 方案取舍

实验室测试（Lighthouse）

优点可复现、适合 CI 回归

代价不代表真实设备与网络，测不了真实交互

适用开发阶段与 PR 检查

字段数据（CrUX / RUM）

优点反映真实用户

代价有延迟，需流量积累

适用评估效果与 SEO

两者结合

优点既能定位又能验证

代价需要维护埋点与看板

适用成熟产品

🕳️ 07 · 常见坑

  • ✗只盯 Lighthouse 分数，忽略真实用户数据

    ✓以 CrUX/RUM 的 P75 为准，Lighthouse 用于诊断

  • ✗LCP 图片懒加载或低优先级

    ✓首屏主图不要 loading=lazy，可加 fetchpriority=high

  • ✗图片、广告、嵌入未预留尺寸

    ✓设置 width/height 或 aspect-ratio，动态内容预留空间

  • ✗事件处理里执行大量同步计算

    ✓拆分长任务、让出主线程，重计算放 Web Worker

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么 INP 替代了 FID？

FID 只测首次交互的输入延迟，不含处理与渲染时间；INP 覆盖整个访问期间所有交互、包含输入延迟+处理时间+呈现延迟，更能反映真实响应性。

LCP 慢如何拆解排查？

可拆为 TTFB、资源加载延迟、资源加载时长、元素渲染延迟四段。对症处理：优化服务器与 CDN、尽早发现 LCP 资源（preload）、压缩图片、减少阻塞渲染的 JS/CSS。

CLS 为什么不是整个页面生命周期的总和？

早期定义会随页面停留时间不断累积，对长会话不公平；现在把偏移分组为会话窗口（间隔小于 1 秒、窗口最长 5 秒），取最大窗口得分。
