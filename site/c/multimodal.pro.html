多模态

Multimodal

📐 01 · 定义

多模态（Multimodal）指模型能处理文本以外的输入或输出，如图像、音频、视频、PDF。常见实现是把图像等编码成与文本 Token 同一表示空间的向量，再由语言模型统一推理。对开发者而言，多模态让截图调试、设计稿转代码、文档解析等任务可以直接交给模型。

⚙️ 02 · 原理
  1. 1

    编码：图像经视觉编码器（如 ViT）切成小块并转成向量序列。

  2. 2

    对齐：通过投影层把视觉向量映射到语言模型的嵌入空间，与文本 Token 拼接。

  3. 3

    联合推理：语言模型对图文混合序列做注意力计算，回答与图像相关的问题。

  4. 4

    计费折算：图片按分辨率折算成一定数量的输入 Token，大图会被缩放。

  5. 5

    多模态输出：部分模型还能生成图像或语音，通常由专门的生成模型或解码器完成。

🔤 03 · 术语
视觉编码器 (Vision Encoder)
把图像转换为向量表示的网络，如 ViT。
ViT (Vision Transformer)
把图像切成固定大小块，当作序列输入 Transformer。
图文对齐 (Vision-Language Alignment)
让图像表示和文字表示处于同一语义空间。
OCR
光学字符识别，从图像中提取文字；多模态模型可部分替代。
Base64
把二进制文件编码成文本，API 常用它传图片数据。
💻 04 · 代码
让模型看一张截图python
import anthropic, base64

client = anthropic.Anthropic()

with open("error.png", "rb") as f:            # 本地截图
    img_b64 = base64.standard_b64encode(f.read()).decode()

resp = client.messages.create(
    model="claude-sonnet-4-5",
    max_tokens=800,
    messages=[{
        "role": "user",
        "content": [
            {"type": "image",
             "source": {"type": "base64", "media_type": "image/png", "data": img_b64}},
            {"type": "text", "text": "这是页面报错截图，指出原因并给出修复步骤。"},
        ],
    }],
)
print(resp.content[0].text)

一条消息的 content 可以是图片块和文本块的数组，图文一起作为输入。

📊 05 · 参数对比

常见多模态输入与要点

输入类型典型用途工程要点
截图/照片UI 报错、设计稿转代码裁剪到关键区域，保证文字清晰
PDF合同、论文、报表解析注意页数限制和按页计费
图表读取趋势和数值精确数值仍应以原始数据为准

⚖️ 06 · 方案取舍

直接发截图

优点保留布局与视觉信息

代价Token 更多，小字可能识别错

适用UI 问题、视觉布局相关

复制文本发送

优点精确、省 Token

代价丢失视觉上下文

适用报错日志、代码、长文本

截图 + 文本一起

优点互相印证，信息最全

代价成本最高

适用复杂前端 bug

🕳️ 07 · 常见坑

  • ✗用超大分辨率全屏截图，关键信息很小

    ✓裁剪到相关区域，必要时放大局部

  • ✗让模型从图表里读精确数字用于计算

    ✓精确值从源数据获取，图像只用于理解趋势

  • ✗截图中包含密钥、个人信息直接上传

    ✓上传前打码敏感区域

☑️ 08 · 检查清单
🎤 09 · 面试追问
多模态模型如何「看懂」图片？

视觉编码器把图像分块编码为向量，经投影层映射到语言模型的嵌入空间，与文本 Token 拼成一个序列；语言模型通过注意力在图文之间建立关联，从而回答与图像相关的问题。训练依赖大量图文配对数据。

设计稿转代码的局限在哪？

模型能还原大致布局和样式，但像素级间距、响应式断点、交互状态和设计系统约束常不准确。实践上配合设计 Token 规范、组件库说明、分区域生成，并用浏览器截图对比迭代。

多模态的成本怎么估算？

图片按尺寸折算为输入 Token，各家公式不同，大图通常先被缩放到上限；PDF 往往按页同时计算文字和图像。以官方文档公式估算，或用响应中的 usage 字段实测。
