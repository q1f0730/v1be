📐 01 · 定义

开发 / 测试 / 生产环境（Dev / Test / Prod）是把软件运行环境按用途隔离的实践：开发环境供编码调试，测试或预发环境（Staging）用于集成验证，生产环境服务真实用户。它属于交付与运维层，核心原则是同一份代码与制品流经各环境，只通过配置区分，同时让环境尽量一致。

⚙️ 02 · 原理
  1. 1

    代码在本地开发环境编写与调试，连接本地或共享的开发数据库与模拟服务。

  2. 2

    合并后部署到测试环境运行集成测试和端到端测试，使用测试数据。

  3. 3

    预发环境尽量复刻生产的配置、数据规模和依赖版本，用于上线前最终验证。

  4. 4

    通过同一制品晋升到生产，环境差异仅由环境变量、密钥和资源规格体现。

  5. 5

    各环境的账号、数据库、密钥和权限相互隔离，防止测试操作影响生产数据。

🔤 03 · 术语
预发环境 (Staging)
与生产配置接近的最后验证环境。
环境一致性 (Dev/Prod Parity)
十二要素应用原则之一，缩小各环境之间的差异。
环境变量 (Environment Variable)
按环境注入配置的常用方式，与代码分离。
预览环境 (Preview Environment)
为每个 PR 自动创建的临时环境。
制品晋升 (Promotion)
同一制品从测试环境逐级发布到生产。
💻 04 · 代码
按环境加载配置bash
# 目录中按环境区分配置文件（不提交真实密钥）
# .env.development   本地开发
# .env.test          测试
# .env.production    生产（真实值由部署平台注入）

# .env.development 示例
DATABASE_URL=postgres://dev:dev@localhost:5432/app_dev
PAYMENT_API=https://sandbox.payment.example.com
LOG_LEVEL=debug

# Vite 按 mode 选择 .env.[mode] 文件
npx vite build --mode staging      # 读取 .env.staging

# Node.js 20.6+ 内置读取 env 文件
node --env-file=.env.development server.js

同一代码按环境读取不同配置；生产密钥不进仓库，由平台注入。

📊 05 · 参数对比

三类环境对比

环境数据访问者变更频率
开发模拟或脱敏数据开发者本人随时
测试/预发测试数据，接近生产规模团队、测试每次合并
生产真实用户数据真实用户受控发布
⚖️ 06 · 方案取舍

完整三套环境

优点风险隔离充分

代价成本和维护量高

适用有真实用户和收入的产品

每 PR 预览环境

优点并行验证，反馈快

代价需要自动化基础设施

适用前端或可容器化的服务

只有开发与生产

优点简单便宜

代价问题直接暴露给用户

适用个人项目、早期原型

🕳️ 07 · 常见坑

  • ✗测试环境直连生产数据库

    ✓环境间数据库与凭证完全隔离

  • ✗把生产数据原样复制到测试环境

    ✓使用脱敏或合成数据，遵守隐私法规

  • ✗预发与生产依赖版本、配置差异大

    ✓用同一镜像和基础设施代码，只改变量

  • ✗AI Agent 本地会话加载了生产 .env

    ✓本地只放开发凭证，生产密钥仅存于部署平台

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么强调各环境用同一个制品？

如果每个环境单独构建，依赖、编译选项、构建机环境都可能不同，测试通过的不一定是上线的那个版本。同一制品只换配置，能确保验证对象与上线对象完全一致，回滚也只需切换版本。

预发环境发现不了的问题有哪些？

真实流量规模与访问模式、生产数据的长尾异常、第三方服务的真实限流与行为、跨区域网络问题等。因此还需要金丝雀发布、特性开关和完善的生产监控，作为预发之后的防线。

特性开关和多环境是什么关系？

多环境在部署层隔离版本，特性开关在运行时控制功能是否对某些用户生效。两者互补：代码可以先部署到生产但默认关闭，再通过开关逐步放量，从而把部署与发布解耦。
