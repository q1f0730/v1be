威胁建模

Threat Modeling

📐 01 · 定义

威胁建模（Threat Modeling）是在设计阶段系统性识别安全威胁的结构化方法：画出系统的数据流和信任边界，按 STRIDE 等框架逐项分析攻击者可能做什么，评估风险并确定缓解措施。它把安全前移到写代码之前，比上线后修补成本低得多。

⚙️ 02 · 原理
  1. 1

    明确范围：我们在构建什么？画数据流图，标出组件、数据存储、外部实体。

  2. 2

    标信任边界：用户与服务、服务与第三方、内网与公网之间的权限与信任变化处。

  3. 3

    识别威胁：在每条跨边界的数据流上，按 STRIDE 六类逐项提问可能出什么问题。

  4. 4

    评估与缓解：按可能性和影响排序，为每个威胁确定缓解、接受、转移或规避。

  5. 5

    验证与迭代：缓解措施落到任务和测试中；架构变化时更新模型并复审。

🔤 03 · 术语
STRIDE
仿冒、篡改、抵赖、信息泄露、拒绝服务、权限提升六类威胁。
数据流图 (DFD)
用进程、数据存储、外部实体和数据流描述系统的图。
信任边界 (Trust Boundary)
数据或调用跨越不同信任级别的分界线。
攻击面 (Attack Surface)
攻击者可以接触和尝试利用的所有入口集合。
攻击树 (Attack Tree)
把攻击目标逐层分解为子目标与手段的树状模型。
💻 04 · 代码
威胁登记表示例yaml
# threats.yaml：随设计文档一起入库、一起评审
system: 文件分享服务
boundaries:
  - 浏览器 -> API 网关（公网）
  - API -> 对象存储（内网）
threats:
  - id: T1
    stride: Spoofing
    flow: 浏览器 -> API
    desc: 攻击者重放窃取的会话令牌
    mitigation: 短期令牌 + HttpOnly/Secure Cookie + 绑定刷新令牌
    status: planned
  - id: T2
    stride: Information disclosure
    flow: API -> 对象存储
    desc: 可猜测的文件 URL 导致越权下载
    mitigation: 短时效签名 URL，按用户校验所有权
    status: done
  - id: T3
    stride: Denial of service
    flow: 浏览器 -> API
    desc: 超大文件上传耗尽存储与带宽
    mitigation: 大小上限、配额、按用户限流
    status: accepted-risk

每条威胁对应数据流、STRIDE 类别、缓解与状态，可追踪到任务。

📊 05 · 参数对比

STRIDE 与安全属性

威胁破坏的属性典型缓解
仿冒 Spoofing身份认证MFA、强会话管理
篡改 Tampering完整性签名、校验、最小写权限
抵赖 Repudiation不可抵赖性审计日志、防篡改日志
信息泄露 Info Disclosure机密性加密、访问控制
权限提升 Elevation授权最小权限、服务端鉴权
⚖️ 06 · 方案取舍

STRIDE 逐项分析

优点系统全面，易教易推广

代价组件多时工作量大，易流于形式

适用新系统或重大架构变更

攻击树

优点聚焦高价值目标，深入具体路径

代价依赖分析者经验，覆盖面窄

适用关键资产、支付等高风险点

轻量问答式评审

优点成本低，可纳入每次设计评审

代价深度有限

适用日常功能迭代

🕳️ 07 · 常见坑

  • ✗系统上线后才做威胁建模，只能补丁式修复

    ✓在设计评审阶段完成，并作为开工前置条件

  • ✗做一次就归档，架构变了模型没更新

    ✓新增外部依赖、数据流或权限时触发复审

  • ✗列出一堆威胁但没有负责人和跟踪

    ✓每条威胁转成工单，有缓解状态与验收测试

  • ✗只关注外部攻击者，忽略内部人员与供应链

    ✓把内部角色、CI/CD、第三方依赖也画进数据流

🎤 09 · 面试追问
威胁建模的四个核心问题是什么？

我们在构建什么？可能出什么问题？我们打算怎么应对？我们做得够好吗？对应画模型、识别威胁、确定缓解、验证复盘四步，是 Shostack 等人推广的通用框架，与具体方法无关。

为 LLM Agent 应用做威胁建模要额外注意什么？

把模型视为不可信组件：外部内容可能携带提示注入；工具调用是新的权限提升路径；输出可能泄露上下文中的敏感数据。重点画出模型可调用的工具和可读取的数据，以及不可信输入的来源。

如何避免威胁建模流于形式？

限定范围、按变更触发而非按周期；用模板和检查清单降低门槛；产出必须落为可跟踪的工单和测试；邀请开发、运维、安全共同参与，让一线工程师成为主要建模者。
