请求体大小限制

Request Size Limits

📐 01 · 定义

请求体大小限制（Request Size Limits）是在反向代理、网关和应用框架中对单个 HTTP 请求的 body、头部或上传文件设置上限的防护措施。它属于入口防护层，防止超大请求耗尽内存、带宽和磁盘，抵御资源耗尽型拒绝服务，同时约束业务合理的上传规模。

⚙️ 02 · 原理
  1. 1

    请求先经过 CDN 或负载均衡，这一层可能有自己的上限，超出直接拒绝。

  2. 2

    反向代理检查 Content-Length 或累计已读字节，超过配置值返回 413 Content Too Large。

  3. 3

    应用框架的 body 解析中间件再设一层上限，在解析 JSON 或表单前截断。

  4. 4

    大文件不经应用服务器，改由客户端用预签名 URL 直传对象存储，并在签名中限制大小。

  5. 5

    头部、URL 长度、字段个数和 JSON 嵌套深度也需要单独限制，防止解析层被拖垮。

🔤 03 · 术语
413 Content Too Large
RFC 9110 定义，请求体超出服务器愿意处理的大小。
client_max_body_size
Nginx 限制请求体大小的指令，默认 1m。
分块传输 (Chunked Encoding)
无 Content-Length 的流式传输，需边读边计数。
预签名 URL (Presigned URL)
带签名与过期时间的临时上传/下载地址。
资源耗尽攻击
通过超大或大量请求耗尽内存、CPU 或连接。
💻 04 · 代码
Nginx 与 Express 分层限制text
# ---- Nginx：全局较小，上传接口单独放宽 ----
http {
    client_max_body_size 1m;            # 默认值即 1m
    large_client_header_buffers 4 8k;   # 限制请求头
    server {
        location /api/upload {
            client_max_body_size 20m;   # 仅上传接口放宽
        }
    }
}

// ---- Express：应用层再限制一次 ----
const express = require("express");
const app = express();
app.use(express.json({ limit: "100kb" }));    // 默认即 100kb
app.use(express.urlencoded({ limit: "100kb", extended: false }));
app.use((err, req, res, next) => {
  if (err.type === "entity.too.large") return res.status(413).end();
  next(err);
});

代理层和应用层各设上限，全局收紧、按接口放宽；超限统一返回 413。

⚖️ 06 · 方案取舍

代理层统一限制

优点在进入应用前拒绝，最省资源

代价粒度粗，错误信息不友好

适用所有服务的第一道防线

应用层按接口限制

优点可按业务精细控制并返回明确错误

代价请求已占用连接和部分资源

适用不同接口上限差异大

直传对象存储

优点大文件不经应用，扩展性好

代价需签名、回调与校验流程

适用图片、视频等大文件上传

🕳️ 07 · 常见坑

  • ✗只在前端校验文件大小

    ✓服务端和代理层必须强制限制，前端只做体验提示

  • ✗整体放大全局上限以支持一个上传接口

    ✓全局保持小值，仅对上传路由单独放宽

  • ✗只看 Content-Length，忽略分块传输

    ✓边读边计数，超限立即中断读取

  • ✗忽略解压后的大小，被压缩炸弹打爆内存

    ✓对解压后数据也设上限，流式处理

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么要多层都设大小限制？

纵深防御：CDN 和代理在最外层低成本拒绝超大请求；应用层根据接口语义精细控制并返回业务错误；任何一层配置遗漏都不会让请求直接打到内存。各层值需协调，避免外层过小导致内层配置无效。

上传 1GB 文件怎么设计？

服务端签发限定大小、类型和有效期的预签名 URL，客户端直传对象存储，大文件用分片上传；完成后通过回调或事件通知应用校验并入库，应用服务器不承载文件流量。

什么是压缩炸弹？

很小的压缩数据解压后膨胀成极大内容，耗尽内存或磁盘。若服务端接受压缩请求体或解压上传文件，必须限制解压后大小和压缩比，并以流式方式处理。
