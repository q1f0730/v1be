智能体钩子 (Hooks)

Agent Hooks

🧸 回到小白版

📐 01 · 定义

智能体钩子（Agent Hooks）是编程 Agent 在生命周期特定节点（如工具调用前后、会话开始、任务结束）自动执行的用户自定义命令。与写在提示词里的“软约束”不同，钩子由运行时确定性地执行，可阻止危险操作、改文件后自动格式化、注入上下文。Claude Code、Cursor 等均提供（细节以官方文档为准）。

⚙️ 02 · 原理
  1. 1

    在配置文件（如 Claude Code 的 .claude/settings.json）中为事件注册钩子，并可用 matcher 匹配特定工具名。

  2. 2

    Agent 准备调用工具时触发 PreToolUse 类事件，运行时把工具名与参数以 JSON 通过标准输入传给钩子命令。

  3. 3

    钩子返回决定：以 Claude Code 为例，退出码 0 表示放行，退出码 2 表示阻止并把 stderr 反馈给模型；也可输出 JSON 精细控制。

  4. 4

    工具执行成功后触发 PostToolUse 类事件，常用于对刚改动的文件运行格式化、lint 或测试。

  5. 5

    其他事件如 UserPromptSubmit、SessionStart、Stop 可用于注入上下文、校验提示或在任务结束时做检查与通知。

🔤 03 · 术语
PreToolUse
工具调用前触发，可放行、拒绝或要求确认。
PostToolUse
工具调用成功后触发，常用于格式化与校验。
matcher
按工具名匹配钩子适用范围，如 Bash、Edit|Write。
退出码 2 (Exit Code 2)
Claude Code 约定的阻止信号，stderr 会反馈给模型。
确定性控制 (Deterministic Control)
不依赖模型自觉、由程序保证执行的约束。
💻 04 · 代码
拦截危险命令的 PreToolUse 钩子python
#!/usr/bin/env python3
# .claude/hooks/block_dangerous.py  （需 chmod +x）
# 在 .claude/settings.json 中注册（格式以官方文档为准）：
# {"hooks": {"PreToolUse": [{"matcher": "Bash",
#   "hooks": [{"type": "command",
#              "command": ".claude/hooks/block_dangerous.py"}]}]}}
import json, re, sys

event = json.load(sys.stdin)                    # 运行时通过 stdin 传入 JSON
cmd = event.get("tool_input", {}).get("command", "")

RULES = [
    (r"\brm\s+-rf\s+(/|~|\*)", "禁止递归删除根目录、家目录或通配"),
    (r"git\s+push\b.*\b(main|master)\b", "禁止直接推送主分支，请提 PR"),
    (r"--no-verify", "禁止跳过 Git 钩子"),
]
for pattern, reason in RULES:
    if re.search(pattern, cmd):
        print(f"已拦截：{reason}", file=sys.stderr)  # 反馈给模型
        sys.exit(2)                              # 退出码 2 = 阻止该工具调用
sys.exit(0)                                      # 放行

钩子读取工具参数并按规则阻止；正则黑名单只是示例，生产中应结合权限白名单使用。

📊 05 · 参数对比

常见钩子事件与用途（以 Claude Code 为例）

事件触发时机典型用途
PreToolUse工具调用前拦截危险命令、保护敏感文件
PostToolUse工具调用成功后格式化、lint、运行相关测试
UserPromptSubmit用户提交提示时注入上下文、过滤敏感信息
SessionStart会话开始时加载项目状态、环境信息
StopAgent 结束回复时检查任务完成度、发送通知
⚖️ 06 · 方案取舍

钩子强制执行

优点确定性，模型无法绕过

代价需编写维护脚本，规则过严会妨碍工作

适用安全底线、格式规范

提示词/规则文件约束

优点编写简单、灵活

代价模型可能忽略

适用风格偏好、一般建议

权限白名单配置

优点声明式、易审计

代价粒度有限

适用控制可用工具与命令范围

🕳️ 07 · 常见坑

  • ✗只靠正则黑名单防危险命令

    ✓黑名单易被变形绕过，应结合权限白名单与沙箱

  • ✗PostToolUse 钩子运行全量测试，每次改文件等很久

    ✓只针对改动文件运行快速检查，全量测试放到 Stop 或 CI

  • ✗钩子脚本出错时静默放行或卡死

    ✓处理异常并设置超时，失败时给出明确信息

  • ✗使用来源不明的钩子配置

    ✓钩子以用户权限执行任意命令，配置需代码审查

☑️ 08 · 检查清单
🎤 09 · 面试追问
钩子和提示词里的规则有什么本质区别？

提示词规则是对模型的请求，模型可能误解、遗忘或在压力下忽略；钩子是运行时在固定事件上执行的程序，结果由退出码或返回值决定，模型无法绕过。硬性约束应放在钩子或权限配置里，提示词用于表达偏好与背景。

钩子会带来哪些安全风险？

钩子以当前用户权限自动执行任意命令，恶意或有缺陷的配置可能泄露数据或破坏文件。因此要审查钩子来源、把配置纳入版本控制、避免执行不可信输入拼接的命令，并注意项目级配置可能被他人提交修改。

PostToolUse 钩子如何提升 Agent 的代码质量？

每次编辑后自动运行格式化、类型检查或相关测试，并把错误反馈给模型，让 Agent 立即修复，而不是等到最后才发现。这把“写完再检查”变成持续的快速反馈循环，减少人工返工。
