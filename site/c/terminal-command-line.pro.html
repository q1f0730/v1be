终端 / 命令行

Terminal / Command Line

📐 01 · 定义

终端（Terminal）是文本输入输出的窗口程序，Shell（如 bash、zsh、PowerShell）是在其中解释命令的程序，二者合称命令行界面（CLI）。命令行可组合、可脚本化、可远程，是安装依赖、运行项目、操作 Git、部署服务器的标准方式，也是 Claude Code 等终端 Agent 的工作环境。

⚙️ 02 · 原理
  1. 1

    读取输入：Shell 显示提示符（如 $ 或 %），读取用户输入的一行命令文本。

  2. 2

    解析展开：拆分命令与参数，展开变量（$HOME）、通配符（*.js）和 ~ 等。

  3. 3

    查找程序：内置命令直接执行，其他命令按 PATH 环境变量中的目录顺序查找可执行文件。

  4. 4

    创建进程：启动子进程运行程序，连接标准输入、标准输出和标准错误三个流。

  5. 5

    返回状态：程序结束返回退出码，0 表示成功，非 0 表示失败，供脚本判断。

🔤 03 · 术语
Shell
解释并执行命令的程序，如 bash、zsh、fish、PowerShell。
PATH
存放可执行文件搜索目录的环境变量，决定输入命令能否被找到。
标准流 (stdin/stdout/stderr)
程序的标准输入、正常输出和错误输出通道。
管道 (Pipe)
用「|」把前一命令的输出作为后一命令的输入。
退出码 (Exit Code)
程序结束状态，0 为成功，可用 echo $? 查看。
💻 04 · 代码
常用组合命令bash
pwd                          # 当前所在目录
ls -la                       # 列出文件（含隐藏文件）
cd ~/projects/my-app         # 进入项目目录

which node                   # 查看命令实际来自哪个路径
echo $PATH                   # 查看命令搜索路径

# 管道：统计 src 下 .ts 文件数量
find src -name "*.ts" | wc -l

# 在代码里搜索关键字（带行号）
grep -rn "TODO" src/

# 重定向：正常输出写文件，错误输出单独写
npm run build > build.log 2> build.err

# && 前一步成功才执行下一步
npm install && npm test
echo "exit code: $?"         # 上一条命令的退出码

管道、重定向、退出码和 && 是命令行可组合性的核心，也是脚本和 CI 的基础。

Shell 对比

Shell常见平台特点
bash多数 Linux 默认脚本最通用，兼容性好
zshmacOS 默认（自 Catalina 起）补全与插件生态丰富，兼容大部分 bash 语法

🕳️ 07 · 常见坑

  • ✗复制网上的 rm -rf 或 curl | sh 命令直接运行

    ✓先读懂每个参数，确认来源可信再执行

  • ✗装了工具却提示 command not found

    ✓检查安装目录是否在 PATH 中，重开终端或 source 配置文件

  • ✗在 PowerShell 里照抄 bash 语法

    ✓确认当前 Shell 类型，或在 WSL/Git Bash 中执行

  • ✗脚本出错后继续往下执行

    ✓bash 脚本开头加 set -euo pipefail

🎤 09 · 面试追问
终端、Shell、控制台有什么区别？

终端是显示和输入文本的程序（如 iTerm2、Windows Terminal）；Shell 是解释命令的程序（bash、zsh）；控制台原指物理设备，现常与终端混用。一个终端窗口里运行一个 Shell 进程。

为什么 AI 编程 Agent 偏爱命令行？

命令行是纯文本接口，输入输出都能被模型直接读写；工具可组合、结果有退出码便于判断成败；几乎所有开发工具都提供 CLI。图形界面则需要截图识别与坐标操作，更慢更不可靠。

stdout 和 stderr 为什么要分开？

让正常结果与错误信息互不干扰：管道默认只传 stdout，错误仍显示在屏幕上；可以分别重定向到不同文件。脚本和 CI 依靠这一点把数据流和诊断信息分开处理。
