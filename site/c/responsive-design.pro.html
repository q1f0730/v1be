响应式设计

Responsive Design

📐 01 · 定义

响应式设计（Responsive Web Design）是让同一份 HTML/CSS 根据视口尺寸、像素密度和输入方式自适应布局的做法，核心手段是流式布局、弹性媒体与媒体查询。它属于前端表现层，取代了维护独立移动站的方案；移动端体验也是搜索引擎评估页面的重要因素。

⚙️ 02 · 原理
  1. 1

    通过 viewport meta 标签让移动浏览器按设备宽度渲染，而不是按桌面宽度缩小显示。

  2. 2

    布局使用 Flexbox、Grid 与相对单位（%、rem、fr），让元素随容器伸缩。

  3. 3

    媒体查询在断点处切换布局；移动优先写法先写小屏样式，再用 min-width 逐级增强。

  4. 4

    图片用 max-width:100%、srcset/sizes 或 picture 按屏幕提供合适尺寸，避免溢出与浪费流量。

  5. 5

    容器查询（@container）让组件依据自身容器宽度而非整个视口调整，更适合组件化开发。

🔤 03 · 术语
视口 (Viewport)
浏览器中显示页面的可视区域，移动端需 meta 标签设定。
断点 (Breakpoint)
布局发生切换的宽度阈值，应依据内容而非具体机型。
移动优先 (Mobile First)
默认写小屏样式，用 min-width 媒体查询向大屏增强。
容器查询 (Container Query)
按父容器尺寸应用样式，组件可在不同位置自适应。
clamp()
CSS 函数，在最小值与最大值间按视口流式取值，常用于字号。
💻 04 · 代码
移动优先的 HTML + CSStext
<!-- HTML：没有这一行，手机会按桌面宽度缩放显示 -->
<meta name="viewport" content="width=device-width, initial-scale=1">

/* CSS：默认是手机单列 */
.grid { display: grid; gap: 1rem; grid-template-columns: 1fr; }
img { max-width: 100%; height: auto; }
h1 { font-size: clamp(1.5rem, 4vw, 2.5rem); } /* 流式字号 */

/* 平板及以上：两列 */
@media (min-width: 640px) {
  .grid { grid-template-columns: repeat(2, 1fr); }
}
/* 桌面：三列 */
@media (min-width: 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

/* 组件按自身容器宽度调整 */
.card-wrap { container-type: inline-size; }
@container (min-width: 400px) {
  .card { display: flex; }
}

viewport 标签 + 流式网格 + min-width 断点是骨架；容器查询处理组件级自适应。

⚖️ 06 · 方案取舍

单一响应式站点

优点一套代码、URL 统一、利于 SEO

代价样式复杂度上升

适用绝大多数网站

独立移动站 (m. 站)

优点可为移动端深度定制

代价两套维护，需处理跳转与重复内容

适用历史遗留或极端差异需求

原生 App

优点体验与设备能力最好

代价开发与发布成本高

适用高频重度使用场景

🕳️ 07 · 常见坑

  • ✗按具体机型设置断点

    ✓依据内容何时「挤坏」设置断点，并用 rem 等相对单位

  • ✗只在开发者工具模拟，不测真机

    ✓至少在一台 iOS 与一台 Android 真机上检查触控与字体

  • ✗固定宽度元素或长链接撑破布局导致横向滚动

    ✓设置 max-width、min-width:0 与 overflow-wrap 处理长文本

  • ✗用 hover 承载关键交互

    ✓触屏无 hover，关键操作需可点击，可用 @media (hover: hover) 区分

🎤 09 · 面试追问
移动优先和桌面优先在 CSS 上有什么区别？

移动优先默认写小屏样式，用 min-width 媒体查询叠加大屏规则，小屏设备加载的覆盖样式更少、心智上从简到繁；桌面优先用 max-width 向下覆盖，容易积累大量重置规则。

容器查询解决了媒体查询的什么问题？

媒体查询只看视口，同一组件放在侧栏和主区时宽度不同却拿到相同样式；容器查询让组件依据父容器尺寸调整，组件真正可移植，更契合组件化设计系统。

响应式图片如何兼顾清晰与流量？

用 srcset 提供多种宽度并配 sizes 告诉浏览器显示尺寸，由浏览器按像素密度选择；需要不同裁切时用 picture 的 source 媒体条件；配合 loading=lazy 和现代格式（WebP/AVIF）。
