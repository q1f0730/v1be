优雅停机机制

Graceful Shutdown

📐 01 · 定义

优雅停机（Graceful Shutdown）是进程收到终止信号后，停止接收新工作、完成或妥善移交在途工作、释放资源再退出的过程。它位于应用与编排平台的生命周期契约层：Kubernetes、systemd、容器运行时先发 SIGTERM，等待宽限期后才发 SIGKILL。做好它是零停机发布和自动扩缩容不丢请求的前提。

⚙️ 02 · 原理
  1. 1

    平台决定终止实例，向主进程发送 SIGTERM，并开始计时宽限期，Kubernetes 默认 30 秒。

  2. 2

    应用捕获信号后先把自身标记为未就绪，让负载均衡器停止发来新请求。

  3. 3

    停止接受新连接和新任务，消费者停止拉取消息，定时任务不再调度。

  4. 4

    等待在途请求和任务处理完成，或在超时之前把未完成的任务退回队列。

  5. 5

    关闭数据库连接池、刷新日志和指标缓冲后退出；超时未退出将被 SIGKILL 强杀。

🔤 03 · 术语
SIGTERM
请求进程终止的可捕获信号，优雅停机的起点。
SIGKILL
不可捕获的强制终止信号，宽限期到后发送。
宽限期 (terminationGracePeriodSeconds)
Kubernetes 从发 SIGTERM 到强杀的时间，默认 30 秒。
preStop 钩子 (preStop Hook)
容器终止前执行的命令或请求，常用于等待摘流。
PID 1 问题
容器中 PID 1 进程不转发信号或无默认处理，导致应用收不到 SIGTERM。
💻 04 · 代码
Node.js 处理 SIGTERMjavascript
const http = require("node:http");

let shuttingDown = false;
const server = http.createServer((req, res) => {
  if (req.url === "/readyz") {
    res.writeHead(shuttingDown ? 503 : 200).end();  // 停机时就绪失败
    return;
  }
  setTimeout(() => res.end("ok"), 200);             // 模拟业务处理
});
server.listen(8080);

process.on("SIGTERM", () => {
  shuttingDown = true;
  // 停止接新连接，等在途请求结束后回调
  server.close(() => process.exit(0));
  server.closeIdleConnections();                    // 关闭空闲 keep-alive 连接
  // 兜底：宽限期前强制退出
  setTimeout(() => process.exit(1), 25_000).unref();
});

收到 SIGTERM 后就绪失败、停止接新连接，在途请求完成再退出，并设兜底超时。

⚖️ 06 · 方案取舍

等待全部在途工作完成

优点不丢请求

代价长任务会拖长停机甚至被强杀

适用请求短、可预期

中断并退回队列

优点停机快

代价任务需幂等可重做

适用长任务、批处理

preStop 先等待再处理信号

优点覆盖摘流传播延迟

代价占用宽限期时间

适用Kubernetes 后面挂负载均衡

🕳️ 07 · 常见坑

  • ✗Dockerfile 用 shell 形式 CMD，SIGTERM 发给 sh，应用收不到。

    ✓用 exec 形式 CMD 或加 tini 等 init 进程转发信号。

  • ✗收到 SIGTERM 立即退出，正在处理的请求全部 502。

    ✓先摘流、再关监听、等在途完成后退出。

  • ✗应用清理时间比宽限期还长，总被 SIGKILL。

    ✓让应用超时小于宽限期，或调大 terminationGracePeriodSeconds。

  • ✗消息消费者停机时没归还未确认消息。

    ✓停止拉取，处理完或 nack 后再关闭连接。

🎤 09 · 面试追问
Kubernetes 删除 Pod 时发生了什么？

Pod 标记为 Terminating，同时并行地从端点中移除并执行 preStop，之后发 SIGTERM；宽限期到仍未退出则 SIGKILL。由于摘流传播与 SIGTERM 并行，常在 preStop 里等几秒，避免新请求打到正在关闭的进程。

为什么容器里经常收不到 SIGTERM？

shell 形式的 CMD 会让 /bin/sh 成为 PID 1，它默认不转发信号；PID 1 对未注册处理器的信号也不执行默认终止。解决方法是 exec 形式启动、使用 tini 或 docker run --init。

长时间任务如何优雅停机？

设计成可中断：分段提交进度或保存检查点；收到信号后停止领取新任务，当前任务在宽限期内完成，否则退回队列由其他实例接手，要求任务幂等。
