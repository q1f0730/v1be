惊群效应 / 缓存击穿

Thundering Herd

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

惊群效应（Thundering Herd）指大量等待者因同一事件被同时唤醒或同时行动，争抢有限资源，造成瞬时负载尖峰。在缓存场景中表现为热点键失效瞬间大量请求同时回源数据库，常称缓存击穿（Cache Stampede）；在操作系统、连接重建和定时任务中也存在。解决思路是合并请求、错峰和提前刷新。

⚙️ 02 · 原理
  1. 1

    大量请求依赖同一共享资源，例如一个热点缓存键或一个监听套接字。

  2. 2

    触发事件发生，例如缓存键到期、服务批量重启、整点定时器触发或网络恢复。

  3. 3

    所有等待者在同一时刻发现资源不可用并同时发起昂贵操作，如查询数据库。

  4. 4

    下游被尖峰压垮，延迟上升导致更多请求未命中，可能演变为级联故障。

  5. 5

    防护：单飞合并（single-flight）、分布式互斥锁、TTL 随机化、提前异步刷新、过期数据兜底。

🔤 03 · 术语
缓存击穿 (Cache Stampede)
热点键失效时大量并发请求同时回源。
请求合并 (Single-flight)
同一键的并发请求只放一个去加载，其余等待共享结果。
概率提前过期 (Probabilistic Early Expiration)
临近过期时按概率提前刷新，避免集中失效。
过期可用 (Stale-While-Revalidate)
先返回旧值，同时后台刷新缓存。
缓存雪崩 (Cache Avalanche)
大量键同时过期或缓存整体故障导致回源激增。
💻 04 · 代码
Redis 互斥锁防击穿python
import json, random, time
import redis

r = redis.Redis()

def get_product(pid, load_from_db):
    key, lock = f"product:{pid}", f"lock:product:{pid}"
    for _ in range(50):
        cached = r.get(key)
        if cached is not None:
            return json.loads(cached)
        # 只有抢到锁的请求去查库，锁 10 秒自动过期防死锁
        if r.set(lock, "1", nx=True, ex=10):
            try:
                data = load_from_db(pid)
                ttl = 300 + random.randint(0, 60)   # TTL 加抖动，错开过期
                r.set(key, json.dumps(data), ex=ttl)
                return data
            finally:
                r.delete(lock)
        time.sleep(0.05)                           # 没抢到锁：稍等再读缓存
    return load_from_db(pid)                       # 兜底

未命中时只放一个请求回源，其余短暂等待读缓存；TTL 加随机量防集中过期。

📊 05 · 参数对比

缓存三类问题区分

问题原因典型对策
缓存击穿单个热点键过期互斥锁、single-flight、永不过期加异步刷新
缓存雪崩大量键同时过期或缓存宕机TTL 随机化、多级缓存、限流
缓存穿透查询不存在的数据缓存空值、布隆过滤器
⚖️ 06 · 方案取舍

互斥锁回源

优点保证只有一次回源

代价等待者延迟增加，锁实现要小心

适用热点键回源代价高

返回旧值后台刷新

优点用户无感知延迟

代价短时间读到旧数据

适用可容忍短暂不一致

TTL 随机化

优点实现极简

代价无法处理单个超热键

适用大批键同时写入的场景

🕳️ 07 · 常见坑

  • ✗批量预热缓存时所有键 TTL 相同，到点一起失效。

    ✓TTL 叠加随机偏移。

  • ✗分布式锁不设过期，持锁进程挂掉后键永远无法重建。

    ✓锁带过期时间，释放时校验持有者。

  • ✗等待者忙等轮询缓存，把 Redis 打满。

    ✓限制轮询次数与间隔，或进程内 single-flight 合并。

🎤 09 · 面试追问
如何解决热点键过期导致的击穿？

三种思路：同键请求合并，进程内用 single-flight、跨进程用分布式锁，只放一个回源；逻辑过期，键不真正过期，读到过期标记时异步刷新并先返回旧值；对超热键提前定时刷新。

惊群在操作系统层面指什么？

多个进程或线程阻塞在同一事件上，如 accept 同一监听套接字，事件到来时全部被唤醒但只有一个能处理，其余白白切换上下文。Linux 通过 EPOLLEXCLUSIVE、SO_REUSEPORT 等机制缓解。

服务大规模重启后为什么会出现尖峰？

所有实例同时冷启动：缓存为空、连接池重建、客户端同时重连，请求集中回源。应对方法是滚动重启、连接重试加抖动、启动预热以及就绪探针延后接流。
