语义缓存

Semantic Caching

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

语义缓存（Semantic Caching）是面向 LLM 应用的缓存方式：把用户查询转为嵌入向量，在缓存中按向量相似度查找语义相近的历史查询，若相似度超过阈值，就直接返回其已缓存的回答，跳过模型调用。它比精确匹配缓存命中率高，可降低成本与延迟，但有误命中、跨用户泄露和过时风险；它不同于厂商的提示缓存。

⚙️ 02 · 原理
  1. 1

    收到查询后先做规范化（去空白、统一大小写），并判断是否属于可缓存类别（排除个性化、实时数据类问题）。

  2. 2

    用嵌入模型把查询编码为向量，在向量索引中做最近邻搜索。

  3. 3

    若最相似条目的相似度高于阈值（且满足元数据过滤，如语言、租户、模型版本），返回其缓存回答。

  4. 4

    未命中则调用大模型生成回答，把“查询向量 + 回答 + 元数据”写入缓存，并设置 TTL。

  5. 5

    持续监控命中率与误命中，抽样人工评估，按业务调节阈值与可缓存范围。

🔤 03 · 术语
相似度阈值 (Similarity Threshold)
判定命中的最低相似度，过低会误命中。
余弦相似度 (Cosine Similarity)
比较两个向量方向的指标，常用于语义相似度。
误命中 (False Hit)
语义相近但意图不同的查询被错误复用回答。
提示缓存 (Prompt Caching)
厂商复用相同前缀的计算结果，输出仍由模型实时生成。
缓存分区 (Cache Partitioning)
按用户、租户或场景隔离缓存，防止数据串用。
💻 04 · 代码
最小语义缓存实现python
import numpy as np
from openai import OpenAI

client = OpenAI()
EMB_MODEL = "text-embedding-3-small"   # 以官方文档为准
THRESHOLD = 0.95                      # 需按业务评测调整
cache: list[tuple[np.ndarray, str]] = []  # 生产中用向量数据库并设 TTL

def embed(text: str) -> np.ndarray:
    v = client.embeddings.create(model=EMB_MODEL, input=text).data[0].embedding
    v = np.array(v)
    return v / np.linalg.norm(v)          # 归一化后点积即余弦相似度

def answer(question: str, call_llm) -> str:
    q = embed(question)
    if cache:
        sims = [float(q @ v) for v, _ in cache]
        best = int(np.argmax(sims))
        if sims[best] >= THRESHOLD:       # 命中：直接复用
            return cache[best][1]
    reply = call_llm(question)            # 未命中：调用模型
    cache.append((q, reply))
    return reply

演示嵌入—相似度—阈值判定的核心流程；生产中需向量索引、TTL、按租户隔离与可缓存性判断。

📊 05 · 参数对比

三种缓存对比

类型匹配方式缓存内容主要风险
精确匹配缓存查询字符串完全相同最终回答命中率低
语义缓存嵌入相似度超过阈值最终回答误命中、跨用户泄露
提示缓存（厂商侧）提示前缀完全相同中间计算（KV）几乎无正确性风险，只省成本与延迟
⚖️ 06 · 方案取舍

高阈值语义缓存

优点误命中少

代价命中率有限

适用通用客服、FAQ 类问答

低阈值语义缓存

优点命中率高、更省钱

代价答非所问风险上升

适用只适合低风险、答案高度一致的场景

只用精确缓存 + 提示缓存

优点零正确性风险

代价节省有限

适用回答高度个性化或要求严格准确

🕳️ 07 · 常见坑

  • ✗缓存涉及个人数据或订单状态的回答，返回给其他用户

    ✓排除个性化问题，或按用户/租户分区缓存

  • ✗阈值凭感觉设定

    ✓用标注的相似/不相似查询对评测，选择误命中可接受的阈值

  • ✗模型或提示词升级后仍复用旧回答

    ✓把模型与提示词版本写入元数据，变更时失效旧缓存

  • ✗忽视时效性，过期政策仍被复用

    ✓设置 TTL，知识更新时清除相关缓存

☑️ 08 · 检查清单
🎤 09 · 面试追问
语义缓存和厂商的 Prompt Caching 有何不同？

语义缓存在应用层运行，命中时完全跳过模型调用，直接返回旧回答，节省最多但可能答错。Prompt Caching 由模型服务商提供，复用相同提示前缀的计算，模型仍实时生成新回答，只降低成本与首字延迟，不影响正确性。

如何设置相似度阈值？

收集真实查询，标注“应命中”和“不应命中”的查询对，在不同阈值下计算误命中率和命中率，选择业务可接受的点。不同嵌入模型的分数分布不同，阈值不可直接照搬，且需随模型更换重新校准。

语义缓存有哪些安全与隐私风险？

若缓存不分区，用户 A 的个性化回答可能被用户 B 的相似问题命中，造成数据泄露；攻击者也可能通过构造查询探测缓存内容。应只缓存通用知识类回答，按租户隔离，并对敏感信息做过滤。
