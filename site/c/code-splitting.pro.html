代码分割与懒加载

Code Splitting & Lazy Loading

📐 01 · 定义

代码分割（Code Splitting）是把应用 JavaScript 拆成多个按需加载的块（chunk），而不是打成一个大 bundle；懒加载（Lazy Loading）是在需要时才请求这些块。它属于前端构建与性能层，借助动态 import() 让打包器自动生成分割点，减少首屏下载与解析的代码量，改善 LCP 与交互指标。

⚙️ 02 · 原理
  1. 1

    开发者在代码中使用动态 import()，或框架按路由自动生成分割点。

  2. 2

    打包器为每个分割点生成独立 chunk，并把公共依赖提取为共享块，避免重复。

  3. 3

    首屏只加载入口块和当前路由所需块；其他块在路由切换、组件渲染或用户交互时请求。

  4. 4

    React 中用 React.lazy 包装动态导入，配合 Suspense 在加载期间显示占位内容。

  5. 5

    可通过预取（prefetch）在空闲时提前下载可能用到的块，减少切换等待。

🔤 03 · 术语
动态导入 (Dynamic import())
返回 Promise 的运行时模块加载语法，打包器据此分割。
Chunk
打包器输出的一个独立 JS 文件，可单独缓存与加载。
路由级分割 (Route-based Splitting)
按页面路由拆分代码，最常见、收益最大。
预取 / 预加载 (Prefetch / Preload)
提前低优先级或高优先级获取资源。
Suspense
React 中在异步组件就绪前显示 fallback 的机制。
💻 04 · 代码
React.lazy 懒加载图表组件typescript
import { lazy, Suspense, useState } from "react";

// 图表库体积大且不在首屏：拆成独立 chunk，用到时才下载
const SalesChart = lazy(() => import("./SalesChart"));

export default function Dashboard() {
  const [show, setShow] = useState(false);
  return (
    <main>
      <h1>销售概览</h1>
      <button onClick={() => setShow(true)}>查看图表</button>
      {show && (
        <Suspense fallback={<div className="skeleton">图表加载中…</div>}>
          <SalesChart />
        </Suspense>
      )}
    </main>
  );
}
// Next.js 中可用 next/dynamic 实现同样效果

点击后才请求图表 chunk，首屏 bundle 不包含图表库。

📊 05 · 参数对比

分割策略对比

策略分割粒度适用
路由级每个页面一个块多页面 SPA，默认首选
组件级大组件单独成块弹窗、图表、编辑器
第三方库拆分vendor 独立缓存依赖稳定、业务代码常变
交互触发用户操作后再加载低频功能
⚖️ 06 · 方案取舍

激进细粒度分割

优点首屏最小

代价请求数多，瀑布式加载延迟

适用首屏极度敏感的移动端

路由级分割

优点收益大、实现简单

代价单页内仍可能有大组件

适用大多数应用

不分割单 bundle

优点无加载等待，配置最简

代价首屏下载解析全部代码

适用非常小的应用

🕳️ 07 · 常见坑

  • ✗把首屏可见的组件也懒加载，导致 LCP 变差

    ✓只懒加载首屏外或交互后才需要的部分

  • ✗懒加载块依次请求形成瀑布

    ✓并行触发或对关键路径做 preload/prefetch

  • ✗没有加载占位，内容出现时布局跳动

    ✓Suspense fallback 预留与真实内容相同的尺寸

  • ✗部署新版本后旧 chunk 被删，用户切路由报错

    ✓保留旧版本资源一段时间，捕获加载失败并提示刷新

☑️ 08 · 检查清单
🎤 09 · 面试追问
代码分割会不会让性能变差？

会，如果分割过细或把首屏关键内容延后：增加请求往返、产生瀑布、推迟 LCP。原则是首屏关键路径完整加载，非关键部分延后，并用预取掩盖切换延迟。

动态 import() 如何被打包器处理？

打包器把 import() 的目标模块及其依赖作为新的异步 chunk 输出，原位置替换为运行时加载代码（创建 script 或 fetch 模块），返回解析为模块对象的 Promise。

部署后出现 ChunkLoadError 怎么办？

通常是旧页面引用的 chunk 文件已被新部署删除。保留历史资源、使用内容哈希文件名、捕获错误后提示刷新或自动重载；部署平台的版本偏差保护（skew protection）也可缓解。
