内容分发网络 (CDN)

CDNs

📐 01 · 定义

内容分发网络（Content Delivery Network, CDN）是分布在全球各地的边缘节点（PoP）网络，把静态资源乃至动态响应缓存在离用户近的位置，并代为终止 TLS、抵御 DDoS。它位于用户与源站之间的边缘层，用于降低延迟、减轻源站负载与带宽成本，现代 CDN 还提供边缘计算能力。

⚙️ 02 · 原理
  1. 1

    域名通过 CNAME 或 NS 托管指向 CDN，DNS 或 Anycast 路由把用户导向就近节点。

  2. 2

    边缘节点按缓存键（通常是 URL 加部分头）查找本地缓存，命中则直接返回。

  3. 3

    未命中时回源（可能先经中间层缓存）获取内容，并按 Cache-Control 或规则缓存。

  4. 4

    内容更新时通过带哈希的文件名自然失效，或调用清除（Purge）接口主动删除。

  5. 5

    边缘还可执行 WAF、限流、重定向和边缘函数，在靠近用户处处理请求。

🔤 03 · 术语
PoP (Point of Presence)
CDN 在某地部署的边缘节点机房。
回源 (Origin Fetch)
边缘未命中时向源站请求内容。
缓存键 (Cache Key)
决定两个请求是否共享同一缓存对象的标识。
Anycast
多个节点共享同一 IP，路由自动选最近节点。
源站保护 (Origin Shield)
在边缘与源站间加一层集中缓存，减少回源。
💻 04 · 代码
指纹资源与 HTML 的缓存头http
# 带内容哈希的静态资源：一年缓存，内容变则文件名变
GET /assets/app.3f9c2b.js HTTP/1.1
Host: www.example.com

HTTP/1.1 200 OK
Cache-Control: public, max-age=31536000, immutable
Content-Type: application/javascript

# HTML 入口：浏览器每次校验，CDN 缓存 60 秒
GET /index.html HTTP/1.1
Host: www.example.com

HTTP/1.1 200 OK
Cache-Control: public, max-age=0, s-maxage=60, stale-while-revalidate=30
ETag: "a1b2c3"

# 登录后的个性化接口：禁止共享缓存
GET /api/me HTTP/1.1

HTTP/1.1 200 OK
Cache-Control: private, no-store

资源用文件指纹加长缓存，HTML 短缓存，个性化内容禁止 CDN 缓存。

📊 05 · 参数对比

CDN 内容缓存策略

内容类型缓存策略更新方式
带哈希的 JS/CSS/图片长 TTL + immutable发布新文件名
HTML 页面短 s-maxage 或不缓存TTL 到期或 Purge
公共 API 响应短 TTL，按参数分键TTL 到期
个性化/鉴权内容private, no-store不经 CDN 缓存
⚖️ 06 · 方案取舍

只缓存静态资源

优点简单安全，无数据泄露风险

代价动态请求仍全部回源

适用大多数 Web 应用起步

缓存公共动态页面

优点大幅降低源站负载

代价需精确控制缓存键与失效

适用内容站、商品列表等公共页面

边缘计算

优点在边缘做鉴权、个性化

代价运行时受限，调试复杂

适用全球用户且需低延迟逻辑

🕳️ 07 · 常见坑

  • ✗个性化响应被 CDN 缓存，A 用户看到 B 的数据

    ✓鉴权内容设 private/no-store，并核对 CDN 是否忽略 Cookie

  • ✗文件名不带哈希却设长缓存，发布后旧资源迟迟不更新

    ✓构建产物加内容哈希，入口 HTML 用短缓存

  • ✗缓存键包含无关查询参数，命中率极低

    ✓规范化缓存键，忽略 utm 等追踪参数

  • ✗源站 IP 暴露，攻击者绕过 CDN 直连

    ✓源站只允许 CDN 回源 IP 或使用认证回源

🎤 09 · 面试追问
如何判断一个响应是否命中了 CDN？

查看 CDN 返回的诊断头，如 Age、X-Cache 或厂商特有头（如 CF-Cache-Status）。Age 大于 0 通常表示来自缓存；具体头名以所用 CDN 文档为准。

发布后如何让用户立刻拿到新版本？

构建产物用内容哈希命名并长缓存；入口 HTML 短缓存或 no-cache，新 HTML 引用新文件名即可生效；必要时对 HTML 路径调用 Purge，而不是全站清缓存。

CDN 为什么能降低 TLS 握手延迟？

TLS 在离用户最近的边缘节点终止，握手往返距离短；边缘与源站之间可复用长连接。HTTP/3 与 0-RTT 进一步减少握手开销。
