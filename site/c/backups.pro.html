数据备份体系

Backups

📐 01 · 定义

数据备份体系（Backups）是按策略定期复制数据并独立保存，以便在误删、硬件故障、勒索软件、错误迁移等事故后恢复的机制。它由备份频率、保留周期、存储位置、加密和恢复演练共同构成，以 RPO（可容忍丢失多少数据）和 RTO（可容忍停机多久）衡量。未经恢复验证的备份不能算可靠备份。

⚙️ 02 · 原理
  1. 1

    定目标：按业务影响确定 RPO 和 RTO，决定备份频率与恢复方式。

  2. 2

    选方式：全量、增量、差异备份组合，数据库可加连续日志归档实现时间点恢复。

  3. 3

    隔离存储：备份放在与生产不同的账号、区域或介质，防止同一事故一起损毁。

  4. 4

    保护备份：加密、设置不可变（WORM）或版本保留，防止被勒索软件删除或篡改。

  5. 5

    定期演练：按计划把备份恢复到隔离环境，校验数据完整性并记录实际恢复耗时。

🔤 03 · 术语
RPO
恢复点目标：事故后最多可丢失多长时间的数据。
RTO
恢复时间目标：从事故到服务恢复的最长可接受时间。
3-2-1 原则
至少 3 份数据，2 种介质，1 份异地。
时间点恢复 (PITR)
借助日志把数据库恢复到任意指定时刻。
不可变备份 (Immutable Backup)
在保留期内无法被修改或删除的备份。
💻 04 · 代码
PostgreSQL 备份与恢复验证bash
#!/usr/bin/env bash
set -euo pipefail
TS=$(date +%Y%m%d-%H%M)

# 1. 逻辑备份（自定义格式，压缩且支持选择性恢复）
pg_dump "$DATABASE_URL" -Fc -f "backup-$TS.dump"

# 2. 生成校验和，防止传输或存储损坏
sha256sum "backup-$TS.dump" > "backup-$TS.dump.sha256"

# 3. 上传到独立账号的对象存储（示例：AWS CLI，桶应开启版本控制）
# aws s3 cp "backup-$TS.dump" s3://my-backups/db/

# 4. 恢复演练：还原到临时数据库并做基本校验
createdb restore_test
pg_restore -d restore_test --no-owner "backup-$TS.dump"
psql -d restore_test -c "SELECT count(*) FROM users;"
dropdb restore_test

备份脚本要包含恢复验证这一步；只备份不还原，等于不知道备份是否可用。

📊 05 · 参数对比

备份方式对比

方式恢复粒度存储开销说明
全量备份备份时刻大恢复最简单
增量备份备份时刻小恢复需按顺序叠加多个增量
快照（磁盘/云盘）快照时刻中快，但需确保应用数据一致
日志归档 + PITR任意时刻中满足较小 RPO，托管数据库常内置
⚖️ 06 · 方案取舍

托管数据库自动备份

优点开箱即用，支持时间点恢复

代价与生产同账号，误删账号可能连带

适用默认开启，作为第一层

额外异地/跨账号备份

优点抵御账号级与区域级灾难

代价额外成本与流程

适用核心业务数据

高频备份

优点RPO 小，丢数据少

代价存储与性能开销大

适用交易类、写入频繁的系统

🕳️ 07 · 常见坑

  • ✗备份从未做过恢复演练

    ✓定期恢复到隔离环境，记录耗时与问题

  • ✗备份和生产在同一台机器或同一账号

    ✓备份隔离到不同账号、区域，并开启不可变保护

  • ✗只备份数据库，忘了上传文件与配置

    ✓盘点所有数据：对象存储、配置、密钥恢复方式

  • ✗让 Agent 执行迁移前没有备份

    ✓破坏性操作前先做备份或确认时间点恢复可用

🎤 09 · 面试追问
RPO 和 RTO 如何影响架构？

RPO 决定备份频率：RPO 一天可每日备份，RPO 分钟级则需要日志归档或同步复制。RTO 决定恢复手段：小时级可从备份重建，分钟级需要热备与自动故障切换。目标越严格成本越高，应按业务价值取舍。

主从复制能代替备份吗？

不能。复制会把误删、错误更新和勒索加密同步到从库，它解决的是可用性而非数据恢复。备份是时间维度上的独立副本，能回到事故之前的状态。两者需要同时具备。

如何防御勒索软件破坏备份？

备份存放在独立账号或离线介质；启用对象锁定等不可变保留；备份系统使用独立凭证与 MFA；监控异常删除；保留多个时间点版本；定期演练从隔离备份恢复整个系统。
