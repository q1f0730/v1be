预发布/准生产环境

Staging Environments

📐 01 · 定义

预发布环境（Staging Environment）是在上线前用于最终验证的、尽可能贴近生产的独立环境：相同的构建产物、相近的基础设施与配置，但使用隔离的数据和第三方沙箱账号。它位于 CI/CD 流水线中测试与生产之间，用来发现单元测试与本地环境发现不了的集成、配置与部署问题。

⚙️ 02 · 原理
  1. 1

    CI 构建出唯一制品后先部署到 staging，生产随后部署同一个制品，不重新构建。

  2. 2

    staging 使用与生产相同的基础设施定义（IaC），仅规模和密钥不同。

  3. 3

    数据使用脱敏的生产快照或合成数据，外部支付、邮件等接入沙箱账号。

  4. 4

    在 staging 运行端到端测试、数据库迁移演练、冒烟测试和人工验收。

  5. 5

    验证通过后经审批进入生产；有的团队用按 PR 创建的临时预览环境补充。

🔤 03 · 术语
环境一致性 (Dev/Prod Parity)
开发、预发、生产尽可能一致，减少「本地能跑」。
基础设施即代码 (IaC)
用代码定义环境资源，保证可复制。
预览环境 (Preview Environment)
按分支或 PR 临时创建的短期环境。
冒烟测试 (Smoke Test)
部署后快速验证核心路径是否可用。
配置漂移 (Configuration Drift)
环境间配置逐渐不一致的现象。
💻 04 · 代码
GitHub Actions 分环境部署yaml
name: deploy
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: ./scripts/build-image.sh "$GITHUB_SHA"   # 只构建一次
  deploy-staging:
    needs: build
    runs-on: ubuntu-latest
    environment: staging            # 使用 staging 的独立密钥
    steps:
      - run: ./scripts/deploy.sh staging "$GITHUB_SHA"
      - run: ./scripts/smoke-test.sh https://staging.example.com
  deploy-production:
    needs: deploy-staging
    runs-on: ubuntu-latest
    environment: production         # 可在仓库设置中配置必需审批人
    steps:
      - run: ./scripts/deploy.sh production "$GITHUB_SHA"   # 同一制品

同一提交的制品依次进入 staging 与生产；environment 隔离密钥并可加人工审批。脚本为示意。

⚖️ 06 · 方案取舍

长期 staging

优点稳定，便于验收与演练

代价成本高，易与生产漂移

适用需要统一集成验证的团队

按 PR 预览环境

优点并行验证，互不干扰

代价数据与依赖难做全

适用前端或无状态服务为主

生产灰度替代

优点真实流量与数据

代价风险直接作用于用户

适用配合开关与金丝雀的成熟团队

🕳️ 07 · 常见坑

  • ✗staging 与生产各自构建，验证的不是同一份产物

    ✓构建一次，按环境注入配置后部署同一制品

  • ✗直接复制生产数据到 staging

    ✓对个人信息脱敏或使用合成数据，并限制访问

  • ✗staging 接真实支付或给真实用户发邮件

    ✓第三方一律使用沙箱账号与测试收件地址

  • ✗staging 长期无人维护，配置与生产漂移

    ✓用同一套 IaC 管理，定期比对配置差异

🎤 09 · 面试追问
staging 测过了为什么生产还会出问题？

数据规模与分布不同、真实流量模式与并发、第三方生产行为差异、配置漂移、缓存与时序问题等都难以在 staging 复现。因此还需要金丝雀、特性开关与可观测性兜底。

为什么强调「构建一次，到处部署」？

每次重新构建都可能引入不同依赖版本或构建参数，导致验证过的产物与上线产物不一致。固定制品摘要、配置外置注入，才能保证 staging 的验证结论对生产有效。

staging 的数据怎么准备？

优先合成数据覆盖边界场景；需要真实分布时用生产快照经过不可逆脱敏后导入，并控制访问权限与保留期。迁移演练需要接近生产的数据量。
