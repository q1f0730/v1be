云安全组

Security Groups

📐 01 · 定义

安全组（Security Group）是云平台提供的虚拟防火墙，作用于实例或网卡级别，以“允许规则”控制入站和出站流量。它是有状态的：放行的请求其回包自动允许。安全组可以引用其他安全组作为来源，从而按角色而非 IP 描述访问关系，是云上最常用的访问控制手段。

⚙️ 02 · 原理
  1. 1

    安全组绑定到实例、网卡、负载均衡或数据库等资源，一个资源可绑定多个安全组。

  2. 2

    规则只有允许没有拒绝，未匹配的入站流量一律丢弃；AWS 新建安全组默认允许全部出站。

  3. 3

    规则来源可以是 CIDR 网段、前缀列表，或另一个安全组（表示绑定了它的所有资源）。

  4. 4

    有状态跟踪：入站被允许的连接，其响应流量无需出站规则即可返回。

  5. 5

    子网级的网络 ACL 是另一层无状态控制，按编号顺序评估，可写拒绝规则。

🔤 03 · 术语
入站/出站规则 (Ingress/Egress Rule)
分别控制进入和离开资源的流量。
安全组引用 (SG Reference)
以另一安全组为来源，按角色授权。
网络 ACL (NACL)
子网级无状态访问控制，支持拒绝规则。
前缀列表 (Prefix List)
可复用的 CIDR 集合，便于统一维护。
最小权限 (Least Privilege)
只开放完成功能所需的最小端口与来源。
💻 04 · 代码
按角色串联三层安全组bash
#!/usr/bin/env bash
set -euo pipefail
VPC_ID=vpc-0123456789abcdef0
mk() { aws ec2 create-security-group --vpc-id "$VPC_ID" \
         --group-name "$1" --description "$1" --query GroupId --output text; }

ALB_SG=$(mk alb-sg); APP_SG=$(mk app-sg); DB_SG=$(mk db-sg)

# 公网只能访问负载均衡的 443
aws ec2 authorize-security-group-ingress --group-id "$ALB_SG" \
  --protocol tcp --port 443 --cidr 0.0.0.0/0
# 应用只接受来自负载均衡安全组的流量
aws ec2 authorize-security-group-ingress --group-id "$APP_SG" \
  --protocol tcp --port 8080 --source-group "$ALB_SG"
# 数据库只接受来自应用安全组的流量
aws ec2 authorize-security-group-ingress --group-id "$DB_SG" \
  --protocol tcp --port 5432 --source-group "$APP_SG"

# 审计：找出对全网开放 22 端口的安全组
aws ec2 describe-security-groups \
  --filters Name=ip-permission.from-port,Values=22 \
            Name=ip-permission.cidr,Values=0.0.0.0/0 \
  --query 'SecurityGroups[].[GroupId,GroupName]' --output table

用安全组引用代替 IP，扩缩容无需改规则；定期审计对 0.0.0.0/0 开放的端口。

📊 05 · 参数对比

安全组 vs 网络 ACL

维度安全组网络 ACL
作用范围实例/网卡子网
状态有状态无状态（需放行回包端口）
规则类型仅允许允许和拒绝
评估方式所有规则合并评估按规则编号顺序，命中即止
⚖️ 06 · 方案取舍

按角色引用安全组

优点自动适配扩缩容，意图清晰

代价跨 VPC 引用受限制

适用同 VPC 内服务间访问

按 CIDR 授权

优点可表达外部网段

代价IP 变动需改规则，易过宽

适用办公网、合作方固定 IP

叠加 NACL 拒绝规则

优点可快速封禁恶意网段

代价无状态，配置易出错

适用需要显式拒绝时

🕳️ 07 · 常见坑

  • ✗为排障临时开放 0.0.0.0/0:22 后忘记关闭

    ✓用 Session Manager 等免开端口方式，并定期审计

  • ✗数据库安全组按应用子网 CIDR 放行

    ✓改为引用应用安全组，缩小到具体角色

  • ✗所有服务共用一个“万能”安全组

    ✓按角色拆分，每个安全组职责单一

  • ✗改了 NACL 却忘了放行回包的临时端口

    ✓无状态规则需同时放行出站临时端口范围

🎤 09 · 面试追问
安全组为什么只需要写入站规则就能通信？

安全组有状态，会跟踪连接。入站请求被允许后，响应流量属于同一连接，自动放行，不需要额外出站规则。反过来，实例主动发起的出站连接被允许后，其回包入站也自动放行。

引用安全组作为来源有什么好处？

规则表达的是“哪个角色可以访问”，与具体 IP 无关。自动扩容新增实例只要绑定该安全组就自动获得访问权限，下线实例自动失去权限，避免维护 IP 列表，也不会因网段过宽误放其他服务。

不开 22 端口如何登录云服务器？

使用云厂商的会话管理服务（如 AWS Systems Manager Session Manager），通过实例上的代理反向连接，权限由 IAM 控制并有审计日志；或使用零信任访问网关。这样安全组无需任何入站管理端口。
