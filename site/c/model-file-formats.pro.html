模型文件格式 (GGUF / safetensors)

📐 01 · 定义

模型文件格式决定了权重张量、元数据和分词器如何序列化到磁盘，直接影响加载速度、安全性和可用的推理引擎。主流有 safetensors（只存张量、可 mmap、不含代码）、GGUF（llama.cpp 生态单文件格式，内置量化与元数据），以及基于 pickle 的 PyTorch .bin/.pt，后者加载时有任意代码执行风险。

⚙️ 02 · 原理
  1. 1

    训练框架在内存中保存的是张量字典（参数名到多维数组），保存时需要选一种序列化格式写入磁盘。

  2. 2

    PyTorch 传统的 torch.save 使用 pickle，反序列化时可执行任意 Python 对象构造逻辑，恶意文件可借此运行代码。

  3. 3

    safetensors 文件开头 8 字节记录头部长度，随后是 JSON 头（张量名、dtype、形状、偏移），之后是连续的原始数据，可零拷贝 mmap 加载。

  4. 4

    GGUF 在单文件内存储超参数、分词器、聊天模板等键值元数据和各张量，张量可使用 Q4_K、Q8_0 等量化类型，供 llama.cpp、Ollama 等直接加载。

  5. 5

    大模型常按体积拆为多个分片（shard），配合 index JSON 记录每个张量位于哪个文件；GGUF 也支持分片文件。

🔤 03 · 术语
safetensors
只含张量与 JSON 头的安全格式，支持 mmap 与惰性加载。
GGUF
llama.cpp 定义的二进制格式，单文件包含权重、元数据和量化信息。
pickle 反序列化风险
加载 pickle 文件可能执行任意代码，不可信来源需避免。
量化类型 (Quant Type)
如 Q4_K_M、Q8_0，表示每个权重用的位数与分组方式。
分片 (Shard)
把大模型权重拆为多个文件，配合索引文件加载。
内存映射 (mmap)
把文件直接映射进地址空间，按需读取，加快加载并省内存。
💻 04 · 代码
读写 safetensors 并查看文件头python
import json, struct
import torch
from safetensors.torch import save_file, load_file

tensors = {"w": torch.randn(4, 4), "b": torch.zeros(4)}
save_file(tensors, "demo.safetensors", metadata={"note": "demo"})

# 文件结构：8 字节小端整数 = JSON 头长度，随后是 JSON 头
with open("demo.safetensors", "rb") as f:
    n = struct.unpack("<Q", f.read(8))[0]
    header = json.loads(f.read(n))
print(header["w"])          # dtype、shape、data_offsets

loaded = load_file("demo.safetensors")   # 不经过 pickle
print(torch.equal(loaded["w"], tensors["w"]))  # True

说明 safetensors 只是“JSON 头 + 原始字节”，加载过程不执行任何代码。

📊 05 · 参数对比

主流格式对比

格式主要生态是否可执行代码典型用途
safetensorsTransformers、Diffusers否模型发布、训练、GPU 推理

⚖️ 06 · 方案取舍

safetensors + GPU 推理引擎

优点精度高、生态完整、加载快

代价显存需求大

适用有服务器 GPU、生产推理

GGUF 量化文件

优点单文件易分发，消费级硬件可跑

代价低比特量化有质量损失

适用个人电脑、离线本地使用

自行转换格式

优点可定制量化与精度

代价转换脚本与版本兼容需验证

适用官方未提供所需格式时

🕳️ 07 · 常见坑

  • ✗从不可信来源加载 .bin/.pt 文件

    ✓优先 safetensors；必须用 torch.load 时设 weights_only=True

  • ✗只看参数量挑文件，忽略量化位数

    ✓按“参数量 × 每权重位数”估算体积，并为 KV 缓存留显存

  • ✗GGUF 聊天模板与模型不匹配导致输出异常

    ✓使用文件内置模板或官方推荐模板，升级推理引擎

  • ✗下载了 LoRA 适配器却当完整模型加载

    ✓检查是否为 adapter 文件，需与对应基座模型合并或一起加载

🎤 09 · 面试追问
为什么社区从 pickle 迁移到 safetensors？

pickle 反序列化能调用任意可调用对象，模型文件可藏恶意代码，在共享平台上风险很大。safetensors 只描述张量布局，没有可执行逻辑，同时支持 mmap 零拷贝和按需加载单个张量，加载速度更快。

GGUF 相比 safetensors 的定位差异？

safetensors 是通用张量容器，通常保存 FP16/BF16 原始权重，配合 config 与 tokenizer 文件使用。GGUF 是面向推理的自包含格式，把元数据、分词器和量化权重打包在一个文件，便于本地工具开箱即用。

如何估算 GGUF 文件能否在显卡上运行？

文件体积约等于权重显存占用，再加上 KV 缓存（随上下文长度和并发增长）与运行时开销。显存不足时可部分层卸载到 CPU，但速度会下降。实际可用性以推理引擎的报告为准。
