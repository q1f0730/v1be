推理引擎 (vLLM / SGLang / llama.cpp)

Inference Engines

📐 01 · 定义

推理引擎（Inference Engine）是专门执行大模型推理的服务软件，负责加载权重、调度请求、管理 KV 缓存并调用优化内核，对外暴露 HTTP/OpenAI 兼容接口。它属于模型服务层，决定自部署模型的吞吐、延迟与成本。vLLM、SGLang 面向 GPU 服务器的高并发服务，llama.cpp 面向 CPU/消费级硬件与 GGUF 量化模型。

⚙️ 02 · 原理
  1. 1

    加载模型权重（可选量化格式）到 GPU/CPU 内存，并预留显存给 KV 缓存。

  2. 2

    请求进入调度器，连续批处理（continuous batching）在每个解码步动态加入新请求、移出已完成请求。

  3. 3

    KV 缓存按块管理（如 PagedAttention），支持前缀共享，减少碎片，提高可容纳的并发数。

  4. 4

    调用融合注意力、量化矩阵乘等优化内核，并可启用张量并行、投机解码、结构化输出等特性。

  5. 5

    通过 OpenAI 兼容 API 流式返回 token，同时暴露吞吐、排队、缓存使用率等监控指标。

🔤 03 · 术语
连续批处理 (Continuous Batching)
以解码步为粒度动态组批，避免等待整批完成。
PagedAttention
vLLM 的分页 KV 缓存管理机制。
RadixAttention
SGLang 用基数树管理并复用 KV 缓存前缀的机制。
GGUF
llama.cpp 使用的模型文件格式，支持多种量化等级。
张量并行 (Tensor Parallelism)
把单层权重切分到多张 GPU 上并行计算。
💻 04 · 代码
三种引擎的启动方式bash
# vLLM：启动 OpenAI 兼容服务（默认端口 8000）
vllm serve Qwen/Qwen2.5-7B-Instruct \
  --max-model-len 8192 \
  --gpu-memory-utilization 0.90

# SGLang：启动服务（默认端口 30000）
python -m sglang.launch_server \
  --model-path Qwen/Qwen2.5-7B-Instruct --port 30000

# llama.cpp：用 GGUF 量化模型在 CPU/消费级 GPU 上运行
llama-server -m ./qwen2.5-7b-instruct-q4_k_m.gguf -c 4096 --port 8080

# 三者都可用 OpenAI 风格接口调用
curl http://localhost:8000/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -d '{"model":"Qwen/Qwen2.5-7B-Instruct","messages":[{"role":"user","content":"你好"}]}'

按需替换模型名与路径；--gpu-memory-utilization 决定留给权重和 KV 缓存的显存比例。

🕳️ 07 · 常见坑

  • ✗用 transformers 的 generate 循环直接对外服务

    ✓生产服务使用支持连续批处理的推理引擎

  • ✗把 gpu-memory-utilization 设满且同卡运行其他程序

    ✓为其他进程预留显存，避免 OOM

  • ✗只测单请求延迟就评估容量

    ✓按目标并发压测吞吐、TTFT 与 TPOT 分位数

  • ✗对外暴露推理端口而无鉴权

    ✓放在网关之后，加 API Key 与限流

🎤 09 · 面试追问
为什么推理引擎比朴素 generate 快很多？

朴素实现静态组批、显存预分配浪费；引擎用连续批处理提高 GPU 利用率，分页 KV 缓存提升并发，配合融合内核、前缀缓存与 CUDA Graph 等优化，在并发场景下吞吐显著更高。

vLLM 和 llama.cpp 如何选择？

多用户、GPU 服务器、追求吞吐选 vLLM/SGLang；单用户、CPU/Mac/消费级显卡、需要低比特量化与离线运行选 llama.cpp（或基于它的 Ollama）。

TTFT 和 TPOT 分别受什么影响？

TTFT 主要受排队与预填充（输入长度、前缀缓存命中）影响；TPOT 受解码阶段的显存带宽、批大小与模型大小影响。批越大吞吐越高，但单请求 TPOT 可能变差。
