客户端与服务端

Client & Server

📐 01 · 定义

客户端—服务器模型（Client–Server Model）是一种分布式架构：客户端主动发起请求，服务器被动监听并返回响应，双方通过网络协议（如 HTTP）通信。浏览器、App、CLI 工具、AI Agent 都可以是客户端。该模型把展示与交互放在客户端、数据与权威逻辑集中在服务器，是 Web 与 API 的基本形态。

⚙️ 02 · 原理
  1. 1

    服务器启动：服务进程在约定的地址和端口上监听，被动等待客户端发起连接。

  2. 2

    客户端发起：解析服务器地址，建立连接，按协议发送请求（方法、路径、头、体）。

  3. 3

    服务器处理：鉴权、执行业务逻辑、访问数据，生成带状态码的响应。

  4. 4

    客户端消费：解析响应，更新界面或交给后续逻辑，处理错误与超时。

  5. 5

    状态维持：HTTP 本身无状态，会话通过 Cookie、Token 等在每次请求中携带。

🔤 03 · 术语
请求/响应 (Request/Response)
客户端发出请求，服务器返回响应的一次交互。
状态码 (Status Code)
如 200 成功、404 未找到、500 服务器错误。
无状态协议 (Stateless)
每个请求独立，服务器不依赖之前请求的记忆。
长连接 / WebSocket
建立后可双向持续通信，服务器可主动推送。
P2P (点对点)
对等节点互为客户端与服务器，与集中式模型相对。
💻 04 · 代码
Node.js 服务端与客户端javascript
// server.js —— 运行：node server.js
const http = require("node:http");

const server = http.createServer((req, res) => {
  console.log(req.method, req.url);           // 记录收到的请求
  if (req.url === "/api/time") {
    res.writeHead(200, { "Content-Type": "application/json" });
    res.end(JSON.stringify({ now: new Date().toISOString() }));
  } else {
    res.writeHead(404).end("Not Found");
  }
});
server.listen(3000, "127.0.0.1", () => console.log("listening on :3000"));

// client.js —— 另开终端运行：node client.js（Node 18+ 内置 fetch）
// const res = await fetch("http://127.0.0.1:3000/api/time");
// console.log(res.status, await res.json());

// 也可以用 curl 当客户端：curl -i http://127.0.0.1:3000/api/time

服务端监听并按路径响应，客户端可以是浏览器、脚本或 curl，协议一致即可通信。

⚖️ 06 · 方案取舍

胖客户端（逻辑多在前端）

优点交互快、减轻服务器压力

代价逻辑可被篡改，多端重复实现

适用富交互应用、离线能力

瘦客户端（逻辑在服务器）

优点安全、规则统一

代价依赖网络，服务器负载高

适用涉及权限、金额、核心规则

实时双向连接

优点低延迟推送

代价连接管理与扩展更复杂

适用协作、聊天、实时数据

🕳️ 07 · 常见坑

  • ✗客户端没有超时和重试，网络抖动就卡死

    ✓设置请求超时，对幂等请求做指数退避重试

  • ✗信任客户端传来的身份或价格字段

    ✓服务器以会话身份和自身数据为准重新校验

  • ✗LLM 长回复用普通请求，用户久等无反馈

    ✓用流式（SSE）边生成边返回

🎤 09 · 面试追问
HTTP 无状态，登录状态怎么保持？

服务器登录成功后下发凭证：基于 Session 的方式把会话存服务端、客户端持有 Session ID Cookie；基于 Token 的方式（如 JWT）把签名令牌交给客户端，每次请求在头部携带，服务器验签即可识别用户。

LLM 应用的流式输出用什么技术？

多数模型 API 用 Server-Sent Events（SSE）：一个 HTTP 响应保持打开，服务器按事件逐段推送 Token。前端用 fetch 读取流或 EventSource 接收，逐步渲染，从而显著降低用户感知等待时间。

什么是幂等？为什么客户端重试需要它？

幂等指同一请求执行一次和多次效果相同。网络超时时客户端不知道服务器是否已处理，重试非幂等操作（如下单）可能重复扣款。对策：GET/PUT/DELETE 设计为幂等，POST 使用幂等键去重。
