智能体式检索 (Agentic RAG)

Agentic RAG

📐 01 · 定义

智能体式检索（Agentic RAG）把检索封装成工具交给 LLM Agent，由模型在推理循环中自主决定是否检索、检索什么、使用哪个知识源、何时停止，并可基于中间结果改写查询、多跳追问或调用其他工具。它属于 RAG 与 Agent 的交叉层，用于复杂、多跳、需综合多来源的问题，代价是延迟、成本与行为不确定性上升。

⚙️ 02 · 原理
  1. 1

    把一个或多个检索器（向量库、关键词搜索、SQL、Web 搜索）定义为带描述与参数的工具。

  2. 2

    模型读取问题，判断能否直接回答；需要外部信息时生成工具调用和查询参数。

  3. 3

    系统执行检索并把结果返回模型，模型评估信息是否充分、是否相关。

  4. 4

    信息不足时改写查询、换知识源或拆分子问题继续检索，直到满足或达到步数上限。

  5. 5

    模型基于累积的证据生成带引用的回答；系统记录完整轨迹以便评测与排查。

🔤 03 · 术语
工具调用 (Tool Calling)
模型输出结构化调用请求，由系统执行并返回结果。
ReAct
推理（Reason）与行动（Act）交替进行的 Agent 模式。
多跳检索 (Multi-hop Retrieval)
根据前一次检索结果发起后续检索。
路由 (Routing)
根据问题选择合适的知识源或检索方式。
Self-RAG
让模型自行决定检索并对检索与生成结果进行反思评估的方法。
💻 04 · 代码
带步数上限的检索 Agent 循环python
import json
from openai import OpenAI
client = OpenAI()
TOOLS = [{"type": "function", "function": {
    "name": "search_docs", "description": "在公司知识库中检索相关段落",
    "parameters": {"type": "object", "properties": {"query": {"type": "string"}},
                   "required": ["query"]}}}]

def agentic_rag(question: str, max_steps: int = 5) -> str:
    msgs = [{"role": "system", "content": "必要时调用 search_docs，可多次换关键词；信息足够后作答并注明来源。"},
            {"role": "user", "content": question}]
    for _ in range(max_steps):
        r = client.chat.completions.create(model="gpt-4o-mini", messages=msgs, tools=TOOLS)
        msg = r.choices[0].message
        if not msg.tool_calls:                 # 模型认为信息已足够
            return msg.content
        msgs.append(msg)
        for call in msg.tool_calls:
            q = json.loads(call.function.arguments)["query"]
            msgs.append({"role": "tool", "tool_call_id": call.id,
                         "content": search_docs(q)})   # search_docs 为你的检索函数
    msgs.append({"role": "user", "content": "已达检索上限，请基于现有信息作答并说明不确定处。"})
    return client.chat.completions.create(model="gpt-4o-mini", messages=msgs).choices[0].message.content

检索作为工具由模型自主调用；max_steps 限制循环，防止无限检索与成本失控。

📊 05 · 参数对比

RAG 形态对比

形态检索决策适合问题成本/延迟
朴素 RAG固定检索一次单跳事实问题低
高级 RAG（改写+重排）固定流程多步表述不规范的问题中
Agentic RAG模型动态决定多跳、多源、开放问题高且波动
多智能体 RAG多个 Agent 分工协作大型研究型任务最高
⚖️ 06 · 方案取舍

Agentic RAG

优点能处理复杂多跳问题，灵活使用多源

代价延迟和成本不可预测，难调试

适用研究、分析、复杂客服

固定流程 RAG

优点可预测、便宜、易评测

代价复杂问题容易检索不全

适用高频、简单问答

路由 + 固定流程

优点按问题类型分流，兼顾两者

代价需要可靠的分类器

适用问题类型可区分的产品

🕳️ 07 · 常见坑

  • ✗不设步数与 Token 上限

    ✓限制最大检索次数与总 Token，超限后基于现有信息作答

  • ✗工具描述含糊，模型乱选知识源

    ✓为每个工具写清用途、适用问题与参数示例

  • ✗只评测最终答案，不看检索轨迹

    ✓记录并评测轨迹：检索次数、查询质量、冗余调用

  • ✗检索结果原样塞入上下文，越积越长

    ✓截断或摘要工具结果，只保留相关片段与来源

☑️ 08 · 检查清单
🎤 09 · 面试追问
什么时候应该用 Agentic RAG 而不是普通 RAG？

问题需要多跳推理、组合多个来源、或第一次检索后才知道下一步查什么时。若问题多为单跳事实查询，普通 RAG 更快更便宜、更容易评测。

如何评测 Agentic RAG？

除最终答案正确性与忠实度外，还要评测轨迹：是否调用了正确工具、查询是否合理、检索次数是否冗余、是否在信息足够时停止，以及每题成本与延迟分布。

Agentic RAG 有哪些安全风险？

检索到的文档可能包含提示注入，诱导 Agent 调用其他工具或泄露数据；循环可能耗尽预算。需要把工具结果当作不可信数据、限制工具权限、设置预算与人工审批。
