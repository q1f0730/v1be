📐 01 · 定义

编程语言（Programming Language）是用形式化语法和语义描述计算过程的语言，代码经编译器或解释器转换为机器可执行的指令。语言在类型系统（静态/动态）、执行方式（编译/解释/JIT）、内存管理（手动/垃圾回收/所有权）和生态上各有取舍，选型主要取决于运行平台、团队能力与生态成熟度。

⚙️ 02 · 原理
  1. 1

    词法与语法分析：源代码被切成词法单元，再按语法规则构建抽象语法树（AST）。

  2. 2

    语义检查：检查变量作用域和类型，静态类型语言在这一阶段就能发现大量错误。

  3. 3

    代码生成：编译型语言生成机器码；Java、C# 等生成字节码交给虚拟机执行。

  4. 4

    执行：解释器逐条执行，或由 JIT 在运行时把热点代码编译为机器码以提速。

  5. 5

    运行时支持：内存分配、垃圾回收、异常处理、标准库等由运行时环境提供。

🔤 03 · 术语
静态类型 / 动态类型
类型在编译期检查还是运行时检查。
编译 / 解释 / JIT
提前编译成机器码、逐条解释执行、运行时即时编译。
垃圾回收 (GC)
运行时自动回收不再使用的内存。
运行时 (Runtime)
程序执行所需的环境，如 Node.js、JVM、CPython。
类型推断 (Type Inference)
编译器自动推导变量类型，无需处处标注。
💻 04 · 代码
静态类型提前发现错误typescript
// TypeScript 在编译期检查类型，JavaScript 要到运行时才报错
interface User {
  id: number;
  name: string;
  email?: string;          // 可选字段
}

function greet(user: User): string {
  return `Hello, ${user.name.toUpperCase()}`;
}

greet({ id: 1, name: "Ann" });          // 正确

// greet({ id: 2 });
// 编译错误：Property 'name' is missing in type '{ id: number; }'

function sendMail(user: User) {
  // user.email.trim();
  // 严格模式下报错：'user.email' is possibly 'undefined'
  if (user.email) console.log(user.email.trim());
}
// 运行：npx tsc --noEmit 只做类型检查

静态类型把一部分运行时错误提前到编写阶段，也为 AI 生成代码提供了自动校验信号。

⚖️ 06 · 方案取舍

动态类型语言

优点写得快、灵活、上手容易

代价大型项目重构风险高

适用脚本、原型、数据分析

静态类型语言

优点错误早发现、IDE 与重构支持好

代价前期书写成本更高

适用长期维护、多人协作项目

选 AI 训练语料丰富的语言

优点AI 生成质量通常更高

代价未必是性能最优解

适用主要依赖 AI 编写代码

🕳️ 07 · 常见坑

  • ✗因为「性能更好」给简单 Web 项目选冷门语言

    ✓优先考虑生态、团队熟悉度和招聘，瓶颈通常不在语言

  • ✗TypeScript 项目里到处用 any 绕过检查

    ✓开启 strict 模式，用 unknown 加类型收窄

  • ✗混淆语言版本，如用 Python 2 语法写 Python 3

    ✓在项目中声明语言版本，并在 CI 中固定运行时

🎤 09 · 面试追问
编译型和解释型的界限还清晰吗？

已经模糊。Java 先编译为字节码再由 JVM 解释与 JIT 编译；JavaScript 引擎用 JIT 把热点代码编译为机器码；Python 也会先编译成字节码。更有意义的区分是类型检查时机和运行时模型。

AI 编程时代，类型系统更重要还是更不重要？

更重要。类型检查是零成本的自动验证：AI 生成的代码能否通过类型检查立刻可知，Agent 可以据此自我修正；类型签名也为模型提供更清晰的上下文。很多团队在 AI 辅助开发中更倾向 TypeScript 而非纯 JavaScript。

垃圾回收和所有权有何取舍？

GC 由运行时自动回收内存，开发简单，但有停顿和额外开销；Rust 的所有权在编译期确定内存释放时机，无 GC 停顿且内存安全，但学习曲线陡峭。按延迟敏感度和团队能力选择。
