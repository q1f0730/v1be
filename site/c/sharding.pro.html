数据库水平分片

Sharding

📐 01 · 定义

数据库水平分片（Sharding）把同一张逻辑表的数据按分片键拆分到多个独立数据库节点上，每个节点只存一部分行。它属于数据层的横向扩展手段，用于突破单机在存储容量、写入吞吐和连接数上的上限，代价是跨分片查询、事务和运维复杂度显著上升。

⚙️ 02 · 原理
  1. 1

    选分片键：选择查询中最常用作过滤条件、取值分散的列，如租户 ID 或用户 ID。

  2. 2

    定分片策略：哈希分片均匀但范围查询难；范围分片利于区间查询但易热点；目录分片灵活。

  3. 3

    请求路由：应用层、代理层（如 Vitess）或数据库扩展（如 Citus）根据分片键定位节点。

  4. 4

    跨分片操作：无分片键的查询需扇出到所有分片再合并，跨分片事务需分布式协议或避免。

  5. 5

    扩容再平衡：新增节点后迁移部分数据，常用预先切多个逻辑分片再映射到物理节点。

🔤 03 · 术语
分片键 (Shard Key)
决定一行数据落到哪个分片的列或列组合。
扇出查询 (Scatter-Gather)
查询发往所有分片并汇总结果，成本随分片数增长。
再平衡 (Rebalancing)
增删节点后在分片间迁移数据以恢复均衡。
逻辑分片 (Logical Shard)
数量多于物理节点的虚拟分片，迁移时整块移动。
共置 (Co-location)
相关表按同一分片键放在同一节点，使关联查询本地执行。
💻 04 · 代码
Citus 按租户分片sql
-- PostgreSQL + Citus 扩展：按 tenant_id 把表分布到多个 worker 节点
CREATE EXTENSION IF NOT EXISTS citus;

CREATE TABLE orders (
  tenant_id  bigint NOT NULL,
  order_id   bigint NOT NULL,
  amount     numeric(12,2),
  created_at timestamptz DEFAULT now(),
  PRIMARY KEY (tenant_id, order_id)     -- 主键需包含分布列
);

SELECT create_distributed_table('orders', 'tenant_id');

-- 小而常被关联的维表复制到每个节点
CREATE TABLE countries (code text PRIMARY KEY, name text);
SELECT create_reference_table('countries');

-- 带分片键的查询只路由到一个分片
SELECT sum(amount) FROM orders WHERE tenant_id = 42;

多租户 SaaS 常以租户 ID 为分片键，单租户查询与事务都留在一个分片内。

📊 05 · 参数对比

分片策略对比

策略优点缺点
哈希分片分布均匀，避免顺序写热点范围查询需扇出，扩容需迁移
范围分片区间查询高效递增键导致最新分片成热点
目录/查找表映射灵活，可单独迁移大租户查找表本身成为依赖与瓶颈
⚖️ 06 · 方案取舍

应用层自行分片

优点无额外组件，完全可控

代价路由、迁移、跨片查询全靠自研

适用分片规则简单、团队有经验

中间件/扩展（Vitess、Citus）

优点路由和再平衡有成熟实现

代价引入新组件与运维学习成本

适用MySQL/PG 体系下规模化

原生分布式数据库

优点分片对应用透明，支持分布式事务

代价迁移成本高，部分特性不兼容

适用新系统且预期规模很大

🕳️ 07 · 常见坑

  • ✗过早分片，单机还远未到瓶颈就引入复杂度

    ✓先做索引、读写分离、缓存、分区和垂直扩容

  • ✗分片键选了低基数或单调递增列，数据和流量倾斜

    ✓选高基数且与主要查询匹配的键，必要时用哈希

  • ✗大量查询不带分片键，变成全分片扇出

    ✓按访问模式设计分片键，或为其他维度建冗余索引表

  • ✗分片数与节点数一一对应，扩容需重切全部数据

    ✓预先划分较多逻辑分片，扩容时整片迁移

☑️ 08 · 检查清单
🎤 09 · 面试追问
分片键怎么选？

看访问模式：高频查询和事务都带的列优先，如租户或用户 ID；要求基数高、分布均匀、不随时间单调递增；关联表尽量共置。最终目标是绝大多数请求只命中一个分片。

分片后跨分片事务怎么办？

首选通过分片键设计避免；无法避免时可用两阶段提交（性能和可用性代价高），或拆成本地事务配合 Saga、Outbox 实现最终一致。数据库扩展可能提供分布式事务，但要评估延迟。

分片和分区的区别？

分区在单个数据库实例内把表拆成多个子表，主要改善管理和查询裁剪，不增加机器；分片把数据分布到多台独立节点，解决单机容量与吞吐上限，但带来分布式问题。
