AI 当裁判 (LLM-as-Judge)

LLM-as-a-Judge

📐 01 · 定义

LLM-as-a-Judge 是一种自动评测方法：用一个（通常更强的）大模型，依据评分细则（rubric）对另一个模型的输出打分或做两两比较，以近似人工评价。它位于评测（Evals）层，解决开放式生成任务难以用精确匹配评分、人工评审又慢又贵的问题。

⚙️ 02 · 原理
  1. 1

    定义评测维度和细则：如正确性、完整性、简洁性，每档分数配描述与示例。

  2. 2

    选择模式：单点打分（pointwise）、两两比较（pairwise）或对照参考答案打分（reference-based）。

  3. 3

    构造评审提示：给出问题、待评回答、可选参考答案，要求先写理由再给结构化分数（JSON）。

  4. 4

    去偏处理：两两比较时交换顺序各评一次，固定温度，必要时多次采样取多数或均值。

  5. 5

    校准：用一小批人工标注样本计算与人工的一致率，调整细则后再大规模使用。

🔤 03 · 术语
评分细则 (Rubric)
每个维度、每档分数的明确判定标准，是评审一致性的基础。
位置偏差 (Position Bias)
两两比较时评审模型倾向偏好排在某一位置的回答。
冗长偏差 (Verbosity Bias)
评审倾向给更长的回答更高分，即便信息量并未增加。
自我偏好 (Self-enhancement Bias)
评审模型偏爱自己或同家族模型生成的回答。
一致率 (Agreement Rate)
评审结果与人工标注相同的比例，用于衡量裁判可信度。
💻 04 · 代码
两两比较并交换顺序python
import json
from openai import OpenAI

client = OpenAI()
RUBRIC = "按正确性、完整性、简洁性比较两个回答。先写理由，再输出 JSON：{\"reason\": str, \"winner\": \"A\"|\"B\"|\"tie\"}"

def judge(q, a, b):
    resp = client.chat.completions.create(
        model="gpt-4o-mini",
        temperature=0,                      # 降低随机性
        response_format={"type": "json_object"},
        messages=[{"role": "system", "content": RUBRIC},
                  {"role": "user", "content": f"问题：{q}\n回答A：{a}\n回答B：{b}"}],
    )
    return json.loads(resp.choices[0].message.content)["winner"]

def compare(q, x, y):
    r1 = judge(q, x, y)                     # x 在 A 位
    r2 = judge(q, y, x)                     # 交换位置
    r2 = {"A": "B", "B": "A"}.get(r2, r2)   # 映射回原顺序
    return r1 if r1 == r2 else "tie"        # 不一致视为平局

交换位置各评一次可抵消位置偏差，结论不一致时判平局更稳妥。

📊 05 · 参数对比

三种评审模式

模式输入适用场景
单点打分问题+回答监控线上质量、批量打分
两两比较问题+两个回答模型/提示词 A/B 选型
参考答案对照问题+回答+标准答案事实性问答、有标准解的任务
⚖️ 06 · 方案取舍

LLM 裁判

优点快、便宜、可大规模和持续运行

代价有系统性偏差，需人工校准

适用迭代提示词、回归测试

人工评审

优点可信度高，能发现细微问题

代价慢、贵、评审者之间也不一致

适用建立金标集、关键发布前

规则/程序化检查

优点确定、零成本、可解释

代价只能覆盖格式、可执行性等硬指标

适用JSON 结构、代码能否通过测试

🕳️ 07 · 常见坑

  • ✗用被测模型本身当裁判，分数虚高

    ✓换不同家族或更强的模型当裁判，并用人工样本校准

  • ✗只让裁判给 1–10 分，没有细则，分数漂移

    ✓每档写明判定标准和示例，或改用两两比较

  • ✗从不检查裁判与人工的一致性就上线

    ✓保留一份人工标注集，定期计算一致率并跟踪变化

  • ✗能用程序验证的也交给 LLM 裁判

    ✓可执行的先跑测试或规则，LLM 只评主观维度

🎤 09 · 面试追问
LLM 裁判有哪些已知偏差，如何缓解？

位置偏差：交换顺序双评；冗长偏差：细则中明确不因长度加分，或控制长度；自我偏好：用不同家族模型；分数尺度漂移：改两两比较或给锚点示例。最后都要用人工样本校准。

单点打分和两两比较怎么选？

两两比较对细微差异更敏感、评审更稳定，适合选型和 A/B；但成本随候选数平方增长。单点打分可独立评每条，适合线上监控和趋势跟踪，但尺度容易漂移，需细则锚定。

怎么证明你的裁判可信？

抽取有代表性的样本做人工标注，计算裁判与人工的一致率或相关系数，并与人与人之间的一致率对比；接近人际一致水平才可替代。裁判模型或细则变更后要重新校准。
