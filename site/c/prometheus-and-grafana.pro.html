指标监控 (Prometheus / Grafana)

Prometheus & Grafana

📐 01 · 定义

Prometheus 是 CNCF 毕业的开源监控系统与时序数据库，以拉取（pull）方式定期抓取目标暴露的指标，用 PromQL 查询，并通过 Alertmanager 发送告警；Grafana 是开源可视化平台，连接 Prometheus 等数据源构建看板。二者组合是云原生指标监控的事实标准，属于可观测性层中的指标（metrics）支柱。

⚙️ 02 · 原理
  1. 1

    应用通过客户端库或 exporter 在 /metrics 端点以文本格式暴露计数器、仪表、直方图等指标。

  2. 2

    Prometheus 按 scrape_interval 定期拉取各目标，目标来自静态配置或服务发现（如 Kubernetes）。

  3. 3

    样本以「指标名 + 标签集」标识的时间序列存入本地 TSDB；记录规则可预计算常用查询。

  4. 4

    告警规则持续计算 PromQL 表达式，条件持续满足 for 时长后发给 Alertmanager，由其去重、分组、路由到通知渠道。

  5. 5

    Grafana 以 Prometheus 为数据源执行 PromQL，渲染图表与看板，也可配置自身的告警。

🔤 03 · 术语
时间序列 (Time Series)
由指标名和标签唯一标识的一串带时间戳的样本。
Counter / Gauge / Histogram
只增计数器 / 可增可减的瞬时值 / 分桶分布。
PromQL
Prometheus 查询语言，支持 rate、sum by、histogram_quantile 等。
Exporter
把第三方系统（如数据库、主机）的状态转换为 Prometheus 指标的程序。
基数 (Cardinality)
时间序列数量，由标签取值组合决定，过高会耗尽内存。
Alertmanager
接收告警并负责去重、分组、静默与通知路由的组件。
💻 04 · 代码
抓取配置与告警规则yaml
# prometheus.yml
global:
  scrape_interval: 15s
rule_files: ["alerts.yml"]
alerting:
  alertmanagers:
    - static_configs: [{ targets: ["alertmanager:9093"] }]
scrape_configs:
  - job_name: api
    static_configs:
      - targets: ["api:3000"]        # 应用暴露 http://api:3000/metrics
---
# alerts.yml
groups:
  - name: api
    rules:
      - alert: HighErrorRate
        expr: |
          sum(rate(http_requests_total{job="api",status=~"5.."}[5m]))
          / sum(rate(http_requests_total{job="api"}[5m])) > 0.05
        for: 10m                       # 持续 10 分钟才触发，避免抖动
        labels: { severity: page }
        annotations:
          summary: "API 5xx 错误率超过 5%"

两个文件以 --- 分隔仅为展示；阈值 5% 为示例，应按 SLO 设定。

📊 05 · 参数对比

指标类型选择

类型特点典型指标常用函数
Counter只增，重启归零请求总数、错误总数rate / increase
Gauge可增可减的当前值内存使用、队列长度直接取值、avg_over_time
Histogram按桶累计分布，可跨实例聚合请求耗时、响应大小histogram_quantile
Summary客户端计算分位数单实例耗时分位数不可跨实例聚合分位数

🕳️ 07 · 常见坑

  • ✗把用户 ID、请求 ID 等高基数值作为标签

    ✓标签只用有限取值（状态码、路由模板），高基数信息放日志或追踪

  • ✗对 Counter 直接画图或求和

    ✓先用 rate() 或 increase() 计算速率再聚合

  • ✗用 Summary 分位数做跨实例平均

    ✓需要聚合时使用 Histogram，再 histogram_quantile

  • ✗告警不设 for 或阈值随意，频繁抖动

    ✓设置持续时间，按 SLO 定义阈值并做告警分级

🎤 09 · 面试追问
Prometheus 为什么采用拉模式？

由服务端控制抓取频率，目标是否存活一目了然（抓取失败即 up=0），便于本地调试直接访问 /metrics。短生命周期任务可借助 Pushgateway，但不适合作为通用推送通道。

rate() 和 irate() 有什么区别？

rate 计算区间内的平均每秒增长率，平滑、适合告警与趋势；irate 只用区间内最后两个样本，反映瞬时变化，适合观察快速波动的图表，不适合告警。两者都会处理计数器重置。

高基数问题如何发现与治理？

查看 TSDB 状态页或用 count by (__name__) 找序列最多的指标；删除或改写高基数标签，用 relabel 丢弃无用标签，必要时为每个目标设置样本数上限。
