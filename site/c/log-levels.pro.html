日志级别规范

Log Levels

📐 01 · 定义

日志级别（Log Levels）是给每条日志标注严重程度的分级约定，常见为 DEBUG、INFO、WARN、ERROR、FATAL/CRITICAL，运行时按阈值过滤输出。它属于可观测性规范层，决定日志噪声、存储成本与告警准确性：级别用错会让真正的故障淹没在海量日志里。

⚙️ 02 · 原理
  1. 1

    每个级别对应一个数值，如 Python 中 DEBUG=10、INFO=20、WARNING=30、ERROR=40、CRITICAL=50。

  2. 2

    logger 与 handler 各自设置阈值，只有级别不低于阈值的日志才会被输出。

  3. 3

    阈值通常由环境变量或配置控制：开发环境 DEBUG，生产环境 INFO 或 WARNING。

  4. 4

    支持按模块单独设置级别，如只把某个第三方库调到 WARNING 以减少噪声。

  5. 5

    告警系统通常基于 ERROR 及以上的数量或比例触发，因此级别语义直接影响值班。

🔤 03 · 术语
阈值 (Threshold)
低于该级别的日志被丢弃。
syslog 严重性 (RFC 5424)
0–7 共八级，从 Emergency 到 Debug。
logger 层级 (Logger Hierarchy)
按点分名称继承级别，如 app.db 继承 app。
动态调级 (Dynamic Log Level)
不重启进程临时提高某模块的日志详细度。
惰性求值 (Lazy Formatting)
级别未启用时不执行格式化，减少开销。
💻 04 · 代码
按环境与模块配置级别python
import logging, os

logging.basicConfig(
    level=os.getenv("LOG_LEVEL", "INFO"),       # 生产默认 INFO
    format="%(asctime)s %(levelname)s %(name)s %(message)s",
)
logging.getLogger("urllib3").setLevel(logging.WARNING)  # 压制第三方噪声

log = logging.getLogger("app.payment")

def charge(order_id, amount):
    log.debug("charge request payload built: %s", order_id)   # 排查细节
    log.info("charge succeeded order=%s amount=%s", order_id, amount)
    log.warning("retrying gateway, attempt=%d", 2)  # 可自愈的异常
    try:
        1 / 0
    except ZeroDivisionError:
        # 需要人处理的失败，exception() 自动附带堆栈
        log.exception("charge failed order=%s", order_id)

charge(981, 4999)
# 用 %s 占位而非 f-string：级别未启用时不做格式化

级别由环境变量控制；第三方库单独调高阈值；ERROR 用 exception() 保留堆栈。

📊 05 · 参数对比

级别使用约定

级别含义示例是否告警
DEBUG排查用细节请求参数、分支走向否
INFO正常业务事件订单创建、任务完成否
WARN异常但已自动处理重试成功、降级看趋势
ERROR需要人处理的失败支付失败、未捕获异常是
FATAL/CRITICAL进程无法继续配置缺失无法启动立即
⚖️ 06 · 方案取舍

生产 INFO

优点保留业务轨迹，便于追溯

代价日志量与成本较高

适用大多数服务默认

生产 WARN

优点噪声与成本低

代价排查时缺少上下文

适用超高吞吐服务

动态调级

优点按需打开 DEBUG 不需发版

代价需配置中心或管理接口

适用线上疑难问题排查

🕳️ 07 · 常见坑

  • ✗用户输错密码记为 ERROR，告警被刷爆

    ✓预期内的客户端错误用 INFO 或 WARN，ERROR 留给需处理的问题

  • ✗捕获异常后只记 WARN 且吞掉堆栈

    ✓真正的失败记 ERROR 并附堆栈，或继续抛出

  • ✗生产开 DEBUG 忘记关，磁盘和费用暴涨

    ✓动态调级设置自动过期，并监控日志量

  • ✗在循环热路径里拼接大字符串记 DEBUG

    ✓使用占位符惰性格式化，或先判断 isEnabledFor

🎤 09 · 面试追问
WARN 和 ERROR 的分界线在哪？

看是否需要人介入：系统已自动恢复或降级、不影响结果的记 WARN；请求失败、数据可能不一致、需要排查修复的记 ERROR。原则是每条 ERROR 都应可行动，否则会稀释告警。

4xx 错误应该记什么级别？

多数客户端错误是预期行为，记 INFO 或 DEBUG 并计入指标即可；但异常激增（如大量 401）可能是攻击或客户端 bug，应通过指标告警而非逐条 ERROR。

为什么推荐用占位符而不是 f-string？

占位符格式化在确认级别启用后才执行，DEBUG 关闭时几乎零开销；f-string 无论级别都会先计算字符串。同时占位符形式更便于日志聚合按模板分组。
