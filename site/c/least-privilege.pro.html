最小权限原则

Least Privilege

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

最小权限原则（Principle of Least Privilege，PoLP）要求每个用户、服务、进程和 AI Agent 只拥有完成其任务所必需的最小权限，且只在需要的时间内拥有。它是贯穿身份、云资源、数据库、API 密钥和 Agent 工具设计的安全原则，目的是在凭证泄露或组件被攻破时把损失限制在最小范围。

⚙️ 02 · 原理
  1. 1

    梳理主体需要执行的具体操作和访问的资源，而不是按“可能会用到”授予。

  2. 2

    按操作和资源粒度授权，如只读某个存储桶、只能写某张表，避免使用通配符。

  3. 3

    按职责拆分身份：不同服务、环境、Agent 使用不同凭证，互不共享。

  4. 4

    临时提升：需要高权限时短时授予并自动过期，而不是长期持有管理员权限。

  5. 5

    定期审查实际使用情况，回收未使用的权限，并对权限变更做审计。

🔤 03 · 术语
爆炸半径 (Blast Radius)
某个凭证或组件被攻破时可能造成的影响范围。
职责分离 (Separation of Duties)
关键操作需不同主体共同完成，防止单点滥权。
即时访问 (Just-in-Time Access)
按需临时授予权限，到期自动撤销。
服务账号 (Service Account)
供程序使用的非人身份，应按服务单独创建。
权限蔓延 (Privilege Creep)
权限随时间累积而不回收的现象。
💻 04 · 代码
PostgreSQL 最小权限账号sql
-- 应用运行账号：只能读写业务表，不能改表结构
CREATE ROLE app_rw LOGIN PASSWORD 'from-secret-manager';
GRANT CONNECT ON DATABASE shop TO app_rw;
GRANT USAGE ON SCHEMA public TO app_rw;
GRANT SELECT, INSERT, UPDATE ON orders, order_items TO app_rw;
GRANT SELECT ON products TO app_rw;          -- 商品表只读

-- 报表账号：只读
CREATE ROLE report_ro LOGIN PASSWORD 'from-secret-manager';
GRANT CONNECT ON DATABASE shop TO report_ro;
GRANT USAGE ON SCHEMA public TO report_ro;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO report_ro;

-- 迁移由单独的高权限账号在 CI 中执行，应用账号无 DDL 权限
REVOKE CREATE ON SCHEMA public FROM PUBLIC;

应用、报表、迁移各用独立账号；即使应用存在 SQL 注入，也无法删表。

⚖️ 06 · 方案取舍

细粒度权限

优点风险最小

代价配置和维护成本高

适用生产环境与敏感数据

粗粒度角色

优点管理简单

代价权限过度授予

适用早期原型、非敏感环境

即时临时授权

优点无长期高权限

代价需要审批流程

适用运维、生产故障处理

🕳️ 07 · 常见坑

  • ✗图省事给服务分配管理员角色

    ✓从零权限开始，按报错逐项补充所需权限

  • ✗多个服务共用同一个凭证

    ✓每个服务、每个环境使用独立凭证

  • ✗给 AI 编码 Agent 跳过所有权限确认

    ✓仅在隔离沙箱中放开，常规环境保留确认

  • ✗离职或下线后权限未回收

    ✓定期审计并自动回收闲置权限

☑️ 08 · 检查清单
🎤 09 · 面试追问
最小权限为什么重要？

安全事件无法完全避免，凭证会泄露、代码会有漏洞。最小权限不阻止入侵，但决定了入侵后的损失上限：只读账号泄露不会导致数据被删，受限的 Agent 被注入也无法执行危险命令。它是纵深防御的基础。

如何为一个新服务确定最小权限？

列出服务实际要做的操作和资源；从零权限开始在测试环境运行，根据拒绝记录逐项添加；利用云平台的访问分析工具根据实际调用生成策略；上线后定期对比已授予与实际使用的权限，删除多余部分。

最小权限如何应用到 AI Agent？

只提供任务需要的工具；文件系统限制在项目目录；命令执行用白名单，删除、推送、部署等需人工确认；使用只读或开发环境凭证；在容器中运行并限制网络。这样即使 Agent 被提示注入，损害也受限。
