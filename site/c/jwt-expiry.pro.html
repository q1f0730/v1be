JWT过期时间机制

JWT Expiry

📐 01 · 定义

JWT 过期机制（JWT Expiry）指在 JSON Web Token 的载荷中使用 exp（过期时间）、nbf（生效时间）、iat（签发时间）等注册声明限定令牌有效期，由校验方在每次请求时检查。由于 JWT 通常无状态、签发后难以撤销，较短的过期时间是控制令牌泄露风险的主要手段，常与刷新令牌配合使用。

⚙️ 02 · 原理
  1. 1

    签发时在载荷中写入 exp，值为 Unix 时间戳秒数（NumericDate），表示令牌过期时刻。

  2. 2

    令牌由头部、载荷、签名三段 Base64URL 编码组成，签名保证声明不被篡改。

  3. 3

    校验方先用固定的算法和密钥验证签名，再检查 exp、nbf、iss、aud 等声明。

  4. 4

    当前时间超过 exp（允许少量时钟偏差 leeway）则拒绝，客户端需用刷新令牌换取新令牌。

  5. 5

    需要提前失效时，只能借助黑名单、令牌版本号或缩短有效期等有状态补充手段。

🔤 03 · 术语
exp 声明
过期时间，NumericDate 格式，超过即令牌无效。
时钟偏差 (Clock Skew)
签发方与校验方时间不一致，通常允许小幅容忍。
JWS
JSON Web Signature，带签名的 JWT 形式，载荷未加密可被读取。
aud 声明
令牌的目标受众，校验方应确认令牌是发给自己的。
jti 声明
令牌唯一 ID，可用于黑名单和防重放。
💻 04 · 代码
PyJWT 设置与校验过期python
# pip install pyjwt
import datetime as dt, os
import jwt

SECRET = os.environ["JWT_SECRET"]   # 至少 32 字节随机值
now = dt.datetime.now(dt.timezone.utc)

token = jwt.encode({
    "sub": "user_42",
    "aud": "api.example.com",
    "iat": now,
    "exp": now + dt.timedelta(minutes=15),   # 短有效期
}, SECRET, algorithm="HS256")

try:
    claims = jwt.decode(
        token, SECRET,
        algorithms=["HS256"],       # 显式指定算法，防算法混淆
        audience="api.example.com",
        leeway=30,                   # 容忍 30 秒时钟偏差
    )
    print(claims["sub"])
except jwt.ExpiredSignatureError:
    print("令牌已过期，请用刷新令牌换新")
except jwt.InvalidTokenError as e:
    print("无效令牌:", e)

PyJWT 默认校验 exp；datetime 会被转换为时间戳；必须显式传入 algorithms。

📊 05 · 参数对比

JWT 时间相关声明

声明含义校验行为
exp过期时间当前时间晚于它则拒绝
nbf生效时间当前时间早于它则拒绝
iat签发时间可用于计算令牌年龄
jti唯一标识配合黑名单或防重放
⚖️ 06 · 方案取舍

短期访问令牌（分钟级）

优点泄露窗口小

代价需刷新机制

适用大多数 API 认证

长期 JWT

优点实现简单

代价泄露后长期可用且难撤销

适用不推荐用于用户会话

JWT + 服务端黑名单

优点可立即撤销

代价失去无状态优势

适用需强制登出的场景

🕳️ 07 · 常见坑

  • ✗签发时不设置 exp

    ✓所有用户令牌都设置较短的 exp

  • ✗decode 时未指定 algorithms

    ✓显式限定允许的算法，拒绝 none

  • ✗在 JWT 载荷中放敏感信息

    ✓载荷只是 Base64URL 编码，任何人可读

  • ✗用户改密或登出后旧令牌仍有效

    ✓缩短有效期，或引入令牌版本号/黑名单

🎤 09 · 面试追问
JWT 为什么难以撤销？

JWT 的设计是自包含的：校验方只需验证签名和声明，不查询服务端状态。这带来了扩展性，但也意味着签发后在 exp 之前一直有效。要提前撤销，就必须引入黑名单、版本号等服务端状态，部分抵消无状态的优势。

访问令牌有效期设多长合适？

没有统一值，取决于风险与体验：常见做法是访问令牌设为几分钟到一小时，配合刷新令牌维持登录。越敏感的系统越短。关键是权衡泄露窗口与刷新频率，并确保刷新令牌本身有更严格的保护。

什么是 JWT 算法混淆攻击？

若校验代码信任令牌头部的 alg 字段，攻击者可把算法改为 none 绕过签名，或把 RS256 改为 HS256，用公开的公钥当作 HMAC 密钥伪造签名。防御方法是服务端显式指定允许的算法并按密钥类型校验。
