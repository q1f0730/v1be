报错信息与堆栈

Error Message & Stack Trace

🧸 回到小白版

📐 01 · 定义

报错信息（Error Message）说明出了什么错，通常包含异常类型与描述；堆栈跟踪（Stack Trace）记录异常发生时的函数调用链，每一帧标明文件、行号和函数名。读懂两者能迅速定位故障点并区分是自己的代码还是第三方库的问题，也是交给 AI 修复时最有价值的上下文。

⚙️ 02 · 原理
  1. 1

    调用入栈：程序每调用一个函数，就在调用栈中压入一帧，记录调用位置。

  2. 2

    抛出异常：出错时创建异常对象，携带类型、消息和当前调用栈快照。

  3. 3

    向上传播：异常沿调用栈逐层向上，直到被某层捕获处理，或到达顶层导致程序终止。

  4. 4

    打印输出：未处理的异常由运行时打印类型、消息和每一帧的文件与行号。

  5. 5

    链式原因：处理中再次抛错时，许多语言会附带原始异常（cause），形成异常链。

🔤 03 · 术语
调用栈 (Call Stack)
记录当前正在执行的函数及其调用关系的栈结构。
栈帧 (Stack Frame)
调用栈中的一层，对应一次函数调用。
异常类型 (Exception Type)
如 TypeError、KeyError，指明错误类别。
异常链 (Exception Chaining)
新异常保留引发它的原始异常，便于追溯根因。
Source Map
把压缩后的前端代码位置映射回源码位置。
💻 04 · 代码
读懂 Python 堆栈text
Traceback (most recent call last):          ← Python：越往下越接近出错点
  File "app.py", line 30, in <module>
    main()
  File "app.py", line 25, in main
    total = calc_total(cart)
  File "app.py", line 12, in calc_total     ← 最后一帧自己的代码：优先看这里
    return sum(item["price"] * item["qty"] for item in cart)
  File "app.py", line 12, in <genexpr>
    return sum(item["price"] * item["qty"] for item in cart)
                               ~~~~^^^^^^^
KeyError: 'qty'                              ← 最后一行：异常类型 + 原因

阅读顺序：
1. 先看最后一行：KeyError，字典里没有 'qty' 键
2. 往上找最后一个属于自己项目的文件：app.py 第 12 行
3. 再往上看调用路径：main → calc_total，确认数据从哪里来

注意：JavaScript/Java 相反，第一行是错误信息，紧接着是最内层出错位置

不同语言堆栈的方向不同；核心方法都是先读异常类型，再找第一个属于自己代码的栈帧。

⚖️ 06 · 方案取舍

捕获并处理异常

优点程序可恢复，用户体验好

代价处理不当会掩盖问题

适用可预期的错误，如网络超时

让异常向上抛出

优点问题暴露清晰

代价可能导致请求或进程失败

适用不可恢复的编程错误

包装后重新抛出

优点补充上下文且保留原因

代价需正确保留异常链

适用跨层边界传递错误

🕳️ 07 · 常见坑

  • ✗只看最后一行，忽略上方的调用路径

    ✓顺着栈帧找到第一个属于自己项目的位置

  • ✗构建日志只看最后一条错误

    ✓编译类错误往往第一条才是根因，后续是连锁反应

  • ✗捕获异常后只打印消息，丢失堆栈

    ✓记录完整堆栈，如 logging.exception 或保留 error.stack

  • ✗把含堆栈的错误详情直接返回给用户

    ✓对外显示通用提示与请求 ID，详情写入服务端日志

☑️ 08 · 检查清单
🎤 09 · 面试追问
堆栈里全是第三方库的帧，怎么定位？

向上（Python 往上、JS 往下）找第一个属于自己项目的帧，那通常是你传入错误参数或错误用法的地方；检查调用该库时的参数和版本；搜索异常消息与库的 issue；必要时开启库的调试日志。

生产环境的前端报错为什么看不懂？

生产代码被压缩混淆，堆栈中的文件名和行号对应压缩后的代码。需要在构建时生成 Source Map，并上传到错误监控平台（不必公开给浏览器），平台就能把堆栈还原为源码位置。

异常与错误码各适合什么场景？

异常适合意外、不可忽略的错误，能自动沿调用栈传播并携带堆栈；错误码或结果类型适合可预期的业务失败（如余额不足），迫使调用方显式处理。Go、Rust 偏向显式错误值，Python、Java 偏向异常。
