扩展-收缩式零停机迁移

Expand-Contract Migrations

📐 01 · 定义

扩展-收缩（Expand-Contract）迁移，也称并行变更（Parallel Change），是把破坏性的数据库或接口变更拆成多个各自向后兼容的步骤：先扩展出新结构并让新旧共存，再迁移数据和调用方，最后收缩删除旧结构。它让滚动发布期间新旧版本代码同时运行而不出错，实现零停机变更。

⚙️ 02 · 原理
  1. 1

    扩展：新增列、表或索引，且不影响旧代码，例如新增可空列、在线创建索引。

  2. 2

    双写：新版本代码同时写旧结构与新结构，读仍以旧结构为准，确保回滚安全。

  3. 3

    回填：分批把历史数据迁移到新结构，控制每批大小与速率，避免长事务和复制延迟。

  4. 4

    切换读取：校验新旧数据一致后，代码改为读新结构，可用功能开关逐步放量。

  5. 5

    收缩：确认没有任何调用方再读写旧结构后，停止双写并删除旧列或旧表，每一步可单独发布与回退。

🔤 03 · 术语
并行变更 (Parallel Change)
Martin Fowler 命名的模式，即 expand、migrate、contract 三阶段。
回填 (Backfill)
为新结构补齐历史数据的批量任务。
双写 (Dual Write)
过渡期同时写入新旧两处，保证任一侧都完整。
锁超时 (lock_timeout)
PostgreSQL 参数，DDL 等锁超时即放弃，避免长时间阻塞业务。
NOT VALID 约束
PostgreSQL 先添加不校验存量数据的约束，再单独 VALIDATE，减少锁表时间。
💻 04 · 代码
PostgreSQL 拆分 name 字段sql
-- 第 1 次发布（扩展）：只加可空列，元数据操作，很快
SET lock_timeout = '3s';
ALTER TABLE users ADD COLUMN first_name text, ADD COLUMN last_name text;

-- 第 2 次发布：应用双写 name 与 first/last；后台分批回填
UPDATE users
SET first_name = split_part(name, ' ', 1),
    last_name  = substr(name, length(split_part(name, ' ', 1)) + 2)
WHERE id BETWEEN 1 AND 10000 AND first_name IS NULL;   -- 循环推进区间

-- 在线建索引，不阻塞写入（不能放在事务块中）
CREATE INDEX CONCURRENTLY idx_users_last_name ON users (last_name);

-- 加非空约束：先 NOT VALID，再单独校验
ALTER TABLE users ADD CONSTRAINT first_name_nn
  CHECK (first_name IS NOT NULL) NOT VALID;
ALTER TABLE users VALIDATE CONSTRAINT first_name_nn;

-- 第 3 次发布：读改为新列；观察稳定后（收缩）
ALTER TABLE users DROP COLUMN name;

每段对应一次独立发布；拆名规则仅为演示，真实姓名拆分需按业务规则处理。

📊 05 · 参数对比

常见变更的零停机做法

变更危险做法扩展-收缩做法
重命名列直接 RENAME加新列、双写、切读、删旧列
改列类型ALTER TYPE 重写全表新建列回填后切换
加非空列带校验一次加上可空列、回填、NOT VALID 后 VALIDATE
加索引普通 CREATE INDEX 锁写CREATE INDEX CONCURRENTLY
拆表一次迁移并改代码新表双写、回填、切读、删旧
⚖️ 06 · 方案取舍

扩展-收缩多次发布

优点全程不停机，每步可回退

代价周期长，过渡期代码更复杂

适用高可用在线服务

维护窗口一次迁移

优点步骤简单，数据只有一种形态

代价需要停机，失败回退压力大

适用内部系统或能接受停机

在线 schema 变更工具

优点自动处理影子表与切换（如 gh-ost）

代价引入额外工具与运维成本

适用MySQL 大表结构变更

🕳️ 07 · 常见坑

  • ✗迁移与新代码同一次发布，旧实例读不到旧列

    ✓结构变更先行发布，代码变更随后，保证新旧代码都兼容

  • ✗一个大 UPDATE 回填整张表

    ✓按主键分批、限速，并监控复制延迟与锁等待

  • ✗DDL 等锁时排在长查询后面，阻塞所有后续请求

    ✓设置 lock_timeout 并重试，避开长事务

  • ✗忘记收缩，旧列和双写代码长期残留

    ✓为收缩步骤建工单或截止日期，纳入技术债跟踪

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么不能在同一次发布里加列并删旧列？

滚动发布期间新旧两版代码会同时运行。若删掉旧列，旧版本实例的查询立刻报错；若改名，同理。扩展-收缩保证任一时刻数据库结构同时满足正在运行的所有代码版本，也让每一步可以独立回滚。

回填大表时需要注意什么？

按主键区间分批、每批独立小事务，避免长事务导致 MVCC 膨胀和锁等待；限速并监控复制延迟与 CPU；任务可幂等、可断点续跑；回填期间新写入由双写保证，最后做一致性核对。

AI 生成迁移脚本时如何把关？

检查是否包含会重写全表或长时间持锁的操作（改列类型、普通建索引、带校验的约束）；要求拆成多次发布并说明每步兼容哪些代码版本；确认有 lock_timeout、分批回填和回退脚本，先在生产规模数据的副本上演练。
