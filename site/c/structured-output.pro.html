结构化输出

Structured Output

🧸 回到小白版

📐 01 · 定义

结构化输出（Structured Output）指让大模型按预先定义的数据结构（通常是 JSON Schema）生成结果，使输出可被程序直接解析和校验。它位于模型 API 与应用代码之间，实现方式包括提示约束、JSON 模式和约束解码（Constrained Decoding），后者能保证输出语法符合 schema。

⚙️ 02 · 原理
  1. 1

    开发者用 JSON Schema 或 Pydantic/Zod 模型描述字段、类型、枚举和必填项。

  2. 2

    API 收到 schema 后，严格模式下会将其编译为语法约束，解码时屏蔽不符合语法的 token。

  3. 3

    非严格方式（如仅开启 JSON 模式或在提示中要求 JSON）只保证是合法 JSON 或尽力而为，不保证字段齐全。

  4. 4

    SDK 把返回文本反序列化为对象；模型拒答或输出被截断时，需要检查拒绝字段和结束原因。

  5. 5

    应用层仍要做业务校验，如数值范围、ID 是否存在，因为语法正确不代表内容正确。

🔤 03 · 术语
JSON Schema
描述 JSON 结构的规范，定义类型、必填字段、枚举等约束。
约束解码 (Constrained Decoding)
生成时按语法屏蔽非法 token，从机制上保证格式合规。
JSON 模式 (JSON Mode)
只保证输出是合法 JSON，不保证符合特定 schema。
Pydantic
Python 数据校验库，可由类型注解生成 JSON Schema 并解析结果。
拒绝 (Refusal)
模型出于安全原因不按 schema 输出时，API 返回的单独字段。
💻 04 · 代码
解析为 Pydantic 对象python
from typing import Literal
from openai import OpenAI
from pydantic import BaseModel

class Ticket(BaseModel):
    title: str
    priority: Literal["low", "medium", "high"]
    tags: list[str]

client = OpenAI()
completion = client.chat.completions.parse(
    model="gpt-4o-mini",
    messages=[
        {"role": "system", "content": "从用户描述中提取工单信息"},
        {"role": "user", "content": "登录页一直转圈，客户急着用"},
    ],
    response_format=Ticket,   # SDK 自动转成严格 JSON Schema
)
msg = completion.choices[0].message
if msg.refusal:
    print("模型拒绝:", msg.refusal)
else:
    print(msg.parsed.priority, msg.parsed.tags)

parse 把 Pydantic 类转为 schema 并返回对象，旧版 SDK 中位于 client.beta。

⚖️ 06 · 方案取舍

严格结构化输出

优点免解析失败与重试

代价schema 能力受限，首次编译有延迟

适用数据抽取、程序消费结果

自由文本 + 后处理

优点表达灵活

代价解析脆弱

适用面向人阅读的长文本

先自由推理再结构化

优点保留推理质量

代价多一次调用或多一个字段

适用需要复杂推理的抽取

🕳️ 07 · 常见坑

  • ✗格式对了就直接入库

    ✓再做业务校验：范围、引用完整性、去重

  • ✗schema 字段只写名字不写描述

    ✓为字段加 description，说明含义和取值规则

  • ✗强制只输出结论字段，推理质量下降

    ✓在 schema 中先放 reasoning 字段，再放结论字段

  • ✗忽略 max_tokens 截断导致 JSON 不完整

    ✓检查 finish_reason，留足输出长度

🎤 09 · 面试追问
约束解码是如何保证格式的？

把 JSON Schema 转成上下文无关文法或有限状态机，每一步解码时计算哪些 token 能使当前前缀仍合法，把其余 token 的概率置零。这样无论模型多想输出别的，采样结果都只能落在合法语言内。

结构化输出会不会降低答案质量？

有可能。强制格式会改变模型的生成分布，尤其当结论字段排在前面、缺少推理空间时。常见做法是让 schema 先包含推理或证据字段，或者先自由生成再做一次结构化转换，并用评测集量化差异。

结构化输出和工具调用怎么选？

目标是让模型直接回复一份数据时用结构化输出；目标是让模型决定调用哪个外部动作及参数时用工具调用。两者底层都依赖 schema，区别在语义：前者是最终答案，后者是中间动作请求。
