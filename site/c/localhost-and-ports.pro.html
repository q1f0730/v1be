localhost 与端口

localhost & Ports

📐 01 · 定义

localhost 是指向本机的保留主机名，通常解析为 IPv4 回环地址 127.0.0.1 或 IPv6 的 ::1，流量不离开本机。端口（Port）是 0–65535 的 16 位编号，用来区分同一台机器上不同的网络服务。「地址 + 端口」唯一确定一个服务入口，本地开发时各种服务就靠不同端口共存。

⚙️ 02 · 原理
  1. 1

    名称解析：系统把 localhost 解析为回环地址，通常由 hosts 文件或系统内置规则完成。

  2. 2

    回环接口：发往 127.0.0.0/8 的数据包由操作系统内部回送，不经过物理网卡。

  3. 3

    端口绑定：服务启动时向系统申请监听某个端口，同一地址同一端口只能被一个进程占用。

  4. 4

    连接建立：客户端连接「地址:端口」，系统把数据交给监听该端口的进程。

  5. 5

    绑定地址决定可达范围：绑定 127.0.0.1 仅本机可访问，绑定 0.0.0.0 则所有网卡都可访问。

🔤 03 · 术语
回环地址 (Loopback)
127.0.0.0/8 与 ::1，发往它的数据只在本机内部流转。
0.0.0.0
监听时表示绑定本机所有 IPv4 网卡，局域网也可访问。
知名端口 (Well-known Ports)
0–1023，分配给 HTTP(80)、HTTPS(443)、SSH(22) 等标准服务。
端口占用 (EADDRINUSE)
目标端口已被其他进程监听导致启动失败的错误。
端口转发 (Port Forwarding)
把一个地址端口的流量转到另一个，如 SSH 隧道、容器端口映射。
💻 04 · 代码
排查端口占用bash
# 查看谁占用了 3000 端口（macOS / Linux）
lsof -i :3000

# Linux 也可以用 ss 列出所有监听端口及进程
sudo ss -tlnp

# Windows（PowerShell）
# Get-NetTCPConnection -LocalPort 3000 | Select OwningProcess

# 结束占用进程（确认是自己的开发服务后再执行）
kill <PID>

# 或者换个端口启动（多数开发服务器支持 PORT 变量或参数）
PORT=3001 npm run dev

# 测试服务是否在本机可达
curl -i http://localhost:3001

端口冲突是本地开发最常见的启动失败原因，先查占用进程再决定是结束还是换端口。

⚖️ 06 · 方案取舍

绑定 127.0.0.1

优点只有本机可访问，最安全

代价手机、同事无法访问

适用默认开发场景

绑定 0.0.0.0

优点局域网设备可访问，便于真机测试

代价同网络的人都能访问

适用受信任网络下的移动端调试

隧道服务暴露公网

优点外网临时访问本地服务

代价暴露面大，需注意鉴权

适用Webhook 调试、临时演示

🕳️ 07 · 常见坑

  • ✗容器里服务监听 127.0.0.1，宿主机访问不到

    ✓容器内应监听 0.0.0.0，再通过端口映射控制对外暴露

  • ✗localhost 解析到 ::1，服务只监听 IPv4 导致连不上

    ✓直接用 127.0.0.1，或让服务同时监听 IPv4 与 IPv6

  • ✗把含 localhost 的地址发给别人或写进生产配置

    ✓localhost 永远指「当前这台机器」，生产用真实域名

  • ✗数据库端口映射到 0.0.0.0 暴露在公网

    ✓映射写成 127.0.0.1:5432:5432，服务器上配防火墙

🎤 09 · 面试追问
localhost 和 127.0.0.1 完全等价吗？

通常等价但不完全相同：localhost 是主机名，需要解析，可能解析到 IPv6 的 ::1；127.0.0.1 是确定的 IPv4 地址。若服务只监听 IPv4，访问 localhost 可能失败。浏览器对 localhost 还有特殊处理，如视为安全上下文。

为什么 Linux 上普通用户不能直接监听 80 端口？

传统上 1024 以下端口为特权端口，绑定需要 root 或相应能力（CAP_NET_BIND_SERVICE）。常见做法是应用监听高位端口，由 Nginx 等反向代理或负载均衡对外监听 80/443。

Docker 中 -p 3000:3000 是什么意思？

把宿主机的 3000 端口映射到容器的 3000 端口，默认绑定宿主机所有网卡。写成 -p 127.0.0.1:3000:3000 只允许本机访问。容器内服务必须监听 0.0.0.0，否则映射后仍无法访问。
