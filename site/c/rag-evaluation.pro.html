RAG 评测 (召回率 / 忠实度)

RAG Evaluation

📐 01 · 定义

RAG 评测（RAG Evaluation）是对检索增强生成系统分环节量化质量的方法：检索端衡量是否找回了回答所需的上下文（召回率、精确率、MRR、nDCG），生成端衡量回答是否忠于上下文（忠实度/有据性）、是否切题（答案相关性）以及是否正确。它属于 LLM 应用的评测与质量保障层，代表工具有 RAGAS、TruLens 等。

⚙️ 02 · 原理
  1. 1

    构建评测集：问题、参考答案，最好还有标注的相关文档或片段 ID，覆盖常见、困难与无答案问题。

  2. 2

    检索评测：对每个问题运行检索，计算 Recall@k、Precision@k、MRR、nDCG 等，与标注的相关片段对比。

  3. 3

    生成评测：用 LLM-as-a-judge 或 NLI 模型把回答拆成陈述，检查每条是否能由检索上下文支持，得到忠实度。

  4. 4

    端到端评测：比较回答与参考答案的正确性，并评估答案相关性、拒答是否恰当。

  5. 5

    把评测集成到迭代流程：切块、嵌入模型、重排、提示的每次改动都重跑并对比，回归即阻断。

🔤 03 · 术语
Recall@k
前 k 个检索结果中覆盖了多少比例的相关片段。
MRR (Mean Reciprocal Rank)
第一个相关结果排名倒数的平均值，衡量排序。
忠实度 (Faithfulness)
回答中的陈述能被检索上下文支持的比例。
上下文精确率 (Context Precision)
检索到的上下文中真正相关内容是否排在前面。
答案相关性 (Answer Relevancy)
回答与问题的切题程度，不衡量事实正确性。
💻 04 · 代码
计算检索指标 Recall@k 与 MRRpython
def recall_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    if not relevant:
        return 1.0
    return len(set(retrieved[:k]) & relevant) / len(relevant)

def reciprocal_rank(retrieved: list[str], relevant: set[str]) -> float:
    for i, doc_id in enumerate(retrieved, start=1):
        if doc_id in relevant:
            return 1 / i
    return 0.0

# 评测集：每题标注相关片段 ID；retrieve() 为待评测的检索函数
dataset = [
    {"q": "退货期限是多久？", "relevant": {"policy#3"}},
    {"q": "国际运费怎么算？", "relevant": {"ship#1", "ship#4"}},
]
recalls, rrs = [], []
for item in dataset:
    ids = retrieve(item["q"], top_k=5)          # 返回片段 ID 列表
    recalls.append(recall_at_k(ids, item["relevant"], k=5))
    rrs.append(reciprocal_rank(ids, item["relevant"]))
print(f"Recall@5={sum(recalls)/len(recalls):.2f}  MRR={sum(rrs)/len(rrs):.2f}")
# 生成端忠实度等指标可用 RAGAS 等库，以 LLM 作为评审计算

检索指标确定、便宜，可每次提交运行；忠实度依赖 LLM 评审，需抽样人工校准。

📊 05 · 参数对比

按环节选择指标

环节指标需要的标注
检索Recall@k、Precision@k相关片段 ID
排序MRR、nDCG相关片段（可带分级）
生成-有据性忠实度无需参考答案，需上下文

⚖️ 06 · 方案取舍

确定性检索指标

优点便宜、稳定、可复现

代价需要标注相关片段

适用调切块、嵌入、重排

LLM-as-a-judge

优点无需大量标注，可评语义

代价评审有偏差与波动，有成本

适用评忠实度与相关性

人工评测

优点最可信

代价慢且贵

适用校准自动指标、上线前抽检

🕳️ 07 · 常见坑

  • ✗只看最终回答好坏，不分环节

    ✓分别评测检索与生成，才知道该改哪里

  • ✗评测集只有简单问题

    ✓覆盖多跳、对比、无答案与口语化问题

  • ✗完全信任 LLM 评审分数

    ✓抽样人工复核，计算与人工判断的一致性

  • ✗评测集与调参用同一批数据

    ✓保留独立测试集，防止过拟合评测

🎤 09 · 面试追问
忠实度高但回答错误，可能是什么原因？

回答忠于检索上下文，但上下文本身错误、过时或不相关，问题在检索或知识库；也可能参考答案标注有误。需结合上下文召回与知识库质量排查。

没有人工标注时如何起步？

用 LLM 从文档片段生成问题，天然知道相关片段 ID（合成数据），再人工筛查一部分；同时收集真实用户问题与反馈，逐步替换和补充。

召回率和精确率在 RAG 中如何权衡？

召回不足则答案缺信息、模型可能编造；精确率低则上下文噪音多、成本上升，且可能被无关内容干扰。常见做法是检索阶段多召回，再用重排器提升前几名的精确率。
