Web Worker 多线程

Web Workers

📐 01 · 定义

Web Worker 是浏览器提供的后台线程机制，让 JavaScript 在主线程之外执行计算密集型任务，避免阻塞渲染与用户交互。Worker 拥有独立的全局作用域和事件循环，不能访问 DOM，通过 postMessage 与主线程异步通信。常见类型有专用 Worker、共享 Worker，Service Worker 则主要用于网络代理与离线缓存。

⚙️ 02 · 原理
  1. 1

    主线程用 new Worker(url) 创建 Worker，现代浏览器支持 type: 'module' 以 ES 模块方式加载。

  2. 2

    双方通过 postMessage 发送消息，数据默认经结构化克隆算法复制，监听 message 事件接收。

  3. 3

    对 ArrayBuffer、MessagePort、OffscreenCanvas 等可转移对象，可在 postMessage 时转移所有权，实现零拷贝。

  4. 4

    Worker 内可用 fetch、IndexedDB、WebAssembly 等能力，但不能访问 window 与 DOM，结果需发回主线程渲染。

  5. 5

    需要真正共享内存时使用 SharedArrayBuffer 配合 Atomics，这要求页面启用跨源隔离（COOP 与 COEP 响应头）。

🔤 03 · 术语
主线程 (Main Thread)
负责执行页面 JS、样式计算、布局与绘制的线程，长任务会造成卡顿。
结构化克隆 (Structured Clone)
postMessage 默认使用的深拷贝算法，支持多数内置类型，不支持函数。
可转移对象 (Transferable)
可转移所有权而非复制的对象，转移后发送方不能再使用。
跨源隔离 (Cross-Origin Isolation)
通过 COOP/COEP 头启用的页面状态，是使用 SharedArrayBuffer 的前提。
长任务 (Long Task)
主线程上超过 50 毫秒的任务，会影响交互响应指标。
💻 04 · 代码
模块 Worker 处理大数组javascript
// main.js —— 主线程
const worker = new Worker(new URL('./worker.js', import.meta.url), { type: 'module' })

const data = new Float64Array(10_000_000).map(() => Math.random())
worker.postMessage(data.buffer, [data.buffer])   // 转移所有权，零拷贝
// 此后 data.buffer 在主线程中已不可用（byteLength 变为 0）

worker.onmessage = (e) => {
  document.querySelector('#result').textContent = `均值：${e.data.mean.toFixed(4)}`
  worker.terminate()                             // 用完释放线程
}
worker.onerror = (e) => console.error('Worker 出错', e.message)

// worker.js —— 后台线程，无法访问 document
self.onmessage = (e) => {
  const arr = new Float64Array(e.data)
  let sum = 0
  for (let i = 0; i < arr.length; i++) sum += arr[i]
  self.postMessage({ mean: sum / arr.length })
}

两段为两个文件；new URL(..., import.meta.url) 写法可被 Vite、webpack 5 等打包器识别。

浏览器中的几种 Worker

类型作用域典型用途

⚖️ 06 · 方案取舍

Web Worker

优点真正并行，不阻塞界面

代价通信开销，无法直接操作 DOM

适用持续较长的 CPU 密集计算

主线程分片（时间切片）

优点无需额外线程，可访问 DOM

代价总耗时不变，只是让出主线程

适用必须操作 DOM 的批量更新

交给服务器处理

优点不受设备性能限制

代价网络延迟，数据需上传

适用数据量大或涉及敏感算法

🕳️ 07 · 常见坑

  • ✗频繁发送大对象，克隆开销抵消并行收益

    ✓使用可转移对象，或批量发送、减少消息次数

  • ✗每个任务新建 Worker，启动开销大

    ✓复用 Worker 或使用 Worker 池

  • ✗直接使用 SharedArrayBuffer 却报未定义

    ✓为页面配置 COOP/COEP 响应头启用跨源隔离

  • ✗未处理 Worker 错误，任务静默失败

    ✓监听 error 与 messageerror 事件并向用户反馈

🎤 09 · 面试追问
Web Worker 为什么不能访问 DOM？

DOM 不是线程安全的，浏览器渲染引擎假设只有主线程修改它。若允许多线程并发修改，需要复杂锁机制并带来竞态。因此 Worker 只做计算，通过消息把结果交回主线程统一更新界面。

postMessage 的结构化克隆和转移有什么区别？

克隆会复制一份数据，双方各持一份，大对象耗时耗内存；转移只移交底层内存所有权，几乎零开销，但发送方的对象随即失效。适合一次性交给 Worker 处理的大缓冲区。

在浏览器里跑本地 AI 模型时 Worker 有什么作用？

模型加载与推理是重计算，放在主线程会冻结界面。常见做法是在 Worker 中加载 WebAssembly 或调用 WebGPU 推理，主线程只负责输入和渲染，通过消息流式接收生成结果，保持页面可滚动可点击。
