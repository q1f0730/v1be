代码编辑器与 IDE

Code Editor / IDE

📐 01 · 定义

代码编辑器（Code Editor）是面向源码的文本编辑工具，IDE（集成开发环境）在其上集成语言智能、调试、构建、测试与版本控制。VS Code 一类可扩展编辑器借助语言服务器协议（LSP）获得接近 IDE 的能力；Cursor、Windsurf 等则在 VS Code 基础上深度集成 AI Agent。它是开发者与代码交互的主界面层。

⚙️ 02 · 原理
  1. 1

    编辑器负责文本缓冲、语法高亮（如 TextMate 语法或 Tree-sitter）、多光标与搜索替换等基础编辑能力。

  2. 2

    语言服务器以独立进程运行，通过 LSP 提供补全、跳转定义、查找引用、重命名与诊断信息。

  3. 3

    调试通过调试适配器协议（DAP）对接各语言调试器，实现断点、单步与变量查看。

  4. 4

    扩展、工作区设置与任务配置（.vscode/ 目录）把格式化、Lint、测试串入保存与运行流程。

  5. 5

    AI 编辑器在此之上读取打开文件、项目索引与终端输出作为上下文，生成补全、编辑与多文件改动。

🔤 03 · 术语
LSP (Language Server Protocol)
编辑器与语言服务器之间的 JSON-RPC 协议，一次实现多编辑器复用。
DAP (Debug Adapter Protocol)
编辑器与调试器之间的通用协议，统一断点与单步等操作。
工作区设置 (Workspace Settings)
存于项目 .vscode/settings.json，对团队成员统一生效。
推荐扩展 (Recommended Extensions)
.vscode/extensions.json 中列出，打开项目时提示安装。
代码索引 (Codebase Indexing)
AI 编辑器为检索相关代码建立的索引，影响上下文质量。
💻 04 · 代码
团队共享的工作区设置json
// .vscode/settings.json（JSONC，允许注释）
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode",
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  "files.trimTrailingWhitespace": true,
  "files.insertFinalNewline": true,
  // 让编辑器与 Agent 使用项目虚拟环境
  "python.defaultInterpreterPath": "${workspaceFolder}/.venv/bin/python",
  "[python]": {
    "editor.defaultFormatter": "charliermarsh.ruff"
  }
}

把格式化与 Lint 规则放进仓库，人和 AI 改出的代码风格才一致；扩展需另行安装。

🕳️ 07 · 常见坑

  • ✗格式化规则只存在个人设置里

    ✓提交 .vscode/settings.json 与格式化配置文件，CI 中也执行检查

  • ✗编辑器选错解释器或 Node 版本，报错与终端不一致

    ✓在工作区设置中固定解释器路径，配合 .nvmrc 等版本文件

  • ✗在 AI 编辑器中打开含密钥的目录未做排除

    ✓配置忽略文件（如 .cursorignore），密钥放环境变量

  • ✗安装来路不明的扩展

    ✓核对发布者与下载量，团队维护推荐扩展清单

🎤 09 · 面试追问
LSP 解决了什么问题？

过去每个编辑器要为每种语言单独实现补全、跳转等功能，是 M×N 的工作量。LSP 把语言智能放进独立服务器，编辑器只实现协议客户端，变成 M+N，使 VS Code、Neovim 等共享同一语言服务器。

团队如何保证人和 AI 写出的代码风格一致？

格式化器与 Linter 配置入库；工作区设置启用保存时格式化；pre-commit 钩子与 CI 再次检查；规则文件向 Agent 说明代码约定与常用命令，让其改完自行运行检查。

选 AI 编辑器时要评估哪些安全点？

代码与上下文是否上传、保留多久、是否用于训练；能否本地或私有模型；忽略文件机制；Agent 执行终端命令的权限与确认策略；企业版的审计与 SSO 能力。
