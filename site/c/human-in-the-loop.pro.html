人在回路

Human-in-the-Loop

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

人在回路（Human-in-the-Loop, HITL）是在自动化或 AI 智能体的执行流程中设置人工检查点的设计模式：在高风险、不可逆或低置信度的步骤暂停，由人批准、修改或拒绝后再继续。它属于 Agent 编排与治理层，在自动化效率和安全可控之间取得平衡，也为后续评测与训练积累人工反馈。

⚙️ 02 · 原理
  1. 1

    按风险给操作分级：只读操作自动执行，写入、付款、对外发送、删除等需要审批。

  2. 2

    执行到检查点时，智能体暂停并保存当前状态，向人展示拟执行的操作、参数和理由。

  3. 3

    人可以批准、修改参数、拒绝或给出反馈，决定通过界面或消息回传。

  4. 4

    系统从保存的检查点恢复执行；若被拒绝，智能体根据反馈调整方案。

  5. 5

    记录每次审批的内容、决定人与时间，用于审计，并据此调整自动化边界。

🔤 03 · 术语
审批门 (Approval Gate)
流程中必须获得人工批准才能继续的节点。
中断与恢复 (Interrupt/Resume)
暂停执行并持久化状态，收到输入后继续。
检查点 (Checkpoint)
保存的执行状态快照，支持暂停后恢复。
审批疲劳 (Approval Fatigue)
审批请求过多导致人不看内容就点同意。
权限模式 (Permission Mode)
编码 Agent 中决定哪些操作需确认的配置。
💻 04 · 代码
按风险分级的审批门python
import json

RISK = {
    "read_file": "low",
    "search": "low",
    "write_file": "medium",
    "send_email": "high",
    "delete_records": "high",
}

def approve(tool: str, args: dict) -> dict | None:
    """返回（可能被修改的）参数；拒绝返回 None"""
    print(f"\n[待审批] {tool}\n{json.dumps(args, ensure_ascii=False, indent=2)}")
    choice = input("批准 y / 拒绝 n / 修改 e: ").strip().lower()
    if choice == "y":
        return args
    if choice == "e":
        return json.loads(input("输入修改后的 JSON 参数: "))
    return None

def execute(tool: str, args: dict, tools: dict):
    level = RISK.get(tool, "high")          # 未登记的工具按高风险处理
    if level != "low":
        args = approve(tool, args)
        if args is None:
            return {"status": "rejected", "tool": tool}   # 反馈给智能体
    return tools[tool](**args)

未知工具默认高风险；人可批准、改参或拒绝，拒绝结果回传给智能体继续规划。

📊 05 · 参数对比

审批粒度选择

粒度适用场景风险
每个操作都审批初期试运行、高风险环境效率低，审批疲劳
按风险分级审批大多数生产 Agent风险分级需持续维护
计划级审批多步任务，先批准整体计划执行偏离计划需检测
事后抽检低风险批量任务问题发现滞后
⚖️ 06 · 方案取舍

全自动

优点最快，无需人工

代价错误直接生效

适用低风险、可回滚的操作

关键步骤审批

优点在可控前提下保持效率

代价需要定义风险边界

适用涉及资金、外发、删除

全部人工确认

优点最安全

代价抵消自动化价值，易疲劳

适用新上线或高合规场景

🕳️ 07 · 常见坑

  • ✗审批界面只显示「是否继续？」

    ✓展示具体操作、参数、影响范围与回滚方式

  • ✗审批请求太多，用户习惯性全部批准

    ✓只对高风险操作审批，低风险自动化并事后可查

  • ✗暂停后状态只在内存里，进程重启就丢失

    ✓检查点持久化，支持跨进程恢复

  • ✗把模型自报的置信度当作是否需要审批的唯一依据

    ✓以操作类型与影响范围为主要依据

☑️ 08 · 检查清单
🎤 09 · 面试追问
如何决定哪些操作需要人工审批？

看不可逆性、影响范围和外部可见性：删除数据、付款、对外发送、生产变更、权限修改需要审批；只读和可轻易回滚的操作可自动执行。未登记的新工具默认按高风险处理。

如何避免审批疲劳？

减少低价值审批：按风险分级、批准整体计划而非逐步、允许对某类安全操作设置「本次会话不再询问」；审批界面突出关键差异，让人能快速做出有效判断。

HITL 在编码 Agent 中如何体现？

编码 Agent 通常有权限模式：读文件自动执行，编辑文件、运行命令或访问网络需确认，也可按规则预先允许或拒绝某些命令。高风险操作如推送代码、删除文件建议始终保留确认。
