非Root权限运行容器

Non-Root Containers

🧸 回到小白版

📐 01 · 定义

非 root 容器（Non-Root Containers）指容器主进程以非特权用户（UID 非 0）而非默认的 root 运行。容器与宿主机共享内核，以 root 运行时一旦有逃逸漏洞或错误挂载，攻击者可能拿到宿主机高权限。它是最小权限基线，Pod 安全标准 restricted 级别即要求非 root。

⚙️ 02 · 原理
  1. 1

    在 Dockerfile 中创建专用用户，并用 USER 指令切换，或选用自带非 root 用户的基础镜像。

  2. 2

    确保应用需要写入的目录归属于该用户，其余文件和目录保持只读，避免权限报错。

  3. 3

    Kubernetes 中用 securityContext 设置 runAsNonRoot 与 runAsUser，kubelet 会拒绝以 root 启动。

  4. 4

    进一步禁止提权、丢弃全部 Linux 能力、启用只读根文件系统和 seccomp 默认配置。

  5. 5

    应用监听 8080 等高位端口，避免为了绑定低位端口而需要额外特权。

🔤 03 · 术语
UID 0
Linux 中 root 用户的 ID，容器内默认即为它。
Linux 能力 (Capabilities)
把 root 权限拆分成的细粒度特权，如 NET_BIND_SERVICE。
runAsNonRoot
Kubernetes 安全上下文字段，镜像以 root 运行时拒绝启动。
allowPrivilegeEscalation
控制进程能否获得比父进程更多权限，如通过 setuid。
Rootless 模式
连容器运行时本身也以非 root 运行，比非 root 容器更进一步。
💻 04 · 代码
Pod 安全上下文yaml
# Dockerfile 中对应：
#   RUN useradd --uid 10001 --no-create-home app
#   USER 10001
apiVersion: v1
kind: Pod
metadata: { name: api }
spec:
  securityContext:
    runAsNonRoot: true           # 镜像若以 root 运行则拒绝启动
    runAsUser: 10001
    fsGroup: 10001               # 挂载卷归属该组，便于写入
    seccompProfile: { type: RuntimeDefault }
  containers:
    - name: api
      image: example/api:1.0
      ports: [{ containerPort: 8080 }]   # 高位端口，无需特权
      securityContext:
        allowPrivilegeEscalation: false
        readOnlyRootFilesystem: true
        capabilities: { drop: ["ALL"] }
      volumeMounts: [{ name: tmp, mountPath: /tmp }]
  volumes: [{ name: tmp, emptyDir: {} }]

满足 Pod 安全标准 restricted 的主要要求；只读根文件系统下用 emptyDir 提供可写目录。

🕳️ 07 · 常见坑

  • ✗USER 用用户名而非数字 UID，runAsNonRoot 无法校验。

    ✓Dockerfile 中使用数字 UID，或在 Pod 中显式设置 runAsUser。

  • ✗切换用户后应用无法写缓存目录，启动报权限错误。

    ✓为可写目录设置属主，或挂载 emptyDir。

  • ✗为绑定 80 端口给容器加特权。

    ✓应用监听高位端口，由 Service 映射到 80。

  • ✗挂载 Docker socket 到非 root 容器，以为很安全。

    ✓访问 Docker socket 等同宿主机 root，应避免。

🎤 09 · 面试追问
容器已经隔离了，为什么还要非 root？

容器与宿主机共享内核，隔离依赖命名空间和 cgroup。一旦出现内核或运行时漏洞、错误的卷挂载或特权配置，容器内的 root 可能直接获得宿主机 root。非 root 让攻击者即使逃逸也只拿到普通用户权限。

为什么 runAsNonRoot 要配合数字 UID？

kubelet 只能根据镜像元数据中的数字 UID 判断是否为 root；若镜像 USER 写的是用户名，kubelet 无法确认，会拒绝启动。因此 Dockerfile 用数字 UID，或在 Pod 中显式指定 runAsUser。

非 root 容器和 rootless 模式有什么区别？

非 root 容器指容器内进程不是 root，但运行时守护进程可能仍以 root 运行；rootless 模式让 Docker 或 Podman 运行时本身也在非特权用户下运行，进一步降低运行时被攻破的影响。两者可以叠加。
