反向代理 (Nginx)

Reverse Proxy

📐 01 · 定义

反向代理（Reverse Proxy）是部署在服务端、代表后端服务接收客户端请求的中间层。客户端只与代理通信，代理再把请求转发给内部服务。它集中承担 TLS 终止、路由、压缩、缓存、限流和安全过滤等横切职责，常见实现有 Nginx、Caddy、Envoy、Traefik。

⚙️ 02 · 原理
  1. 1

    客户端 DNS 解析到代理的地址，与代理建立连接并完成 TLS 握手。

  2. 2

    代理按 Host、路径等规则匹配，把请求转发给对应的上游服务。

  3. 3

    转发时改写或添加请求头，如 X-Forwarded-For、X-Forwarded-Proto，告知后端原始信息。

  4. 4

    代理接收上游响应，可先缓冲、压缩或写入缓存，再返回给客户端。

  5. 5

    代理在入口统一实施超时、请求体大小限制、限流、访问日志等策略。

🔤 03 · 术语
正向代理 (Forward Proxy)
代表客户端访问外部，与反向代理方向相反。
TLS 终止 (TLS Termination)
在代理上解密 HTTPS，内部再转发。
X-Forwarded-For
事实标准请求头，记录经过的客户端与代理 IP 链。
Forwarded
RFC 7239 定义的标准化转发信息头。
响应缓冲 (Proxy Buffering)
代理先接收上游响应再发给客户端，影响流式输出。
可信代理 (Trusted Proxy)
后端只信任来自已知代理地址的转发头。
💻 04 · 代码
Nginx 反向代理配置text
server {
    listen 443 ssl;
    server_name app.example.com;
    ssl_certificate     /etc/ssl/app/fullchain.pem;
    ssl_certificate_key /etc/ssl/app/privkey.pem;
    client_max_body_size 20m;                    # 上传大小上限

    location /api/ {
        proxy_pass http://127.0.0.1:3000;        # 转发给本机 Node 服务
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }

    location /api/stream {                      # SSE/AI 流式输出
        proxy_pass http://127.0.0.1:3000;
        proxy_buffering off;                     # 关闭缓冲，逐块下发
        proxy_read_timeout 1h;
    }

    location /ws {                               # WebSocket 升级
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}

转发头告诉后端原始协议与 IP；流式接口需关缓冲，WebSocket 需透传 Upgrade。

⚖️ 06 · 方案取舍

代理处终止 TLS

优点证书集中管理，后端简单

代价代理到后端是明文，需内网隔离

适用可信内网的常规部署

端到端 TLS / mTLS

优点内部流量也加密并鉴权

代价证书分发与轮换复杂

适用零信任或合规要求

托管边缘代理（CDN）

优点抗 DDoS、全球就近接入

代价配置受平台限制，有费用

适用面向公网的大流量站点

🕳️ 07 · 常见坑

  • ✗后端无条件信任 X-Forwarded-For，IP 可被伪造

    ✓只信任来自已知代理的头，按跳数取真实 IP

  • ✗AI 流式接口经代理后一次性才返回

    ✓关闭代理缓冲，后端设置 X-Accel-Buffering: no

  • ✗后端生成的跳转链接变成 http 或内网地址

    ✓传递 Host 与 X-Forwarded-Proto，并配置框架信任代理

  • ✗代理超时短于后端处理时间，返回 504

    ✓按接口设置合理超时，长任务改异步

🎤 09 · 面试追问
反向代理和负载均衡器是什么关系？

负载均衡是反向代理的一种功能。反向代理泛指在服务端代收请求的中间层，可只代理一个后端，侧重 TLS、路由、缓存、安全；当它把流量分到多个后端时就承担了负载均衡。Nginx、Envoy 两者兼备。

如何在代理链后正确获取客户端 IP？

X-Forwarded-For 按“客户端, 代理1, 代理2”追加。应从右往左跳过已知可信代理，取第一个不可信的地址；框架中配置可信代理列表（如 Express 的 trust proxy）。最左边的值可被客户端伪造。

为什么 SSE 经过 Nginx 后不流式了？

Nginx 默认开启 proxy_buffering，会先缓冲上游响应再发出，小块数据被攒起来。需在 location 中关闭缓冲，或由后端返回 X-Accel-Buffering: no；同时调大读超时，并关闭可能干扰的压缩。
