电脑 / 浏览器操作智能体

Computer Use Agents

📐 01 · 定义

电脑/浏览器操作智能体（Computer Use Agents）是通过“看屏幕—决定动作—执行鼠标键盘操作”循环来使用图形界面的 AI Agent。模型以截图（有时加上可访问性树或 DOM）为输入，输出点击坐标、输入文本、滚动等动作，由运行环境执行。它能操作没有 API 的系统，但速度慢、可靠性有限，并面临网页内容提示注入等安全风险。

⚙️ 02 · 原理
  1. 1

    运行环境（虚拟机、容器或浏览器实例）截取当前屏幕，连同任务描述和历史动作发给模型。

  2. 2

    模型理解界面元素，输出结构化动作，如 click(x, y)、type(text)、key("Enter")、scroll。

  3. 3

    执行器（如 xdotool、Playwright）在环境中执行动作，等待页面稳定后再次截图。

  4. 4

    循环直到任务完成、达到步数上限，或遇到需要人类介入的步骤（登录、验证码、付款确认）。

  5. 5

    另一类实现不靠像素坐标，而是读取 DOM 或可访问性树，用选择器操作元素，速度与精确度更高。

🔤 03 · 术语
截图驱动 (Screenshot-based)
只用屏幕像素理解界面，通用但对坐标精度敏感。
可访问性树 (Accessibility Tree)
系统为辅助技术提供的界面元素结构，可供 Agent 定位元素。
间接提示注入 (Indirect Prompt Injection)
网页或文档中的文字被模型当作指令执行。
沙箱环境 (Sandbox)
与主机隔离的虚拟机或容器，限制 Agent 的破坏范围。
OSWorld
评估 Agent 在真实操作系统中完成任务能力的基准。

from playwright.sync_api import sync_playwright

def decide_next_action(png: bytes, goal: str) -> dict:
    """占位：把截图和目标发给支持电脑操作的模型，返回动作。
    具体工具名与参数以所用厂商官方文档为准。"""
    raise NotImplementedError

ALLOWED = {"click", "type", "scroll", "done"}

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)          # 在隔离环境中运行
    page = browser.new_page(viewport={"width": 1280, "height": 800})
    page.goto("https://example.com")
    for step in range(20):                               # 步数上限
        action = decide_next_action(page.screenshot(), "找到 More information 链接")
        kind = action.get("type")
        if kind not in ALLOWED or kind == "done":
            break
        if kind == "click":
            page.mouse.click(action["x"], action["y"])
        elif kind == "type":
            page.keyboard.type(action["text"])
        elif kind == "scroll":
            page.mouse.wheel(0, action.get("dy", 400))
        page.wait_for_load_state()
    browser.close()

展示截图—决策—执行循环与动作白名单；模型调用部分为占位，需对接具体厂商接口。

📊 05 · 参数对比

操作方式对比

方式输入优点缺点
截图 + 坐标屏幕像素适用任何 GUI 应用慢，坐标易偏，成本高
DOM / 选择器网页结构精确、快仅限网页，动态页面易变
可访问性树系统 UI 结构语义清晰部分应用支持不完整
直接调用 API结构化接口最快最可靠需系统提供 API
⚖️ 06 · 方案取舍

电脑操作 Agent

优点能用没有 API 的系统

代价慢、不稳定、安全风险高

适用遗留系统、跨应用操作

传统 RPA / 脚本自动化

优点确定性强、速度快

代价界面变化即失效，开发成本高

适用流程固定的高频任务

API / MCP 集成

优点可靠、可审计

代价需要服务方提供接口

适用有接口时优先选择

🕳️ 07 · 常见坑

  • ✗在日常主力电脑和已登录账号上直接运行

    ✓使用隔离虚拟机或浏览器配置文件，只授予最小账号权限

  • ✗允许 Agent 自主完成付款、删除等不可逆操作

    ✓对高风险动作设置人工确认

  • ✗信任网页中出现的任何文字

    ✓把页面内容视为不可信数据，限制可访问域名

  • ✗有 API 却仍用截图点击

    ✓优先用 API 或 MCP 工具，界面操作作为兜底

🎤 09 · 面试追问
电脑操作 Agent 的主要安全风险是什么？

最大风险是间接提示注入：网页、邮件或文件里的文字可能诱导 Agent 执行用户未授权的操作，如泄露数据或下单。此外还有误操作与凭据暴露。缓解措施包括沙箱隔离、域名白名单、最小权限账号和关键步骤人工确认。

为什么它比 API 集成慢且不稳定？

每一步都需要截图、上传图片、模型推理再执行动作，单步耗时较长；界面布局变化、弹窗、加载延迟都会导致点错位置。API 返回结构化数据且语义稳定，因此有接口时应优先使用。

如何评估这类 Agent？

使用 OSWorld、WebArena 等在真实或仿真环境中执行任务的基准，按任务成功率衡量；在自己的场景中准备固定任务集，记录成功率、步数、耗时和人工介入次数，并对失败轨迹做归因分析。
