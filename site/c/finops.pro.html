云成本治理 (FinOps)

FinOps

📐 01 · 定义

FinOps 是把财务责任引入云的运营实践，属于组织流程与平台治理层。FinOps Foundation 将其描述为工程、财务与业务协作、按价值做云支出决策的框架，常以「Inform（可见）→ Optimize（优化）→ Operate（运营）」循环推进。AI 时代它同样覆盖 GPU 与模型 Token 费用。

⚙️ 02 · 原理
  1. 1

    Inform：采集账单与用量数据，用标签/账户把成本分摊到团队、产品与环境，形成可见性。

  2. 2

    建立单位经济指标，如每用户、每请求、每千次 AI 调用的成本，衡量支出是否创造价值。

  3. 3

    Optimize：削减闲置资源、调整规格（rightsizing）、使用承诺折扣或抢占式实例。

  4. 4

    AI 负载额外优化模型选择、提示缓存、批处理接口与输出长度，降低每次调用的 Token 成本。

  5. 5

    Operate：设预算与异常告警、制定标签与审批策略，把成本检查纳入日常发布流程。

🔤 03 · 术语
成本分摊 (Cost Allocation)
通过标签、账户或项目把共享账单归属到具体团队。
单位经济 (Unit Economics)
每单位业务产出（用户、请求）对应的云成本。
规格优化 (Rightsizing)
按实际利用率调整实例或容器资源规格。
承诺折扣 (Commitment Discounts)
以一定期限用量承诺换取折扣，如 Savings Plans、预留实例。
Showback / Chargeback
向团队展示成本 / 实际向团队内部计费。
💻 04 · 代码
AWS 设置月度预算告警bash
# 创建每月 500 美元成本预算，实际花费超过 80% 时邮件告警
aws budgets create-budget \
  --account-id 123456789012 \
  --budget '{
    "BudgetName": "monthly-total",
    "BudgetLimit": {"Amount": "500", "Unit": "USD"},
    "TimeUnit": "MONTHLY",
    "BudgetType": "COST"
  }' \
  --notifications-with-subscribers '[{
    "Notification": {
      "NotificationType": "ACTUAL",
      "ComparisonOperator": "GREATER_THAN",
      "Threshold": 80,
      "ThresholdType": "PERCENTAGE"
    },
    "Subscribers": [{"SubscriptionType": "EMAIL", "Address": "ops@example.com"}]
  }]'

预算告警是最低成本的护栏；账号 ID 与邮箱为示例值，需替换。

🕳️ 07 · 常见坑

  • ✗没有标签规范，账单无法归属到团队

    ✓强制必填标签（团队、环境、服务），用策略拦截无标签资源

  • ✗只看总额，不看单位成本

    ✓跟踪每用户/每请求成本，增长带来的支出与浪费要分开看

  • ✗一次性大扫除后不再跟进，成本反弹

    ✓预算+异常检测常态化，月度复盘纳入流程

  • ✗忽视 LLM 调用成本，Agent 循环无上限

    ✓设置每任务 Token/步数上限，监控每用户 AI 成本

🎤 09 · 面试追问
FinOps 的三个阶段是什么？

Inform：建立成本可见与分摊；Optimize：基于数据优化用量和费率；Operate：把目标、策略与告警固化为持续运营。三者循环迭代，而非一次性项目。

用量优化和费率优化有什么区别？

用量优化减少消耗量，如关闲置、规格优化、缓存；费率优化降低单价，如承诺折扣、Spot、谈判。通常先做用量优化，避免为浪费的资源签长期承诺。

如何控制 LLM 应用的成本？

按任务难度路由模型；启用提示缓存；非实时任务走批处理接口；限制上下文与输出长度；为 Agent 设步数和 Token 上限；按用户/功能统计成本并告警。
