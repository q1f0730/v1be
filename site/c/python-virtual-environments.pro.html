Python 虚拟环境 (venv / uv)

Python Virtual Environments

📐 01 · 定义

Python 虚拟环境（Virtual Environment）是带独立 site-packages 目录与解释器链接的隔离运行环境，由标准库 venv（PEP 405）提供，uv、virtualenv、conda 等工具也可创建。它属于开发环境层，解决多项目依赖版本冲突和污染系统 Python 的问题，是可复现构建的起点。

⚙️ 02 · 原理
  1. 1

    创建时生成 pyvenv.cfg、bin（Windows 为 Scripts）与独立的 site-packages 目录，并链接或复制基础解释器。

  2. 2

    激活脚本把环境的 bin 目录放到 PATH 最前面，使 python/pip 指向环境内的版本。

  3. 3

    此后 pip install 只写入该环境的 site-packages，不影响系统和其他项目。

  4. 4

    依赖用 requirements.txt 或 pyproject.toml 声明，锁文件（如 uv.lock）固定完整依赖树以便复现。

  5. 5

    PEP 668 允许发行版把系统 Python 标记为「外部管理」，此时直接 pip install 会被拒绝，需改用虚拟环境。

🔤 03 · 术语
venv
Python 3.3 起内置的虚拟环境模块，python -m venv 创建。
uv
Astral 用 Rust 编写的包与项目管理器，兼容 pip 接口且速度快。
site-packages
第三方包的安装目录，每个虚拟环境各有一份。
锁文件 (Lockfile)
记录精确版本与哈希的完整依赖树，如 uv.lock。
外部管理环境 (PEP 668)
系统 Python 拒绝 pip 直接安装，提示使用虚拟环境。
💻 04 · 代码
venv 与 uv 两种做法bash
# 方式一：标准库 venv
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install requests
pip freeze > requirements.txt    # 记录当前依赖
deactivate

# 方式二：uv 项目工作流
uv init my-app && cd my-app      # 生成 pyproject.toml
uv add requests                  # 写入依赖并更新 uv.lock
uv run python main.py            # 自动在 .venv 中运行
uv sync                          # 新机器上按锁文件还原环境

# 别把环境目录提交到 Git
echo ".venv/" >> .gitignore

环境目录不入库，入库的是依赖声明与锁文件；uv run 免去手动激活。

⚖️ 06 · 方案取舍

venv + requirements.txt

优点标准、无需额外工具

代价间接依赖不锁定，复现性弱

适用脚本与小项目

uv 项目模式

优点快、自带锁文件与版本管理

代价团队需统一工具

适用新项目、CI 加速

容器/Dev Container

优点连系统库一起隔离

代价镜像构建与资源开销

适用依赖系统库或团队协作

🕳️ 07 · 常见坑

  • ✗未激活环境就 pip install，装进了全局

    ✓用 which python 确认路径，或统一用 uv run / python -m pip

  • ✗把 .venv 目录提交到仓库

    ✓加入 .gitignore，只提交声明与锁文件

  • ✗requirements.txt 只写顶层包且不固定版本

    ✓使用锁文件，或用 pip-tools/uv 生成固定版本清单

  • ✗编辑器或 Agent 用的解释器与终端不一致

    ✓在 IDE 中选择 .venv 解释器，规则文件写明运行命令

🎤 09 · 面试追问
激活虚拟环境实际上做了什么？

主要是修改 PATH，把环境的 bin/Scripts 放在最前面，并设置 VIRTUAL_ENV 等变量和提示符。不激活也能用：直接调用 .venv/bin/python 即可，激活只是便利。

requirements.txt 和锁文件的区别？

requirements.txt 常只列直接依赖、版本范围宽松，不同时间安装可能得到不同间接依赖；锁文件记录完整依赖树的精确版本与哈希，保证各环境安装结果一致。

为什么新系统上 pip install 报 externally-managed-environment？

PEP 668 允许发行版把系统 Python 标记为外部管理，防止 pip 破坏系统包管理器安装的包。正确做法是创建虚拟环境，或用 pipx 安装命令行工具，而不是加 --break-system-packages。
