架构决策记录 (ADR)

Architecture Decision Records

🧸 回到小白版

📐 01 · 定义

架构决策记录（Architecture Decision Record，ADR）是记录单个重要架构决策的短文档，包含决策背景、可选方案、最终决定及其后果，按编号存放在代码仓库中。该做法由 Michael Nygard 于 2011 年推广。ADR 让后来者（包括 AI Agent）理解“为什么是现在这样”，避免重复讨论或无意中推翻有意为之的设计。

⚙️ 02 · 原理
  1. 1

    识别值得记录的决策：影响结构、难以逆转、存在多个合理选项或会被反复质疑的选择。

  2. 2

    按模板撰写：标题、状态（提议/已接受/已废弃/被取代）、背景与约束、决定、后果（正面与负面）。

  3. 3

    以编号文件存放在仓库（如 docs/adr/0007-use-postgres.md），通过 PR 评审后标记为已接受。

  4. 4

    ADR 不修改历史：决策变化时新建 ADR 并将旧记录标记为“被 0012 取代”，保留演进脉络。

  5. 5

    在规则文件或文档中引用 ADR 目录，让新成员与编程 Agent 在改动前查阅相关决策。

🔤 03 · 术语
状态 (Status)
提议、已接受、已废弃、被取代等决策生命周期标记。
背景 (Context)
做出决策时的问题、约束与驱动因素。
后果 (Consequences)
决策带来的影响，包括代价与后续工作。
被取代 (Superseded)
旧决策被新 ADR 替代时的标记，保留可追溯性。
MADR
Markdown Architectural Decision Records，一种流行的 ADR 模板。
💻 04 · 代码
ADR 文档示例（Nygard 格式）text
# docs/adr/0007-use-postgresql.md

# 7. 使用 PostgreSQL 作为主数据库

状态：已接受（2026-03-02）；取代 ADR-0003

## 背景
订单与库存需要跨表事务和强一致；团队熟悉 SQL；
需要 JSON 字段存储商品扩展属性；托管服务可选项多。

## 决定
使用 PostgreSQL 作为主数据库，扩展属性使用 JSONB，
不引入 MongoDB。迁移工具统一用 Alembic。

## 后果
+ 获得 ACID 事务、外键与成熟生态
+ JSONB 满足半结构化需求
- 水平扩展需额外方案（读副本、分区）
- 需要为 JSONB 查询设计 GIN 索引

一个决策一个文件，写清背景、决定和正负后果；变更时新建 ADR 并标注取代关系。

📊 05 · 参数对比

ADR 与其他文档对比

文档回答的问题生命周期存放位置
ADR为什么这样决定追加式，不修改历史代码仓库
设计文档 / RFC打算怎么做，征求意见评审期活跃，之后归档仓库或文档平台
README / 架构概览现在是什么样持续更新代码仓库
规则文件（AGENTS.md 等）AI 应遵守什么持续更新代码仓库根目录
⚖️ 06 · 方案取舍

轻量 ADR（Nygard 模板）

优点写作成本低，易坚持

代价方案比较信息较少

适用大多数团队

详细模板（MADR 含备选方案）

优点记录被否决的选项与理由

代价写作成本更高

适用重大、长期影响的决策

不写 ADR，只靠口头/聊天

优点零成本

代价知识随人员流失，反复争论

适用不推荐

🕳️ 07 · 常见坑

  • ✗把所有小事都写成 ADR，最终无人阅读

    ✓只记录影响结构、难以逆转或有争议的决策

  • ✗决策改变后直接修改旧 ADR

    ✓新建 ADR 并将旧的标记为被取代

  • ✗ADR 存在外部文档平台，与代码脱节

    ✓放在代码仓库中，随 PR 评审和版本控制

  • ✗只写决定不写后果与代价

    ✓明确列出负面后果和后续需要的工作

☑️ 08 · 检查清单
🎤 09 · 面试追问
哪些决策值得写 ADR？

影响系统结构或质量属性（性能、安全、可用性）的、难以逆转的、存在多个合理方案的、或者团队可能反复质疑的决策，例如数据库选型、认证方案、模块边界、同步还是异步通信。日常实现细节不需要。

为什么 ADR 应该是不可变的？

ADR 记录的是某一时刻基于当时信息做出的决定。修改历史会抹去决策演进的脉络，使人无法理解过去为何如此。新建 ADR 取代旧记录，既保留历史，也明确当前有效的决策。

ADR 对 AI 编程有什么帮助？

Agent 只看代码时，可能把有意为之的设计当成缺陷“修复”。在规则文件中指向 ADR 目录，让 Agent 在改动相关模块前阅读决策和约束，可减少推翻既定设计；也可让 Agent 在完成重要改动时起草新的 ADR。
