数据库事务

Transactions

📐 01 · 定义

数据库事务（Transaction）是一组作为不可分割单元执行的读写操作，满足 ACID：原子性、一致性、隔离性、持久性。它由存储引擎通过日志与锁或多版本并发控制实现，解决并发访问与故障中途中断时的数据正确性问题，是业务一致性的最底层保障。

⚙️ 02 · 原理
  1. 1

    客户端执行 BEGIN 开启事务，后续语句共享同一事务上下文与快照。

  2. 2

    修改先写入预写日志（WAL / redo log），保证崩溃后可重放或撤销。

  3. 3

    隔离通过锁或 MVCC 实现：读者看到某个一致快照，写者对行加锁防止冲突。

  4. 4

    COMMIT 时日志刷盘即视为持久化；ROLLBACK 时利用旧版本或 undo 撤销修改。

  5. 5

    并发冲突时，较高隔离级别可能抛出序列化失败，需要应用捕获后重试整个事务。

🔤 03 · 术语
ACID
原子性、一致性、隔离性、持久性四项事务保证。
隔离级别 (Isolation Level)
读未提交、读已提交、可重复读、可串行化，越高异常越少。
MVCC
多版本并发控制，读不阻塞写，每个事务看到自己的快照。
写偏斜 (Write Skew)
两事务基于同一快照各自更新不同行，合起来破坏约束。
保存点 (Savepoint)
事务内的回滚标记，可部分回滚而不放弃整个事务。
💻 04 · 代码
转账事务与重试python
import psycopg  # psycopg 3
from psycopg import errors

def transfer(conn, src, dst, amount, retries=3):
    for _ in range(retries):
        try:
            # with conn.transaction(): 正常退出 COMMIT，异常 ROLLBACK
            with conn.transaction():
                conn.execute("SET TRANSACTION ISOLATION LEVEL SERIALIZABLE")
                cur = conn.execute(
                    "SELECT balance FROM accounts WHERE id=%s FOR UPDATE", (src,))
                (balance,) = cur.fetchone()
                if balance < amount:
                    raise ValueError("余额不足")
                conn.execute("UPDATE accounts SET balance=balance-%s WHERE id=%s", (amount, src))
                conn.execute("UPDATE accounts SET balance=balance+%s WHERE id=%s", (amount, dst))
            return True
        except errors.SerializationFailure:
            continue  # 序列化冲突：整个事务重来
    raise RuntimeError("重试次数用尽")

with psycopg.connect("dbname=app") as conn:
    transfer(conn, 1, 2, 100)

扣款和入账必须同成同败；SERIALIZABLE 冲突时要重试整个事务而非单条语句。

⚖️ 06 · 方案取舍

悲观锁 SELECT … FOR UPDATE

优点语义直观，冲突时排队等待

代价持锁时间长会阻塞、可能死锁

适用热点行、冲突概率高

乐观锁（版本号字段）

优点无锁等待，读多写少时吞吐高

代价冲突时需重试，业务要处理失败

适用冲突少、可接受重试

SERIALIZABLE 隔离

优点数据库兜底所有并发异常

代价冲突中止率高，必须有重试逻辑

适用复杂不变量难以手工加锁

🕳️ 07 · 常见坑

  • ✗在事务中调用外部 HTTP 或等用户输入

    ✓事务只包数据库操作，外部调用放在事务外或用 outbox 模式

  • ✗以为默认隔离级别能防止所有并发问题

    ✓确认数据库默认级别（PostgreSQL 为读已提交），按需加锁或提级

  • ✗捕获异常后继续在已失败的事务里执行语句

    ✓出错后先 ROLLBACK（或回到保存点）再继续

  • ✗跨多个服务的数据库期待单个本地事务保证一致

    ✓改用 Saga、outbox 等最终一致方案并设计补偿

🎤 09 · 面试追问
什么是写偏斜？如何防止？

两个事务读取同一快照，各自更新不同行，单独都合法，合起来违反约束（如值班至少一人）。可重复读/快照隔离防不住。可用 SERIALIZABLE、对相关行 SELECT FOR UPDATE，或把约束物化为可加锁的行。

PostgreSQL 与 MySQL InnoDB 默认隔离级别有何不同？

PostgreSQL 默认读已提交，每条语句取新快照；InnoDB 默认可重复读，事务内一致快照，并通过间隙锁在锁定读时减少幻读。迁移代码时要注意行为差异。

事务提交了，数据一定不丢吗？

取决于持久化配置：日志是否同步刷盘（如 synchronous_commit、innodb_flush_log_at_trx_commit）、存储是否可靠、主从复制是同步还是异步。异步复制下主库故障切换可能丢失最近已提交事务。
