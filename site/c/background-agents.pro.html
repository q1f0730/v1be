后台 / 云端智能体

Background Agents

📐 01 · 定义

后台/云端智能体（Background Agents）是在远程隔离环境中异步执行编程任务的 AI Agent：开发者派发任务后，Agent 在云端容器中克隆仓库、改代码、跑测试，完成后推送分支并创建 PR 供人审核。代表有 GitHub Copilot coding agent、OpenAI Codex 云端任务等（名称与能力以官方文档为准）。

⚙️ 02 · 原理
  1. 1

    开发者通过 Issue 指派、评论触发或产品界面提交任务描述，并指定仓库与基础分支。

  2. 2

    平台启动隔离的云端环境（容器或虚拟机），克隆代码，并按配置文件执行环境初始化脚本。

  3. 3

    Agent 在该环境中运行“读代码—修改—执行命令—看结果”的循环，网络访问与密钥按策略受限。

  4. 4

    完成后推送到新分支并创建 PR，附带变更说明、测试结果与运行日志。

  5. 5

    人类在 PR 中审核，可通过评论要求 Agent 继续修改；CI 与分支保护作为合并前的最后关卡。

🔤 03 · 术语
异步任务 (Async Task)
派发后无需等待，Agent 独立完成并回报结果。
环境初始化 (Environment Setup)
为 Agent 准备依赖、工具链与测试数据的脚本或配置。
出站网络策略 (Egress Policy)
限制 Agent 可访问的外部域名，降低数据泄露风险。
分支隔离 (Branch Isolation)
每个任务在独立分支上工作，互不干扰。
人工审核门禁 (Review Gate)
Agent 的改动必须经人审核和 CI 通过才能合并。
💻 04 · 代码
评论 @claude 触发云端修改yaml
# .github/workflows/claude.yml（参照 anthropics/claude-code-action 官方示例精简）
name: Claude Code
on:
  issue_comment:
    types: [created]
jobs:
  claude:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    permissions:
      contents: write        # 推送分支
      pull-requests: write   # 创建/更新 PR
      issues: write
      id-token: write
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 1
      - uses: anthropics/claude-code-action@v1
        with:
          anthropic_api_key: ${{ secrets.ANTHROPIC_API_KEY }}
          # 可选：限制轮数与可用工具（参数以官方文档为准）
          # claude_args: --max-turns 10 --allowedTools "Bash(npm run test:*)"

在 Issue/PR 评论中 @claude 即触发 Agent 在 CI 环境中改代码并提交，权限按需最小化。

📊 05 · 参数对比

本地 Agent vs 后台 Agent

维度本地交互式 Agent后台云端 Agent
运行位置开发者电脑云端隔离环境
人的参与实时观察和批准派发后异步审核 PR
并行能力受本机资源限制可同时运行多个任务
环境开发者完整本地环境需显式配置依赖与密钥
适合任务探索性、需频繁沟通边界清晰、可测试验证
⚖️ 06 · 方案取舍

后台 Agent 处理小而明确的任务

优点并行提效，不打断开发者

代价需求模糊时产出偏离

适用修 bug、补测试、依赖升级、文档

本地交互式协作

优点可随时纠正方向

代价占用开发者注意力

适用架构调整、需求不清的探索

多个后台 Agent 并行

优点吞吐高

代价PR 冲突与审核负担

适用任务相互独立时

🕳️ 07 · 常见坑

  • ✗任务描述含糊，如“优化一下性能”

    ✓写清目标、范围、验收标准和需运行的测试命令

  • ✗环境未配置，Agent 无法运行测试就提交

    ✓提供环境初始化脚本，要求测试通过后才提 PR

  • ✗给云端环境注入生产密钥和无限制网络

    ✓只提供测试用凭据，启用出站域名白名单

  • ✗同时派发互相重叠的任务导致冲突

    ✓按模块拆分任务，避免多个 Agent 修改同一文件

🎤 09 · 面试追问
什么样的任务适合交给后台 Agent？

边界清晰、可通过测试自动验证、上下文主要在仓库内的任务，如修复有复现步骤的 bug、补充测试、依赖升级、小型功能。需要大量产品判断或跨系统协调的任务，更适合人机实时协作。

后台 Agent 有哪些安全风险？

它在无人值守的情况下执行命令，可能被仓库内容或 Issue 中的提示注入诱导泄露密钥、引入恶意依赖。应限制网络出站、使用最小权限凭据、禁止直接推主分支，并对 PR 做与人类代码同等的审核。

如何提高后台 Agent 的成功率？

维护好规则文件（如 AGENTS.md、CLAUDE.md）说明项目约定与命令；提供可一键运行的测试与环境脚本；任务描述包含复现步骤和验收标准；把大任务拆小；从失败的 PR 中总结并更新规则。
