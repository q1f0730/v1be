React 服务端组件 (RSC)

React Server Components

📐 01 · 定义

React 服务端组件（RSC）是只在服务器（或构建时）执行的 React 组件，可直接访问数据库、文件系统和密钥，其渲染结果以序列化的 RSC 负载发送给客户端，组件代码本身不进入浏览器包。客户端组件用 'use client' 指令标记，负责状态与交互。RSC 在 React 19 中稳定，Next.js App Router 默认使用。

⚙️ 02 · 原理
  1. 1

    在支持 RSC 的框架中，组件默认是服务端组件，可以是 async 函数，直接 await 数据。

  2. 2

    服务器渲染组件树，生成描述 UI 的 RSC 负载：服务端组件被展开为结果，客户端组件以模块引用和序列化 props 占位。

  3. 3

    'use client' 标记客户端边界：该文件及其导入的模块进入客户端包，可使用 useState、事件处理和浏览器 API。

  4. 4

    服务端组件可把可序列化的 props 或其他服务端组件作为 children 传给客户端组件，反之客户端组件不能导入服务端组件。

  5. 5

    客户端根据负载重建树并对客户端组件进行水合；配合 Suspense 可流式发送，'use server' 标记的服务器函数供客户端调用以修改数据。

🔤 03 · 术语
RSC 负载 (RSC Payload)
服务端组件树渲染结果的紧凑序列化格式，客户端据此构建 UI。
'use client'
放在文件顶部的指令，声明客户端组件边界及其依赖进入浏览器包。
服务器函数 (Server Functions)
用 'use server' 标记、可被客户端调用的服务端异步函数，原称 Server Actions。
可序列化 Props
跨边界传递的数据须可序列化，函数（服务器函数除外）和类实例不能传。
server-only
npm 包，导入后若模块被客户端引用则构建报错，防止泄露服务端代码。
💻 04 · 代码
Next.js 服务端与客户端组件typescript
// app/posts/page.tsx —— 服务端组件（默认）
import 'server-only'
import { db } from '@/lib/db'          // 数据库客户端只存在于服务器
import LikeButton from './LikeButton'

export default async function PostsPage() {
  const posts = await db.post.findMany({ take: 10 })   // 直接查库
  return (
    <ul>
      {posts.map((p) => (
        <li key={p.id}>
          {p.title}
          <LikeButton postId={p.id} initial={p.likes} />  {/* 只传可序列化数据 */}
        </li>
      ))}
    </ul>
  )
}

// app/posts/LikeButton.tsx —— 客户端组件
'use client'
import { useState } from 'react'

export default function LikeButton({ postId, initial }: { postId: number; initial: number }) {
  const [likes, setLikes] = useState(initial)
  return <button onClick={() => setLikes(likes + 1)}>👍 {likes}</button>
}

两段为两个文件；db 的具体 ORM 写法为示意，以项目实际为准。'use client' 必须位于文件最顶部。

📊 05 · 参数对比

服务端组件与客户端组件

能力服务端组件客户端组件
async/await 取数支持不直接支持（用框架或 use）
useState / useEffect不支持支持
访问数据库与密钥可以不可以
代码进入浏览器包否是
事件处理（onClick）不支持支持
⚖️ 06 · 方案取舍

默认服务端组件，交互处下沉客户端

优点JS 包更小，数据就近获取，密钥不外泄

代价需要理解边界与序列化规则

适用内容型页面、数据密集的后台

传统客户端渲染 SPA

优点心智模型简单，前后端完全分离

代价首屏依赖 JS 下载与 API 往返

适用高度交互的工具型应用

SSR + 全量水合

优点首屏有 HTML，生态成熟

代价所有组件代码仍要下载并水合

适用Pages Router 等既有项目

🕳️ 07 · 常见坑

  • ✗在页面顶层加 'use client'，整棵树变成客户端组件

    ✓只给需要交互的叶子组件加 'use client'

  • ✗把含密钥的配置对象作为 props 传给客户端组件

    ✓跨边界只传最少的可序列化数据，敏感模块导入 server-only

  • ✗向客户端组件传递函数或类实例导致报错

    ✓传原始数据，或使用 'use server' 服务器函数

  • ✗以为服务器函数天然有权限保护

    ✓服务器函数是公开端点，内部必须做认证与授权校验

🎤 09 · 面试追问
RSC 和 SSR 的区别是什么？

SSR 在服务器把组件渲染成 HTML，但组件代码仍会发到浏览器并水合；RSC 的服务端组件只在服务器运行，代码不进入客户端包，输出的是可与客户端组件组合的 RSC 负载。两者可同时使用：RSC 负载也可在服务器上进一步渲染成首屏 HTML。

为什么客户端组件不能导入服务端组件？

客户端组件及其导入都会打包进浏览器，而服务端组件可能依赖数据库和密钥，无法在浏览器运行。正确做法是在服务端组件中把服务端组件作为 children 或 props 传入客户端组件，由服务器先渲染好再组合。

AI 生成 Next.js 代码常见的 RSC 错误？

在服务端组件中使用 useState 或 onClick 导致报错；为消除报错在顶层滥加 'use client'，失去 RSC 收益；把环境变量或数据库对象传给客户端；服务器函数缺少鉴权。评审时应重点检查边界位置与跨边界数据。
