单点登录 (SSO / SAML)

SSO & SAML

📐 01 · 定义

单点登录（SSO）让用户通过一次认证访问多个应用；SAML 2.0（OASIS 于 2005 年发布）是企业 SSO 的主流协议之一，以 XML 签名断言在身份提供方（IdP，如 Okta、Microsoft Entra ID）与服务提供方（SP，你的应用）之间传递身份。它属于身份与访问管理层，是 SaaS 进入企业市场的常见门槛，常与 SCIM 自动开通账号搭配。

⚙️ 02 · 原理
  1. 1

    双方交换元数据：SP 提供 Entity ID 与 ACS（断言消费服务）URL，IdP 提供 SSO URL 与签名证书。

  2. 2

    SP 发起：用户访问应用，SP 生成 AuthnRequest，通过浏览器重定向到 IdP。

  3. 3

    IdP 认证用户（密码、MFA 等），生成包含用户标识与属性的断言并用私钥签名。

  4. 4

    浏览器把 SAMLResponse 以 POST 方式提交到 SP 的 ACS URL。

  5. 5

    SP 验证签名、受众、有效期与 InResponseTo，映射到本地账号并建立会话。

🔤 03 · 术语
身份提供方 (IdP)
负责认证用户并签发断言的系统，如 Okta、Entra ID。
服务提供方 (SP)
依赖 IdP 认证结果的应用，即你的产品。
断言 (Assertion)
IdP 签名的 XML 声明，包含主体、属性与条件。
ACS URL
SP 接收 SAMLResponse 的回调地址。
SCIM
跨域身份管理协议，用于自动创建、更新、停用用户账号。
IdP 发起登录 (IdP-initiated)
用户从 IdP 门户点击进入应用，无 SP 请求。
💻 04 · 代码
python3-saml 的 SP 配置json
{
  "strict": true,
  "sp": {
    "entityId": "https://app.example.com/saml/metadata",
    "assertionConsumerService": {
      "url": "https://app.example.com/saml/acs",
      "binding": "urn:oasis:names:tc:SAML:2.0:bindings:HTTP-POST"
    },
    "NameIDFormat": "urn:oasis:names:tc:SAML:1.1:nameid-format:emailAddress"
  },
  "idp": {
    "entityId": "http://www.okta.com/exk_example",
    "singleSignOnService": {
      "url": "https://example.okta.com/app/example/sso/saml",
      "binding": "urn:oasis:names:tc:SAML:2.0:bindings:HTTP-Redirect"
    },
    "x509cert": "MIIDpDCCAoygAwIBAgIG..."
  }
}

strict 模式会严格校验签名、受众与时间；IdP 的 ID、URL 与证书来自客户提供的元数据（示例值）。

⚖️ 06 · 方案取舍

自研 SAML 集成

优点无第三方费用，完全掌控

代价XML 签名安全细节多，易出漏洞

适用安全团队强、客户少

身份中间层服务（如 WorkOS、Auth0）

优点快速支持多种 IdP 与 SCIM

代价按连接或用户付费，引入依赖

适用需要快速满足企业客户

只支持 OIDC

优点实现简单、现代

代价部分企业 IdP 配置或政策要求 SAML

适用客户以现代 IdP 为主

🕳️ 07 · 常见坑

  • ✗只验证断言存在，不严格校验签名

    ✓使用成熟库并开启严格模式，校验签名、受众、有效期

  • ✗XML 解析存在签名包装攻击风险

    ✓使用维护良好的库，禁止外部实体，只信任已验证的签名节点

  • ✗只做 SSO 登录，不做账号停用

    ✓接入 SCIM 或定期同步，员工离职后自动停用

  • ✗按邮箱自动合并已有账号，被用于接管

    ✓按租户校验已验证域名，合并前确认归属

☑️ 08 · 检查清单
🎤 09 · 面试追问
SAML 和 OIDC 怎么选？

OIDC 基于 OAuth 2.0 与 JWT，对移动端和 API 友好、实现简单；SAML 基于 XML，企业存量 IdP 支持最广。面向企业的 SaaS 往往两者都支持，新项目优先 OIDC，并按客户需求提供 SAML。

IdP 发起登录有什么安全风险？

没有 SP 的 AuthnRequest，无法用 InResponseTo 绑定请求，更易受断言重放与登录 CSRF 影响。需校验断言一次性使用、短有效期，或引导为 SP 发起流程。

SSO 之外企业客户通常还要求什么？

SCIM 自动开通与停用、强制 SSO（禁用密码）、基于组的角色映射、审计日志、会话超时策略，以及多个已验证域名管理。这些常出现在企业采购的安全问卷中。
