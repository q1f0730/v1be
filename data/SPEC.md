# 内容写作规范（每个概念一份 JSON 对象）

读者：完全不会代码、不懂计算机的人，可能有 ADHD 或阅读障碍。
全部用简体中文。英文术语只在必要处出现，并且紧跟中文解释。

## 写作铁律
- 一句话只讲一件事。每句 ≤ 20 个汉字（表格单元格 ≤ 12 字）。
- 不用生僻字、不用长从句、不堆术语。出现新词，马上用大白话解释。
- 比喻必须来自日常生活（外卖、快递、奶茶店、银行、餐厅、宿舍、地铁、游戏……）。
- 每个要点以一个 emoji 开头。
- 语气像靠谱的朋友，轻松，但不油腻、不说教。
- 尽量把概念和「用 AI 做产品」联系起来：你在 Cursor / Claude Code 里会在哪碰到它。
- 如果输入里有 orig_analogy / orig_oops（原书内容），以它为基础改写得更短更简单，不要照抄长句。

{

  "oneLiner": "一句话说清它是什么，≤ 22 字",
  "analogy": "生活比喻，2–3 个短句，总共 ≤ 60 字",

## table 写法建议
优先做「对比表」：如 ✅ 对的做法 vs ❌ 错的做法；或 A vs B；或「生活里 / 电脑里 / 你要做什么」三列对照。

## anim.type 可选值与 labels 个数
- flow    ：东西从 A 经过 B 到 C（请求、流水线、数据流）。labels 3 个
- guard   ：门卫拦坏人放好人（安全类）。labels 3 个：[好人/正常请求, 门卫/防护, 坏人/攻击]
- queue   ：东西排队被一个个处理（队列、任务）。labels 2 个：[排队的东西, 处理者]
- layers  ：三层从下往上叠起来（架构、分层）。labels 3 个，顺序：底层→顶层
- split   ：一个分给三个（分片、负载均衡、CDN）。labels 4 个：[源头, 去处1, 去处2, 去处3]
- merge   ：三个汇成一个（汇总、日志收集）。labels 4 个：[来源1, 来源2, 来源3, 汇总处]
- loop    ：循环往复的步骤（重试、CI、Agent 循环）。labels 3 或 4 个
- lock    ：东西被锁进箱子（加密、认证、密钥）。labels 3 个：[原来的东西, 锁/钥匙, 锁好后]
- copy    ：一份复制成两份（备份、副本、复制）。labels 3 个：[原件, 副本1, 副本2]
- filter  ：漏斗过滤，不合格的被弹走（校验、限流）。labels 3 个：[输入, 过滤器, 通过的]
- timer   ：倒计时，到点失效（过期、TTL、超时）。labels 2 个：[东西, 时间限制]
- chat    ：你说一句，AI 回一句（AI 类）。labels 2 个：[你说的话 ≤10字, AI 回的话 ≤10字]
- balance ：天平两边权衡（取舍、对比）。labels 2 个：[左边, 右边]
- toggle  ：开关在两种状态间切换（开关、蓝绿、版本）。labels 2 个：[状态A, 状态B]
- grow    ：柱子逐渐长高（扩容、增长、指标）。labels 3 个
尽量让同一批里各种动画类型都用到，别全是 flow。

## 输出
一个 JSON 数组，顺序与输入相同，写入指定的输出文件。写完用 python3 -c "import json;json.load(open('文件'))" 校验能解析、条数与输入相同、每个 related 的 slug 都存在。
