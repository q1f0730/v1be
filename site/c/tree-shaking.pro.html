摇树优化 (Tree Shaking)

Tree Shaking

📐 01 · 定义

摇树优化（Tree Shaking）是打包器基于 ES 模块静态结构做的死代码消除：分析 import/export 依赖图，标记实际被使用的导出，把未使用的导出从最终产物中删除。它属于前端构建优化层，Rollup 首先推广此概念，webpack、esbuild、Vite（生产构建）等都支持，目标是减少 bundle 体积。

⚙️ 02 · 原理
  1. 1

    打包器从入口开始解析 ES 模块，import/export 是静态声明，可在不执行代码的情况下确定依赖。

  2. 2

    构建模块依赖图，标记每个模块中哪些导出被其他模块真正引用。

  3. 3

    检查未引用的代码是否有副作用；无副作用或 package.json 声明 sideEffects: false 的模块可整体跳过。

  4. 4

    压缩器（Terser、esbuild 等）在此基础上删除不可达代码与未使用变量。

  5. 5

    CommonJS 的 require 是动态的，难以静态分析，通常只能整体保留。

🔤 03 · 术语
ES 模块 (ESM)
使用静态 import/export 的标准模块系统，是摇树的前提。
副作用 (Side Effects)
模块被导入时就执行的影响，如修改全局、注入样式。
sideEffects 字段
package.json 中声明哪些文件有副作用，供打包器安全删除。
死代码消除 (Dead Code Elimination)
移除不会被执行或结果未使用的代码。
/*#__PURE__*/ 注释
标记函数调用无副作用，未使用时可被删除。
💻 04 · 代码
按需引入与 sideEffectsjavascript
// ❌ 引入 CommonJS 版整库，难以摇树
import _ from "lodash";
_.debounce(save, 300);

// ✅ 使用 ESM 版本并按名引入，只打包 debounce 及其依赖
import { debounce } from "lodash-es";
debounce(save, 300);

// 库作者在 package.json 声明无副作用，允许打包器删除未用模块
// {
//   "type": "module",
//   "sideEffects": ["*.css"],   // 仅 CSS 导入有副作用
//   "exports": { ".": "./dist/index.js" }
// }

// 分析产物体积（Vite 项目可用 rollup-plugin-visualizer）
// npx vite build && 打开生成的 stats.html

lodash 主包为 CommonJS，lodash-es 为 ESM；sideEffects 声明决定未使用模块能否整体删除。

⚖️ 06 · 方案取舍

依赖摇树

优点自动、无需改架构

代价受库格式与副作用声明限制

适用常规项目默认开启

换用更小的库

优点直接减小体积

代价迁移成本，功能可能不全

适用大库只用少量功能

代码分割

优点把非首屏代码延后加载

代价不减少总量，只调整加载时机

适用体积大但功能必需

🕳️ 07 · 常见坑

  • ✗误把有副作用的 CSS 导入写进 sideEffects: false

    ✓用数组精确列出 *.css 等有副作用的文件

  • ✗开发模式下检查体积，得出摇树无效结论

    ✓以生产构建结果为准，开发模式通常不做完整优化

  • ✗用 import * as lib 后通过动态键访问属性

    ✓具名导入，避免打包器无法静态判断使用了什么

  • ✗Babel 把 ESM 转成 CommonJS 后再交给打包器

    ✓保留 ESM（如 preset-env 设 modules: false）交给打包器处理

🎤 09 · 面试追问
为什么 CommonJS 难以摇树？

require 可以出现在条件、循环中，参数可以是变量，导出对象可在运行时修改，打包器无法在不执行代码的情况下确定用到了什么，只能保守保留整个模块。

sideEffects: false 有什么风险？

它告诉打包器未被使用的导入可直接删除；若某文件导入时会注册全局、注入样式或打补丁，就会被误删，导致功能缺失。应精确列出有副作用的文件。

摇树和代码分割的区别？

摇树删除根本没用到的代码，减少总量；代码分割把用到但不急需的代码拆成异步块延后加载，总量不变，改善首屏。二者互补。
