HTTP缓存控制头

Cache-Control Headers

📐 01 · 定义

Cache-Control 是 HTTP 中控制缓存行为的核心头部（RFC 9111），用一组指令告诉浏览器、CDN 和代理：响应能否被缓存、由谁缓存、保持新鲜多久、过期后是否必须先向源站验证。正确设置可大幅减少请求与带宽，设置错误则会导致用户看到旧版本或隐私数据被共享缓存。

⚙️ 02 · 原理
  1. 1

    源站在响应中设置 Cache-Control，缓存据此判断是否存储以及新鲜期长短。

  2. 2

    新鲜期内（max-age，共享缓存优先 s-maxage）直接使用缓存副本，不发请求。

  3. 3

    过期后缓存带 If-None-Match 或 If-Modified-Since 向源站验证，未变则返回 304。

  4. 4

    no-cache 表示可存储但每次使用前必须验证；no-store 表示完全不得存储。

  5. 5

    private 只允许浏览器缓存，public 允许 CDN 等共享缓存；未设置时缓存可能按启发式规则自行决定。

🔤 03 · 术语
max-age
响应保持新鲜的秒数。
s-maxage
仅对共享缓存（CDN/代理）生效的新鲜期。
no-cache
可存储，但每次使用前必须向源站验证。
no-store
任何缓存都不得存储该响应。
immutable
新鲜期内内容不会变化，刷新页面也无需验证。
stale-while-revalidate
过期后的一段时间内先返回旧值，后台异步验证。
💻 04 · 代码
按资源类型设置缓存http
# 1. 带内容哈希的静态资源：缓存一年，内容变了文件名就变
GET /assets/app.3f9a1c.js HTTP/1.1

HTTP/1.1 200 OK
Cache-Control: public, max-age=31536000, immutable

# 2. HTML 入口：可存储但每次都验证，确保能拿到新版本引用
GET /index.html HTTP/1.1

HTTP/1.1 200 OK
Cache-Control: no-cache
ETag: "v42"

# 3. 公共 API：CDN 缓存 60 秒，过期后 5 分钟内可先返回旧值再后台刷新
HTTP/1.1 200 OK
Cache-Control: public, max-age=0, s-maxage=60, stale-while-revalidate=300

# 4. 含个人信息的响应：禁止任何缓存存储
GET /api/me HTTP/1.1

HTTP/1.1 200 OK
Cache-Control: private, no-store

哈希文件长缓存，HTML 每次验证，个人数据 no-store；s-maxage 只作用于 CDN。

⚖️ 06 · 方案取舍

长 max-age + 文件名哈希

优点几乎零重复请求

代价依赖构建工具生成哈希名

适用所有可构建的静态资源

no-cache + ETag

优点始终最新，未变时只回 304

代价每次仍有一次往返

适用HTML 与频繁变化的内容

stale-while-revalidate

优点用户几乎感受不到回源延迟

代价短时间内可能看到旧数据

适用可容忍秒级旧数据的接口

🕳️ 07 · 常见坑

  • ✗以为 no-cache 是“不缓存”

    ✓要完全禁止存储用 no-store；no-cache 是必须验证

  • ✗HTML 设置长 max-age，发版后用户仍加载旧资源

    ✓HTML 用 no-cache，静态资源靠哈希文件名长缓存

  • ✗带 Cookie 的个性化响应被 CDN 缓存给了别人

    ✓设置 private 或 no-store，并检查 CDN 规则

  • ✗不写 Cache-Control，依赖缓存的启发式行为

    ✓每类响应显式声明缓存策略

☑️ 08 · 检查清单
🎤 09 · 面试追问
no-cache 和 no-store 有什么区别？

no-cache 允许缓存存储，但每次使用前必须向源站验证（通常得到 304，省去传输正文）；no-store 禁止任何缓存存储响应，每次都完整请求。前者用于需要最新但可节省带宽的资源，后者用于敏感数据。

为什么前端静态资源要用文件名哈希？

哈希让 URL 随内容变化。这样可以给静态资源设置一年缓存加 immutable，用户永远不重复下载未变文件；发版时新 HTML 引用新文件名，自然拿到新资源，不需要清理浏览器或 CDN 缓存。

s-maxage 和 max-age 同时存在时如何生效？

共享缓存（CDN、代理）优先使用 s-maxage，忽略 max-age；浏览器等私有缓存只看 max-age。借此可以让 CDN 缓存较久、浏览器每次都回 CDN 验证，发版时只需清理 CDN。
