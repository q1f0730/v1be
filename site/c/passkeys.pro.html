通行密钥 (Passkey)

📐 01 · 定义

通行密钥（Passkey）是基于 FIDO2/WebAuthn 标准的无密码凭据：设备为每个网站生成一对非对称密钥，私钥保存在平台认证器或安全硬件中并可跨设备同步，网站只保存公钥。登录时用户通过指纹、面容或 PIN 本地解锁，设备对服务器挑战签名。由于凭据绑定到域名，通行密钥天然抗钓鱼，也不会因服务器数据泄露而暴露可复用的秘密。

⚙️ 02 · 原理
  1. 1

    注册时服务器生成随机挑战（challenge）和用户信息，前端调用 navigator.credentials.create() 请求认证器创建凭据。

  2. 2

    认证器验证用户（生物识别或 PIN）后，为该依赖方 ID（rpId，通常是域名）生成密钥对，返回公钥与凭据 ID。

  3. 3

    服务器验证返回数据中的挑战、来源（origin）和签名，存储凭据 ID 与公钥，关联到账号。

  4. 4

    登录时服务器下发新挑战，前端调用 navigator.credentials.get()；浏览器只允许与 rpId 匹配的站点使用该凭据。

  5. 5

    认证器用私钥签名挑战与客户端数据，服务器用存储的公钥验签并检查签名计数等字段后建立会话。

🔤 03 · 术语
WebAuthn
W3C 标准的浏览器 API，用于创建和使用公钥凭据。
依赖方 (Relying Party, RP)
接受通行密钥登录的网站，由 rpId（域名）标识。
可发现凭据 (Discoverable Credential)
存于认证器上、无需先输入用户名即可选择的凭据。
用户验证 (User Verification)
认证器通过生物识别或 PIN 确认是本人操作。
挑战 (Challenge)
服务器生成的一次性随机值，防止签名被重放。
条件式界面 (Conditional UI)
在用户名输入框的自动填充里直接提供通行密钥选项。
💻 04 · 代码
浏览器端注册通行密钥javascript
// options 由服务器生成（推荐用 SimpleWebAuthn 等库，勿自行实现验签）
const options = {
  challenge: Uint8Array.from(serverChallenge),   // 服务器下发的随机值
  rp: { name: "My App", id: "example.com" },
  user: {
    id: Uint8Array.from(userIdBytes),            // 不要用邮箱等个人信息
    name: "ada@example.com",
    displayName: "Ada",
  },
  pubKeyCredParams: [
    { type: "public-key", alg: -7 },   // ES256
    { type: "public-key", alg: -257 }, // RS256
  ],
  authenticatorSelection: {
    residentKey: "required",           // 可发现凭据 = 通行密钥
    userVerification: "preferred",
  },
};
const cred = await navigator.credentials.create({ publicKey: options });
// 把 cred（attestationObject、clientDataJSON 等）发回服务器验证并保存公钥
await fetch("/webauthn/register", { method: "POST", body: JSON.stringify(cred) });

演示 WebAuthn 注册调用的关键参数；PublicKeyCredential 支持 toJSON 序列化，服务端验证交给成熟库。

登录方式安全性对比

方式抗钓鱼服务器泄露影响用户体验
密码否可能被离线破解后复用需记忆
密码 + 短信验证码弱验证码可被实时钓鱼需等短信
密码 + TOTP弱可被实时中间人钓鱼需打开应用

⚖️ 06 · 方案取舍

通行密钥作为唯一登录方式

优点体验最佳，彻底消除密码风险

代价设备全丢时账号恢复难

适用用户群设备较新、恢复流程完善

通行密钥 + 密码并存

优点渐进迁移，兼容旧设备

代价密码仍是可被攻击的入口

适用大多数现有产品的过渡期

通行密钥作为第二因素

优点在现有流程上加强安全

代价体验提升有限

适用高安全要求的企业系统

🕳️ 07 · 常见坑

  • ✗自己实现 CBOR 解析和签名验证

    ✓使用 SimpleWebAuthn、py_webauthn 等成熟库

  • ✗rpId 设为错误的域名，换子域后无法登录

    ✓rpId 设为可注册域（如 example.com），覆盖所需子域

  • ✗user.id 使用邮箱或手机号

    ✓使用随机生成的不透明字节，避免泄露个人信息

  • ✗没有账号恢复方案

    ✓允许绑定多个通行密钥，并设计安全的恢复流程

🎤 09 · 面试追问
通行密钥为什么能防钓鱼？

浏览器把凭据与 rpId 绑定，只在来源域名匹配时才允许调用；钓鱼站域名不同，根本无法请求真实网站的凭据。签名数据中还包含 origin，服务器会校验，因此即便中间人转发也无法通过验证。

同步通行密钥和设备绑定通行密钥有何区别？

同步通行密钥由平台（如 iCloud 钥匙串、Google 密码管理器）端到端加密同步到同一账号的设备，丢失单台设备也能登录。设备绑定的凭据存于安全密钥等硬件中，不可导出，安全性更高但需要备份密钥。

服务器被拖库后通行密钥还安全吗？

服务器只存公钥和凭据 ID，公钥无法用于登录或推导私钥，因此攻击者拿不到可复用的秘密。这与密码哈希泄露后可被离线破解形成鲜明对比，但会话令牌等其他数据仍需保护。
