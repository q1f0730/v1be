📐 01 · 定义

VPS（Virtual Private Server，虚拟专用服务器）是在物理主机上通过虚拟化切分出的独立虚拟机，拥有自己的操作系统与 root 权限；阿里云 ECS、AWS EC2 等云服务器属于同一类 IaaS 产品。它给予最大的控制自由，代价是系统安全、更新、备份与监控全部由使用者负责。

⚙️ 02 · 原理
  1. 1

    云厂商用 KVM 等虚拟化技术把物理机资源切分给多台虚拟机，各自分配 vCPU、内存与磁盘。

  2. 2

    创建实例时选择镜像（如 Ubuntu）、规格、地域与网络，获得公网 IP 并通过 SSH 登录。

  3. 3

    首次登录后需做安全初始化：创建普通用户、配置 SSH 密钥、禁用密码与 root 登录、启用防火墙。

  4. 4

    部署时自行安装运行时、反向代理（Nginx/Caddy）、TLS 证书，并用 systemd 或 Docker 托管进程。

  5. 5

    运维阶段需持续打补丁、备份或快照、监控资源与日志，必要时升级规格或增加实例。

🔤 03 · 术语
vCPU
分配给虚拟机的虚拟处理器，可能与其他租户共享物理核心。
快照 (Snapshot)
磁盘某一时刻的完整副本，用于回滚或克隆。
安全组 (Security Group)
云平台层面的实例防火墙规则，控制进出流量。
SSH 密钥认证
用公私钥对代替密码登录，抗暴力破解。
systemd
Linux 服务管理器，负责开机自启、重启与日志收集。
💻 04 · 代码
Ubuntu 服务器安全初始化bash
# 以 root 登录后：创建日常使用的普通用户
adduser deploy
usermod -aG sudo deploy

# 在【本地电脑】上传公钥，之后用密钥登录
#   ssh-copy-id deploy@<服务器IP>

# 关闭密码与 root 登录（注意 sshd_config.d 下的文件可能覆盖主配置）
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo sed -i 's/^#\?PermitRootLogin.*/PermitRootLogin no/' /etc/ssh/sshd_config
grep -r PasswordAuthentication /etc/ssh/sshd_config.d/ 2>/dev/null
sudo sshd -t && sudo systemctl restart ssh   # 先校验配置再重启

# 防火墙：只放行 SSH 与 Web
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw enable

# 自动安装安全更新
sudo apt update && sudo apt install -y unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades

重启 SSH 前保持当前会话不断开，新开窗口确认能用密钥登录，避免把自己锁在外面。

🕳️ 07 · 常见坑

  • ✗保留密码登录且用弱密码

    ✓启用密钥认证、禁用密码登录，可加 fail2ban

  • ✗只改了 sshd_config，云镜像的 drop-in 配置又把密码登录打开

    ✓检查 /etc/ssh/sshd_config.d/ 并用 sshd -T 查看最终生效值

  • ✗数据库端口对公网开放

    ✓数据库只监听内网或本机，经 SSH 隧道管理

  • ✗只在同一台机器上备份

    ✓备份存到异地或对象存储，并定期演练恢复

🎤 09 · 面试追问
VPS 被入侵挖矿，你会怎么处置？

先隔离（安全组断网或快照留证），排查入口（弱口令、暴露服务、未打补丁），检查持久化手段（crontab、systemd、authorized_keys）。最稳妥是用干净镜像重建，轮换所有密钥，从可信备份恢复数据，再补齐加固项。

安全组和系统防火墙有何区别？

安全组在云平台网络层生效，流量到达实例前即被过滤，且可统一管理多台实例；ufw/iptables 在操作系统内生效。两者叠加形成纵深防御，任何一层放行过宽都会扩大攻击面。

单台 VPS 如何提高可用性？

进程级：systemd 自动重启、健康检查；数据级：定期快照与异地备份；部署级：用容器或配置管理工具保证可快速重建；架构级：最终需多实例 + 负载均衡，消除单点。
