人机验证 (CAPTCHA / Turnstile)

Bot Protection / CAPTCHA

📐 01 · 定义

人机验证（CAPTCHA 及其现代替代品）用于区分人类用户与自动化程序，防止批量注册、撞库、短信轰炸、爬取和刷单。现代方案如 Cloudflare Turnstile、reCAPTCHA v3、hCaptcha 多以浏览器信号、行为特征和隐式挑战为主，前端生成一次性 token，后端必须向服务商校验 token 后才放行业务请求。

⚙️ 02 · 原理
  1. 1

    页面加载服务商脚本并渲染组件，组件在浏览器中运行检测（环境指纹、工作量证明、行为信号等），必要时才弹出交互挑战。

  2. 2

    检测通过后生成一次性 token，随表单或请求一起提交到你的后端。

  3. 3

    后端用私密的 secret key 调用服务商校验接口，确认 token 有效、未被使用、未过期，并可核对 hostname 与 action。

  4. 4

    校验成功才执行注册、登录等敏感操作；失败或超时则拒绝并返回通用错误。

  5. 5

    人机验证与限流、设备指纹、风控评分组合使用，形成纵深防御，而不是唯一防线。

🔤 03 · 术语
Turnstile
Cloudflare 的人机验证服务，强调无需用户解题。
siteverify
服务端校验 token 的接口，需用 secret key 调用。
撞库 (Credential Stuffing)
用泄露的账号密码批量尝试登录其他网站。
分数制验证 (Score-based)
如 reCAPTCHA v3，返回机器人可能性分数，由业务决定阈值。
打码平台 (CAPTCHA Farm)
雇人或用模型批量破解验证码的服务，说明验证码可被绕过。
💻 04 · 代码
后端校验 Turnstile tokenpython
import os
import requests

VERIFY_URL = "https://challenges.cloudflare.com/turnstile/v0/siteverify"

def verify_turnstile(token: str, remote_ip: str | None = None) -> bool:
    if not token:
        return False
    data = {"secret": os.environ["TURNSTILE_SECRET"], "response": token}
    if remote_ip:
        data["remoteip"] = remote_ip      # 可选
    try:
        r = requests.post(VERIFY_URL, data=data, timeout=5)
        result = r.json()
    except requests.RequestException:
        return False                      # 校验服务异常时按失败处理
    # 建议同时核对 hostname / action 是否符合预期
    return result.get("success") is True

前端组件提交的 token 必须在后端用 secret 调用 siteverify 校验，token 一次性且有时效。

⚖️ 06 · 方案取舍

全站强制验证

优点防护面广

代价影响转化与无障碍体验

适用遭受大规模攻击期间

仅敏感操作验证

优点体验与安全平衡

代价需识别全部敏感入口

适用注册、登录、发短信、提交表单

风险自适应触发

优点正常用户无感

代价需要风控信号与调优

适用中大型业务

🕳️ 07 · 常见坑

  • ✗只在前端渲染组件，后端不校验 token

    ✓所有敏感接口在后端调用 siteverify 并拒绝失败请求

  • ✗同一 token 重复使用或长期缓存

    ✓token 一次性使用，过期后重新获取

  • ✗把 secret key 写进前端代码

    ✓secret 只放服务器环境变量，前端只用 site key

  • ✗只靠验证码防刷短信

    ✓叠加按手机号、IP、设备的限流与每日上限

🎤 09 · 面试追问
为什么前端验证可以被绕过？

攻击者可以不经过浏览器，直接构造 HTTP 请求调用你的接口，前端组件根本不会执行。只有后端向服务商校验 token，才能确认这次请求确实完成了验证，因此校验逻辑必须放在服务端。

验证码能完全挡住机器人吗？

不能。打码平台和多模态模型可以破解许多图片题，自动化浏览器也能模拟部分行为。验证码的价值是提高攻击成本，应与限流、风控评分、异常检测和业务上限一起构成纵深防御。

分数制验证如何设阈值？

先只记录分数不拦截，观察正常用户与已知恶意流量的分布；再按业务风险设定阈值，低分请求不直接拒绝，而是追加验证（如短信或交互挑战），并持续监控误杀率。
