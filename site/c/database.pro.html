数据库是什么

Database

📐 01 · 定义

数据库（Database）是持久化存储与高效检索结构化数据的系统，由数据库管理系统（DBMS）提供数据模型、查询语言、并发控制、事务与恢复能力。主流类型包括关系型（PostgreSQL、MySQL，使用 SQL）和非关系型（文档、键值、向量等）。它通常是应用中最需要谨慎设计与保护的部分。

⚙️ 02 · 原理
  1. 1

    建模：定义表（或集合）结构、字段类型、主键与表间关系，形成数据模式（Schema）。

  2. 2

    写入：数据先写入日志（如预写日志 WAL）再落盘，保证崩溃后可恢复。

  3. 3

    索引：为常用查询列建立 B-Tree 等索引，把全表扫描变为快速定位。

  4. 4

    查询执行：解析 SQL，查询优化器选择执行计划，读取数据并返回结果。

  5. 5

    事务与并发：通过锁或多版本并发控制（MVCC）让并发读写满足 ACID 性质。

🔤 03 · 术语
ACID
原子性、一致性、隔离性、持久性，事务的四个核心保证。
索引 (Index)
加速查询的数据结构，代价是写入变慢、占用空间。
主键/外键 (Primary/Foreign Key)
唯一标识行的列，及引用其他表主键的列。
迁移 (Migration)
版本化记录 Schema 变更的脚本，保证各环境结构一致。
连接池 (Connection Pool)
复用数据库连接，避免频繁建连耗尽资源。
💻 04 · 代码
建表、索引与事务sql
-- PostgreSQL 示例
CREATE TABLE users (
  id         BIGSERIAL PRIMARY KEY,
  email      TEXT NOT NULL UNIQUE,          -- 唯一约束防重复注册
  created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE orders (
  id       BIGSERIAL PRIMARY KEY,
  user_id  BIGINT NOT NULL REFERENCES users(id),  -- 外键保证引用有效
  amount   NUMERIC(10,2) NOT NULL CHECK (amount > 0),
  status   TEXT NOT NULL DEFAULT 'pending'
);
CREATE INDEX idx_orders_user ON orders(user_id); -- 按用户查订单更快

-- 事务：两步操作要么都成功，要么都回滚
BEGIN;
UPDATE orders SET status = 'paid' WHERE id = 1 AND status = 'pending';
INSERT INTO users (email) VALUES ('a@example.com');
COMMIT;

EXPLAIN SELECT * FROM orders WHERE user_id = 42;  -- 查看是否用到索引

约束、索引、事务和执行计划，是把数据库用对的四个基本工具。

类型代表擅长注意

文档型MongoDB灵活结构、嵌套数据跨文档关联与事务较弱

⚖️ 06 · 方案取舍

托管数据库（RDS、Supabase 等）

优点自动备份、高可用、免运维

代价费用更高，部分配置受限

适用生产环境首选

自建数据库

优点完全可控、成本低

代价备份、升级、高可用全靠自己

适用有专业运维能力

ORM 访问

优点开发快、类型安全、防注入

代价复杂查询可能低效

适用常规业务 CRUD

🕳️ 07 · 常见坑

  • ✗用字符串拼接 SQL，导致 SQL 注入

    ✓始终使用参数化查询或 ORM

  • ✗直接在生产库手动改表结构

    ✓通过迁移脚本变更，先在预发环境验证

  • ✗没有备份或从未演练恢复

    ✓开启自动备份并定期做恢复演练

  • ✗AI 生成的查询在列表页触发 N+1 查询

    ✓检查执行计划与查询日志，用 JOIN 或批量加载

🎤 09 · 面试追问
索引为什么能加速查询？代价是什么？

B-Tree 等索引按键有序组织，查找复杂度约为对数级，避免全表扫描。代价是每次写入都要维护索引，写入变慢、占用额外存储；低区分度列或很少查询的列建索引收益很低。

什么时候选 NoSQL 而不是关系型？

数据结构高度多变、以单文档读写为主、需要特定能力（缓存、图关系、时序、向量）或特殊扩展模式时。多数业务场景关系型数据库更稳妥，PostgreSQL 还支持 JSONB 和向量扩展，能覆盖不少需求。

事务隔离级别解决什么问题？

控制并发事务间的可见性，权衡一致性与性能。从低到高有读未提交、读已提交、可重复读、可串行化，分别防止脏读、不可重复读、幻读等异常。PostgreSQL 默认读已提交，MySQL InnoDB 默认可重复读。
