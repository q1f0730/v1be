本地模型 (Ollama / LM Studio)

Local Models

📐 01 · 定义

本地模型指下载开放权重的 LLM，在自己的电脑或服务器上用推理引擎运行，不调用云端 API。常用工具有 Ollama、LM Studio、llama.cpp 和 vLLM，多加载 GGUF 等量化格式并提供 OpenAI 兼容接口。它解决数据不出本机、离线可用和长期成本问题，代价是受硬件限制、能力通常弱于顶级闭源模型。

⚙️ 02 · 原理
  1. 1

    从模型库下载开放权重，通常选择已量化的版本以适配显存或内存。

  2. 2

    推理引擎把权重加载到 GPU 显存，放不下的层可卸载到 CPU 内存运行，速度会下降。

  3. 3

    引擎启动本地 HTTP 服务：Ollama 默认监听 11434 端口，LM Studio 本地服务器默认 1234。

  4. 4

    应用通过原生接口或 OpenAI 兼容接口调用，只需把 base_url 指向本地地址。

  5. 5

    根据速度与质量调整模型大小、量化级别、上下文长度与并发设置。

🔤 03 · 术语
开放权重 (Open Weights)
公开可下载的模型参数，许可条款各不相同。
GGUF
llama.cpp 生态使用的单文件模型格式，支持多种量化。
显存 (VRAM)
GPU 内存，决定能完整加载多大的模型。
层卸载 (Offloading)
部分层放到 CPU 内存运行，以小显存跑大模型。
tokens/s
每秒生成 token 数，衡量本地推理速度。
💻 04 · 代码
Ollama 本地运行与调用bash
# 拉取并交互运行一个模型（名称以 ollama 模型库为准）
ollama pull llama3.2
ollama run llama3.2 "用一句话解释什么是索引"

# 查看已下载模型与正在运行的模型
ollama list
ollama ps

# 原生 REST 接口
curl http://localhost:11434/api/chat -d '{
  "model": "llama3.2",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": false
}'

# OpenAI 兼容接口：现有 SDK 只需改 base_url
curl http://localhost:11434/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "llama3.2", "messages": [{"role": "user", "content": "hi"}]}'

本地服务提供原生与 OpenAI 兼容两种接口，便于把云端代码切换到本地模型。

⚖️ 06 · 方案取舍

本地模型

优点数据不出本机，可离线，无按量费

代价受硬件限制，能力与速度有限

适用隐私敏感、离线、批量低难度任务

云端 API

优点能力最强，免运维

代价按量付费，数据需出网

适用复杂推理、编码 Agent

自建 GPU 推理服务

优点团队共享，可控性高

代价硬件与运维成本高

适用企业内网、稳定大流量

🕳️ 07 · 常见坑

  • ✗选的模型超过显存，大量卸载到 CPU，慢到不可用

    ✓按显存选模型大小与量化级别，用 ollama ps 查看加载情况

  • ✗把本地服务直接暴露到公网且无鉴权

    ✓只监听本机或内网，必要时加反向代理鉴权

  • ✗默认上下文长度较短，长文档被截断

    ✓按需调大上下文参数，注意显存随之增加

  • ✗忽视模型许可证，直接商用

    ✓逐个核对模型许可条款与使用限制

🎤 09 · 面试追问
如何估算本地运行一个模型需要多少显存？

粗估：参数量 × 每参数字节数，再加 KV 缓存与运行开销。FP16 每参数约 2 字节，4 位量化约 0.5 字节多一点；上下文越长 KV 缓存越大。实际以工具显示的占用为准。

本地模型适合接入编码 Agent 吗？

可以用于补全、简单问答和隐私敏感的代码，但复杂的多步规划和工具调用通常明显弱于顶级云端模型，且长上下文对显存要求高。常见做法是本地处理简单任务，复杂任务路由到云端。

Ollama 和 vLLM 怎么选？

个人电脑、单用户、快速试用选 Ollama 或 LM Studio；需要在 GPU 服务器上高并发服务多个用户时选 vLLM 等面向吞吐优化的推理引擎。
