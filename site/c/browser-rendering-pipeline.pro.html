浏览器渲染流程 (重排 / 重绘)

Browser Rendering Pipeline

📐 01 · 定义

浏览器渲染流程（Rendering Pipeline）是浏览器把 HTML、CSS、JS 转为屏幕像素的一系列阶段：解析构建 DOM 与 CSSOM、样式计算、布局（Layout/Reflow）、绘制（Paint）、合成（Composite）。它属于浏览器引擎与前端性能层，理解哪些改动触发哪些阶段，是排查卡顿、掉帧和 INP 问题的基础。

⚙️ 02 · 原理
  1. 1

    解析 HTML 生成 DOM 树，解析 CSS 生成 CSSOM；遇到同步脚本会阻塞解析。

  2. 2

    样式计算（Recalculate Style）为每个 DOM 节点确定最终的计算样式。

  3. 3

    布局阶段计算每个可见元素的几何信息（位置、尺寸）；几何改变需要重新布局，即重排。

  4. 4

    绘制阶段把元素的文本、颜色、边框、阴影等记录为绘制指令并栅格化为像素，即重绘。

  5. 5

    合成阶段把分层后的图层按顺序组合输出到屏幕，transform 与 opacity 通常只需合成，可由合成线程/GPU 处理。

🔤 03 · 术语
重排 (Reflow / Layout)
重新计算元素几何信息，代价通常最高，可能波及大量节点。
重绘 (Repaint)
外观变化但几何不变时重新绘制像素。
合成层 (Compositing Layer)
单独栅格化、可独立变换的图层，如 will-change 元素。
强制同步布局 (Forced Synchronous Layout)
JS 修改样式后立即读取布局属性，迫使浏览器提前布局。
布局抖动 (Layout Thrashing)
循环中交替读写布局属性，反复触发强制布局。
💻 04 · 代码
避免布局抖动javascript
const items = document.querySelectorAll(".card");

// ❌ 读写交替：每次读 offsetWidth 都强制浏览器重新布局
items.forEach(el => {
  el.style.width = el.parentElement.offsetWidth / 2 + "px";
});

// ✅ 先批量读，再批量写，只触发一次布局
const widths = [...items].map(el => el.parentElement.offsetWidth);
items.forEach((el, i) => {
  el.style.width = widths[i] / 2 + "px";
});

// ✅ 动画优先用 transform/opacity，并在下一帧前统一写入
requestAnimationFrame(() => {
  items.forEach(el => (el.style.transform = "translateX(100px)"));
});

读写分离避免强制同步布局；transform 动画通常跳过布局与绘制。

📊 05 · 参数对比

CSS 属性触发的阶段

属性示例布局绘制合成
width / height / top / margin是是是
color / background / box-shadow否是是
transform / opacity否否是
font-size是是是
⚖️ 06 · 方案取舍

transform/opacity 动画

优点通常只需合成，帧率稳定

代价不改变布局，其他元素不会让位

适用位移、缩放、淡入淡出

will-change 提升图层

优点提前创建合成层，动画更顺

代价每层占用显存，过多反而变慢

适用确定即将动画的少量元素

CSS containment / content-visibility

优点限制布局与绘制影响范围

代价需理解副作用，兼容性需确认

适用长列表、复杂独立区块

🕳️ 07 · 常见坑

  • ✗用 top/left 或 width 做动画

    ✓改用 transform: translate/scale

  • ✗给大量元素加 will-change 作为「优化」

    ✓只对即将动画的元素临时设置，结束后移除

  • ✗循环中读取 offsetHeight、getBoundingClientRect 后又写样式

    ✓先批量读再批量写，或使用 requestAnimationFrame 分帧

  • ✗长列表全部渲染，滚动时大面积重绘

    ✓虚拟列表或 content-visibility: auto

🎤 09 · 面试追问
一帧内浏览器大致做哪些事？

处理输入与任务 → 执行 requestAnimationFrame 回调 → 样式计算 → 布局 → 绘制 → 合成。60Hz 屏幕每帧约 16.7ms，主线程工作超出预算就会掉帧。

为什么 transform 动画比 left 动画流畅？

left 改变几何，需要重新布局与绘制；transform 作用于合成层，浏览器可只重新合成，且常可在合成线程上执行，不受主线程繁忙影响。

什么是强制同步布局，如何发现？

JS 写入样式后立即读取布局属性，浏览器必须立刻执行布局来返回准确值。在 DevTools Performance 面板中会看到紫色 Layout 块并带有强制重排警告。
