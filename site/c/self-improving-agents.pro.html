自我进化的智能体

Self-Improving Agents

🧸 回到小白版

📐 01 · 定义

自我进化智能体（Self-Improving Agents）指能从执行经验中积累知识并改进后续表现的 Agent，通常不修改模型权重，而是通过反思总结、长期记忆、可复用技能库和提示词/工具的迭代来实现。目标是减少重复犯错、沉淀团队经验，但需防止错误经验被固化。

⚙️ 02 · 原理
  1. 1

    执行任务：Agent 按当前提示、已有记忆与技能完成任务，并留下完整执行轨迹。

  2. 2

    获取反馈：信号可来自测试结果、环境返回、评测打分或人工评价。

  3. 3

    反思总结：让模型分析失败原因，提炼成简短可复用的经验或规则。

  4. 4

    写入记忆/技能：把经验存入记忆文件、技能库或提示词，下次按相关性检索加载。

  5. 5

    验证与淘汰：在评测集上确认改进有效，过时或有害的经验及时删除。

🔤 03 · 术语
反思 (Reflection)
让模型对失败轨迹进行语言化分析并提出改进方向。
情景记忆 (Episodic Memory)
记录过去具体任务经历，供相似任务检索参考。
技能库 (Skill Library)
把验证过的解决方案存为可调用的代码或流程。
Reflexion
以语言反馈代替权重更新、让 Agent 迭代改进的方法。
经验污染 (Memory Poisoning)
错误或恶意内容写入记忆后持续影响后续行为。
💻 04 · 代码
失败反思写入记忆python
import json, subprocess, pathlib

MEM = pathlib.Path("lessons.json")

def load_lessons():
    return json.loads(MEM.read_text()) if MEM.exists() else []

def save_lesson(text):
    lessons = load_lessons()
    if text not in lessons:
        lessons.append(text)
        MEM.write_text(json.dumps(lessons[-50:], ensure_ascii=False))  # 只留最近 50 条

def run_tests():
    r = subprocess.run(["pytest", "-q"], capture_output=True, text=True)
    return r.returncode == 0, r.stdout[-2000:]   # 截断输出

# 每次任务开始：把 load_lessons() 拼进系统提示
# 任务结束：ok, log = run_tests()
# 若失败：让模型基于 log 写一句「下次应当…」，再 save_lesson(...)

最朴素的经验沉淀：以测试结果为反馈，把教训存成文件并在下次加载。

⚖️ 06 · 方案取舍

自动写入记忆

优点无需人工，经验持续积累

代价易积累错误或过拟合的规则

适用有可靠自动反馈（如测试）

人工审核后写入

优点质量可控，团队可共享

代价需要人力，更新慢

适用团队共享的项目规则

不做持久记忆

优点行为可预测，无污染风险

代价重复犯同样的错

适用一次性任务、高安全要求

🕳️ 07 · 常见坑

  • ✗把一次偶然失败总结成绝对规则，后续过度约束

    ✓记录经验的适用条件，定期复审和合并冲突条目

  • ✗记忆无限增长，挤占上下文且相互矛盾

    ✓设置容量上限，按相关性检索，过期条目淘汰

  • ✗把网页等不可信内容自动写进长期记忆

    ✓写入前过滤来源，敏感或外部内容需人工确认

  • ✗声称变好了却没有评测对比

    ✓用固定评测集对比改进前后的成功率

🎤 09 · 面试追问
不改权重，Agent 怎么变好？

通过上下文层面的改进：把反思得出的经验写入记忆并在相关任务中检索注入；把成功方案沉淀为技能或工具；迭代系统提示。本质是用更好的上下文和工具让同一模型做出更好决策。

自我改进最大的风险是什么？

错误经验被固化并反复放大，或被提示注入写入恶意规则（记忆污染）。缓解：经验必须有可靠反馈支撑、记录来源与适用条件、可审查可删除，并定期在评测集上回归。

在 Claude Code 里怎么落地这类机制？

用项目说明文件（如 CLAUDE.md）记录团队约定与踩坑经验，把重复流程沉淀为自定义命令或技能；新增条目通过代码审查，避免 Agent 随意写入未经验证的规则。
