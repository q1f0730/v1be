无冲突复制数据类型 (CRDT)

CRDTs

📐 01 · 定义

无冲突复制数据类型（CRDT）是一类特殊设计的数据结构，各副本可以在无协调、甚至离线的情况下独立修改，之后以任意顺序、任意次数交换并合并，最终都收敛到相同状态（强最终一致）。Shapiro 等人于 2011 年对其系统化。CRDT 是实时协同编辑、离线优先应用与多主复制的基础。

⚙️ 02 · 原理
  1. 1

    基于状态的 CRDT（CvRDT）在副本间发送完整或增量状态，合并函数满足交换律、结合律和幂等律。

  2. 2

    基于操作的 CRDT（CmRDT）广播操作，要求并发操作可交换，并依赖可靠的因果有序投递。

  3. 3

    计数器类：G-Counter 为每个副本单独计数后求和，PN-Counter 用两个 G-Counter 支持减法。

  4. 4

    集合与寄存器：LWW-Register 按时间戳保留最后写入；OR-Set 给每次添加打唯一标签以正确处理并发增删。

  5. 5

    文本序列：为每个字符分配全局唯一且可排序的标识（如 RGA、Yjs 的 YATA），并发插入按规则确定先后，删除用墓碑标记。

🔤 03 · 术语
强最终一致 (Strong Eventual Consistency)
收到相同更新集合的副本必然处于相同状态，无需冲突解决。
半格合并 (Join-semilattice)
状态型 CRDT 的数学基础：合并取最小上界，满足三条代数律。
OR-Set (Observed-Remove Set)
只删除已观察到的添加标签，使并发添加优先于删除。
墓碑 (Tombstone)
被删除元素保留的标记，用于正确合并，需垃圾回收控制体积。
Yjs / Automerge
两个主流开源 CRDT 库，常用于协同文档、白板和本地优先应用。
💻 04 · 代码
Yjs 两副本并发编辑合并javascript
// npm install yjs
import * as Y from 'yjs'

const a = new Y.Doc()
const b = new Y.Doc()

a.getText('note').insert(0, 'Hello')
Y.applyUpdate(b, Y.encodeStateAsUpdate(a))     // 同步初始内容

// 断网状态下两端在同一位置并发插入
a.getText('note').insert(5, ' from A')
b.getText('note').insert(5, ' from B')

// 恢复网络后互相交换更新（顺序与次数都不影响结果）
Y.applyUpdate(a, Y.encodeStateAsUpdate(b))
Y.applyUpdate(b, Y.encodeStateAsUpdate(a))

console.log(a.getText('note').toString())
console.log(a.getText('note').toString() === b.getText('note').toString()) // true

两端都保留了各自的插入，并按确定性规则排列；实际传输可用 y-websocket 等 provider。

CRDT数据结构保证合并收敛支持离线与点对点元数据与墓碑占空间

⚖️ 06 · 方案取舍

成熟 CRDT 库

优点离线优先、实时协作开箱可用

代价文档历史与元数据增长，需压缩

适用协同文档、白板、本地优先应用

服务端 OT

优点存储紧凑，权限集中控制

代价依赖中心服务器，实现难度大

适用始终在线的集中式编辑器

简单字段级 LWW

优点易实现，存储开销小

代价并发编辑同字段会丢数据

适用冲突极少的设置类数据

🕳️ 07 · 常见坑

  • ✗以为 CRDT 能保证业务语义正确

    ✓CRDT 只保证收敛；如余额不能为负等约束仍需协调或校验

  • ✗自行实现序列 CRDT

    ✓优先使用 Yjs、Automerge 等经过验证的库

  • ✗墓碑与历史无限增长，文档越来越慢

    ✓启用库提供的垃圾回收或快照压缩，归档旧历史

  • ✗依赖本机时间戳做 LWW

    ✓使用逻辑时钟或混合逻辑时钟，避免时钟偏差导致错误覆盖

🎤 09 · 面试追问
状态型 CRDT 的合并为什么要满足交换、结合、幂等？

网络中消息可能乱序、重复、经不同路径到达。交换律保证顺序无关，结合律保证分组无关，幂等律保证重复投递无害。三者合起来，任意副本只要收到相同的更新集合，就一定合并成同一状态。

CRDT 和 OT 怎么选？

需要离线编辑、点对点或多数据中心多主写入时，CRDT 更合适，因为不依赖中心转换。全程在线、已有中心服务、对文档体积敏感时，OT 也成熟可用。现代协作产品越来越多采用 CRDT 库以简化同步层。

OR-Set 如何处理并发的添加和删除？

每次添加元素都生成唯一标签，删除只移除当时观察到的标签。若一端删除元素的同时另一端重新添加，新添加带新标签不在删除集合中，合并后元素依然存在，即「添加获胜」语义，避免了简单集合的歧义。
