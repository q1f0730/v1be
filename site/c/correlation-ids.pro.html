请求关联标识符

Correlation IDs

📐 01 · 定义

关联标识符（Correlation ID）是在请求入口生成或接收、随请求在服务、队列与日志间传递的唯一 ID，用来把同一请求产生的所有日志和事件串联起来。它是轻量的可观测性手段，常经 X-Request-ID 等请求头传递；已接入分布式追踪时，traceparent 里的 Trace ID 通常可直接充当关联 ID。

⚙️ 02 · 原理
  1. 1

    入口网关或首个服务检查请求头，已有 ID 则沿用，没有则生成一个 UUID 等唯一值。

  2. 2

    服务把 ID 存入请求作用域上下文，如 Python 的 contextvars、Java 的 MDC。

  3. 3

    日志框架通过过滤器或格式化器在每条日志里自动输出该 ID，开发者无需手动传参。

  4. 4

    调用下游 HTTP 服务或发布消息时，把 ID 写入请求头或消息属性继续传递。

  5. 5

    响应头也返回该 ID，用户报障或前端报错时可凭它检索整条链路的日志。

🔤 03 · 术语
X-Request-ID
常见的非标准请求 ID 头，许多网关和框架都支持。
MDC (Mapped Diagnostic Context)
Java 日志框架中按线程保存上下文字段的机制。
contextvars
Python 标准库中支持异步任务隔离的上下文变量。
结构化日志 (Structured Logging)
以 JSON 等键值格式输出日志，便于按 ID 检索。
Trace ID
分布式追踪中的请求标识，可兼作关联 ID。
💻 04 · 代码
Flask 注入请求 IDpython
import logging, uuid
from contextvars import ContextVar
from flask import Flask, request, g

request_id: ContextVar[str] = ContextVar("request_id", default="-")

class RequestIdFilter(logging.Filter):
    def filter(self, record):
        record.request_id = request_id.get()  # 每条日志自动带上 ID
        return True

handler = logging.StreamHandler()
handler.addFilter(RequestIdFilter())
handler.setFormatter(logging.Formatter("%(asctime)s %(request_id)s %(message)s"))
logging.basicConfig(level=logging.INFO, handlers=[handler])

app = Flask(__name__)

@app.before_request
def assign_id():
    rid = request.headers.get("X-Request-ID") or str(uuid.uuid4())
    g.rid = rid
    request_id.set(rid)

@app.after_request
def echo_id(resp):
    resp.headers["X-Request-ID"] = g.rid      # 回传给调用方
    return resp

沿用或生成请求 ID，写入上下文变量并由日志过滤器自动输出，同时回写响应头。

🕳️ 07 · 常见坑

  • ✗异步任务或线程池中丢失上下文，后台日志没有 ID。

    ✓提交任务时显式传递 ID，或使用能复制上下文的执行器。

  • ✗盲目信任外部传入的 ID，被注入超长或恶意字符串。

    ✓校验格式与长度，不合法则重新生成。

  • ✗只在入口服务记录 ID，下游调用没传递。

    ✓在 HTTP 客户端和消息生产者统一注入。

☑️ 08 · 检查清单
🎤 09 · 面试追问
有了分布式追踪还需要关联 ID 吗？

多数情况下可直接用 Trace ID 作为关联 ID，并把它写入日志，二者合一。只有在对接未接入追踪的外部系统、或需要跨越追踪边界的业务 ID 如订单号时，才额外维护关联 ID。

异步场景如何保证关联 ID 不丢？

把 ID 放进消息头或任务参数，消费端取出后写入当前上下文；在线程池或协程中使用支持上下文复制的机制，如 Python 的 contextvars 配合 asyncio 自动传播，Java 用包装后的执行器传递 MDC。

关联 ID 对客服排障有什么价值？

把 ID 显示在错误页或返回给客户端，用户报障时提供该 ID，工程师即可在集中日志中一次检索出这次请求在所有服务里的日志，大幅缩短定位时间。
