进程与线程

Processes & Threads

📐 01 · 定义

进程（Process）是操作系统资源分配的基本单位，拥有独立的虚拟地址空间、文件描述符等资源；线程（Thread）是 CPU 调度的基本单位，同一进程内的多个线程共享内存与资源，但各自拥有栈和寄存器状态。理解二者的隔离性、开销与通信方式，是选择并发模型、排查资源占用和设计容器化服务的基础。

⚙️ 02 · 原理
  1. 1

    操作系统创建进程时为其分配独立的虚拟地址空间、页表和资源句柄，进程间默认相互隔离。

  2. 2

    进程内可创建多个线程，共享堆内存、全局变量和打开的文件，每个线程有独立的栈与程序计数器。

  3. 3

    调度器在 CPU 核心上切换线程；线程切换不涉及地址空间切换，通常比进程切换开销小。

  4. 4

    线程共享内存使通信高效，但需要锁、原子操作等同步机制避免竞态；进程间则需 IPC（管道、套接字、共享内存）。

  5. 5

    在 CPython 中，全局解释器锁（GIL）使同一时刻只有一个线程执行 Python 字节码，CPU 密集任务常用多进程（3.13 起提供实验性自由线程构建）。

🔤 03 · 术语
虚拟地址空间 (Virtual Address Space)
每个进程看到的独立内存视图，由操作系统映射到物理内存。
上下文切换 (Context Switch)
保存当前执行状态并切换到另一个线程或进程。
进程间通信 (IPC)
进程交换数据的机制，如管道、套接字、共享内存。
GIL (Global Interpreter Lock)
CPython 中保证同一时刻只有一个线程执行字节码的锁。
竞态条件 (Race Condition)
多个线程无同步地访问共享数据导致结果不确定。
PID
操作系统分配给每个进程的唯一标识号。
💻 04 · 代码
CPU 密集任务：线程池 vs 进程池python
import time
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor

def cpu_task(n: int) -> int:
    return sum(i * i for i in range(n))   # 纯计算，不等待 I/O

def bench(executor_cls, label):
    start = time.perf_counter()
    with executor_cls(max_workers=4) as ex:
        list(ex.map(cpu_task, [5_000_000] * 4))
    print(f"{label}: {time.perf_counter() - start:.2f}s")

if __name__ == "__main__":                # 多进程在部分平台需要此保护
    bench(ThreadPoolExecutor, "4 线程")    # 标准 CPython 受 GIL 限制，接近串行
    bench(ProcessPoolExecutor, "4 进程")   # 多核真正并行，通常明显更快

标准 CPython 中 CPU 密集任务多线程难以利用多核，多进程可以；具体加速比取决于机器核数。

📊 05 · 参数对比

进程与线程对比

维度进程线程
地址空间独立共享所属进程
创建与切换开销较大较小
通信方式IPC（管道、套接字等）直接读写共享内存
故障隔离一个崩溃通常不影响其他进程一个线程崩溃可能拖垮整个进程
同步需求较少需要锁等同步机制
⚖️ 06 · 方案取舍

多进程

优点隔离性好，可绕开 GIL 利用多核

代价内存占用高，通信成本高

适用CPU 密集、需要隔离的任务

多线程

优点共享内存、创建快

代价竞态与死锁风险，Python 受 GIL 限制

适用I/O 密集、需共享状态

单线程异步（事件循环）

优点极低开销处理大量并发 I/O

代价CPU 密集任务会阻塞循环

适用高并发网络服务

🕳️ 07 · 常见坑

  • ✗Python 中用多线程加速纯计算

    ✓CPU 密集用多进程或原生扩展，I/O 密集用线程或异步

  • ✗多线程修改共享变量不加锁

    ✓使用锁、队列或线程安全的数据结构

  • ✗进程池中传递巨大对象，序列化开销抵消收益

    ✓只传必要数据，或使用共享内存

  • ✗容器内开过多工作进程导致 OOM

    ✓按容器内存与 CPU 限额设置工作进程数

🎤 09 · 面试追问
进程和线程的根本区别是什么？

进程是资源分配单位，拥有独立地址空间，彼此隔离；线程是调度单位，同进程线程共享地址空间和资源。由此带来差异：线程通信快但需要同步，进程隔离好但创建和通信成本高。

Python 的 GIL 对并发有什么影响？

GIL 让标准 CPython 中同一时刻只有一个线程执行 Python 字节码，因此多线程无法让纯 Python 计算利用多核。但线程在等待 I/O 时会释放 GIL，所以 I/O 密集任务仍可受益；许多 C 扩展在计算时也会释放 GIL。PEP 703 引入了可选的自由线程构建。

为什么一个线程崩溃可能导致整个进程退出？

线程共享同一地址空间，段错误等致命错误会破坏整个进程的状态，操作系统通常终止整个进程。进程间则有地址空间隔离，因此 Chrome 等程序用多进程架构隔离标签页，提高稳定性。
