采样策略 (Top-p / Top-k)

Top-p / Top-k Sampling

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

采样策略是 LLM 解码时从下一个 Token 的概率分布中选取输出的方法。Top-k 只保留概率最高的 k 个候选；Top-p（核采样，Nucleus Sampling）保留累积概率达到 p 的最小候选集合；二者常与温度（temperature）配合，在确定性与多样性之间调节，属于推理参数层。

⚙️ 02 · 原理
  1. 1

    模型为词表中每个 Token 输出一个 logit（未归一化分数）。

  2. 2

    温度缩放：logits 除以 T，T<1 使分布更尖锐，T>1 使分布更平坦，T 趋近 0 接近贪心解码。

  3. 3

    Top-k 截断只保留分数最高的 k 个 Token；Top-p 按概率降序累加，保留到总和首次达到 p 为止。

  4. 4

    对保留的候选重新归一化，按概率随机抽取一个 Token，追加到序列后继续下一步。

  5. 5

    参数支持因厂商与模型而异：部分 API 不提供 top_k，部分推理模型不支持自定义这些参数。

🔤 03 · 术语
Logits
模型输出层的原始分数，经 softmax 变为概率。
贪心解码 (Greedy Decoding)
每步都选概率最高的 Token，结果确定但易重复。
核采样 (Nucleus / Top-p)
从累积概率达 p 的最小候选集中采样，候选数随分布动态变化。
Min-p 采样
保留概率不低于最高概率乘以系数的候选，部分开源引擎支持。
种子 (Seed)
固定随机数种子以提高可复现性，但多数服务不保证完全一致。
💻 04 · 代码
手写一次采样流程python
import numpy as np

def sample(logits, temperature=1.0, top_k=None, top_p=None, rng=np.random.default_rng(0)):
    logits = np.asarray(logits, dtype=float) / max(temperature, 1e-6)
    probs = np.exp(logits - logits.max())
    probs /= probs.sum()                      # softmax

    order = np.argsort(probs)[::-1]           # 概率从高到低
    keep = np.ones_like(probs, dtype=bool)
    if top_k is not None:                     # Top-k：只留前 k 个
        keep[order[top_k:]] = False
    if top_p is not None:                     # Top-p：累积到 p 为止
        cum = np.cumsum(probs[order])
        cutoff = np.searchsorted(cum, top_p) + 1
        keep[order[cutoff:]] = False

    probs = np.where(keep, probs, 0.0)
    probs /= probs.sum()                      # 重新归一化
    return rng.choice(len(probs), p=probs)

logits = [2.0, 1.5, 0.3, -1.0, -2.0]          # 5 个候选 Token 的分数
print(sample(logits, temperature=0.7, top_p=0.9))
print(sample(logits, top_k=1))                # 等价于贪心：总是选 0

推理引擎的实现细节（处理顺序、并列值）可能不同，这里只演示原理。

⚖️ 06 · 方案取舍

Top-k

优点实现简单，候选数固定

代价分布尖锐或平坦时 k 不合适

适用开源引擎中配合其他参数

Top-p

优点候选数随置信度自适应

代价分布很平时仍可能纳入长尾

适用多数 API 的主选项

低温/贪心

优点确定性强、利于测试

代价易重复、缺乏多样性

适用结构化、事实性任务

🕳️ 07 · 常见坑

  • ✗同时大幅调整 temperature 与 top_p，难以归因

    ✓一次只调一个，多数厂商建议二者择一调整

  • ✗以为 temperature=0 就完全可复现

    ✓批处理、硬件差异仍可能导致输出不同，测试需容忍差异

  • ✗对推理模型传入不支持的采样参数

    ✓查阅该模型文档，按其支持的参数调用

  • ✗用高温度掩盖提示词不清晰

    ✓先改进提示与上下文，再微调采样参数

☑️ 08 · 检查清单
🎤 09 · 面试追问
Top-p 相比 Top-k 的优势？

Top-k 候选数固定：模型很确定时仍保留 k 个低质候选，不确定时又可能截掉合理选项。Top-p 按累积概率截断，候选数随分布形状自适应，这是核采样论文提出的主要动机。

temperature 和 top_p 的作用顺序？

常见实现先用温度缩放 logits 改变分布形状，再在新分布上做 top-k/top-p 截断，最后归一化采样。因此温度会改变 top-p 截断后保留的候选数量，二者存在交互。

为什么写代码时通常建议低随机性？

代码对精确性要求高，一个错 Token 就可能导致语法或逻辑错误；低随机性让模型倾向最可能的写法，结果更稳定、便于复现和测试。需要多方案时可多次采样再用测试筛选。
