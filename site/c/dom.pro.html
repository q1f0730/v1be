文档对象模型 (DOM)

DOM

📐 01 · 定义

DOM（Document Object Model，文档对象模型）是浏览器把 HTML/XML 文档解析成的节点树，以及操作这棵树的编程接口，由 WHATWG DOM 标准定义。它位于前端运行时层：JavaScript 通过 DOM 读取和修改结构、样式与内容，浏览器据此重新计算样式、布局并绘制，React 等框架也最终落到 DOM 操作上。

⚙️ 02 · 原理
  1. 1

    浏览器边下载边解析 HTML，生成 Document 根下的元素、文本、注释等节点树。

  2. 2

    同步脚本会阻塞解析；DOMContentLoaded 在 DOM 构建完成时触发，load 要等图片等资源加载完。

  3. 3

    JS 通过 querySelector、createElement、append 等 API 查询与修改节点，通过 addEventListener 订阅事件。

  4. 4

    事件按捕获、目标、冒泡三个阶段传播，可在父节点统一处理子节点事件（事件委托）。

  5. 5

    DOM 变更触发样式重算、布局与绘制；频繁读写布局属性会造成强制同步布局，影响性能。

🔤 03 · 术语
节点 (Node) / 元素 (Element)
Node 是树中所有对象的基类，Element 是对应 HTML 标签的节点。
事件冒泡 (Bubbling)
事件从目标节点逐层向上传给祖先节点的过程。
事件委托 (Event Delegation)
在父元素上监听，依据 event.target 处理子元素事件。
回流/重排 (Reflow / Layout)
几何信息变化后重新计算布局，开销较大。
Shadow DOM
附着在元素上的隔离子树，Web Components 用于封装样式。
💻 04 · 代码
安全高效地操作 DOMjavascript
// DOM 构建完成后再查询元素（或给 script 加 defer）
document.addEventListener("DOMContentLoaded", () => {
  const list = document.querySelector("#todo-list");
  const items = ["买牛奶", "<img src=x onerror=alert(1)>"];

  // 批量插入：先放进 DocumentFragment，只触发一次插入
  const frag = document.createDocumentFragment();
  for (const text of items) {
    const li = document.createElement("li");
    li.textContent = text; // 用 textContent，不解析 HTML，防 XSS
    frag.append(li);
  }
  list.append(frag);

  // 事件委托：一个监听器处理所有 li，包括后来新增的
  list.addEventListener("click", (e) => {
    const li = e.target.closest("li");
    if (li) li.classList.toggle("done");
  });
});

用户数据用 textContent 插入；批量插入用片段；动态列表用事件委托。

⚖️ 06 · 方案取舍

原生 DOM 操作

优点无依赖、性能可控

代价状态与视图同步需手写

适用小交互、静态站增强

声明式框架（React/Vue）

优点状态驱动视图，组件化

代价运行时开销与构建链

适用交互复杂的应用

轻量增强库（htmx/Alpine）

优点贴近 HTML，学习成本低

代价复杂状态管理能力有限

适用服务端渲染为主的站点

🕳️ 07 · 常见坑

  • ✗脚本放在 head 且无 defer，查询元素得到 null

    ✓使用 defer、type=module 或在 DOMContentLoaded 后执行

  • ✗用 innerHTML 拼接用户输入

    ✓用 textContent 或 createElement；必须插 HTML 时先做净化

  • ✗循环中交替读取布局属性和修改样式

    ✓先批量读、再批量写，或用 requestAnimationFrame 合并

  • ✗在 React 组件中直接改 DOM 与框架状态打架

    ✓通过状态驱动渲染，必要时用 ref 并限定范围

🎤 09 · 面试追问
DOMContentLoaded 和 load 有什么区别？

DOMContentLoaded 在 HTML 解析完成、DOM 树建好且 defer 脚本执行后触发，不等图片、样式表等资源；load 在页面所有依赖资源加载完成后触发。需要操作 DOM 用前者，需要图片尺寸等用后者。

为什么说虚拟 DOM 不一定比直接操作 DOM 快？

虚拟 DOM 需要先在 JS 中生成新树并比对，再把差异应用到真实 DOM，本身有开销。它的价值在于用声明式写法换取「足够快」和可维护性；精心手写的最少 DOM 操作理论上更快。

事件委托的原理和局限？

利用冒泡在祖先上统一监听，用 target/closest 定位源元素，减少监听器数量并自动覆盖新增元素。局限：不冒泡的事件（如 focus，可改用 focusin）无法直接委托，且需注意 stopPropagation 会截断。
