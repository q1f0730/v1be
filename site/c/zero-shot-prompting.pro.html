零样本提示 (Zero-shot)

Zero-Shot Prompting

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

零样本提示（Zero-shot Prompting）指只给任务说明、不提供任何输入输出示例，依赖模型预训练与指令微调获得的泛化能力完成任务。它是提示工程的基线方法：成本最低、最易维护；当输出格式或判定标准模糊时，再升级为少样本（Few-shot）、思维链或结构化输出约束。

⚙️ 02 · 原理
  1. 1

    提示只包含角色/上下文、任务描述、约束与输出格式，不含示例对。

  2. 2

    指令微调（Instruction Tuning）与 RLHF 让模型学会遵循自然语言指令，这是零样本可行的前提。

  3. 3

    模型依据任务描述在其已学分布中匹配最相近的任务模式并生成结果。

  4. 4

    可叠加零样本思维链（如加入「请逐步思考」）提升推理类任务表现，推理模型则通常内置此过程。

  5. 5

    评估零样本基线后，若格式漂移或边界判定不稳，再引入示例、JSON Schema 或拆分任务。

🔤 03 · 术语
少样本 (Few-shot)
在提示中给出若干输入输出示例，让模型照样模仿。
上下文学习 (In-context Learning)
不更新权重，仅凭提示中的信息适应新任务的能力。
零样本思维链 (Zero-shot CoT)
不给示例，仅加入逐步推理指令以引导中间推理。
指令微调 (Instruction Tuning)
用大量指令-回答数据微调，使模型更会遵循指令。
基线 (Baseline)
最简单方案的效果，用于衡量后续复杂改进是否值得。
💻 04 · 代码
零样本分类 + 固定格式python
# pip install openai
from openai import OpenAI

client = OpenAI()  # 读取环境变量 OPENAI_API_KEY

review = "物流很快，但包装有点破"
resp = client.chat.completions.create(
    model="gpt-4o-mini",  # 换成你在用的模型
    temperature=0,        # 分类任务降低随机性
    messages=[
        {"role": "system", "content": "你是电商评价分类器。"},
        {"role": "user", "content": (
            "把评价分为 正面/中性/负面 之一。\n"
            "判定标准：同时有褒贬时选 中性。\n"
            "只输出类别，不要解释。\n"
            f"评价：{review}"
        )},
    ],
)
print(resp.choices[0].message.content)

零样本靠写清判定标准和输出格式取胜；没有示例时，边界规则必须用文字说明。

📊 05 · 参数对比

提示方式选型

方式Token 成本稳定性典型用途
零样本最低依赖指令清晰度通用问答、常见分类
少样本中格式更稳特殊格式、风格模仿
零样本 + CoT中（输出变长）推理更好数学、多步推理
结构化输出低格式可保证需机器解析的结果
⚖️ 06 · 方案取舍

纯零样本

优点提示短、易维护、成本低

代价边界与格式可能漂移

适用任务常见、标准清晰

加少量示例

优点格式与判定更一致

代价占 Token，示例偏差会被放大

适用零样本评估不达标时

零样本 + Schema 约束

优点格式由 API 保证

代价只管结构不管内容对错

适用结果要被程序解析

🕳️ 07 · 常见坑

  • ✗任务描述含糊（如「整理一下」）却期待特定格式

    ✓明确输出格式、字段与长度，必要时给 Schema

  • ✗没测零样本基线就堆示例和复杂提示

    ✓先建小评测集测零样本，再按收益逐步加料

  • ✗边界情况全靠模型猜

    ✓用规则写出边界判定（如褒贬并存归中性）

☑️ 08 · 检查清单
🎤 09 · 面试追问
零样本能力从何而来？

预训练让模型见过海量任务形态；指令微调与人类反馈对齐让它学会把自然语言指令映射到相应行为。因此无需示例也能执行常见任务，但对罕见格式或私有标准仍需示例或约束。

什么时候从零样本升级到少样本？

评测发现格式不稳定、边界判定不一致，或任务带有难以用文字描述的风格时。升级后要对比准确率与 Token 成本，并注意示例的分布、顺序和标签平衡，避免模型偏向某类。

对推理模型还需要「请逐步思考」吗？

通常收益有限：推理模型已内置思考过程，部分厂商文档也建议直接给清晰目标而非手动写思维链。更有效的是给足上下文、明确约束和验收标准。
