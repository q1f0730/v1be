本地 vs 云端

Local vs Cloud

📐 01 · 定义

本地（Local）指代码、数据或服务运行在开发者自己的机器上；云端（Cloud）指运行在云服务商的数据中心，通过网络按需使用算力、存储与托管服务。两者是开发流程的不同阶段与部署选择：本地用于快速开发调试，云端用于对外提供服务、弹性扩展与协作。差异集中在可达性、环境一致性、成本与数据控制。

⚙️ 02 · 原理
  1. 1

    本地开发：代码在本机运行，服务监听 localhost，只有本机能访问，改动即时可见。

  2. 2

    环境描述：用依赖锁文件、.env 示例、Dockerfile 把运行环境写成可复现的配置。

  3. 3

    构建产物：通过构建命令生成可部署的产物，如静态文件、容器镜像或函数包。

  4. 4

    云端部署：把产物推送到云平台，平台分配公网入口、注入环境变量并启动实例。

  5. 5

    运行与运维：云端负责扩缩容、日志、监控与备份，开发者通过控制台或 CLI 管理。

🔤 03 · 术语
IaaS / PaaS / SaaS
云服务三层：租基础设施、租运行平台、直接用软件。
环境一致性 (Parity)
开发、预发、生产环境尽量相同，减少「本地能跑」问题。
预发环境 (Staging)
与生产配置接近、用于上线前验证的环境。
区域 (Region)
云厂商数据中心所在地理区域，影响延迟与数据合规。
本地模型 (Local LLM)
用 Ollama、LM Studio 等在本机运行开源模型，数据不出机器。
💻 04 · 代码
Docker Compose 本地环境yaml
# docker-compose.yml：在本地一键启动与云端一致的依赖
# 运行：docker compose up -d
services:
  db:
    image: postgres:16            # 与云端数据库保持同一大版本
    environment:
      POSTGRES_PASSWORD: devpass   # 仅本地开发用，生产用密钥管理
      POSTGRES_DB: app
    ports:
      - "127.0.0.1:5432:5432"      # 只绑定本机，不暴露给局域网
    volumes:
      - pgdata:/var/lib/postgresql/data

  redis:
    image: redis:7
    ports:
      - "127.0.0.1:6379:6379"

volumes:
  pgdata:

用容器在本地复刻云端依赖的版本与配置，是缩小本地与云端差异的常用做法。

📊 05 · 参数对比

本地与云端工程差异

维度本地云端
可访问性默认仅本机公网可达，需安全防护
配置来源.env 文件平台环境变量 / 密钥管理
数据测试数据，可随意重置真实用户数据，需备份与合规
成本已有硬件，无边际费用按资源或用量计费
故障影响只影响自己影响所有用户
⚖️ 06 · 方案取舍

纯本地开发

优点快、免费、离线可用

代价无法给他人访问，环境易漂移

适用编码与调试阶段

云端开发环境（如 Codespaces）

优点环境统一、开箱即用

代价依赖网络，按时长计费

适用团队协作、配置复杂的项目

本地运行开源模型

优点数据不出机器、无调用费

代价受显存限制，能力通常弱于云端旗舰

适用隐私敏感、离线、实验

🕳️ 07 · 常见坑

  • ✗本地能跑，上云就报错，环境变量没配

    ✓维护 .env.example 列出全部变量，部署前逐项核对

  • ✗本地用 SQLite，生产用 Postgres，行为不一致

    ✓本地用容器跑与生产相同的数据库与版本

  • ✗为了调试把本地服务绑定 0.0.0.0 暴露在公共 Wi-Fi

    ✓开发服务默认只绑定 127.0.0.1

🎤 09 · 面试追问
「在我电脑上能跑」的根本原因是什么？

环境差异：操作系统、运行时版本、依赖版本、环境变量、文件路径大小写、数据库类型与数据。解决思路是把环境声明化：锁文件、容器镜像、配置清单，并在 CI 中用同一环境构建测试。

什么时候选择本地部署大模型？

数据不能外发、需要离线、调用量大到 API 费用不划算、或需要深度定制时。代价是硬件投入（主要是显存）、运维与较弱的模型能力。可先用 Ollama 等工具做验证，再评估是否值得。

IaaS、PaaS、SaaS 如何区分责任？

IaaS 提供虚拟机与网络，系统和应用归你；PaaS 提供运行平台，你只负责代码和配置；SaaS 直接提供成品软件，你只管使用与数据。越往上运维越少，可控性也越低。
