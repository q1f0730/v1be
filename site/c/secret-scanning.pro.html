机密扫描

📐 01 · 定义

机密扫描（Secret Scanning）是自动检测代码仓库、提交历史、CI 日志、容器镜像中意外包含的 API 密钥、令牌、私钥和密码的安全实践，基于正则特征、熵值和厂商令牌格式识别，部分工具还会调用接口验证密钥是否有效。它属于软件供应链与 DevSecOps 层，目标是在泄露前拦截、泄露后快速吊销。

⚙️ 02 · 原理
  1. 1

    在开发者本机用 pre-commit 钩子扫描暂存改动，发现疑似密钥即阻止提交。

  2. 2

    托管平台在推送时检查（如 GitHub 推送保护），命中已知令牌格式则拒绝推送。

  3. 3

    在 CI 中拉取并扫描完整提交历史，覆盖那些早已进入仓库的旧提交。

  4. 4

    命中后按格式识别服务商，部分工具验证密钥是否仍有效，以确定优先级。

  5. 5

    确认泄露后首先吊销并轮换密钥，再清理历史，并排查是否已被滥用。

🔤 03 · 术语
推送保护 (Push Protection)
在推送阶段拦截包含已知格式密钥的提交。
熵检测 (Entropy Detection)
根据字符串随机程度判断是否像密钥。
密钥轮换 (Secret Rotation)
生成新密钥替换旧密钥并使旧密钥失效。
误报 (False Positive)
被误认为密钥的测试值或示例字符串。
合作伙伴计划 (Partner Program)
平台把检测到的令牌通知发行方以便自动吊销。
💻 04 · 代码
用 gitleaks 扫描密钥yaml
# 文件：.pre-commit-config.yaml —— 提交前在本机扫描
repos:
  - repo: https://github.com/gitleaks/gitleaks
    rev: v8.18.0            # 建议固定为当前最新的发布版本
    hooks:
      - id: gitleaks

# 文件：.github/workflows/secrets.yml —— CI 扫描完整历史
# name: secret-scan
# on: [push, pull_request]
# jobs:
#   gitleaks:
#     runs-on: ubuntu-latest
#     steps:
#       - uses: actions/checkout@v4
#         with:
#           fetch-depth: 0          # 拉取全部历史，旧提交也会被扫描
#       - uses: gitleaks/gitleaks-action@v2
#         env:
#           GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}

# 安装钩子：pip install pre-commit && pre-commit install

本机钩子尽早拦截，CI 扫描全历史兜底；开发者可跳过本地钩子，所以服务端检查不可省。

🕳️ 07 · 常见坑

  • ✗发现泄露后只删除文件或改写历史，不吊销密钥

    ✓立即吊销并轮换；公开过的密钥应视为已被获取

  • ✗为消除告警随意加入忽略规则

    ✓忽略项需审查并记录原因，仅限确认的测试值

  • ✗只扫描当前代码，不扫描历史提交

    ✓CI 使用完整历史扫描，定期全量扫描

  • ✗让 AI 生成代码时把真实密钥写进示例或配置

    ✓用环境变量与 .env.example 占位，.env 加入 .gitignore

🎤 09 · 面试追问
密钥已经推送到公开仓库，第一步做什么？

第一步是吊销并轮换该密钥，而不是清理历史：公开仓库会被自动化工具快速抓取，应假设已泄露。随后检查服务商日志确认是否被滥用，再清理历史、补上扫描与防护措施并复盘。

为什么改写 git 历史还不够？

历史可能已被克隆、fork 或被缓存与镜像收录，CI 日志、PR 页面也可能残留。改写历史只能减少继续暴露，无法撤回已泄露的副本，因此密钥必须失效。

如何从根上减少密钥泄露？

使用密钥管理服务并在运行时注入；优先短期凭证与工作负载身份（如 OIDC 联合）替代长期密钥；为每个环境与服务分配最小权限密钥；配合多层扫描与快速轮换能力。
