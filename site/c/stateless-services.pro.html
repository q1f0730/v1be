无状态服务架构

Stateless Services

📐 01 · 定义

无状态服务（Stateless Service）指服务实例不在本地内存或磁盘中保存跨请求的业务状态，每个请求携带或从外部存储取得所需上下文，因此任意实例都能处理任意请求。它是云原生应用层的基础设计原则，使水平扩展、滚动发布、故障替换和自动扩缩容变得简单；状态被下沉到数据库、缓存、对象存储等专门的有状态组件。

⚙️ 02 · 原理
  1. 1

    会话、购物车、上传中的文件等状态从进程内存移到 Redis、数据库或对象存储。

  2. 2

    身份信息由请求携带，例如签名的 Cookie、JWT，或会话 ID 指向外部会话存储。

  3. 3

    负载均衡器可以把请求发给任意一个健康实例，不需要粘性会话，负载分配更均匀。

  4. 4

    实例可随时被创建、销毁和替换，扩缩容只需修改副本数，故障实例直接丢弃重建。

  5. 5

    真正有状态的组件单独管理，用 StatefulSet、托管数据库等承担持久化与复制。

🔤 03 · 术语
粘性会话 (Session Affinity)
负载均衡把同一客户端固定到同一实例，是有状态的信号。
外部化会话 (Externalized Session)
把会话数据存到共享存储，任意实例都可读取。
StatefulSet
Kubernetes 中为有状态应用提供稳定标识和持久卷的控制器。
可丢弃性 (Disposability)
进程可快速启动和停止，十二要素原则之一。
JWT (JSON Web Token)
自包含的签名令牌，服务端无需存储即可校验身份声明。
💻 04 · 代码
购物车状态外置到 Redispython
from flask import Flask, request, jsonify
import redis

app = Flask(__name__)
store = redis.Redis(host="redis", decode_responses=True)
# 反例：carts = {}  放在进程内存，换个实例就丢

@app.post("/cart/<user_id>/items")
def add_item(user_id):
    sku = request.json["sku"]
    key = f"cart:{user_id}"
    store.hincrby(key, sku, 1)       # 状态写到共享存储
    store.expire(key, 7 * 24 * 3600) # 购物车保留 7 天
    return jsonify(store.hgetall(key))

@app.get("/cart/<user_id>")
def get_cart(user_id):
    return jsonify(store.hgetall(f"cart:{user_id}"))

购物车写入 Redis 而非进程字典，任何实例都能读写，实例可随意扩缩。

📊 05 · 参数对比

状态放在哪里

状态类型推荐位置说明
登录会话Redis 或签名 Cookie/JWTJWT 需考虑吊销
用户上传文件对象存储（如 S3）不要写本地磁盘
业务数据数据库持久化与事务
进程内缓存本地内存（可丢）只存可重建的数据
⚖️ 06 · 方案取舍

外部会话存储

优点实例完全可替换

代价多一次网络访问，存储需高可用

适用大多数 Web 服务

自包含令牌（JWT）

优点无需服务端查询

代价吊销困难，令牌体积大

适用跨服务认证、短有效期

粘性会话

优点改造成本低

代价负载不均，实例下线丢会话

适用遗留系统过渡期

🕳️ 07 · 常见坑

  • ✗上传文件先存本地磁盘，后续请求落到其他实例找不到文件。

    ✓直接上传到对象存储，或用预签名 URL。

  • ✗进程内定时任务在每个副本都跑一遍。

    ✓定时任务独立部署或使用分布式锁/调度器。

  • ✗进程内缓存被当作唯一数据源。

    ✓本地缓存只存可从外部重建的数据，并设过期。

🎤 09 · 面试追问
无状态服务是不是就完全没有状态？

不是。它指实例不持有跨请求的业务状态，状态被外置到数据库、缓存等专门组件。系统整体仍有状态，只是集中到少数可专门做复制和备份的地方，计算层因此可以随意扩缩替换。

JWT 和服务端会话怎么选？

服务端会话可随时吊销、令牌小，但需要共享存储；JWT 无需查询，适合跨服务，但吊销难，只能靠短有效期加刷新令牌或黑名单。高敏感场景偏向服务端会话。

如何验证一个服务真的是无状态的？

部署多个副本并关闭粘性会话，压测过程中随机杀副本，观察请求是否全部成功、用户会话是否保持；检查代码中的全局变量、本地文件写入和进程内定时任务。
