📐 01 · 定义

前端（Frontend）是运行在用户设备（浏览器或 App）上、负责界面呈现与交互的那部分软件。Web 前端由 HTML、CSS、JavaScript 构成，现代工程通常借助 React、Vue 等框架和构建工具，通过 HTTP 调用后端 API 获取数据。前端关注渲染性能、交互体验、可访问性与跨设备兼容。

⚙️ 02 · 原理
  1. 1

    请求资源：浏览器根据 URL 下载 HTML，再加载其中引用的 CSS、JS、图片等。

  2. 2

    构建 DOM/CSSOM：解析 HTML 生成 DOM 树，解析 CSS 生成 CSSOM。

  3. 3

    渲染：合成渲染树后进行布局（Layout）和绘制（Paint），把页面画到屏幕上。

  4. 4

    执行脚本：JavaScript 监听用户事件、调用 API、修改 DOM，使页面动态更新。

  5. 5

    框架层：React/Vue 等用组件和状态管理界面，按状态变化高效更新 DOM。

🔤 03 · 术语
DOM
文档对象模型，页面结构的树形对象表示，JS 通过它操作页面。
SPA (单页应用)
首次加载后由 JS 在浏览器内切换视图，不整页刷新。
SSR (服务端渲染)
在服务器生成 HTML 再发给浏览器，利于首屏和 SEO。
构建工具 (Bundler)
如 Vite、webpack，打包、转译和优化前端代码。
Core Web Vitals
Google 定义的 LCP、INP、CLS 等用户体验性能指标。
💻 04 · 代码
前端调用后端 APIjavascript
// 浏览器原生 fetch：获取数据并渲染到页面
async function loadTodos() {
  const list = document.querySelector("#todos");
  try {
    const res = await fetch("/api/todos");          // 请求后端接口
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    const todos = await res.json();                 // 解析 JSON
    list.innerHTML = "";
    for (const t of todos) {
      const li = document.createElement("li");
      li.textContent = t.title;                     // 用 textContent 防 XSS
      list.appendChild(li);
    }
  } catch (err) {
    list.textContent = "加载失败，请稍后重试";       // 给用户可理解的反馈
    console.error(err);
  }
}

document.addEventListener("DOMContentLoaded", loadTodos);

前端的典型职责：请求数据、处理错误、安全地更新 DOM。框架只是把这些过程组件化。

📊 05 · 参数对比

渲染模式对比

模式原理优点代价
CSR 客户端渲染浏览器下载 JS 后生成页面交互流畅、部署简单首屏慢、SEO 较弱
SSR 服务端渲染每次请求在服务器生成 HTML首屏快、SEO 好需要服务器算力
SSG 静态生成构建时预生成 HTML最快、可放 CDN内容更新需重新构建
混合（如 Next.js）按页面选择渲染方式灵活心智负担与复杂度高
⚖️ 06 · 方案取舍

原生 HTML/CSS/JS

优点零依赖、加载快

代价复杂交互难维护

适用落地页、小工具

React/Vue 等框架

优点组件化、生态丰富

代价构建复杂、包体积大

适用交互复杂的应用

元框架（Next.js、Nuxt）

优点路由、SSR、部署一体化

代价约定多，学习成本高

适用需要 SEO 或全栈的产品

🕳️ 07 · 常见坑

  • ✗在前端校验权限或藏 API Key

    ✓前端代码对用户可见，权限与密钥只能放后端

  • ✗用 innerHTML 插入用户输入

    ✓用 textContent 或框架默认转义，防止 XSS

  • ✗只在自己的大屏电脑上测试

    ✓测试移动端尺寸、慢网和主流浏览器

  • ✗忽视加载和错误状态

    ✓为每个请求设计加载中、空数据、失败三种界面

🎤 09 · 面试追问
浏览器输入 URL 到页面显示经历什么？

DNS 解析域名 → 建立 TCP 连接与 TLS 握手 → 发送 HTTP 请求 → 服务器返回 HTML → 解析 HTML 构建 DOM、加载 CSS 构建 CSSOM → 执行 JS → 布局与绘制 → 合成显示。其中阻塞渲染的 CSS/JS 是首屏优化重点。

为什么前端校验不能替代后端校验？

前端运行在用户设备上，用户可修改代码、禁用 JS 或直接用 curl 调接口绕过页面。前端校验只改善体验，安全和数据正确性必须由后端再次校验。

AI 生成前端代码最常见的问题？

样式能看但不响应式；缺少加载与错误状态；可访问性缺失；直接用 innerHTML；引入过时或多余依赖；组件过大难维护。评审时要在多尺寸下实测，并检查状态处理与安全写法。
