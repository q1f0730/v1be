环境变量

Environment Variables

📐 01 · 定义

环境变量（Environment Variables）是操作系统为每个进程提供的键值对配置，进程启动时从父进程继承。现代应用遵循「配置与代码分离」原则，把数据库地址、API Key、运行模式等随环境变化的配置放在环境变量中，使同一份代码无需修改就能在开发、测试和生产环境运行。

⚙️ 02 · 原理
  1. 1

    设置：在 Shell、系统设置、部署平台控制台或 .env 文件中定义键值对。

  2. 2

    继承：子进程启动时复制父进程的环境变量，之后双方的修改互不影响。

  3. 3

    加载：开发时常用 dotenv 类工具或 Node 的 --env-file 把 .env 文件内容注入进程环境。

  4. 4

    读取：代码通过 process.env、os.environ 等接口读取，值一律是字符串。

  5. 5

    构建期注入：前端框架会把带特定前缀的变量在构建时直接写入打包产物，浏览器可见。

🔤 03 · 术语
.env 文件
本地存放环境变量的文本文件，不应提交到仓库。
.env.example
只列变量名和示例值的模板，提交到仓库供他人参考。
NEXT_PUBLIC_ / VITE_ 前缀
Next.js、Vite 中会被打包进前端代码的公开变量前缀。
十二要素应用 (Twelve-Factor App)
主张把配置存放在环境变量中的应用设计方法论。
PATH
最常见的系统环境变量，决定命令行到哪里查找可执行程序。
💻 04 · 代码
读取并校验配置python
# pip install python-dotenv
import os
from dotenv import load_dotenv

load_dotenv()   # 开发环境读取 .env；生产由平台注入，文件不存在也不报错

def require(name: str) -> str:
    value = os.environ.get(name)
    if not value:
        raise RuntimeError(f"缺少必需的环境变量: {name}")  # 启动即失败，比运行中报错好
    return value

DATABASE_URL = require("DATABASE_URL")
ANTHROPIC_API_KEY = require("ANTHROPIC_API_KEY")
DEBUG = os.environ.get("DEBUG", "false").lower() == "true"  # 值都是字符串，需自行转换
PORT = int(os.environ.get("PORT", "8000"))

print(f"debug={DEBUG}, port={PORT}")   # 不要打印密钥本身

# Node.js 20.6+ 可直接：node --env-file=.env app.js

启动时集中读取并校验必需变量，缺失立即报错；注意所有值都是字符串。

📊 05 · 参数对比

配置存放位置对比

位置适合放什么注意
代码常量不随环境变化的默认值绝不放密钥
环境变量随环境变化的配置与密钥值为字符串，需校验
前端公开变量公开的站点地址、分析 ID打包后任何人可见
密钥管理服务生产密钥、需轮换的凭证需额外集成与权限配置
⚖️ 06 · 方案取舍

.env 文件

优点本地开发简单直观

代价明文存储，易被误提交

适用本地开发

部署平台环境变量

优点与代码分离，按环境配置

代价多平台时管理分散

适用大多数线上应用

专用密钥管理（Vault 等）

优点加密、审计、轮换

代价引入额外系统

适用团队协作、合规要求高

🕳️ 07 · 常见坑

  • ✗把密钥放进 NEXT_PUBLIC_ 或 VITE_ 前缀变量

    ✓带公开前缀的变量会进入前端包，密钥只能在服务端使用

  • ✗改了 .env 但没重启服务，以为配置无效

    ✓环境变量在进程启动时读取，修改后需重启

  • ✗把 "false" 字符串当布尔值判断，结果恒为真

    ✓显式比较字符串或使用配置校验库

  • ✗在日志或报错中打印全部环境变量

    ✓日志中屏蔽敏感字段，只输出必要的非敏感配置

🎤 09 · 面试追问
为什么配置要放环境变量而不是配置文件？

环境变量与代码彻底分离，不会随代码提交；与语言和操作系统无关；部署平台和容器原生支持按环境注入。配置文件容易被误提交、各环境分支化。但复杂结构化配置仍可用文件，敏感部分再用环境变量引用。

前端项目能用环境变量保护 API Key 吗？

不能。前端构建工具会在打包时把变量值替换进 JS 代码，用户可直接看到。前端环境变量只适合公开配置。需要保密的 Key 必须留在服务端，由后端代理调用第三方服务。

Agent 读取项目时如何防止密钥泄露？

密钥只放在 .env 并被 Git 忽略；配置编码工具禁止读取 .env 或敏感目录（Claude Code 支持在权限设置中拒绝读取特定文件）；用占位值的 .env.example 让 Agent 了解变量名；避免把真实密钥粘贴进对话。
