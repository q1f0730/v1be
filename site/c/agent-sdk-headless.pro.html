智能体 SDK 与无头模式

Agent SDK & Headless Mode

🧸 回到小白版

📐 01 · 定义

智能体 SDK 与无头模式（Agent SDK & Headless Mode）指以编程方式而非交互界面驱动编程 Agent：通过 CLI 非交互参数（如 claude -p、codex exec）或语言 SDK 提交任务、配置工具权限、接收结构化输出，让 Agent 能嵌入脚本、CI/CD 和自研产品。

⚙️ 02 · 原理
  1. 1

    调用方以命令行参数或 SDK 函数传入提示、工作目录、系统提示与可用工具列表。

  2. 2

    运行时在无人值守的情况下执行 Agent 循环，权限由预先配置决定（允许的工具、权限模式），不会弹窗询问。

  3. 3

    输出以纯文本、JSON 或流式 JSON 返回，包含最终结果、轮数、耗时、费用等元数据，便于程序解析。

  4. 4

    SDK 通常以异步迭代器逐条返回消息（助手消息、工具调用、最终结果），调用方可实时记录或中断。

  5. 5

    会话 ID 可用于续接多轮任务；轮数与预算上限防止失控，退出码用于在 CI 中判断成功失败。

🔤 03 · 术语
无头模式 (Headless Mode)
不启动交互界面、一次性执行并输出结果的运行方式。
print 模式 (claude -p)
Claude Code 的非交互调用方式，执行后打印结果并退出。
允许工具列表 (allowedTools)
预先批准的工具或命令模式，未列出的不自动执行。
权限模式 (Permission Mode)
决定 Agent 遇到需批准操作时如何处理的整体策略。
结构化输出 (Structured Output)
JSON 或流式 JSON 格式，便于脚本解析结果与元数据。
💻 04 · 代码
Agent SDK 只读代码审查python
# pip install claude-agent-sdk  （接口以官方文档为准）
# CLI 等价写法：
#   claude -p "审查最近一次提交" --allowedTools "Read,Grep,Glob,Bash(git diff:*)" --output-format json
import asyncio
from claude_agent_sdk import query, ClaudeAgentOptions, ResultMessage

async def main():
    options = ClaudeAgentOptions(
        system_prompt="你是严格的代码审查员，只指出问题，不修改文件。",
        allowed_tools=["Read", "Grep", "Glob"],   # 只读工具
        max_turns=8,                              # 轮数上限
        cwd=".",
    )
    async for msg in query(prompt="审查 src/ 下的鉴权逻辑，按严重程度列出问题",
                           options=options):
        if isinstance(msg, ResultMessage):
            print(msg.result)
            print("轮数:", msg.num_turns, "费用(USD):", msg.total_cost_usd)

asyncio.run(main())

以只读工具与轮数上限运行无人值守任务，并从结果消息读取输出、轮数与费用。

📊 05 · 参数对比

调用方式对比

方式集成难度可控性适用
交互式 CLI/IDE无人实时把关日常开发
CLI 无头模式低，一行命令靠参数控制脚本、CI、定时任务
语言 SDK中可编程回调、细粒度控制自研产品、复杂流水线
托管 Action / 集成低受平台功能限制GitHub 评论触发、PR 审查
⚖️ 06 · 方案取舍

CLI 无头模式

优点上手快、适合 shell 与 CI

代价复杂逻辑需靠脚本拼接

适用简单自动化任务

SDK 嵌入

优点可编程处理消息、权限与工具

代价需要编写和维护代码

适用把 Agent 做成产品功能

交互式使用

优点人随时纠偏

代价无法自动化

适用探索性开发

🕳️ 07 · 常见坑

  • ✗CI 中使用跳过所有权限检查的模式

    ✓只授予任务所需的最小工具集，运行在隔离环境

  • ✗不设轮数或预算上限

    ✓设置最大轮数、预算与作业超时

  • ✗直接解析自然语言输出做判断

    ✓使用 JSON 输出或结构化结果字段

  • ✗把 API Key 写进脚本或日志

    ✓通过 CI 密钥注入，日志中脱敏

🎤 09 · 面试追问
无头模式下如何保证安全？

无人值守意味着没人能在危险操作前拒绝，所以权限必须事先收紧：只允许必要的工具和命令模式、在容器或临时环境中运行、使用最小权限凭据、限制网络出站，并保留完整日志供事后审计。

CLI 无头模式和 SDK 怎么选？

任务简单、在 shell 或 CI 中一次性执行，用 CLI 加参数即可；需要在程序中处理中间消息、动态决定权限、注册自定义工具或把 Agent 嵌入产品时，用 SDK 获得更细粒度的控制。

典型的 CI 场景有哪些？

PR 自动代码审查并发表评论、根据失败测试尝试修复、生成变更日志与发布说明、Issue 自动分类、定期依赖升级。关键是输出可解析、权限受限、结果仍需人工或 CI 门禁把关。
