绑定域名与证书

Domain & SSL

📐 01 · 定义

绑定域名与证书（Domain & SSL）是让用户通过可读的域名、以 HTTPS 加密方式访问服务的配置过程，涉及 DNS 解析和 TLS 证书两部分。DNS 把域名映射到服务器地址或平台主机名；TLS 证书由证书颁发机构（CA）签发，证明服务器身份并用于建立加密连接。习惯说的 SSL 实际已被 TLS 取代。

⚙️ 02 · 原理
  1. 1

    在注册商购买域名，并把权威 DNS 托管在注册商或 Cloudflare 等 DNS 服务商。

  2. 2

    添加 DNS 记录：A/AAAA 指向 IP，CNAME 指向平台主机名；根域名常用 ALIAS/CNAME 拉平等方案。

  3. 3

    CA 通过 ACME 等协议验证你控制该域名（HTTP-01、DNS-01 挑战），验证通过后签发证书。

  4. 4

    服务器或平台配置证书与私钥，客户端握手时校验证书链、有效期和域名匹配。

  5. 5

    证书到期前自动续期；托管平台和 Let's Encrypt 客户端通常自动完成。

🔤 03 · 术语
DNS 记录 (A/AAAA/CNAME)
A 指向 IPv4，AAAA 指向 IPv6，CNAME 指向另一个域名。
TTL
DNS 记录可被缓存的秒数，影响修改生效速度。
ACME
RFC 8555 定义的自动化证书签发协议，Let's Encrypt 使用。
证书链 (Certificate Chain)
从服务器证书经中间证书到受信根证书的信任路径。
SNI
TLS 扩展，客户端握手时告知目标域名，使同一 IP 可服务多证书。
💻 04 · 代码
检查 DNS 与证书bash
# 查看域名解析结果
dig +short example.com A
dig +short www.example.com CNAME

# 查看 TTL 与权威 DNS
dig example.com NS

# 查看证书颁发者与有效期（-servername 发送 SNI）
openssl s_client -connect example.com:443 -servername example.com </dev/null 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates

# 自建服务器用 certbot 为 Nginx 申请并自动配置 Let's Encrypt 证书
sudo certbot --nginx -d example.com -d www.example.com

# 测试自动续期
sudo certbot renew --dry-run

dig 排查解析，openssl 查看证书，certbot 负责签发与续期；托管平台通常自动处理证书。

🕳️ 07 · 常见坑

  • ✗根域名直接设置 CNAME 与其他记录冲突

    ✓根域名用 A 记录或服务商的 CNAME 拉平/ALIAS

  • ✗改 DNS 前未降低 TTL，迁移时长时间不生效

    ✓迁移前提前调低 TTL，切换后再调回

  • ✗证书续期失败无人知晓

    ✓监控证书到期时间并告警

  • ✗HTTPS 页面引用 HTTP 资源导致混合内容

    ✓所有资源使用 HTTPS 或相对协议

🎤 09 · 面试追问
HTTPS 证书解决了什么问题？

证书把公钥与域名绑定，并由受信任 CA 签名。浏览器校验证书后确认正在与真正的域名持有者通信，防止中间人冒充；随后通过 TLS 握手协商会话密钥，实现加密和完整性保护。没有证书校验，加密也可能是在和攻击者加密。

为什么根域名不能随便用 CNAME？

DNS 规范要求 CNAME 不能与同名的其他记录共存，而根域名必须有 SOA 和 NS 记录，因此根域名不能设 CNAME。许多 DNS 服务商提供 ALIAS、ANAME 或 CNAME 拉平，在服务端解析后返回 A 记录来解决。

HTTP-01 与 DNS-01 挑战有何区别？

HTTP-01 要求在域名的 80 端口特定路径放置验证文件，简单但需服务器公网可达，且不能签通配符证书。DNS-01 要求添加特定 TXT 记录，可签通配符、适合内网服务，但需要 DNS 写权限，凭证泄露风险更大。
