📐 01 · 定义

虚拟私有云（VPC）是在公有云中按账户隔离出的一块逻辑私有网络。你可以自定义 IP 地址段、划分子网、配置路由表、互联网网关和 NAT，决定哪些资源能访问公网、哪些只在内网互通。它是云上网络安全与架构设计的基础容器。

⚙️ 02 · 原理
  1. 1

    创建 VPC 时指定一个私有 CIDR 地址段（通常取自 RFC 1918，如 10.0.0.0/16）。

  2. 2

    在 VPC 内按可用区划分子网，每个子网关联一张路由表决定流量去向。

  3. 3

    附加互联网网关（IGW）供公有子网出入公网，NAT 网关供私有子网单向出网。

  4. 4

    通过 VPC 对等、Transit Gateway 或 VPN/专线与其他 VPC 和本地机房互联。

  5. 5

    VPC 端点让私网直接访问对象存储等云服务；流日志记录网络流量用于审计排障。

🔤 03 · 术语
CIDR 块
用前缀长度表示的地址段，如 10.0.0.0/16。
互联网网关 (Internet Gateway)
让 VPC 与公网双向通信的组件。
NAT 网关 (NAT Gateway)
让私有子网主动出网但不被公网直接访问。
VPC 对等 (VPC Peering)
两个 VPC 私网直连，不具传递性。
Transit Gateway
AWS 中多个 VPC 与本地网络的中心路由枢纽。
流日志 (Flow Logs)
记录网卡级 IP 流量的元数据日志。
💻 04 · 代码
AWS CLI 搭建 VPC 骨架bash
#!/usr/bin/env bash
set -euo pipefail
REGION=us-east-1

# 1. 创建 VPC，地址段避免与公司内网、其他 VPC 重叠
VPC_ID=$(aws ec2 create-vpc --cidr-block 10.20.0.0/16 \
  --query Vpc.VpcId --output text)
aws ec2 modify-vpc-attribute --vpc-id "$VPC_ID" --enable-dns-hostnames '{"Value":true}'

# 2. 互联网网关，供公有子网使用
IGW_ID=$(aws ec2 create-internet-gateway \
  --query InternetGateway.InternetGatewayId --output text)
aws ec2 attach-internet-gateway --vpc-id "$VPC_ID" --internet-gateway-id "$IGW_ID"

# 3. S3 网关端点：私有子网访问 S3 不经过 NAT
RT_ID=$(aws ec2 describe-route-tables --filters Name=vpc-id,Values="$VPC_ID" \
  --query 'RouteTables[0].RouteTableId' --output text)
aws ec2 create-vpc-endpoint --vpc-id "$VPC_ID" \
  --service-name "com.amazonaws.$REGION.s3" --route-table-ids "$RT_ID"

# 4. 开启流日志（发往 S3 存储桶，需事先创建）
aws ec2 create-flow-logs --resource-type VPC --resource-ids "$VPC_ID" \
  --traffic-type ALL --log-destination-type s3 \
  --log-destination arn:aws:s3:::my-flow-logs-bucket

演示 VPC 的核心组件；生产中建议用 Terraform 等 IaC 管理，子网另行规划。

VPC 互联方式

方式拓扑特点
VPC 对等点对点简单，不可传递，CIDR 不能重叠
Transit Gateway中心辐射集中路由，适合大量 VPC
PrivateLink/接口端点服务暴露只暴露单个服务，不打通整网
VPN / 专线云与机房混合云连接
⚖️ 06 · 方案取舍

单 VPC 多子网

优点简单，内部互通方便

代价环境隔离弱，爆炸半径大

适用小团队、早期项目

按环境/团队多 VPC

优点隔离清晰，权限边界明确

代价互联与地址规划更复杂

适用多环境、多团队组织

共享 VPC

优点网络集中管理，业务账号复用

代价需要平台团队治理

适用多账号的大型组织

🕳️ 07 · 常见坑

  • ✗多个 VPC 都用 10.0.0.0/16，日后无法对等

    ✓建立组织级 IP 地址规划，分配不重叠网段

  • ✗地址段开得太小，扩容时 IP 耗尽

    ✓预留足够大的 CIDR 与空闲子网块

  • ✗以为 A↔B、B↔C 对等后 A 能访问 C

    ✓对等不可传递，需直连或用 Transit Gateway

  • ✗数据库放在有公网路由的子网

    ✓数据层放私有或隔离子网

🎤 09 · 面试追问
VPC 对等和 Transit Gateway 怎么选？

少量 VPC、简单点对点互通用对等，免费且延迟低（跨 AZ 等流量仍计费）；VPC 数量多、需要集中路由、连接本地网络或做流量检查时用 Transit Gateway，代价是按连接与流量收费、多一跳。

私有子网的服务如何安全访问公网？

出向流量经 NAT 网关，NAT 位于公有子网并通过 IGW 出网，外部无法主动发起连接到私有实例。访问云服务优先用 VPC 端点；需要限制出网目的地时加出口代理或防火墙。

规划 VPC CIDR 要考虑什么？

与本地机房、其他 VPC、合作方网络不重叠；为未来可用区、子网和 Kubernetes Pod 地址留足空间；按环境或区域分配规则清晰的网段并登记；避免使用过小的前缀，后期扩容代价很高。
