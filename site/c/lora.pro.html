低秩适配微调 (LoRA / QLoRA)

LoRA / QLoRA

📐 01 · 定义

LoRA（Low-Rank Adaptation，低秩适配）是一种参数高效微调（PEFT）方法：冻结预训练权重 W，在选定线性层旁注入两个低秩矩阵 A、B，只训练它们，使权重更新 ΔW = BA 的秩远小于原矩阵。QLoRA 进一步把冻结的基座以 4-bit 量化加载，在其上训练 LoRA，显著降低显存。它属于模型训练与适配层。

⚙️ 02 · 原理
  1. 1

    选择目标模块（常见为注意力的 q/k/v/o 投影，或加上 MLP 层），冻结全部原始参数。

  2. 2

    为每个目标线性层添加 A（r×d）与 B（d×r），r 为秩（常见 8–64）；B 初始化为零，使训练开始时输出不变。

  3. 3

    前向时输出为 Wx + (α/r)·BAx，α 为缩放系数；反向传播只更新 A、B，优化器状态也只为它们保存。

  4. 4

    QLoRA 把基座权重量化为 4-bit NF4，计算时反量化到 BF16，并配合双重量化与分页优化器节省显存。

  5. 5

    训练后可单独保存适配器（通常几十 MB 级），推理时动态加载，或合并回基座权重消除额外延迟。

🔤 03 · 术语
秩 (Rank, r)
低秩矩阵的内维度，决定适配器容量与参数量。
lora_alpha
缩放系数，实际缩放为 α/r，影响更新幅度。
目标模块 (target_modules)
被注入 LoRA 的层名，如 q_proj、v_proj。
NF4 (4-bit NormalFloat)
QLoRA 提出的 4-bit 数据类型，针对正态分布权重设计。
PEFT
参数高效微调方法族，也是 Hugging Face 对应库的名称。
权重合并 (Merge)
把 BA 加回 W，得到无额外推理开销的完整模型。
💻 04 · 代码
PEFT 配置 QLoRApython
import torch
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4",
                         bnb_4bit_compute_dtype=torch.bfloat16,
                         bnb_4bit_use_double_quant=True)
model = AutoModelForCausalLM.from_pretrained(
    "Qwen/Qwen2.5-1.5B-Instruct", quantization_config=bnb, device_map="auto")
model = prepare_model_for_kbit_training(model)   # 4-bit 基座冻结

config = LoraConfig(
    r=16, lora_alpha=32, lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    task_type="CAUSAL_LM")
model = get_peft_model(model, config)
model.print_trainable_parameters()   # 可训练参数通常只占总量很小比例
# 之后交给 transformers Trainer 或 TRL 的 SFTTrainer 训练
# model.save_pretrained("my-adapter") 只保存适配器权重

基座以 4-bit 加载并冻结，只训练注意力投影上的 LoRA 矩阵；需 GPU 与 bitsandbytes。

📊 05 · 参数对比

微调方式对比

方式训练参数显存需求产物
全量微调全部最高（含优化器状态）完整模型
LoRA极少（低秩矩阵）需装下 16 位基座适配器文件
QLoRA同 LoRA基座 4-bit，显著更低适配器文件
提示工程/RAG无仅推理提示或知识库
⚖️ 06 · 方案取舍

LoRA

优点显存低、训练快、适配器可热切换

代价容量有限，复杂新知识效果不如全量

适用风格、格式、领域语气适配

QLoRA

优点单卡可微调较大模型

代价量化带来额外计算与轻微误差

适用显存紧张的个人/小团队

全量微调

优点表达能力最强

代价成本高，易灾难性遗忘

适用大量数据、深度领域迁移

不微调（RAG/提示）

优点无训练成本，知识可实时更新

代价无法改变模型行为习惯

适用知识问答类需求

🕳️ 07 · 常见坑

  • ✗用微调灌输事实知识，期望模型准确记住

    ✓事实知识用 RAG；微调更适合行为、格式和风格

  • ✗小数据集训练过多轮导致过拟合

    ✓留验证集，监控验证损失，早停或减少轮次

  • ✗训练与推理使用不同的对话模板

    ✓训练数据套用与推理一致的 chat template

  • ✗合并到 4-bit 量化基座后精度异常

    ✓合并时在 16 位精度的基座上进行，再按需量化

🎤 09 · 面试追问
LoRA 为什么有效？

论文假设微调时权重更新具有低「内在秩」，用低秩矩阵即可近似；冻结基座也减少优化器状态和梯度显存。实验表明在多种任务上接近全量微调效果。

秩 r 和 alpha 如何选？

r 越大容量越高、参数越多；常从 8 或 16 起步。缩放为 α/r，常见做法是 α 设为 r 的 1–2 倍。最终以验证集效果为准，并配合学习率一起调。

QLoRA 节省显存的三个关键技术？

4-bit NF4 量化基座权重；双重量化（对量化常数再量化）；分页优化器在显存峰值时把优化器状态换出到 CPU 内存。论文据此在单张 48GB GPU 上微调了 65B 模型。
