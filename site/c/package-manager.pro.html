包管理器 (npm / pip)

Package Manager

📐 01 · 定义

包管理器（Package Manager）是自动完成依赖的查找、版本解析、下载、安装、更新与移除的工具，如 JavaScript 的 npm、pnpm、Yarn，Python 的 pip、uv、Poetry。它读取项目清单文件中的依赖声明，生成锁文件记录精确版本，使团队、CI 与生产环境能安装出完全一致的依赖树。

⚙️ 02 · 原理
  1. 1

    读取清单：解析 package.json 或 pyproject.toml 中声明的依赖及版本范围。

  2. 2

    版本解析：计算满足所有约束的版本组合，包括依赖的依赖（传递依赖）。

  3. 3

    下载缓存：从注册表下载包，存入本地缓存，重复安装时直接复用。

  4. 4

    安装布局：写入 node_modules 或虚拟环境的 site-packages，必要时执行安装脚本。

  5. 5

    写锁文件：把解析出的精确版本与校验和写入锁文件，供后续可复现安装。

🔤 03 · 术语
锁文件 (Lockfile)
记录精确依赖版本与校验和的文件，如 package-lock.json。
版本范围 (^ / ~)
^1.2.3 允许 <2.0.0 的更新；~1.2.3 允许 <1.3.0。
虚拟环境 (venv)
Python 中隔离项目依赖的独立环境。
devDependencies
只在开发和构建时需要的依赖，如测试工具。
npm ci
严格按锁文件进行干净安装的命令，适合 CI。
💻 04 · 代码
Node 与 Python 常用命令bash
# ---- Node.js（npm）----
npm install                 # 按 package.json 安装，并更新锁文件
npm install zod             # 添加运行时依赖
npm install -D vitest       # 添加开发依赖
npm ci                      # CI 中使用：严格按锁文件安装
npm outdated                # 查看可升级的依赖
npm audit                   # 检查已知漏洞

# ---- Python（venv + pip）----
python3 -m venv .venv       # 创建虚拟环境
source .venv/bin/activate   # 激活（Windows: .venv\Scripts\activate）
pip install requests
pip freeze > requirements.txt   # 记录当前精确版本

# ---- Python（uv，更快的替代）----
uv init my-app && cd my-app
uv add requests             # 写入 pyproject.toml 并生成 uv.lock
uv run main.py              # 在项目环境中运行

日常开发用 install，CI 用 ci 或按锁文件安装；Python 项目务必在虚拟环境中装依赖。

⚖️ 06 · 方案取舍

宽松版本范围（^）

优点自动获得修复与新功能

代价依赖更新可能引入意外变化

适用配合锁文件与测试使用

精确锁定版本

优点完全可复现

代价需主动升级，否则积累过时依赖

适用生产应用、关键系统

自动化依赖更新机器人

优点持续小步升级，降低积压

代价PR 数量多，需要测试兜底

适用有 CI 测试的活跃项目

🕳️ 07 · 常见坑

  • ✗锁文件被加入 .gitignore 不提交

    ✓应用项目必须提交锁文件，保证各环境一致

  • ✗同一项目混用 npm 和 yarn，出现两份锁文件

    ✓团队统一一个包管理器，可在 package.json 的 packageManager 字段声明

  • ✗Python 依赖装进系统全局环境

    ✓每个项目使用独立虚拟环境

  • ✗CI 中用 npm install，悄悄改变依赖版本

    ✓CI 用 npm ci 严格按锁文件安装

🎤 09 · 面试追问
为什么有了版本范围还需要锁文件？

版本范围只声明可接受区间，不同时间安装可能解析出不同版本，传递依赖更是如此。锁文件记录整棵依赖树的精确版本和校验和，保证开发、CI、生产安装结果一致，也便于审计和回溯问题。

npm install 和 npm ci 的区别？

npm install 会根据 package.json 解析并可能更新锁文件；npm ci 要求锁文件存在且与 package.json 一致，删除现有 node_modules 后严格按锁文件安装，不修改锁文件，更快更可复现，适合 CI 和部署。

安装脚本为什么是安全风险？

npm 等允许包在安装时执行 preinstall/postinstall 脚本，恶意包可借此窃取环境变量和凭证。缓解：审查新依赖、在 CI 中按需禁用脚本（如 --ignore-scripts）、使用锁文件和依赖扫描、最小化构建环境中的密钥。
