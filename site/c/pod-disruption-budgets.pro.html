Pod中断预算 (PDB)

Pod Disruption Budgets

🧸 回到小白版

📐 01 · 定义

Pod 中断预算（PodDisruptionBudget，PDB）是 Kubernetes 中限制自愿中断时同时不可用 Pod 数量的策略对象。在节点排空、集群升级、自动缩容等通过驱逐 API 进行的操作中，若驱逐会使可用 Pod 低于预算，请求就会被拒绝，从而保证维护期间服务仍有足够副本运行。

⚙️ 02 · 原理
  1. 1

    定义预算：用标签选择器匹配一组 Pod，设置 minAvailable 或 maxUnavailable。

  2. 2

    自愿中断：kubectl drain、集群自动扩缩器等通过驱逐 API 请求移除 Pod。

  3. 3

    预算检查：API Server 计算当前健康 Pod 数，驱逐后若违反预算则拒绝该请求。

  4. 4

    重试推进：调用方稍后重试，待替换 Pod 在其他节点就绪后，驱逐才得以继续。

  5. 5

    范围限制：节点宕机等非自愿中断不受 PDB 约束，直接删除 Pod 也会绕过 PDB。

🔤 03 · 术语
自愿中断 (Voluntary Disruption)
由运维操作主动发起的中断，如排空节点、升级。
非自愿中断 (Involuntary Disruption)
硬件故障、内核崩溃、节点失联等不可控中断。
驱逐 API (Eviction API)
会检查 PDB 的 Pod 移除接口，drain 通过它工作。
minAvailable / maxUnavailable
至少保持可用数或最多不可用数，可写整数或百分比。
unhealthyPodEvictionPolicy
控制不健康 Pod 是否可在预算不足时被驱逐。
💻 04 · 代码
PDB 定义与检查yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: api-pdb
  namespace: shop
spec:
  maxUnavailable: 1            # 任意时刻最多 1 个副本因自愿中断不可用
  selector:
    matchLabels:
      app: api
  # 不健康的 Pod 即使预算不足也允许被驱逐，避免卡住排空
  unhealthyPodEvictionPolicy: AlwaysAllow

# 查看当前允许的中断数：
#   kubectl get pdb -n shop
#   ALLOWED DISRUPTIONS 为 0 时，drain 会一直等待重试

maxUnavailable 在扩缩副本时更稳定；ALLOWED DISRUPTIONS 长期为 0 会阻塞节点维护。

📊 05 · 参数对比

PDB 配置选择

配置效果风险
maxUnavailable: 1每次只中断 1 个副本多时升级较慢
minAvailable: 50%至少一半副本在线副本数很少时取整可能过严
minAvailable 等于副本数不允许任何自愿驱逐节点排空与升级被永久阻塞
maxUnavailable: 0同样不允许驱逐同上，应避免
⚖️ 06 · 方案取舍

maxUnavailable

优点随副本数变化仍允许固定中断量

代价副本少时比例可能过大

适用多数无状态服务

minAvailable

优点直观表达最低在线要求

代价副本数调整后需同步修改

适用有明确最小副本要求的服务

不设 PDB

优点维护操作不受阻

代价排空时可能同时下线全部副本

适用可接受中断的批处理或开发环境

🕳️ 07 · 常见坑

  • ✗单副本服务配 minAvailable: 1，节点永远排空不了

    ✓关键服务至少两副本，或用 maxUnavailable: 1 接受短暂中断

  • ✗以为 PDB 能防止节点宕机导致的不可用

    ✓PDB 只管自愿中断，可用性还需多副本和跨可用区分布

  • ✗PDB 选择器与 Deployment 标签不匹配，预算形同虚设

    ✓用 kubectl get pdb 检查 CURRENT/ALLOWED 字段是否符合预期

  • ✗Pod 一直不就绪导致预算耗尽，维护被卡住

    ✓修复就绪探针或设置 unhealthyPodEvictionPolicy: AlwaysAllow

☑️ 08 · 检查清单
🎤 09 · 面试追问
PDB 能防住哪些中断，防不住哪些？

能限制经由驱逐 API 的自愿中断，如 kubectl drain、集群自动缩容、托管集群节点升级。防不住节点宕机、内核崩溃、网络分区等非自愿中断，也拦不住直接删除 Pod 或删除 Deployment。

集群升级卡在排空节点，怎么排查？

先看 kubectl get pdb 是否有 ALLOWED DISRUPTIONS 为 0 的预算；常见原因是单副本服务配置了 minAvailable: 1、Pod 未就绪占用预算、副本无法在其他节点调度。按原因扩副本、修复探针或调整 PDB。

minAvailable 和 maxUnavailable 怎么选？

maxUnavailable 表达每次允许中断几个，副本数增加时也不需修改，对滚动维护更友好；minAvailable 表达最少在线数，适合对最低容量有硬性要求的服务。两者只能设置一个。
