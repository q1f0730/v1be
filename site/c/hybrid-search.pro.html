混合检索 (BM25 + 向量)

Hybrid Search

📐 01 · 定义

混合检索（Hybrid Search）是同时运行稀疏检索（关键词匹配，常用 BM25）与稠密检索（向量语义相似度），再把两路结果融合成一个排序的检索方法。稀疏检索擅长精确匹配型号、人名、代码标识符，稠密检索擅长同义改写和语义相近的表达，二者互补，是生产级 RAG 的常见基线。

⚙️ 02 · 原理
  1. 1

    离线阶段同时建立倒排索引（用于 BM25）和向量索引（用于 ANN 检索），文档切块后两者都要写入。

  2. 2

    查询时并行执行两路检索：BM25 按词频与逆文档频率打分，向量检索按嵌入的余弦或点积相似度打分。

  3. 3

    两路分数尺度不同，融合常用倒数排名融合（RRF）：按名次计算 1/(k+rank) 并求和，常用 k=60。

  4. 4

    也可做分数归一化后线性加权（alpha 参数控制语义与关键词比重），但需要调参。

  5. 5

    融合结果可再交给重排模型精排，最后取 Top-K 放入大模型上下文。

🔤 03 · 术语
BM25
基于词频、逆文档频率和文档长度归一化的经典关键词排序函数。
稀疏向量 (Sparse Vector)
维度为词表、多数为 0 的表示，如 BM25、SPLADE。
稠密向量 (Dense Vector)
由嵌入模型生成的低维连续向量，表示语义。
倒数排名融合 (RRF)
按各路排名的倒数求和融合结果，无需分数归一化。
alpha 加权
在归一化分数上按比例混合两路结果的融合方式。
分词 (Tokenization)
中文 BM25 需要合适的分词器，否则关键词匹配效果差。
💻 04 · 代码
BM25 + 向量结果用 RRF 融合python
from rank_bm25 import BM25Okapi

docs = ["iPhone 15 电池续航说明", "手机过热怎么办", "订单 A1023 物流查询", "iPhone 14 维修政策"]
# 中文建议先用 jieba 等分词，这里按单字粗略示意
bm25 = BM25Okapi([list(d) for d in docs])

def bm25_rank(q):
    scores = bm25.get_scores(list(q))
    return sorted(range(len(docs)), key=lambda i: -scores[i])

def rrf(rankings, k=60):
    fused = {}
    for ranking in rankings:
        for rank, doc_id in enumerate(ranking, start=1):
            fused[doc_id] = fused.get(doc_id, 0) + 1 / (k + rank)
    return sorted(fused, key=fused.get, reverse=True)

q = "手机发烫 iPhone 15"
keyword = bm25_rank(q)
vector = [1, 0, 3, 2]   # 假设这是向量检索返回的文档 ID 排名
for i in rrf([keyword, vector])[:3]:
    print(docs[i])

RRF 只用名次融合，避免 BM25 分数与余弦相似度量纲不同的问题；向量排名在此为示意。

⚖️ 06 · 方案取舍

RRF 融合

优点无需调参、对分数尺度不敏感

代价忽略分数差距信息

适用默认首选

归一化 + alpha 加权

优点可按业务调节两路比重

代价需评测集调参，分布变化需重调

适用有评测数据、追求极致效果

只用向量检索

优点架构最简单

代价精确匹配类查询效果差

适用纯语义问答、无编号类查询

🕳️ 07 · 常见坑

  • ✗中文 BM25 不做分词或用英文分词器

    ✓使用中文分词（如 jieba）或 n-gram 分析器

  • ✗直接把 BM25 分数和余弦相似度相加

    ✓用 RRF 或先归一化再加权

  • ✗两个索引更新不同步，结果不一致

    ✓文档写入时同时更新两路索引，或使用原生支持混合检索的数据库

  • ✗上线前没有对比单路与混合的效果

    ✓在评测集上比较 Recall@K 与答案准确率

🎤 09 · 面试追问
为什么向量检索搜不准订单号？

嵌入模型把文本压缩为语义向量，A1023 与 A1032 这类字符串在语义空间里非常接近，也缺乏训练语料中的含义，因此相似度区分度低。BM25 按精确词项匹配，能直接命中，这正是混合检索的价值。

RRF 的原理和优点是什么？

对每个文档在各路结果中的排名 r 计算 1/(k+r) 并求和，k 常取 60 用于平滑头部差距。它只依赖名次，不需要把不同量纲的分数归一化，也无需训练，鲁棒且实现简单。

混合检索和重排是什么关系？

混合检索属于召回阶段，目标是尽量把相关文档都找出来；重排属于精排阶段，在召回的候选上用更重的模型精确排序。生产中常组合为“混合检索召回 → 重排 → Top-K 送入大模型”。
