水合 (Hydration)

Hydration

📐 01 · 定义

水合（Hydration）是客户端 JavaScript 接管服务端渲染（SSR/SSG）HTML 的过程：框架在浏览器中重新执行组件，把生成的虚拟树与已有 DOM 对齐，并绑定事件处理和状态，使静态页面变得可交互。它属于前端渲染层，常见问题是服务端与客户端首次渲染结果不一致导致的 hydration mismatch。

⚙️ 02 · 原理
  1. 1

    服务端执行组件生成 HTML，浏览器先显示这份 HTML，用户能看到内容但还不能交互。

  2. 2

    浏览器下载并执行页面 JS bundle，框架入口调用如 React 的 hydrateRoot。

  3. 3

    框架在客户端重新渲染组件树，逐个复用已有 DOM 节点，而不是重新创建。

  4. 4

    对齐过程中绑定事件监听、恢复状态；若某处文本或结构不同，即报告 mismatch，React 可能放弃该部分转为客户端重新渲染。

  5. 5

    完成后页面进入可交互状态；从显示到可交互之间的空窗影响 INP 与用户体验。

🔤 03 · 术语
Hydration Mismatch
服务端 HTML 与客户端首次渲染结果不一致的错误。
hydrateRoot
React 18 起用于在已有 SSR HTML 上挂载并水合的 API。
选择性水合 (Selective Hydration)
React 18 结合 Suspense 按优先级分块水合，用户交互的部分优先。
岛屿架构 (Islands Architecture)
页面大部分静态，只水合少数交互组件，如 Astro。
可恢复性 (Resumability)
Qwik 的思路：序列化状态，客户端无需重新执行即可恢复交互。
💻 04 · 代码
修复时间导致的 mismatchtypescript
"use client";
import { useEffect, useState } from "react";

// ❌ 服务端与客户端执行时刻不同，文本必然不一致
// export function Clock() { return <span>{new Date().toLocaleTimeString()}</span>; }

// ✅ 首次渲染输出与服务端一致，挂载后再取浏览器时间
export function Clock() {
  const [now, setNow] = useState<string | null>(null);
  useEffect(() => {
    setNow(new Date().toLocaleTimeString());
    const t = setInterval(() => setNow(new Date().toLocaleTimeString()), 1000);
    return () => clearInterval(t);
  }, []);
  return <span>{now ?? "--:--:--"}</span>;
}

// 少数无法避免的差异（如时间戳文本）可在该元素上
// 使用 suppressHydrationWarning，它只作用于一层文本

useEffect 只在客户端执行，把依赖浏览器环境的值推迟到水合之后。

常见 mismatch 来源

来源例子修复

随机值Math.random() 生成 key/ID用 useId 或服务端传入

🕳️ 07 · 常见坑

  • ✗组件渲染中直接读 window/localStorage

    ✓放到 useEffect 或使用动态导入并关闭 SSR

  • ✗用 suppressHydrationWarning 掩盖所有警告

    ✓只用于确知无害的单个文本差异，先修根因

  • ✗在 <p> 内嵌套块级元素

    ✓浏览器会自动修正 DOM 导致结构不一致，改用合法嵌套

  • ✗服务端与客户端使用不同时区格式化日期

    ✓统一时区或传入已格式化的字符串

🎤 09 · 面试追问
为什么会出现「页面能看但点不动」？

SSR HTML 已显示，但 JS 尚未下载、执行或水合完成，事件还没绑定。JS 越大、主线程越忙，这段空窗越长。可通过代码分割、减少客户端组件、选择性水合缓解。

React 18 的选择性水合解决了什么？

以前水合必须整棵树一次完成；配合 Suspense 后可分块进行，并优先水合用户正在交互的区域，避免一个慢组件阻塞全页交互。

Server Components 与水合是什么关系？

Server Components 只在服务端运行，输出不需要客户端 JS，也不参与水合；只有标记 "use client" 的组件会被打包并水合，从而减少水合成本。
