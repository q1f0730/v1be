事务性发件箱模式

Outbox Pattern

🧸 回到小白版

📐 01 · 定义

事务性发件箱（Transactional Outbox）是解决「更新数据库」与「发布消息」双写一致性的模式：业务数据与待发事件在同一个本地事务中写入数据库，事件存入 outbox 表；再由独立的中继进程（轮询或 CDC）把事件投递到消息系统。这样避免了提交成功但消息丢失，或消息发出但事务回滚。

⚙️ 02 · 原理
  1. 1

    同一事务写入：业务表更新与 outbox 表插入事件在一个本地数据库事务中提交。

  2. 2

    事件内容：outbox 行包含事件 ID、聚合类型与 ID、事件类型、负载和创建时间。

  3. 3

    中继读取：轮询进程按顺序取未发送事件，或用 CDC 读取 outbox 表的变更日志。

  4. 4

    投递消息：发送到 Kafka 等消息系统，成功后标记已发送或删除该行。

  5. 5

    消费者去重：中继可能重复投递，消费者按事件 ID 幂等处理。

🔤 03 · 术语
双写问题 (Dual Write)
同时写数据库和消息系统，无法保证两者原子成功或失败。
消息中继 (Message Relay)
把 outbox 表中的事件搬运到消息代理的进程。
至少一次投递 (At-least-once)
消息保证送达但可能重复，需要消费者幂等。
SKIP LOCKED
行锁选项：跳过被其他事务锁定的行，便于多个中继并发取任务。
收件箱模式 (Inbox Pattern)
消费者记录已处理消息 ID，以实现幂等消费。
💻 04 · 代码
写入与中继取件sql
-- 业务事务：订单与事件一起提交，要么都成功，要么都回滚
BEGIN;
INSERT INTO orders (id, user_id, amount) VALUES (1001, 7, 99.00);
INSERT INTO outbox (id, aggregate_type, aggregate_id, event_type, payload)
VALUES (gen_random_uuid(), 'order', '1001', 'OrderCreated',
        '{"orderId":1001,"amount":99.00}');
COMMIT;

-- 中继进程：批量取未发送事件，多实例并发时互不抢同一行
BEGIN;
SELECT id, event_type, payload FROM outbox
WHERE sent_at IS NULL
ORDER BY created_at
LIMIT 100
FOR UPDATE SKIP LOCKED;
-- ……逐条发送到消息队列，成功后：
UPDATE outbox SET sent_at = now() WHERE id = ANY($1);
COMMIT;

PostgreSQL 写法；中继发送后再标记，崩溃时会重发，故消费者需幂等。

⚖️ 06 · 方案取舍

Outbox 模式

优点本地事务保证不丢事件

代价多一张表和一个中继组件

适用服务需可靠发布领域事件

直接双写

优点实现最简单

代价崩溃或网络故障时数据与消息不一致

适用可容忍偶发丢失的非关键通知

分布式事务（2PC）

优点强一致

代价性能差，消息系统支持有限

适用极少数强一致且组件都支持时

🕳️ 07 · 常见坑

  • ✗先提交事务再发消息，期间进程崩溃导致事件永久丢失

    ✓事件写入 outbox 并与业务数据同事务提交

  • ✗outbox 表只增不删，越来越大拖慢查询

    ✓发送后删除或定期清理，并为未发送条件建索引

  • ✗消费者假设不会重复，重复事件导致重复扣款

    ✓消费者按事件 ID 去重，业务操作幂等

  • ✗多中继并发且无锁，同一事件被并发发送

    ✓使用 SKIP LOCKED、单活中继或按分区分配

☑️ 08 · 检查清单
🎤 09 · 面试追问
Outbox 解决了什么问题？为什么不直接发消息？

解决双写原子性：数据库提交与消息发送分属两个系统，任何一步失败都会导致不一致。Outbox 把发消息变成写本地表，借助数据库事务保证与业务数据一起成功或失败，再异步可靠投递。

Outbox 能保证 exactly-once 吗？

不能，中继在发送成功但标记前崩溃会重发，属于至少一次投递。要达到效果上的一次处理，需要消费者按事件 ID 幂等，比如用收件箱表记录已处理 ID 或使用唯一约束。

Outbox 中继如何保证顺序？

按聚合 ID 作为消息 key 发送，使同一聚合的事件进同一分区；中继按创建顺序读取同一聚合的事件，失败时不跳过后续事件。全局顺序代价太高，一般只保证同一实体内有序。
