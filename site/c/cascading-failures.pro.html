级联故障 / 雪崩效应

Cascading Failures

📐 01 · 定义

级联故障（Cascading Failure）是指一个组件的故障或过载通过依赖关系、共享资源和正反馈传播到其他组件，最终导致大范围服务不可用。它是分布式系统可靠性的核心风险，常见诱因是过载、资源耗尽和重试放大；防护重点在于限制传播路径：超时、熔断、舱壁、负载卸载和降级。

⚙️ 02 · 原理
  1. 1

    某个实例或依赖变慢或宕机，原本由它承担的流量转移到剩余实例上。

  2. 2

    剩余实例负载升高，延迟上升，线程、连接、内存等资源逐渐被占满。

  3. 3

    上游调用方因等待而堆积请求并开始重试，自身资源也被耗尽，故障沿调用链向上蔓延。

  4. 4

    健康检查失败触发实例重启或摘除，可用容量进一步减少，形成正反馈循环。

  5. 5

    阻断手段是快速失败：超时、熔断、舱壁隔离、卸载与降级，必要时人工减流。

🔤 03 · 术语
正反馈环 (Positive Feedback Loop)
故障结果反过来加剧故障原因，如过载导致重试再加重过载。
熔断器 (Circuit Breaker)
依赖失败率过高时暂停调用、快速失败，定期试探恢复。
资源耗尽 (Resource Exhaustion)
CPU、内存、线程、文件描述符等被占满导致服务失效。
故障域 (Failure Domain)
会因同一原因一起失效的组件集合。
容量余量 (Headroom)
在峰值之外预留的处理能力，用于吸收故障转移流量。
💻 04 · 代码
最小熔断器实现python
import time

class CircuitBreaker:
    def __init__(self, threshold=5, reset_after=30.0):
        self.threshold, self.reset_after = threshold, reset_after
        self.failures, self.opened_at = 0, None

    def call(self, fn, *args, **kwargs):
        if self.opened_at is not None:
            if time.monotonic() - self.opened_at < self.reset_after:
                raise RuntimeError("circuit open")  # 快速失败，不打下游
            self.opened_at = None                    # 半开：放行一次试探
        try:
            result = fn(*args, **kwargs)
        except Exception:
            self.failures += 1
            if self.failures >= self.threshold:
                self.opened_at = time.monotonic()    # 打开熔断
            raise
        self.failures = 0                            # 成功则复位
        return result

连续失败达到阈值后熔断，冷却期内直接拒绝，之后放行请求试探恢复。

⚖️ 06 · 方案取舍

熔断快速失败

优点保护上游资源，给下游恢复时间

代价阈值不当会误伤正常流量

适用依赖可能持续故障

降级返回兜底数据

优点用户体验平滑

代价数据可能过期或不完整

适用非核心功能依赖

预留容量余量

优点吸收单点故障的流量转移

代价平时资源利用率低

适用关键服务的 N+1/N+2 规划

🕳️ 07 · 常见坑

  • ✗存活探针检查数据库连通性，数据库一抖所有 Pod 被重启。

    ✓存活探针只反映进程自身是否卡死，依赖状态放就绪探针或不检查。

  • ✗超时设得比上游还长，上游先放弃了下游还在算。

    ✓超时自外向内递减，并传播截止时间。

  • ✗故障时自动扩容，但新实例启动要预热，反而加重数据库负担。

    ✓扩容配合限流，冷启动实例逐步接流。

  • ✗容量规划按平均负载，没考虑一个可用区宕机。

    ✓按失去一个故障域后的剩余容量规划。

🎤 09 · 面试追问
举例说明一次典型的级联故障。

缓存集群故障使请求直达数据库，数据库延迟升高，应用线程等待耗尽，上游超时重试使流量翻倍，健康检查失败导致实例被重启，剩余实例负载更高，最终全站不可用。每一步都是前一步的放大。

为什么说超时是最基础的防线？

没有超时，慢依赖会无限期占用线程和连接，故障直接转化为资源耗尽并向上蔓延。合理超时让调用方及时释放资源，是熔断、降级、重试能够生效的前提。

如何从级联故障中恢复？

先减负载：关闭非关键功能、卸载流量、暂停重试或批任务；再恢复容量：扩容并逐步放量，避免新实例被瞬间打垮；最后复盘反馈环，加熔断、预算和余量。
