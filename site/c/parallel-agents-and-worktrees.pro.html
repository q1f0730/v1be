并行智能体与 Git Worktree

Parallel Agents & Worktrees

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

并行智能体（Parallel Agents）指同时运行多个编码 Agent 处理不同任务；Git Worktree 让同一仓库检出多个独立工作目录，每个目录有自己的分支和文件状态，共享同一份对象库。两者结合可避免多个 Agent 在同一目录互相覆盖文件，是 AI 编码提效的常用工作流。

⚙️ 02 · 原理
  1. 1

    拆分任务：把工作拆成彼此文件交集小的独立任务，如不同模块或不同 bug。

  2. 2

    创建工作树：git worktree add 为每个任务建目录与分支，共享 .git 对象，不必重复克隆。

  3. 3

    各自启动 Agent：在每个工作树目录中运行一个 Agent 会话，各自安装依赖、跑测试。

  4. 4

    人工审查：任务完成后分别查看 diff，通过 PR 或本地合并回主分支。

  5. 5

    清理：合并后 git worktree remove 删除目录，git worktree prune 清理失效记录。

🔤 03 · 术语
工作树 (Worktree)
与某分支关联的独立检出目录，同一仓库可有多个。
主工作树 (Main Worktree)
git clone 或 git init 产生的原始工作目录。
同分支限制
默认同一分支不能同时被两个工作树检出，防止状态冲突。
合并冲突 (Merge Conflict)
多个分支修改同一处代码，合并时需人工裁决。
后台 Agent (Background Agent)
在云端或后台独立运行、完成后提交分支或 PR 的 Agent。
💻 04 · 代码
为两个 Agent 建工作树bash
# 在主仓库目录中，为两个任务各建一个工作树+新分支
git worktree add ../app-fix-login -b fix/login
git worktree add ../app-feat-export -b feat/export

git worktree list        # 查看所有工作树及其分支

# 分别在两个终端里启动 Agent（以 Claude Code 为例）
cd ../app-fix-login && claude
cd ../app-feat-export && claude

# 完成并合并后清理
git worktree remove ../app-fix-login
git branch -d fix/login
git worktree prune       # 清理已手动删除目录的残留记录

每个 Agent 有独立目录和分支，互不覆盖；对象库共享，比多次 clone 省空间。

📊 05 · 参数对比

并行隔离方式对比

方式隔离程度成本
同目录多会话无，文件互相覆盖最低，但不可取
Git Worktree文件与分支隔离低，共享对象库
多次 clone完全独立仓库磁盘与同步成本较高
容器/云端沙箱环境、网络都隔离最高，适合不可信任务
⚖️ 06 · 方案取舍

本地多工作树

优点启动快，可随时介入查看

代价端口、数据库等共享资源会冲突

适用2–4 个中小任务并行

云端后台 Agent

优点不占本机资源，可大规模并行

代价环境配置成本，介入不便

适用任务独立且定义清晰

串行单 Agent

优点无合并冲突，上下文连贯

代价总耗时长

适用任务强耦合或涉及同一文件

🕳️ 07 · 常见坑

  • ✗并行任务改动同一批文件，最后合并冲突严重

    ✓拆任务时按模块边界划分，共享接口先在主分支定好

  • ✗多个工作树的开发服务器抢同一端口或共用一个本地数据库

    ✓为每个工作树配置不同端口和独立数据库/环境变量

  • ✗新工作树没装依赖或缺少 .env，Agent 反复报错

    ✓写初始化脚本：建树后自动安装依赖并复制所需配置

  • ✗开太多并行任务，审查跟不上，质量下降

    ✓并行数以自己能认真审查的量为上限

☑️ 08 · 检查清单
🎤 09 · 面试追问
Worktree 和多次 clone 有什么区别？

Worktree 共享同一 .git 对象库和引用，新建快、省磁盘，分支在各工作树间立即可见；多次 clone 是完全独立的仓库，需要 push/fetch 同步。Worktree 默认禁止同一分支被两处检出。

怎么拆任务才适合并行 Agent？

选彼此独立、可单独验证的任务：不同模块、不同 bug、测试补全等。先在主分支确定共享接口或数据结构，再让各 Agent 实现。强耦合任务并行只会制造冲突，宜串行。

并行 Agent 的瓶颈通常在哪？

往往不在生成速度，而在人的审查与合并能力，以及共享资源冲突（端口、数据库、API 配额）。因此要控制并行度，给每个任务清晰的验收标准和自动化测试。
