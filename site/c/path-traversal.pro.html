路径遍历

Path Traversal

📐 01 · 定义

路径遍历（Path Traversal / Directory Traversal，CWE-22）是攻击者利用 ../、绝对路径或编码变体，让应用访问预期目录之外文件的漏洞，常见于文件下载、模板加载、上传保存和压缩包解压。它可导致读取配置与密钥、覆盖程序文件，进而远程代码执行。根因是把用户输入直接拼进文件路径。

⚙️ 02 · 原理
  1. 1

    应用根据用户输入构造文件路径，如 base_dir + "/" + filename。

  2. 2

    攻击者提交 ../../etc/passwd 或绝对路径，使拼接结果跳出基准目录。

  3. 3

    绕过简单过滤的变体包括 URL 编码 %2e%2e%2f、双重编码、反斜杠和符号链接。

  4. 4

    解压时条目名包含 ../ 可把文件写到任意位置，即 Zip Slip。

  5. 5

    正确防御是先规范化为绝对真实路径，再确认它仍位于基准目录之内。

🔤 03 · 术语
CWE-22
对受限目录的路径名限制不当，即路径遍历。
规范化 (Canonicalization)
解析 ..、符号链接等，得到唯一真实路径。
Zip Slip
压缩包条目名含 ../，解压时写出目标目录。
符号链接攻击 (Symlink Attack)
借助指向外部的链接绕过目录检查。
间接引用 (Indirect Reference)
用 ID 映射文件而不让用户直接给路径。
💻 04 · 代码
安全地拼接用户文件路径python
from pathlib import Path
import zipfile

BASE = Path("/srv/app/uploads").resolve()

def safe_path(user_name: str) -> Path:
    # resolve() 会处理 ..、绝对路径与符号链接
    p = (BASE / user_name).resolve()
    if not p.is_relative_to(BASE):          # Python 3.9+
        raise PermissionError("非法路径")
    return p

def safe_extract(zip_path: str, dest: Path):
    dest = dest.resolve()
    with zipfile.ZipFile(zip_path) as z:
        for name in z.namelist():
            target = (dest / name).resolve()
            if not target.is_relative_to(dest):   # 防 Zip Slip
                raise PermissionError(f"恶意条目: {name}")
        z.extractall(dest)

print(safe_path("report.pdf"))
# safe_path("../../etc/passwd")  -> PermissionError

先 resolve 规范化再判断是否仍在基准目录内；解压前逐个检查条目。

🕳️ 07 · 常见坑

  • ✗用 replace("../", "") 过滤

    ✓....// 等变体可绕过；改为规范化后校验

  • ✗用字符串 startswith 比较路径前缀

    ✓/srv/app2 会匹配 /srv/app；用 is_relative_to 等路径语义判断

  • ✗上传文件直接使用客户端提供的文件名保存

    ✓服务端生成随机文件名，原名只存数据库

  • ✗Agent 文件工具未限制工作目录

    ✓Agent 读写工具同样做目录限制并在沙箱中运行

🎤 09 · 面试追问
为什么黑名单过滤 ../ 不可靠？

存在大量变体：URL 编码、双重编码、Unicode 形式、Windows 反斜杠、嵌套如 ....//、绝对路径和符号链接。正确方法是把路径规范化为真实绝对路径，再判断其是否位于允许的目录内。

路径遍历如何升级为代码执行？

若能写文件，攻击者可覆盖应用代码、模板、启动脚本、cron 配置或 SSH authorized_keys，从而执行任意代码；即使只能读，也可能读到密钥和配置，再进一步入侵。

检查和使用之间有什么竞态风险？

检查路径后、打开文件前，攻击者可能把文件替换为符号链接（TOCTOU）。可在打开时使用不跟随符号链接的选项，或在受控目录中操作，并限制进程文件权限。
