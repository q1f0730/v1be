级联删除

Cascading Deletes

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

级联删除是外键约束的一种引用动作：删除父表记录时，数据库自动删除所有引用它的子表记录（ON DELETE CASCADE）。它保证引用完整性、免去手工清理，但一次删除可能沿关系链扩散到大量数据，且无法撤销，必须谨慎设计关系边界。

⚙️ 02 · 原理
  1. 1

    在子表外键上声明 ON DELETE 动作：CASCADE、SET NULL、SET DEFAULT、RESTRICT 或 NO ACTION。

  2. 2

    删除父行时，数据库查找所有引用它的子行，按声明的动作处理。

  3. 3

    子行若又被其他表以 CASCADE 引用，删除会沿关系链递归传播，全部在同一事务中完成。

  4. 4

    引擎需要通过子表外键列定位子行；没有索引时每次删除都可能全表扫描。

  5. 5

    ORM 也能在应用层模拟级联，但不经过 ORM 的删除不会触发这类逻辑。

🔤 03 · 术语
引用动作 (Referential Action)
外键在父行删除或更新时执行的动作。
RESTRICT / NO ACTION
有子行引用时拒绝删除父行；二者检查时机略有差别。
SET NULL
删除父行时把子行外键置空，保留子行。
软删除 (Soft Delete)
用 deleted_at 标记删除而不物理删除。
孤儿记录 (Orphan Record)
外键指向已不存在父行的子记录。
💻 04 · 代码
按关系选择引用动作sql
CREATE TABLE users (id bigint PRIMARY KEY, email text UNIQUE NOT NULL);

-- 组成关系：用户删了，其会话没有意义 → 级联删除
CREATE TABLE sessions (
  id      uuid PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE
);

-- 关联关系：订单要留存做账 → 拒绝删除有订单的用户
CREATE TABLE orders (
  id      bigint PRIMARY KEY,
  user_id bigint NOT NULL REFERENCES users(id) ON DELETE RESTRICT
);

-- 可选关系：指派人离开，任务保留 → 置空
CREATE TABLE tasks (
  id          bigint PRIMARY KEY,
  assignee_id bigint REFERENCES users(id) ON DELETE SET NULL
);

-- PostgreSQL 不会自动为外键列建索引，级联与 JOIN 都依赖它
CREATE INDEX ON sessions (user_id);
CREATE INDEX ON orders (user_id);
CREATE INDEX ON tasks (assignee_id);

按“组成/关联/可选”关系选动作；外键列建索引，避免级联时扫描全表。

📊 05 · 参数对比

ON DELETE 动作对比

动作子行结果适用关系
CASCADE随父行删除强组成：会话、订单明细
SET NULL外键置空保留可选关联：负责人、分类
RESTRICT / NO ACTION阻止删除父行需留存的业务记录
SET DEFAULT改为默认值有兜底父行的场景
⚖️ 06 · 方案取舍

数据库级联

优点原子、可靠，任何客户端删除都生效

代价影响范围不直观，难审计

适用生命周期完全依附父行的数据

ORM/应用层级联

优点可触发回调、写审计日志

代价绕过 ORM 的删除不生效

适用删除需附带业务逻辑

软删除

优点可恢复、保留历史

代价查询都要过滤，唯一约束复杂

适用用户可见数据需要回收站

🕳️ 07 · 常见坑

  • ✗到处默认 CASCADE，误删一个账户连带清空订单

    ✓只对组成关系用 CASCADE，业务记录用 RESTRICT

  • ✗外键列没索引，删除大父行时极慢且长时间锁表

    ✓为所有外键列建索引，大批量删除分批执行

  • ✗依赖级联删除时期望触发器或审计逻辑执行

    ✓确认引擎行为：MySQL InnoDB 级联不触发触发器

  • ✗合规删除只删主表，日志与备份仍留数据

    ✓梳理全部副本，制定数据删除清单

🎤 09 · 面试追问
ON DELETE CASCADE 和 ORM 的 cascade 有什么区别？

数据库级联由引擎在同一事务内执行，任何客户端的 DELETE 都会触发，可靠但不运行应用回调。ORM 级联先加载子对象再逐个删除，可触发钩子，但慢，且直接执行 SQL 删除时不生效。SQLAlchemy 可用 passive_deletes 交给数据库。

如何评估一次删除会波及多少数据？

从父表出发沿外键图列出所有 CASCADE 关系，对每张子表执行 COUNT 预估；在预发环境用事务执行删除并统计受影响行数后回滚。对用户触发的删除，可在界面上展示影响范围再确认。

软删除和级联怎么配合？

软删除不会触发外键动作，需要在应用层同步标记子记录，或在查询时通过父表状态过滤。唯一约束要改为部分索引（如仅约束 deleted_at IS NULL 的行），并有定期物理清理策略。
