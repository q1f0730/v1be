仓库 (Repo)

📐 01 · 定义

仓库（Repository）是被 Git 管理的项目单元，包含工作文件和隐藏的 .git 目录，后者存储全部提交对象、分支引用和配置。本地与远程仓库（如 origin）结构相同、地位对等，通过推送和拉取同步。仓库的组织方式、根目录约定文件和权限，直接影响协作效率与 AI Agent 理解项目的难度。

⚙️ 02 · 原理
  1. 1

    初始化：git init 创建 .git 目录，或 git clone 复制一个已有仓库及其完整历史。

  2. 2

    对象存储：.git/objects 保存文件内容、目录树和提交，均以内容哈希命名。

  3. 3

    引用管理：.git/refs 记录分支和标签指向的提交，HEAD 标记当前所在位置。

  4. 4

    远程关联：git remote 记录远程仓库地址，常用名称 origin 指向克隆来源。

  5. 5

    根目录约定：README、LICENSE、.gitignore、CLAUDE.md 等文件描述项目与协作规则。

🔤 03 · 术语
.git 目录
仓库的数据库，删除它就失去全部版本历史。
远程仓库 (Remote)
托管在服务器上的仓库副本，如 origin。
裸仓库 (Bare Repository)
没有工作区、只有版本数据的仓库，常用于服务器。
单仓 (Monorepo)
多个项目或服务放在同一个仓库中统一管理。
git worktree
同一仓库同时检出多个分支到不同目录。
💻 04 · 代码
创建并关联仓库bash
# 从零创建本地仓库
mkdir my-app && cd my-app
git init -b main                 # 初始化并把默认分支命名为 main

# 根目录的约定文件
echo "# My App" > README.md
printf "node_modules/\n.env\ndist/\n" > .gitignore
git add . && git commit -m "chore: initial commit"

# 用 GitHub CLI 创建远程仓库并推送（私有）
gh repo create my-app --private --source=. --push

# 或手动关联已存在的远程仓库
# git remote add origin git@github.com:<user>/my-app.git
# git push -u origin main

git remote -v                    # 查看远程地址
du -sh .git                      # 版本数据占用的空间

仓库从第一天就该有 README 与 .gitignore；gh 可一步完成创建远程并推送。

📊 05 · 参数对比

仓库组织方式对比

方式优点代价
多仓 (Polyrepo)边界清晰、权限独立跨仓改动需多次 PR、版本协调难
单仓 (Monorepo)原子化跨项目改动、共享代码方便需要专门的构建与权限工具
单仓 + 子目录说明Agent 能看到全局上下文上下文更大，需要分目录规则文件
⚖️ 06 · 方案取舍

公开仓库

优点开放协作、展示作品

代价历史中的任何内容都公开

适用开源与学习项目

私有仓库

优点保密，可控访问

代价协作者需逐一授权

适用商业与未发布项目

Git LFS 管理大文件

优点仓库保持轻量

代价额外配置与存储配额

适用设计稿、模型、数据集

🕳️ 07 · 常见坑

  • ✗把 node_modules、构建产物提交进仓库

    ✓初始化时就配置 .gitignore，已提交的用 git rm --cached 移除

  • ✗在仓库里提交大体积二进制文件导致克隆缓慢

    ✓大文件使用 Git LFS 或对象存储

  • ✗私有仓库改公开前没检查历史

    ✓先扫描历史中的密钥与敏感数据再公开

  • ✗在家目录等大目录误执行 git init

    ✓确认所在路径，误建时删除对应 .git 目录

🎤 09 · 面试追问
为什么说 Git 是分布式的？

每个克隆都是完整仓库，拥有全部历史与分支，可以离线提交、查看日志、建分支。远程仓库只是约定的协作中心，而非唯一真相来源；任何一份副本都能恢复整个项目，这与 SVN 等集中式系统不同。

Monorepo 适合什么团队？

多个项目共享大量代码、需要频繁跨项目原子改动、希望统一工具链和依赖版本的团队。代价是需要增量构建、受影响范围分析、精细权限等工具支持。小团队多个紧密相关的前后端项目也常用单仓。

仓库结构如何影响 AI Agent 的效果？

清晰的目录约定、README 与 CLAUDE.md 等说明文件、可一键运行的测试命令，能让 Agent 快速建立上下文并自我验证；混乱的结构和缺失的文档会导致 Agent 误改文件、重复实现已有功能。
