12-Factor Apps

📐 01 · 定义

十二要素应用（The Twelve-Factor App）是 Heroku 工程师整理的一套构建云上 SaaS 应用的方法论，包括代码库、依赖、配置、后端服务、构建发布运行、进程、端口绑定、并发、易处理、开发生产一致、日志和管理进程十二条。它奠定了云原生应用的基本约定，配置入环境、无状态进程、日志即事件流影响最广。

⚙️ 02 · 原理
  1. 1

    一份代码库对应一个应用，多环境部署同一代码；依赖显式声明并隔离。

  2. 2

    配置存放在环境变量中，与代码严格分离，同一构建可部署到任意环境。

  3. 3

    构建、发布、运行三阶段分离：构建产出制品，发布等于制品加配置，运行时不改代码。

  4. 4

    进程无状态，通过端口绑定对外服务，靠增加进程数水平扩展，可快速启停。

  5. 5

    日志作为事件流写到标准输出，由环境收集；一次性管理任务与应用使用相同代码和配置。

🔤 03 · 术语
配置 (Config)
随部署环境变化的值，如数据库地址、密钥，应放环境变量。
后端服务 (Backing Services)
通过网络使用的数据库、缓存等，视为可替换的附加资源。
构建/发布/运行 (Build, Release, Run)
三个严格分离的阶段，发布有唯一版本号。
易处理 (Disposability)
进程快速启动、优雅终止，便于扩缩和替换。
日志即事件流 (Logs as Event Streams)
应用只写 stdout，不管理日志文件。
💻 04 · 代码
配置入环境、日志写 stdoutpython
import logging
import os
import sys
from flask import Flask

# 第三条：配置来自环境变量，缺了就启动失败，而不是用硬编码默认值
DATABASE_URL = os.environ["DATABASE_URL"]
PORT = int(os.environ.get("PORT", "8080"))       # 第七条：端口绑定

# 第十一条：日志写到标准输出，由平台收集
logging.basicConfig(stream=sys.stdout, level=logging.INFO)
log = logging.getLogger("app")

app = Flask(__name__)

@app.get("/healthz")
def healthz():
    return "ok"

if __name__ == "__main__":
    log.info("starting on port %s", PORT)
    app.run(host="0.0.0.0", port=PORT)

同一份代码，换一组环境变量就能部署到任何环境，日志交给平台处理。

🕳️ 07 · 常见坑

  • ✗按环境构建不同的镜像，把配置打进镜像里。

    ✓构建一次，配置在运行时通过环境变量注入。

  • ✗把密钥以明文环境变量写在仓库的部署文件里。

    ✓环境变量值来自密钥管理系统，不进代码库。

  • ✗应用自己写日志文件并轮转。

    ✓写 stdout，交给运行时和采集器。

  • ✗数据库迁移在应用启动时由每个副本执行。

    ✓作为一次性管理进程单独运行。

🎤 09 · 面试追问
为什么十二要素建议把配置放环境变量？

环境变量与语言和框架无关，不容易被误提交进代码库，同一个构建产物换一组环境变量即可部署到任意环境。判断标准是：能否在不泄露任何凭据的前提下立刻开源代码库。

十二要素在今天还适用吗？

核心思想仍是容器和 Kubernetes 的基础，如配置外置、无状态、日志写 stdout、优雅停机。但有补充：密钥更适合用专门的密钥管理而不是裸环境变量，可观测性需加入指标和追踪，配置有时需要动态下发。

构建、发布、运行分离的好处是什么？

构建产物不可变，发布由制品加配置组成并有唯一版本，运行时不修改代码。这样每次部署都可追溯，回滚就是重新运行上一个发布，避免直接在服务器上改代码造成不可复现。
