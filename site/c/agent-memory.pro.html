智能体记忆

Agent Memory

📐 01 · 定义

智能体记忆（Agent Memory）是让 LLM 智能体在单次上下文之外保存并检索信息的机制，使其跨会话记住用户偏好、项目约定和过往经验。通常分为短期记忆（当前上下文）和长期记忆（文件、数据库、向量库），由检索或按需读取注入上下文。它位于 Agent 架构的状态管理层。

⚙️ 02 · 原理
  1. 1

    短期记忆即当前对话的消息历史，受上下文窗口限制，会话结束即消失。

  2. 2

    长期记忆写入外部存储：Markdown 文件、键值库、关系库或向量数据库。

  3. 3

    写入时机由规则或模型决定：用户明确要求、任务结束总结、检测到稳定偏好。

  4. 4

    读取方式包括固定加载（如项目说明文件）、关键词或向量检索、由 Agent 调用工具查询。

  5. 5

    定期整理记忆：合并重复条目、更新过时内容、删除用户要求遗忘的信息。

🔤 03 · 术语
短期记忆 (Working Memory)
当前上下文窗口中的信息。
情景记忆 (Episodic Memory)
过去具体交互或任务经历的记录。
语义记忆 (Semantic Memory)
提炼出的事实与偏好，如用户使用的技术栈。
程序性记忆 (Procedural Memory)
做事的方法与规则，如团队的提交规范。
记忆投毒 (Memory Poisoning)
恶意内容被写入记忆，持续影响后续行为。

# 文件：./CLAUDE.md（项目级，随仓库共享；Claude Code 启动时自动加载）

## 项目约定
- 包管理用 pnpm，不要使用 npm 或 yarn
- 测试命令：pnpm test；提交前必须通过 pnpm lint
- 数据库变更只能通过 prisma migrate 生成迁移文件

## 代码风格
- TypeScript 严格模式，禁止 any
- 组件放在 src/components，按功能分目录

## 注意事项
- payments/ 目录改动需人工审查，不要自动提交
- 环境变量见 .env.example，切勿写入真实密钥

⚖️ 06 · 方案取舍

固定加载记忆文件

优点确定、透明、易审查

代价内容多时挤占上下文

适用项目约定、少量稳定偏好

检索式记忆

优点可扩展到大量记录

代价可能取错或漏取

适用历史对话、知识积累

Agent 自主读写记忆

优点灵活，能自我积累经验

代价可能写入错误或被投毒

适用需配合审查与可删除机制

🕳️ 07 · 常见坑

  • ✗把一次性的临时信息写成长期规则

    ✓只记录稳定且会复用的事实，并注明适用条件

  • ✗记忆文件越积越长，充满过时规则

    ✓定期整理，更新或删除过时条目

  • ✗把网页或工具返回的内容直接写入记忆

    ✓外部内容视为不可信，写入前过滤并标注来源

  • ✗记忆中保存密钥或个人隐私

    ✓禁止写入敏感信息，并提供查看与删除入口

🎤 09 · 面试追问
记忆和 RAG 有什么区别？

RAG 检索的是外部知识库，通常相对静态、与具体用户无关；记忆是 Agent 在交互中积累的、与用户或项目相关的状态，需要写入、更新和遗忘。两者可共用检索技术，但生命周期与治理要求不同。

如何防止记忆投毒？

把来自网页、文件、工具的内容视为不可信数据，不允许其直接写入长期记忆；写入需经用户确认或规则过滤；记忆条目记录来源与时间，可审计与回滚。

记忆过多会有什么问题？

占用上下文、引入过时或冲突信息，导致模型遵循错误规则。应控制总量、按相关性检索，冲突时以最新且用户明确的信息为准，并定期清理。
