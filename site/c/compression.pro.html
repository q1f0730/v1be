Compression

📐 01 · 定义

数据压缩（Compression）在 HTTP 中主要指内容编码（Content Encoding）：服务端用 gzip、Brotli、Zstandard 等算法压缩响应体，经 Accept-Encoding 与 Content-Encoding 协商。它以 CPU 换带宽与存储，直接影响页面加载速度和流量成本。

⚙️ 02 · 原理
  1. 1

    客户端在请求头 Accept-Encoding 中列出自己支持的编码，如 gzip、br、zstd。

  2. 2

    服务端或 CDN 选择双方都支持的算法压缩响应，并设置 Content-Encoding 与 Vary: Accept-Encoding。

  3. 3

    静态资源适合构建时预压缩（如生成 .br/.gz 文件），用高压缩级别且不占请求时 CPU。

  4. 4

    动态响应只能在线压缩，通常选中等压缩级别，以平衡请求延迟与压缩率。

  5. 5

    图片、视频、zip 等已压缩格式再压缩收益很小，应跳过；过小的响应也不值得压缩。

🔤 03 · 术语
Content-Encoding
说明响应体使用的压缩编码的响应头。
Brotli (br)
RFC 7932 定义的压缩算法，文本压缩率通常优于 gzip。
Zstandard (zstd)
RFC 8878 定义，压缩与解压速度快，可调级别范围大。
Vary: Accept-Encoding
告诉缓存按编码区分存储，避免发错版本。
BREACH 攻击
利用压缩后长度变化推测 HTTPS 响应中的秘密。
💻 04 · 代码
Nginx 压缩配置text
http {
    gzip on;
    gzip_comp_level 5;            # 1-9，在线压缩取中间值
    gzip_min_length 1024;         # 太小的响应不压缩
    gzip_vary on;                 # 自动加 Vary: Accept-Encoding
    gzip_proxied any;
    gzip_types text/css application/javascript
               application/json image/svg+xml;  # text/html 默认已包含

    # 构建时生成的 .gz 文件直接发送，不再实时压缩
    gzip_static on;

    # Brotli 需第三方模块 ngx_brotli，可用时再启用：
    # brotli on;
    # brotli_static on;
}

# 验证：
# curl -sI -H 'Accept-Encoding: gzip' https://example.com/app.js | grep -i content-encoding

按类型和大小有选择地压缩，静态资源用预压缩文件；Brotli 需额外模块。

⚖️ 06 · 方案取舍

构建时预压缩

优点可用最高级别，零运行时 CPU

代价只适用于静态资源

适用JS/CSS/字体等静态文件

在线动态压缩

优点适用于任意响应

代价占 CPU，增加少量延迟

适用API JSON、SSR 页面

交给 CDN 压缩

优点源站省 CPU，边缘自动协商

代价依赖 CDN 能力与配置

适用已使用 CDN 的站点

🕳️ 07 · 常见坑

  • ✗对 JPEG、MP4、zip 再做 gzip

    ✓只对文本类 MIME 类型启用压缩

  • ✗缺少 Vary: Accept-Encoding，缓存把压缩版发给不支持的客户端

    ✓开启 gzip_vary 或手动加 Vary 头

  • ✗在线压缩用最高级别，CPU 飙升延迟变长

    ✓动态内容用中等级别，最高级别留给预压缩

  • ✗压缩响应中同时包含用户输入与 CSRF 令牌等秘密

    ✓评估 BREACH 风险：秘密按请求随机掩码，或对敏感响应禁用压缩

🎤 09 · 面试追问
为什么 Brotli 只在 HTTPS 下使用？

浏览器只在安全连接上声明支持 br，主要是避免老旧中间代理错误处理不认识的编码。通过 HTTPS 传输可绕过这些中间设备。

压缩为什么可能带来安全问题？

压缩后的长度取决于内容重复度。攻击者若能注入可控内容并观测响应长度，就能逐字节猜测同一响应中的秘密，即 CRIME/BREACH 类攻击。缓解是分离秘密与用户输入、掩码令牌或禁用压缩。

HTTP/2 下还需要关心头部压缩吗？

HTTP/2 用 HPACK、HTTP/3 用 QPACK 自动压缩头部，无需应用配置；但它们只处理头部，响应体仍需 Content-Encoding 压缩。
