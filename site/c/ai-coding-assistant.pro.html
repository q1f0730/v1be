📐 01 · 定义

AI 编程助手（AI Coding Assistant）是集成 LLM 的开发工具，能力从行内补全、对话扩展到读写多文件、执行命令的自主 Agent。代表形态有 IDE 插件（GitHub Copilot）、AI 原生编辑器（Cursor）和终端 Agent（Claude Code），位于开发者与模型之间的工具层。

⚙️ 02 · 原理
  1. 1

    收集上下文：读取当前文件、打开的标签页、项目索引或按需搜索代码库。

  2. 2

    组装提示：把代码片段、项目规则文件、用户指令和工具定义拼成模型请求。

  3. 3

    生成建议：补全模式返回行内代码；Agent 模式返回文件编辑与工具调用。

  4. 4

    执行与权限：Agent 在用户授权下编辑文件、运行终端命令、调用 MCP 工具。

  5. 5

    反馈闭环：读取编译、测试或运行结果，继续修改直到任务完成或需要人确认。

🔤 03 · 术语
行内补全 (Inline Completion)
根据光标前后代码实时预测接下来的代码。
代码库索引 (Codebase Indexing)
对项目建立检索索引，便于按语义找到相关代码。
MCP (Model Context Protocol)
让 AI 工具以统一协议连接外部数据源和工具的开放协议。
规则文件 (Rules)
CLAUDE.md、.cursor/rules 等，向助手注入项目约定。
权限模式 (Permission Mode)
控制 Agent 执行编辑和命令前是否需要用户批准。
💻 04 · 代码
CLAUDE.md 项目说明示例text
# 项目说明（Claude Code 启动时自动读取）

## 常用命令
- 安装依赖：pnpm install
- 本地开发：pnpm dev（端口 3000）
- 测试：pnpm test
- 类型检查：pnpm typecheck

## 代码规范
- TypeScript 严格模式，禁止 any
- 组件放在 src/components，一个文件一个组件
- 样式只用 Tailwind，不新增 CSS 文件

## 约束
- 不要修改 src/generated/ 下的文件（自动生成）
- 新增依赖前先说明理由
- 每次改完运行 pnpm typecheck 和 pnpm test

规则文件把隐性约定写成显性上下文，是提升助手输出一致性的最低成本手段。

📊 05 · 参数对比

三种产品形态对比

形态代表强项注意
IDE 插件GitHub Copilot补全快、融入现有编辑器复杂任务需切换 Agent 模式
AI 原生编辑器Cursor、Windsurf、Trae编辑体验与 Agent 深度集成需迁移编辑器
终端 AgentClaude Code、Codex CLI可脚本化，擅长多文件任务需熟悉命令行与权限设置
⚖️ 06 · 方案取舍

只用补全

优点低打扰、可控

代价提效有限，难做跨文件改动

适用熟练开发者写熟悉代码

对话式问答

优点解释、方案讨论方便

代价需手动复制粘贴落地

适用学习、调研、设计讨论

自主 Agent

优点能端到端完成任务

代价改动面大，需审查和权限管理

适用明确的功能开发、重构、修 bug

🕳️ 07 · 常见坑

  • ✗给 Agent 全部自动批准权限，在主分支上直接跑

    ✓在独立分支或容器里运行，危险命令保留人工确认

  • ✗不写规则文件，每次口头重复项目约定

    ✓把命令、规范、禁区写进 CLAUDE.md 或规则文件

  • ✗接受 Agent 改动不看 diff

    ✓逐文件审阅变更，重点关注删除、配置和依赖变化

☑️ 08 · 检查清单
🎤 09 · 面试追问
补全和 Agent 在技术上有何不同？

补全是单次、低延迟预测，通常用较小或专门优化的模型，以光标附近代码为上下文；Agent 是多轮循环，模型通过工具调用读文件、改文件、跑命令，并根据结果继续决策，上下文管理和权限控制更复杂。

企业引入编程助手的主要风险？

代码与数据外发合规、生成代码的许可证与安全漏洞、Agent 误执行破坏性命令、密钥泄露到上下文、过度依赖导致质量下降。对策：私有化或零数据保留方案、权限策略、代码审查、密钥扫描、使用规范培训。

MCP 解决了编程助手的什么问题？

此前每个工具要为每个数据源单独做集成。MCP 定义统一的客户端—服务器协议，数据库、文档、工单系统等只需实现一次 MCP 服务器，就能被 Claude Code、Cursor 等支持 MCP 的客户端调用。
