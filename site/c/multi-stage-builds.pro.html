Docker多阶段构建

Multi-Stage Builds

🧸 回到小白版

📐 01 · 定义

多阶段构建（Multi-Stage Builds）是 Dockerfile 中使用多个 FROM 指令划分阶段的技术：前面的阶段安装编译工具、下载依赖并构建，最后一个阶段只从前面阶段复制运行所需的产物。它属于镜像构建层，能显著减小最终镜像体积、减少攻击面，并把构建依赖与运行环境分离，同时利用层缓存加速构建。

⚙️ 02 · 原理
  1. 1

    第一个阶段基于含 SDK 的镜像，用 AS 命名，例如 FROM golang AS build。

  2. 2

    先复制依赖清单并安装依赖，再复制源码构建，使依赖层能被缓存复用。

  3. 3

    最终阶段基于精简基础镜像，如 distroless、alpine 或 scratch。

  4. 4

    用 COPY --from=build 只复制编译产物和必要文件，编译器与源码不进入最终镜像。

  5. 5

    BuildKit 会跳过最终目标不依赖的阶段，也可用 --target 只构建某个阶段用于测试。

🔤 03 · 术语
构建阶段 (Build Stage)
Dockerfile 中一个 FROM 开始的段落，可用 AS 命名。
COPY --from
从其他阶段或镜像复制文件到当前阶段。
Distroless 镜像
只含应用与运行时依赖、没有 shell 和包管理器的基础镜像。
BuildKit
Docker 的现代构建后端，支持并行阶段、缓存挂载等特性。
层缓存 (Layer Cache)
未变化的指令复用之前的层结果，加速重建。
💻 04 · 代码
Go 应用多阶段 Dockerfiletext
# syntax=docker/dockerfile:1
# ---- 阶段 1：构建 ----
FROM golang:1.23 AS build
WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download            # 依赖层：go.mod 不变就命中缓存
COPY . .
RUN CGO_ENABLED=0 go build -o /out/app ./cmd/app

# ---- 阶段 2：运行 ----
FROM gcr.io/distroless/static-debian12:nonroot
COPY --from=build /out/app /app
USER nonroot:nonroot           # 以非 root 用户运行
EXPOSE 8080
ENTRYPOINT ["/app"]

# 构建：docker build -t example/app:1.0 .
# 只跑到构建阶段：docker build --target build .

编译器和源码留在 build 阶段，最终镜像只有静态二进制，且默认非 root。

📊 05 · 参数对比

常见最终基础镜像

基础镜像特点注意点
scratch完全空白，体积最小无 CA 证书、时区等，需要自行复制
distroless含运行时依赖，无 shell排障需用调试变体或临时容器
alpine体积小，有包管理器基于 musl libc，可能有兼容差异
debian-slim兼容性好体积相对较大
⚖️ 06 · 方案取舍

distroless/scratch

优点攻击面最小，镜像小

代价无 shell，现场排障不便

适用生产环境的编译型语言服务

slim 发行版镜像

优点兼容性好，便于调试

代价体积和漏洞面更大

适用解释型语言、依赖系统库

单阶段构建

优点Dockerfile 简单

代价镜像含编译工具和源码

适用仅本地开发

🕳️ 07 · 常见坑

  • ✗先 COPY . . 再安装依赖，每次改代码都重装依赖。

    ✓先复制依赖清单安装，再复制源码。

  • ✗最终阶段用 scratch，但程序需要 CA 证书访问 HTTPS 而失败。

    ✓复制证书文件，或改用 distroless/static。

  • ✗在构建阶段用 ARG 传入密钥，被写入镜像历史。

    ✓使用 BuildKit 的 --mount=type=secret。

  • ✗动态链接的二进制放进 scratch，运行时找不到 libc。

    ✓静态编译或选用含 libc 的基础镜像。

🎤 09 · 面试追问
多阶段构建如何减小镜像体积？

把编译器、构建工具、源码和中间产物留在前面的阶段，最终阶段从精简基础镜像开始，只复制运行所需的二进制或打包结果。最终镜像只包含最后阶段的层，前面阶段的内容不会被带入。

多阶段构建对安全有什么帮助？

最终镜像不含 shell、包管理器和编译工具时，攻击者即使进入容器也缺少可用工具，镜像扫描出的漏洞也更少。配合非 root 用户和只读文件系统效果更好。

解释型语言能用多阶段构建吗？

可以。例如 Node.js 在构建阶段安装全部依赖并打包，最终阶段只安装生产依赖或复制构建产物；Python 可在构建阶段编译依赖为 wheel 或虚拟环境，再复制到精简运行镜像中。
