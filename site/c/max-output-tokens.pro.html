最大输出长度 (max_tokens)

Max Output Tokens

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

最大输出长度（max_tokens / max_output_tokens / max_completion_tokens）是 LLM API 的生成上限参数：模型生成的 Token 数达到该值即强制停止。它位于推理请求层，用于控制成本、延迟与响应体积；设得过小会导致回答或 JSON 被截断，是「输出不完整」的首要排查点。

⚙️ 02 · 原理
  1. 1

    请求中指定上限；输入 Token 与输出上限之和通常不能超过模型上下文窗口，且输出上限还受模型自身最大输出限制。

  2. 2

    模型逐 Token 解码，遇到结束符、stop 序列或达到上限之一即停止。

  3. 3

    响应通过停止原因字段告知结果：OpenAI 为 finish_reason="length"，Anthropic 为 stop_reason="max_tokens"。

  4. 4

    推理模型的思考 Token 也计入输出额度与费用；Anthropic 扩展思考要求 budget_tokens 小于 max_tokens。

  5. 5

    应用层据停止原因决定：提高上限、让模型续写，或把任务拆小分段生成。

🔤 03 · 术语
max_tokens
Anthropic Messages API 必填参数；OpenAI Chat Completions 中旧参数名。
max_completion_tokens
OpenAI Chat Completions 的新参数，包含推理 Token，推理模型需用它。
max_output_tokens
OpenAI Responses API 与 Gemini 中对应的输出上限参数名。
停止原因 (finish_reason / stop_reason)
说明生成为何结束：自然结束、命中上限、调用工具等。
截断 (Truncation)
输出达到上限被切断，常造成 JSON 不闭合、代码缺尾。
💻 04 · 代码
检测截断并提示python
# pip install anthropic
import anthropic

client = anthropic.Anthropic()  # 读取 ANTHROPIC_API_KEY

msg = client.messages.create(
    model="claude-sonnet-4-5",  # 换成你在用的模型
    max_tokens=1024,             # 输出上限，Anthropic 必填
    messages=[{"role": "user", "content": "写一个完整的 Todo 应用后端"}],
)

text = "".join(b.text for b in msg.content if b.type == "text")
if msg.stop_reason == "max_tokens":
    # 被截断：不要把半截 JSON/代码直接交给下游
    print("输出被截断，已用", msg.usage.output_tokens, "tokens")
    # 处理办法：调大 max_tokens，或把任务拆成多步
else:
    print(text)

上线代码必须检查停止原因；命中上限时的半截结果不能当成功处理。

⚖️ 06 · 方案取舍

上限设得紧

优点成本与延迟可控，防止跑飞

代价长回答易被截断

适用分类、抽取等短输出任务

上限设得宽

优点完整输出长代码与文档

代价失控时费用高、响应慢

适用代码生成、长文写作

分段生成

优点每段可校验，失败重试代价小

代价需编排与拼接逻辑

适用超出单次输出上限的任务

🕳️ 07 · 常见坑

  • ✗只看返回文本，不检查停止原因

    ✓判断 finish_reason/stop_reason，截断时重试或报错

  • ✗推理模型沿用很小的上限，结果回答为空

    ✓为思考 Token 预留额度，查阅该模型的最大输出限制

  • ✗以为调大上限会让回答更长更好

    ✓上限只是天花板；长度应由提示要求控制

  • ✗结构化输出被截断后仍尝试 json.loads

    ✓先确认正常结束，再解析并做 Schema 校验

☑️ 08 · 检查清单
🎤 09 · 面试追问
max_tokens 和上下文窗口是什么关系？

上下文窗口是单次请求输入与输出 Token 的总容量；max_tokens 是输出部分的上限，还受模型自身最大输出限制。长输入会挤占可用输出空间，部分 API 在两者之和超限时直接报错。

生成 JSON 时被截断，系统层面怎么兜底？

检查停止原因；截断则提高上限或缩小单次任务；使用结构化输出功能；解析前做 Schema 校验，失败时重试并记录；对超大结果改为分页或逐项生成。

推理模型为什么会出现「花了 Token 却没有回答」？

推理 Token 计入输出额度，若上限过小，思考阶段就耗尽额度，最终可见回答为空或不完整。应按厂商建议预留足够输出空间，并监控推理 Token 用量。
