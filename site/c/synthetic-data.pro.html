合成数据

Synthetic Data

📐 01 · 定义

合成数据（Synthetic Data）是由模型或程序生成、而非直接采集自真实世界的数据，在 LLM 开发中用于构造微调指令数据、评测用例、对抗样本与长尾场景。典型做法是用少量高质量种子样例引导强模型批量生成，再经过去重、过滤、验证与人工抽检。它能降低标注成本、规避隐私问题，但存在分布偏移、错误放大和模型坍缩风险。

⚙️ 02 · 原理
  1. 1

    准备种子数据：少量真实且高质量的示例，以及覆盖目标场景的主题、难度和格式清单。

  2. 2

    设计生成提示：给出角色、约束和多样性要求，并用结构化输出保证格式可解析。

  3. 3

    批量生成时变换主题、语气、长度和难度参数，避免样本高度同质化（如 Self-Instruct、Evol-Instruct 等方法）。

  4. 4

    质量控制：精确与近似去重、规则过滤、用模型或执行（代码可运行、答案可验证）校验正确性。

  5. 5

    人工抽检并与真实数据混合使用，在独立的真实评测集上验证效果，避免只在合成数据上“自证”。

🔤 03 · 术语
种子数据 (Seed Data)
引导生成的少量真实高质量样例。
Self-Instruct
用模型自身从种子任务扩展生成指令数据的方法。
模型坍缩 (Model Collapse)
反复用模型生成数据训练导致分布尾部丢失、质量退化。
近似去重 (Near-dedup)
用 MinHash 或嵌入相似度去除高度相似样本。
可验证奖励 (Verifiable)
能用程序判定对错的数据，如数学答案、单元测试。
💻 04 · 代码
基于种子样例生成并去重python
import json, hashlib
from openai import OpenAI

client = OpenAI()
seeds = ["我的快递三天没更新了", "收到的杯子是碎的，怎么退？"]
topics = ["退款", "物流", "发票", "账号安全"]

def gen(topic: str) -> list[dict]:
    prompt = (f"参考这些真实客服问题风格：{seeds}\n"
              f"生成 5 条关于「{topic}」的用户问题，语气、长度各不相同。"
              '输出 JSON：{"items": [{"q": "...", "difficulty": "easy|hard"}]}')
    r = client.chat.completions.create(
        model="gpt-4o-mini",                 # 以官方文档为准
        messages=[{"role": "user", "content": prompt}],
        response_format={"type": "json_object"}, temperature=1.0)
    return json.loads(r.choices[0].message.content)["items"]

seen, data = set(), []
for t in topics:
    for item in gen(t):
        key = hashlib.md5(item["q"].strip().encode()).hexdigest()
        if key not in seen:                  # 精确去重；生产中再做近似去重
            seen.add(key); data.append({**item, "topic": t})
print(len(data), "条，需人工抽检后使用")

用种子样例和主题清单控制多样性，JSON 输出便于解析，去重后仍需人工抽检。

📊 05 · 参数对比

合成数据用途与风险

用途做法主要风险
微调指令数据强模型生成问答对错误被学进模型、风格同质化
评测用例补充生成边界与对抗问题与真实分布不符，评分失真
隐私替代生成仿真用户记录可能复现训练数据中的敏感信息
蒸馏大模型输出训练小模型受上游模型条款约束，需核查许可
⚖️ 06 · 方案取舍

纯合成数据

优点成本低、规模大

代价分布偏移，质量上限受生成模型限制

适用冷启动、无真实数据时

真实 + 合成混合

优点兼顾真实性与覆盖面

代价需要配比调优

适用多数微调与评测场景

人工标注

优点质量与真实性最好

代价昂贵、慢

适用高风险领域与最终评测集

🕳️ 07 · 常见坑

  • ✗只用合成数据评测合成数据训练的模型

    ✓保留独立的真实数据评测集作为最终依据

  • ✗不检查多样性，大量近似重复样本

    ✓做近似去重，并统计主题、长度、难度分布

  • ✗忽视生成模型的使用条款

    ✓核查厂商条款中对输出用于训练其他模型的限制

  • ✗相信生成的答案都正确

    ✓对可验证任务用程序校验，其余人工抽检

🎤 09 · 面试追问
什么是模型坍缩？

模型反复用前代模型生成的数据训练时，低概率的长尾内容在每一代都更少被采样，分布逐渐收窄，最终输出单一且失真。缓解方法是始终保留真实数据、控制合成比例并持续监控多样性。

如何保证合成数据的多样性？

在提示中显式变换主题、角色、难度、长度与格式；使用较高温度并分批生成；用进化式方法改写已有样本；生成后用嵌入聚类检查覆盖情况，删除过密簇中的重复样本，补足稀疏区域。

合成数据适合用来做评测集吗？

可以作为补充，用于覆盖罕见场景和对抗用例，但核心评测集应来自真实用户数据并经过人工标注。否则评测会偏向生成模型的风格，高估或低估真实效果。
