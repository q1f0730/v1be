DNS 记录类型 (A / CNAME / MX / TXT)

DNS Record Types

📐 01 · 定义

DNS 记录（Resource Record）是权威 DNS 区域中的条目，每条由名称、类型、TTL 和值组成，告诉解析器某个域名的地址、别名、邮件服务器或任意文本信息。常用类型有 A/AAAA（IPv4/IPv6 地址）、CNAME（别名）、MX（邮件交换）、TXT（文本，承载 SPF、DKIM、域名验证）、NS 和 CAA。

⚙️ 02 · 原理
  1. 1

    注册商处设置 NS 记录，把域名委派给某个权威 DNS 服务商（如 Cloudflare、阿里云 DNS）。

  2. 2

    在权威服务商的区域中添加记录；递归解析器查询时，从根、顶级域逐级找到权威服务器并取回记录。

  3. 3

    A/AAAA 直接返回 IP；CNAME 返回另一个域名，解析器继续解析目标直到拿到地址。

  4. 4

    发邮件时，发送方查询收件域的 MX 记录，按优先级（数值越小越优先）连接邮件服务器，并用 TXT 中的 SPF/DKIM/DMARC 校验。

  5. 5

    每条记录带 TTL，解析器在 TTL 内缓存结果；修改记录后旧值可能在缓存中保留至 TTL 结束。

🔤 03 · 术语
TTL (Time To Live)
记录可被缓存的秒数，决定修改后生效所需时间。
Apex / 根域
不带子域的裸域名，如 example.com，按规范不能设 CNAME。
CNAME 拉平 (CNAME Flattening)
部分 DNS 服务商在根域模拟 CNAME 的功能，返回 A 记录。
SPF / DKIM / DMARC
通过 TXT 发布的邮件发件授权、签名公钥和处理策略。
CAA
指定哪些证书颁发机构可为该域名签发证书。
NS
声明负责该区域的权威 DNS 服务器。
💻 04 · 代码
用 dig 检查各类记录bash
# A / AAAA：域名 -> IP
dig +short example.com A
dig +short example.com AAAA

# CNAME：子域 -> 另一个域名
dig +short www.github.com CNAME

# MX：邮件服务器及优先级
dig +short gmail.com MX

# TXT：SPF、域名验证等
dig +short google.com TXT

# NS：权威 DNS；直接问权威服务器可绕过缓存
dig +short example.com NS
dig @a.iana-servers.net example.com A +norecurse

# 查看剩余 TTL（第二列）
dig example.com A +noall +answer

用 dig 逐类查询，并直接询问权威服务器以区分“没配对”与“缓存未过期”。

⚖️ 06 · 方案取舍

A 记录指向固定 IP

优点解析链短，根域可用

代价IP 变化需手动更新

适用自有服务器、固定 IP

CNAME 指向平台域名

优点平台换 IP 无需改动

代价根域不能用标准 CNAME，多一次解析

适用Vercel、CDN、SaaS 子域

ALIAS / CNAME 拉平

优点根域也能跟随平台变化

代价依赖服务商私有实现

适用根域接入托管平台

🕳️ 07 · 常见坑

  • ✗在根域设置 CNAME 导致 MX 等记录失效

    ✓根域用 A 记录或服务商提供的 ALIAS/拉平功能

  • ✗同时存在两条 SPF TXT 记录

    ✓SPF 只能有一条，多个发件服务合并到同一条 include

  • ✗迁移前未调低 TTL，切换后长时间不生效

    ✓提前一到两个 TTL 周期调低 TTL，迁移完成后再调回

  • ✗Cloudflare 代理开启后邮件或 SSH 失效

    ✓代理只适用于 HTTP(S)，邮件和 SSH 相关记录设为仅 DNS

🎤 09 · 面试追问
为什么根域不能设置 CNAME？

RFC 规定 CNAME 不能与同名的其他记录共存，而根域必须有 SOA 和 NS 记录，MX、TXT 也常放在根域。若根域使用 CNAME，会与这些记录冲突。服务商的 ALIAS 或 CNAME 拉平在服务端解析目标后返回 A 记录来规避这一限制。

什么是子域接管（Subdomain Takeover）？

CNAME 仍指向已删除的云资源（如过期的存储桶或平台项目），攻击者注册同名资源后即可控制该子域内容，用于钓鱼或窃取 Cookie。防范方法是下线资源时同步删除 DNS 记录，并定期审计悬空记录。

改了 DNS 记录为什么各地生效时间不同？

各递归解析器独立缓存旧记录，按收到时的 TTL 倒计时，过期才重新查询；部分解析器还会延长缓存。因此生效时间取决于旧 TTL 与各解析器行为，而非 DNS 在“传播”。
