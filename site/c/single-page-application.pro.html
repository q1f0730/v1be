单页应用 (SPA)

Single-Page Application

📐 01 · 定义

单页应用（SPA，Single-Page Application）只在首次访问时加载一个 HTML 外壳和 JavaScript 包，之后由前端路由拦截导航、通过 API 获取数据并局部更新 DOM，无需整页刷新。它属于前端应用架构，带来接近原生应用的流畅交互，代价是首屏加载、SEO、服务器路由回退与长生命周期内存管理等问题。

⚙️ 02 · 原理
  1. 1

    服务器对所有页面路径返回同一个 index.html，浏览器下载并执行 JS 包，在客户端渲染界面。

  2. 2

    前端路由使用 History API（pushState/popstate）修改地址栏而不发起页面请求，并渲染对应组件。

  3. 3

    页面数据通过 fetch 调用后端 API 获取，界面根据状态局部更新。

  4. 4

    用户直接访问或刷新子路径时，服务器必须把未知路径回退到 index.html，否则返回 404。

  5. 5

    代码分割按路由懒加载 JS，缓解首包过大；SSR/SSG 可补齐首屏与 SEO。

🔤 03 · 术语
前端路由 (Client-side Routing)
由 JS 根据 URL 选择渲染的视图，不向服务器请求新页面。
History API
浏览器提供的 pushState、replaceState 与 popstate 事件接口。
回退路由 (Fallback / Rewrite)
服务器把未匹配的路径都返回 index.html 的配置。
代码分割 (Code Splitting)
把 JS 拆成多个按需加载的块，减小首包体积。
MPA
多页应用，每次导航由服务器返回新的 HTML 页面。
💻 04 · 代码
SPA 刷新 404 的服务器配置text
# Nginx：先找真实文件，找不到就返回 index.html
server {
  listen 80;
  root /var/www/app/dist;
  location / {
    try_files $uri $uri/ /index.html;
  }
  # 带哈希的静态资源长期缓存
  location /assets/ {
    add_header Cache-Control "public, max-age=31536000, immutable";
  }
}

# Vercel（vercel.json）：把所有路径重写到 index.html
{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }

# Netlify（public/_redirects 文件）
/*    /index.html   200

回退规则让服务器把子路径交给前端路由处理；真实不存在的页面需由前端路由显示 404。

📊 05 · 参数对比

SPA 与 MPA 对比

维度SPAMPA
页面切换局部更新，无白屏闪烁整页加载
首屏需下载并执行 JS 后才有内容服务器直接返回 HTML
SEO依赖爬虫执行 JS，需额外处理天然友好
部署静态托管 + 回退配置需要服务端渲染页面
⚖️ 06 · 方案取舍

纯 SPA（CSR）

优点交互流畅，可纯静态托管

代价首屏慢、SEO 弱

适用登录后的后台、工具类应用

SSR/SSG 框架

优点首屏快、SEO 好，仍保留客户端导航

代价需服务端或构建流程，复杂度更高

适用内容站、营销页、电商

传统 MPA + 局部增强

优点简单、稳健、SEO 好

代价复杂交互实现成本高

适用内容为主、交互较少

🕳️ 07 · 常见坑

  • ✗部署后刷新子页面 404

    ✓配置服务器或平台的回退重写到 index.html

  • ✗首包过大导致长时间白屏

    ✓按路由代码分割、压缩与缓存，并测量首屏指标

  • ✗路由切换后焦点与读屏不更新

    ✓导航后移动焦点到主标题并更新 document.title

  • ✗长时间运行积累定时器和监听器导致内存泄漏

    ✓组件卸载时清理订阅、定时器与事件监听

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么 SPA 刷新子页面会 404？

客户端导航只调用 pushState 修改地址，不请求服务器；刷新或直接访问时浏览器向服务器请求该路径，静态服务器上没有对应文件就返回 404。需配置未匹配路径回退到 index.html，由前端路由接管。

SPA 的 SEO 问题如何解决？

对需收录的页面使用 SSR 或 SSG 输出完整 HTML；为每个路由设置 title、meta 与规范链接；提供站点地图。依赖爬虫执行 JS 存在延迟与不确定性，不应作为唯一方案。

SPA 中如何避免内存泄漏？

SPA 页面长时间不刷新，未清理的定时器、全局事件监听、WebSocket 订阅与闭包引用会累积。组件卸载时在清理函数中取消订阅、清除定时器、中止进行中的请求，并用浏览器内存快照排查。
