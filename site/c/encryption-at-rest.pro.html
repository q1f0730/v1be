静态数据加密

Encryption at Rest

📐 01 · 定义

静态数据加密（Encryption at Rest）指数据在磁盘、数据库文件、对象存储和备份中以密文保存。它可落在全盘、卷/存储服务、数据库（TDE）或应用字段等不同层次，主要防御介质丢失、快照泄露和越权读取底层存储，不防御已获授权的应用层访问。

⚙️ 02 · 原理
  1. 1

    选定加密层：全盘/卷加密对应用透明，字段级加密在写入数据库前就由应用完成。

  2. 2

    普遍采用信封加密：数据密钥（DEK）用 AES-GCM 加密数据，DEK 再被主密钥（KEK）加密。

  3. 3

    KEK 托管在 KMS 或 HSM 中，不离开硬件边界，应用只能请求加解密 DEK。

  4. 4

    密文 DEK 与数据一起存储；读取时先调 KMS 解密 DEK，再在内存中解密数据。

  5. 5

    密钥轮换通常只轮换 KEK 并重新包裹 DEK，访问 KMS 的每次调用都有审计日志。

🔤 03 · 术语
信封加密 (Envelope Encryption)
用 KEK 加密 DEK、用 DEK 加密数据的两层结构。
KMS
密钥管理服务，集中保管主密钥并提供权限控制与审计。
TDE (Transparent Data Encryption)
数据库引擎在页写盘时加密，对 SQL 透明。
AES-GCM
带认证的对称加密模式，同时提供机密性与完整性。
加密上下文 / AAD
参与认证但不加密的附加数据，防止密文被挪用到别处。
加密擦除 (Crypto-shredding)
销毁密钥使对应数据永久不可读，用于删除合规。
💻 04 · 代码
KMS 信封加密字段python
# pip install boto3 cryptography
import os, boto3
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

kms = boto3.client("kms")
KEY_ID = "alias/app-data"  # KMS 中的主密钥别名

def encrypt_field(plaintext: bytes, user_id: str) -> dict:
    dk = kms.generate_data_key(KeyId=KEY_ID, KeySpec="AES_256")
    nonce = os.urandom(12)                       # GCM 每次加密用新 nonce
    aad = user_id.encode()                       # 绑定到该用户，防挪用
    ct = AESGCM(dk["Plaintext"]).encrypt(nonce, plaintext, aad)
    # 只持久化：密文 DEK + nonce + 密文，明文 DEK 用完即丢
    return {"edk": dk["CiphertextBlob"], "nonce": nonce, "ct": ct}

def decrypt_field(rec: dict, user_id: str) -> bytes:
    dek = kms.decrypt(CiphertextBlob=rec["edk"])["Plaintext"]
    return AESGCM(dek).decrypt(rec["nonce"], rec["ct"], user_id.encode())

主密钥不出 KMS；每条记录有独立 DEK，AAD 让密文无法被搬到别的用户名下。

⚖️ 06 · 方案取舍

云存储默认加密

优点零改造，几乎无性能损耗

代价云账号权限即可解密读取

适用所有场景的基线

字段级加密

优点最小化明文暴露面，DBA 也看不到

代价无法直接索引、排序和模糊查询

适用身份证号、银行卡等高敏字段

客户自管密钥（CMK/BYOK）

优点可随时停用密钥，满足合规

代价密钥误删即数据永久丢失

适用受监管行业或客户合同要求

🕳️ 07 · 常见坑

  • ✗开了磁盘加密就宣称“数据已加密安全”

    ✓明确威胁模型，敏感字段另做应用层加密

  • ✗加密密钥写在代码或同库配置表里

    ✓主密钥放 KMS/HSM，应用只持有调用权限

  • ✗AES-GCM 重复使用同一 nonce

    ✓每次加密生成随机 96 位 nonce 或使用计数器

  • ✗备份、日志、缓存仍是明文

    ✓盘点所有数据副本，统一纳入加密策略

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么要用信封加密而不是直接用 KMS 加密数据？

KMS 单次加密有大小限制且每次网络调用有延迟和费用。信封加密只让 KMS 处理很小的 DEK，大数据在本地用 AES 加密；轮换 KEK 时只需重包 DEK，无需重加密全部数据。

TDE 能防 SQL 注入拖库吗？

不能。TDE 在存储层透明解密，凡是能正常执行 SQL 的连接看到的都是明文，注入同样如此。它防的是数据文件、备份介质被直接拿走。要防注入拖库需应用层加密与访问控制。

字段加密后还要按手机号查询怎么办？

可额外存一列确定性的盲索引：用独立密钥对规范化手机号做 HMAC，查询时同样计算后等值匹配。代价是泄露“值是否相同”，不支持范围与模糊查询。
