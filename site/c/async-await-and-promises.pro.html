异步编程 (Promise / async-await)

Async/Await & Promises

📐 01 · 定义

Promise 是表示异步操作最终结果（成功值或失败原因）的对象，async/await 是基于 Promise 的语法糖，让异步代码以接近同步的顺序书写。它属于语言运行时的并发模型层：JavaScript 单线程通过事件循环调度回调，Python asyncio 也采用类似的协程模型。网络请求、文件读写、LLM API 调用都依赖它。

⚙️ 02 · 原理
  1. 1

    Promise 有三种状态：pending、fulfilled、rejected，状态一旦确定不可再变。

  2. 2

    then/catch 注册的回调在 Promise 敲定后作为微任务进入队列，由事件循环在当前同步代码执行完后调度。

  3. 3

    async 函数总是返回 Promise；await 暂停当前函数，等待 Promise 敲定后再恢复，期间线程可处理其他任务。

  4. 4

    await 遇到 rejected 会抛出异常，可用 try/catch 捕获；未处理的 rejection 会触发运行时警告或进程退出。

  5. 5

    Promise.all、allSettled、race、any 组合多个 Promise，实现并行、容错与超时竞速。

🔤 03 · 术语
微任务 (Microtask)
Promise 回调所在的队列，优先于定时器等宏任务执行。
Promise.all
全部成功才成功，任一失败立即失败。
Promise.allSettled
等待全部结束，返回每个的成功或失败结果。
AbortController
用于取消 fetch 等异步操作的标准接口。
未处理的拒绝 (Unhandled Rejection)
没有被 catch 的失败 Promise，Node.js 默认会终止进程。
💻 04 · 代码
并行、容错与超时javascript
// 1) 串行 vs 并行：互不依赖的请求应并行
async function loadDashboard(userId) {
  const [user, orders] = await Promise.all([
    fetchJson(`/api/users/${userId}`),
    fetchJson(`/api/orders?user=${userId}`),
  ]);
  return { user, orders };
}

// 2) 带超时与错误处理的请求
async function fetchJson(url) {
  const res = await fetch(url, { signal: AbortSignal.timeout(5000) }); // 5 秒超时
  if (!res.ok) throw new Error(`HTTP ${res.status}: ${url}`);
  return res.json();
}

// 3) 部分失败也要继续：allSettled
const results = await Promise.allSettled(urls.map(fetchJson));
const ok = results.filter((r) => r.status === "fulfilled").map((r) => r.value);

// 4) 常见坑：forEach 不会等待 async 回调
// items.forEach(async (it) => await save(it));   // 错：不等待、错误也丢失
for (const it of items) await save(it);          // 需要顺序时用 for...of

fetch 只在网络失败时 reject，HTTP 4xx/5xx 需手动检查 res.ok；顶层 await 需 ES 模块。

📊 05 · 参数对比

Promise 组合器对比

方法何时完成失败行为适用
Promise.all全部成功任一失败即失败都必须成功
Promise.allSettled全部结束不失败，逐个报告批量容错
Promise.race第一个结束第一个失败即失败超时竞速
Promise.any第一个成功全部失败才失败多源冗余请求
⚖️ 06 · 方案取舍

顺序 await

优点逻辑清晰，便于依赖前一步结果

代价总耗时是各步之和

适用后一步依赖前一步

Promise.all 并行

优点总耗时约等于最慢一个

代价并发过高可能触发限流

适用相互独立的少量请求

限并发池

优点兼顾速度与下游压力

代价需额外实现或依赖库

适用批量调用 LLM 或第三方 API

🕳️ 07 · 常见坑

  • ✗漏写 await，拿到 Promise 对象或错误未被捕获

    ✓开启 no-floating-promises 等 Lint 规则与 TypeScript 检查

  • ✗在 forEach/map 中用 async 回调期望顺序执行

    ✓顺序用 for...of + await，并行用 Promise.all(map)

  • ✗无超时的外部请求导致请求堆积

    ✓为 fetch 设置 AbortSignal.timeout 或使用带超时的客户端

  • ✗批量 Promise.all 上千个 LLM 请求触发 429

    ✓限制并发数并对 429 做退避重试

🎤 09 · 面试追问
await 会阻塞线程吗？

不会。await 只暂停当前 async 函数的执行，把后续逻辑作为回调交还事件循环，线程可继续处理其他任务；但 await 之前或之后的同步重计算仍会阻塞事件循环。

以下输出顺序是什么：setTimeout、Promise.then、同步 log？

先输出同步 log；当前任务结束后清空微任务队列，执行 Promise.then；最后才执行 setTimeout 的宏任务回调。原因是微任务在每个宏任务之后、下一个宏任务之前全部执行。

如何控制大量异步任务的并发？

实现或使用并发池：维持固定数量的进行中 Promise，完成一个再启动下一个；配合超时、重试与退避；Python 中可用 asyncio.Semaphore，JavaScript 可用 p-limit 等库。
