推理模型与思维链

Reasoning Models

📐 01 · 定义

推理模型（Reasoning Models）是经专门训练、在给出答案前先生成较长推理过程的大语言模型，如 OpenAI o 系列、DeepSeek-R1。它属于模型能力层，用推理时计算（Test-Time Compute）换取准确率，适合数学、代码、规划等多步任务，代价是延迟和 token 成本更高。

⚙️ 02 · 原理
  1. 1

    训练上通常在预训练模型基础上用强化学习（RL）奖励正确结果，使模型学会生成有效的推理链。

  2. 2

    推理时模型先输出思考 token，再输出答案；部分厂商不返回原始思考内容，只返回摘要。

  3. 3

    思考 token 一般按输出 token 计费，并计入上下文和输出长度限制。

  4. 4

    API 提供思考预算控制：如 Claude 的 thinking.budget_tokens、OpenAI 的 reasoning effort 档位。

  5. 5

    在多轮工具调用中，部分 API 要求把思考块原样回传，以保持推理连续性。

🔤 03 · 术语
思维链 (Chain-of-Thought)
让模型写出中间推理步骤，可通过提示或训练获得。
推理时计算 (Test-Time Compute)
在推理阶段投入更多计算换取更好结果的扩展维度。
思考预算 (Thinking Budget)
限制模型可用于内部推理的最大 token 数。
可验证奖励 (Verifiable Reward)
用单元测试、标准答案等自动判定对错作为 RL 奖励信号。
过度思考 (Overthinking)
简单问题也消耗大量推理 token，增加延迟和成本。
💻 04 · 代码
Claude 开启扩展思考python
import anthropic

client = anthropic.Anthropic()
resp = client.messages.create(
    model="claude-sonnet-4-5",      # 以官方模型列表为准
    max_tokens=16000,               # 必须大于思考预算
    thinking={"type": "enabled", "budget_tokens": 8000},
    messages=[{"role": "user",
               "content": "一个数列前三项 2,6,12，求第 20 项并说明规律"}],
)

for block in resp.content:
    if block.type == "thinking":
        print("[思考]", block.thinking[:200], "...")
    elif block.type == "text":
        print("[回答]", block.text)

print(resp.usage)   # 思考 token 计入 output_tokens

budget_tokens 设上限而非固定消耗；不同模型返回完整思考或摘要，以文档为准。

📊 05 · 参数对比

推理模型 vs 常规模型

维度推理模型常规模型
擅长数学、代码、多步规划对话、改写、抽取、简单问答
延迟高，先思考再输出低，首 token 快
成本思考 token 额外计费仅输入/输出
提示写法说清目标与约束即可可受益于分步引导
⚖️ 06 · 方案取舍

全程使用推理模型

优点复杂任务准确率高

代价慢且贵

适用低频、高价值的难题

常规模型 + CoT 提示

优点便宜、可控

代价复杂推理上限较低

适用中等难度、对延迟敏感

路由：难题才走推理

优点成本与质量平衡

代价需要分类器和评测

适用流量大、难度差异大

🕳️ 07 · 常见坑

  • ✗对推理模型再写“请一步步思考”和大量步骤示例

    ✓给目标、约束、验收标准，让模型自行规划

  • ✗max_tokens 设得太小，思考完就截断没有答案

    ✓max_tokens 留足输出空间，并监控 stop_reason

  • ✗把思考内容直接展示给用户或当作事实依据

    ✓思考过程不保证忠实，只以最终答案和可验证结果为准

  • ✗简单分类任务也开高思考预算

    ✓按任务难度设置预算或路由到常规模型

☑️ 08 · 检查清单
🎤 09 · 面试追问
推理模型和 CoT 提示有什么关系？

CoT 最初是一种提示技巧，让常规模型写出中间步骤。推理模型则通过强化学习等训练，把生成有效推理链变成默认行为，并能在思考中自我检查和回溯。两者都是用更多推理 token 换准确率，后者更稳定、上限更高。

为什么思考过程不能完全信任？

研究发现模型写出的推理不一定忠实反映其真实决策依据，可能省略关键因素或事后合理化。此外部分厂商只返回摘要。因此应以可验证的最终结果（测试、标准答案）评估，而不是读推理链。

生产环境如何控制推理模型成本？

按难度路由，只把难题发给推理模型；设定思考预算或 effort 档位；对相同前缀启用缓存；缓存常见问题答案；监控每请求的思考 token 和延迟分布，并用评测集确认降低预算后质量是否可接受。
