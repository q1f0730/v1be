分析型与事务型数据库

OLAP vs OLTP

📐 01 · 定义

OLTP（Online Transaction Processing，联机事务处理）与 OLAP（Online Analytical Processing，联机分析处理）是两类数据负载。OLTP 面向大量并发的短事务，强调低延迟、ACID 与单行读写；OLAP 面向少量但扫描海量数据的聚合查询，强调吞吐与扫描效率。区分二者决定了数据库选型、存储格式与架构隔离方式。

⚙️ 02 · 原理
  1. 1

    OLTP 请求通常按主键或索引读写少量行，要求毫秒级延迟和事务一致性，典型如下单、扣库存。

  2. 2

    OLTP 系统多用行式存储与 B-tree 索引，一行的所有列连续存放，适合整行读写。

  3. 3

    OLAP 查询常对数亿行做 GROUP BY、JOIN、窗口函数，只用少数列，瓶颈在扫描与聚合吞吐。

  4. 4

    OLAP 系统多用列式存储、压缩、向量化执行与 MPP 并行，提升每秒处理的行数。

  5. 5

    实际架构通过 CDC 或批量 ETL 把 OLTP 数据同步到 OLAP 系统，二者负载物理隔离。

🔤 03 · 术语
ACID
原子性、一致性、隔离性、持久性，事务型数据库的核心保证。
MPP (Massively Parallel Processing)
把查询拆到多节点并行执行的架构。
向量化执行 (Vectorized Execution)
一次处理一批列值而非逐行，提升 CPU 效率。
HTAP
混合事务/分析处理，同一系统兼顾两类负载。
CDC (Change Data Capture)
捕获数据库变更并实时同步到下游系统。
💻 04 · 代码
两类查询的典型形态sql
-- OLTP：按主键改一行，要求毫秒级 + 事务
BEGIN;
UPDATE inventory SET stock = stock - 1
 WHERE sku = 'A100' AND stock > 0;
INSERT INTO orders (user_id, sku, amount)
 VALUES (42, 'A100', 99.00);
COMMIT;

-- OLAP：扫全年数据做聚合，只用 3 列
SELECT date_trunc('month', created_at) AS m,
       sku,
       SUM(amount) AS revenue
FROM orders
WHERE created_at >= '2025-01-01'
GROUP BY 1, 2
ORDER BY 1, 3 DESC;

第一段是高并发短事务，第二段是低频大扫描；后者应放到分析库执行。

OLTP 与 OLAP 关键差异

维度OLTPOLAP
访问模式点查/小范围读写大范围扫描聚合
存储格式行式 + B-tree列式 + 压缩
优化目标延迟、并发、一致性吞吐、扫描效率
代表系统PostgreSQL、MySQLClickHouse、BigQuery、Snowflake
⚖️ 06 · 方案取舍

分析查询走只读副本

优点改动最小，数据准实时

代价仍是行存，复杂聚合慢，可能拖累复制

适用报表量小、早期产品

同步到专用 OLAP 库

优点隔离彻底，分析性能高

代价多一套系统和同步链路

适用分析需求稳定增长

HTAP 数据库

优点一套系统、数据新鲜

代价选型受限，极端负载仍需拆分

适用需要实时分析且团队想少运维

🕳️ 07 · 常见坑

  • ✗在 OLTP 主库上跑长时间报表查询

    ✓迁到只读副本或分析库，并设置 statement_timeout

  • ✗为了报表在业务表上加大量索引

    ✓索引拖慢写入；聚合需求交给列式分析库

  • ✗把 OLAP 库当业务库，做高频单行更新

    ✓OLAP 擅长批量追加，点更新代价高，保留在 OLTP

  • ✗同步链路无监控，分析数据静默滞后

    ✓监控 CDC 延迟与行数对账，异常告警

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么列式存储适合 OLAP 而不适合 OLTP？

OLAP 只读少数列、扫描大量行，列存只读所需列且同列压缩率高；OLTP 常整行读写，列存要把一行拆到多列文件中更新，写放大且点查需拼行，延迟高。

如何把 OLTP 数据实时同步给 OLAP？

用 CDC（如 Debezium 读 binlog/WAL）推到 Kafka 等消息系统，再写入分析库；注意顺序、幂等、Schema 演进和删除事件处理，并监控端到端延迟。

HTAP 能否完全替代分离架构？

能减少同步链路与数据延迟，但两类负载仍在争用资源，通常靠行列双存或副本隔离实现；超大规模分析或复杂建模场景仍常用独立数仓。
