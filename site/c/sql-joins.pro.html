表连接 (JOIN)

SQL Joins

📐 01 · 定义

JOIN 是 SQL 中按连接条件组合多张表行的操作，包括 INNER、LEFT/RIGHT/FULL OUTER、CROSS 以及自连接，配合 EXISTS 可表达半连接与反连接。它是关系模型「规范化存储、查询时组合」的核心机制。正确性陷阱（行数扇出、NULL、条件位置）与性能（连接算法、索引）是评审重点。

⚙️ 02 · 原理
  1. 1

    逻辑上，JOIN 先形成两表行的组合，再按 ON 条件筛选；OUTER JOIN 会为未匹配的一侧补 NULL 行。

  2. 2

    ON 条件在连接时生效，WHERE 在连接后过滤；对 LEFT JOIN 右表列写 WHERE 条件会过滤掉补出的 NULL 行。

  3. 3

    一对多连接会使左表行重复（扇出），在其上直接 SUM/COUNT 会重复计数。

  4. 4

    优化器为每对连接选择算法：嵌套循环（小表驱动 + 索引）、哈希连接（大表等值）、归并连接（已排序输入）。

  5. 5

    连接列上的索引和统计信息决定了连接顺序与算法选择，可用 EXPLAIN 查看。

🔤 03 · 术语
外连接 (Outer Join)
保留一侧或两侧未匹配的行，缺失列以 NULL 填充。
半连接 (Semi Join)
只判断是否存在匹配，常用 EXISTS 表达，不产生重复行。
反连接 (Anti Join)
找出没有匹配的行，推荐 NOT EXISTS。
扇出 (Fan-out)
一对多连接导致左侧行被复制多份的现象。
哈希连接 (Hash Join)
对较小输入建哈希表，再扫描另一侧探测匹配。
💻 04 · 代码
LEFT JOIN 与常见陷阱sql
-- 每个用户的已支付订单数，没订单的显示 0
SELECT u.id, u.name, COUNT(o.id) AS paid_orders   -- COUNT(列) 不计 NULL
FROM users u
LEFT JOIN orders o
  ON o.user_id = u.id
 AND o.status = 'paid'          -- 右表条件放 ON：保留无订单用户
GROUP BY u.id, u.name;

-- 错误写法：放到 WHERE 会过滤掉补出的 NULL 行，变成 INNER JOIN
-- ... LEFT JOIN orders o ON o.user_id = u.id WHERE o.status = 'paid'

-- 反连接：从未下单的用户（NOT IN 遇到 NULL 会得到空结果）
SELECT u.id FROM users u
WHERE NOT EXISTS (SELECT 1 FROM orders o WHERE o.user_id = u.id);

-- 扇出陷阱：同时连两张一对多表再求和会重复计数，应先分别聚合
SELECT u.id, o.total_amount, p.total_paid
FROM users u
LEFT JOIN (SELECT user_id, SUM(amount) AS total_amount FROM orders GROUP BY user_id) o ON o.user_id = u.id
LEFT JOIN (SELECT user_id, SUM(paid) AS total_paid FROM payments GROUP BY user_id) p ON p.user_id = u.id;

外连接右表条件放 ON；反连接用 NOT EXISTS；多个一对多关系先聚合再连接。

⚖️ 06 · 方案取舍

数据库内 JOIN

优点一次往返，优化器选算法

代价复杂多表连接难读、难调优

适用关系型数据的常规查询

应用层分次查询再组装

优点可分别缓存，适合跨服务数据

代价易出现 N+1，往返多

适用数据分布在不同服务或库

反规范化冗余字段

优点读取无需连接，快

代价写入需同步，存在不一致风险

适用读远多于写的热点查询

🕳️ 07 · 常见坑

  • ✗LEFT JOIN 后在 WHERE 中过滤右表列

    ✓把右表条件移到 ON，或明确改用 INNER JOIN

  • ✗连接多个一对多表后直接 SUM，金额翻倍

    ✓先在子查询中分别聚合，再连接

  • ✗用 NOT IN 做反连接，子查询含 NULL 时结果为空

    ✓使用 NOT EXISTS

  • ✗连接列缺少索引或类型不一致

    ✓外键列建索引，保持两侧类型与排序规则一致

🎤 09 · 面试追问
COUNT(*) 和 COUNT(o.id) 在 LEFT JOIN 中有何区别？

COUNT(*) 统计行数，未匹配的左表行因被补了一行 NULL 也会计为 1；COUNT(o.id) 只统计非 NULL 值，未匹配时为 0。统计「每个用户订单数」应使用 COUNT(右表主键)。

为什么 NOT IN 遇到 NULL 会返回空结果？

x NOT IN (a, NULL) 等价于 x<>a AND x<>NULL，后者结果为 UNKNOWN，整个条件不可能为 TRUE，因此不返回任何行。NOT EXISTS 只判断是否存在匹配行，不受 NULL 影响。

优化器如何选择连接顺序？

基于统计信息估算各表过滤后的行数与连接选择性，枚举连接顺序与算法组合，选总代价最低的计划；表很多时使用启发式或遗传算法限制搜索空间。统计信息过期会导致严重误判。
