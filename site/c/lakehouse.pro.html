湖仓一体 (Iceberg / Delta Lake)

Lakehouse

📐 01 · 定义

湖仓一体（Lakehouse）是在对象存储上的开放文件（通常为 Parquet）之上，增加一层事务性表格式元数据，使数据湖具备数据仓库的 ACID 事务、模式管理、时间旅行和高效查询能力。主流开放表格式包括 Apache Iceberg、Delta Lake 和 Apache Hudi，多种计算引擎可共享同一份数据。

⚙️ 02 · 原理
  1. 1

    数据文件以列式格式（如 Parquet）存放在对象存储，存储与计算分离，按量付费。

  2. 2

    表格式维护元数据：Iceberg 用元数据文件、清单列表和清单文件描述快照；Delta Lake 用 _delta_log 中的提交日志与检查点。

  3. 3

    写入先生成新数据文件，再通过原子操作提交新快照（如目录服务中的指针替换），读者看到完整的旧版或新版。

  4. 4

    查询时引擎读元数据中的分区与列统计信息做文件裁剪，只扫描相关文件。

  5. 5

    保留历史快照以支持时间旅行与回滚；通过快照过期和小文件合并等维护任务控制存储与性能。

🔤 03 · 术语
开放表格式 (Open Table Format)
定义如何用元数据把一组文件组织成可事务读写的表，如 Iceberg、Delta。
快照 (Snapshot)
表在某次提交后的完整状态，支持按快照 ID 或时间读取。
目录 (Catalog)
记录表名到当前元数据位置的服务，如 Hive Metastore、REST Catalog。
隐藏分区 (Hidden Partitioning)
Iceberg 由列值变换派生分区，查询无需显式写分区列。
合并 (Compaction)
把大量小文件重写为较大的文件，降低元数据和读取开销。
💻 04 · 代码
Spark SQL 操作 Iceberg 表sql
-- 假设已在 Spark 中配置名为 demo 的 Iceberg catalog
CREATE TABLE demo.db.events (
  id      BIGINT,
  user_id BIGINT,
  kind    STRING,
  ts      TIMESTAMP
) USING iceberg
PARTITIONED BY (days(ts));          -- 隐藏分区

INSERT INTO demo.db.events VALUES (1, 42, 'click', current_timestamp());

-- 模式演进：加列只改元数据，不重写数据文件
ALTER TABLE demo.db.events ADD COLUMN device STRING;

-- 查看快照并时间旅行
SELECT snapshot_id, committed_at FROM demo.db.events.snapshots;
SELECT * FROM demo.db.events TIMESTAMP AS OF '2026-10-01 00:00:00';

-- 维护：合并小文件、过期旧快照
CALL demo.system.rewrite_data_files(table => 'db.events');
CALL demo.system.expire_snapshots(table => 'db.events',
     older_than => TIMESTAMP '2026-09-01 00:00:00');

时间旅行语法需 Spark 3.3 及以上；过期快照后，更早的时间点将无法回溯。

⚖️ 06 · 方案取舍

Apache Iceberg

优点引擎中立，隐藏分区与分区演进

代价需要选型和运维 Catalog

适用多引擎共享、避免厂商锁定

Delta Lake

优点与 Spark/Databricks 集成深

代价部分高级特性依赖特定生态

适用以 Spark 为主的团队

托管云数据仓库

优点开箱即用，运维最少

代价存储格式与计费受厂商约束

适用团队小、追求简单的分析需求

🕳️ 07 · 常见坑

  • ✗流式高频小批写入，产生海量小文件

    ✓调大提交间隔并定期执行 rewrite_data_files 合并

  • ✗从不过期快照，存储成本持续增长

    ✓按保留策略定期 expire_snapshots，并清理孤儿文件

  • ✗多个写入方绕过 Catalog 直接改文件

    ✓所有写入都经表格式 API 提交，保证并发控制与原子性

  • ✗按高基数字段分区导致分区过多

    ✓按时间等低基数维度分区，必要时用分桶变换

🎤 09 · 面试追问
表格式如何在对象存储上实现 ACID？

数据文件一旦写入不再修改；每次提交生成新的元数据描述新快照，最后通过原子操作切换当前元数据指针（Catalog 的比较并交换，或 Delta 日志的原子创建）。并发写入采用乐观并发：提交时发现冲突则基于新版本重试或失败。

为什么湖仓表要定期合并小文件？

每个文件都有打开开销和元数据条目，海量小文件会让查询规划变慢、扫描效率下降、对象存储请求费用上升。合并把小文件重写为目标大小的文件，同时可按排序或聚簇优化数据布局。

时间旅行有哪些实际用途和限制？

用途：误写后回滚、复现历史报表、机器学习训练集按快照固定版本、审计。限制：依赖快照保留，过期后无法回溯；保留越久存储成本越高；且时间旅行回看的是表状态，不等同于业务时间。
