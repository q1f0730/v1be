策略即代码 (OPA)

Policy as Code

📐 01 · 定义

策略即代码（Policy as Code）把安全、合规与运维规则写成可版本化、可测试、可自动执行的代码，在 CI、部署准入和运行时由策略引擎统一判定。Open Policy Agent（OPA，CNCF 毕业项目）是通用策略引擎，使用声明式语言 Rego；Kubernetes 场景还常用基于 OPA 的 Gatekeeper 或 Kyverno。

⚙️ 02 · 原理
  1. 1

    把规则写成策略文件，与代码一起放在 Git 中评审、测试和发布。

  2. 2

    被检查对象以结构化数据（JSON/YAML）作为输入，如 Kubernetes 清单、Terraform 计划、API 请求。

  3. 3

    策略引擎对输入求值，输出允许/拒绝及原因列表，业务系统只依据决策结果行动，实现决策与执行解耦。

  4. 4

    在多个关口执行：本地与 CI 用 Conftest 检查配置，集群用准入控制器拦截，服务内部用 OPA 做授权。

  5. 5

    通过审计模式先观察违规而不拦截，再逐步切换为强制执行。

🔤 03 · 术语
Rego
OPA 的声明式查询语言，规则描述在何种条件下产生决策。
策略决策点 (PDP)
负责计算策略结果的组件，如 OPA；执行点（PEP）据此放行或拒绝。
准入控制 (Admission Control)
Kubernetes 在对象持久化前调用 Webhook 校验或改写请求。
Conftest
用 Rego 策略测试结构化配置文件的命令行工具，常用于 CI。
审计模式 (Audit/Dry-run)
只记录违规不拦截，用于新策略上线前评估影响面。
💻 04 · 代码
Conftest 检查 K8s 清单bash
mkdir -p policy
cat > policy/k8s.rego <<'EOF'
package main
import rego.v1

deny contains msg if {
  input.kind == "Deployment"
  some c in input.spec.template.spec.containers
  not c.securityContext.runAsNonRoot
  msg := sprintf("容器 %s 必须设置 runAsNonRoot: true", [c.name])
}

deny contains msg if {
  input.kind == "Deployment"
  some c in input.spec.template.spec.containers
  not c.resources.limits.memory
  msg := sprintf("容器 %s 缺少内存上限", [c.name])
}
EOF

# 在 CI 中执行：任一 deny 命中则返回非零退出码
conftest test deploy/deployment.yaml --policy policy/

同一份 Rego 可在 CI 与集群准入两处复用；import rego.v1 兼容 OPA 1.0 语法。

⚖️ 06 · 方案取舍

CI 阶段检查

优点反馈最早，修复成本最低

代价可被绕过，不覆盖手工变更

适用所有 IaC 与清单仓库

集群准入强制

优点无法绕过的最后关口

代价策略错误会阻断发布，需高可用

适用生产集群的关键安全规则

运行时授权（OPA sidecar/库）

优点授权逻辑与业务代码解耦，统一审计

代价增加调用延迟与部署组件

适用多服务需要一致的细粒度授权

🕳️ 07 · 常见坑

  • ✗新策略直接强制执行，阻断大量现有工作负载

    ✓先审计模式统计违规，修复存量后再强制

  • ✗策略没有单元测试，改动后误放或误杀

    ✓用 opa test 或 conftest verify 为每条规则写正反用例

  • ✗准入 Webhook 故障导致集群无法创建资源

    ✓多副本部署，合理设置 failurePolicy 与超时，排除系统命名空间

  • ✗拒绝信息含糊，开发者不知道怎么改

    ✓消息写明违规字段与修复方法，并附文档链接

🎤 09 · 面试追问
为什么把策略决策与执行分离？

业务服务只询问「能否执行」，规则统一在策略引擎中维护，修改规则无需改动和发布每个服务；决策可集中记录审计；同一策略语言覆盖 Kubernetes、CI、API 授权等多个执行点，减少规则在各处重复实现而不一致。

Gatekeeper 和 Kyverno 如何选？

Gatekeeper 基于 OPA 与 Rego，表达力强，可与组织内其他 OPA 场景共享技能；Kyverno 用 Kubernetes 风格的 YAML 编写，上手快，并原生支持改写与生成资源。只管 Kubernetes 且团队不熟 Rego 时常选 Kyverno。

AI 生成的 IaC 如何借助策略即代码把关？

在 CI 中对 Terraform 计划与 Kubernetes 清单运行策略检查，拦截公开存储桶、特权容器、缺少资源限制等问题；把违规消息反馈给 Agent 让其自行修复，形成自动闭环，人工只审查例外与高风险变更。
