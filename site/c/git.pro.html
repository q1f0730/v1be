📐 01 · 定义

Git 是分布式版本控制系统，以「快照」方式记录项目每次提交时全部文件的状态，每个克隆都包含完整历史。它通过内容寻址的对象存储、轻量分支和合并机制，支持离线工作、并行开发和精确回溯。在 AI 编程中，Git 是审查 Agent 改动、随时回滚的核心安全网。

⚙️ 02 · 原理
  1. 1

    工作区修改：在工作目录中编辑文件，Git 通过对比发现哪些文件发生了变化。

  2. 2

    暂存：git add 把选定的改动放入暂存区（Index），精确控制下一次提交的内容。

  3. 3

    提交：git commit 把暂存内容存为快照对象，记录作者、时间、说明和父提交。

  4. 4

    对象存储：文件内容、目录结构、提交都以哈希命名存储，相同内容只存一份。

  5. 5

    分支与同步：分支是指向提交的可移动指针，通过 fetch、push 与远程仓库交换提交。

🔤 03 · 术语
工作区 / 暂存区 / 仓库
Git 的三个区域：正在编辑、准备提交、已提交历史。
提交哈希 (Commit Hash)
由提交内容计算出的唯一 ID，默认使用 SHA-1。
HEAD
指向当前所在分支或提交的指针。
reflog
记录 HEAD 移动历史，可找回误删的提交或分支。
.gitignore
列出不纳入版本控制的文件与目录。
💻 04 · 代码
日常与救急命令bash
git status                    # 当前改动概览
git diff                      # 未暂存的改动
git add -p                    # 逐块选择要暂存的改动
git commit -m "feat: add login form validation"
git log --oneline --graph -10 # 最近 10 条提交

# 撤销与回退
git restore app.js            # 丢弃工作区中该文件的修改
git restore --staged app.js   # 取消暂存，保留修改
git revert <hash>             # 生成一个反向提交（适合已推送的历史）

# 临时保存手头工作
git stash && git stash pop

# 误操作后的救命稻草：找回「丢失」的提交
git reflog
git switch -c rescue <hash>   # 基于找到的提交建新分支

restore、revert、stash、reflog 覆盖了大部分「改坏了怎么办」的场景。

📊 05 · 参数对比

撤销操作对比

命令作用改写历史适用
git restore丢弃工作区修改否还没提交的改动
git revert新增反向提交否已推送到共享分支
git reset --hard移动分支指针并丢弃修改是仅本地未推送的提交
git commit --amend修改最近一次提交是刚提交、尚未推送
⚖️ 06 · 方案取舍

merge 合并

优点保留真实历史，不改写提交

代价历史图分叉较多

适用合并共享分支

rebase 变基

优点历史线性、清晰

代价改写提交，不当使用会扰乱协作

适用整理本地未推送的提交

squash 压缩合并

优点一个功能一个提交

代价丢失细粒度历史

适用PR 合入主分支

🕳️ 07 · 常见坑

  • ✗对已推送的共享分支 reset 或 force push

    ✓共享历史用 revert；必须强推时用 --force-with-lease 并通知团队

  • ✗git add . 把 .env、构建产物一起提交

    ✓先配置 .gitignore，提交前看 git status 与 diff

  • ✗让 Agent 连续大改几十个文件才提交一次

    ✓每完成一个可验证的小步骤就提交，便于回滚

  • ✗以为 reset --hard 后提交彻底没了而慌张

    ✓用 git reflog 找回提交哈希并恢复

🎤 09 · 面试追问
Git 为什么说存的是快照而不是差异？

每次提交记录的是整个项目目录树的状态（tree 对象），未变化的文件直接复用已有对象的引用，因此实际存储高效。差异是在比较两个快照时动态计算的；打包存储时 Git 也会做增量压缩，但这是存储优化而非模型本身。

merge 和 rebase 怎么选？

merge 保留真实的分叉与合并历史，安全，不改写提交；rebase 把提交重放到新基点上，历史线性但会改写哈希。原则：不对他人已基于的公共分支做 rebase；本地整理提交、同步主干时可以 rebase。

AI Agent 工作流中 Git 起什么作用？

检查点：每步改动可提交、可回退；审查：用 diff 清楚看到 Agent 改了什么；隔离：用分支或 git worktree 让多个 Agent 并行工作互不干扰；追溯：提交说明记录意图，便于事后排查。
