流式输出

Streaming Output

🧸 回到小白版

📐 01 · 定义

流式输出（Streaming Output）指模型服务在生成过程中把 token 增量推送给客户端，而不是等完整结果生成后一次性返回。它属于 API 传输与交互层，主流 LLM API 通常通过服务器发送事件（Server-Sent Events，SSE）实现，能显著降低首字延迟（TTFT），改善长回答的体验。

⚙️ 02 · 原理
  1. 1

    客户端在请求中设置 stream 参数，服务端以 text/event-stream 类型保持 HTTP 连接不关闭。

  2. 2

    模型每生成一段内容，服务端就写出一个 SSE 事件，格式为 data: 加 JSON 再加空行。

  3. 3

    事件类型通常包括消息开始、内容增量、工具调用参数增量、用量统计和结束信号。

  4. 4

    客户端逐块解析并拼接增量，实时渲染到界面；工具调用参数需全部拼完后再解析 JSON。

  5. 5

    用户中断时客户端关闭连接或调用 abort，服务端停止生成；中间网关需关闭缓冲才能真正流式。

🔤 03 · 术语
SSE (Server-Sent Events)
基于 HTTP 的单向服务器推送协议，MIME 为 text/event-stream。
首字延迟 (TTFT)
从发送请求到收到第一个 token 的时间。
增量 (Delta)
每个流事件携带的新增内容片段。
背压 (Backpressure)
消费端处理不过来时向生产端施加的流量控制。
AbortController
Web API，用于取消进行中的 fetch 请求与流。
💻 04 · 代码
前端读取 SSE 流typescript
// 假设后端 /api/chat 以 SSE 转发模型输出，每条为 data: {"text": "..."}
const ctrl = new AbortController();
const res = await fetch("/api/chat", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ q: "解释一下 SSE" }),
  signal: ctrl.signal,            // 调用 ctrl.abort() 可中途停止
});

const reader = res.body!.pipeThrough(new TextDecoderStream()).getReader();
let buf = "";
while (true) {
  const { value, done } = await reader.read();
  if (done) break;
  buf += value;
  const events = buf.split("\n\n");   // SSE 事件以空行分隔
  buf = events.pop()!;                // 最后一段可能不完整，留到下次
  for (const ev of events) {
    if (!ev.startsWith("data: ")) continue;
    const payload = ev.slice(6);
    if (payload === "[DONE]") continue;
    output.textContent += JSON.parse(payload).text;
  }
}

演示按空行切分事件和处理半包；POST 请求不能用 EventSource，故用 fetch 读流。

⚖️ 06 · 方案取舍

流式返回

优点首字快，可中途取消

代价错误处理和解析更复杂

适用聊天、长文本生成

非流式返回

优点实现简单，便于整体校验

代价长回答等待久

适用批处理、后台任务、需完整 JSON

流式 + 结构化输出

优点边生成边展示

代价需处理不完整 JSON

适用渐进渲染表单或卡片

🕳️ 07 · 常见坑

  • ✗Nginx 等代理默认缓冲，前端收到一大坨

    ✓关闭代理缓冲，如 proxy_buffering off 或响应头 X-Accel-Buffering: no

  • ✗按网络块直接 JSON.parse，遇半包报错

    ✓维护缓冲区，按事件分隔符切分后再解析

  • ✗流中途出错却只在开头检查状态码

    ✓处理流内的 error 事件和异常断开

  • ✗流式内容先展示再做安全审核

    ✓对敏感场景增量审核，或渲染时做转义与过滤

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么 LLM API 多用 SSE 而非 WebSocket？

LLM 回复是典型的服务器单向推送，SSE 基于普通 HTTP，易穿透代理、复用现有鉴权和负载均衡，协议简单。WebSocket 需要协议升级和额外的连接管理，适合双向实时场景，如语音对话。

流式输出会让总耗时变短吗？

通常不会，模型生成全部 token 的时间基本不变。改善的是首字延迟和感知速度：用户能更早开始阅读，并可在发现方向错误时提前中断，节省时间和 token。

流式下如何处理工具调用？

工具调用的参数也以增量片段到达，客户端需按调用索引累积 JSON 片段，等到该内容块结束事件后再整体解析并执行，不能对半截参数做 JSON.parse。
