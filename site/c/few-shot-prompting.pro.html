少样本提示 (Few-shot)

Few-Shot Prompting

🧸 回到小白版

📐 01 · 定义

少样本提示（Few-Shot Prompting）是在提示中放入少量输入-输出示例，让模型通过上下文学习（In-Context Learning）推断任务格式与规则的技术，属于提示词层，不改变模型权重。它与零样本（Zero-Shot）相对，常用于统一输出格式、对齐分类标准、示范风格，以及说明难以用文字讲清的边界情况。

⚙️ 02 · 原理
  1. 1

    选择与目标任务分布接近的示例，既覆盖典型情况，也覆盖关键边界情况。

  2. 2

    用一致的格式呈现示例，如 XML 标签或固定的“输入/输出”结构，让模型能识别模式。

  3. 3

    在聊天接口中可把示例写成多轮 user/assistant 消息，或集中放进系统提示。

  4. 4

    模型在推理时依据示例中的映射关系续写新输入的输出，示例的格式、长度和标签分布都会被模仿。

  5. 5

    通过评测集对比零样本与不同示例组合的效果，迭代示例的数量、顺序和多样性。

🔤 03 · 术语
上下文学习 (In-Context Learning)
模型仅凭提示中的示例完成新任务，不更新参数。
零样本 (Zero-Shot)
只给任务说明不给示例，依赖模型已有能力。
动态示例选择 (Dynamic Few-Shot)
按与当前输入的相似度从示例库检索最相关的几条。
标签偏置 (Label Bias)
示例中某类标签占比过高，模型倾向输出该类。
近因偏置 (Recency Bias)
模型更受最后几个示例影响的现象。
💻 04 · 代码
用多轮消息提供示例python
from openai import OpenAI

client = OpenAI()
messages = [
    {"role": "system", "content": "把用户反馈分类为 bug / feature / praise，只输出标签。"},
    # 示例：覆盖三类，且包含一个易混边界
    {"role": "user", "content": "点保存按钮没反应"},
    {"role": "assistant", "content": "bug"},
    {"role": "user", "content": "希望能导出 PDF"},
    {"role": "assistant", "content": "feature"},
    {"role": "user", "content": "新界面好用，就是加载慢了点"},
    {"role": "assistant", "content": "bug"},
    {"role": "user", "content": "客服回复很快，赞"},
    {"role": "assistant", "content": "praise"},
    # 真实输入
    {"role": "user", "content": "深色模式什么时候上？"},
]
resp = client.chat.completions.create(model="gpt-4o-mini", messages=messages)
print(resp.choices[0].message.content)

示例写成对话轮次；第三条示范了“夸奖+问题”按 bug 处理的边界规则。模型名可替换。

📊 05 · 参数对比

示例设计要点

维度建议原因
数量常见 3–5 条起步，按评测调整过多增加成本，收益递减
多样性覆盖不同类别和边界避免模型只学到表面特征
标签分布大致均衡或贴近真实分布减少标签偏置
格式与期望输出完全一致格式会被严格模仿
⚖️ 06 · 方案取舍

零样本 + 清晰说明

优点token 少，易维护

代价格式和边界不稳定

适用简单任务、强模型

固定少样本

优点稳定，可复现

代价对分布外输入帮助有限

适用输出格式要求严格

动态检索示例

优点示例与输入最相关

代价需维护示例库和检索

适用类别多、长尾输入多

微调

优点无需每次带示例

代价需数据与训练成本

适用高调用量、模式稳定

🕳️ 07 · 常见坑

  • ✗示例全是简单情况，真实输入一难就错

    ✓有意加入边界和易混样本，并和评测集对齐

  • ✗示例内容被模型照抄进答案

    ✓示例用不同主题，说明它们仅示范格式

  • ✗对推理模型堆大量带解题步骤的示例

    ✓推理模型优先清晰说明目标，少样本按评测决定是否保留

  • ✗示例格式与指令要求互相矛盾

    ✓以示例为准统一检查，模型通常更信示例

🎤 09 · 面试追问
few-shot 为什么有效？

大模型预训练中见过大量“模式-续写”结构，示例在上下文中提供了任务的输入分布、标签空间和输出格式，模型据此推断映射关系。研究表明格式和标签空间的示范作用很大，示例标签是否完全正确的影响有时反而较小。

怎么减少示例顺序带来的偏差？

打乱或轮换示例顺序做评测，看结果方差；保持各类别均衡交错排列；用动态检索选与输入最相似的示例；必要时多次采样投票。顺序敏感本身就是需要通过评测量化的风险。

few-shot 和微调如何取舍？

few-shot 零训练成本、迭代快，但每次调用都付示例的 token，且受窗口限制。调用量大、模式稳定、示例多到放不下时考虑微调。通常先用 few-shot 验证可行性，再用积累的数据决定是否微调。
