HTTP严格传输安全

HSTS

📐 01 · 定义

HTTP 严格传输安全（HTTP Strict Transport Security，HSTS）是 RFC 6797 定义的机制：服务器用 Strict-Transport-Security 响应头告诉浏览器在指定时间内只用 HTTPS 访问该域名。可防御 SSL 剥离等降级攻击，并禁止用户跳过证书错误。

⚙️ 02 · 原理
  1. 1

    浏览器通过 HTTPS 访问网站，收到 Strict-Transport-Security 响应头；通过 HTTP 收到的该头会被忽略。

  2. 2

    浏览器记录该域名为 HSTS 主机，有效期为 max-age 秒，可选 includeSubDomains 覆盖所有子域。

  3. 3

    有效期内，用户输入 http:// 或点击 HTTP 链接，浏览器在本地直接改写为 https://，不发出明文请求。

  4. 4

    若 HTTPS 证书无效，浏览器直接阻断，不提供“继续访问”的选项。

  5. 5

    首次访问前仍有窗口期，可申请加入浏览器内置的 HSTS 预加载列表来消除。

🔤 03 · 术语
max-age
浏览器记住只用 HTTPS 的秒数，设为 0 表示删除该策略。
includeSubDomains
策略同时适用于所有子域名。
preload
表示同意加入浏览器预加载列表，需另行到 hstspreload.org 提交。
SSL 剥离 (SSL Stripping)
中间人把 HTTPS 链接降级为 HTTP 以窃听或篡改。
首次访问信任 (TOFU)
HSTS 依赖首次 HTTPS 响应，首访前无保护。
💻 04 · 代码
Nginx 配置 HSTStext
server {
    listen 80;
    server_name example.com www.example.com;
    return 301 https://$host$request_uri;      # 先把 HTTP 跳转到 HTTPS
}

server {
    listen 443 ssl;
    server_name example.com www.example.com;
    ssl_certificate     /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    # 先用较短 max-age 验证，确认所有子域都支持 HTTPS 后再加长
    add_header Strict-Transport-Security "max-age=300; includeSubDomains" always;

    # 稳定后的目标配置（加入预加载列表的要求之一是 max-age 至少一年）
    # add_header Strict-Transport-Security "max-age=31536000; includeSubDomains; preload" always;
}

always 让错误响应也带上该头；推荐从短 max-age 逐步提高，降低误配风险。

📊 05 · 参数对比

HSTS 推进阶段

阶段配置目的
试运行max-age=300发现不支持 HTTPS 的子域
扩大max-age 逐步提高到一周、一个月观察兼容问题
稳定max-age=31536000; includeSubDomains长期强制 HTTPS
预加载追加 preload 并提交列表消除首访窗口
⚖️ 06 · 方案取舍

仅 HTTP→HTTPS 跳转

优点简单

代价首个明文请求可被劫持

适用过渡期

HSTS + 长 max-age

优点有效防降级

代价首访前仍有窗口

适用所有正式 HTTPS 站点

加入预加载列表

优点首访即受保护

代价移除缓慢，误配代价高

适用确认全域长期支持 HTTPS

🕳️ 07 · 常见坑

  • ✗一上来就设一年 max-age 加 includeSubDomains

    ✓先短期验证所有子域支持 HTTPS，再逐步加长

  • ✗内网或旧系统子域只支持 HTTP 却被覆盖

    ✓排查全部子域，或暂不启用 includeSubDomains

  • ✗以为加了 preload 指令就已进入列表

    ✓需到 hstspreload.org 提交并满足全部要求

  • ✗在 HTTP 响应中下发 HSTS 头

    ✓浏览器只认 HTTPS 响应中的 HSTS 头

☑️ 08 · 检查清单
🎤 09 · 面试追问
已经有 HTTP 到 HTTPS 的 301 跳转，为什么还要 HSTS？

跳转发生前，用户的首个请求仍是明文 HTTP，中间人可拦截并阻止跳转，把用户留在 HTTP 上（SSL 剥离）。HSTS 让浏览器在本地把后续请求直接改写为 HTTPS，不再发出明文请求，从而堵住这个窗口。

HSTS 预加载有什么风险？

预加载列表硬编码在浏览器中，域名及其全部子域将被强制 HTTPS。若之后某个子域需要 HTTP，或想撤出列表，移除需要随浏览器版本更新逐步生效，周期较长。因此只有在确定长期全域 HTTPS 时才应申请。

HSTS 如何影响证书错误处理？

对 HSTS 主机，证书无效时浏览器会硬性阻断，用户无法点击继续访问。这能防止用户被训练成忽略警告，但也意味着证书过期会让网站对所有用户直接不可用，所以必须配合可靠的自动续期和监控。
