KV 缓存 (KV Cache)

KV Cache

📐 01 · 定义

KV 缓存（KV Cache）是 Transformer 自回归推理中的优化：把已处理 token 在每层注意力中计算出的 Key 与 Value 张量保存在显存里，生成新 token 时只为新 token 计算 Q/K/V 并与缓存做注意力，避免对整个前缀重复计算。它属于模型推理层，是解码速度、显存占用与并发能力的核心约束。

⚙️ 02 · 原理
  1. 1

    预填充（Prefill）阶段：并行处理整段输入提示，为每层生成并缓存所有 token 的 K、V。

  2. 2

    解码（Decode）阶段：每步只为最新 token 计算 Q、K、V，把新 K、V 追加进缓存。

  3. 3

    新 token 的 Q 与缓存中全部 K 做点积得到注意力权重，再加权 V，复杂度从重算前缀降为与长度线性相关。

  4. 4

    缓存大小约为 2 × 层数 × KV 头数 × 头维度 × 序列长度 × 批大小 × 每元素字节数，随上下文与并发线性增长。

  5. 5

    推理引擎通过分页管理（PagedAttention）、前缀共享、KV 量化与 GQA 等结构降低缓存占用。

🔤 03 · 术语
预填充 (Prefill)
一次性处理输入提示并建立 KV 缓存的阶段，偏计算密集。
解码 (Decode)
逐 token 生成的阶段，通常受显存带宽限制。
分组查询注意力 (GQA)
多个查询头共享一组 K/V 头，按比例减小 KV 缓存。
PagedAttention
vLLM 提出的按块分页管理 KV 缓存的方法，减少显存碎片。
前缀缓存 (Prefix Caching)
相同提示前缀的 KV 缓存在请求间复用，降低 TTFT。
💻 04 · 代码
估算 KV 缓存显存占用python
def kv_cache_bytes(layers, kv_heads, head_dim, seq_len, batch=1, bytes_per_elem=2):
    """2 代表 K 和 V 两份；bytes_per_elem=2 对应 FP16/BF16"""
    return 2 * layers * kv_heads * head_dim * seq_len * batch * bytes_per_elem

# 以 Llama-3-8B 的公开配置为例：32 层、8 个 KV 头（GQA）、头维度 128
cfg = dict(layers=32, kv_heads=8, head_dim=128)

for seq in (4_096, 32_768, 131_072):
    gib = kv_cache_bytes(**cfg, seq_len=seq) / 1024**3
    print(f"单请求 {seq:>7} tokens: {gib:.2f} GiB")

# 若不用 GQA（32 个 KV 头），缓存会是上面的 4 倍
# 并发 batch 个请求时再乘以 batch

按公式可见：上下文和并发都会线性放大 KV 缓存，GQA 通过减少 KV 头来压缩。

📊 05 · 参数对比

降低 KV 缓存占用的手段

手段原理代价
GQA / MQA多个查询头共享 K/V 头需在模型架构阶段决定
PagedAttention按块分配，减少碎片浪费需引擎支持
KV 缓存量化（如 FP8）降低每元素字节数可能轻微影响质量
前缀缓存相同前缀只存一份仅对重复前缀有效
限制最大上下文直接限制序列长度长文档能力受限
⚖️ 06 · 方案取舍

为长上下文预留大量 KV 显存

优点支持长文档与长对话

代价并发数下降，单卡吞吐降低

适用长文档问答、代码库分析

限制上下文、提高并发

优点吞吐高、成本低

代价长输入需截断或分段

适用短对话客服、分类任务

KV 缓存量化

优点同显存下容纳更多 token

代价需验证质量影响

适用显存紧张的自部署

🕳️ 07 · 常见坑

  • ✗只按模型权重大小估算显存，忘了 KV 缓存

    ✓按目标上下文长度与并发数计算 KV 缓存并预留余量

  • ✗把 max-model-len 设到模型上限却无需求

    ✓按实际业务长度设置，释放显存给并发

  • ✗动态内容放在提示开头，前缀缓存始终失效

    ✓固定内容（系统提示、工具定义）放前面，变化部分放后面

  • ✗以为 KV 缓存能跨会话长期记忆

    ✓它只服务于单次推理序列，持久记忆需另行存储

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么解码阶段通常受显存带宽限制？

每生成一个 token 都要读取全部模型权重和该序列的 KV 缓存，而计算量相对较小，算术强度低，瓶颈在从显存搬运数据的速度，而不是算力。

GQA 如何减少 KV 缓存？

标准多头注意力每个查询头都有独立 K/V；GQA 让一组查询头共享一对 K/V 头，KV 头数减少为原来的若干分之一，缓存按相同比例缩小，质量通常接近多头注意力。

提示缓存（Prompt Caching）和 KV 缓存什么关系？

API 厂商的提示缓存本质是在请求之间复用相同前缀的 KV 缓存，跳过这部分预填充，从而降低延迟和输入费用。前缀必须完全一致才能命中。
