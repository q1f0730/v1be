平台工程 (内部开发者平台)

Platform Engineering

📐 01 · 定义

平台工程（Platform Engineering）是构建和运营内部开发者平台（IDP）的工程实践：把基础设施、CI/CD、可观测性、安全合规等能力封装为自助服务和标准化「黄金路径」，以产品思维服务内部开发者，降低认知负担，提升交付速度与一致性。它通常由专门的平台团队负责。

⚙️ 02 · 原理
  1. 1

    调研开发者在交付链路上的高频痛点，如新建服务、申请资源、配置流水线、查看日志。

  2. 2

    把这些能力整合成平台接口：门户、CLI、API 或 GitOps 仓库，底层对接 Kubernetes、云资源与 CI。

  3. 3

    提供黄金路径模板：新服务一键生成仓库、流水线、监控、告警与安全基线。

  4. 4

    通过服务目录登记所有权、依赖与文档，用记分卡衡量各服务是否满足标准。

  5. 5

    以产品方式运营：度量采用率、开发者满意度和交付指标，持续迭代，而非强制推行。

🔤 03 · 术语
内部开发者平台 (IDP)
面向内部开发者的自助能力集合，屏蔽底层基础设施复杂度。
黄金路径 (Golden Path)
平台推荐且全面支持的标准做法，可选而非强制。
最薄可行平台 (TVP)
Team Topologies 提出的理念：平台只做到足以加速团队的最小程度。
Backstage
Spotify 开源、CNCF 托管的开发者门户框架，含服务目录与软件模板。
DORA 指标
部署频率、变更前置时间、变更失败率、恢复时间等交付效能指标。
💻 04 · 代码
Backstage 服务目录登记yaml
# catalog-info.yaml：放在服务仓库根目录，被 Backstage 目录收录
apiVersion: backstage.io/v1alpha1
kind: Component
metadata:
  name: payments-service
  description: 支付下单与回调处理
  annotations:
    github.com/project-slug: acme/payments-service
    backstage.io/techdocs-ref: dir:.
  tags: [python, grpc]
spec:
  type: service
  lifecycle: production
  owner: team-payments          # 所有权明确，告警与工单有人认领
  system: checkout
  providesApis:
    - payments-api
  dependsOn:
    - resource:payments-db

服务目录是平台的基础数据：模板、记分卡、文档和告警路由都依赖准确的所有权与依赖信息。

📊 05 · 参数对比

DevOps、SRE 与平台工程

实践核心目标主要产出
DevOps打通开发与运维的文化与流程CI/CD、协作方式
SRE用工程方法保障可靠性SLO、错误预算、事故流程
平台工程降低开发者认知负担、自助交付内部开发者平台与黄金路径
⚖️ 06 · 方案取舍

自建门户（如 Backstage）

优点可深度定制，插件生态丰富

代价需要前端与插件维护投入

适用工程团队规模较大、工具链多样

商业 IDP 产品

优点上线快，维护负担小

代价订阅成本，定制受限

适用希望快速见效的中型团队

模板仓库 + 文档

优点成本最低，立刻可用

代价缺乏统一入口与度量

适用团队小、服务数量少的起步期

🕳️ 07 · 常见坑

  • ✗先建大平台，再找用户

    ✓从一两个高频痛点做起，用最薄可行平台验证价值

  • ✗强制所有团队迁移，忽视特殊需求

    ✓黄金路径可选且最省力，保留有支持的例外通道

  • ✗平台变成新的工单队列

    ✓能力以 API 和自助方式提供，平台团队不做人工中转

  • ✗没有度量，无法证明平台价值

    ✓跟踪采用率、DORA 指标与开发者满意度

🎤 09 · 面试追问
平台工程和传统运维团队的区别？

传统运维通过工单替开发者执行操作，平台工程把能力产品化为自助服务。平台团队把开发者当用户，关注体验与采用率，通过黄金路径让正确做法成为最省力的做法，而不是靠审批和人力把关。

如何衡量内部开发者平台是否成功？

看结果而非功能数量：新服务从零到上线的时间、DORA 指标变化、平台能力的采用率、自助完成比例、开发者满意度调查，以及工单数量是否下降。结合定性访谈找出仍然绕开平台的原因。

AI 编码助手对平台工程有什么影响？

Agent 能快速生成代码，但部署、权限与合规仍是瓶颈。平台提供标准化模板、API 和策略检查后，Agent 可以按黄金路径自助创建服务与预览环境，平台规则也能作为 Agent 的上下文，减少生成不合规配置。
