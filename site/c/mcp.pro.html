模型上下文协议 (MCP)

MCP

📐 01 · 定义

模型上下文协议（Model Context Protocol，MCP）是 Anthropic 于 2024 年发布的开放协议，用统一接口把 AI 应用连接到外部工具和数据源。它基于 JSON-RPC 2.0 的客户端-服务器架构：服务器实现一次，即可被 Claude Code、Cursor 等多个宿主复用。

⚙️ 02 · 原理
  1. 1

    宿主（Host）为每个服务器创建一个 MCP 客户端，与服务器建立一对一连接。

  2. 2

    连接后先执行 initialize 握手，双方交换协议版本和各自支持的能力（capabilities）。

  3. 3

    服务器可暴露三类原语：Tools（可执行动作）、Resources（可读数据）、Prompts（提示模板）。

  4. 4

    客户端通过 tools/list 等方法发现能力，宿主把工具交给模型，模型发起调用后经 tools/call 执行。

  5. 5

    传输层支持 stdio（本地子进程）和 Streamable HTTP（远程服务），远程场景使用基于 OAuth 的授权。

🔤 03 · 术语
宿主 (Host)
运行模型并管理 MCP 客户端的应用，如 Claude Desktop、IDE。
JSON-RPC 2.0
MCP 使用的轻量远程调用消息格式，含请求、响应和通知。
stdio 传输
宿主以子进程启动服务器，通过标准输入输出交换消息。
Streamable HTTP
MCP 的远程传输方式，基于 HTTP，可选用 SSE 流式返回。
能力协商 (Capability Negotiation)
初始化时双方声明支持的功能，后续只使用共同支持的。
💻 04 · 代码
用 Python 写 MCP 服务器python
# pip install "mcp[cli]"
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("notes")
NOTES = {"todo": "写周报；修复登录 bug"}

@mcp.tool()
def add_note(name: str, text: str) -> str:
    """新建或覆盖一条笔记"""
    NOTES[name] = text
    return f"saved {name}"

@mcp.resource("notes://{name}")
def read_note(name: str) -> str:
    """按名称读取笔记内容"""
    return NOTES.get(name, "")

if __name__ == "__main__":
    mcp.run()          # 默认 stdio 传输

签名与 docstring 自动生成 schema；可用 claude mcp add 注册到 Claude Code。

📊 05 · 参数对比

MCP 三类服务器原语

原语控制方用途
Tools模型决定调用执行动作，如查库、发请求
Resources应用决定读取提供文件、记录等上下文数据
Prompts用户选择触发预置的提示模板或工作流
⚖️ 06 · 方案取舍

使用 MCP 服务器

优点一次实现多宿主复用，生态现成

代价多一层进程和协议

适用工具需在多个 AI 应用中共享

直接写函数调用

优点简单、延迟低

代价与单个应用绑定

适用只在自家应用内使用

远程 MCP

优点集中部署、统一授权

代价需处理鉴权与网络安全

适用团队或 SaaS 对外提供

🕳️ 07 · 常见坑

  • ✗随手安装来源不明的 MCP 服务器

    ✓只用可信来源，审查代码与权限，本地服务器有完整执行权限

  • ✗一次接入几十个服务器，工具清单爆炸

    ✓按项目启用必要服务器，减少工具描述占用的上下文

  • ✗工具描述或返回中混入隐藏指令

    ✓把工具输出当不可信数据，高风险操作需人工确认

  • ✗stdio 服务器往 stdout 打日志

    ✓stdout 只用于协议消息，日志写到 stderr

🎤 09 · 面试追问
MCP 和普通函数调用是什么关系？

函数调用是模型 API 层的能力：模型输出调用请求。MCP 是应用与工具之间的协议层：标准化工具如何被发现、描述和调用。宿主通过 MCP 拿到工具列表后，仍然借助模型的函数调用能力让模型决定何时调用。

MCP 解决了什么问题？

解决 M 个 AI 应用 × N 个工具的集成爆炸：过去每个应用要为每个工具单独写适配，有了 MCP，工具方实现一个服务器，所有支持 MCP 的宿主都能接入，问题从 M×N 降为 M+N。

MCP 的主要安全风险是什么？

本地服务器以用户权限运行，可读写文件和执行命令；工具描述和返回内容可能携带提示注入；多服务器组合可能导致数据外泄。对策是来源审查、最小权限、沙箱、操作确认，并把所有工具输出视为不可信。
