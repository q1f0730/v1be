数据库模式迁移

Database Migrations

🧸 回到小白版

📐 01 · 定义

数据库模式迁移（Schema Migration）是把表结构、索引、约束等变更写成有序、可版本控制的脚本，由迁移工具按顺序执行并记录已应用版本。它位于应用与数据库之间的发布流程层，解决多环境结构一致、变更可追溯、可重复部署的问题。

⚙️ 02 · 原理
  1. 1

    每次结构变更生成一个带序号或时间戳的迁移文件，包含 up（应用）与可选的 down（回退）逻辑。

  2. 2

    迁移工具在数据库中维护一张版本表（如 schema_migrations），记录已执行的迁移 ID。

  3. 3

    部署时工具比对代码中的迁移与版本表，按顺序执行尚未应用的迁移，并写入记录。

  4. 4

    多数工具会加锁（如 advisory lock）防止多个实例并发执行同一批迁移。

  5. 5

    大表变更需拆为扩展—迁移数据—收缩多步，配合应用发布实现零停机。

🔤 03 · 术语
扩展-收缩 (Expand/Contract)
先加新结构兼容新旧代码，切流后再删旧结构的零停机模式。
版本表 (Migration Table)
数据库内记录已执行迁移 ID 与时间的元数据表。
DDL 事务性 (Transactional DDL)
DDL 能否在事务内回滚；PostgreSQL 支持，MySQL 大多不支持。
在线 DDL (Online DDL)
不长时间锁表的结构变更方式，如 CREATE INDEX CONCURRENTLY。
数据回填 (Backfill)
为新列或新表批量补齐历史数据的过程，通常分批执行。
💻 04 · 代码
零停机重命名列（分步）sql
-- 迁移 0012：扩展——新增列，允许为空，不阻塞旧代码
ALTER TABLE users ADD COLUMN display_name text;

-- 迁移 0013：回填——分批更新，避免长事务与锁
UPDATE users SET display_name = nickname
WHERE id IN (
  SELECT id FROM users
  WHERE display_name IS NULL
  LIMIT 5000
);  -- 由脚本循环执行直到影响行数为 0

-- 此时发布应用：双写 nickname 与 display_name，读新列

-- 迁移 0014：收缩——确认无代码读旧列后再删除
ALTER TABLE users DROP COLUMN nickname;

-- PostgreSQL 建索引不锁写（不能放在事务块内）
CREATE INDEX CONCURRENTLY idx_users_display_name
  ON users (display_name);

直接 RENAME COLUMN 会让正在运行的旧版本报错；拆成三步可与滚动发布兼容。

⚖️ 06 · 方案取舍

手写 SQL 迁移

优点完全可控，能用数据库专有特性

代价工作量大，易漏写回退

适用复杂变更、大表、性能敏感

ORM 自动生成迁移

优点快，与模型定义保持同步

代价可能生成锁表或删列的危险语句

适用早期项目，生成后人工审查

声明式 schema diff

优点只描述目标状态，工具算差异

代价重命名等意图难识别，可能误删

适用团队熟悉工具且有审查流程

🕳️ 07 · 常见坑

  • ✗修改已在生产执行过的迁移文件

    ✓已发布迁移视为不可变，修正应新增一个迁移

  • ✗在同一迁移里加 NOT NULL 列并大表回填

    ✓先加可空列，分批回填，最后再加约束

  • ✗依赖 down 迁移做生产回滚，删列后数据已丢

    ✓以前向修复为主，破坏性变更延后并先备份

  • ✗让 AI 直接改 schema 并在生产 push，跳过迁移文件

    ✓要求生成迁移文件并走审查，生产只通过 CI 执行迁移

🎤 09 · 面试追问
如何做到加 NOT NULL 列零停机？

分步：先加可空列（或带默认值，新版本 PostgreSQL 加常量默认值不重写表）；应用开始写新列；分批回填历史数据；最后加 NOT NULL 约束，PostgreSQL 可先加 CHECK … NOT VALID 再 VALIDATE 降低锁影响。

迁移应在应用启动时执行还是单独步骤？

多实例环境建议作为部署流水线中的独立步骤，避免多个实例竞争、启动超时和失败时应用不可用。若在启动时执行，必须有分布式锁且迁移足够快。

down 迁移有必要写吗？

开发环境有用，便于来回切换。生产中删除列或表的回退无法恢复数据，实践上多采用前向修复（roll forward），并让每一步迁移本身向后兼容。
