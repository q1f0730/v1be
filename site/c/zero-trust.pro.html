零信任架构

Zero Trust

🧸 回到小白版

📐 01 · 定义

零信任（Zero Trust）是一种安全架构理念：不因网络位置（如处于内网或 VPN 中）而默认信任任何用户、设备或服务，每次访问资源都基于身份、设备状态和上下文进行显式认证与授权，并遵循最小权限、假定已被入侵。NIST SP 800-207（2020）给出了参考架构，Google BeyondCorp 是早期大规模实践。

⚙️ 02 · 原理
  1. 1

    身份为中心：所有用户与工作负载都有强身份，使用 SSO 与多因素认证，服务之间使用证书或工作负载身份。

  2. 2

    每个访问请求经过策略执行点（PEP），由策略引擎（PE）结合身份、设备合规、位置、风险信号实时决策。

  3. 3

    授权按资源粒度、最小权限授予，会话短期有效并持续评估，风险变化时可重新认证或撤销。

  4. 4

    网络微分段：默认拒绝东西向流量，仅允许明确声明的服务间通信，限制攻击者横向移动。

  5. 5

    全面记录与监控访问日志，把检测结果反馈给策略引擎，形成持续改进的闭环。

🔤 03 · 术语
策略引擎/执行点 (PE/PEP)
NIST 800-207 中做出访问决策与执行决策的组件。
ZTNA
零信任网络访问，按应用粒度代理访问，替代把用户接入整个内网的 VPN。
设备态势 (Device Posture)
设备的补丁、加密、管控状态等，作为访问决策的输入。
微分段 (Micro-segmentation)
按工作负载细粒度划分网络访问边界，默认拒绝。
假定入侵 (Assume Breach)
设计时默认攻击者已在内部，以限制影响范围为目标。
💻 04 · 代码
K8s 默认拒绝 + 显式放行yaml
# 1) 命名空间内默认拒绝所有入站流量（需 CNI 支持 NetworkPolicy）
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-ingress
  namespace: shop
spec:
  podSelector: {}
  policyTypes: [Ingress]
---
# 2) 只允许 frontend 访问 api 的 8080 端口
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-frontend-to-api
  namespace: shop
spec:
  podSelector:
    matchLabels: { app: api }
  policyTypes: [Ingress]
  ingress:
    - from:
        - podSelector:
            matchLabels: { app: frontend }
      ports:
        - { protocol: TCP, port: 8080 }

网络策略只解决微分段这一层；还需服务身份（如 mTLS）与应用层授权共同构成零信任。

⚖️ 06 · 方案取舍

身份感知代理/ZTNA

优点按应用授权，用户无需接入整个内网

代价需改造访问入口与身份体系

适用替代传统 VPN、远程办公

服务网格 mTLS + 授权策略

优点服务间身份与加密自动化

代价引入网格的运维复杂度

适用微服务较多的 Kubernetes 环境

传统边界防护 + VPN

优点部署简单，存量广泛

代价一点失守即可横向移动

适用过渡期，逐步迁移

🕳️ 07 · 常见坑

  • ✗把零信任当成购买某个产品

    ✓从身份、设备、网络、应用、数据逐项评估成熟度并分阶段推进

  • ✗认证一次后长期信任会话

    ✓短会话加持续评估，风险变化时重新认证

  • ✗只管用户访问，忽视服务间与 CI 等机器身份

    ✓为工作负载签发短期身份并做授权

  • ✗微分段策略一步到位，导致业务中断

    ✓先观察流量生成基线，再以审计模式逐步收紧

🎤 09 · 面试追问
零信任和传统边界安全的核心区别？

边界安全假设内网可信，重点防外部进入，一旦突破即可横向移动。零信任取消基于位置的默认信任，每次访问都显式验证身份、设备与上下文，按最小权限授权，并假定已被入侵，以限制爆炸半径为设计目标。

如何在一家中型公司落地零信任？

先盘点身份与资产，统一 SSO 并强制 MFA；把内部应用置于身份感知代理之后，逐步替代 VPN；对服务间通信启用 mTLS 与授权策略；网络上从观察流量开始逐步微分段；建立集中日志与告警。按成熟度模型分阶段推进。

AI Agent 在零信任中如何处理？

把 Agent 当作独立的工作负载身份，而不是借用开发者的长期凭证；按任务授予最小、短期的权限；所有工具调用经过策略检查与审计；高风险操作要求人工确认。Agent 输入来源不可信，更要坚持每次显式授权。
