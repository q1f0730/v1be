显存 (VRAM)

GPU VRAM

📐 01 · 定义

显存（VRAM）是 GPU 板载的高带宽内存，LLM 推理时需容纳模型权重、KV Cache、激活值与框架开销。它是本地与自建推理的首要约束：决定可运行的模型规模、量化精度、上下文长度与并发数。显存带宽同样关键，解码阶段速度往往受限于读取权重的带宽。

⚙️ 02 · 原理
  1. 1

    权重占用 ≈ 参数量 × 每参数字节数：FP16/BF16 为 2 字节，INT8 约 1 字节，4-bit 约 0.5 字节（另有少量量化元数据）。

  2. 2

    KV Cache 每 Token 占用 ≈ 2 × 层数 × KV 头数 × 头维度 × 字节数，随上下文长度与并发线性增长。

  3. 3

    激活值、CUDA 上下文与推理引擎预分配也需要空间；vLLM 等会按比例预留显存给 KV Cache。

  4. 4

    显存不足时可量化、换小模型、缩短上下文、降低并发，或把部分层卸载到 CPU（速度显著下降）。

  5. 5

    多卡可用张量并行切分权重；Apple 芯片等统一内存架构由 CPU 与 GPU 共享内存。

🔤 03 · 术语
KV Cache
缓存已处理 Token 的 Key/Value，避免重复计算，占用随上下文增长。
GQA (Grouped-Query Attention)
多个查询头共享 KV 头，显著减少 KV Cache 占用。
显存带宽 (Memory Bandwidth)
每秒可读写的数据量，常是解码速度瓶颈。
CPU 卸载 (Offloading)
把部分层放到内存由 CPU 计算，能跑但更慢。
OOM (Out of Memory)
显存分配失败，进程报错退出。
💻 04 · 代码
估算推理所需显存python
def estimate_vram_gb(params_b, bytes_per_param, layers, kv_heads,
                     head_dim, ctx_len, batch=1, kv_bytes=2, overhead=1.2):
    """粗略估算：权重 + KV Cache，再乘开销系数"""
    weights = params_b * 1e9 * bytes_per_param
    # 每个 Token 的 KV：K 和 V 两份 × 层数 × KV 头数 × 头维度 × 字节数
    kv_per_token = 2 * layers * kv_heads * head_dim * kv_bytes
    kv_total = kv_per_token * ctx_len * batch
    return (weights + kv_total) * overhead / 1024**3

# 以 Llama 3 8B 的公开配置为例：32 层、8 个 KV 头、头维度 128
for name, bpp in [("BF16", 2), ("INT8", 1), ("4-bit", 0.5)]:
    gb = estimate_vram_gb(8, bpp, layers=32, kv_heads=8,
                          head_dim=128, ctx_len=8192)
    print(f"{name}: 约 {gb:.1f} GB")

# 实际占用用 nvidia-smi 查看：
#   nvidia-smi --query-gpu=memory.used,memory.total --format=csv

该配置下每 Token KV 为 128 KiB，8K 上下文约 1 GiB；开销系数是经验假设，需实测校准。

⚖️ 06 · 方案取舍

高精度 (BF16)

优点效果最接近原模型

代价显存需求最大

适用显存充足、追求质量

4-bit 量化

优点权重约降为 1/4，可上消费卡

代价有精度损失，部分任务明显

适用本地运行、资源受限

CPU/内存卸载

优点小显存也能跑大模型

代价速度显著下降

适用偶尔使用、可容忍慢

🕳️ 07 · 常见坑

  • ✗只按权重估算显存，长上下文时 OOM

    ✓把 KV Cache 按最大上下文与并发计入预算

  • ✗忽略显存带宽，只看容量选卡

    ✓解码速度主要看带宽，同时比较容量与带宽

  • ✗同机其他进程占着显存不自知

    ✓部署前用 nvidia-smi 检查已用显存

  • ✗推理引擎默认预占大部分显存，与其他服务冲突

    ✓调整引擎的显存占用比例参数

🎤 09 · 面试追问
为什么长上下文推理显存会暴涨？

KV Cache 与上下文长度和并发数成正比：每个 Token 在每层都要缓存 K 和 V。长上下文或高并发下 KV Cache 可超过权重本身。缓解手段有 GQA/MQA、KV 量化、分页式 KV 管理、限制最大长度与前缀共享。

解码阶段为什么常被称为带宽受限？

单请求自回归解码每生成一个 Token 都要读取全部权重，计算量相对数据搬运很小，瓶颈在显存带宽。因此批处理多个请求能提升吞吐，量化减少读取字节也能提速。

24 GB 显卡能否跑 32B 模型？

BF16 权重约 64 GB，不行；4-bit 量化权重约 16 GB 出头，加上 KV Cache 与开销，短上下文下可能勉强可行，长上下文需进一步压缩或卸载。最终以实测为准。
