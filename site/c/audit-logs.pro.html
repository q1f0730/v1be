审计日志

Audit Logs

📐 01 · 定义

审计日志（Audit Log）是对安全与业务关键操作的不可篡改、按时间顺序的记录，回答「谁（主体）在何时、从哪里、对什么对象、做了什么、结果如何」。它属于安全治理与合规层，服务于事件调查、责任追溯、合规审计（如 SOC 2、ISO 27001）以及企业客户的自助审计需求，与面向排障的应用日志目的不同。

⚙️ 02 · 原理
  1. 1

    定义需审计的事件：登录与认证变更、权限与角色修改、敏感数据访问与导出、配置变更、删除操作。

  2. 2

    为每个事件记录结构化字段：时间、操作者（含 API Key/服务账号）、来源 IP、动作、目标资源、结果、请求 ID。

  3. 3

    写入与业务数据分离的仅追加存储，应用账号只有插入权限，不能更新或删除。

  4. 4

    通过哈希链、WORM 存储（如对象锁）或外部日志服务增强防篡改能力，并按合规要求设定保留期。

  5. 5

    提供检索、导出与告警：异常行为（批量导出、非工作时间提权）触发通知，企业客户可在后台查询。

🔤 03 · 术语
审计追踪 (Audit Trail)
按时间顺序串联的操作记录，可还原事件经过。
仅追加 (Append-only)
只允许新增记录，不允许修改或删除。
WORM (Write Once Read Many)
写入后不可改写的存储模式，如 S3 Object Lock。
哈希链 (Hash Chain)
每条记录包含前一条的哈希，篡改会破坏链条。
不可抵赖性 (Non-repudiation)
操作者无法否认其执行过的操作。
💻 04 · 代码
PostgreSQL 仅追加审计表sql
CREATE TABLE audit_log (
  id          bigserial PRIMARY KEY,
  occurred_at timestamptz NOT NULL DEFAULT now(),
  actor_id    text NOT NULL,          -- 用户、服务账号或 API Key ID
  actor_ip    inet,
  action      text NOT NULL,          -- 如 'user.role.update'
  target      text NOT NULL,          -- 如 'user:42'
  result      text NOT NULL,          -- 'success' | 'denied'
  metadata    jsonb,                  -- 变更前后差异等（勿写入密码与密钥）
  request_id  text
);
CREATE INDEX ON audit_log (target, occurred_at);

-- 应用账号只能插入和查询，不能改删
REVOKE ALL ON audit_log FROM app_user;
GRANT INSERT, SELECT ON audit_log TO app_user;
GRANT USAGE ON SEQUENCE audit_log_id_seq TO app_user;

INSERT INTO audit_log (actor_id, actor_ip, action, target, result, metadata, request_id)
VALUES ('u_7', '203.0.113.5', 'user.role.update', 'user:42', 'success',
        '{"from":"member","to":"admin"}', 'req_abc');

权限层面禁止改删；更高要求可同步到 WORM 存储或独立日志服务，防数据库管理员篡改。

📊 05 · 参数对比

审计日志与相关日志对比

类型目的保留与完整性
审计日志追责、合规、安全调查长期保留，防篡改
应用日志排查故障短期保留，可轮转清理
访问日志流量分析、安全检测中短期，量大
变更数据捕获数据同步不面向追责，无操作者上下文
⚖️ 06 · 方案取舍

数据库内审计表

优点实现简单，可与业务事务一起写入

代价DBA 仍可篡改，影响主库容量

适用早期产品

独立日志/SIEM 服务

优点集中检索与告警，权限隔离

代价费用，需可靠投递

适用有安全团队与合规要求

WORM 对象存储归档

优点强防篡改，存储便宜

代价查询不便

适用长期合规保留

🕳️ 07 · 常见坑

  • ✗审计记录与业务数据同库同权限，可被任意修改

    ✓仅追加权限，关键环境同步到独立的防篡改存储

  • ✗把密码、令牌或完整 PII 写进审计元数据

    ✓记录变更字段名与脱敏后的值，不记录秘密

  • ✗只记录成功操作，忽略被拒绝的尝试

    ✓失败与拒绝同样记录，它们常是攻击信号

  • ✗服务账号、API Key 操作没有可追溯的操作者

    ✓为每个自动化主体分配独立身份并记录

☑️ 08 · 检查清单
🎤 09 · 面试追问
审计日志应记录哪些字段？

至少包括时间（统一时区）、操作者及其类型、认证方式、来源 IP/设备、动作、目标资源、结果（成功/拒绝）、请求或关联 ID；变更类操作记录前后差异，敏感值脱敏。

如何证明审计日志没有被篡改？

权限上仅追加；写入 WORM 存储；对记录做哈希链或定期把批次摘要签名并锚定到外部系统；访问和导出审计日志本身也要记录，形成二级审计。

AI Agent 代用户执行操作时审计要注意什么？

同时记录代表的用户与执行的 Agent/工具身份、触发的提示或任务 ID、调用的工具与参数摘要，以便区分人工操作与自动操作并追溯决策链。
