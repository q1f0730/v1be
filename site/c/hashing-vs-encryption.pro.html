哈希与加密的分野

Hashing vs Encryption

📐 01 · 定义

哈希（Hashing）是把任意数据映射为固定长度摘要的单向函数，无法从摘要还原原文；加密（Encryption）是用密钥把明文变成密文的可逆变换，持有密钥即可解密。二者同属密码学基础层，但用途截然不同：哈希用于完整性校验和密码存储，加密用于保密传输和存储需要还原的数据。

⚙️ 02 · 原理
  1. 1

    哈希：同一输入始终得到同一摘要，输入微小变化导致摘要大幅变化，且难以找到碰撞。

  2. 2

    密码存储使用专门的慢哈希（Argon2、bcrypt、scrypt）并加盐，提高暴力破解成本。

  3. 3

    对称加密（如 AES-GCM）用同一密钥加解密，速度快，适合大量数据。

  4. 4

    非对称加密用公钥加密、私钥解密，常用于密钥交换与数字签名，TLS 结合两者使用。

  5. 5

    HMAC 结合哈希与密钥生成消息认证码，可同时验证完整性和来源。

🔤 03 · 术语
SHA-256
SHA-2 家族的通用哈希函数，输出 256 位，速度快。
AES-GCM
带认证的对称加密模式，同时提供保密性和完整性。
HMAC
基于哈希和密钥的消息认证码，用于签名校验。
Nonce/IV
加密时使用的一次性随机数，同一密钥下不得重复。
编码 (Encoding)
如 Base64，只是格式转换，无任何安全性。
💻 04 · 代码
哈希、HMAC 与加密对比python
import hashlib, hmac, os
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

data = b"order:1024:paid"

# 1. 哈希：单向，用于完整性校验（文件校验和等）
print(hashlib.sha256(data).hexdigest())

# 2. HMAC：带密钥的哈希，验证消息未被篡改且来自持钥方
key = os.urandom(32)
tag = hmac.new(key, data, hashlib.sha256).digest()
print(hmac.compare_digest(tag, hmac.new(key, data, hashlib.sha256).digest()))

# 3. 对称加密：可逆，持有密钥才能解密
aes_key = AESGCM.generate_key(bit_length=256)
nonce = os.urandom(12)                 # 同一密钥下 nonce 绝不能重复
ct = AESGCM(aes_key).encrypt(nonce, data, None)
print(AESGCM(aes_key).decrypt(nonce, ct, None))   # b'order:1024:paid'

# 注意：密码存储不要用 sha256，应使用 argon2/bcrypt 等慢哈希

依赖 cryptography 库；三段代码分别对应完整性、来源认证和保密性。

🕳️ 07 · 常见坑

  • ✗用 SHA-256 或 MD5 直接存密码

    ✓使用 Argon2id、bcrypt 或 scrypt 并加盐

  • ✗把 Base64 当成加密

    ✓Base64 只是编码，敏感数据需真正加密

  • ✗加密密钥与密文存放在同一数据库

    ✓密钥放密钥管理服务，与数据分离

  • ✗自己设计加密算法或模式

    ✓使用成熟库的高层 API，如 AES-GCM、libsodium

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么密码要哈希而不是加密？

系统只需验证用户输入的密码是否正确，不需要知道原文。加密意味着存在能还原所有密码的密钥，密钥一旦泄露所有密码暴露。慢哈希加盐后即使数据库泄露，攻击者也只能逐个高成本暴力猜测。

为什么不能用 SHA-256 存密码？

SHA-256 设计目标是快，GPU 每秒可计算海量次，对低熵的人类密码可快速字典攻击。Argon2、bcrypt 等专门设计为可调节的慢，Argon2 还消耗大量内存，使 GPU/ASIC 并行破解成本大幅上升。

HMAC 和普通哈希的区别？

普通哈希任何人都能计算，攻击者篡改数据后可重新计算哈希；HMAC 需要密钥，只有持钥方能生成有效标签，因此能同时证明完整性和来源。Webhook 签名、Cookie 签名常用 HMAC，比较时需用恒定时间函数防时序攻击。
