网络防火墙与WAF

Firewalls

📐 01 · 定义

防火墙是依据规则允许或阻止网络流量的控制点。传统网络防火墙工作在三、四层，按 IP、端口、协议和连接状态过滤；Web 应用防火墙（WAF）工作在七层，检查 HTTP 请求内容，防御 SQL 注入、XSS 和恶意爬虫等。两者位置与能力不同，常组合成纵深防御。

⚙️ 02 · 原理
  1. 1

    流量到达防火墙后按规则顺序匹配，命中即执行允许、拒绝或记录。

  2. 2

    有状态防火墙跟踪连接，已建立连接的回包自动放行，只需写发起方向规则。

  3. 3

    默认策略应为拒绝（default deny），只显式放行业务需要的端口与来源。

  4. 4

    WAF 解析 HTTP 请求的路径、参数、头部和正文，用签名规则与异常评分识别攻击。

  5. 5

    规则命中记录日志，配合告警与观察模式逐步调优，降低误报。

🔤 03 · 术语
有状态 / 无状态 (Stateful / Stateless)
是否跟踪连接状态并自动放行回包。
默认拒绝 (Default Deny)
未明确允许的流量一律阻止。
WAF
检查 HTTP 层内容的 Web 应用防火墙。
OWASP CRS
开源通用 WAF 规则集，用于 ModSecurity、Coraza 等。
出站过滤 (Egress Filtering)
限制内部主机可访问的外部目的地。
nftables
Linux 内核新一代包过滤框架，取代 iptables。
💻 04 · 代码
nftables 主机防火墙text
#!/usr/sbin/nft -f
# /etc/nftables.conf：默认拒绝入站，只放行必要服务
flush ruleset

table inet filter {
  chain input {
    type filter hook input priority 0; policy drop;
    ct state established,related accept      # 有状态：放行已建立连接的回包
    ct state invalid drop
    iif "lo" accept
    meta l4proto { icmp, ipv6-icmp } accept  # IPv6 依赖 ICMPv6，不能全禁
    tcp dport { 80, 443 } accept             # 对外 Web 服务
    ip saddr 203.0.113.0/24 tcp dport 22 accept   # SSH 只允许办公网段
    limit rate 5/minute log prefix "nft-drop: "   # 抽样记录被丢弃的包
  }
  chain forward {
    type filter hook forward priority 0; policy drop;
  }
  chain output {
    type filter hook output priority 0; policy accept;
  }
}
# 应用：sudo nft -f /etc/nftables.conf   查看：sudo nft list ruleset

默认 drop + 放行已建立连接是有状态防火墙的基本形态；SSH 限定来源网段。

⚖️ 06 · 方案取舍

云托管 WAF

优点规则托管更新，可抗大流量

代价按请求计费，误报需调优

适用面向公网的 Web/API

自建 WAF（Coraza/ModSecurity）

优点规则完全可控，无请求费

代价运维与调优成本高

适用私有化部署或合规要求

仅网络层防火墙

优点简单、性能好

代价看不到应用层攻击

适用内部非 HTTP 服务

🕳️ 07 · 常见坑

  • ✗上了 WAF 就不修代码里的注入漏洞

    ✓WAF 只是缓解层，根因仍要用参数化查询等修复

  • ✗WAF 直接开拦截模式，误伤正常用户

    ✓先观察模式运行，分析日志后再启用拦截

  • ✗源站 IP 暴露，攻击者绕过 CDN/WAF 直连

    ✓源站只允许 CDN/WAF 出口 IP 或私网访问

  • ✗只管入站不管出站

    ✓限制服务器出站目的地，阻断回连与数据外泄

🎤 09 · 面试追问
有状态和无状态防火墙有什么区别？

有状态防火墙维护连接表，允许出站请求后回包自动放行，规则简洁；无状态防火墙逐包独立判断，必须显式为双向流量写规则（包括临时端口范围）。AWS 安全组是有状态的，NACL 是无状态的。

WAF 的检测原理和局限？

基于签名与规则匹配已知攻击模式，配合异常评分、频率限制和机器人识别。局限：无法理解业务逻辑，防不了越权与逻辑漏洞；编码变形可能绕过；误报需持续调优。它是补充而非替代安全编码。

如何防止攻击者绕过 CDN 直接打源站？

源站安全组只允许 CDN/WAF 的出口 IP 段；或使用私网回源、隧道（如 Cloudflare Tunnel）；验证 CDN 注入的密钥头或 mTLS；并确保历史 DNS 记录与证书透明度日志不暴露源站 IP。
