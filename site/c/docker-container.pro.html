Docker 容器

Docker Container

📐 01 · 定义

Docker 容器（Docker Container）是把应用及其运行时、依赖和配置打包为镜像，并以隔离进程运行的技术，属于运行时与交付层。容器共享宿主机内核，借助 Linux namespaces 实现隔离、cgroups 限制资源，比虚拟机更轻量、启动更快，解决“我机器上能跑”的环境不一致问题。

⚙️ 02 · 原理
  1. 1

    Dockerfile 描述从基础镜像开始安装依赖、复制代码、设置启动命令的步骤。

  2. 2

    docker build 逐条执行指令，每条生成一个只读镜像层，未变化的层可复用缓存。

  3. 3

    镜像推送到镜像仓库（Registry），以标签或摘要（digest）标识版本。

  4. 4

    docker run 在镜像之上加一层可写层创建容器，用 namespaces 隔离进程、网络和文件系统。

  5. 5

    cgroups 限制 CPU 和内存；需要持久化的数据通过卷（Volume）挂载到容器外。

🔤 03 · 术语
镜像 (Image)
由只读层组成的模板，容器从镜像创建。
多阶段构建 (Multi-stage Build)
构建与运行分阶段，只把产物复制进最终镜像。
Namespaces
Linux 内核隔离机制，为容器提供独立的进程、网络等视图。
cgroups
Linux 控制组，限制和统计进程的资源使用。
卷 (Volume)
Docker 管理的持久存储，生命周期独立于容器。
💻 04 · 代码
Node 多阶段 Dockerfiletext
# 构建阶段：安装全部依赖并构建
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci                      # 依赖层单独缓存
COPY . .
RUN npm run build

# 运行阶段：只保留生产依赖和产物
FROM node:20-alpine
WORKDIR /app
ENV NODE_ENV=production
COPY package*.json ./
RUN npm ci --omit=dev
COPY --from=build /app/dist ./dist
USER node                       # 不以 root 运行
EXPOSE 3000
CMD ["node", "dist/server.js"]

先复制依赖清单利用层缓存；多阶段减小镜像；以非 root 用户运行。

📊 05 · 参数对比

容器 vs 虚拟机

维度容器虚拟机
隔离层级进程级，共享宿主内核硬件虚拟化，独立内核
启动速度通常秒级或更快通常数十秒到分钟
镜像体积MB 级常见GB 级常见
隔离强度较弱，内核漏洞影响所有容器较强
⚖️ 06 · 方案取舍

容器化部署

优点环境一致、可移植

代价需学习镜像与编排

适用多服务、多环境部署

PaaS 直接运行源码

优点零运维

代价运行时受平台限制

适用单体小应用

虚拟机

优点隔离强，可运行任意系统

代价资源占用大

适用多租户强隔离、非 Linux 负载

🕳️ 07 · 常见坑

  • ✗COPY . . 放在 npm ci 前，每次改代码都重装依赖

    ✓先复制依赖清单安装，再复制源码

  • ✗把 .env、.git 打进镜像

    ✓配置 .dockerignore，密钥运行时注入

  • ✗使用 latest 标签部署生产

    ✓固定版本标签或 digest，保证可复现和回滚

  • ✗数据库数据写在容器可写层

    ✓使用卷持久化，容器应可随时销毁重建

🎤 09 · 面试追问
容器和虚拟机的本质区别？

虚拟机通过 Hypervisor 虚拟硬件，每个虚拟机运行完整的操作系统内核；容器只是宿主机上被 namespaces 隔离、cgroups 限制的普通进程，共享同一内核。因此容器更轻更快，但隔离强度弱于虚拟机。

如何优化镜像构建速度和体积？

利用层缓存：把变化少的步骤（安装依赖）放前面；使用多阶段构建只复制运行所需产物；选择精简基础镜像；用 .dockerignore 排除无关文件；合并清理缓存的命令，避免在层中残留临时文件。

为什么不建议容器以 root 运行？

容器内的 root 默认与宿主机 root 是同一 UID，一旦出现容器逃逸漏洞或挂载配置不当，攻击者可能获得宿主机高权限。以非特权用户运行、删除不必要的能力、使用只读文件系统可以缩小攻击面。
