事务隔离级别

Isolation Levels

📐 01 · 定义

事务隔离级别定义了并发事务之间能“看见”彼此多少未完成或新提交的修改。SQL 标准按允许的异常现象划分为读未提交、读已提交、可重复读、可串行化四级。级别越高越接近串行执行的正确性，但并发度、阻塞或重试成本也越高。

⚙️ 02 · 原理
  1. 1

    数据库用锁或 MVCC 快照实现隔离：MVCC 下每个事务读取某一时刻的数据版本。

  2. 2

    读已提交：每条语句取新快照，只能看到已提交数据，但同一事务两次读可能不同。

  3. 3

    可重复读：整个事务使用同一快照，重复读取结果一致；具体能否防幻读因引擎而异。

  4. 4

    可串行化：保证结果等价于某种串行顺序；PostgreSQL 用 SSI 检测冲突并让事务失败。

  5. 5

    被判定冲突的事务会收到序列化失败错误（SQLSTATE 40001），应用需整体重试该事务。

🔤 03 · 术语
脏读 (Dirty Read)
读到其他事务尚未提交的修改。
不可重复读 (Non-repeatable Read)
同一事务内两次读同一行，结果不同。
幻读 (Phantom Read)
同一条件两次查询，返回的行集合变化。
写偏斜 (Write Skew)
两事务基于同一快照各自写不同行，合起来破坏约束。
快照隔离 (Snapshot Isolation)
事务读固定快照，写冲突时后提交者失败。
SSI
可串行化快照隔离，PostgreSQL 可串行化级别的实现。
💻 04 · 代码
写偏斜与可串行化sql
-- 规则：至少要有一名医生值班
CREATE TABLE doctors (name text PRIMARY KEY, on_call boolean);
INSERT INTO doctors VALUES ('alice', true), ('bob', true);

-- 会话 A                                  -- 会话 B
BEGIN ISOLATION LEVEL REPEATABLE READ;     -- BEGIN ISOLATION LEVEL REPEATABLE READ;
SELECT count(*) FROM doctors               -- SELECT count(*) FROM doctors
  WHERE on_call;  -- 2                     --   WHERE on_call;  -- 2
UPDATE doctors SET on_call = false         -- UPDATE doctors SET on_call = false
  WHERE name = 'alice';                    --   WHERE name = 'bob';
COMMIT;                                    -- COMMIT;
-- 结果：两人都不值班，规则被破坏（写偏斜）

-- 改为 SERIALIZABLE 后，后提交的一方会失败：
-- ERROR: could not serialize access due to read/write dependencies
-- SQLSTATE 40001 → 应用捕获后重试整个事务
SHOW default_transaction_isolation;  -- PostgreSQL 默认 read committed

可重复读挡不住写偏斜；PostgreSQL 可串行化会让其中一个事务失败，需重试。

⚖️ 06 · 方案取舍

读已提交（PG 默认）

优点冲突少，吞吐高

代价需自行处理丢失更新与写偏斜

适用大多数 OLTP 业务

可重复读（MySQL 默认）

优点事务内读一致，适合报表

代价仍可能写偏斜，语义因库而异

适用需一致快照的读多事务

可串行化

优点正确性推理最简单

代价失败重试增多，需幂等设计

适用资金、配额等强约束逻辑

🕳️ 07 · 常见坑

  • ✗以为各数据库同名级别行为一致

    ✓查阅所用引擎文档，MySQL 与 PG 的可重复读差异很大

  • ✗开了可串行化但没写重试逻辑

    ✓捕获 40001 并重试整个事务，限制次数

  • ✗读后改写（读余额再写回）未防丢失更新

    ✓用原子 UPDATE、SELECT FOR UPDATE 或版本号

  • ✗全局调高隔离级别解决个别问题

    ✓只对需要的事务单独设置级别

☑️ 08 · 检查清单
🎤 09 · 面试追问
快照隔离为什么不等于可串行化？

快照隔离只检测两个事务写同一行的冲突。写偏斜中两事务读同一集合、写不同的行，没有写写冲突，各自提交后组合结果违反约束。可串行化需额外追踪读写依赖，如 PostgreSQL 的 SSI。

MySQL InnoDB 的可重复读如何处理幻读？

普通一致性读用快照，看不到新插入行；加锁读（FOR UPDATE）和更新使用 next-key 锁（记录锁加间隙锁）阻止范围内插入。但快照读与当前读混用时仍可能出现与直觉不符的结果。

如何选择业务的隔离级别？

默认用读已提交，识别出需要强一致的少数路径：能用原子 UPDATE 或唯一约束解决的优先；其次用行锁或乐观锁；逻辑涉及多行约束、难以手工加锁时，对该事务使用可串行化并配重试。
