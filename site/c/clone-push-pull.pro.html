Clone / Push / Pull

📐 01 · 定义

克隆（Clone）、推送（Push）、拉取（Pull）是本地仓库与远程仓库同步的三种操作：clone 复制整个远程仓库到本地；push 把本地新提交上传到远程分支；pull 等于 fetch（下载远程新提交）加 merge 或 rebase（整合到当前分支）。分清 fetch 与 pull 是避免意外合并的关键。

⚙️ 02 · 原理
  1. 1

    克隆：下载全部对象与引用，创建远程跟踪分支（如 origin/main），并检出默认分支。

  2. 2

    获取：git fetch 下载远程新提交并更新 origin/* 跟踪分支，不改动你的工作区。

  3. 3

    整合：pull 在 fetch 后把 origin/分支合并或变基到当前分支，可能产生冲突。

  4. 4

    推送：push 把本地提交上传，并要求远程分支能快进到新提交，否则拒绝。

  5. 5

    鉴权：通过 SSH 密钥或 HTTPS 加令牌认证，远程据此检查读写权限。

🔤 03 · 术语
origin
克隆时默认给远程仓库起的名字。
远程跟踪分支 (origin/main)
本地记录的远程分支状态，fetch 时更新。
非快进拒绝 (non-fast-forward)
远程有你没有的提交时，push 被拒绝。
--force-with-lease
比 --force 更安全的强推，远程被他人更新时会拒绝。
浅克隆 (Shallow Clone)
只下载最近若干提交，如 --depth 1，节省时间。
💻 04 · 代码
同步流程与常见报错bash
# 克隆（SSH 方式需先把公钥添加到 GitHub）
git clone git@github.com:owner/repo.git
git clone --depth 1 https://github.com/owner/repo.git   # 只要最新代码

# 安全的同步方式：先看再合
git fetch origin
git log --oneline HEAD..origin/main   # 远程有哪些我没有的提交
git pull --rebase                     # 把我的提交放到远程最新提交之后

# 推送并设置上游
git push -u origin feat/search

# 报错 rejected (non-fast-forward)：远程有新提交
git pull --rebase && git push

# 个人分支 rebase 后需要强推时，用更安全的方式
git push --force-with-lease

# 设置 pull 默认使用 rebase（个人偏好）
git config --global pull.rebase true

fetch 只下载不改动工作区，适合先查看；push 被拒绝通常是因为远程领先，先整合再推送。

📊 05 · 参数对比

pull 的整合方式

方式命令结果适合
merge（默认之一）git pull --no-rebase生成合并提交共享分支、保留真实历史
rebasegit pull --rebase本地提交重放到远程之后个人分支，追求线性历史
仅快进git pull --ff-only无法快进就失败主分支，只想同步不想合并
⚖️ 06 · 方案取舍

SSH 认证

优点配置一次长期免密，安全

代价需要生成和管理密钥

适用个人开发机

HTTPS + 令牌

优点穿透防火墙，权限粒度细

代价令牌需安全存储与轮换

适用CI、受限网络

gh auth login

优点交互式完成认证与凭证配置

代价依赖 GitHub CLI

适用使用 GitHub 的开发者

🕳️ 07 · 常见坑

  • ✗工作区有未提交改动时直接 pull，产生混乱冲突

    ✓先提交或 git stash，再 pull

  • ✗push 被拒就用 --force，覆盖了同事的提交

    ✓先 pull 整合；必须强推时用 --force-with-lease

  • ✗在 main 上 pull 意外产生合并提交

    ✓主分支用 git pull --ff-only

  • ✗HTTPS 推送时输入 GitHub 账号密码失败

    ✓GitHub 不再接受密码进行 Git 操作，改用令牌或 SSH

🎤 09 · 面试追问
git fetch 和 git pull 的区别？

fetch 只下载远程新提交并更新远程跟踪分支，不改动本地分支和工作区，可以先审查再决定如何整合；pull 是 fetch 加 merge 或 rebase 的组合，会直接修改当前分支，可能触发冲突。

--force 与 --force-with-lease 的区别？

--force 无条件用本地覆盖远程分支，会抹掉他人新推的提交；--force-with-lease 先检查远程分支是否仍是你上次获取时的状态，若已被他人更新则拒绝，从而避免误覆盖。

CI 为什么常用浅克隆？

CI 通常只需要最新代码来构建和测试，浅克隆（--depth 1）只下载最近提交，显著减少时间和带宽。但需要完整历史的操作（如 git describe 计算版本、按变更范围测试）要加深克隆深度。
