HTTP持久连接复用

Keep-Alive

🧸 回到小白版

📐 01 · 定义

HTTP Keep-Alive（持久连接）指在同一条 TCP（及 TLS）连接上连续发送多个 HTTP 请求，而不是每个请求新建连接。HTTP/1.1 默认启用。它省去重复的 TCP 握手、TLS 握手与慢启动，显著降低延迟和服务器开销，但需要在客户端、代理和服务端之间协调空闲超时。

⚙️ 02 · 原理
  1. 1

    首个请求完成 TCP 与 TLS 握手，响应后连接不关闭，进入空闲状态。

  2. 2

    后续请求复用这条连接，跳过握手；HTTP/1.1 中同一连接上请求按顺序处理。

  3. 3

    任一方发送 Connection: close 或空闲超过超时时间，连接被关闭。

  4. 4

    客户端用连接池按主机维护多条空闲连接，请求时优先取出复用。

  5. 5

    链路中各跳（客户端→负载均衡→后端）各自管理连接，超时需按链路协调。

🔤 03 · 术语
持久连接 (Persistent Connection)
一条连接承载多个请求/响应。
空闲超时 (Idle Timeout)
连接无请求多久后被关闭。
Connection: close
表示本次响应后关闭连接的头。
连接池 (Connection Pool / Agent)
客户端按主机复用空闲连接的组件。
TCP Keepalive
TCP 层探活机制，与 HTTP Keep-Alive 是两回事。
队头阻塞 (Head-of-line Blocking)
HTTP/1.1 同连接上前一个响应未完成，后面只能等。
💻 04 · 代码
Node 服务端与客户端复用javascript
const http = require('node:http');

// 服务端：空闲超时要大于前面负载均衡的空闲超时（AWS ALB 默认 60 秒）
// 否则后端先关连接，均衡器复用到已关闭的连接会返回 502
const server = http.createServer((req, res) => res.end('ok'));
server.keepAliveTimeout = 65_000;  // Node 默认值为 5 秒
server.headersTimeout = 66_000;    // 旧版 Node 中需大于 keepAliveTimeout
server.listen(3000);

// 客户端：显式启用连接复用并限制每个主机的并发连接
const agent = new http.Agent({ keepAlive: true, maxSockets: 50 });

function ping() {
  http.get({ host: 'localhost', port: 3000, path: '/', agent }, (res) => {
    res.resume();  // 必须读完响应体，连接才会被放回池中复用
  });
}
ping(); ping(); // 第二次请求复用第一次的连接

// Python 对应：requests.Session() 会自动复用连接

后端空闲超时大于上游；客户端用 Agent 复用，并读完响应体以归还连接。

⚖️ 06 · 方案取舍

长空闲超时

优点复用率高，握手少

代价占用更多文件描述符与内存

适用客户端少、请求频繁

短空闲超时

优点快速释放空闲资源

代价频繁重连，延迟上升

适用海量低频客户端

升级到 HTTP/2

优点一条连接并发多请求

代价需 TLS 与组件支持

适用浏览器访问、多请求并发

🕳️ 07 · 常见坑

  • ✗后端空闲超时短于负载均衡，偶发 502

    ✓后端超时设为大于上游空闲超时

  • ✗客户端没读完响应体，连接无法复用

    ✓总是消费或丢弃完整响应体

  • ✗每次请求 new 一个 HTTP 客户端

    ✓全局复用客户端/Session 及其连接池

  • ✗把 TCP keepalive 当作 HTTP keep-alive 调

    ✓区分两层，各自按需配置

🎤 09 · 面试追问
为什么负载均衡后偶发 502？

常见原因是后端空闲超时短于均衡器：后端关闭空闲连接的同时，均衡器正好在这条连接上转发新请求，收到 RST 就返回 502。把后端 keep-alive 超时设得比均衡器更长即可解决。

HTTP Keep-Alive 与 TCP Keepalive 的区别？

HTTP Keep-Alive 指连接在请求之间保持打开以供复用，由应用层空闲超时控制。TCP Keepalive 是内核在长时间无数据时发送探测包，检测对端是否存活、维持 NAT 映射。两者独立。

有了 keep-alive 为什么还需要 HTTP/2？

HTTP/1.1 持久连接上请求只能串行，前一个响应慢会阻塞后面（队头阻塞），浏览器只好对同一主机开多条连接。HTTP/2 在一条连接上多路复用多个流，并压缩头部。
