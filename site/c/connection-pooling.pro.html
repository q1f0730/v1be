数据库连接池

Connection Pooling

📐 01 · 定义

数据库连接池是在应用与数据库之间维护一组可复用长连接的组件。建立连接需要 TCP 握手、TLS、认证和后端进程初始化，开销大；数据库能承受的并发连接也有限。连接池把连接的创建成本摊薄，并对并发访问数设上限，保护数据库。

⚙️ 02 · 原理
  1. 1

    应用启动或首次使用时创建若干连接放入池中，空闲连接保持打开。

  2. 2

    请求需要数据库时从池中借出一个连接，用完归还，而不是关闭。

  3. 3

    池满时新请求排队等待，超过等待超时则报错，从而形成背压。

  4. 4

    池定期检测连接有效性（pre-ping），并按最大寿命回收，避免使用被网络设备断开的连接。

  5. 5

    外部连接池（如 PgBouncer）可在多个应用实例与数据库之间再做一层复用，按事务分配连接。

🔤 03 · 术语
pool_size / 最大连接数
池中常驻或允许的最大连接数量。
等待超时 (Acquire Timeout)
借不到连接时最多等待多久才报错。
连接回收 (Max Lifetime / Recycle)
连接存活超过阈值后主动关闭重建。
事务级池化 (Transaction Pooling)
PgBouncer 模式，事务结束即归还服务器连接。
连接泄漏 (Connection Leak)
借出后未归还，池逐渐耗尽。
max_connections
PostgreSQL 允许的最大并发连接数参数，默认通常为 100。
💻 04 · 代码
SQLAlchemy 连接池配置python
# pip install sqlalchemy psycopg[binary]
from sqlalchemy import create_engine, text

engine = create_engine(
    "postgresql+psycopg://app:secret@db:5432/app",
    pool_size=10,        # 常驻连接数
    max_overflow=5,      # 高峰时允许额外临时连接
    pool_timeout=30,     # 借连接最多等 30 秒
    pool_recycle=1800,   # 连接用满 30 分钟后重建
    pool_pre_ping=True,  # 借出前探活，避免拿到已断开的连接
)

# with 块结束自动归还连接，避免泄漏
with engine.connect() as conn:
    rows = conn.execute(text("SELECT id, name FROM users LIMIT 5")).all()

# 容量估算：实例数 × (pool_size + max_overflow) 应小于数据库 max_connections
# 例如 6 个实例 × 15 = 90，需给管理连接留余量
print(engine.pool.status())

上下文管理器保证归还；总连接数要按实例数乘以单实例上限来规划。

⚖️ 06 · 方案取舍

应用内连接池

优点零额外组件，延迟最低

代价实例多时总连接数膨胀

适用实例数少的常规服务

外部池（PgBouncer/RDS Proxy）

优点大量客户端共享少量后端连接

代价多一跳与运维，有模式限制

适用多实例、Serverless 场景

池开得很大

优点排队少

代价数据库上下文切换与锁竞争加剧

适用几乎不应作为默认

🕳️ 07 · 常见坑

  • ✗Serverless 函数每次调用都新建连接

    ✓在函数外部复用客户端，并使用外部连接池

  • ✗池越大越快的直觉

    ✓按 CPU 核数估起点并压测，过大反而降低吞吐

  • ✗长事务或慢请求占着连接不放

    ✓缩短事务，外部调用不要夹在事务中

  • ✗事务池模式下依赖 SET 会话变量

    ✓改用 SET LOCAL 或连接参数，确认驱动兼容

🎤 09 · 面试追问
为什么连接池不是越大越好？

数据库真正能并行处理的查询受 CPU 核数和磁盘限制。连接过多会增加上下文切换、内存占用与锁竞争，吞吐反而下降。较小的池加排队通常更稳，HikariCP 的池大小文档对此有详细论述。

PostgreSQL 为什么特别需要连接池？

PostgreSQL 采用每连接一个后端进程的模型，每个连接都有进程与内存开销，建立连接也较慢。大量短连接或成千上万并发连接会拖垮实例，因此常配合应用池或 PgBouncer 使用。

如何发现连接泄漏？

监控池中借出连接数持续上升不回落、借连接等待超时增加；数据库侧看 pg_stat_activity 中长时间 idle in transaction 的连接。代码上统一用上下文管理器，部分池可开启泄漏检测阈值。
