📐 01 · 定义

DNS（域名系统）是互联网的分布式命名数据库，把人类可读的域名解析为 IP 地址等记录。它由根服务器、顶级域服务器和权威服务器组成层级结构，配合递归解析器和多级缓存运作。部署网站、配置邮件、验证域名所有权、接入 CDN 都要修改 DNS 记录，TTL 决定修改生效的速度。

⚙️ 02 · 原理
  1. 1

    本地查询：程序先查系统缓存与 hosts 文件，未命中则询问配置的递归解析器。

  2. 2

    递归解析：解析器从根服务器查到顶级域（如 .com）服务器，再找到该域名的权威服务器。

  3. 3

    权威应答：权威服务器返回记录（如 A 记录对应的 IP）及其 TTL。

  4. 4

    缓存：解析器和客户端按 TTL 缓存结果，期间不再重复查询。

  5. 5

    变更传播：修改记录后，旧值要等各级缓存的 TTL 过期才会全部更新。

🔤 03 · 术语
A / AAAA 记录
把域名指向 IPv4 / IPv6 地址。
CNAME 记录
把域名指向另一个域名，不能与同名其他记录共存。
MX / TXT 记录
邮件服务器地址 / 任意文本，常用于 SPF 与域名验证。
TTL
记录可被缓存的秒数，决定变更生效速度。
NS 记录
指定该域名由哪些权威服务器负责解析。
💻 04 · 代码
用 dig 排查解析bash
# 查询 A 记录（简洁输出）
dig +short example.com A

# 查看完整应答，包括 TTL
dig example.com A +noall +answer

# 查询其他类型记录
dig +short example.com AAAA
dig +short www.example.com CNAME
dig +short example.com MX
dig +short example.com TXT        # SPF、域名验证等

# 查看域名由哪些权威服务器负责
dig +short example.com NS

# 绕过本地缓存，直接问指定解析器（对比是否已生效）
dig @1.1.1.1 +short example.com
dig @8.8.8.8 +short example.com

# 跟踪完整的递归解析路径：根 → 顶级域 → 权威
dig +trace example.com

改了 DNS 不生效时，用 dig 对比权威服务器与公共解析器的结果，并看 TTL 剩余时间。

⚖️ 06 · 方案取舍

长 TTL（数小时到一天）

优点查询少、解析快、抗权威故障

代价变更生效慢

适用长期稳定的记录

短 TTL（数分钟）

优点变更与切换快

代价查询量增加

适用迁移前、故障切换场景

托管 DNS 服务

优点高可用、全球节点、API 管理

代价依赖服务商

适用绝大多数网站

🕳️ 07 · 常见坑

  • ✗迁移服务器时直接改记录，旧 TTL 很长导致长时间不一致

    ✓迁移前提前把 TTL 调低，切换完成再调回

  • ✗在根域名上配置标准 CNAME

    ✓根域用 A 记录或服务商的 ALIAS/CNAME 拉平功能

  • ✗停用云资源后没删 CNAME，导致子域名被接管

    ✓下线资源时同步清理指向它的 DNS 记录

  • ✗域名注册商账号未开 MFA

    ✓域名与 DNS 账号开启 MFA 和注册商锁定

🎤 09 · 面试追问
为什么改了 DNS 别人还访问旧地址？

各级缓存（递归解析器、操作系统、浏览器）会在 TTL 过期前继续使用旧记录。改动只是更新了权威服务器，传播取决于旧 TTL。所以迁移前要提前降低 TTL；可用 dig 分别查询权威服务器和公共解析器确认进度。

什么是子域名接管？

子域名的 CNAME 指向某云服务资源（如存储桶、托管站点），资源被删除后记录仍在。攻击者在该服务上注册同名资源，就能控制这个子域名，用于钓鱼或窃取 Cookie。防御是下线资源时同步删除 DNS 记录并定期审计。

DNS 默认是加密的吗？

传统 DNS 查询基于 UDP/TCP 明文传输，路径上的人可以看到甚至篡改。DoH（DNS over HTTPS）和 DoT（DNS over TLS）加密客户端到解析器的通信；DNSSEC 则通过签名保证记录真实性，但不加密。三者解决的问题不同。
