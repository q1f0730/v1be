可验证奖励强化学习 (RLVR / GRPO)

RLVR / GRPO

📐 01 · 定义

可验证奖励强化学习（RLVR）指用程序可判定的奖励（答案是否正确、单元测试是否通过、格式是否合规）对语言模型做强化学习，「RLVR」一词由 Tülu 3 报告推广。GRPO（Group Relative Policy Optimization）由 DeepSeekMath 提出，用同一题目多次采样的组内相对奖励估计优势，省去价值模型。DeepSeek-R1 等推理模型展示了二者结合的效果。

⚙️ 02 · 原理
  1. 1

    对每个提示，用当前策略采样 G 个回答（一组），通常包含推理过程与最终答案。

  2. 2

    用验证器为每个回答打分：如数学答案与标准答案比对、代码在沙箱中跑测试，可附加格式奖励。

  3. 3

    组内标准化：优势 A_i =（r_i − 组均值）/ 组标准差，高于平均的回答被强化，低于平均的被抑制。

  4. 4

    按 PPO 式裁剪目标更新策略，并加入与参考模型的 KL 惩罚，防止过度偏离；不训练价值网络。

  5. 5

    若一组回答全对或全错，组内优势为零，该题不提供学习信号，因此题目难度需与模型能力匹配。

🔤 03 · 术语
可验证奖励 (Verifiable Reward)
由确定性程序计算的奖励，不依赖学习得到的奖励模型。
组相对优势 (Group Relative Advantage)
以同题多个回答的平均奖励为基线计算的优势值。
价值模型 (Critic)
PPO 中估计状态价值的网络，GRPO 用组内基线替代它以节省显存。
KL 惩罚
约束策略与参考模型分布距离的正则项，避免语言能力崩坏。
推理链 (Chain of Thought)
模型在给出答案前生成的中间推理，RL 训练常使其变长。
💻 04 · 代码
TRL GRPO 自定义验证器python
# pip install trl datasets ；模型与数据集名以官方文档为准
import re
from datasets import load_dataset
from trl import GRPOConfig, GRPOTrainer

# GSM8K 的 answer 列末尾形如 "#### 42"
ds = load_dataset("openai/gsm8k", "main", split="train")
ds = ds.map(lambda x: {"prompt": x["question"] + "\n最后一行写：答案：<数字>",
                       "gold": x["answer"].split("####")[-1].strip()})

def correctness(completions, gold, **kwargs):
    """可验证奖励：提取最终数字与标准答案比对"""
    rewards = []
    for text, g in zip(completions, gold):
        m = re.search(r"答案[:：]\s*(-?[\d,\.]+)\s*$", text.strip())
        pred = m.group(1).replace(",", "") if m else None
        rewards.append(1.0 if pred == g.replace(",", "") else 0.0)
    return rewards

trainer = GRPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    reward_funcs=[correctness],
    args=GRPOConfig(output_dir="grpo-gsm8k", logging_steps=10),
    train_dataset=ds,
)
trainer.train()

数据集额外列（gold）会作为关键字参数传入奖励函数；严格的答案抽取规则是防止投机的第一道防线。

⚖️ 06 · 方案取舍

GRPO

优点无价值模型，显存与实现更简单

代价每题需多次采样，生成开销大

适用可验证任务、资源有限

PPO + 价值模型

优点优势估计更细粒度

代价多一个大模型，调参复杂

适用大规模训练且基础设施成熟

拒绝采样 + SFT

优点实现最简单，稳定

代价只利用正确样本，效率较低

适用RL 前的冷启动或小规模实验

🕳️ 07 · 常见坑

  • ✗验证器只检查格式或过于宽松，模型学会投机

    ✓严格抽取与比对答案，抽查高奖励样本

  • ✗题目过难或过易，组内奖励全相同无梯度

    ✓按模型通过率筛选难度，动态调整课程

  • ✗代码奖励在无隔离环境执行模型生成代码

    ✓在资源受限、断网的沙箱中运行测试

  • ✗只看训练奖励上升

    ✓在保留集上评测，并检查推理长度与语言质量

🎤 09 · 面试追问
GRPO 如何在没有价值模型的情况下估计优势？

对同一提示采样一组回答，用组内平均奖励作为基线，奖励减均值再除以标准差即为每个回答的优势。这相当于用蒙特卡洛的同题对照代替价值网络预测，节省一个与策略同规模的模型，代价是每题需要多次采样。

为什么 RLVR 特别适合训练推理能力？

数学与代码有客观可判定的正确性，奖励信号准确且难以被评分模型的偏差利用；模型可通过反复尝试，自主探索出更长、更有效的推理链。对于没有标准答案的开放式写作任务，可验证奖励难以定义，仍需偏好或奖励模型。

RLVR 训练中常见的奖励投机有哪些？

只匹配答案格式而不真正解题、利用宽松抽取规则输出多个候选、在代码任务中修改测试或硬编码输出、通过超长输出碰运气。对策是严格验证器、隐藏测试、长度约束与人工抽检。
