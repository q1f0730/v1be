混合专家模型 (MoE)

Mixture of Experts

📐 01 · 定义

混合专家模型（Mixture of Experts，MoE）是一种稀疏激活的神经网络架构：把 Transformer 中的前馈层（FFN）替换为多个并列的「专家」子网络，由路由器为每个 token 选择少数几个专家参与计算。它属于模型架构层，使总参数量可以很大，而每个 token 的计算量只取决于激活参数，Mixtral、DeepSeek-V3 等开源模型均采用此架构。

⚙️ 02 · 原理
  1. 1

    每个 MoE 层包含路由器（门控网络）和 N 个专家 FFN，注意力层通常仍是共享的稠密结构。

  2. 2

    路由器为每个 token 计算对各专家的打分，选取 Top-k（常见 k=1 或 2，也有更细粒度设计）专家。

  3. 3

    token 只送入被选中的专家，输出按门控权重加权求和；未选中的专家不参与该 token 的计算。

  4. 4

    训练时加入负载均衡损失或其他均衡策略，防止路由集中在少数专家导致其他专家闲置。

  5. 5

    推理时全部专家权重都需加载进显存（或分布到多卡），因此显存按总参数计、计算按激活参数计。

🔤 03 · 术语
专家 (Expert)
MoE 层中的一个独立前馈子网络。
路由器 / 门控 (Router / Gating)
为每个 token 选择专家并给出权重的小网络。
Top-k 路由
每个 token 只激活得分最高的 k 个专家。
激活参数 (Active Parameters)
处理单个 token 实际参与计算的参数量。
专家并行 (Expert Parallelism)
把不同专家放在不同 GPU 上的并行方式，需要 all-to-all 通信。
负载均衡损失 (Load Balancing Loss)
鼓励 token 均匀分布到各专家的辅助训练目标。
💻 04 · 代码
Top-2 路由的最小实现python
import torch, torch.nn as nn, torch.nn.functional as F

class MoE(nn.Module):
    def __init__(self, dim=512, n_experts=8, k=2):
        super().__init__()
        self.k = k
        self.router = nn.Linear(dim, n_experts)
        self.experts = nn.ModuleList(
            nn.Sequential(nn.Linear(dim, 4 * dim), nn.GELU(), nn.Linear(4 * dim, dim))
            for _ in range(n_experts))

    def forward(self, x):                      # x: [tokens, dim]
        logits = self.router(x)                # 每个 token 对每个专家打分
        w, idx = logits.topk(self.k, dim=-1)   # 选 Top-k 专家
        w = F.softmax(w, dim=-1)
        out = torch.zeros_like(x)
        for slot in range(self.k):
            for e in idx[:, slot].unique():
                mask = idx[:, slot] == e       # 只把相关 token 送进该专家
                out[mask] += w[mask, slot, None] * self.experts[e](x[mask])
        return out

print(MoE()(torch.randn(10, 512)).shape)       # torch.Size([10, 512])

教学示例：8 个专家只算 2 个；生产实现还需负载均衡损失、容量限制与高效分发内核。

⚖️ 06 · 方案取舍

MoE 模型

优点同等计算量下容量更大，训练与推理 FLOPs 低

代价显存需装下全部专家，通信复杂

适用大规模服务、多卡部署

稠密模型

优点结构简单、部署与微调生态成熟

代价参数增大则每 token 计算同步增大

适用单卡或边缘部署

MoE 量化部署

优点降低全部专家的显存占用

代价质量与路由稳定性需验证

适用显存受限但想用大 MoE

🕳️ 07 · 常见坑

  • ✗按激活参数估算部署显存

    ✓显存按总参数估算，激活参数决定的是计算量与速度

  • ✗小批量单卡推理期望达到宣传的高吞吐

    ✓MoE 优势在大批量、专家并行；小批量时访存不一定省

  • ✗微调时不处理路由，导致专家塌缩

    ✓保留负载均衡机制，或冻结路由器只调专家/注意力

  • ✗忽视专家并行的跨卡通信开销

    ✓评估 all-to-all 带宽，优先使用高速互联

🎤 09 · 面试追问
MoE 为什么能「大参数、低成本」？

每个 token 只经过少数专家，计算量由激活参数决定；总参数提供更大的知识容量。代价是显存要装下全部参数，以及路由与通信带来的工程复杂度。

负载不均衡会造成什么问题？

少数专家过载、其他专家很少被训练，模型容量被浪费；分布式时热门专家所在 GPU 成为瓶颈或触发 token 丢弃。通过辅助损失、容量因子或无辅助损失的偏置调整来均衡。

MoE 中「专家」真的按领域分工吗？

不一定。研究观察到路由更多与 token 层面的模式（语法、符号类型）相关，而非人类意义上的学科领域。「专家」是结构名称，不应理解为数学专家、代码专家。
