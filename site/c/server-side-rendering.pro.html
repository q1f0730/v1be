服务端渲染 (SSR)

Server-Side Rendering

🧸 回到小白版

📐 01 · 定义

服务端渲染（SSR，Server-Side Rendering）指在每次请求时由服务器运行组件代码、获取数据并生成完整 HTML 返回，浏览器先显示内容，再加载 JS 进行水合（Hydration）使页面可交互。Next.js、Nuxt、Remix 等框架提供 SSR，可与静态生成、流式渲染、服务端组件组合，兼顾首屏、SEO 与交互。

⚙️ 02 · 原理
  1. 1

    请求到达服务器，框架匹配路由并在服务端执行数据获取与组件渲染。

  2. 2

    生成的 HTML 返回浏览器（可流式分块发送），用户在 JS 加载前就能看到内容。

  3. 3

    浏览器下载 JS 后执行水合：复用已有 DOM，绑定事件处理器并恢复组件状态。

  4. 4

    服务端与客户端首轮渲染结果必须一致，否则出现水合不匹配警告或界面跳变。

  5. 5

    可在 CDN 或框架层缓存渲染结果，按时间或事件重新验证，降低服务器压力。

🔤 03 · 术语
水合 (Hydration)
客户端 JS 接管服务端生成的 HTML，使其可交互。
TTFB (Time to First Byte)
从请求到收到首字节的时间，SSR 中受服务端渲染耗时影响。
流式 SSR (Streaming SSR)
分块发送 HTML，先出外壳，慢数据部分后到。
增量静态再生 (ISR)
静态页面按时间间隔或按需在后台重新生成。
水合不匹配 (Hydration Mismatch)
服务端与客户端渲染结果不一致导致的错误。
💻 04 · 代码
Next.js 服务端渲染详情页typescript
// app/products/[id]/page.tsx（Next.js App Router，默认是服务端组件）
import type { Metadata } from "next";

type Props = { params: Promise<{ id: string }> }; // Next.js 15 起 params 为 Promise

async function getProduct(id: string) {
  const res = await fetch(`https://api.example.com/products/${id}`, {
    next: { revalidate: 60 }, // 缓存 60 秒后重新验证；要每次请求都渲染可用 cache: "no-store"
  });
  if (!res.ok) throw new Error("商品获取失败");
  return res.json();
}

// 服务端生成 title/description，利于 SEO
export async function generateMetadata({ params }: Props): Promise<Metadata> {
  const { id } = await params;
  const p = await getProduct(id);
  return { title: p.name, description: p.summary };
}

export default async function ProductPage({ params }: Props) {
  const { id } = await params;
  const p = await getProduct(id);
  return (
    <main>
      <h1>{p.name}</h1>
      <p>{p.summary}</p>
    </main>
  );
}

组件在服务器执行，可直接 await 数据；不要在这里访问 window 等浏览器 API。

📊 05 · 参数对比

渲染策略对比

策略HTML 生成时机首屏适合
CSR浏览器运行时慢登录后应用
SSR每次请求快，TTFB 受服务端影响个性化、实时数据页
SSG构建时最快（CDN）文档、博客
ISR构建时 + 后台再生快商品页等准静态内容
⚖️ 06 · 方案取舍

SSR

优点首屏快、SEO 好、数据实时

代价服务器成本与 TTFB 增加，需处理水合

适用个性化或频繁变化且需收录

SSG/ISR

优点CDN 分发、成本低、极快

代价数据有延迟，构建或再生需管理

适用内容更新不频繁的页面

CSR

优点服务器压力最小

代价首屏与 SEO 弱

适用无需收录的交互应用

🕳️ 07 · 常见坑

  • ✗渲染期间访问 window、localStorage 导致服务端报错

    ✓浏览器专属逻辑放到 useEffect 或客户端组件中

  • ✗渲染中使用 Date.now()、随机数造成水合不匹配

    ✓由服务端生成值传给客户端，或只在客户端挂载后渲染

  • ✗每个请求都串行调用多个慢接口，TTFB 很高

    ✓并行获取、加缓存，配合流式渲染先出外壳

  • ✗把含用户私有数据的 SSR 页面放进共享缓存

    ✓个性化响应设置 private 或 no-store，避免串号

🎤 09 · 面试追问
SSR 为什么还需要水合？

服务端只输出静态 HTML，没有事件处理器与组件状态。浏览器需下载组件 JS，在已有 DOM 上重新执行渲染逻辑并绑定事件，页面才可交互。水合期间页面可见但可能暂不可交互。

如何降低 SSR 的 TTFB？

并行化数据获取、对上游加缓存；使用流式 SSR 先发送外壳；对可共享页面使用 CDN 缓存或 ISR；把非关键内容延后到客户端或 Suspense 边界；把渲染部署到更靠近用户或数据的区域。

什么是水合不匹配，怎么排查？

服务端与客户端首次渲染输出不同，如使用当前时间、随机 ID、浏览器专属 API 或依赖用户时区格式化。框架会警告并可能重新渲染。排查方法：定位警告节点，消除非确定性输入，或改为挂载后渲染。
