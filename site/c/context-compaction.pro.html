上下文压缩

Context Compaction

🧸 回到小白版

📐 01 · 定义

上下文压缩（Context Compaction）是在长对话或长任务中，当累积的消息、工具结果接近上下文窗口上限时，把较早的内容压缩为摘要或删除可再获取的信息，以腾出空间继续工作的技术。它属于上下文工程层，常见于编码 Agent 的长会话，如 Claude Code 的 /compact。

⚙️ 02 · 原理
  1. 1

    持续统计当前上下文的 token 数，接近阈值（如窗口的某个比例）时触发压缩。

  2. 2

    原样保留系统提示词、当前任务目标和最近若干轮对话，不做摘要。

  3. 3

    把更早的对话交给模型总结：已做决定、已修改文件、未解决问题和下一步。

  4. 4

    清理可重新获取的大块内容，如旧的工具输出、文件全文，只留引用路径。

  5. 5

    用「摘要 + 最近消息」替换原历史继续对话，必要时把关键状态写入外部文件。

🔤 03 · 术语
上下文窗口 (Context Window)
模型单次请求能处理的最大 token 数。
上下文工程 (Context Engineering)
决定每一步把哪些信息放进上下文的设计。
工具结果清理 (Tool Result Clearing)
删除旧工具调用的输出，保留调用记录。
结构化笔记 (Structured Note-taking)
Agent 把进度写入外部文件，压缩后可读回。
上下文腐化 (Context Rot)
上下文越长，模型回忆与利用信息的准确度下降。
💻 04 · 代码
超阈值时摘要旧消息python
import anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-4-5"     # 以实际可用模型为准
LIMIT = 150_000                  # 触发阈值，按模型窗口设定
KEEP_RECENT = 6                  # 保留最近 6 条原文

def tokens(messages, system):
    r = client.messages.count_tokens(model=MODEL, system=system, messages=messages)
    return r.input_tokens

def compact(messages, system):
    if tokens(messages, system) < LIMIT:
        return messages
    old, recent = messages[:-KEEP_RECENT], messages[-KEEP_RECENT:]
    summary = client.messages.create(
        model=MODEL, max_tokens=2000,
        system="把以下对话压缩为要点：目标、已做决定、改过的文件、待办、关键报错。",
        messages=[{"role": "user", "content": str(old)}],
    ).content[0].text
    head = {"role": "user", "content": f"[此前对话摘要]\n{summary}"}
    # 注意：消息需保持 user/assistant 交替，必要时调整 recent 的起点
    return [head] + recent

用官方 count_tokens 计数，超阈值时把旧消息换成结构化摘要；需注意消息角色交替。

📊 05 · 参数对比

压缩手段对比

手段信息损失实现难度适用
截断最旧消息高，直接丢弃低闲聊类对话
LLM 摘要中，取决于摘要质量中长任务会话

⚖️ 06 · 方案取舍

自动压缩

优点无需用户干预，任务不中断

代价时机不可控，可能丢关键细节

适用长时间自主运行的 Agent

手动压缩（如 /compact）

优点可在阶段边界执行并给出保留重点

代价依赖用户判断

适用交互式编码会话

开新会话 + 交接文档

优点上下文最干净

代价需写交接说明

适用任务阶段切换

🕳️ 07 · 常见坑

  • ✗摘要丢了用户明确提出的约束

    ✓摘要模板中单列约束与决定，原文保留用户指令

  • ✗在任务中途压缩，正在调试的报错细节消失

    ✓尽量在阶段完成时压缩，或要求摘要保留最近报错原文

  • ✗把大量文件全文留在上下文中

    ✓只保留路径和关键片段，需要时重新读取

  • ✗压缩后消息角色顺序错误导致 API 报错

    ✓压缩后校验消息格式与 user/assistant 交替规则

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么不直接用更大的上下文窗口？

窗口再大也有上限，且成本与延迟随长度增长；更重要的是长上下文中模型对信息的利用会退化，无关内容会稀释注意力。主动精简上下文往往比塞满窗口效果更好。

压缩时哪些信息必须保留？

用户原始目标与约束、已经做出的设计决定、修改过的文件与当前状态、未解决的错误和下一步计划。可重新获取的内容（文件全文、搜索结果）可以只留引用。

压缩和外部记忆如何配合？

压缩处理单个会话内的窗口压力；外部记忆（如项目说明文件、进度笔记）跨会话持久保存。Agent 在压缩前把关键进度写入文件，压缩后或新会话开始时读回，避免依赖摘要质量。
