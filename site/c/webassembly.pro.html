📐 01 · 定义

WebAssembly（Wasm）是一种可移植的低级二进制指令格式，作为 C/C++、Rust、Go 等语言的编译目标，在浏览器和独立运行时中以接近原生的速度、在内存安全的沙箱中执行。WebAssembly 1.0 于 2019 年成为 W3C 推荐标准。它与 JavaScript 互补：Wasm 处理计算密集部分，JS 负责 DOM 与业务胶水。

⚙️ 02 · 原理
  1. 1

    源语言通过编译器工具链（如 Emscripten、Rust 的 wasm32 目标、wasm-pack）生成 .wasm 二进制模块。

  2. 2

    宿主（浏览器或 Wasmtime 等运行时）加载模块时先进行验证，确保类型安全与控制流合法，然后编译为本地机器码。

  3. 3

    模块运行在基于栈的虚拟机语义上，只能访问自己的线性内存，无法直接访问宿主内存或系统调用。

  4. 4

    与外界交互必须通过导入与导出：JS 把函数导入给 Wasm，Wasm 导出函数供 JS 调用，复杂数据通过线性内存传递。

  5. 5

    浏览器外由 WASI 提供标准化的系统接口（文件、时钟、网络等），组件模型（Component Model）定义跨语言的高级接口类型。

🔤 03 · 术语
线性内存 (Linear Memory)
Wasm 模块可访问的一段连续可增长字节数组，越界访问会触发陷阱。
WAT (WebAssembly Text Format)
Wasm 二进制的人类可读文本表示，便于调试与学习。
导入/导出 (Imports/Exports)
模块与宿主之间交换函数、内存、表和全局变量的唯一通道。
WASI
WebAssembly System Interface，为浏览器外运行提供基于能力的系统接口。
陷阱 (Trap)
执行遇到越界、除零等错误时立即终止并向宿主抛出异常。
💻 04 · 代码
手写 Wasm 模块并调用javascript
// 等价的 WAT：
// (module (func (export "add") (param i32 i32) (result i32)
//   local.get 0  local.get 1  i32.add))
const bytes = new Uint8Array([
  0x00, 0x61, 0x73, 0x6d, 0x01, 0x00, 0x00, 0x00,       // 魔数 \0asm + 版本 1
  0x01, 0x07, 0x01, 0x60, 0x02, 0x7f, 0x7f, 0x01, 0x7f, // 类型段：(i32,i32)->i32
  0x03, 0x02, 0x01, 0x00,                               // 函数段
  0x07, 0x07, 0x01, 0x03, 0x61, 0x64, 0x64, 0x00, 0x00, // 导出段："add"
  0x0a, 0x09, 0x01, 0x07, 0x00, 0x20, 0x00, 0x20, 0x01, 0x6a, 0x0b, // 代码段
])

const { instance } = await WebAssembly.instantiate(bytes)
console.log(instance.exports.add(2, 3))   // 5

// 实际项目从网络加载：
// const { instance } = await WebAssembly.instantiateStreaming(fetch('/app.wasm'), imports)

可在 Node.js 或浏览器控制台运行；真实项目由编译器生成 .wasm，instantiateStreaming 要求服务器返回 application/wasm。

🕳️ 07 · 常见坑

  • ✗频繁在 JS 与 Wasm 之间传小对象，开销超过计算本身

    ✓批量传递数据，在线性内存中原地处理，减少跨边界调用

  • ✗把整个应用迁移到 Wasm 期待全面提速

    ✓先性能分析，只把被证实的计算热点移入 Wasm

  • ✗未开启压缩与缓存，首屏下载巨大的 .wasm

    ✓开启 gzip/brotli、长缓存与流式编译，必要时按需加载

  • ✗以为 Wasm 沙箱能防御所有安全问题

    ✓模块内部仍可能有内存错误；对导入给它的宿主能力做最小授权

🎤 09 · 面试追问
Wasm 为什么比 JS 性能更可预测？

Wasm 是静态类型的低级字节码，加载时即可验证并提前编译，不需要像 JS 那样依赖运行时类型推测与去优化；内存布局由程序显式控制，没有隐藏的对象形状变化。因此在数值计算上性能更稳定，但对 DOM 操作并无优势。

Wasm 的安全模型是什么？

模块只能访问自己的线性内存，越界会触发陷阱；控制流结构化且经过验证，不能跳转到任意地址；与外界交互只能通过显式导入的函数。宿主据此实施最小授权。WASI 也采用基于能力的设计，只能访问被授予的目录与资源。

WASI 与组件模型解决什么问题？

核心 Wasm 只有数值类型，没有标准系统接口。WASI 定义了文件、时钟、随机数、网络等可移植接口，让 Wasm 能在浏览器外运行；组件模型定义字符串、记录等高级类型与接口描述，使不同语言编写的模块可以直接组合。
