Agent Harness

📐 01 · 定义

智能体外壳（Agent Harness）是包在大模型外面的运行框架：负责组装系统提示与上下文、定义和执行工具、驱动「模型决策→调用工具→回传结果」循环，并处理权限、上下文压缩、错误重试与终止条件。同一模型配不同 harness，表现可能差异很大。

⚙️ 02 · 原理
  1. 1

    组装上下文：系统提示、项目说明文件、对话历史和工具定义一起发给模型。

  2. 2

    模型决策：模型输出文本或结构化的工具调用请求（工具名+参数）。

  3. 3

    执行工具：harness 校验权限后在本地或沙箱执行，捕获输出与错误。

  4. 4

    回传结果：把工具结果作为新消息追加，模型据此决定下一步，循环直至任务完成。

  5. 5

    上下文管理：历史过长时摘要压缩或裁剪，并设置最大步数、超时等终止条件。

🔤 03 · 术语
Agent 循环 (Agent Loop)
模型反复调用工具并读取结果，直到给出最终答复。
工具定义 (Tool Schema)
用 JSON Schema 描述工具名称、用途与参数格式。
上下文压缩 (Compaction)
对过长历史做摘要以腾出上下文窗口空间。
子智能体 (Subagent)
由主 Agent 派生、拥有独立上下文处理子任务的 Agent。
终止条件 (Stop Condition)
结束循环的规则，如模型不再调用工具或超出步数。
💻 04 · 代码
最小 Agent 循环python
import subprocess, anthropic

client = anthropic.Anthropic()
tools = [{"name": "run", "description": "执行 shell 命令并返回输出",
          "input_schema": {"type": "object",
                           "properties": {"cmd": {"type": "string"}},
                           "required": ["cmd"]}}]
messages = [{"role": "user", "content": "统计当前目录下 .py 文件数量"}]

for _ in range(10):                           # 最大步数，防止死循环
    resp = client.messages.create(model="claude-sonnet-4-5", max_tokens=1024,
                                  tools=tools, messages=messages)
    messages.append({"role": "assistant", "content": resp.content})
    if resp.stop_reason != "tool_use":
        break                                 # 模型给出最终答复
    results = []
    for b in resp.content:
        if b.type == "tool_use":              # 真实 harness 在此做权限检查
            out = subprocess.run(b.input["cmd"], shell=True,
                                 capture_output=True, text=True, timeout=30)
            results.append({"type": "tool_result", "tool_use_id": b.id,
                            "content": out.stdout + out.stderr})
    messages.append({"role": "user", "content": results})
print(resp.content[-1].text)

演示用：直接执行任意命令有风险，真实 harness 需加权限校验和沙箱。

🕳️ 07 · 常见坑

  • ✗工具报错时吞掉错误，只回传空结果

    ✓把错误信息原样（截断后）回传给模型，让它能自我纠正

  • ✗工具输出不截断，一次 cat 大文件撑爆上下文

    ✓对工具输出设长度上限，并提示可分段读取

  • ✗没有步数或成本上限，Agent 陷入循环烧钱

    ✓设置最大轮数、token 预算与超时，超出即停止并汇报

  • ✗工具描述含糊，模型选错工具或传错参数

    ✓像写 API 文档一样写工具描述，附参数示例与边界

☑️ 08 · 检查清单
🎤 09 · 面试追问
为什么说 harness 和模型一样重要？

模型只能输出文本，能否完成任务取决于它看到的上下文、可用工具、错误反馈和停止策略。基准测试中同一模型换不同脚手架成绩差异明显，说明工程设计是能力的放大器或瓶颈。

上下文窗口快满时 harness 该怎么做？

常见做法：对早期历史做摘要压缩、丢弃冗长的工具输出只留结论、把中间产物写入文件按需读取、把子任务交给拥有独立上下文的子 Agent，主 Agent 只接收结果摘要。

设计工具时最重要的原则是什么？

让模型容易用对：名称和描述明确，参数少且有约束，返回结果精炼并包含可行动的错误信息。工具数量过多会增加选错概率，宜按任务精简，并用真实任务测试模型是否会正确调用。
