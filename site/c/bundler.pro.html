打包工具 (Vite / webpack)

Bundler

📐 01 · 定义

打包工具（Bundler）从入口文件出发解析模块依赖图，对 TypeScript、JSX、CSS 等进行转换，再经摇树、代码分割、压缩与文件名哈希，输出浏览器可高效加载的静态资源。Vite、webpack、esbuild、Rollup、Rspack 是代表。它属于前端构建层，同时提供带热更新的开发服务器。

⚙️ 02 · 原理
  1. 1

    从入口开始解析 import，按解析规则定位模块（node_modules、路径别名），构建依赖图。

  2. 2

    对每个模块应用转换：TS/JSX 编译、CSS 处理、资源导入、环境变量替换。

  3. 3

    生产构建做摇树移除未使用导出、按动态 import 分割代码块、压缩并生成带内容哈希的文件名。

  4. 4

    开发模式下，Vite 利用浏览器原生 ES 模块按需编译，并用 esbuild 预构建依赖；webpack 打包后提供服务。

  5. 5

    热模块替换（HMR）在文件变化时只替换受影响模块，保留页面状态。

🔤 03 · 术语
依赖图 (Module Graph)
模块间导入关系构成的图，是打包与分割的基础。
摇树 (Tree Shaking)
基于 ES 模块静态分析移除未被使用的代码。
代码分割 (Code Splitting)
把代码拆成多个块，按需或并行加载。
HMR (Hot Module Replacement)
开发时不刷新整页即替换已修改的模块。
Source Map
把压缩后代码映射回源码，便于调试与错误定位。
💻 04 · 代码
Vite 配置与体积分析typescript
// vite.config.ts
// npm i -D vite @vitejs/plugin-react rollup-plugin-visualizer
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";
import { visualizer } from "rollup-plugin-visualizer";

export default defineConfig({
  plugins: [
    react(),
    visualizer({ filename: "stats.html" }), // build 后生成体积分析图
  ],
  resolve: {
    alias: { "@": "/src" },               // 路径别名，需与 tsconfig 一致
  },
  build: {
    sourcemap: true,                        // 便于线上错误定位（注意是否公开）
    rollupOptions: {
      output: {
        manualChunks: { react: ["react", "react-dom"] }, // 第三方库单独成块
      },
    },
  },
});
// 注意：只有 VITE_ 前缀的环境变量会暴露给前端代码（import.meta.env）

先用可视化找出最大依赖再优化；前端可见的环境变量都会进入产物，不能放密钥。

优点开发体验好、配置简洁

🕳️ 07 · 常见坑

  • ✗把 API 密钥放在 VITE_ 变量中

    ✓前端变量全部公开可见，密钥只留在服务端

  • ✗开发环境正常、build 失败（大小写、循环依赖）

    ✓CI 中执行 build，保持导入路径大小写一致

  • ✗整库导入导致体积膨胀

    ✓按需导入或换用支持摇树的 ES 模块版本

  • ✗生产公开完整 source map 暴露源码

    ✓上传到错误监控平台后不随站点公开，或用 hidden source map

🎤 09 · 面试追问
Vite 开发服务器为什么启动快？

它不在启动时打包整个应用，而是利用浏览器原生 ES 模块，按需在请求时编译源码；对依赖用 esbuild 预构建并缓存。因此启动时间与项目规模基本无关，HMR 也只需处理变更模块。

摇树为什么需要 ES 模块？

ES 模块的 import/export 是静态的，打包工具可在构建时确定哪些导出被使用；CommonJS 的 require 是运行时动态求值，难以静态分析。另外有副作用的模块需在 package.json 的 sideEffects 中声明，否则不能安全删除。

如何系统地减小前端包体积？

可视化分析找出大依赖；路由级与组件级代码分割；替换臃肿库、按需导入；开启压缩与现代语法输出；图片字体单独优化；设置体积预算并在 CI 中检查。
