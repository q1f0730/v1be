📐 01 · 定义

黄金评测集（Golden Dataset）是一组经过精心挑选和人工审核的输入样例，配有期望输出或明确评分标准，用作衡量 LLM 应用质量的固定基准。每次修改提示词、模型、检索参数或代码时都在同一数据集上回归运行，量化改动的好坏。它是 LLM 工程中“评测驱动开发”的核心资产，需要像代码一样版本化维护。

⚙️ 02 · 原理
  1. 1

    从真实日志、用户反馈和已知故障中收集代表性输入，覆盖常见场景、边界情况和对抗样例。

  2. 2

    为每条样例编写参考答案或评分细则：精确值、必须包含的要点、禁止出现的内容，或结构化断言。

  3. 3

    选择评分方式：确定性检查（匹配、正则、JSON schema、代码执行）优先，难以规则化的用 LLM 评审并人工校准。

  4. 4

    把评测接入 CI 或发布流程：每次改动自动跑分，与基线对比，低于阈值则阻止上线。

  5. 5

    持续维护：把线上新发现的失败案例加入数据集，定期复审过时样例，并记录数据集版本。

🔤 03 · 术语
回归评测 (Regression Eval)
改动后在固定数据集上重跑，检查是否变差。
参考答案 (Reference Answer)
人工给出的期望输出，用于对比评分。
评分细则 (Rubric)
描述合格标准的可操作条目，供人或模型打分。
LLM 评审 (LLM-as-a-Judge)
用模型按细则给输出打分，需要与人工判断对齐。
数据泄露 (Leakage)
评测样例混入提示词或训练数据，导致分数虚高。
切片分析 (Slice Analysis)
按场景、难度等维度分别统计分数，定位短板。

def score(case: dict, output: str) -> bool:
    ok_in = all(k in output for k in case.get("must_include", []))
    ok_out = not any(k in output for k in case.get("must_not", []))
    return ok_in and ok_out

cases = [json.loads(l) for l in open("golden.jsonl", encoding="utf-8")]
results = {}
for c in cases:
    passed = score(c, run_app(c["input"]))
    results.setdefault(c["tag"], []).append(passed)

total = sum(sum(v) for v in results.values()) / len(cases)
for tag, v in results.items():                     # 按场景切片
    print(f"{tag:10s} {sum(v)}/{len(v)}")
print(f"总通过率 {total:.1%}")
assert total >= 0.85, "低于基线，阻止发布"        # 阈值按项目设定

确定性断言打分并按标签切片统计，接入 CI 后可作为提示词或模型变更的发布门禁。

📊 05 · 参数对比

评分方式对比

方式适用输出优点局限
精确/正则匹配分类标签、数值、格式快、稳定、免费无法评价开放式回答
结构断言JSON、函数调用参数可验证字段与类型不判断语义质量
执行验证代码、SQL直接验证正确性需要沙箱与测试用例
LLM 评审开放式文本可扩展、可评价语气与完整性有偏差，需人工校准
人工评审高风险或模糊任务最可靠慢且昂贵
⚖️ 06 · 方案取舍

小而精（几十到几百条）

优点维护成本低，可快速迭代

代价统计波动大

适用早期产品、频繁改提示词

大规模评测集

优点结论更稳定，可细分切片

代价标注与运行成本高

适用成熟产品、模型选型

线上采样持续补充

优点贴近真实分布变化

代价需要隐私处理与标注流程

适用长期运营的产品

🕳️ 07 · 常见坑

  • ✗评测样例只覆盖开发者想到的简单情况

    ✓从真实日志与失败案例中挑选，刻意加入边界与对抗样例

  • ✗把评测样例直接塞进 few-shot 示例

    ✓评测集与提示示例严格分离，防止泄露

  • ✗LLM 评审结果不经人工校准就信任

    ✓抽样对比人工打分，调整细则直到一致性可接受

  • ✗数据集不做版本管理，分数无法横向比较

    ✓数据集纳入版本控制，报告中注明数据集版本

☑️ 08 · 检查清单
🎤 09 · 面试追问
黄金评测集需要多大？

取决于要检测的效果差异。几十条足以发现明显退化，适合早期迭代；要区分细微差异或做模型选型，则需要数百条以上并按场景切片。关键是质量与覆盖度，而非盲目追求数量。

如何避免评测集过拟合？

反复针对同一评测集调提示词，可能让分数上升但真实效果不变。可保留一部分隐藏测试集只在重大发布时使用，定期加入新的线上样例，并结合线上指标与用户反馈综合判断。

LLM 评审如何与人工对齐？

先由人工标注一批样例，再让模型按细则打分，计算一致率或相关性；分析不一致样例，细化评分细则或改用成对比较；对齐达到可接受水平后再规模化使用，并定期抽查。
