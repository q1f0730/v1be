人类反馈强化学习 (RLHF)

RLHF

📐 01 · 定义

人类反馈强化学习（RLHF）是大模型对齐（alignment）阶段的训练方法：先收集人类对多个回答的偏好排序，训练奖励模型（Reward Model）学会打分，再用强化学习（常用 PPO）优化语言模型以获得更高奖励，同时用 KL 约束防止偏离原模型太远。

⚙️ 02 · 原理
  1. 1

    监督微调（SFT）：用人工撰写的示范回答微调预训练模型，得到初始策略。

  2. 2

    收集偏好：对同一提示采样多个回答，标注员比较好坏，形成 (chosen, rejected) 对。

  3. 3

    训练奖励模型：常用 Bradley-Terry 损失，使 chosen 的分数高于 rejected。

  4. 4

    强化学习优化：用 PPO 最大化奖励，并加入与参考模型的 KL 惩罚，避免奖励投机。

  5. 5

    迭代评估：用人工评测和基准检查有用性、无害性，必要时补充偏好数据再训练。

🔤 03 · 术语
奖励模型 (Reward Model)
输入提示和回答、输出标量分数，用于近似人类偏好。
PPO (Proximal Policy Optimization)
限制每步策略更新幅度的策略梯度算法，RLHF 经典选择。
KL 惩罚 (KL Penalty)
惩罚策略与参考模型分布差异，防止模型为刷分变得怪异。
奖励投机 (Reward Hacking)
模型利用奖励模型漏洞拿高分，实际质量并未提升。
DPO (Direct Preference Optimization)
直接用偏好对优化策略，无需显式奖励模型和 RL 循环。
RLAIF
用 AI 生成的偏好标签替代或补充人类标注。
💻 04 · 代码
奖励模型与 DPO 损失python
import torch.nn.functional as F

# 1) 奖励模型：Bradley-Terry 成对损失
#    r_chosen / r_rejected：奖励模型对两个回答的标量打分，形状 [batch]
def reward_loss(r_chosen, r_rejected):
    return -F.logsigmoid(r_chosen - r_rejected).mean()

# 2) DPO：直接用策略与参考模型的对数概率
#    logp_*：整段回答的 log 概率之和，形状 [batch]
def dpo_loss(pi_logp_c, pi_logp_r, ref_logp_c, ref_logp_r, beta=0.1):
    # 隐式奖励 = beta * (策略 logp - 参考 logp)
    chosen = beta * (pi_logp_c - ref_logp_c)
    rejected = beta * (pi_logp_r - ref_logp_r)
    return -F.logsigmoid(chosen - rejected).mean()

两者都在拉开 chosen 与 rejected 的差距；DPO 省去奖励模型和 PPO 采样循环。

📊 05 · 参数对比

偏好对齐方法对比

方法是否需奖励模型特点
RLHF (PPO)需要效果上限高，但训练不稳定、工程复杂
DPO不需要离线训练，简单稳定，依赖偏好数据质量
RLAIF视实现而定用 AI 标注降成本，需控制标注模型偏差
可验证奖励 RL用规则/测试替代适合数学、代码等可自动判对的任务
⚖️ 06 · 方案取舍

PPO 式 RLHF

优点在线采样，可持续探索更优回答

代价需同时维护多个模型，调参难

适用有大规模算力和成熟训练团队

DPO 等离线方法

优点实现简单，显存与算力需求低

代价无在线探索，易过拟合偏好集

适用中小团队做领域偏好微调

仅 SFT

优点最简单，可控性强

代价难以学到细粒度偏好与拒答边界

适用格式化任务、示范数据充足

🕳️ 07 · 常见坑

  • ✗去掉 KL 约束追求更高奖励，输出变得冗长讨好

    ✓保留 KL 惩罚并监控长度、多样性，结合人工评测

  • ✗偏好数据标注标准不一，奖励模型学到噪声

    ✓制定标注指南、计算标注者一致性，剔除争议样本

  • ✗只看奖励模型分数判断训练效果

    ✓用独立人工评测或留出基准验证，警惕奖励投机

🎤 09 · 面试追问
RLHF 里为什么要加 KL 惩罚？

奖励模型只是人类偏好的有限近似，策略若自由优化会找到其漏洞，生成高分但质量差的文本，同时丢失语言能力。KL 惩罚让策略保持在参考模型附近，在奖励和原有能力之间折中。

DPO 和 PPO 式 RLHF 的本质区别？

DPO 推导出最优策略与奖励的闭式关系，把奖励隐式表示为策略与参考模型的对数概率比，从而直接用偏好对做分类式训练；省掉奖励模型和在线采样，但失去在线探索能力。

RLHF 可能带来哪些副作用？

谄媚（迎合用户观点）、回答变长、过度拒答、多样性下降，以及校准性变差。根源多在偏好数据偏差和奖励投机，需要在数据、KL 系数和评测维度上共同控制。
