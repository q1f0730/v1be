多智能体协作

Multi-Agent Systems

📐 01 · 定义

多智能体系统（Multi-Agent System）是由多个具备独立提示词、工具和上下文的 LLM 智能体协作完成任务的架构，常见形态有编排者-工作者、流水线和对等协商。它位于 AI 应用编排层，用并行与分工突破单个上下文窗口和单一角色的限制，代价是更高的 token 成本与协调复杂度。

⚙️ 02 · 原理
  1. 1

    编排者分析任务，拆成可独立推进的子任务，并为每个子任务写清目标、边界和输出格式。

  2. 2

    工作者智能体在各自独立的上下文中并行执行，调用搜索、代码执行等工具。

  3. 3

    工作者只返回压缩后的结论与证据，避免把大量中间过程塞回编排者的上下文。

  4. 4

    编排者汇总结果，判断是否需要补充子任务、交叉验证或进入下一阶段。

  5. 5

    全流程记录追踪数据（每个智能体的输入、工具调用、token 消耗），用于调试与评测。

🔤 03 · 术语
编排者-工作者 (Orchestrator-Worker)
一个主智能体分派任务、汇总多个子智能体结果。
交接 (Handoff)
一个智能体把控制权和上下文移交给另一个智能体。
上下文隔离 (Context Isolation)
每个智能体只看到完成自身任务所需信息。
扇出/扇入 (Fan-out/Fan-in)
并行分发子任务，再统一收集结果。
智能体追踪 (Agent Tracing)
记录多智能体调用链路，定位哪一步出错。
💻 04 · 代码
编排者并行派发工作者python
import asyncio, os
import anthropic

client = anthropic.AsyncAnthropic()          # 读取 ANTHROPIC_API_KEY
MODEL = os.getenv("MODEL", "claude-sonnet-4-5")

async def ask(system: str, prompt: str) -> str:
    msg = await client.messages.create(
        model=MODEL, max_tokens=1024, system=system,
        messages=[{"role": "user", "content": prompt}],
    )
    return msg.content[0].text

async def research(question: str) -> str:
    # 1) 编排者拆解任务（真实系统中可让模型输出 JSON 子任务列表）
    subtasks = [f"{question}——技术原理", f"{question}——成本与风险"]
    worker_sys = "你是研究员。只回答分配的子问题，输出不超过 200 字的要点与依据。"
    # 2) 工作者并行执行，各自独立上下文
    results = await asyncio.gather(*(ask(worker_sys, t) for t in subtasks))
    # 3) 编排者汇总
    merged = "\n\n".join(results)
    return await ask("你是主编，整合以下要点，指出矛盾之处。", merged)

print(asyncio.run(research("是否应在产品中引入向量数据库")))

子任务并行、上下文隔离、结果压缩后汇总；模型名通过环境变量配置。

⚖️ 06 · 方案取舍

单智能体 + 工具

优点简单、便宜、易调试

代价上下文易被撑满，难并行

适用任务线性、规模中等

编排者-工作者

优点可并行，突破单窗口限制

代价token 成本显著上升，协调难

适用可拆分的广度型任务

固定流水线

优点行为可预期，易评测

代价灵活性差

适用流程稳定的生产任务

🕳️ 07 · 常见坑

  • ✗子任务描述模糊，多个工作者做重复的事

    ✓为每个子任务写明目标、范围、禁止事项与输出格式

  • ✗工作者把完整原始资料返回，撑爆编排者上下文

    ✓要求返回压缩摘要与引用，原始数据写入文件

  • ✗强耦合任务硬拆给多个智能体并行写同一文件

    ✓按依赖拆分；共享对象只交给一个智能体修改

  • ✗没有追踪，出错时不知道是哪个智能体

    ✓记录每个智能体的输入、工具调用和输出

🎤 09 · 面试追问
什么任务适合多智能体？

可拆成多个相对独立、可并行的子问题，且信息量超出单个上下文窗口的广度型任务，如大范围调研。强依赖、需要频繁共享状态的任务（如多数编码任务）收益较小，协调成本可能超过并行收益。

多智能体系统的主要成本在哪？

每个智能体都要独立加载指令与上下文，并行探索带来大量重复读取，token 消耗远高于单次对话；另外是调试与评测难度。Anthropic 工程博客提到其研究系统的 token 用量约为普通对话的 15 倍。

如何评测多智能体系统？

以最终结果为主做端到端评测（正确性、引用质量、完整性），可用 LLM 评审辅以人工抽检；同时统计成本、耗时与工具调用次数，并通过追踪定位失败发生在规划、执行还是汇总阶段。
