张量并行

Tensor Parallelism

📐 01 · 定义

张量并行（Tensor Parallelism，TP）是把单个层内部的权重矩阵切分到多张 GPU 上协同计算的模型并行方式，由 Megatron-LM（2019）推广。每张卡只保存和计算一部分权重，通过集合通信（如 All-Reduce）拼出完整结果。它用于模型单卡放不下或需要降低单请求延迟的训练与推理，通常限于 NVLink 等高带宽互联的单机多卡内。

⚙️ 02 · 原理
  1. 1

    MLP 层第一层线性按列切分：每卡持有部分输出列，各自独立计算并施加激活函数，无需通信。

  2. 2

    MLP 第二层线性按行切分：每卡用自己那份中间结果算出部分和，再通过一次 All-Reduce 求和得到完整输出。

  3. 3

    注意力层按注意力头切分：每卡计算若干个头，输出投影按行切分，同样以一次 All-Reduce 汇总。

  4. 4

    因此每个 Transformer 层前向大约需要两次 All-Reduce，通信量与批大小和隐藏维度成正比，频繁且同步。

  5. 5

    TP 常与流水线并行（按层分段，跨机）和数据并行（复制模型）组合；推理时 TP 规模通常需整除注意力头数。

🔤 03 · 术语
列并行/行并行 (Column/Row Parallel)
按输出维度或输入维度切分权重矩阵的两种方式，成对使用可减少通信。
All-Reduce
所有设备的张量求和后结果分发给每个设备的集合通信操作。
流水线并行 (Pipeline Parallelism)
按层把模型分段放到不同设备，适合跨节点，存在流水线气泡。
NVLink
NVIDIA GPU 之间的高带宽互联，显著优于 PCIe，是 TP 的常见前提。
序列并行 (Sequence Parallelism)
在 TP 基础上把 LayerNorm、Dropout 等沿序列维切分，进一步省显存。
💻 04 · 代码
用 NumPy 验证列/行切分等价python
import numpy as np

rng = np.random.default_rng(0)
x  = rng.standard_normal((4, 8))     # 批 4，隐藏维 8
W1 = rng.standard_normal((8, 16))    # MLP 上投影
W2 = rng.standard_normal((16, 8))    # MLP 下投影
relu = lambda t: np.maximum(t, 0)

full = relu(x @ W1) @ W2             # 单卡结果

tp = 2                               # 模拟 2 张卡
W1_parts = np.split(W1, tp, axis=1)  # 列切分：每卡 8x8
W2_parts = np.split(W2, tp, axis=0)  # 行切分：每卡 8x8

# 每卡独立计算部分和；激活函数逐元素，可在本卡完成
partials = [relu(x @ a) @ b for a, b in zip(W1_parts, W2_parts)]
out = sum(partials)                  # 相当于一次 All-Reduce

print(np.allclose(full, out))        # True

# 推理引擎中通常一个参数即可，例如：
# vllm serve <model> --tensor-parallel-size 4

列切分加行切分的组合让每个 MLP 只需一次求和通信；实际框架用 NCCL 在 GPU 间完成 All-Reduce。

⚖️ 06 · 方案取舍

增大 TP 规模

优点单卡显存需求下降，单请求延迟降低

代价通信占比上升，扩展效率递减

适用模型单卡放不下且有 NVLink

TP + 流水线并行

优点可跨多机部署超大模型

代价流水线气泡与调度更复杂

适用单机显存不足以容纳模型

量化后单卡部署

优点无卡间通信，部署简单

代价可能有精度损失

适用量化后能放进单卡且质量可接受

🕳️ 07 · 常见坑

  • ✗跨节点做张量并行，网络成为瓶颈

    ✓TP 限制在机内高速互联范围，跨机用流水线并行

  • ✗TP 规模不能整除注意力头数导致启动失败

    ✓按模型头数与 KV 头数选择 TP 规模

  • ✗以为卡数翻倍吞吐也翻倍

    ✓实测扩展效率，有时多个单卡或小 TP 副本吞吐更高

  • ✗忽略 PCIe 拓扑，卡间走跨 CPU 通道

    ✓用 nvidia-smi topo -m 检查拓扑，选择互联最好的卡组

🎤 09 · 面试追问
为什么 MLP 要先列切再行切？

第一层按列切，每卡得到中间激活的一部分，而激活函数逐元素，可在本卡直接计算无需通信；第二层按行切，每卡用本地中间结果算出完整形状的部分和，最后一次 All-Reduce 求和。若顺序相反，中间就需要额外的同步。

张量并行为什么一般不跨节点？

每层前向都有同步 All-Reduce，通信频繁且在关键路径上，跨节点网络带宽通常远低于机内 NVLink，延迟也更高，会让 GPU 大部分时间在等通信。跨节点更适合通信量小、只传激活的流水线并行。

推理时如何在 TP 和多副本之间选择？

若模型单卡放得下，多个独立副本没有卡间通信，总吞吐通常更高；TP 能降低单请求延迟并为 KV 缓存腾出空间。模型放不下时必须用 TP 或流水线。最终应在目标 SLO 下实测两种方案的吞吐与延迟。
