📐 01 · 定义

SQL（Structured Query Language，结构化查询语言）是操作关系型数据库的声明式语言，由 ISO/IEC 9075 标准化。开发者描述“要什么数据”，优化器决定“怎么取”。它分为 DDL、DML、DCL 和事务控制，PostgreSQL、MySQL、SQLite 均实现标准核心并各有方言。

⚙️ 02 · 原理
  1. 1

    DDL 用 CREATE TABLE 等定义表结构、数据类型、主键、外键和约束。

  2. 2

    DML 用 SELECT、INSERT、UPDATE、DELETE 读写数据，JOIN 根据关联列组合多张表。

  3. 3

    SELECT 的逻辑执行顺序为 FROM/JOIN、WHERE、GROUP BY、HAVING、SELECT、ORDER BY、LIMIT。

  4. 4

    数据库解析 SQL，优化器基于统计信息和索引生成执行计划，可用 EXPLAIN 查看。

  5. 5

    事务用 BEGIN、COMMIT、ROLLBACK 把多条语句组成原子单元，保证 ACID 特性。

🔤 03 · 术语
JOIN
按关联条件组合多表行，常见 INNER、LEFT 连接。
GROUP BY / 聚合函数
按列分组后用 COUNT、SUM、AVG 等计算汇总。
NULL
表示未知或缺失，比较需用 IS NULL，参与运算结果通常为 NULL。
事务 (Transaction)
一组要么全部成功、要么全部回滚的操作。
执行计划 (Query Plan)
数据库实际执行查询的步骤，用 EXPLAIN 查看。
💻 04 · 代码
建表、关联与聚合sql
CREATE TABLE users (
  id    INTEGER PRIMARY KEY,
  name  TEXT NOT NULL
);
CREATE TABLE orders (
  id      INTEGER PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  amount  NUMERIC NOT NULL,
  status  TEXT NOT NULL DEFAULT 'paid'
);

INSERT INTO users (id, name) VALUES (1, 'Ada'), (2, 'Lin'), (3, 'Mo');
INSERT INTO orders (user_id, amount) VALUES (1, 30), (1, 70), (2, 15);

-- 每个用户的订单数与总额，包括没有订单的用户
SELECT u.name,
       COUNT(o.id)              AS order_count,
       COALESCE(SUM(o.amount), 0) AS total
FROM users u
LEFT JOIN orders o ON o.user_id = u.id AND o.status = 'paid'
GROUP BY u.id, u.name
HAVING COUNT(o.id) < 3
ORDER BY total DESC;

LEFT JOIN 保留无订单用户；条件写在 ON 而非 WHERE，否则会把无订单的行过滤掉。

🕳️ 07 · 常见坑

  • ✗用 = NULL 判断空值

    ✓使用 IS NULL / IS NOT NULL

  • ✗LEFT JOIN 后在 WHERE 中过滤右表列

    ✓右表条件放到 ON 子句，否则退化为内连接

  • ✗SELECT * 用于生产查询

    ✓只选需要的列，减少 I/O 并避免结构变化影响

  • ✗UPDATE/DELETE 忘写 WHERE

    ✓先用 SELECT 验证条件，在事务中执行

🎤 09 · 面试追问
WHERE 和 HAVING 的区别？

WHERE 在分组前过滤行，不能使用聚合函数；HAVING 在 GROUP BY 之后过滤分组，可以使用聚合结果，例如 HAVING COUNT(*) > 5。能在 WHERE 中完成的过滤应尽量放在 WHERE，以减少参与分组的数据量。

INNER JOIN 和 LEFT JOIN 有何不同？

INNER JOIN 只返回两表都匹配的行；LEFT JOIN 返回左表所有行，右表无匹配时以 NULL 填充。常用于“包括没有订单的用户”这类需求。注意右表过滤条件位置，放在 WHERE 中会让 LEFT JOIN 退化为 INNER JOIN。

为什么说 SQL 是声明式的？

SQL 只描述想要的结果集，而不指定使用哪个索引、以什么顺序连接表。这些由优化器根据统计信息选择。好处是同一查询可随数据变化自动选择更优计划，代价是需要用 EXPLAIN 理解并引导实际执行方式。
