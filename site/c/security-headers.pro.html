安全响应头

Security Headers

📐 01 · 定义

安全响应头（Security Headers）是服务器在 HTTP 响应中下发的一组指令，让浏览器启用额外的安全行为：强制 HTTPS（HSTS）、禁止 MIME 嗅探、限制被嵌入、控制 Referer 泄露、禁用不需要的浏览器能力、隔离跨源窗口等。它们成本低、覆盖面广，是 Web 应用安全基线的一部分。

⚙️ 02 · 原理
  1. 1

    由服务器、反向代理或框架中间件在每个响应中统一添加这些安全头。

  2. 2

    Strict-Transport-Security 让浏览器在有效期内只用 HTTPS 访问该域名。

  3. 3

    X-Content-Type-Options: nosniff 禁止浏览器猜测内容类型，防止把上传文件当脚本执行。

  4. 4

    Referrer-Policy 控制跳转时发送多少来源信息，Permissions-Policy 禁用摄像头等能力。

  5. 5

    Content-Security-Policy 与 frame-ancestors 限制脚本来源与页面嵌入，跨源隔离头控制窗口关系。

🔤 03 · 术语
HSTS
RFC 6797 定义，强制浏览器只通过 HTTPS 访问。
HSTS 预加载 (Preload)
把域名写入浏览器内置列表，首次访问也强制 HTTPS。
MIME 嗅探 (MIME Sniffing)
浏览器无视 Content-Type 猜测类型的行为。
Permissions-Policy
控制页面及 iframe 可使用的浏览器功能。
COOP
Cross-Origin-Opener-Policy，隔离跨源窗口引用。
💻 04 · 代码
Nginx 统一下发安全头text
server {
    listen 443 ssl;
    server_name example.com;

    # always：错误页（4xx/5xx）也带上这些头
    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Content-Type-Options "nosniff" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;
    add_header Permissions-Policy "camera=(), microphone=(), geolocation=()" always;
    add_header Content-Security-Policy "frame-ancestors 'none'; object-src 'none'; base-uri 'none'" always;
    add_header X-Frame-Options "DENY" always;
    add_header Cross-Origin-Opener-Policy "same-origin" always;

    # 注意：location 块里若再写 add_header，
    # 不会继承这里的配置，需要重复声明
    location / {
        proxy_pass http://app:3000;
    }
}

# 验证：curl -sI https://example.com | grep -iE 'strict|nosniff|referrer|policy'

always 保证错误响应也带头；Nginx 子块写 add_header 会覆盖父级，是常见遗漏点。

⚖️ 06 · 方案取舍

网关/代理统一添加

优点覆盖所有服务，集中管理

代价难以按应用定制

适用通用安全头

应用中间件添加

优点可按页面精细配置

代价每个服务都需维护

适用CSP 等与应用强相关的头

HSTS 预加载

优点首次访问也受保护

代价撤销需要很长时间

适用确认全部子域永久支持 HTTPS

🕳️ 07 · 常见坑

  • ✗HSTS 一上来就设很长 max-age 并 preload

    ✓先用短 max-age 验证所有子域 HTTPS 正常，再逐步加长

  • ✗Nginx location 中新增 add_header 导致全局头丢失

    ✓在每个有 add_header 的块中重复声明，或使用 include 片段

  • ✗错误页不带安全头

    ✓Nginx 使用 always 参数

  • ✗继续依赖 X-XSS-Protection

    ✓该头已被主流浏览器移除支持，改用 CSP

🎤 09 · 面试追问
HSTS 解决什么问题，有什么风险？

防止用户首次输入 http 或点击 http 链接时被中间人劫持降级，浏览器在有效期内直接用 HTTPS。风险是配置后若某子域不支持 HTTPS 将无法访问，预加载后撤销需要很长时间，因此要逐步上线。

为什么需要 X-Content-Type-Options: nosniff？

浏览器可能无视 Content-Type 猜测内容类型，把用户上传的文本文件当作脚本或 HTML 执行。nosniff 要求浏览器严格按声明类型处理，配合正确的 Content-Type 防止此类攻击。

Referrer-Policy 为什么重要？

URL 中可能包含令牌、搜索词或内部路径，跳转第三方时会通过 Referer 泄露。strict-origin-when-cross-origin 在跨站时只发送源，降级到 HTTP 时不发送，兼顾分析需求与隐私。
