智能体权限安全

Agent Permission Security

🧸 回到小白版

📐 01 · 定义

智能体权限安全是为 AI Agent 设计访问控制的实践：按最小权限原则限定它能读写的文件、能执行的命令、能访问的网络与凭证，并对高风险操作要求人工确认。它针对的是提示注入、模型误判导致的越权操作和数据外泄，对应 OWASP 所说的过度授权（Excessive Agency）。

⚙️ 02 · 原理
  1. 1

    盘点能力：列出 Agent 可用的工具、文件系统范围、网络出口和凭证。

  2. 2

    最小授权：只开放完成任务所需的工具和路径，敏感文件（如 .env、密钥）显式拒绝。

  3. 3

    分级确认：只读操作可自动放行，写入、删除、部署、付款等需人工审批。

  4. 4

    隔离执行：在容器、虚拟机或沙箱中运行，限制网络出口，凭证用短期、低权限令牌。

  5. 5

    审计与回滚：记录所有工具调用，保留版本控制和备份，异常时可追溯与撤销。

🔤 03 · 术语
最小权限 (Least Privilege)
只授予完成当前任务所必需的最小权限集合。
提示注入 (Prompt Injection)
恶意文本混入输入或网页，诱导模型执行非预期指令。
过度授权 (Excessive Agency)
Agent 拥有超出需要的功能、权限或自主性而导致风险。
致命三要素 (Lethal Trifecta)
同时具备私有数据访问、接触不可信内容和外传能力时风险最高。
人在环 (Human-in-the-loop)
关键动作执行前需要人确认的机制。
💻 04 · 代码
Claude Code 权限配置json
{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Bash(git diff:*)",
      "Read(./src/**)"
    ],
    "ask": [
      "Bash(git push:*)"
    ],
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)",
      "Bash(curl:*)",
      "WebFetch"
    ]
  }
}

写在 .claude/settings.json：测试和查看自动放行，推送需确认，读取密钥和外联直接拒绝。

操作类型风险建议策略

⚖️ 06 · 方案取舍

白名单放行

优点默认安全，边界清晰

代价初期频繁弹确认，打断节奏

适用生产仓库、含敏感数据

沙箱内全自动

优点效率最高，Agent 可长时间自主

代价沙箱配置成本，需防网络外泄

适用一次性任务、可丢弃环境

逐条人工确认

优点每步可控

代价效率低，人容易疲劳盲点

适用首次接入陌生 Agent 或工具

🕳️ 07 · 常见坑

  • ✗为图省事开启跳过所有权限确认的模式在本机运行

    ✓只在无凭证、无敏感数据的容器或沙箱中使用全自动模式

  • ✗把长期、高权限的云凭证放在 Agent 可读的环境变量里

    ✓使用短期、最小权限的令牌，敏感文件加入 deny 规则

  • ✗认为写进系统提示的禁止事项就能防住注入

    ✓用工具层的硬性权限和网络隔离兜底，而非依赖模型自律

  • ✗接入第三方 MCP 服务器不审查其工具和权限

    ✓只用可信来源，审查工具描述，限制其可访问的数据

🎤 09 · 面试追问
为什么不能只靠系统提示约束 Agent？

模型会被提示注入或误解指令覆盖，系统提示只是软约束。权限必须在工具执行层强制：路径白名单、命令黑白名单、网络隔离、凭证最小化，让模型即便想做也做不到。

什么是致命三要素？怎么打破？

Agent 同时能访问私有数据、会读取不可信内容（网页、邮件、issue）、又能对外发送数据时，注入即可导致外泄。打破任意一环即可：去掉外传通道、隔离不可信输入，或不给私有数据。

给编码 Agent 设计权限，你会怎么分层？

按风险分层：读与测试自动放行；文件修改在 Git 管控下放行并审查 diff；push、部署、数据库迁移需确认；读密钥和任意外联默认拒绝。全自动只在一次性沙箱里开，并配审计日志。
