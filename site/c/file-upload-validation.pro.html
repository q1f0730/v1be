文件上传验证

File Upload Validation

📐 01 · 定义

文件上传验证（File Upload Validation）是在服务端对用户上传文件的类型、内容、大小、名称和存储方式进行多层校验与处置的安全实践。上传功能可能导致远程代码执行、存储型 XSS、路径穿越、恶意软件分发和资源耗尽，因此不能只依赖前端限制或客户端声明的 Content-Type。

⚙️ 02 · 原理
  1. 1

    在网关与应用层同时限制请求体大小和单次文件数量，防止资源耗尽。

  2. 2

    用扩展名白名单校验，并读取文件头魔数（Magic Bytes）确认真实类型。

  3. 3

    丢弃用户提供的文件名，由服务端生成随机名称，防止路径穿越和覆盖。

  4. 4

    存储在 Web 根目录之外或对象存储中，不赋予执行权限，下载时设置正确的 Content-Type 与 Content-Disposition。

  5. 5

    对图片重新编码以去除嵌入内容，必要时进行病毒扫描，并对 SVG、HTML 等可执行内容特殊处理。

🔤 03 · 术语
魔数 (Magic Bytes)
文件开头标识格式的固定字节，如 PNG 以 89 50 4E 47 开头。
路径穿越 (Path Traversal)
利用 ../ 等在文件名中跳出目标目录。
Content-Disposition: attachment
强制浏览器下载而非内联渲染文件。
预签名 URL (Presigned URL)
限时限权的上传或下载地址，让客户端直传对象存储。
多语言文件 (Polyglot File)
同时是多种合法格式的文件，可绕过单一检查。
💻 04 · 代码
FastAPI 上传多层校验python
import uuid
from pathlib import Path
from fastapi import FastAPI, UploadFile, HTTPException

app = FastAPI()
UPLOAD_DIR = Path("/srv/uploads")          # Web 根目录之外
MAX_BYTES = 5 * 1024 * 1024
SIGNATURES = {b"\x89PNG\r\n\x1a\n": ".png", b"\xff\xd8\xff": ".jpg",
              b"%PDF-": ".pdf"}

@app.post("/upload")
async def upload(file: UploadFile):
    data = await file.read(MAX_BYTES + 1)
    if len(data) > MAX_BYTES:
        raise HTTPException(413, "文件过大")
    # 按魔数判断真实类型，不信任文件名与 Content-Type
    ext = next((e for sig, e in SIGNATURES.items() if data.startswith(sig)), None)
    if ext is None:
        raise HTTPException(415, "不支持的文件类型")
    name = f"{uuid.uuid4().hex}{ext}"       # 服务端生成文件名
    (UPLOAD_DIR / name).write_bytes(data)
    return {"id": name}

演示大小、魔数、重命名、隔离存储四层；生产还应加病毒扫描并考虑图片重编码。

风险攻击方式对策

客户端直传对象存储

优点减轻服务器负载

代价校验需在上传后异步进行

适用大文件、高并发上传

经服务器中转校验

优点落盘前完成校验

代价占用带宽和内存

适用小文件、强校验需求

独立域名托管用户文件

优点隔离 Cookie 与同源风险

代价需额外域名配置

适用允许用户上传可渲染内容

🕳️ 07 · 常见坑

  • ✗只检查客户端传来的 Content-Type

    ✓该值由客户端控制，需读取文件内容判断

  • ✗扩展名黑名单拦截 .php

    ✓使用白名单，黑名单易被 .phtml 等变体绕过

  • ✗直接使用用户上传的原始文件名保存

    ✓生成随机文件名，原名仅作元数据并转义展示

  • ✗允许上传 SVG 并在主域名内联展示

    ✓SVG 可含脚本，需清洗或作为附件下载

🎤 09 · 面试追问
为什么不能只靠扩展名或 Content-Type？

两者都由客户端决定，攻击者可以随意伪造。扩展名白名单仍是必要的一层，但必须结合文件内容的魔数检测；对于图片等格式，重新解码再编码能进一步去除隐藏的恶意载荷。

用户上传的文件为什么建议放在独立域名？

如果用户上传的 HTML、SVG 在主域名下被浏览器渲染，其中的脚本就会以主站身份执行，能访问主站 Cookie 和接口，形成存储型 XSS。使用独立域名（不共享 Cookie 的源）托管，可把这种风险隔离出去。

直传对象存储时如何校验？

后端签发限定路径、大小、类型和有效期的预签名 URL；文件先上传到隔离区，由事件触发的后台任务检查魔数、扫描病毒、处理图片，通过后再移到正式位置并标记可用，未通过则删除。
