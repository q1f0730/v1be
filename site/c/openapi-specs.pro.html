📐 01 · 定义

OpenAPI 规范（OpenAPI Specification，前身 Swagger）是由 OpenAPI Initiative 维护、用 YAML/JSON 描述 HTTP API 的机器可读标准，覆盖路径、参数、响应、认证与数据模型。它是 API 契约层的事实标准，可驱动文档、SDK 生成、Mock、校验与测试。

⚙️ 02 · 原理
  1. 1

    文档顶层声明 openapi 版本、info 元数据与 servers，再在 paths 下按路径和方法描述操作。

  2. 2

    每个操作定义 parameters、requestBody 与按状态码区分的 responses，并给出媒体类型。

  3. 3

    复用的数据模型放在 components/schemas，通过 $ref 引用，3.1 起与 JSON Schema 完全对齐。

  4. 4

    securitySchemes 声明 Bearer、API Key、OAuth2 等认证方式，并在全局或操作级引用。

  5. 5

    工具链读取该文件生成交互文档、客户端 SDK、服务端桩代码，或在运行时校验请求响应。

🔤 03 · 术语
OpenAPI Initiative (OAI)
Linux 基金会下维护 OpenAPI 规范的组织。
$ref
JSON 引用，指向复用的组件定义。
operationId
操作的唯一标识，常用作生成 SDK 的方法名。
契约优先 (Design-first)
先写规范评审，再实现代码的开发方式。
代码优先 (Code-first)
从代码注解或类型自动生成规范。
💻 04 · 代码
最小 OpenAPI 3.1 文档yaml
openapi: 3.1.0
info: { title: Orders API, version: 1.0.0 }
servers:
  - url: https://api.example.com/v1
security: [{ bearerAuth: [] }]   # 全局认证
paths:
  /orders/{id}:
    get:
      operationId: getOrder
      parameters:
        - { name: id, in: path, required: true, schema: { type: integer } }
      responses:
        "200":
          description: 订单详情
          content:
            application/json:
              schema: { $ref: "#/components/schemas/Order" }
        "404": { description: 订单不存在 }
components:
  securitySchemes:
    bearerAuth: { type: http, scheme: bearer }
  schemas:
    Order:
      type: object
      required: [id, status]
      properties:
        id: { type: integer }
        status: { type: string, enum: [pending, paid, shipped] }

一个操作的路径参数、响应模型与认证方式；可直接喂给 Swagger UI 或 SDK 生成器。

⚖️ 06 · 方案取舍

契约优先

优点先评审接口，前后端可并行

代价需维护规范与实现一致

适用公开 API、多团队协作

代码优先

优点规范随代码自动更新

代价接口设计易被实现细节牵着走

适用内部服务、快速迭代

规范 + 运行时校验

优点保证实现不偏离契约

代价增加少量请求开销

适用对契约一致性要求高

🕳️ 07 · 常见坑

  • ✗规范写完就不更新，与实现越来越远

    ✓CI 中做契约测试或从代码生成，保证单一事实来源

  • ✗所有响应都只写 200，错误格式不描述

    ✓为 4xx/5xx 定义统一错误 schema

  • ✗混用 3.0 与 3.1 语法，如 nullable 与 type 数组

    ✓确定版本；3.1 用 type: [string, "null"]

  • ✗让 AI 凭空写规范，字段与实际接口不符

    ✓以真实代码或抓包为输入生成，再用工具校验

🎤 09 · 面试追问
OpenAPI 3.1 相比 3.0 的关键变化？

3.1 的 Schema Object 与 JSON Schema 2020-12 完全对齐，用 type 数组表达可空而非 nullable；新增顶层 webhooks 描述回调；paths 变为可选，便于只描述组件或 webhook。

OpenAPI 对 AI Agent 有什么用？

机器可读的接口描述可被转换为 LLM 工具/函数定义，Agent 据此知道有哪些操作、参数和返回结构；描述越准确，模型调用出错越少。

如何防止规范与实现漂移？

选一个事实来源：从代码生成规范，或从规范生成桩代码；在 CI 中跑契约测试或运行时校验，比较实际响应与 schema；变更走 PR 审查并检测破坏性差异。
