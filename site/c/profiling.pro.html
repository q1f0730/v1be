运行时性能剖析

Profiling

📐 01 · 定义

运行时性能剖析（Profiling）是在程序运行时采样或插桩，统计 CPU 时间、内存分配、锁等待、I/O 等资源消耗在各函数和调用栈上的分布，从而定位性能热点的技术。它比日志和指标更细，回答慢在哪行代码。常见工具有 perf、Go pprof、cProfile、py-spy 及持续剖析平台。

⚙️ 02 · 原理
  1. 1

    选择剖析维度：CPU 时间、墙钟时间、内存分配、堆占用、锁竞争或阻塞。

  2. 2

    采样式剖析器按固定频率中断程序、记录当前调用栈，开销较低，适合生产。

  3. 3

    插桩式剖析器在函数进出处计时，结果精确但开销大，适合开发环境。

  4. 4

    汇总大量调用栈样本，得出各函数的自身耗时和包含子调用的累计耗时。

  5. 5

    用火焰图、调用图或热点排行表查看结果，优化之后在相同负载下重新剖析对比。

🔤 03 · 术语
采样剖析 (Sampling Profiler)
定时抓取调用栈统计热点，开销低。
插桩剖析 (Instrumenting Profiler)
在函数入口出口插入计时代码，精确但开销大。
自身时间 (Self Time)
函数自身代码消耗的时间，不含其调用的子函数。
墙钟时间 (Wall-clock Time)
包含等待 I/O、锁等在内的真实经过时间。
持续剖析 (Continuous Profiling)
在生产环境长期低开销采样并存储剖析数据。
💻 04 · 代码
常用剖析命令bash
# Python：开发时用内置 cProfile，按累计耗时排序
python -m cProfile -s cumtime app.py

# Python：对线上进程采样，无需改代码、无需重启
py-spy top --pid 12345                              # 实时热点排行
py-spy record -o profile.svg --pid 12345 --duration 30  # 输出火焰图

# Go：服务引入 net/http/pprof 后，采集 30 秒 CPU 剖析并打开网页视图
go tool pprof -http=:8080 "http://localhost:6060/debug/pprof/profile?seconds=30"

# Linux：系统级 CPU 采样（99Hz，带调用栈）
perf record -F 99 -g -p 12345 -- sleep 30
perf report

开发期用 cProfile，线上用 py-spy、pprof、perf 等采样工具，开销小且不需改代码。

剖析维度与适用问题

维度回答的问题常用工具
CPU哪段代码最耗计算perf、pprof、py-spy
墙钟/阻塞时间花在等待什么pprof block、py-spy --idle

⚖️ 06 · 方案取舍

采样剖析

优点开销低，可用于生产

代价短函数可能统计不准

适用线上热点定位

插桩剖析

优点调用次数和耗时精确

代价开销大，可能扭曲结果

适用本地精细分析

持续剖析平台

优点随时回看任意时段

代价需要部署与存储成本

适用性能敏感的长期服务

🕳️ 07 · 常见坑

  • ✗凭直觉优化，没剖析就改代码。

    ✓先剖析定位热点，再针对性优化并对比。

  • ✗只看 CPU 剖析，问题其实是 I/O 等待。

    ✓CPU 利用率低但延迟高时，看墙钟或阻塞剖析。

  • ✗在调试构建或小数据量下剖析，结论不适用生产。

    ✓用接近生产的构建、数据和负载。

☑️ 08 · 检查清单
🎤 09 · 面试追问
采样剖析和插桩剖析如何选择？

采样剖析定时抓栈，开销低、对程序干扰小，适合生产与整体热点定位；插桩剖析精确记录每次调用，但开销大，可能改变程序行为，适合本地对小范围代码精细分析。通常先采样找方向，再局部深入。

CPU 剖析看不出问题，但接口很慢，怎么办？

说明时间多花在等待上，如数据库、网络、锁或线程池排队。应使用墙钟剖析或阻塞、锁剖析，结合分布式追踪查看各下游耗时，以及连接池和队列指标。

什么是持续剖析，有何价值？

在生产中长期以低频采样收集剖析数据并存储，可以回看任意时段、对比不同版本的热点变化，定位偶发性能问题和版本回归，而不必等问题重现时再手动抓取。
