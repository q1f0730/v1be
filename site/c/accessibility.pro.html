📐 01 · 定义

无障碍（Accessibility，常缩写为 a11y）指让残障人士及在各种设备、环境下的用户都能感知、理解、操作网页内容。W3C 的 WCAG 是主流标准，按可感知、可操作、可理解、健壮四原则组织，分 A/AA/AAA 三级，现行最新版本为 2.2。多地法规以 WCAG AA 为基准，它也直接提升 SEO 与整体可用性。

⚙️ 02 · 原理
  1. 1

    浏览器把 DOM 转换为无障碍树，读屏软件等辅助技术读取元素的角色、名称、状态与值。

  2. 2

    语义化 HTML（button、label、nav、h1–h6）自动提供正确的角色与键盘行为，是最主要的手段。

  3. 3

    原生元素无法表达时，用 WAI-ARIA 属性补充角色与状态；ARIA 只改语义，不添加行为。

  4. 4

    键盘用户依赖 Tab 顺序与可见焦点，所有交互都必须可用键盘完成且不陷入焦点陷阱。

  5. 5

    视觉方面需满足对比度、可缩放、不只靠颜色传达信息，动效需尊重减少动态偏好。

🔤 03 · 术语
WCAG
Web 内容无障碍指南，W3C 标准，AA 级是常见合规目标。
无障碍树 (Accessibility Tree)
浏览器提供给辅助技术的语义结构。
可访问名称 (Accessible Name)
辅助技术读出的元素名称，来自文本、label、aria-label 等。
WAI-ARIA
补充角色、状态与属性的规范；能用原生元素时不用 ARIA。
对比度 (Contrast Ratio)
WCAG AA 要求正文至少 4.5:1，大字号至少 3:1。
💻 04 · 代码
用 axe 在 E2E 中自动检测javascript
// npm i -D @playwright/test @axe-core/playwright
import { test, expect } from "@playwright/test";
import AxeBuilder from "@axe-core/playwright";

test("首页没有可自动检测的 WCAG A/AA 违规", async ({ page }) => {
  await page.goto("http://localhost:3000/");
  const results = await new AxeBuilder({ page })
    .withTags(["wcag2a", "wcag2aa"])
    .analyze();
  expect(results.violations).toEqual([]);
});

test("注册按钮可用键盘操作", async ({ page }) => {
  await page.goto("http://localhost:3000/signup");
  // 用角色和可访问名称定位：定位不到说明语义有问题
  const btn = page.getByRole("button", { name: "注册" });
  await btn.focus();
  await page.keyboard.press("Enter");
  await expect(page.getByRole("alert")).toBeVisible();
});

// 对应的正确标记：<label for="email">邮箱</label><input id="email" type="email">
//                 <button type="submit">注册</button>（不要用 div 假装按钮）

自动化工具只能发现部分问题，仍需键盘走查与读屏实测；按角色定位的测试同时约束了语义。

📊 05 · 参数对比

WCAG 四原则与常见要求

原则要求示例常见违规
可感知图片替代文本、对比度、字幕缺 alt、浅灰文字
可操作全键盘可用、可见焦点div 按钮、去掉焦点框
可理解表单标签、清晰错误提示只用占位符当标签
健壮语义正确、兼容辅助技术错误或冗余的 ARIA
⚖️ 06 · 方案取舍

语义化 HTML 优先

优点免费获得键盘与读屏支持

代价需克制「全用 div」的习惯

适用所有项目的默认做法

使用无障碍组件库

优点复杂控件交互已实现

代价仍需正确传入标签等属性

适用弹窗、下拉、标签页等控件

手写 ARIA 自定义控件

优点完全可控

代价极易出错，测试成本高

适用确无现成方案时

🕳️ 07 · 常见坑

  • ✗用 div/span 加 onClick 做按钮

    ✓使用 button 或 a 元素，自带焦点与回车/空格行为

  • ✗CSS 去掉 outline 又不提供替代焦点样式

    ✓使用 :focus-visible 提供清晰的焦点样式

  • ✗到处加 aria-label 甚至覆盖可见文本

    ✓优先可见文本与 label，ARIA 只用于补缺

  • ✗只跑自动化扫描就宣称合规

    ✓补充键盘走查、读屏测试与人工审查

🎤 09 · 面试追问
ARIA 的第一条使用规则是什么？

能用具有所需语义和行为的原生 HTML 元素时，就不要用 ARIA 去改造其他元素。ARIA 只改变辅助技术看到的语义，不提供键盘交互等行为，错误使用会比不用更糟。

自动化工具能发现多少无障碍问题？

只能覆盖可机器判定的一部分，如缺少 alt、对比度不足、标签缺失。替代文本是否有意义、焦点顺序是否合理、读屏体验是否通顺等需要人工测试，因此要组合自动化、键盘走查与辅助技术实测。

做 SPA 时有哪些特有的无障碍问题？

路由切换不刷新页面，读屏不会自动播报新页面：需更新 document.title、把焦点移到主标题或用实时区域通知；动态加载内容要用 aria-live 告知；弹窗需焦点锁定与关闭后焦点归还。
