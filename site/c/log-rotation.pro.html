日志轮转与清理

Log Rotation

📐 01 · 定义

日志轮转（Log Rotation）是按大小或时间把正在写入的日志归档成新文件，并压缩、限量保留、删除过期文件的机制。它属于主机与运行时的运维层，防止日志写满磁盘，并满足保留与合规要求。常见实现有 logrotate、journald 容量限制、Docker 日志驱动选项和 kubelet 容器日志轮转。

⚙️ 02 · 原理
  1. 1

    轮转工具按计划检查日志文件，满足时间（每日、每周）或大小阈值即触发。

  2. 2

    把当前文件重命名为带序号或日期的归档文件，再创建新文件供程序继续写入。

  3. 3

    程序仍持有旧文件句柄时，需要发信号让其重新打开文件，或使用复制后截断。

  4. 4

    旧归档按策略进行压缩，超过保留份数或保留天数的归档文件会被自动删除。

  5. 5

    在容器环境中，应用写 stdout，由运行时或 kubelet 负责轮转，再由采集器发送到集中日志系统。

🔤 03 · 术语
logrotate
Linux 常用的日志轮转工具，通过配置文件定义规则。
copytruncate
先复制日志再截断原文件，适用于无法重开文件的程序，可能丢少量日志。
postrotate 脚本
轮转后执行的命令，常用于通知进程重新打开日志。
json-file 驱动
Docker 默认日志驱动，需配置 max-size 和 max-file 才会轮转。
保留策略 (Retention Policy)
日志保存多长时间或多少份，兼顾排查、成本与合规。
💻 04 · 代码
logrotate 配置示例text
# /etc/logrotate.d/myapp
/var/log/myapp/*.log {
    daily                # 每天轮转
    maxsize 100M         # 不到一天但超过 100M 也轮转
    rotate 14            # 保留 14 份
    compress             # gzip 压缩归档
    delaycompress        # 最近一份暂不压缩，便于查看
    missingok            # 文件不存在不报错
    notifempty           # 空文件不轮转
    create 0640 myapp myapp
    sharedscripts
    postrotate
        # 通知进程重新打开日志文件（进程需支持 SIGHUP 或 USR1）
        systemctl kill -s HUP myapp.service
    endscript
}

轮转后通过信号让进程重开文件；不支持重开的程序可改用 copytruncate。

🕳️ 07 · 常见坑

  • ✗Docker 使用默认 json-file 不设上限，容器日志写满宿主机磁盘。

    ✓在 daemon.json 或运行参数中设置 max-size 与 max-file。

  • ✗轮转后没通知进程，程序继续写已被重命名或删除的文件。

    ✓用 postrotate 发信号重开，或改用 copytruncate。

  • ✗删除了仍被进程打开的大日志，磁盘空间不释放。

    ✓用 lsof 找到持有者并重启或截断，规范轮转流程。

  • ✗日志中含个人敏感信息且保留过久。

    ✓脱敏，并按合规要求设置保留期。

🎤 09 · 面试追问
copytruncate 和 create 模式有何区别？

create 模式重命名旧文件并新建文件，需要程序重新打开日志，否则会继续写旧文件；copytruncate 复制内容后截断原文件，程序无需配合，但复制与截断之间写入的日志可能丢失。能发信号重开时优先 create。

为什么删了日志文件磁盘空间还是没释放？

在 Linux 中，文件被删除后若仍有进程持有打开的句柄，数据块不会释放。可用 lsof 查看已删除但打开的文件，让进程重开文件或重启，规范地通过轮转工具处理。

容器化后还需要关心日志轮转吗？

需要。应用应写 stdout/stderr，但运行时仍会把日志落到节点磁盘，Docker json-file 默认不轮转，kubelet 有自己的大小和份数配置。同时需要采集器把日志发到集中系统，避免节点磁盘成为唯一存储。
