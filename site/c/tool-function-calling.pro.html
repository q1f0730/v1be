工具调用 (Function Calling)

Tool / Function Calling

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

工具调用（Tool / Function Calling）是让大模型以结构化方式请求执行外部函数的机制：开发者声明工具名称、描述和参数 schema，模型判断是否需要调用并输出调用参数，由应用程序真正执行后把结果回传给模型。它是 Agent 与外部世界交互的基础接口，模型本身不直接执行任何代码。

⚙️ 02 · 原理
  1. 1

    请求中附带 tools 列表，每个工具包括 name、description 和 JSON Schema 格式的参数定义。

  2. 2

    模型推理后若决定调用工具，返回一个或多个工具调用块，包含调用 ID、工具名和参数 JSON。

  3. 3

    应用解析参数、做校验和权限检查后执行真实函数，如查询数据库或调用第三方 API。

  4. 4

    把执行结果作为工具结果消息回传，并带上对应调用 ID，模型据此继续推理或给出最终回答。

  5. 5

    循环往复直到模型不再请求工具；tool_choice 可设置为自动、必须调用或指定某个工具。

🔤 03 · 术语
工具 schema (Tool Schema)
用 JSON Schema 描述工具参数，模型据此生成调用参数。
tool_choice
控制模型是否必须调用工具或调用指定工具的参数。
并行工具调用 (Parallel Tool Calls)
模型在一轮中同时请求多个互不依赖的工具。
工具调用 ID (Tool Call ID)
关联调用请求与执行结果的标识，回传时必须对应。
人在回路 (Human-in-the-Loop)
高风险工具执行前由人确认。
💻 04 · 代码
Anthropic 工具调用往返python
import anthropic, json
client = anthropic.Anthropic()
tools = [{
    "name": "get_weather",
    "description": "查询城市当前天气",
    "input_schema": {"type": "object",
        "properties": {"city": {"type": "string"}}, "required": ["city"]},
}]
msgs = [{"role": "user", "content": "上海现在热吗？"}]
r = client.messages.create(model="claude-sonnet-4-5", max_tokens=1024,
                           tools=tools, messages=msgs)
if r.stop_reason == "tool_use":
    call = next(b for b in r.content if b.type == "tool_use")
    result = {"city": call.input["city"], "temp_c": 31}   # 这里应调用真实接口
    msgs += [{"role": "assistant", "content": r.content},
             {"role": "user", "content": [{"type": "tool_result",
               "tool_use_id": call.id, "content": json.dumps(result)}]}]
    r = client.messages.create(model="claude-sonnet-4-5", max_tokens=1024,
                               tools=tools, messages=msgs)
print(r.content[0].text)

模型只产出调用请求，执行由代码完成；结果通过 tool_result 和 tool_use_id 回传。

📊 05 · 参数对比

工具设计要点

方面建议原因
命名与描述动词+对象，描述何时用、何时不用模型靠描述选择工具
参数少而明确，用枚举限定取值降低参数幻觉
返回值精简、结构化，含可读错误信息节省上下文，便于自我纠错
数量按任务提供相关子集工具过多会降低选择准确率
⚖️ 06 · 方案取舍

细粒度工具

优点组合灵活

代价调用轮次多，易选错

适用探索性 Agent 任务

粗粒度工作流工具

优点一步完成，可控

代价灵活性差

适用固定业务流程

执行前人工确认

优点防误操作

代价打断自动化

适用转账、删除、对外发送

🕳️ 07 · 常见坑

  • ✗直接执行模型给的参数，如拼 SQL 或 shell

    ✓严格校验参数，参数化执行，最小权限

  • ✗工具报错时抛异常中断整个流程

    ✓把错误信息作为工具结果回传，让模型调整

  • ✗把海量原始数据作为工具结果返回

    ✓在工具内过滤、分页、摘要后返回

  • ✗工具描述含糊，多个工具功能重叠

    ✓明确边界与使用时机，合并或删除重叠工具

🎤 09 · 面试追问
模型是如何“调用”函数的？

模型并不执行任何东西。工具定义被注入上下文，模型经过训练会在需要时输出特定格式的调用块，API 将其解析为结构化的工具名和参数返回给应用。应用执行后把结果放回对话，模型再基于结果继续生成。

如何提高工具选择的准确率？

写好描述，说明适用和不适用场景；减少同时暴露的工具数量，按任务动态加载；参数用枚举和必填约束；给出调用示例；用评测集统计选错率和参数错误率，针对性改描述。

工具调用有哪些安全风险？

参数注入导致 SQL/命令执行、越权访问数据、工具结果中的提示注入劫持后续行为、无限循环耗费资源。对策包括参数校验、最小权限凭证、高风险操作确认、把工具结果当不可信数据处理、限制轮次和预算。
