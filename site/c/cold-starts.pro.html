冷启动延迟

Cold Starts

📐 01 · 定义

冷启动（Cold Start）是函数或实例在没有可复用运行环境时，从零创建环境、加载运行时和代码、执行初始化后才能处理首个请求所产生的额外延迟。它常见于 Serverless（如 AWS Lambda、Cloud Run）和缩到零的服务，扩容时也会出现。治理手段包括减小包体、延迟初始化、预置并发和保持最小实例。

⚙️ 02 · 原理
  1. 1

    请求到达时若没有空闲的已初始化环境，平台需要新建执行环境或容器。

  2. 2

    平台下载代码包或镜像，启动运行时，如 Python 解释器或 JVM。

  3. 3

    执行函数处理器外的初始化代码：导入依赖、读取配置、建立数据库连接。

  4. 4

    初始化完成后才开始执行请求处理，用户感知到的额外延迟主要就来自前面这几步。

  5. 5

    环境处理完请求后会被保留一段时间复用，后续请求是热启动，直到被回收。

🔤 03 · 术语
热启动 (Warm Start)
复用已初始化的执行环境处理请求，没有初始化开销。
预置并发 (Provisioned Concurrency)
Lambda 中预先初始化并保持一定数量执行环境。
SnapStart
Lambda 对初始化后的环境做快照，冷启动时从快照恢复。
最小实例数 (Min Instances)
Cloud Run 等平台保持常驻的实例数，避免缩到零。
初始化阶段 (Init Phase)
Lambda 生命周期中运行处理器外代码的阶段。
💻 04 · 代码
Lambda 初始化放在外层python
import json
import os
import boto3

# 处理器外的代码只在冷启动时执行一次，热启动复用
TABLE = boto3.resource("dynamodb").Table(os.environ["TABLE_NAME"])

def handler(event, context):
    # 每次调用只做必要工作，复用外层创建的客户端
    item = TABLE.get_item(Key={"id": event["id"]}).get("Item")
    return {"statusCode": 200, "body": json.dumps(item, default=str)}

# 对延迟敏感的别名开启预置并发（AWS CLI）：
# aws lambda put-provisioned-concurrency-config \
#   --function-name orders-api --qualifier live \
#   --provisioned-concurrent-executions 5

客户端在初始化阶段创建并在热启动中复用；预置并发让一部分环境始终就绪。

📊 05 · 参数对比

冷启动治理手段

手段作用代价
减小依赖与包体缩短下载和导入时间需要裁剪依赖
延迟加载只在用到时初始化首次用到时仍有开销
预置并发/最小实例保持环境常驻按常驻时长计费
SnapStart/快照恢复跳过大部分初始化有运行时与唯一性等限制
⚖️ 06 · 方案取舍

缩到零

优点空闲零成本

代价首个请求冷启动

适用低频、对延迟不敏感

预置并发/最小实例

优点消除大部分冷启动

代价持续产生费用

适用面向用户的延迟敏感接口

改用常驻服务

优点延迟稳定

代价失去按调用计费的弹性

适用流量持续且稳定

🕳️ 07 · 常见坑

  • ✗在处理器内每次调用都新建 SDK 客户端和数据库连接。

    ✓在处理器外初始化并复用，注意连接数上限。

  • ✗打包整个大型依赖库，导入耗时数秒。

    ✓精简依赖，按需导入，或使用分层与容器镜像优化。

  • ✗用定时 ping 保温替代预置并发，并发突增时仍大量冷启动。

    ✓对关键路径使用平台提供的预置并发或最小实例。

  • ✗只看平均延迟，冷启动的长尾被掩盖。

    ✓关注 p99 延迟，并单独统计初始化耗时。

🎤 09 · 面试追问
冷启动延迟由哪些部分组成？

主要包括创建执行环境、下载代码或镜像、启动运行时、执行处理器外的初始化代码。语言运行时、包体大小、依赖导入和初始化中的网络调用都会影响时长。

Lambda 预置并发和 SnapStart 有何区别？

预置并发预先初始化并持续保持一定数量的执行环境，按时长计费，能基本消除这部分容量内的冷启动；SnapStart 对初始化完成的环境做快照，冷启动时从快照恢复，缩短初始化但不保证零延迟，并对运行时和代码有要求，如唯一性数据需在恢复后重新生成。

缩到零的服务如何兼顾成本与体验？

对用户直接访问的路径保持少量最小实例或预置并发；后台任务允许缩到零；优化启动时间；在前端用加载状态或异步处理掩盖首次延迟。
