大模型可观测 (Tracing)

LLM Observability

📐 01 · 定义

大模型可观测（LLM Observability）是在传统日志、指标、链路追踪之上，记录每次模型调用和 Agent 步骤的输入输出、token 用量、延迟、成本、工具调用与评测分数，以 trace/span 形式串起来。它解决的是 LLM 应用不确定、难调试、成本难控的问题。

⚙️ 02 · 原理
  1. 1

    埋点：通过 SDK 自动插桩或手动创建 span，包住模型调用、检索、工具调用等步骤。

  2. 2

    记录属性：模型名、参数、输入输出 token 数、耗时、错误、提示词版本等写入 span 属性。

  3. 3

    串联链路：同一次用户请求的所有步骤共享 trace ID，形成父子关系的调用树。

  4. 4

    导出与存储：经 OTLP 等协议发送到后端（如 Langfuse、Phoenix 或通用 APM）。

  5. 5

    分析与闭环：按成本、延迟、错误聚合看板；抽样 trace 做人工或自动评测，反哺提示词。

🔤 03 · 术语
Trace / Span
一次请求的完整链路及其中每个步骤的计时单元，可嵌套。
GenAI 语义约定 (GenAI Semantic Conventions)
OpenTelemetry 为生成式 AI 定义的 gen_ai.* 属性命名规范。
OTLP
OpenTelemetry 的标准传输协议，用于导出 trace、指标和日志。
首 token 延迟 (TTFT)
从发出请求到收到第一个输出 token 的时间，影响流式体验。
会话 (Session)
把同一用户多轮对话的多个 trace 归为一组便于回放。
💻 04 · 代码
手动为 LLM 调用建 spanpython
from openai import OpenAI
from opentelemetry import trace

tracer = trace.get_tracer("my-llm-app")
client = OpenAI()

def ask(question: str) -> str:
    # 一个 span 对应一次模型调用，属性名遵循 gen_ai.* 约定
    with tracer.start_as_current_span("chat gpt-4o-mini") as span:
        span.set_attribute("gen_ai.operation.name", "chat")
        span.set_attribute("gen_ai.request.model", "gpt-4o-mini")
        resp = client.chat.completions.create(
            model="gpt-4o-mini",
            messages=[{"role": "user", "content": question}],
        )
        span.set_attribute("gen_ai.response.model", resp.model)
        span.set_attribute("gen_ai.usage.input_tokens", resp.usage.prompt_tokens)
        span.set_attribute("gen_ai.usage.output_tokens", resp.usage.completion_tokens)
        return resp.choices[0].message.content

需另行配置 TracerProvider 与导出器；属性名采用 OTel GenAI 约定以便跨后端通用。

📊 05 · 参数对比

LLM 应用关键观测指标

指标含义用途
token 用量输入/输出 token 数成本核算、发现提示词膨胀
TTFT / 总延迟首 token 与完整响应耗时体验 SLO、模型选型
工具调用次数Agent 每轮调用工具数发现死循环与低效规划
评测分数裁判或用户反馈打分质量回归监控
⚖️ 06 · 方案取舍

专用 LLM 观测平台

优点提示词、评测、会话回放开箱即用

代价多一套系统，与现有 APM 割裂

适用LLM 是产品核心、需频繁调提示词

沿用通用 APM + OTel

优点与服务链路统一，复用告警体系

代价提示词管理和评测要自己补

适用LLM 只是系统中的一环

只打日志

优点零依赖，最快上手

代价无法串联多步，难做聚合分析

适用原型期、调用量很小

🕳️ 07 · 常见坑

  • ✗把完整提示词和用户隐私原文无脱敏写入 trace

    ✓对敏感字段脱敏或只存哈希，按合规要求设置保留期

  • ✗只记录最终回答，Agent 中间步骤不可见

    ✓为检索、每次工具调用、每轮规划都建子 span

  • ✗不记录提示词和模型版本，质量下降无从对比

    ✓把 prompt 版本、模型名作为 span 属性，支持按版本切片

🎤 09 · 面试追问
LLM 可观测和传统 APM 有什么不同？

传统 APM 关注延迟、错误率、吞吐；LLM 还要看输入输出内容、token 与成本、提示词版本和输出质量。输出不确定，所以需要回放具体 trace 并结合评测打分，而不仅仅看指标。

Agent 跑了 40 步才失败，怎么定位？

打开该请求的 trace 树，按 span 看每轮规划输出和工具调用参数/结果，找到首次偏离的步骤；对比成功 trace 的同一步。常见原因是工具返回过长被截断、错误信息未回传给模型、上下文溢出。

为什么推荐 OpenTelemetry 约定？

统一 gen_ai.* 属性名后，埋点与后端解耦，换观测平台不必改代码，且 LLM span 能与 HTTP、数据库 span 处在同一条链路。注意该约定截至 2026 年仍在演进，属性名可能调整。
