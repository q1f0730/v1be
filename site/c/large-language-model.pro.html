📐 01 · 定义

大语言模型（Large Language Model, LLM）是基于 Transformer 架构、在海量文本上做自监督预训练的神经网络，本质是「给定前文，预测下一个 Token 的概率分布」。经过指令微调和人类反馈对齐后，它成为对话、写代码、Agent 等上层应用的推理引擎，处在 AI 应用栈的模型层。

⚙️ 02 · 原理
  1. 1

    分词：输入文本先被 Tokenizer 切成 Token 序列，再映射为向量（Embedding）。

  2. 2

    编码上下文：多层 Transformer 用自注意力（Self-Attention）让每个 Token 参考前文所有 Token。

  3. 3

    预测分布：最后一层输出整个词表上的概率分布，表示下一个 Token 是谁的可能性。

  4. 4

    采样解码：按 temperature、top_p 等参数从分布中选出一个 Token，追加到序列末尾。

  5. 5

    自回归循环：重复「预测—采样—追加」，直到遇到停止符或达到 max_tokens 上限。

  6. 6

    训练三段：预训练学语言与知识，指令微调（SFT）学听话，RLHF 等对齐方法学偏好与安全。

🔤 03 · 术语
Transformer
2017 年提出的基于注意力机制的网络架构，几乎所有主流 LLM 的骨架。
自回归 (Autoregressive)
每次只生成一个 Token，并把它作为下一步的输入。
预训练 (Pre-training)
在大规模无标注语料上做下一个 Token 预测，学到通用语言能力。
指令微调 (Instruction Tuning / SFT)
用「指令—回答」样本继续训练，让模型按人类指令作答。
RLHF
基于人类反馈的强化学习，用偏好数据把模型输出往「有用、无害」方向调。
参数量 (Parameters)
模型中可训练权重的数量，影响能力上限与推理成本，但不是唯一指标。
💻 04 · 代码
调用一次 LLMpython
# pip install anthropic ；需设置环境变量 ANTHROPIC_API_KEY
import anthropic

client = anthropic.Anthropic()  # 自动读取环境变量中的 Key

resp = client.messages.create(
    model="claude-sonnet-4-5",   # 模型名以官方模型列表为准
    max_tokens=512,              # 输出上限，超出会被截断
    messages=[
        {"role": "user", "content": "用三句话解释什么是自回归生成"}
    ],
)

print(resp.content[0].text)      # 模型回复正文
print(resp.usage)                # 输入/输出 Token 数，用于核算成本
print(resp.stop_reason)          # end_turn 正常结束，max_tokens 表示被截断

LLM 对外就是一个无状态的 HTTP 接口：传入消息，返回文本和用量；多轮记忆要自己把历史传回去。

📊 05 · 参数对比

LLM 选型关键维度

维度影响什么评审时问什么
上下文长度一次能塞多少资料真实任务需要多长？长了是否掉质量
推理/思考能力复杂多步任务成功率有无扩展思考模式，延迟能否接受
工具调用能否接入 Agent 流程函数调用、结构化输出是否稳定
单价与延迟成本和用户体验按输入/输出分别计价，首 Token 延迟多少
部署方式数据合规与可控性闭源 API、云托管还是开源自部署
⚖️ 06 · 方案取舍

闭源 API 模型

优点能力强、免运维、迭代快

代价按量付费，数据出境与供应商锁定风险

适用原型期、追求效果、数据可外发

开源权重自部署

优点数据不出域，可微调，可控成本

代价需要 GPU 与运维，能力通常落后头部闭源

适用强合规、高调用量、需定制

小模型 + 检索增强

优点便宜、快、知识可更新

代价推理深度有限，依赖检索质量

适用问答、客服等知识密集场景

🕳️ 07 · 常见坑

  • ✗把 LLM 当数据库，直接信它报出的事实和数字

    ✓关键事实走检索或工具调用，并要求给出来源再核对

  • ✗以为 API 有记忆，第二次请求不带历史

    ✓接口是无状态的，多轮对话要自己维护并回传 messages

  • ✗只看榜单分数选模型

    ✓用自己业务的真实样本做小规模评测（eval）再定

  • ✗忽略 stop_reason，被截断的输出当完整结果用

    ✓检查是否因 max_tokens 截断，必要时续写或调大上限

🎤 09 · 面试追问
LLM 为什么会「一本正经胡说」？

训练目标是让续写在统计上合理，而非保证事实正确；模型没有内置的真假校验，知识有截止日期且被压缩在参数里。缓解手段：检索增强（RAG）、工具调用查实时数据、要求引用来源、降低 temperature、对输出做事后校验。

上下文越长越好吗？

不一定。长上下文增加成本和延迟；不少研究观察到模型对中间位置信息利用变差（Lost in the Middle）。实践上应检索最相关片段、精简历史、把关键指令放在开头或结尾，并用真实任务测长文效果。

预训练、SFT、RLHF 各解决什么？

预训练：在海量语料上学语言规律和世界知识；SFT：用指令—回答对教会模型按格式完成任务；RLHF 或 DPO 等偏好优化：让输出更符合人类偏好、更安全。三者依次叠加，分别对应「会说话」「听指令」「说得好」。
