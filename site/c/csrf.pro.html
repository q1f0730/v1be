跨站请求伪造

CSRF

📐 01 · 定义

跨站请求伪造（Cross-Site Request Forgery，CSRF）是恶意网站诱导已登录用户的浏览器向目标站点发送请求，借助浏览器自动携带的 Cookie 以用户身份执行非本意操作的攻击。它针对依赖 Cookie 等环境凭证认证的状态变更接口，攻击者通常看不到响应，只求操作生效。

⚙️ 02 · 原理
  1. 1

    用户已登录目标站点，浏览器中保存着该站点的会话 Cookie。

  2. 2

    用户访问攻击者页面，页面通过自动提交的表单、图片或脚本向目标站点发起请求。

  3. 3

    浏览器按规则自动附加目标站点的 Cookie，服务器无法仅凭 Cookie 区分请求是否出自用户本意。

  4. 4

    若接口只校验会话而不验证请求来源，就会执行转账、改邮箱等状态变更操作。

  5. 5

    防御方案让请求必须携带攻击者无法获取或伪造的信息，或拒绝跨站来源的请求。

🔤 03 · 术语
环境凭证 (Ambient Credential)
浏览器自动附带的凭证，如 Cookie、HTTP Basic 认证。
同步令牌模式 (Synchronizer Token)
服务端生成随机令牌嵌入表单，提交时校验。
双重提交 Cookie (Double Submit)
令牌同时放在 Cookie 和请求参数中比对，推荐签名版本。
Origin 头
浏览器在跨源和 POST 请求中附带的请求来源，可用于校验。
Fetch Metadata
Sec-Fetch-Site 等请求头，标明请求是否跨站。
💻 04 · 代码
Flask 同步令牌防护python
import secrets, hmac
from flask import Flask, session, request, abort

app = Flask(__name__)
app.secret_key = "replace-with-env-secret"   # 实际从环境变量读取

@app.get("/settings")
def settings_form():
    session.setdefault("csrf", secrets.token_urlsafe(32))
    return f'''<form method="post" action="/settings/email">
      <input type="hidden" name="csrf" value="{session['csrf']}">
      <input name="email"><button>保存</button></form>'''

@app.post("/settings/email")
def change_email():
    token = request.form.get("csrf", "")
    # 恒定时间比较，攻击者页面无法读取这个令牌
    if not hmac.compare_digest(token, session.get("csrf", "")):
        abort(403)
    # ... 更新邮箱
    return "ok"

演示原理；生产中优先使用框架内置 CSRF 中间件，如 Flask-WTF、Django CSRF。

优点成熟可靠

适用服务端渲染表单应用

SameSite + Origin 校验

优点无需令牌，实现轻

适用现代浏览器为主的 API

Authorization 头携带令牌

优点非环境凭证，天然免疫 CSRF

🕳️ 07 · 常见坑

  • ✗用 GET 请求执行状态变更

    ✓状态变更只用 POST/PUT/DELETE，GET 保持安全无副作用

  • ✗只依赖 SameSite 不做其他防护

    ✓配合 CSRF 令牌或 Origin 校验作为纵深防御

  • ✗CSRF 令牌放在 URL 中

    ✓放在请求体或自定义头，避免经 Referer 和日志泄露

  • ✗存在 XSS 时仍以为 CSRF 令牌有效

    ✓XSS 可读取令牌，必须先修复 XSS

🎤 09 · 面试追问
CSRF 和 XSS 有什么区别？

XSS 是在目标站点执行攻击者脚本，脚本能读写页面和发任意同源请求；CSRF 是在攻击者站点构造请求，借用户浏览器自动带的凭证让目标站点执行操作，通常读不到响应。存在 XSS 时，CSRF 防御基本失效。

用 Bearer Token 的 API 还需要防 CSRF 吗？

如果令牌放在 Authorization 头中由前端代码显式添加，浏览器不会自动携带，跨站页面无法读取它，因此天然不受 CSRF 影响。但若令牌放在 Cookie 中，就重新变成环境凭证，需要 CSRF 防护。

为什么 CORS 不能防 CSRF？

CORS 控制的是跨源脚本能否读取响应，而不是能否发送请求。简单请求（如表单 POST）不触发预检，会直接发到服务器并执行，只是攻击者读不到结果。CSRF 只需要请求被执行，因此 CORS 不能替代 CSRF 防护。
