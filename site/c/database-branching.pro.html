数据库分支 (Neon / PlanetScale)

Database Branching

📐 01 · 定义

数据库分支（Database Branching）指像 Git 分支一样，从某个时间点快速派生出一个独立可写的数据库副本，属于开发流程与数据库平台层。以 Neon 为代表的实现基于存算分离与写时复制（copy-on-write），创建分支不需要完整拷贝数据；PlanetScale 的分支则用于在隔离环境中开发 Schema 变更并通过部署请求合入生产。

⚙️ 02 · 原理
  1. 1

    存储层把数据保存为按页的版本历史，分支只是指向某个时间点（LSN）的元数据指针。

  2. 2

    创建分支时不复制数据，读取未修改的页直接共享父分支的历史版本。

  3. 3

    分支上发生写入时，只为被修改的页写入新版本（写时复制），父分支不受影响。

  4. 4

    每个分支有独立的连接串和计算资源，可接入预览部署或 CI 跑迁移与测试。

  5. 5

    验证通过后把 Schema 迁移应用到主分支（或 PlanetScale 的部署请求），临时分支删除。

🔤 03 · 术语
写时复制 (Copy-on-Write)
共享未修改数据，只在写入时为改动部分创建副本。
LSN (Log Sequence Number)
WAL 中的位置编号，可用于指定分支起点的时间点。
部署请求 (Deploy Request)
PlanetScale 中把分支的 Schema 变更合入生产的审核流程。
存算分离 (Separation of Storage and Compute)
存储与计算节点独立，分支可各自挂载计算。
数据脱敏 (Data Masking)
复制生产数据到分支时替换敏感字段，降低泄露风险。
💻 04 · 代码
PR 自动创建 Neon 分支yaml
# .github/workflows/preview-db.yml
name: Preview DB
on:
  pull_request:
    types: [opened, reopened, synchronize]
jobs:
  branch:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - id: neon
        uses: neondatabase/create-branch-action@v6
        with:
          project_id: ${{ vars.NEON_PROJECT_ID }}
          branch_name: preview/pr-${{ github.event.number }}
          api_key: ${{ secrets.NEON_API_KEY }}
      # 在分支上跑迁移，主库不受影响
      - run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ steps.neon.outputs.db_url }}

每个 PR 得到独立数据库分支并先跑迁移；PR 关闭时可用 delete-branch-action 清理。

隔离开发数据库方案对比

方案创建速度数据真实度成本
共享测试库无需创建低，常被改乱低
本地 Docker 库秒级低，需种子数据低

⚖️ 06 · 方案取舍

每个 PR 一个分支

优点迁移与测试完全隔离，可配预览环境

代价分支数量多，需自动清理

适用团队并行开发多

长期 dev/staging 分支

优点简单稳定

代价数据漂移，与生产差异变大

适用小团队、变更少

从生产派生并脱敏

优点数据贴近真实，复现问题容易

代价需要脱敏流程，合规要求高

适用排查生产数据相关 Bug

🕳️ 07 · 常见坑

  • ✗直接从生产派生分支给开发者，含真实用户隐私

    ✓派生后做脱敏，或从已脱敏的父分支派生

  • ✗以为分支能像 Git 一样自动合并数据

    ✓通常只合并 Schema 迁移，数据改动不会回流主库

  • ✗PR 关闭后分支不删，费用与连接数累积

    ✓CI 中在 PR 关闭事件里自动删除分支

  • ✗迁移只在分支上验证 Schema，没测锁与耗时

    ✓在接近生产数据量的分支上计时，评估锁表风险

🎤 09 · 面试追问
Neon 创建分支为什么快？

存储层保存页的历史版本，分支只是指向某个 LSN 的元数据；未修改的页与父分支共享，写入时才复制修改页，所以创建时间基本不随数据量增长。

数据库分支和 Git 分支有何关键区别？

Git 能三方合并任意文件改动；数据库分支一般只把 Schema 迁移合入主库，数据写入不会合并回去。分支的价值在于隔离测试与快速派生，而非数据合并。

在 AI 编程流程中数据库分支有什么用？

Agent 生成的迁移和破坏性操作可先在独立分支执行，失败直接丢弃；配合预览部署，让每个 Agent/PR 拥有隔离数据库，避免互相覆盖或误伤主库。
