📐 01 · 定义

Redis 是基于内存的键值数据存储，提供字符串、哈希、列表、集合、有序集合、流等数据结构，以单线程执行命令保证单条命令原子性。它常用作缓存、会话存储、限流计数器、轻量队列、排行榜与分布式锁，属于缓存与中间件层。2024 年起 Redis 许可证有变化，社区分支 Valkey 也广泛使用。

⚙️ 02 · 原理
  1. 1

    数据驻留内存，命令由单个主线程顺序执行，因此单命令天然原子；网络 I/O 可由多线程处理。

  2. 2

    可为键设置 TTL，到期自动删除；内存达上限时按淘汰策略（如 allkeys-lru）驱逐键。

  3. 3

    持久化可选 RDB 快照与 AOF 追加日志，用于重启恢复，但不应当作唯一数据源。

  4. 4

    高可用通过主从复制 + Sentinel 自动故障转移；Redis Cluster 把键空间分为 16384 个槽分片。

  5. 5

    MULTI/EXEC 事务、Lua 脚本或函数可把多个操作组合为原子执行。

🔤 03 · 术语
TTL
键的剩余生存时间，到期后自动删除。
淘汰策略 (Eviction Policy)
内存满时决定删除哪些键，如 LRU、LFU。
RDB / AOF
两种持久化方式：定期快照与写命令追加日志。
有序集合 (Sorted Set)
按分数排序的集合，常用于排行榜和延时队列。
Valkey
Redis 许可证变更后由 Linux 基金会托管的开源分支。
💻 04 · 代码
缓存、限流与锁python
# pip install redis
import json, time, uuid, redis

r = redis.Redis(host="localhost", port=6379, decode_responses=True)

# 1) 旁路缓存：先读缓存，未命中再查库并回填，带 TTL
def get_product(pid, load_from_db):
    key = f"product:{pid}"
    if (cached := r.get(key)) is not None:
        return json.loads(cached)
    data = load_from_db(pid)
    r.set(key, json.dumps(data), ex=300)   # 5 分钟过期
    return data
# 2) 固定窗口限流：每用户每分钟最多 60 次
def allow(user_id, limit=60):
    key = f"rl:{user_id}:{int(time.time() // 60)}"
    pipe = r.pipeline()
    pipe.incr(key)
    pipe.expire(key, 60)
    count, _ = pipe.execute()
    return count <= limit

# 3) 简单互斥锁：NX 保证只有一个持有者，EX 防止死锁
token = str(uuid.uuid4())
if r.set("lock:daily-report", token, nx=True, ex=30):
    try:
        pass  # 执行任务
    finally:
        if r.get("lock:daily-report") == token:  # 生产中应用 Lua 脚本原子比较并删除
            r.delete("lock:daily-report")

缓存必须带 TTL；锁释放要校验持有者，生产中用 Lua 脚本保证比较与删除的原子性。

⚖️ 06 · 方案取舍

Redis 作缓存

优点亚毫秒级读写，大幅减轻数据库压力

代价需处理一致性与缓存失效

适用读多写少的热点数据

Redis 作队列

优点部署简单、延迟低

代价持久化与投递保证弱于专业 MQ

适用轻量后台任务

Redis 作主存储

优点极快

代价内存成本高，持久化有丢数据窗口

适用可丢失或可重建的数据

🕳️ 07 · 常见坑

  • ✗Redis 无密码监听公网

    ✓只监听内网，启用 ACL/密码与 TLS，配合安全组

  • ✗缓存不设 TTL，内存持续增长

    ✓所有缓存键设过期时间，并配置 maxmemory 与淘汰策略

  • ✗生产环境执行 KEYS * 阻塞主线程

    ✓用 SCAN 渐进遍历，禁用或重命名危险命令

  • ✗存超大值（大 key）导致延迟尖刺

    ✓拆分大对象，监控大 key，并用 UNLINK 异步删除

🎤 09 · 面试追问
Redis 单线程为什么还这么快？

数据在内存，单条命令多为微秒级；单线程避免锁竞争与上下文切换；使用 I/O 多路复用处理大量连接；数据结构针对内存高度优化。较新版本还可把网络读写交给 I/O 线程。

用 SET NX EX 实现分布式锁有哪些问题？

释放时必须校验持有者令牌并原子删除；任务超时会导致锁过期后被他人获取，需要续期或使用防护令牌；主从异步复制下故障转移可能丢锁。对正确性要求极高时考虑基于共识的协调服务。

缓存与数据库如何保持一致？

常用旁路缓存：读时未命中回填，写时先更新数据库再删除缓存；配合 TTL 兜底；高并发下可用延迟双删或基于 CDC 的异步失效。强一致需求则不应依赖缓存读。
