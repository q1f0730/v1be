HTTP 与 HTTPS

HTTP vs HTTPS

📐 01 · 定义

HTTP 是 Web 的应用层请求—响应协议，本身以明文传输；HTTPS 是在 TLS 加密通道之上运行的 HTTP，提供机密性（防窃听）、完整性（防篡改）和服务器身份认证（防冒充）。现代浏览器把 HTTP 页面标记为不安全，许多 Web API 只在 HTTPS 下可用，HTTPS 已是上线的默认要求。

⚙️ 02 · 原理
  1. 1

    建立连接：客户端与服务器建立 TCP 连接（HTTP/3 则基于 UDP 上的 QUIC）。

  2. 2

    TLS 握手：协商协议版本与加密套件，服务器出示证书，双方用密钥交换算法协商会话密钥。

  3. 3

    证书验证：客户端检查证书链是否由受信任 CA 签发、域名是否匹配、是否在有效期内。

  4. 4

    加密传输：之后的 HTTP 请求与响应都用对称会话密钥加密并做完整性校验。

  5. 5

    强制升级：服务器可通过 301 重定向和 HSTS 头要求浏览器以后只用 HTTPS 访问。

🔤 03 · 术语
TLS
传输层安全协议，SSL 的继任者，当前主流为 TLS 1.2 与 1.3。
证书颁发机构 (CA)
签发数字证书、为网站身份背书的受信任机构。
HSTS
响应头告诉浏览器在一段时间内只能用 HTTPS 访问该站点。
混合内容 (Mixed Content)
HTTPS 页面加载 HTTP 资源，会被浏览器阻止或警告。
中间人攻击 (MITM)
攻击者在通信双方之间窃听或篡改流量。
💻 04 · 代码
检查 HTTPS 与证书bash
# 查看 TLS 握手与响应头（-v 显示详细过程）
curl -vI https://example.com 2>&1 | grep -E "SSL connection|subject:|expire date|HTTP/"

# 查看证书的签发者、有效期和域名
echo | openssl s_client -connect example.com:443 -servername example.com 2>/dev/null \
  | openssl x509 -noout -issuer -subject -dates

# 检查是否从 HTTP 跳转到 HTTPS
curl -sI http://example.com | grep -i -E "^HTTP|^location"

# 检查是否设置了 HSTS
curl -sI https://example.com | grep -i strict-transport-security

# 用 Let's Encrypt 的 certbot 为 Nginx 申请证书（服务器上执行）
# sudo certbot --nginx -d example.com

上线前用这几条命令确认：证书有效、HTTP 已跳转、HSTS 已开启。

📊 05 · 参数对比

HTTP 版本演进

版本传输层关键改进
HTTP/1.1TCP持久连接，但同连接请求排队
HTTP/2TCP（实践中基本配合 TLS）二进制分帧、多路复用、头部压缩
HTTP/3QUIC（基于 UDP）消除 TCP 队头阻塞，连接建立更快
⚖️ 06 · 方案取舍

免费自动化证书（如 Let's Encrypt）

优点免费、可自动续期

代价有效期短，依赖自动化运行正常

适用绝大多数网站

平台托管 HTTPS

优点零配置，平台自动签发续期

代价依赖平台

适用部署在 PaaS、CDN 上

商业证书（OV/EV）

优点包含组织验证信息，有商业支持

代价收费，加密强度并无区别

适用有合规或采购要求的企业

🕳️ 07 · 常见坑

  • ✗HTTPS 页面里引用 http:// 的脚本或图片

    ✓所有资源改用 https 或相对协议，消除混合内容

  • ✗代码里关闭证书校验（verify=False）图省事

    ✓修复证书问题本身，关闭校验等于放弃防中间人

  • ✗证书过期导致全站不可访问

    ✓配置自动续期并设置到期监控告警

  • ✗以为 HTTPS 能防所有攻击

    ✓HTTPS 只保护传输，应用层漏洞仍需另行防护

🎤 09 · 面试追问
TLS 为什么同时用非对称和对称加密？

非对称加密（或密钥交换算法）能在不安全信道上安全协商密钥并验证身份，但计算慢；对称加密速度快，适合大量数据。所以握手阶段用前者协商出会话密钥，传输阶段用后者加密数据。

HTTPS 下中间人还能看到什么？

能看到双方 IP、端口、流量大小与时间；通常还能看到 SNI 中的域名（除非启用 ECH）及 DNS 查询（除非用加密 DNS）。看不到 URL 路径、查询参数、请求头和正文。

本地开发需要 HTTPS 吗？

浏览器把 localhost 视为安全上下文，多数需要 HTTPS 的 API 在 localhost 下可直接用。但测试 Cookie 的 Secure 属性、第三方回调或局域网真机调试时，可以用 mkcert 等工具生成本地受信证书。
