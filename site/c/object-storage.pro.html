对象存储 (S3 / R2 / OSS)

Object Storage

📐 01 · 定义

对象存储（Object Storage）是以“桶（Bucket）+ 键（Key）+ 对象（数据与元数据）”为模型的扁平存储服务，通过 HTTP API 读写，容量和吞吐可近乎无限扩展，按存储量、请求数和流出流量计费。AWS S3 定义了事实标准 API，Cloudflare R2、阿里云 OSS、MinIO 等大多提供 S3 兼容接口，常用于存放图片、视频、备份与日志。

⚙️ 02 · 原理
  1. 1

    创建桶并设置区域、访问策略；对象以键名唯一标识，“目录”只是键名中的前缀约定。

  2. 2

    客户端通过 PUT/GET/DELETE 等 HTTP 请求操作对象，请求用 AWS Signature V4 等签名鉴权。

  3. 3

    后端可生成预签名 URL（presigned URL），在限定时间内授权浏览器直接上传或下载，不经过应用服务器。

  4. 4

    大文件使用分段上传（multipart upload），各分段并行上传后合并，失败可只重传单个分段。

  5. 5

    生命周期规则可自动转储到低频/归档存储或删除过期对象；版本控制可保留历史版本防止误删。

🔤 03 · 术语
桶 (Bucket)
对象的顶层容器，名称在命名空间内唯一，承载访问策略。
预签名 URL (Presigned URL)
带签名和过期时间的临时链接，授权特定操作。
分段上传 (Multipart Upload)
把大对象拆成多个分段上传后合并。
存储类别 (Storage Class)
标准、低频、归档等不同价格与取回时延的等级。
流出费 (Egress Fee)
数据从云存储传出到公网时收取的流量费。
版本控制 (Versioning)
同一键保留多个历史版本，可恢复被覆盖或删除的对象。
💻 04 · 代码
生成预签名上传链接（S3 / R2）python
import os, uuid
import boto3

# S3 兼容：换 R2 只需设置 endpoint_url（以官方文档为准）
s3 = boto3.client(
    "s3",
    endpoint_url=os.environ.get("S3_ENDPOINT"),  # R2: https://<ACCOUNT_ID>.r2.cloudflarestorage.com
    aws_access_key_id=os.environ["S3_KEY"],
    aws_secret_access_key=os.environ["S3_SECRET"],
    region_name=os.environ.get("S3_REGION", "auto"),
)

def presign_avatar_upload(user_id: str) -> dict:
    key = f"avatars/{user_id}/{uuid.uuid4()}.png"   # 服务端决定键名
    url = s3.generate_presigned_url(
        "put_object",
        Params={"Bucket": os.environ["S3_BUCKET"], "Key": key,
                "ContentType": "image/png"},
        ExpiresIn=600,                               # 10 分钟有效
    )
    return {"url": url, "key": key}

# 前端：fetch(url, {method: "PUT", headers: {"Content-Type": "image/png"}, body: file})

浏览器拿临时链接直传对象存储，服务器不承载文件流量；桶保持私有，键名由服务端生成。

⚖️ 06 · 方案取舍

浏览器预签名直传

优点节省服务器带宽，速度快

代价需在服务端校验结果与类型

适用用户上传图片、文件

经应用服务器中转上传

优点可在中途检查、压缩

代价占用服务器带宽与内存

适用需要实时处理的小文件

对象存储 + CDN 分发

优点降低延迟与流出费

代价缓存失效需管理

适用公开静态资源、媒体

🕳️ 07 · 常见坑

  • ✗桶开启公开读或公开列表

    ✓默认私有，按需用预签名 URL 或经 CDN 签名访问

  • ✗允许客户端指定任意键名，覆盖他人文件

    ✓键名由服务端生成并带用户前缀，限制可写范围

  • ✗只信任客户端声明的 Content-Type

    ✓上传后服务端校验魔数与大小，必要时异步扫描

  • ✗访问密钥权限过大并写进前端

    ✓最小权限密钥只留服务端，前端只拿临时 URL

🎤 09 · 面试追问
为什么不把文件直接存进数据库？

数据库为结构化小数据和事务优化，大文件会撑大表空间、拖慢备份与复制、挤占缓冲池。对象存储单价低、可无限扩展且支持 CDN 分发。通常只在数据库中保存对象键和元数据。

预签名 URL 的安全边界是什么？

它把指定操作（如对某个键的 PUT）在有效期内授权给任何持有链接的人。因此要限定键名、内容类型和较短有效期，链接不要写入日志或长期存储；上传后仍需服务端校验，不能因已签名就信任内容。

S3 的一致性模型如何？

自 2020 年 12 月起，S3 对所有 PUT、DELETE 提供强读后写一致性，写入成功后立刻读取即可得到最新数据，列举操作也一致。其他 S3 兼容服务的一致性需查阅各自文档。
