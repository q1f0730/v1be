📐 01 · 定义

模型限速与成本控制是调用商用 LLM API 时必须处理的两类约束：供应商按账号或组织限制每分钟请求数（RPM）和 token 数（TPM 等），超限返回 429；费用按输入、输出 token 分别计价。它属于 AI 应用的运维与财务治理层，需要重试退避、并发控制、预算告警和用量归因。

⚙️ 02 · 原理
  1. 1

    供应商按使用层级设定限额，常见维度为每分钟请求数、输入 token 数与输出 token 数。

  2. 2

    超限时返回 429 并可能附带 retry-after 头；客户端应退避重试而非立即重发。

  3. 3

    每次响应的 usage 字段给出输入、输出及缓存 token 数，乘以单价即得单次成本。

  4. 4

    降本手段包括：路由到小模型、提示词缓存、限制 max_tokens、批处理接口、精简上下文。

  5. 5

    按用户、功能、环境打标签汇总用量，设置预算阈值与告警，防止失控循环烧钱。

🔤 03 · 术语
RPM / TPM
每分钟请求数 / 每分钟 token 数限额。
使用层级 (Usage Tier)
按累计消费或充值提升限额的分级制度。
批处理接口 (Batch API)
异步批量提交请求，价格更低但不保证实时。
max_tokens
单次输出 token 上限，限制成本与长度。
成本归因 (Cost Attribution)
把 token 消耗分摊到用户、功能或团队。
💻 04 · 代码
限并发、退避与成本记录python
import asyncio
import anthropic

# SDK 自带对 429/5xx 的指数退避重试，可调 max_retries
client = anthropic.AsyncAnthropic(max_retries=5)
sem = asyncio.Semaphore(8)            # 控制并发，避免瞬间打满限额
PRICE_IN, PRICE_OUT = 3.0, 15.0       # 美元/百万 token，示例值，以官网为准

async def call(prompt: str, feature: str) -> str:
    async with sem:
        resp = await client.messages.create(
            model="claude-sonnet-4-5",
            max_tokens=512,               # 限制输出长度
            messages=[{"role": "user", "content": prompt}],
        )
    u = resp.usage
    cost = (u.input_tokens * PRICE_IN + u.output_tokens * PRICE_OUT) / 1e6
    print(f"[{feature}] in={u.input_tokens} out={u.output_tokens} ${cost:.5f}")
    return resp.content[0].text

async def main(prompts):
    try:
        return await asyncio.gather(*(call(p, "summarize") for p in prompts))
    except anthropic.RateLimitError:
        print("重试后仍被限流：降低并发或申请更高额度")

asyncio.run(main(["总结：…"] * 20))

信号量限并发，SDK 内置退避，按功能记录 token 与成本；价格为示例需以官网为准。

🕳️ 07 · 常见坑

  • ✗Agent 循环无上限，一晚上烧掉大量额度

    ✓设置步数、token 与金额上限，超限中止并告警

  • ✗收到 429 立即并发重试，形成重试风暴

    ✓遵循 retry-after，指数退避加抖动，并限制并发

  • ✗max_tokens 设得极大以防截断

    ✓按任务设合理上限，必要时检测截断后续写

  • ✗所有环境共用一个 API Key，无法归因

    ✓按环境/功能分 Key 或打标签，分别设预算

🎤 09 · 面试追问
429 和 529/503 应如何区别处理？

429 是你的账号超出限额，应退避、降并发或排队；529（Anthropic 的过载）或 503 表示服务端繁忙，与你的用量无关，同样退避重试，持续时可切换备用模型或供应商。

如何估算一个 AI 功能的成本？

统计典型请求的输入与输出 token（含系统提示、工具定义、历史和检索内容），乘以单价得单次成本，再乘以预期调用量；Agent 需乘以平均步数。上线后用实际 usage 校准。

为什么输出 token 通常更贵？

输入可以并行一次处理，输出必须逐 token 自回归生成，每步都要占用计算资源，吞吐更低，因此多数供应商的输出单价高于输入。控制输出长度往往是最直接的降本手段。
