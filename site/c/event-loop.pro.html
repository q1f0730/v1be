JS 事件循环 (Event Loop)

Event Loop

📐 01 · 定义

事件循环（Event Loop）是 JavaScript 运行时调度代码执行的机制。JS 在单个主线程上运行，事件循环不断从任务队列取出任务执行，每个任务结束后清空微任务队列，在浏览器中还会择机进行渲染。它属于语言运行时层（浏览器由 HTML 规范定义，Node.js 由 libuv 实现），决定异步代码的执行顺序与页面响应性。

⚙️ 02 · 原理
  1. 1

    同步代码在调用栈上执行，直到栈清空，期间无法被其他 JS 打断。

  2. 2

    定时器、网络、I/O、用户事件完成后，其回调作为任务（宏任务）进入对应任务队列。

  3. 3

    每执行完一个任务，运行时清空微任务队列：Promise 回调、queueMicrotask、MutationObserver 等，新加入的微任务也在本轮执行。

  4. 4

    浏览器在任务之间判断是否需要渲染，需要时执行 requestAnimationFrame 回调、样式、布局与绘制。

  5. 5

    Node.js 的事件循环分为 timers、poll、check 等阶段；process.nextTick 队列优先于 Promise 微任务执行。

🔤 03 · 术语
调用栈 (Call Stack)
记录当前正在执行的函数调用，栈空时才处理下一个任务。
任务 / 宏任务 (Task)
由 setTimeout、事件、消息等产生的回调，每轮循环取一个执行。
微任务 (Microtask)
Promise.then 等回调，在当前任务结束后、渲染前全部执行。
requestAnimationFrame
在下一次渲染前调用的回调，适合视觉更新。
长任务 (Long Task)
超过 50ms 的任务，阻塞输入响应与渲染。
💻 04 · 代码
判断执行顺序javascript
console.log("1 同步");

setTimeout(() => console.log("5 宏任务 setTimeout"), 0);

Promise.resolve()
  .then(() => console.log("3 微任务 then"))
  .then(() => console.log("4 微任务链中的下一个 then"));

queueMicrotask(() => console.log("3.5 微任务 queueMicrotask"));

(async () => {
  console.log("2 async 函数中 await 之前是同步");
  await null;
  console.log("3.6 await 之后进入微任务");
})();

// 实际输出顺序：1 → 2 → 3 → 3.5 → 3.6 → 4 → 5
// 规则：同步代码 → 清空微任务（按入队顺序）→ 下一个宏任务

微任务按入队顺序执行，链式 then 在前一个执行后才入队；setTimeout 最后。

📊 05 · 参数对比

常见异步 API 归类

API队列类型执行时机
Promise.then / await 之后微任务当前任务结束后立即
queueMicrotask微任务同上
setTimeout / setInterval任务（宏任务）延时到期后排队
requestAnimationFrame渲染步骤下一帧绘制前
process.nextTick（Node）nextTick 队列先于 Promise 微任务
⚖️ 06 · 方案取舍

拆分长任务（分块 + 让出）

优点保持页面响应

代价总耗时略增，代码变复杂

适用主线程必须处理的大量计算

Web Worker

优点真正并行，不阻塞主线程

代价不能直接操作 DOM，需消息通信

适用CPU 密集计算

scheduler.postTask / yield

优点按优先级调度

代价浏览器支持需确认

适用需要精细调度的应用

🕳️ 07 · 常见坑

  • ✗以为 setTimeout(fn, 0) 会立即执行

    ✓它至少要等当前同步代码和所有微任务完成

  • ✗在微任务里无限递归添加微任务

    ✓会饿死渲染和其他任务，循环处理应放进宏任务分批

  • ✗事件处理中做大量同步计算导致卡顿

    ✓拆分任务、让出主线程或移到 Worker

  • ✗Node 中用 nextTick 递归，阻塞 I/O

    ✓优先使用 setImmediate 或 Promise，避免饿死事件循环

🎤 09 · 面试追问
微任务和宏任务的核心区别？

每个宏任务执行完后，引擎会清空整个微任务队列，包括执行过程中新加入的微任务，然后才可能渲染并取下一个宏任务。因此微任务优先级更高，但滥用会阻塞渲染。

await 之后的代码在哪执行？

await 会暂停 async 函数，后续代码作为 Promise 的回调进入微任务队列；await 之前的部分是同步执行的。即使 await 一个非 Promise 值，后续代码也至少要等到当前同步代码结束后才执行。

JS 是单线程，如何处理大量并发请求？

I/O 由宿主环境（浏览器网络线程、libuv 线程池/系统异步接口）在后台完成，JS 线程只处理完成后的回调。单线程限制的是 JS 代码执行，而不是 I/O 并发。
