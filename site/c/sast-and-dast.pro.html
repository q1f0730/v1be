静态与动态安全测试 (SAST / DAST)

SAST & DAST

🧸 回到小白版
📐定义⚙️原理🔤术语💻代码📊参数对比⚖️方案取舍🕳️常见坑☑️检查清单🎤面试追问🔗延伸阅读
📐 01 · 定义

SAST（Static Application Security Testing，静态应用安全测试）在不运行程序的情况下分析源码、字节码或配置以发现漏洞；DAST（Dynamic Application Security Testing，动态应用安全测试）从外部对运行中的应用发起请求，观察响应以发现可利用问题。二者属于安全测试与 DevSecOps 层，常与 SCA（依赖漏洞扫描）、密钥扫描一起嵌入 CI。

⚙️ 02 · 原理
  1. 1

    SAST 解析代码为语法树或数据流图，按规则匹配危险模式，如未经处理的输入流入 SQL 拼接（污点分析）。

  2. 2

    SAST 在 IDE、提交或 PR 阶段运行，结果精确到文件与行号，便于开发者在编写时修复。

  3. 3

    DAST 先爬取或依据 OpenAPI 定义发现页面与接口，再发送注入、跨站脚本等攻击载荷。

  4. 4

    DAST 根据响应内容、状态码与时延判断漏洞，并检查安全头、Cookie 属性、TLS 等配置问题。

  5. 5

    两类结果汇总到告警平台，按严重度分级，设定阻断阈值，并跟踪误报处理与修复。

🔤 03 · 术语
污点分析 (Taint Analysis)
追踪不可信输入从来源到危险函数（sink）的数据流。
误报 / 漏报 (False Positive / Negative)
报告了不存在的问题 / 漏掉真实问题。
SCA (Software Composition Analysis)
扫描第三方依赖的已知漏洞与许可证。
IAST
交互式测试，在运行时通过插桩观察应用内部数据流。
SARIF
静态分析结果交换格式，GitHub 代码扫描等平台支持。
💻 04 · 代码
CI 中运行 Semgrep 与 ZAPyaml
# .github/workflows/security.yml
name: security
on: [pull_request]
jobs:
  sast:
    runs-on: ubuntu-latest
    container: semgrep/semgrep
    steps:
      - uses: actions/checkout@v4
      # 使用社区规则扫描，有发现时以非零退出码使任务失败
      - run: semgrep scan --config auto --error
  dast:
    runs-on: ubuntu-latest
    steps:
      # 对已部署的测试环境做被动基线扫描（不要对生产做主动攻击扫描）
      - run: |
          docker run --rm -t ghcr.io/zaproxy/zaproxy:stable \
            zap-baseline.py -t https://staging.example.com

SAST 每个 PR 运行；DAST 针对预发环境，基线扫描以被动检查为主。目标地址为示例。

📊 05 · 参数对比

应用安全测试方法对比

方法时机能发现局限
SAST编码/PR注入、硬编码密钥、危险 API误报较多，看不到运行时配置
DAST测试/预发环境可利用漏洞、配置与头部问题定位不到代码行，覆盖依赖爬取
SCA依赖变更时第三方组件已知 CVE只能发现已披露漏洞
IAST测试运行时带上下文的数据流漏洞需插桩，语言支持有限
⚖️ 06 · 方案取舍

只用 SAST

优点早发现、成本低、定位精确

代价误报多，运行时问题看不到

适用开发阶段的基础防线

只用 DAST

优点结果贴近真实攻击，误报相对少

代价发现晚、需可运行环境、难定位

适用上线前验证

SAST + DAST + SCA

优点覆盖代码、运行时与依赖

代价工具与告警治理成本

适用有一定规模、合规要求的产品

🕳️ 07 · 常见坑

  • ✗一次开启全部规则，告警淹没团队

    ✓先启用高置信度规则并只阻断高危，逐步扩大

  • ✗对生产环境跑主动 DAST 扫描

    ✓在预发或隔离环境扫描，生产只做被动检查并事先授权

  • ✗把扫描通过当作没有漏洞

    ✓扫描无法发现业务逻辑与越权问题，需威胁建模与人工评审

  • ✗AI 修复建议直接合并

    ✓修复后重新扫描并补充测试，确认未引入新问题

☑️ 08 · 检查清单
🎤 09 · 面试追问
SAST 为什么误报多，如何降低？

静态分析无法知道运行时数据和所有调用路径，只能保守推断。可通过调优规则、声明自定义清洗函数（sanitizer）、只启用高置信度规则、按路径排除测试代码来降低。

DAST 为什么发现不了越权（IDOR）问题？

越权需要理解业务含义：哪个用户可以访问哪个对象。通用扫描器通常不知道这些规则，需要多账号测试、手工渗透或专门编写的授权测试。

AI 编码时代 SAST 有什么新价值？

AI 生成代码速度快、量大，可能复制不安全模式；在 PR 中自动运行 SAST 是低成本的护栏，扫描结果还能直接交给 Agent 修复，再由扫描与测试复核。
