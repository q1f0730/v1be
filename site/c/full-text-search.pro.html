全文检索

Full-Text Search

📐 01 · 定义

全文检索（Full-Text Search）是对自然语言文本按“词”建立倒排索引并按相关性排序返回结果的技术。它解决 LIKE 模糊匹配无法用索引、不懂词形、无法排序的问题。可用数据库内置能力，也可用 Elasticsearch、OpenSearch、Meilisearch 等专用引擎。

⚙️ 02 · 原理
  1. 1

    分析（Analysis）：把文本切分为词元，做小写化、去停用词、词干还原；中文需要专门分词。

  2. 2

    建立倒排索引：记录每个词出现在哪些文档、出现位置与频率。

  3. 3

    查询时对检索词做同样的分析，在倒排表中查找并按布尔逻辑合并文档集合。

  4. 4

    相关性排序：按 TF-IDF、BM25 等模型给文档打分，可叠加字段权重和新鲜度。

  5. 5

    结果返回时可生成高亮片段；索引需随数据写入同步或异步更新。

🔤 03 · 术语
倒排索引 (Inverted Index)
从词到包含它的文档列表的映射结构。
分析器 (Analyzer)
分词器与过滤器的组合，决定文本如何变成词元。
词干还原 (Stemming)
把 running、runs 归一为 run 等词根。
BM25
主流相关性评分模型，考虑词频饱和与文档长度。
tsvector / tsquery
PostgreSQL 中已分析的文档与查询类型。
ngram 分词
按固定长度切分字符序列，常用于中日韩文本。
💻 04 · 代码
PostgreSQL 全文检索sql
-- 用生成列维护 tsvector（PostgreSQL 12+），标题权重高于正文
ALTER TABLE articles ADD COLUMN search tsvector
  GENERATED ALWAYS AS (
    setweight(to_tsvector('english', coalesce(title, '')), 'A') ||
    setweight(to_tsvector('english', coalesce(body,  '')), 'B')
  ) STORED;

-- GIN 倒排索引
CREATE INDEX articles_search_idx ON articles USING GIN (search);

-- 支持类似搜索引擎的语法：引号短语、OR、减号排除
SELECT id, title,
       ts_rank(search, q) AS rank,
       ts_headline('english', body, q) AS snippet
FROM articles,
     websearch_to_tsquery('english', '"connection pool" -mysql') AS q
WHERE search @@ q
ORDER BY rank DESC
LIMIT 20;

-- 注意：内置配置不会切分中文，中文需 zhparser/pg_jieba 等扩展

生成列自动随写入更新；GIN 索引加速 @@ 匹配，ts_rank 排序、ts_headline 高亮。

📊 05 · 参数对比

方案选型

方案中文支持优势局限
PostgreSQL FTS需扩展分词与业务数据同库同事务相关性与聚合能力有限
MySQL FULLTEXT内置 ngram 解析器零部署排序可调性弱
Elasticsearch/OpenSearch需中文分词插件相关性、聚合、扩展性强额外集群与同步链路

⚖️ 06 · 方案取舍

数据库内置全文检索

优点无同步延迟，运维简单

代价高级相关性调优能力弱

适用数据量中等、需求简单

专用搜索引擎

优点相关性、分面、高亮能力完善

代价需维护索引同步与一致性

适用搜索是核心功能

向量/混合检索

优点理解语义近义表达

代价成本高，精确匹配反而变弱

适用问答、RAG 与关键词互补

🕳️ 07 · 常见坑

  • ✗用 LIKE '%关键词%' 扛搜索

    ✓改用全文索引；模糊子串可考虑 pg_trgm

  • ✗中文直接用 english/simple 配置

    ✓接入中文分词扩展，或用 ngram 解析器

  • ✗查询和索引使用不同分析配置

    ✓两端使用同一语言配置与分析器

  • ✗搜索引擎与数据库不同步，删除后仍能搜到

    ✓用 CDC 或可靠事件同步，并定期全量校对

🎤 09 · 面试追问
倒排索引为什么比 LIKE 快？

LIKE '%x%' 前缀不确定，B-tree 无法使用，只能逐行扫描比较。倒排索引预先把词映射到文档列表，查询只需查几个词条的列表并做交并集，复杂度与命中量相关，而不是与全表大小相关。

BM25 相比 TF-IDF 改进了什么？

BM25 引入词频饱和：同一词出现很多次后得分增长趋缓（参数 k1）；并做文档长度归一化（参数 b），避免长文档仅因词多而占优。它是 Lucene 系引擎目前的默认相似度模型。

全文检索和向量检索怎么结合？

关键词检索擅长精确术语、编号、名称，向量检索擅长语义近似。常见做法是两路召回后融合排序（如 RRF 倒数排名融合），再用重排模型精排。RAG 系统中混合检索通常比单一方式召回更稳。
