📐 01 · 定义

TypeScript 是微软开发的 JavaScript 超集，在 JS 之上增加静态类型系统，编译时擦除类型输出普通 JavaScript。它属于开发工具与语言层，在编码阶段发现类型错误、提供精确的补全与重构。类型只在编译期生效，外部数据仍需运行时校验。对 AI 编码而言，类型是 Agent 最可靠的即时反馈之一。

⚙️ 02 · 原理
  1. 1

    开发者为变量、函数参数和返回值标注类型，或由编译器根据赋值自动推断。

  2. 2

    tsc 或编辑器语言服务进行类型检查，基于结构化类型判断兼容性：形状匹配即可赋值。

  3. 3

    联合类型、泛型、类型收窄等特性描述复杂数据，配合控制流分析在分支中精确推断类型。

  4. 4

    编译时擦除类型注解输出 JavaScript；也可用 esbuild、swc 只做转译，类型检查单独运行。

  5. 5

    外部数据（API 响应、表单）运行时没有类型保证，需用 Zod 等库校验并推导出类型。

🔤 03 · 术语
结构化类型 (Structural Typing)
按对象形状判断兼容，而非按名称或继承关系。
类型收窄 (Narrowing)
通过 typeof、in、判别字段等在分支中缩小类型范围。
严格模式 (strict)
tsconfig 中开启一组严格检查，包括 strictNullChecks。
unknown vs any
unknown 使用前必须收窄，any 关闭检查。
类型擦除 (Type Erasure)
编译后不保留类型信息，运行时无法依赖类型。
💻 04 · 代码
Zod 运行时校验推导类型typescript
import { z } from "zod";

// 一份 schema 同时提供运行时校验和静态类型
const User = z.object({
  id: z.number().int(),
  email: z.string().email(),
  role: z.enum(["admin", "member"]),
});
type User = z.infer<typeof User>;

async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const data: unknown = await res.json();   // 外部数据先当 unknown
  return User.parse(data);                   // 不符合则抛 ZodError
}

function label(u: User) {
  // role 是联合类型，switch 中会被收窄
  switch (u.role) {
    case "admin": return "管理员";
    case "member": return "成员";
  }
}

编译期类型由 schema 推导，避免“类型写着对、运行时数据却不对”。

📊 05 · 参数对比

tsconfig 关键选项

选项作用建议
strict开启全部严格检查新项目开启
noUncheckedIndexedAccess索引访问结果包含 undefined推荐开启
noEmit只检查不输出文件配合打包工具使用
skipLibCheck跳过 .d.ts 检查加快构建，常开启
⚖️ 06 · 方案取舍

strict 全开

优点最大化发现错误

代价初期类型工作量大

适用新项目、AI 生成代码多

渐进迁移（allowJs）

优点老项目平滑过渡

代价长期混合，检查不完整

适用大型 JS 遗留项目

JSDoc 类型注释

优点无需编译步骤

代价表达力和体验较弱

适用不想引入构建的小项目

🕳️ 07 · 常见坑

  • ✗用 as 断言让报错消失

    ✓用类型收窄或运行时校验，断言只用于确有把握处

  • ✗API 响应直接标注为某接口类型

    ✓外部数据当 unknown，用 schema 校验后再使用

  • ✗到处使用 any，类型检查形同虚设

    ✓用 unknown 代替，开启 noImplicitAny 并用 lint 限制

  • ✗AI 改完代码不跑类型检查就提交

    ✓把 tsc --noEmit 加入 Agent 的验证步骤和 CI

🎤 09 · 面试追问
TypeScript 的类型在运行时还存在吗？

不存在。编译时类型被擦除，运行时只有普通 JavaScript。因此类型只能保证代码内部一致，无法保证网络响应、用户输入等外部数据的形状，必须在边界用 Zod 等库做运行时校验。

any 和 unknown 的区别？

any 关闭类型检查，可以任意访问属性和赋值，错误会被静默传播。unknown 表示类型未知，必须通过 typeof、in 或 schema 校验收窄后才能使用。处理外部数据时应使用 unknown。

为什么说 TypeScript 对 AI 编码特别有价值？

类型检查能在几秒内给 Agent 提供精确、机器可读的错误反馈，帮助它发现幻觉出的属性名、错误参数和遗漏的分支，并定位到具体文件和行。类型定义本身也是 Agent 理解代码结构的高质量上下文。
