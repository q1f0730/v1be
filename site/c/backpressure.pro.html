反压 / 背压机制

Backpressure

🧸 回到小白版

📐 01 · 定义

反压（Backpressure）是数据流系统中下游把自身处理能力反馈给上游、迫使上游减速或暂停的流量控制机制。它出现在流处理库、消息系统、网络协议和服务调用链中，目的是避免生产快于消费时无界缓冲导致内存耗尽和延迟失控，把过载显式地传递回源头处理。

⚙️ 02 · 原理
  1. 1

    生产者与消费者之间放置有界缓冲区，容量就是系统愿意承受的积压上限。

  2. 2

    缓冲区满时，写入方被阻塞、收到 false 返回值或拒绝信号，而不是继续堆积。

  3. 3

    拉模式中消费者按需请求数据，如 Reactive Streams 的 request(n)，上游只发许可数量。

  4. 4

    压力沿链路逐级向上传递，最终到达可以减速、丢弃或拒绝的源头。

  5. 5

    TCP 滑动窗口是网络层的同类机制：接收窗口缩小，发送方自动放慢。

🔤 03 · 术语
有界队列 (Bounded Queue)
容量固定的缓冲区，满了就阻塞或拒绝写入。
需求信号 (Demand / request(n))
Reactive Streams 中下游声明还能接收多少元素的信号。
高水位线 (highWaterMark)
Node.js 流内部缓冲阈值，超过后 write() 返回 false。
流量控制 (Flow Control)
接收方控制发送方速率的机制，如 TCP 窗口、HTTP/2 流控。
无界缓冲 (Unbounded Buffer)
不设上限的队列，会把过载转化为内存增长和延迟。
💻 04 · 代码
asyncio 有界队列反压python
import asyncio

async def producer(q: asyncio.Queue):
    for i in range(1000):
        await q.put(i)        # 队列满时在这里等待 = 反压生效
    await q.put(None)        # 结束标记

async def consumer(q: asyncio.Queue):
    while (item := await q.get()) is not None:
        await asyncio.sleep(0.01)  # 模拟慢消费者
        q.task_done()

async def main():
    q = asyncio.Queue(maxsize=100)  # 有界：最多积压 100 条
    await asyncio.gather(producer(q), consumer(q))

asyncio.run(main())

maxsize 让生产者在队列满时挂起，速度被动对齐消费者，内存不会无限增长。

📊 05 · 参数对比

过载时的三种应对

策略行为代价
反压（阻塞/减速）让上游等待上游延迟增加，可能级联
丢弃（drop）超出部分直接丢数据丢失
缓冲（buffer）暂存积压内存与延迟上升，需设上限
拒绝（load shedding）返回错误如 503部分请求失败
⚖️ 06 · 方案取舍

阻塞式反压

优点不丢数据，实现简单

代价上游被拖慢，可能占满线程

适用批处理、管道内部

拉模式按需请求

优点消费者精确控制节奏

代价协议和实现更复杂

适用流式处理框架、跨服务数据流

缓冲加丢弃

优点上游不受影响

代价丢失数据，需可观测

适用指标、日志等可容忍丢失的流

🕳️ 07 · 常见坑

  • ✗Node.js 中忽略 write() 返回 false，持续写入导致内存暴涨。

    ✓返回 false 时暂停，等 'drain' 事件再写，或用 pipeline()。

  • ✗服务间用无界内存队列转发请求。

    ✓所有队列设上限，满时反压或拒绝。

  • ✗反压一路传到用户请求线程，所有请求都卡住。

    ✓在边界处配合超时和负载卸载，快速失败。

☑️ 08 · 检查清单
🎤 09 · 面试追问
反压和负载卸载有什么区别？

反压是让上游慢下来，压力被传递而非丢弃；负载卸载是主动拒绝部分请求以保护自身。数据管道内部倾向反压，面向外部请求的入口更适合卸载，因为无法让用户等无限久。

为什么无界队列是危险的？

它把吞吐不足转化为排队延迟和内存增长，系统看似正常实际越来越慢，最终 OOM。并且排队的请求可能早已超时，处理它们纯属浪费。有界队列让过载尽早显性化。

Node.js 流怎样处理反压？

可写流内部缓冲超过 highWaterMark 时 write() 返回 false，生产方应暂停直到 'drain' 事件；使用 stream.pipeline() 或 pipe() 会自动处理暂停与恢复，并统一传播错误。
