📐 01 · 定义

UI 组件库是预先实现好的一组界面组件与设计规范的集合，按形态可分为带样式的成品库（Ant Design、MUI）、只提供行为与无障碍逻辑的无头库（Radix UI、React Aria），以及 shadcn/ui 这类「复制源码到项目」的组件集。它属于前端设计系统层，决定开发效率、视觉一致性与可定制程度。

⚙️ 02 · 原理
  1. 1

    组件库把按钮、表单、弹窗、表格等常见交互封装好，并处理键盘操作、焦点管理与 ARIA 属性。

  2. 2

    成品库以 npm 依赖形式引入，通过主题令牌（颜色、圆角、间距）统一定制外观。

  3. 3

    无头库只输出状态与交互逻辑，样式完全由使用者用 CSS 或 Tailwind 自定义。

  4. 4

    shadcn/ui 通过 CLI 把基于 Radix 与 Tailwind 的组件源码复制进项目，代码归你所有，可直接修改。

  5. 5

    AI 生成界面时，若规则文件指定了组件库，模型会复用其组件与命名，输出更一致。

🔤 03 · 术语
设计令牌 (Design Tokens)
颜色、字号、间距等设计变量，主题定制的基础。
无头组件 (Headless UI)
只提供逻辑与无障碍行为、不带样式的组件。
Radix UI Primitives
React 无头组件库，shadcn/ui 的大部分交互组件基于它。
components.json
shadcn/ui 的项目配置，记录样式风格、路径别名等。
WAI-ARIA 模式
W3C 给出的常见控件无障碍交互规范，组件库应遵循。
💻 04 · 代码
用 shadcn/ui 组装弹窗typescript
// 先在终端初始化并添加组件（源码会复制到 components/ui/）：
//   npx shadcn@latest init
//   npx shadcn@latest add button dialog
import { Button } from "@/components/ui/button";
import {
  Dialog, DialogContent, DialogDescription,
  DialogHeader, DialogTitle, DialogTrigger,
} from "@/components/ui/dialog";

export function DeleteConfirm({ onConfirm }: { onConfirm: () => void }) {
  return (
    <Dialog>
      <DialogTrigger asChild>
        <Button variant="destructive">删除项目</Button>
      </DialogTrigger>
      <DialogContent>
        <DialogHeader>
          <DialogTitle>确定删除？</DialogTitle>
          <DialogDescription>此操作无法撤销。</DialogDescription>
        </DialogHeader>
        <Button onClick={onConfirm}>确认删除</Button>
      </DialogContent>
    </Dialog>
  );
}

焦点锁定、Esc 关闭、ARIA 标注由底层 Radix 处理；源码在项目中，可直接改样式。

⚖️ 06 · 方案取舍

成品样式库

优点组件全、开箱即用，适合后台

代价风格辨识度强，深度定制难

适用中后台、内部工具

shadcn/ui 源码式

优点完全掌控代码，AI 生态示例多

代价升级需自行合并，维护责任在己

适用面向用户的产品、需品牌化

无头库 + 自研样式

优点设计自由与无障碍兼得

代价样式工作量大

适用有设计团队的设计系统

🕳️ 07 · 常见坑

  • ✗同一项目混用多个组件库

    ✓规则文件中指定唯一组件库，Code Review 时拦截

  • ✗直接覆盖组件内部类名做定制

    ✓通过主题令牌或组件暴露的 props/变体定制

  • ✗以为用了组件库就自动满足无障碍

    ✓仍需补 label、alt 和焦点顺序，并用工具与键盘实测

  • ✗随意修改 shadcn 组件后无法追溯

    ✓改动集中在 variants，提交信息注明定制原因

🎤 09 · 面试追问
shadcn/ui 与传统 npm 组件库的核心区别？

传统库作为依赖安装，源码在 node_modules，通过 props 与主题定制，升级即换版本；shadcn/ui 用 CLI 把组件源码复制进项目，开发者拥有并直接修改代码，灵活但上游更新要手动合并。

为什么无头组件库越来越流行？

复杂控件的难点在于键盘交互、焦点管理和 ARIA 语义，而非外观。无头库把这些难点封装好，样式交给团队，使品牌化设计与无障碍兼得，也能与 Tailwind 等方案自然配合。

如何让 AI 生成的界面风格稳定？

在规则文件中固定组件库、导入路径、主题令牌与禁用写法；提供一两个标准页面作为参照；让 Agent 优先复用现有组件；结合 Lint 规则和视觉回归测试拦截偏离。
