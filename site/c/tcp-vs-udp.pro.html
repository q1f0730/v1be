TCP 与 UDP

TCP vs UDP

📐 01 · 定义

TCP 与 UDP 是传输层的两种核心协议，都建立在 IP 之上，用端口区分应用。TCP 面向连接，提供可靠、有序、带流量控制和拥塞控制的字节流；UDP 无连接，只做最小封装，不保证送达与顺序，但开销小、延迟低。HTTP/1.1 与 HTTP/2 跑在 TCP 上，HTTP/3 则基于 UDP 之上的 QUIC。

⚙️ 02 · 原理
  1. 1

    TCP 通过三次握手（SYN、SYN-ACK、ACK）建立连接，双方协商初始序列号。

  2. 2

    TCP 发送的每个字节都有序列号，接收方回复确认（ACK）；超时或重复确认触发重传，接收端按序重组。

  3. 3

    TCP 用滑动窗口做流量控制，用拥塞控制算法（如 CUBIC、BBR）根据丢包或延迟调整发送速率。

  4. 4

    UDP 直接把数据报加上源/目的端口、长度和校验和发出，不建立连接、不确认、不重传。

  5. 5

    应用可在 UDP 之上自行实现所需的可靠性，例如 QUIC 实现了加密、多路复用和按流重传。

🔤 03 · 术语
三次握手 (Three-way Handshake)
TCP 建立连接的 SYN、SYN-ACK、ACK 交换过程。
队头阻塞 (Head-of-Line Blocking)
一个丢失的包阻塞其后所有数据的交付。
拥塞控制 (Congestion Control)
根据网络状况调节发送速率，避免压垮网络。
数据报 (Datagram)
UDP 的独立消息单元，有边界，可能丢失或乱序。
QUIC
基于 UDP 的加密多路复用传输协议，HTTP/3 的底座。
MTU
链路单个帧可承载的最大字节数，影响分片与丢包。
💻 04 · 代码
用 socket 对比 TCP 与 UDPpython
import socket

# TCP：先建立连接，再收发字节流
tcp = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
tcp.connect(("example.com", 80))          # 触发三次握手
tcp.sendall(b"HEAD / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n")
print(tcp.recv(200).decode(errors="ignore").splitlines()[0])
tcp.close()

# UDP：无连接，直接发数据报（这里发一个 DNS 查询示意）
udp = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp.settimeout(2)                          # 可能丢包，需要自己处理超时
query = bytes.fromhex("abcd01000001000000000000") + \
        b"\x07example\x03com\x00" + b"\x00\x01\x00\x01"
udp.sendto(query, ("1.1.1.1", 53))
data, _ = udp.recvfrom(512)
print("DNS 响应字节数:", len(data))
udp.close()

TCP 需 connect 握手、sendall 保证全部送出；UDP 直接 sendto，超时与丢包由应用负责。

⚖️ 06 · 方案取舍

TCP

优点可靠有序，生态成熟，穿透防火墙容易

代价握手延迟、队头阻塞

适用网页、API、文件传输、数据库

UDP 原生

优点延迟最低，开销小

代价需自行处理丢包与乱序

适用实时音视频、游戏状态同步

QUIC（UDP 之上）

优点0-RTT/1-RTT 建连，无 TCP 层队头阻塞

代价部分网络限制 UDP，CPU 开销更高

适用移动网络、HTTP/3

🕳️ 07 · 常见坑

  • ✗以为一次 recv 就能收到完整消息

    ✓TCP 是字节流，需按长度前缀或分隔符自行分帧

  • ✗用 UDP 传文件却不做校验与重传

    ✓需要可靠传输就用 TCP 或基于 QUIC 的方案

  • ✗防火墙只开 TCP 端口，HTTP/3 或 DNS 失败

    ✓按协议分别放行 TCP 与 UDP 端口

  • ✗高并发短连接耗尽端口，TIME_WAIT 堆积

    ✓使用连接池和 keep-alive 复用连接

🎤 09 · 面试追问
TCP 为什么需要三次握手而不是两次？

需要双方都确认对方能收能发，并同步各自的初始序列号。两次握手时服务器无法确认客户端收到了自己的 SYN-ACK；此外三次握手可防止已失效的旧连接请求突然到达，导致服务器误建连接、浪费资源。

HTTP/3 为什么改用 UDP？

TCP 由内核实现，演进慢，且整条连接共享一个有序字节流，单个丢包会阻塞所有 HTTP/2 流。QUIC 在 UDP 上用户态实现，每个流独立重传，并把 TLS 1.3 握手合并进建连过程，减少往返次数。

DNS 为什么主要用 UDP，什么时候用 TCP？

典型 DNS 查询是一问一答的小报文，UDP 免握手更快。当响应过大被截断（TC 位）、进行区域传送（AXFR）或使用 DNS over TLS 时，会使用 TCP。
