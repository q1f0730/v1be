提示链 (Prompt Chaining)

Prompt Chaining

📐 01 · 定义

提示链（Prompt Chaining）把复杂任务分解为一系列有序的 LLM 调用，每步的输出作为下一步的输入，步骤之间可插入程序化检查（gate）。它属于 LLM 应用编排层，是最基础的工作流模式：以多一点延迟换取每步更高的准确率、可观测性与可调试性，介于单次提示与自主 Agent 之间。

⚙️ 02 · 原理
  1. 1

    把任务拆成边界清晰的子任务，如「抽取 → 分析 → 撰写 → 校对」，每步有明确输入输出格式。

  2. 2

    每步用专门的提示，只携带该步所需上下文，减少干扰并降低单次 Token 消耗。

  3. 3

    步骤间用代码做校验：解析 JSON、检查必填字段、规则判断，不合格则重试或中止。

  4. 4

    顺序固定的流程由代码控制流程走向，而非让模型自行决定，因此行为可预测。

  5. 5

    每步输入输出可单独记录与评测，定位问题时只需重跑出错的那一步。

🔤 03 · 术语
工作流 (Workflow)
由代码预定义路径编排 LLM 调用，区别于模型自主决策的 Agent。
关卡 (Gate)
步骤之间的程序化检查，决定继续、重试或终止。
中间表示 (Intermediate Output)
步骤间传递的结构化结果，常用 JSON。
路由 (Routing)
先分类输入，再交给不同的专门链路处理。
自我修正 (Self-correction)
增加一步让模型审查并修改上一步结果。
💻 04 · 代码
三步链 + 程序化关卡python
# pip install anthropic
import json, anthropic

client = anthropic.Anthropic()
MODEL = "claude-sonnet-4-5"  # 换成你在用的模型

def llm(prompt: str) -> str:
    msg = client.messages.create(model=MODEL, max_tokens=2000,
                                 messages=[{"role": "user", "content": prompt}])
    return msg.content[0].text

review = open("feedback.txt", encoding="utf-8").read()

# 第 1 步：抽取结构化问题列表
raw = llm(f"从以下用户反馈中抽取问题，只输出 JSON 数组，元素含 issue 和 severity(1-3)：\n{review}")
issues = json.loads(raw)                     # 关卡：解析失败直接抛错
assert all({"issue", "severity"} <= set(i) for i in issues), "字段缺失"

# 第 2 步：只取严重问题写修复建议
serious = [i for i in issues if i["severity"] >= 2]
plan = llm(f"为这些问题写简短修复建议：\n{json.dumps(serious, ensure_ascii=False)}")

# 第 3 步：面向用户改写成回复
reply = llm(f"把以下内部建议改写成礼貌的客服回复，不提内部细节：\n{plan}")
print(reply)

每步单一职责；第 1 步后用代码校验格式，生产中还应加重试与结构化输出。

📊 05 · 参数对比

编排模式对比

模式控制权可预测性适合
单次提示无编排中简单任务
提示链代码固定顺序高可拆成固定步骤的任务
路由 + 专用链代码按分类分支高输入类型差异大
自主 Agent模型决定下一步较低步骤无法预先确定
⚖️ 06 · 方案取舍

单次大提示

优点延迟低、实现简单

代价易遗漏要求，出错难定位

适用任务短小且一步可完成

提示链

优点每步更准、可校验、可单独优化

代价多次调用增加延迟与成本

适用多阶段、质量要求高

Agent 自主规划

优点能处理开放式任务

代价成本与行为不确定性高

适用路径无法事先固定

🕳️ 07 · 常见坑

  • ✗步骤之间直接传自由文本，格式漂移后下游崩溃

    ✓用 JSON/结构化输出传递，并在关卡处校验

  • ✗把全部上下文传给每一步

    ✓每步只传必要字段，减少噪声与费用

  • ✗拆得过细，延迟与成本失控

    ✓以可独立校验为拆分粒度，合并无需检查的相邻步

  • ✗某一步失败后继续执行下游

    ✓关卡失败时重试或中止，并记录该步输入输出

☑️ 08 · 检查清单
🎤 09 · 面试追问
提示链和 Agent 的边界在哪里？

提示链的执行路径由代码预先定义，模型只负责每步内容，行为可预测；Agent 由模型根据环境反馈动态决定调用哪些工具、走哪一步。能用固定流程解决时优先工作流，确有开放性才上 Agent。

如何决定拆分粒度？

看每步是否有独立可校验的输出、是否需要不同的提示或模型、是否会因同时处理多个目标而降低质量。拆到每步单一职责且可测试即可，避免为拆而拆导致延迟和成本上升。

提示链如何做评测？

既做端到端评测，也对每步建立小型数据集单独打分；记录中间结果，定位质量下降出在哪一步；修改某一步提示后做回归测试，确保下游不受格式变化影响。
