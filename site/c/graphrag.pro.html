知识图谱增强检索 (GraphRAG)

GraphRAG

📐 01 · 定义

GraphRAG 指在检索增强生成中引入知识图谱：先用 LLM 从文档中抽取实体、关系与声明构建图，再基于图结构（邻居、路径、社区）检索上下文。Microsoft 的 GraphRAG 方法还对图做社区划分并预生成分层社区摘要，以回答「数据集的主要主题是什么」这类需要全局理解的问题。它属于 RAG 的索引与检索层。

⚙️ 02 · 原理
  1. 1

    把文档切分为文本单元，用 LLM 抽取实体（人、组织、地点、概念）及其关系与描述。

  2. 2

    合并同名实体与重复关系，构建知识图谱，并可同时保存文本单元与实体的对应关系。

  3. 3

    用 Leiden 等社区检测算法把图划分为分层社区，并用 LLM 为每个社区生成摘要报告。

  4. 4

    全局搜索（Global Search）：对社区摘要做 map-reduce，汇总回答面向整个语料的宏观问题。

  5. 5

    局部搜索（Local Search）：从问题相关的实体出发，取其邻居、关系与原文片段作为上下文回答具体问题。

🔤 03 · 术语
知识图谱 (Knowledge Graph)
以节点（实体）和边（关系）表示知识的数据结构。
实体抽取 (Entity Extraction)
从文本中识别实体及其类型、描述。
社区检测 (Community Detection)
把联系紧密的节点分组，GraphRAG 使用 Leiden 算法。
全局搜索 / 局部搜索
基于社区摘要回答宏观问题 / 基于实体邻域回答具体问题。
多跳问题 (Multi-hop Question)
需要串联多条事实才能回答的问题。
💻 04 · 代码
Microsoft GraphRAG 基本流程bash
# 安装并在项目目录初始化（会生成 settings.yaml、.env 和 input/）
pip install graphrag
mkdir ragtest && cd ragtest
graphrag init
# 编辑 .env 中的 GRAPHRAG_API_KEY，把 .txt 文档放进 input/

# 建立索引：实体关系抽取、社区检测、社区摘要（调用大量 LLM，先小样本试）
graphrag index

# 全局搜索：回答面向整个语料的问题
graphrag query "这批会议纪要的主要议题有哪些？"

# 局部搜索：围绕具体实体的问题
graphrag query "张三参与过哪些项目，与谁合作？" --method local

# 注：命令参数随版本变化，旧版本使用 --root 与 --query，以官方 Get Started 为准

索引阶段调用 LLM 次数与语料规模成正比，是主要成本来源；先用少量文档估算。

📊 05 · 参数对比

向量 RAG 与 GraphRAG 对比

维度向量 RAGGraphRAG
索引成本嵌入计算，较低LLM 抽取与摘要，较高
擅长问题定位具体事实与段落关系、多跳、全局主题

⚖️ 06 · 方案取舍

向量 RAG

优点简单、便宜、成熟

代价跨文档关系与全局问题效果差

适用FAQ、文档问答等多数场景

GraphRAG

优点关系推理与全局摘要能力强

代价建图成本高、抽取有误差

适用情报分析、研究资料、会议记录

混合（向量 + 图）

优点兼顾具体事实与关系

代价系统复杂度最高

适用问题类型多样的大型知识库

轻量图方案（如 LightRAG）

优点降低建图与查询成本

代价成熟度与生态需评估

适用想尝试图检索但预算有限

🕳️ 07 · 常见坑

  • ✗未估算成本直接对全部语料建索引

    ✓先用小样本测量 Token 消耗，再外推并设预算

  • ✗问题大多是具体事实查询，却上 GraphRAG

    ✓先分析问题分布，事实型查询用向量/混合检索即可

  • ✗忽视实体抽取错误与同名合并问题

    ✓抽查图谱质量，配置实体类型与消歧规则

  • ✗语料频繁更新仍全量重建

    ✓评估增量索引能力，或按更新频率分层处理

☑️ 08 · 检查清单
🎤 09 · 面试追问
GraphRAG 的全局搜索如何回答宏观问题？

索引时已为各层社区生成摘要；查询时把相关层级的社区摘要分批交给 LLM 生成部分答案并打分（map），再汇总高分部分得到最终回答（reduce），避免只依赖少数相似片段。

为什么向量检索难以回答「主要主题是什么」？

这类问题需要综合整个语料，而向量检索只返回与问题最相似的少数片段，无法覆盖全局；问题本身也缺少与具体段落相似的关键词。

GraphRAG 的主要局限？

索引成本高、耗时长；LLM 抽取可能遗漏或产生错误关系；增量更新复杂；对具体事实查询未必优于向量检索。应基于评测与成本决定是否采用。
